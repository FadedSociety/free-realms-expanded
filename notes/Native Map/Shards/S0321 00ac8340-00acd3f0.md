## Housing

00aca5d0 is a HousingProcessor virtual dispatcher. It wraps the body as BaseHousingPacket, reads the inner u16, and dispatches it. Relevant paths are instance data 0x1c to 00aca330, fixture update 0x28 to 00ac8340, and fixture item list 0x2b to 00ac9bd0. The packet class names for inner messages come from the community catalogue; they do not establish original server implementation.

00ac8340 calls the bounded record reader 00ac2180. On its continuing path it stores state 2 at +0x4140, copies two parsed values to +0x4170/+0x4174, and appends a record to the list at +0x4258/+0x425c/+0x4260. The guarded debug path prints "Foundation!". The decompilation's pointer/cursor condition is not interpreted as an overflow rejection, and the record fields remain unknown.

00ac9dd0 parses the subtype-28 house instance record. Three length-prefixed fields are read as strings through 00894b10; nested objects and scalar fields populate the house object, and each linked element at +0xdc receives a back-pointer at +0xd0. 00aca330 creates and initializes the house on first receipt, and logs house and placement-box fields only when the debug console is enabled. 00aca2b0 is a separate bounded-reader wrapper with no static callers; the live path is in 00aca330.

For subtype 43, 00ac9a90 reads three fields into a temporary item-list record. 00ac9bd0 drains that temporary list and the pending list at +0xded0, stops an active preview, then traverses the house chain and performs keyed-record lookup/insertion. Its shown code does not unlink or free actor nodes, so the earlier "destroys every actor node" description was unsupported.

The placement paths are now separated by what they send:

- 00ac8680 constructs the payloadless family-127 subtype-4 PickupAllFixtures object and sends it when connected. Its optional +0x4244 branch calls the rating remove-candidate path.
- 00ac8790 builds and sends SaveFixture subtype 5; note 025 directly cites this function. It clears the selected fixture pointer after the send path.

- 00ac8d90 handles the confirmation states: save/move, pickup subtype 3, then place subtype 1, with sends guarded by connection state.
- 00ac9140 calls the preview positioning helper first, saves the current selection pointer, runs 00ac8790, then restores the pointer.

00ac9340 resolves the interned key RatingSystem.HousingId, defaults to Housing, and sends a rating-system request through outer PacketTunneledClientWorldPacket. ## Cross-function server hypotheses

Housing messages reaching 00aca5d0 use family 127 with an inner u16. Client senders wrap outgoing housing data in PacketTunneledClientPacket; the rating path uses PacketTunneledClientWorldPacket. The community catalogue supplies some inner housing names, while native code establishes the client-side parsing and writing paths. These facts do not reconstruct original server logic.

The gateway readers define the client-side layouts listed above. A peer that wants the corresponding handlers to run must provide those fields, but the code does not establish original server triggers or field meanings. In particular, client-ready ID 13 is sent in a tunnel, but this shard does not show that it starts world loading.

## Corrections to earlier claims and open questions

Note 025's statement that some server-to-client housing layouts remain unrecovered still holds for server writers and field meanings. This shard adds client parsing evidence for parts of subtypes 28, 40 and 43. 00ac9bd0 does not prove actor-node destruction; 00ac8340 does not establish a pointer-overflow rejection; 00acb920 removes an owner match, not a mismatch; and 00acb350 does not initialize the array gap.

The main open questions are the field meanings in the subtype-28 house record, subtype-40 fixture record and subtype-43 item-list entries; the reason and lifecycle for traversed house-chain records; TargetProcessor actor/type and vector semantics; the meaning of gateway IDs 4, 7 and 9 payload values; the direction and payload role of gateway ID 10; and the inner rating request class and server behavior. The original server is unavailable, so those behaviors remain hypotheses.
