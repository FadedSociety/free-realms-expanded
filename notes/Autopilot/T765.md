# T765 - Card Duelist launch handshake: type-16 run, 39/37 ticket request, 39/0x28 (lead build, 2026-10-26)

Stacked on T764 (launch tickets). Decode: `lab/content/tcg/analysis/lead-login-decode-2026-10-26.md`.

## Client facts

- The exe's type-16 manager (`00ad4f50`) loads its assets after 39/17, sends 39/37 (`009bf590` ->
  `009bdc60(37, -1, -1)`: the 15-byte lifecycle header with the current instance id) and waits in state 5.
- 39/0x28 `TradingCardStartGamePacket` (reader `009b7f30`): `DispatchMiniGamePacket` (`009bf890`) finds the run
  by the header's instance id and, for type 16, passes the two i32 after the header to slot 25 (`00ad32e0`:
  +0x2ba98 low, +0x2ba9c high), which Startup (`00ad47f0`) gives the DLL as `--ticket=%llu`.
- 39/6 when the card DLL exits (`009be8e0` from state 4).

## What changed

- `src/minigame.rs`: `RunMode::CardClient` (39/5 answered with 39/17 alone, no 26/12 Flash launch); sub 37 on a
  started card run returns `RunOutcome::card_ticket` (instance, game); `card_start_packet` writes 39/0x28.
- `src/card_game.rs`: optional `launch` block (`ticket_ttl_ms`, 1 s..10 min, with a source); `Launches` (one
  session's `MinigameRuns` from instance 61,000,001 and its `LaunchTickets`): `begin` offers the row's run (type
  16, the row's MiniGameData id), `route` mints the character's ticket on 39/37 and appends 39/0x28, `redeem`
  for T766's listener; `Content::row`/`launch`.
- `src/activity_portal.rs`: a Trading Card Game row is admitted only when the card content has a launch block;
  Treasure War stays refused; busy players are refused first, as before.
- `src/gameplay.rs` (hub, +12 lines, CRLF kept): the `card_launches` field (built from the launch block), the
  card arm of Play, `handle_card_game` ahead of chess in the in-world chain, `mod card_launch`.
- `src/gameplay/card_launch.rs` (new): `begin_card_game`, `handle_card_game`, `redeem_card_ticket`.
- `src/gameplay/occupation.rs`: `CardGame` occupation with chess's gates (start, warp, ride, pets).
- `src/gateway.rs` (CRLF kept): the 39/37 label "card_game" (+ label assert).
- `src/card_service.rs`: `LaunchTickets` is `Clone` (gameplay stages clones).

## Not done here

## Checklist

1. A refusal changes nothing: refused Play sends only the chat line; an ignored 39/37 sends nothing.
2. Rollback: the run and tickets are session-only; nothing is saved.
3. Deltas: none.
4. Busy: a card run is an occupation (start, warp, ride, pets); Play is refused while busy.
5. Entry paths: Play is the only start; 39/37 only works on the session's own started run.
6. Real path: portal admit -> `begin_card_game`; in-world chain -> `handle_card_game`; tests drive `Launches` and
   the catalogue (end-to-end session test in T766, see above).
7. Reconnect: a reconnect drops the run and its ticket (session-only); the client launches again.
8. Exits: 39/6 retires the run (39/19); an unused ticket expires.
9. Economy: none.
10. Wire: 39/37 `009bdc60`, 39/0x28 `009b7f30`/`009bf890`/`00ad32e0`; byte-level asserts in card_launch.
11. Ids: card runs start at instance 61,000,001, apart from chess, soccer and harvesting; tickets are random.
12. Others: nothing visible to other players.
13. End to end: pending T766 and the native check.
14. Data: the ticket lifetime is in card_game.json's `launch` block with bounds.
15. Canary: production `handle_client` state gate.
16. Session plumbing: untouched (T766 owns the listener).
17. Tick safety: not on a tick; a randomness failure is an error for that request only.
18. Type rules: the run mode lives on `RunMode`, the ticket policy on `LaunchTickets`, the launch settings on
    `Launch`.
19. Hot path: the card handler returns at once unless a card run is active.

## F766 folded in (lead, 2026-10-27)
The review of T763 found `card_service::put_int` duplicating `game_rules::append_serial_integer` (same compact
layout: low nibble, complement flag 0x10, extra-byte count in bits 5-7, little-endian rest). `put_int` now calls it
with `IntegerEncoding::Compact` (made `pub(crate)`); `compact_integers_match_the_dll_writer` still passes.
