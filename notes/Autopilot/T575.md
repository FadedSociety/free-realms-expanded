# T575 - The host bundle serves the character-creator overlay to private realms

Built on T443 (the overlay list and its pins) and T444 (the creator allow-list in `identity.rs`).

## Decision (lead, 2026-10-22)

Private realms (friends over a VPN, the Playtest Host Runbook setup) may serve the overlay. These are the
same files every community-launcher user downloads publicly from opensourcefreerealms.com, so pinned
redistribution to invited friends follows the owner's direction to use community renditions of original
content. A public release still waits until the licence is clear. This sentence is in `launcher/README.md`
("Licence") and in the bundle README `make_bundle.py` writes.

Provenance (unchanged from T443): all 22 files came from `https://opensourcefreerealms.com/client/<path>` on
2026-10-08, each listed in that site's public `clientmanifest.xml` (SHA-256 `9555ac7c...`), with length and
XXHash64 matching that manifest; per-file records are in `lab/references/asset-cache/cache-index.json`.
The overlay's W121 manifest pin is `dc5c2fb1f0c9ffc92034e5b3a90da584d01c683a55670fdbe4e35651bcb3ae81`
(rebuilt here; the same value T443 recorded).

  pin-checked before anything is written; on a miss it raises and `main` removes the whole bundle, as for
  any other failed input). It copies the two pinned customization tables from that checked folder to the

## (R) choices

- (R) The folder is named `client-overlay/` and lives inside the bundle, beside the server data. The host
  serves only that folder; the bundle README and runbook step 11 say so.
- (R) The startup signal is a field on the existing `listening` line rather than a new event, following
  the gateway's `dev_tools` field; every parser of that line looks for the event name or substring.
- (R) The scan exemption is by name (`CharacterCreate*.txt`), not by content. Saves are JSON/binary and
  never carry that name.

## Threat note

The overlay is served to friends' launchers, which verify every file against the pinned manifest (W121), so
a tampered host copy is refused client-side; the build itself refuses any cached file that misses its pin.
The scan change narrows one heuristic: a `lab/runs` file named `CharacterCreate*.txt` is no longer treated
as a possible save. Key files (`client-login-key.bin`, private-key suffixes) are still caught whatever their
name, and the full save roots (`lab/state`, `lab/keys`, `lab/accounts`, the package's `characters/`) are
untouched. Turning on the allow-list for bundles means a hostile client can no longer create skin 7/8 or the
hidden heads on a bundle-hosted realm (T444's refusal now applies there).
