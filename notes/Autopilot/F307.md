## Security threat note (secure-code-guardian)

A hostile client can send 66/43 with an arbitrary item id, quantity and transaction id.
The server still requires an open shop, the NPC's explicit `vendors.json` stock, range and
zone, a positive server `stores.json` price, the wallet and the bag cap. The new rule trusts
no client field: the mapping is server-owned content, and the menu hint is not a purchase
authorization. Removing the role dependency cannot widen what a player can buy; it only
lets a role-less mapping load. Every 66/43 refusal answers 66/44 false, reports
`changed: false`, leaves the typed state equal and leaves the shop open; the new positive
controls buy after each refusal. No parser, save, session, account role, reward or coin
path changed. The tests drive the production `NpcInteraction::load`,
`Gameplay::handle_in_world` and `Gameplay::on_location` paths; the synthetic role fixture
is test-only and removed after the test.
