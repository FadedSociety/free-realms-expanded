Skills applied: ponytail (full, review pass on the diff), secure-code-guardian (threat note below).

## What changed

`npc_spawns_extra.json` draws 344 enemy bodies (Sandscale, Skullz, cultists, crays, widows, swoopers, vultures, Floren, trolls,
snakes, bears, ghost ninjas ...) as friendly NPC actors (blue name, not fightable). The new `data/content/field_camps.json` takes
each body over by `spawn_guid`: 55 camp rows, each naming an `enemies.json` definition (stats and the kill-credit definition id),
a level, respawn / aggro / leash, the `field_roamer` behaviour, the `standard` drop table, and its member guids. A member keeps
its position, model, texture and name from `npc_spawns_extra.json` (one placement store, so a later placement move follows).
`EncounterEngine::load_field_camps` (`src/encounter/field_camps.rs`) expands the rows into the same `FieldActor` rows that
`field_enemies.json` produces and validates them with the same code, so level scaling (`scale_field_enemy`), the combat marker
(T879), the GUID checks and the home leash apply. The field GUID is the body's GUID, so the existing exclusion
(`visibility.exclude_actor_guids(engine.field_guids())`) hides the friendly copy; the enemy spawns through the usual hostile
field-enemy 35/2 (red name), is fightable through 26/8 -> 26/10, and respawns on its camp's timer.

Why a separate file and loader: `load_field_enemies` refuses more than 64 rows or 128 KB, and a dozen shipped tests pin
`field_enemies.json` as the whole always-on population (`spawned == always_on`, `camps.len() == field_guids().len()`), so the
camps load through their own entry (`load_field_camps`), called right after `load_field_enemies` at startup (one line in
`gameplay.rs`) and inside `reload_field_enemies`.

Refactor in `field_content.rs` (no behaviour change): the per-row validation moved out of the `load_field_enemies` loop into
`build_field_enemy`, the claimed-GUID set into `claimed_guids`, and the spawn-group provenance check into `check_sources` (same
error strings), so camps reuse them instead of copying.

## Threat note

The file is server content, not client input. A hostile client can only reach it through the existing 26/8, 26/10 and tick
paths, whose reach, known-NPC and level checks are unchanged. The loader refuses (and changes nothing on) an unknown or boss
definition, a member that is not a drawn extras row, a GUID that another field row, battle or dungeon already holds, a missing
`(R)` provenance, a level or respawn outside the existing bounds, and a second load of the same camps. Kill rewards come from the
existing level-band table (`field_kill_rewards.json`), nothing new.
