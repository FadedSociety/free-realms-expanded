## Security

Threat note (secure-code-guardian): the tests drive client-controlled 26/8,
26/10, 66/43 and 165/5 fields. A hostile client can name an unknown NPC or
option, send a foreign item ID, zero or `u32::MAX` quantity, a replayed
transaction ID, a closed-shop buy, an unaffordable buy or a full-bag buy. The
production path refuses those before mutation: the NPC must resolve in content,
the option must be in the currently opened menu, the active merchant/range gate
must hold, the item must be in server-owned stock, and `CoinShop` re-checks the
item definition, the server price from `stores.json`, quantity, coins and bag
capacity. Refusals answer 66/44 status 0 and leave the full gateway snapshot
unchanged; the tests assert that and then prove the open shop survives. The
malformed/unknown/quantity cases remain covered by
`gateway_vendor_buy_refusals_always_answer_with_66_44` in `vendor_sell`. The
only new filesystem writes are test fixtures under `lab/build`, removed on
drop.
