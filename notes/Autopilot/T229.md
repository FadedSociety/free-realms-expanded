# T229: Station Cash slice 2 — earned SC and the first-clear ride

## Summary

Station Cash is earned by server-verified completions through the same reward applier slice 1
spends it with. One data table (`data/content/sc_rewards.json`) names every amount; each
completion hook calls `Gameplay::pay_earned_station_cash`, which decides the amount with
`EarnTable::earned` and pays it as the new `sc` kind of `rewards::RewardGrant` through
`rewards::apply_grant`, then adopts the staged wallet. Chrome Drake is the first-clear ride of the
hardest dungeon in our content, Stone Heart's Hideaway (12303); Polar Bear is a dormant data row
because no seasonal event content exists (T418's live events only gate quest offers).

- (R) A dungeon clear is any won combat run: the opening cave and every `field_battles.json` row

- (R) The hardest dungeon is 12303 Stone Heart's Hideaway (evidence above).

  or cooldown exists (the owner 2026-10-20: farming is fine).
- (R) Chrome Drake: first clear of 12303, recorded in `Wallet.earned_rides`. Already owned or no bag

- (R) SC-only grants send no 50/1 bundle; the 66/11 wallet packet is the client update.
- (R) The earn table is read when the session's shop loads (like `stores.json`); an edit applies to

- (R) The 17 opening story stages (OpeningEngine) pay no SC; NPC quest-engine turn-ins do.

## Security threat note (secure-code-guardian)

A hostile client controls the traffic around a completion but neither the completion record nor
the amount:

- Amounts come only from `sc_rewards.json` (bounded at load). No packet field, score, elapsed time
  or quest reward row reaches `EarnSource`/`EarnTable`; the quest id used for a per-quest override is
  the server's pending turn-in (`finish_turnin` refuses any other id), and the dungeon id is the
  server's own active run.
- Each payout is gated on the owning activity's one-shot record (kart claim consumed, derby ledger,
  soccer `settled`, chess run settled once, `pending_turnin` cleared, the run's single transition to
  `Won`). Replays re-raise none of them; the tests replay the attack/ack/turn-in/tick/Close and
  assert no change.
- The wallet is staged on a fresh `RewardState`, paid with checked arithmetic under the ceiling,
  and adopted in the same call; any `Err` drops the whole staged `Gameplay`/`Gateway` clone and ends
  only that session (`contain` in `osfr-gateway.rs` step loop). No long-lived snapshot carries the
  wallet, so no later adopt can restore a spent balance (fishing regression test).
- The ride is recorded in the persisted wallet in the same transaction as its grant, so a replay or
