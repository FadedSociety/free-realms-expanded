Review: `lab/autopilot/reviews/478d485-T528.md`. Every finding was checked against the code on the tip.

## What changed

1. BLOCKER (structure): `mystery_chest::check_reply` now calls
   `item_bar::use_wire::encode_immediate_activation_check` (the one 38/30 encoder, client reader
   documented there). The chest's own 25-byte serializer and its two private constants
   (`OPCODE_CLIENT_UPDATE`, `SUBTYPE_IMMEDIATE_ACTIVATION_REPLY`, now duplicates) are deleted.
   `tests/mystery_chest_codec.rs` still pins the bytes and passes unchanged, so the fold is
   byte-identical.
2. Unknown instance: `MountService::upgrade_use_plan` returns `NotUpgradeItem` for an instance the
   bag does not hold (it was `UpgradeItemNotOwned`, which printed the training-saddle line). The
   route falls through to the item bar / chest / inventory handling again, so a stale 42/16 for a
   chest gets the chest's 38/30 failure dialog. A known saddle whose units are all consumed still
   gets the saddle notice.
3. Derby: `handle_derby` answers a 42/15 or 42/16 with one system line ("Finish the derby before
   using equipment.") instead of an empty `Outcome`. Only the immediate-activation pair, not all of
   42/*: the derby keeps dropping other 42 records as before.
4. Notes/test comment: the gathering refusal is `RideRestrictions::allows` (Harvesting `ride: true`),
   not a movie gate. Test comment and `notes/Autopilot/T528.md` corrected.
5. Allowlist deviation: kept as is. A saddle-class item outside `mounts.json` `upgrade_items` cannot
   be told apart from any other item by the server (there is no "saddle class" field), so it keeps
   the generic route; adding a notice would need a new classification (speculative). Pinned by
   `a_non_saddle_instance_is_left_to_its_own_route` (an owned ride, 42/15 and 42/16, gets no saddle
   notice, no picker and changes nothing). Lead can overrule.
6. Economy: `MountService::upgrade_plan` picks a saddle with `count - consumed_count > 0`, the same
   rule as `upgrade_use_plan`. A fully consumed stack no longer trains a ride.
7. `UPGRADE_PICKER_LUA` is no longer `pub`.
