## Threat note (secure-code-guardian)

A hostile client can send 53/18 for any pet id, any number of times: a non-active/vanity/wet/busy/feed/session
request, an already-clean bar or a missing/unowned fitted kit is refused with one kind-6 packet and no state
change (the kit is only read from the owner's fitted, owned stacks; the start stages the consume on clones and
commits with the session). It can flood 53/22: a mode-2 report with no session now returns one small kind-6
packet and touches no state (same cost class as a 53/18 refusal); with a session, `mode`, `time` and
`movement` are client words that are all validated (negative-as-signed and zero-time count 0, speed clamped,
gain bounded per message and per fixed second with the documented 2x boundary worst case); petting is rate
limited before a pet lookup. No stroke can name an item, coin or reward: only the one summoned pet's need
points move, clamped to the bar. The kind-6 reply's pet-id word is not read by `00b56a00`, so id 0 when no
pet is out is safe. The session is connection state: it is dropped on disconnect and the spent kit and gains
stay in the save.
