## Threat note (secure-code-guardian)

The suite exercises the existing quest trust boundary: a hostile client can forge
a 49/2 accept (wrong giver, unsatisfied prerequisite, wrong job), a 49/14 before
the goal is complete, a duplicate 49/14, or a level claim. The server refuses them
because the accept goes through the engine's offer state/`can_offer` (job and
prerequisite), the 49/14 needs the server-held `pending_turnin` opened by a Talk
at the correct server-known actor, and the `job_level` goal reads only the server
profile (tests use the admin `realm level` path; production uses XP). The payout
is data-read and `apply_grant` is idempotent, so a replay pays once. The tests
snapshot the serialized save before each forged accept/early/duplicate 49/14 and
assert byte equality; `assert_no_offer` also asserts the open NPC menu survives.
No new client input is parsed, no new item or free grant is added, and no
client-reported result is trusted.
