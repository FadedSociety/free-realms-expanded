# T013: Objective events reach the quest engine

## What changed

- `src/gameplay.rs`: `initialize_world` now emits an authoritative
  `QuestEvent::VisitPosition` after the NPC quest login sync. Area and reach
  objectives therefore advance on scene entry and zone transfer, not only
  after the first movement packet.
- `src/gameplay.rs`: kart and fishing minigame completions now reach the
  regional quest engine. Kart routes the paid race identity into
  `QuestEvent::FinishMinigame`; fishing filters its service event list so the
  service's `CollectItem` is still derived from the adopted inventory diff
  (no double count) while its `FinishMinigame` is forwarded once.
- `src/kart_gateway.rs`: added `KartRewardClaim` and
  `claim_reward_with_event`. The existing `claim_reward` wrapper keeps its
  old return type, so existing callers and tests are unchanged. A refused or
  replayed claim returns no minigame id.
- `src/fishing_service.rs`: retained the stable content `game_id` on each
  tracked round and emits it as `FinishMinigame` on a paid catch.
- Tests: `src/gameplay.rs` gained six real-path tests (collect, gather,
  craft, minigame, area, reach), each with a refusal check, plus a fishing
  gameplay integration test that proves the catch reaches the quest engine
  once. Service tests now assert the kart and fishing identities.

## Reconstructed rules

- (R) The kart completion identity is the content speedway id
  (`31..39` in the starter table). No separate kart minigame catalogue id is
  recovered.
- (R) Fishing completion uses the area minigame id already supplied by
  `fishing_spots.json` and `FishingService::begin`; one paid catch is one
  completion.
- (R) Scene entry is an authoritative location event for the regional quest
  engine; the existing movement path remains the second source.

## Evidence summary

- Collect already worked through inventory diffs (`grant_reward`,
  `npc_inventory_events`, and fishing's adopted inventory). Its test keeps
  that path and checks an invalid grant advances nothing.
- Gather already worked through `apply_mining` / `apply_harvesting`
  transactions and the opening gather-node path. The test drives the
  harvesting payout transaction and checks a wrong active job never advances.
- Craft already worked through the cooking, smelting and forging completion
  paths. The test drives the real cooking station path and checks a wrong
  active job never advances.
- Minigame already worked for mining/harvesting/cooking/smelting/forging
  through the server win packet. The test drives a mining win and checks a
  win-shaped result with no payout advances nothing.
- Area and reach were the missing runtime paths on scene entry; both now
  advance before movement. Refusal cases use the wrong zone and a position
  outside the authored radius.

## Open gaps

- No native run: this task's gate is unit-level.
- The bundled regional quest files currently contain only talk, defeat,
  gather and craft goals. Area, reach, collect and minigame hooks are proven
  with synthetic quest definitions; shipping content for those kinds remains
  a content task.
- The kart and fishing quest forwarding is asserted at the service boundary;
  their full gameplay loops were not re-driven in this task (the existing
  kart/fishing suites were rerun).
- Scene-entry location checks now run on every world initialization. Quest
  counters cap at their requirement, so repeated movement/scene events cannot
  over-advance; no regression appeared in the tested gateway suites.
