### Why the three `finish_minigame` rows stay off

The kart claim credits `KartRewardClaim.minigame_id = payout.speedway`
(`src/kart_gateway.rs:763`); `Gameplay::tick_world` forwards that one id to
`QuestEvent::FinishMinigame` (`src/gameplay.rs:1962-1966`). The only shipped kart entry is
`data/content/kart_entry.json` `race.speedway = 31`, and `tests/support/quest_target_sets.rs` pins the
whole producer set (kart 31, derby 39, soccer/chess/fishing/recipes/mining 18/harvesting 111). Client
`MiniGameData` rows 628, 632 and 633 name the individual Wildwood races, but no server path emits
them. Binding `finish_minigame` 31 instead would be a different rule than the fixed spec ("win any
Wildwood race"), so the rows stay disabled until the kart service models a race identity. The
precedent for a deliberate 31 substitution is 3080002, whose (R) tag says so explicitly; T732 does
not extend that substitution to quests whose text names a specific race.

3080004 is blocked twice: the quest answer leaves `giver` null and the record's old key 9000000539
has no NPC row or spawn, so `enabled_quest_reachability` would reject it even with a minigame id.
3080011 is additionally blocked on Big Paulie: the only evidence is reference spawn
`npc_spawns_extra.json` 100000003022, which has no `content_key` and therefore no talkable content row.

## Threat note (secure-code-guardian)

A hostile client can send 26/8/26/10/26/6 at any target, 49/2 for a quest it was never offered, and
49/14 early, twice, or for a quest never accepted. Every path is the existing `Gameplay::handle_in_world`
-> `gameplay/npc.rs` -> `QuestEngine` route: the offer needs the server's job/level/prerequisite/giver
checks, accept rechecks them, the Talk event needs the exact `npc_id`, the end screen needs the
server-held `pending_turnin`, and the 49/14 settles only that pending quest through the per-character
`quest:<character>:<quest>` grant key. No client amount, item id or result is read; rewards are the
two fixed content rows and are paid once. The tests snapshot the serialized save before every forged
49/2, early/duplicate 49/14 and wrong-NPC Talk and assert byte equality after the refusal. No new
parser or trust boundary was added.
