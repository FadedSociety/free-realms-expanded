## Security note (secure-code-guardian)

Threat note: a hostile client can send attack/encounter requests with arbitrary
target GUIDs, job profiles and timestamps, but none of those fields reach the
changed code: `level`, `max_health` and `damage` come from server-authored JSON
at load, and no packet field selects an actor row. The only way to make a fight
tougher or weaker is a hostile/typo'd content file, and a row outside the 1..=20
band now fails the load before scaling (the previous clamp would have silently
produced a level-1 or level-20 fight). Existing bounds are unchanged:
`max_health` 1..=100,000, `damage` <= 1000, `enemy_health_scale` /
`enemy_damage_scale` 0.01..=100. Worst in-bounds effective health is ~1.4e8,
inside `u32`.
A refused load returns `Err` before an engine exists, so it consumes no open
menu, offer, item or cooldown. No reward, coin, item, role, save or chat path is
touched; saved enemy health is still clamped, never overwritten.
