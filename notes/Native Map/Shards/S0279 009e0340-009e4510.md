# S0279 findings (0x009e0340-0x009e4510)

## Subsystems and data structures

- `lib.soeutil` contains bounded stream readers. `009e0340` reads checked 16-bit fields. `009e03a0`, `009e0550`, and `009e05b0` assign length-prefixed bytes into embedded `IString` values through `00894b10`; `009e0f60` assigns a string before two dword fields, and `009e1010` stores its string at output `+0x30`. The span is copied into string storage, not merely skipped.
- `lib.soeutil.container` includes hash-list maps, two red-black-tree/fixed-block-pool variants, and node readers/inserters. `009e0920` allocates, initializes and inserts a keyed node into a 64-bucket map. `009e0e60` and `009e0ee0` also perform full insertion after copying their dword values; their destination offsets differ (`+0x10` versus `+0x0c`). `009e0b10` constructs a FactoryPlot placement node, links it at the tail and hashes its pair key into 1024 buckets.
- Tree helpers `009e1fb0` and `009e2b20` walk from the minimum in order and return seed `10` or `50` plus each node's `+0x14` dword. Their callers `009e2530` and `009e30b0` use these sums for fixed-block sizing. The meaning of `+0x14` remains unknown; weight semantics are not established.
- `net.factory` includes packet constructors and packet-specific destructor bodies. `009e14b0` tears down the embedded request-entry list of `FactoryPacketCreateBlueprintRequest`; `009e1520` tears down the two maps in `FactoryPacketOpenBlueprintBrowserOnFoundation`; `009e40d0` and `009e41b0` tear down the tooltip list and tool map in their respective derived packets, then restore base vtables. `009e4080` is an EH cleanup that calls the tooltip-list destructor on a stack subobject at `+0x18`.
- `game.factory` includes `FactoryProcessor` construction (`009e42a0`) and teardown (`009e4410`). Teardown calls each helper's virtual slot `+0x28`, passes its return through `0081ad80`, releases references at zero, and destroys the embedded tooltip list and state. The slot's operation is unknown.

## Packet paths and server boundary

This establishes a client send path, not the server's processing or response behavior.
- `009e4210` initializes `FactoryPacketOpenBlueprintBrowserOnFoundation` with subopcode `0x18`. The original-server hypothesis is that it sent outer id `0xbc`/subopcode `0x18` to reach that client path; this depends on the dispatcher and base initializer and says nothing about server-side effects.
- Callers connect `009e03a0` to rank-up case `0x1d` (`009e5600`), `009e0550` to BlueprintGenerator case `0x1b` (`009e5cc0`), and `009e05b0` to ShowTools case `0x1a` (`009e5e00`). `009e1010` reads records used by the tool-list response and browser-open payload.
