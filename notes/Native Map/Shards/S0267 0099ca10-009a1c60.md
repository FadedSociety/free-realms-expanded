## Store data and data sources

- Store item/bundle definition constructors, formatters, and cleanup routines are present at `0099D8D0`, `0099D9D0`, `009A00A0`, `009A0180`, `0099E540`, and `0099E5B0`. In particular, `0099D440` clears its row source, follows an instance chain at `+0x258 -> +0x1C8 -> +0x3413C` with next links at `+0x70`, appends each entry's `+4` field, and updates count `+0x25C`; caller thunk `0099F480` identifies the StoreBundleGroups callback context. It does not traverse a global group list.
- The category node is RTTI-identified at `009A0D90`, `0099FFA0`, `009A0020`, `009A0050`, and `009A0E50`. Its accessors expose member address `+0x34` and value `+0x28`; semantic names remain unknown. ## Shared containers and runtime helpers

- `0099F880` and `0099FAE0` drain a map head through entry-unlink helpers, while `0099F980` and `0099F8A0` unlink list heads, repair neighboring links, update counts, and invoke node cleanup callbacks. `0099F8A0` is used by the typed `SoeUtil::List<AppStoreBundleDefinition_const*,-1>` teardown at `009A0300`.
- `0099F900` manages an indexed min-heap: it appends previously unindexed nodes, stores heap indices/values, and repairs heap order; existing nodes are reheapified only when their value changes. This is distinct from a tree or inclusive-bound updater.
- The free-list block helpers `0099FB50` and `0099FD00` allocate metadata headers plus 0x0C- and 0x68-byte-stride nodes, index the blocks in trees, link nodes at head `+8`, and update count `+0xC`. They are block growers, not hash-bucket table constructors. `009A0570` pops the free-list head and `009A05E0` pushes it while adjusting tracked block occupancy.
- `0099F790` swaps two array contents through a temporary array and three `0099DC20` append-helper calls; it is slot 3 of the typed inline-eight StoreBundles pointer array vtable. It does not itself append an external range.
- Tree traversal helpers return node pointers despite Ghidra's `void` pseudocode: `0099D160`, `0099A0FD0`, and `0099A1C60` compute successors; `0099A1010` and `0099A1C20` compute predecessors. Their child/parent offsets and callers establish direction. Red-black balancing and fixup routines appear at `0099CA10`, `0099CE50`, `0099EB40`, `0099EC40`, `009A1230`, and `009A12F0`.
- Several Ghidra call arguments in this range are stack-cookie/SEH artifacts. Raw bytes show that `0099F540`/`0099F5A0` call base constructors with incoming `this` in ECX; `0099F620`/`0099F680` call base destructors with `this` in ECX; and stack cleanup thunks `0099F070`/`0099F100` receive the stack object's pointer in ECX. The cookie-shaped expressions are not real call arguments. The Set/List constructors likewise pass embedded storage at `this+0x0C` (`009A0F00`) and `this+0x10` (`009A1B50`) in ECX to their setup helpers.
- Fixed UTF-16 strings with inline capacities 8, 16, and 8192 use shared empty storage, heap fallback, and reference-count cleanup (`0099DDE0`–`0099EA40`, `0099F540`–`0099F680`). `0099EF90` only returns a static pointer at `0x0175B400`; its contents are not decoded. `0099A0C10` compares two byte strings and returns a signed less-than result; their domain is unknown.
