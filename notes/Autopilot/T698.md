# T698: draw 16 unplaced NPC rows at their one reference spawn

The brief listed 52 regional NPC rows (`wiring/placements/*.json`) whose
placement was `poi_anchor`/`unanchored`, each with one name-matched reference
spawn. This run places **16** of them as `legacy_data` (the placement class
`NpcVisibility::load` draws), and skips **36** under the brief's three rules.
Attempt 1 placed 22; on the newer tip the Sanctuary (T696) and Snowhill (T697)
briefs had already drawn bodies at six of those spawns, so those six rows are
skipped under rule 2 (see "Drawn since attempt 1").
No production Rust changed; the four hub files stay net **0** lines.

## Selection rule

For every listed row the spawn data was re-read from the cited
`FabledRealms.lua:<line>` and that source's `Resources/Npcs.json`: the spawn's
`ModelId`, `ModelFileName` and `NameId`, the locale text for the NameId, and the
spawn x/y/z/heading were compared with the row and with `talk_spawns.py`'s
placement JSON. NameId text normalises to the row's name for all 52. The
`(R)` reference-spawn coordinates are another emulator's placements, not a
native-client transform; the client model/name mapping is the client's own
`Npcs.json` + locale.

One row per spawn is drawn:

- prefer a row the active objective specs target (`quests_waiting`, then the
  quest's `npc_id`);
- otherwise prefer the row whose own zone/evidence matches the spawn
  (recovered `AreaDefinitions` in `restoration/piece_076.rs` — Blackspore,
  Briarwood, Merryvale, Sanctuary, Seaside, Shrouded Glades, Snowhill,
  Wugachug, Sunstone Valley — and the nearest `PointOfInterests.json` entry);
- duplicates are skipped with the reason recorded below.

## Threat note (secure-code-guardian)

A hostile client can send 26/8 (`CommandPacketInteractRequest`) with any u64
target and any claimed position. This task adds no parser and no new handler:
the existing `npc_interaction::check_range` looks up the regional row by id and
refuses an unknown id, another zone, or a target outside the 12 m interaction
radius. The new rows are static content; an out-of-range click sends no menu and
grants no item, coin, quest flag or reward. No client-controlled string is
written to content, and the spawn NameId is resolved server-side from the
client's own `Npcs.json`/locale, not from a packet. The changed fields are
positions/models only; the quest and vendor fields are untouched. The
refusal-path tests in `npc_interaction` and `npc_greetings_*` passed after the
change.
