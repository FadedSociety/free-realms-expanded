## Security threat note (secure-code-guardian)

What a hostile client could send, and why it is refused:

- Nothing new is client-triggered. `bind_npc_quest_catalogue` is called from
  `Gateway::load_gameplay` with the server-selected content directory; a client
  cannot choose content or invoke a rebind. The live-rebind change only changes
  which server-owned state a successful bind rebuilds from.
- A hostile save cannot inject quest state past validation: `from_split_content`
  runs `validate_state` (character id, quest count, statuses, pending
  offer/turnin consistency are checked) and returns `Err` before any field
  write. The wizard and shared-field refusal tests assert the full save bytes
  are unchanged around refused binds.
- The 49/1 decode is a test assertion; it reads server-generated packets and
  trusts nothing from the client. No item, coin, reward or quantity path is
  touched. The w64 decline is test-only and pays nothing.
- Refusals still consume nothing: no menu, offer, attempt counter or cooldown
  is touched on the bind path.
