# Security Model

M1 item **1.0**, for the approximately ten-player Free Realms playtest. **Do not expose the current binaries by merely removing loopback guards.** This is a read-only source review and proposed security policy, not implemented hardening or an exposure approval. The lead reviews this note before integrating M1 changes.

Evidence inspected on 2026-10-16 UTC (2026-10-15 in America/Denver). Unless prefixed otherwise, source citations below are relative to `prototype/osfr-tools/src/`; `Cargo.toml` means `prototype/osfr-tools/Cargo.toml`. Ranges are inclusive. All proposed limits, privileges, deployment choices and security rules are **reconstructed policy (R)**, not recovered original server behaviour. No new native-client function facts were recovered in this task.

> **Update 2026-10-15 (lead, the owner's decision):** L2's credential mechanism is now **Ed25519 challenge-response with per-server key pairs**, held by the launcher. Servers store only public keys, so no password goes to any server, including malicious private hosts. Argon2 is dropped. See [[Research/Multi Login Design]].

## Decisions (the owner, 2026-10-16)

1. **Admin and builder commands by role on the shared server.** On an exposed (VPN) gateway, `--dev-tools` stays refused (L5), but role-checked `realm` commands work for builder and admin accounts without it: the role comes from the server's account store at character binding (W120), every refusal is logged, players get no cheats, and admin-only commands stay admin-only. Studio stays loopback-only and off during exposed play. This completes L5 ("remote builder/admin actions need a separate server-owned account role check") so the host can run `realm role`, placement and the scavenger hunt on playtest night.
2. **The key-pair login broker may listen on the VPN address.** AUTH2 sends no secret (a signature over a server-bound one-time challenge; one-use 60 s tokens; non-enumerating fixed replies; per-IP and per-account failure limits), and the VPN encrypts the link. So `osfr-login --auth-bind <vpn-ip>:<port>` is allowed together with `--allow-lan`, and the launcher accepts a private-network broker endpoint. Bare internet stays closed: a public address is still refused.

## 1. Attack surface inventory

### Boundaries and evidence

Protect account ownership, character progress, world/content files, handoff keys, availability and private communication. Trust only host configuration and administrator-owned files. Treat an invited player, their PC and every UDP payload as untrusted. A local browser is also an untrusted caller of Studio. The intended flow is: untrusted network -> SOE peer -> authenticated login -> selected account/character ticket -> gateway session -> server-owned gameplay -> restricted save directory. Studio is a separate host administration boundary.

The current loopback controls are real: gateway CLI and constructor reject non-loopback binds, and receive filters peers (`bin/osfr-gateway.rs:295-297`, `bin/osfr-gateway.rs:1758-1761`, `bin/osfr-gateway.rs:1830-1832`). Login already accepts a `--bind` argument but rejects non-loopback values and peers; its configured gateway address must also be loopback (`bin/osfr-login.rs:64`, `bin/osfr-login.rs:82-84`, `bin/osfr-login.rs:468`, `login.rs:177-188`). M1 1.1 must address all these boundaries, not just socket binding.

Read first: [[Build Plan]], [[Build Ledger]], [[MMO Worker Contract]], [[Studio Toolkit]], [[World Builder]], [[Debug Harness]], [[../Reviews/Native Login Accounts 023623]] and the newest [[../Reviews/Native Round5 050310]]. The login review records account-store entry but does not establish native HMAC acceptance. Code still issues the fixed ticket for account 1 / character 1 (`login.rs:414-418`); the gateway still accepts that bypass (`bin/osfr-gateway.rs:760-764`).

**Observed drift:** the Ledger's social-without-trace defect is already addressed in this working tree: `application_handler` supplies byte-based routing, and known no-reply messages are forwarded independently of trace records (`gateway.rs:446-461`, `gateway.rs:1125-1149`). This note does not count that old defect as an outstanding vulnerability. Regression/native acceptance remains a separate gate. The other identity/save issues below are judged from code, not assumed from the Ledger. A concurrent CoinShop fix also now refreshes its inventory before each request (`gameplay.rs:1303-1305`); the previous stale-copy bug is recorded as addressed in source, with transaction/save-failure acceptance still open. A subsequent duplicate-cleanup guard now avoids saving when another active session owns the character (`bin/osfr-gateway.rs:2451-2463`); admission-before-file-access remains unproven.

Codebase-memory found `Session::dispatch_message -> Gateway::handle_at -> commit_outcome`; direct source inspection verified the dispatch branches below. Coverage check reported no recorded gaps for 17 paths, but `gateway.rs` had `metadata_changed`, so its source was read directly. ## 3. Ranked mitigations and Build Plan mapping

Exactly **12 ordered must-have items**. L1-L9 block the LAN playtest; I10-I12 additionally block internet access. These are proposed work items, not completed fixes. An item may be satisfied by removing/turning off its capability. Proposed **1.8** = bounded admission/packet hardening; **1.9** = safe administration/audit; **I1** = internet deployment gate. Only the lead updates the Plan and Ledger.

1. **L1 — Constrain exposure** (1.1; S03/S15). Keep loopback defaults. Require an explicit LAN interface/IP and an OS firewall allowlist for invited PCs; do not silently choose wildcard binds or automatic port forwarding. Separate advertised gateway address from listen address. Use an authenticated encrypted tunnel on a shared/untrusted LAN. Plain LAN play is limited to a private isolated network, with unique playtest-only credentials. Enforce Studio's literal loopback bind independently of gameplay bind.
2. **L2 — Real account login and independent connections** (1.2; S01/S02/S04). Replace name equality with provisioned per-account credentials and generic failure responses. Do not auto-register arbitrary remote names. Replace the global login `Option` with a bounded peer/connection map; unrelated handshakes must preserve existing sessions. Reuse versioned account JSON with an explicit migration; no database needed. Store salted Argon2id PHC hashes using the vetted RustCrypto `argon2` crate. Stdlib and existing SHA-256 cannot replace a password KDF: this is a justified new dependency, not a new custom crypto module. Rate-limit before hashing; reject empty/oversized passwords without truncation. Native compatibility of the discarded second field must be tested; if it is unsuitable, use the launcher to supply a short-lived login credential rather than invent an incompatible packet.
3. **L3 — One-use handoff with expiry** (1.2; S02/S14). Require account-store mode for exposed gateway startup; reject the default/fixed ticket and standalone nonempty-ticket route there. Retain the existing 32-ASCII-hex ticket shape. Use an OS-CSPRNG-generated opaque token whose server-side pending record binds account, character, expiry and unused state; atomically consume it before loading saves. A minimal shared host-owned pending-token store is needed because login and gateway are separate processes; use bounded records and the existing atomic replacement pattern, not a web service or JWT stack. On a single gateway, serialize consumption in its existing loop; isolate login creation from consumption so two writers cannot lose updates. Exact repeated handshake within an admitted connection may resend its cached response without redeeming again. The present stateless HMAC alone cannot implement one-use redemption. Do not put the handoff key on player PCs; rotate leaked keys. Existing `sha2` is reusable; a small vetted OS-randomness dependency is justified if no platform source is already exposed.
4. **L4 — Session identity and one save writer** (1.4 + 1.2; S03/S07). Keep account ids and character GUIDs in separate registry namespaces. Reserve selected character ownership before loading/migrating/writing a save. Reject duplicate admission without saving it or disconnecting the owner; only the active owning session may persist. Derive actor identity, roles and all paths from the authenticated binding. Keep current foreign movement-GUID and social actor checks. A new peer is a new authenticated connection, not a client-authorized transfer of ownership.
5. **L5 — Remove blanket dev authority** (1.5 + proposed 1.9; S08/S09/S10/S11). Reject **any exposed startup with `--dev-tools`**. This flag remains local solo tooling. Remote builder/admin actions need a separate server-owned account role check at every command entry, including activity/fallback paths; no role field from the client is authority. Players get no cheats; builders change only owned world records; admin can grant roles/global changes. Do not map every account to admin because a server flag is set. Studio remains disabled during exposed play until it enforces loopback **and** admin authentication: validate Host/Origin for browser calls and a random per-run token on privileged APIs, retain relevant headers, explicitly target an authorized session. Do not proxy Studio to the LAN. Role provisioning can be host-managed JSON; no RBAC framework needed.
6. **L6 — Cheap admission and rate budgets** (proposed 1.8 + 1.2; S04/S05/S13). Use bounded stdlib maps and monotonic-time token buckets. Starting values (R): 16 gateway sessions total including pending, 4 per IP (allow shared household testing), 5 s unauthenticated deadline unaffected by KeepAlive, 5 new handshakes/IP/s with burst 10, 5 credential failures/account/min plus 20/IP/min. Bound and evict limiter keys too. Apply packet-byte and application/action budgets before inflate, cloning, disk writes, chat similarity and fanout. Tune gameplay packet limits against native pose captures; do not rate-limit only chat or treat each reconnect as a fresh unlimited allowance. Over-limit traffic drops/gets a bounded refusal without disturbing admitted peers.
7. **L7 — Bound parser work and remove reachable panics** (proposed 1.8; S05/S06/S10). Reuse current checked readers, bounded inflate, reassembly and send queues; align transport logical-message limits with actual inbound parser needs instead of buffering 16 MiB before the 1 MiB rejection. Use per-family caps and a total reassembly deadline. Decode Studio hex using ASCII bytes before slicing; no `catch_unwind` workaround. Enforce exact header/body caps, an absolute request deadline and write timeout before Studio is re-enabled. Run T1-T3/T8 below. Keep content invariants as explicit errors where hostile packet sequences can violate them; do not mechanically replace proven fixed-length conversions.
8. **L8 — Preserve canonical saves/economy** (1.4 + 2.9 + proposed 1.9; S07/S11/S12). Reuse `replace_bytes`; keep exactly one owning writer per character and one serialized account-store mutation path. Restrict account/save/content/world/key directories to the service/admin OS identities, outside launcher-download roots. Never derive paths from names/chat. Retain the new CoinShop inventory refresh and the inline `Gameplay`/`CoinShop` staging; F195 corrected the pre-F155 assumption that NPC/shop state is shared behind `Arc<Mutex<...>>` (T019 removed the shared shop, F155 the shared NPC menu), and the bundle refusal is covered by `gateway_bundle_failure_does_not_commit_a_vendor_buy` and `a_failed_bundle_keeps_the_trainer_menu_usable`. Do not add a lock or disable buys. Prove rejected inputs and save failures leave authoritative state unchanged; atomic rename alone is insufficient. Before any enabled Studio content write, validate the specific schema, enforce real root containment including junction policy, and atomically replace. Keep a disposable tested backup/restore, not a new save-encryption layer.
9. **L9 — Chat controls and bounded audit** (1.4 + proposed 1.8/1.9; S13/S14). Reuse `SpamGate`, ignore lists, server-owned chat identity and existing trace redaction. Add a cheap per-account/IP action budget shared across typed chat, quick chat, friend/group requests and commands; bound chat history identities. Cap length before edit-distance work; choose a smaller playtest message limit only after native compatibility testing. Player reports/ignore and host-side kick/disable-account are enough for the small test; no speculative moderation platform. Record timestamp, stable account/session id, action, outcome and short reason, without names, chat, passwords or tickets. Rate-bound/rotate security logs and protect their files. Native markup handling remains an acceptance check.
10. **I10 — Protect the entire legacy channel** (proposed I1 + 1.1/1.7; S03/S15). Minimal internet option: invited PCs use an authenticated encrypted VPN/tunnel, and firewall permits legacy login/gateway UDP only from that private interface/peer set. Protect both login and gameplay, not just a future web login page. Bare internet UDP stays closed. Public access without such a tunnel needs a separately reviewed authenticated transport/launcher design compatible with this client; swapping RC4 for an invented cipher is outside M1.
11. **I11 — Internet admission and operational limits** (proposed I1/1.8/1.9; S05/S14). Measure unauthenticated egress amplification and retransmission under loss. Reject oversized/tiny-buffer handshake abuse before expensive session creation; use network-edge filtering/rate limits, with a stateless return-routability cookie only if native handshake compatibility is demonstrated. Do not invent a handshake extension the client cannot answer. Set process memory/disk quotas and log rotation, patch/audit pinned dependencies, restrict service OS rights, document revocation/restart/backup recovery. VPN admission reduces source spoofing but does not excuse hostile admitted peers or replace in-process limits.
12. **I12 — Execute the security gates** (proposed I1, M1 1.6 and M3 3.6; all threats). Run the tests below through actual login/gateway routes, independent review, then the lead's two-PC/native HMAC check. Run ten bots for the existing planned hour with bounded memory, stable tick latency and intact saves, including one abusive bot. Capture applied limits and results. No internet gate closes on unit-test count alone.

Password reference: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) recommends Argon2id and gives a minimum 19 MiB, two iterations, parallelism one. Benchmark bounded concurrent verification before choosing production costs. [RustCrypto argon2 documentation](https://docs.rs/argon2/0.6.0/argon2/) provides password hashing and PHC verification; pin/review the compatible version and features during implementation. Current direct dependencies are only miniz_oxide, serde, serde_json and sha2 (`Cargo.toml:9-13`). No dependency was added here. [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) supports generic auth failures, throttling and protected credential transport. These are external security references, not Free Realms recovery evidence.
