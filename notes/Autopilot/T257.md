## Threat note (secure-code-guardian)

Attack surface: any client can send 26/8 (click), 26/10 (menu choice), 26/6 (dialogue row), 49/2 (accept) and 49/14 (turn in) with arbitrary ids at any time from any position.

- Forged/unknown target: `content_npc_key` resolves the runtime GUID through the server's `NpcVisibility` content-key map; a GUID no extra/legacy spawn binds yields no menu, and both new actors are static content. Tested: forged runtime actor changes nothing.
- Forged choice/offer: 26/10 must name an option of the open menu; `QuestEngine::offer` requires the server-side giver, prerequisite, job and membership checks. A forged 49/2 for W4 before W1 changes nothing. Tested.
- Duplicate/replayed turn-in: 49/14 settles only the saved `pending_turnin`; a duplicate pays nothing (tested three times). The reward is server-authored content (5 coins, 25 XP) with an empty item list; the client cannot supply an amount, item id or result.
- Locked job/reward: the job gate hides W1/W4 from non-Warriors and `finish_turnin` still refuses a reward whose profile is locked (`rewards::locked_job_profile`); the trainer remains the only unlock. Tested: inactive Warrior gets no offer and no state change, while the rank-gated trainer menu still offers "Become a Warrior".
- Range/zone/busy: the existing 26/8/26/10 router re-checks the Snowhill zone, the 12 m radius and the shared busy table; an out-of-range 26/8 is refused with the save byte-identical. No new entry path or bypass was added.
- Isolation: each refusal is a per-request result; the two-player test shows one player's refused turn-in leaves the other player's state and payout intact.
- Economy: no free item is added; the 5/25 rewards cannot be re-granted (pending turn-in is cleared before the grant; replays are no-ops).
