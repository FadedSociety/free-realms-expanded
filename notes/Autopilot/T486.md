## Threat note (secure-code-guardian)

A hostile client controls the 66/3 bundle id, store id, quantity, tint and tracking id. The price, the grant and
the adoption come from the server's catalogue: only a listed bundle orders, quantity must be 1, gifts and
coupons are refused, and the adoption walks only the instance ids the server's own grant reported, so the client
cannot name a pet, species, model, slot or count. A replayed key is answered from the persisted order window and
grants nothing, so no second pet or debit. The roster is capped at 50 (MAX_PETS); past it the unit stays owned.
A refusal (busy, funds, bad bundle) returns before any state is staged and changes nothing (asserted).
The tint is the one client-chosen value reaching the pet record (unchanged for every Marketplace item).
