## Security note (secure-code-guardian)

A hostile client can send a `49/14` for any quest id, replay a paid turn-in,
or send a truncated/trailing-byte body. The decoder requires exactly 10 bytes
and the family/subtype header; `QuestEngine::finish_turnin` refuses unless
`state.pending_turnin == Some(quest_id)`, so a forged or duplicate id is a
`NoPendingTurnin` denial. The reward is applied by the server's
`rewards::apply_grant` with the idempotent `quest:<character>:<quest>` key and
only after the server-owned pending turn-in. The test snapshots the serialized
state before every new refusal and asserts byte equality afterwards, including
the coin balance; no client-reported result grants anything. The C3 canary
changed only server content, not a client field.
