## What changed

- **Finding 1 (BLOCKER), the refusal exception.** `card_service::LaunchTickets::redeem` now spends
  the ticket only on a match: it reads the ticket, refuses `expired` / `character_mismatch`
  without removing anything, and removes it only on success. A refused 411 can no longer burn a
  valid launch ticket, so the exception the review asked the lead to accept no longer exists and
  checklist 1 holds with no exception. No security is lost: spending on presentation could only
  destroy a ticket the presenter already holds (a wrong ticket value is not in the map at all),
  and the retail 411's character id is empty (T804), so a non-empty mismatch is never the
  credential. The sign-off the review asked for is in the register: T770 (2026-10-27) accepts the
  card listener that redeems the T764 store ("single use, TTL, bound to the character") and T765
  (2026-10-27) accepts `LaunchTickets` as the per-session store; T804 and T805 are lead builds on
  top of that. Regression: `a_refused_card_login_changes_nothing_and_the_next_one_still_logs_in`
  drives `card_service::reply` with a client-shaped 411 and the real store (a name-valued
  CharacterID refused, then the empty-id login succeeds, then single use), and
  `a_wrong_character_expired_replaced_or_malformed_ticket_is_refused` snapshots `outstanding()`.
- **Finding 2 (MINOR), the decimal CharacterID.** Answered by T804/T805 and re-checked here: the
  exe's card manager `00ad47f0` builds the DLL command line through `10D2240` (`--sessionID=%s`),
  `10D2160` (`--username=%s`), `10D21D0` (`--realm=%s`), `10D22B0` (`--character=%s`) and
  `10D2450` (`--ticket=%llu`); the exe's `--`-prefixed strings contain no `--characterID`, so the
  411's CharacterID is empty. `redeem` accepts the empty id and requires a non-empty one to be
  the owner's decimal; tests cover empty, a space, a name, `12x` and `+<ticket>`, and assert the
  ticket survives each refusal. (The DLL writer `1017b700`, reader `1017b950` and describe method
  `1017b4b0` are cited from the T763/T764 decode; this workspace's read-only IDA database is the
  exe, not the DLL, so the writer itself cannot be re-queried here.)
- **Finding 3 (MINOR), the store bounds.** `LaunchTickets` now has a redacted `Debug` (a ticket
  never reaches a trace), a `MAX_TICKETS` capacity refusal (64, like `login_auth::MAX_TOKENS`),
  at most four draws instead of an unbounded `loop` (`draw_ticket` / `TICKET_DRAWS`), and the
  mint sweep still runs before the cap check. Redeem deliberately does not sweep (a refusal must
  change nothing); the cap bounds the table and the next mint drops expired rows. The TTL is
  bounded 1 s to 10 min at the content load (`card_game::Content::validate`, the review's allowed
  alternative), and `now_ms` is documented as the one monotonic clock for mint and redeem.
  Monotonic time stays a contract, not enforced state: a backwards clock could only shorten or
  extend a 60 s window, and refusing would wedge logins until it caught up; both callers pass one
  server-start elapsed value.
  Tests: a full table refuses and the next mint makes room; Debug names no ticket; a broken
  generator is refused after four draws and a random-source error is not retried (inline
  `card_service::tests`).
- **Finding 4 (STRUCTURE).** The module header now says the file holds the ticket store and no
  socket (the listener is `bin/osfr_gateway/card_listener.rs`, the session store
  `gameplay/card_launch.rs`). `outstanding()` is documented and is now used by the production cap
  check, so it is not a test-only accessor.
- **Finding 5.** This file carries the evidence; the canaries and gates below are the run record.
  T764's note is left as its historical record (the brief says not to edit other notes); its

## Security threat note (secure-code-guardian)

- Attack surface: the card listener accepts 411 frames from a local TCP peer (loopback, or the
  private address with `--allow-lan`). A hostile client can send an empty or malformed ticket
  (`no_ticket_field` / `ticket_not_decimal`: nothing read, nothing removed), a guessed 64-bit
  decimal (not in the session's map -> `unknown_ticket`, nothing spent), another session's ticket
  (the scan tries each live session; only the minting one matches, and only once), a wrong or
  name-valued character id (`character_mismatch`, ticket kept), an expired ticket (`expired`,
  ticket kept until the mint sweep), and repeated frames (the listener reads at most 64 KiB per
  poll, 16 connections, 4 per address, a 30 s login deadline and capped event logs). Mint is
  server-triggered by the 39/37 inside the authenticated session and uses that session's own
  guid, never a packet field, so the table cannot grow per client-chosen character. Tickets are
  64-bit OS random and never logged (redacted `Debug`; listener events carry lengths and reason
  words only).
- The refusal change removes a denial of service on the player's own credential and widens
  nothing: the ticket is still the only secret and is still single use.
