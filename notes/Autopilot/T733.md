# T733: test-suite audit (obsolete, duplicate, superseded)

Brief: the owner asked "how many of those tests are obsolete at this point?" The audit was made at tip `54e6e094`
(5,807 listed, 5,646 run, 161 ignored); this diff is ported onto the integration tip `62ed8753` (5,817 listed,
5,656 run, 161 ignored — plus T524's 9 new `collection_node_pickups` tests, F735's one `sanctuary_named_npcs`
test and T721's runtime guard). Counts come from `--list` on every test executable. Line numbers are at
`62ed8753` unless a line says otherwise.

**Answer: almost none are obsolete.** Exact-body search, near-body search (MinHash, Jaccard >= 0.6) and
strict-subset search over all 4,665 `#[test]` functions at the audit tip found 4 true duplicates and 0 clear
superseded or obsolete tests. The lead's Haiku audit (`lab/references/quest-lines/testaudits.json`, status
final, 21 non-keep verdicts) was checked test by test: 13 removed, 7 kept and 1 skipped (section "Lead audit
disposition"). With the two self-found duplicates, this diff removes 15 source tests / 23 protected names:
listed 5,817 -> 5,794, runnable 5,656 -> 5,633.

**The redundancy is inclusion, not obsolete tests.** Eight test files `#[path]`-include
`src/bin/osfr-gateway.rs`, so the gateway's 139 inline tests compile and list in every one of them (1,112 extra
names). At the audit tip those copies also *ran* (1,960 s of binary time in `int-batch-022255`); T721

only their own tests (96.1 s total in `lab/autopilot/logs/suite-times.json`) while the bin target still runs
every body once (130.0 s for 139). The remaining included copies are small (< 2 s). That class therefore needs
no removal; only the compile/list cost remains, and fixing it is the lead's `Server`/`Session` library move.

## Follow-up 1 (biggest win): stop re-running the gateway tests in 8 binaries — T721 did the runtime half

Evidence at the audit tip: in `int-batch-022255.txt` the 139 gateway inline tests appear in
`unittests src/bin/osfr-gateway.rs` and again, name for name (set equality, 139 common), in
`tests/{bot_smoke, gateway_npc_offer_runtime, multiplayer, playtest_gateway_smoke,
shared_field_interest, shared_field_state, shared_instance_invites, shared_world_membership}.rs` under the prefix
`gateway_runner::` (`gateway_runtime::` in `gateway_npc_offer_runtime.rs`). Cause: those files do
`#[path = "../src/bin/osfr-gateway.rs"] mod gateway_runner;` to reach `Server`/`Options`, and the file's
`#[cfg(test)] mod tests; ...` lines compile in every test crate. Same source, same fixtures, nothing depends on the
includer.

T721 (`df9e547b`, before this port) added `test_support::bin_test_target` early-returns to 135 of those copies:
each of the eight harnesses prints 135 `embedded gateway copy skipped` lines and runs only its own tests, while
`unittests src/bin/osfr-gateway.rs` still runs every body once. Measured at `62ed8753`
(`lab/autopilot/logs/suite-times.json`): the eight harnesses total **96.1 s** (was 1,960 s in the audit batch;
T721 measured 2,138 s -> 134 s under a foreign build's load) and the bin target **130.0 s** for its 139 (138 after
this diff). The 1,112 extra names still list and compile; only the runtime cost is gone. No removal is needed.

What remains is the **real fix**, which is not test-only: move the gateway's `Server`/`Session` into a library
module so includers `use` it instead of re-compiling the whole hub. That also cuts the eight extra gateway compiles
and the 1,112 listed copies. Lead-only (`src/` plus the hub); not attempted here.
