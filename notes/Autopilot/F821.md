## Security threat note (secure-code-guardian)

Attack surface: the card TCP listener (loopback, or the private address with `--allow-lan`),
unauthenticated 411 frames. A hostile client can send:

- no/empty ticket or a non-decimal one: `no_ticket_field` / `ticket_not_decimal`, nothing read,
  nothing spent;
- a guessed 64-bit decimal: not in any live session's map, so `None`/`unknown_ticket` and nothing
  spent;
- another session's ticket: only the minting session holds it and the listener's scan stops
  there, so only its own store can change;
- a wrong or name-valued character id: `character_mismatch`, ticket kept, and the character
  returned is the ticket's owner, never the presented id;
- an expired ticket: `expired`, kept until the next mint sweeps it;
- repeated frames: per-connection and per-address caps, 64 KiB poll, 30 s login deadline, capped
  event logs.

Mint is server-triggered by the authenticated session's own 39/37 and uses that session's guid,
never a packet field, so the per-session store cannot grow per client-chosen character; with the
unreachable 64-row cap gone there is no false bound to trust (the real bound is one row per
session, documented on the type). The finding-3 fix removes a self-denial: a failed draw no
longer destroys the player's previous ticket (which only forced a relaunch); it widens nothing.
Tickets are 64-bit OS random, non-zero, unique among outstanding ones, and never logged (redacted
`Debug`; the listener logs reason words and lengths only).
