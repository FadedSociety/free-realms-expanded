## Result

Fixed all four BLOCKER findings from `lab/autopilot/reviews/ca6038e-F117.md`. The derby now
grants nothing, session reset retires a live match again, both predecessor save shapes load, and
both derby exits reuse the canonical 39/19 writer. Net tracked diff: **-282 lines** (251 added,

## Findings and fixes

1. **BLOCKER, fabricated contacts still earn rewards.** The derby economy is removed end to end
   instead of tightened: `DerbyReward` / the content `reward` row, `DerbyGateway::grant`,
   `DerbyCloseOutcome`, `DerbyService::handle_close`'s grant application and the reward state
   branch in `Gameplay::handle_derby` are gone. `26/42` after results now retires the match,
   restores the job, sends the existing status carrier and outfit broadcast, and sends **no**
   `50/1` bundle. A client-supplied `34/16` report can still change the non-economic match score
   (server-owned NPCs have no recovered AI), but it cannot mint coins, XP or items.
   - New regression: `tests/derby_route.rs::gameplay_routes_the_npc_offer_and_closes_a_fabricated_contact_without_paying`
     drives the real `Gameplay` route with a stationary identity pose at the NPC's authored start
     transform, a bounded impact, results and Close; it asserts the coin balance is unchanged, no
     `50/1` bundle is sent, the job/outfit are restored and a replay is inert.
   - `tests/app_fuzz.rs::active_derby_hostile_records_cancel_and_tick_transitions_are_bounded`
     repeats the fabricated sequence through `Gateway::handle_at` and now asserts unchanged coins
     and no reward bundle.
   - The old `last_paid_unix` / `reward_cooldown_s` pacing guard was deleted with the payout: a
     cooldown only paced a reward that no longer exists. Removing that admission guard is a
     lead-only rate-limit change and is still awaiting lead sign-off (F206 review, blocker 2);
     F206 made the retired `reward` and `reward_cooldown_s` keys accepted-and-ignored so an
     F117-era operator package still loads instead of failing the whole world load.
2. **BLOCKER, reset left the match active and job 49 selected.** `Gameplay::reset_session` again
   retires the connection-local match and restores the prior profile (`gameplay.rs:1517` →
   `retire_derby_for_reset`, `gameplay/derby_session.rs:35`). This is the same gameplay hook F117
   removed, not a session/teardown change in `gateway.rs` or `bin/osfr-gateway.rs`; F206 flags it
   as a lead-only teardown change awaiting sign-off.
   - New test: `tests/app_fuzz.rs::reset_during_a_running_derby_retires_it_and_restores_the_job`

     `None`.
3. **BLOCKER, F117 saves became unreadable.** `DerbyGatewayState` (`derby_gateway.rs:62-72`) now
   decodes both predecessor shapes: T023's `{"previous_job":N}` and F117's
   `{"last_paid_unix":N}`. Neither field is written again (`Gameplay::state` persists
   `derby: None`; the profile snapshot already carries the restored job). `Gameplay::load`
   (`gameplay.rs:797-799`) calls `restore_saved_derby_job` (`gameplay/derby_session.rs:6`), which
   validates `previous_job > 0` and restores it exactly as T023 did. F117's `last_paid_unix` is
   accepted and ignored because no derby run can pay; there is no cooldown left to initialize.
   - New test: `tests/derby_route.rs::predecessor_and_paid_epoch_derby_saves_load_and_restore_the_job`
     writes real save documents and reads them through `game_store::load_or_create` (the reader
     the finding names), then `Gameplay::load`. The T023 shape (active profile still 49 plus
     `previous_job`) restores the prior job; the F117 shape (`last_paid_unix`) loads.
   - The finding text says "initializes an unpaid cooldown". The cooldown was part of the deleted
     payout guard, so the compatibility requirement is satisfied by loading the epoch without
     applying a gate; no derby entry can pay in this build.
4. **BLOCKER [STRUCTURE], duplicate 39/19 writers.** `minigame::state_remove_packet` is now
   `pub(crate)` (`minigame.rs:739`) and both derby exits call it: cancellation (`derby.rs:1078`)

   A future correction to the canonical lifecycle writer now reaches every derby exit.

## Security note (secure-code-guardian)

Threat: a hostile client owns the 34/* match stream. It can register, acknowledge the phases,
report an arbitrary finite stationary pose at an NPC's authored start transform, report any
bounded impact, drive the match to results, and send 26/42. It can also send stale or malformed
39/6, 39/7, 39/5 and 26/42 records, or call the NPC gate repeatedly.

Why it is refused or harmless: the sender is the authenticated character bound at entry; the
target must be a server-created driver; the instance is server-owned. Contact reports are still
range/age/finite/bounded checked, but more importantly **no code path turns a derby match into
coins, XP or items**: the reward content, grant builder, reward application and reward bundle were
deleted, and Close only retires the match. The regression asserts the coin balance and absence of
50/1 for the exact fabricated sequence. Stale/malformed 39 records leave the service unchanged
(tested); a cancelled or reset match is dropped. The save decoder now accepts only the two
documented predecessor keys; any other key still fails closed, and a non-positive legacy job
fails the load. No client quantity or item id reaches the economy.

## Checklist

1. **Refusal changes nothing.** New refusal tests: `inactive_close_is_inert` (inactive close
   returns false, phase `None`); stale/foreign 39/6, 39/7 and malformed cancels keep the phase
   and the gateway snapshot unchanged in the app_fuzz derby test; `busy_derby_refusal...` keeps
   the exact menu and full `GameplayState` unchanged. Canary 2 (removing reset cleanup) and
   canary 1 (adding a grant) fail the matching tests.
2. **Rollback covers all state.** `DerbyGateway::close`/`cancel`/`handle` stage a service clone
   and commit only on success; `Gameplay::handle_derby` itself runs on the gateway's staged
   `Gameplay` clone (`handle_in_world` replaces `*self = staged`). No shared `Arc`/`Rc` side table
   is touched by a refused request. The only shared object, `NpcInteraction`, is unchanged.
3. **Apply deltas, never restore old snapshots.** The close no longer replaces inventory or
   profiles with a captured `RewardState`; it mutates only the active job through `restore_job`
   (delta) and leaves inventory/coins/position untouched. The route test proves coins stay equal
   across the fabricated match and Close.
4. **Busy rules are mutual.** Derby is still an `Occupation` row (`gameplay/occupation.rs`),
   entry still checks `activity_busy`, and `derby_active` still intercepts ordinary requests
   while a match lives. `active_activity_refuses_derby_without_consuming_the_npc_menu` and
   `busy_derby_refusal_keeps_the_exact_menu_for_a_retry` pass; the reset test proves the
   interception ends with reset.
5. **Every entry path is gated.** The configured NPC menu is still the only entry path; it checks
   the gate list, active match, `activity_busy`, and (before the change) the paid cooldown. The
   local `DerbyGateway::begin` helper is not routed. No second handler was added. Removing the
   cooldown removes a guard only because the payout it guarded is gone.
6. **Reachable in production, tested through it.** Route tests use `Gameplay::handle_in_world`
   (the gateway's production dispatch) and app_fuzz uses `Gateway::handle_at`, `tick_at` and
   `reset_session`; no test calls a copy of the admission or close logic.
7. **Survives reconnect.** The predecessor-save test reads real documents through
   `game_store::load_or_create` and asserts the restored job for T023 and a successful load for
   F117. New saves persist the prior job through `saved_profile_state` (existing mid-match test
   still passes) and no derby marker.
8. **Every exit path restores the player.** Offer cancel (`26/42` in Lobby), running quit
   (`39/6`), pending cancel (`39/7`), lobby timeout, results Close and reset all exit the service
   and restore the prior job; tests cover each, and the invalid variants are inert.
9. **Economy safety.** The derby has no payout: no frame, packet, client value or score can mint
   coins/XP/items. The fabricated-contact regression asserts unchanged coins and no `50/1`; the
   job-49 starter outfit remains an unlock-once grant (`first_time`) and the shipped catalogue
   rows it uses carry no sell price, so the entry path adds no farmable value. No client quantity
   or item id is trusted by this change.
10. **Wire format matches the client reader.** No format changed. 39/19 is header-only
    (`009bf190`, confirmed in the minigame guide), 39/6/39/7 are `[instance,-1,-1]`, 39/5 and
    26/42 are unchanged; the removed 50/1 is a standard reward bundle, not a derby format.
11. **Unique ids.** Unchanged: instance ids still allocate from `FIRST_DERBY_INSTANCE` with a
    checked increment and are never derived from client bytes.
12. **Others see changes.** The Close still goes through `restore_job` ->
    `announce_profile_outfit`, and the route test asserts the `35/7` outfit broadcast and the
    `35/20` status packet.
13. **Content works end to end.** The derby is deliberately non-rewarding until authoritative
    collision evidence exists, so the reward clause does not apply; the test asserts the real end
    state (results -> Close -> match retired, job and outfit restored, no reward) rather than an
    intermediate flag. Content validation still rejects a package with neither score target nor
    time limit.
14. **Values live in data.** Removed tuning; no new compiled constants. The remaining timers and
    radii stay in `derby_entry.json` with the existing sanity bounds.
15. **Canaries break production code.** All four canaries edited production code, failed the
    named test, and were reverted; the final tree is green.
16. **Hands off session plumbing.** `src/bin/osfr-gateway.rs` and `src/gateway.rs` are untouched;
    no session creation, transaction or save ordering changed. **This commit does change teardown
    behaviour through the gameplay hook:** `Gameplay::reset_session` calls
    `retire_derby_for_reset` (`src/gameplay.rs:1517`), reached from `Gateway::reset_session`
    (`src/gateway.rs:1468`); it drops a live derby and reactivates the job it replaced. That is
    the F117 cleanup restored, and it is a LEAD-ONLY teardown change awaiting lead sign-off
    (F206 review, blocker 1). The regression is
    `tests/app_fuzz.rs::reset_during_a_running_derby_retires_it_and_restores_the_job`.
17. **One player's error never stops the server.** The change adds no shared-tick work and no
    `?` into a shared loop. Derby close/cancel errors are the per-session `io::Result` the
    existing handler already contains; the reward overflow/`apply_grant` path that could fail is
    deleted. Hostile 34/* records still return bounded ordinary outcomes (app_fuzz).
18. **A type's rules live on the type.** `DerbyGatewayState` documents both fields on the type:
    `previous_job` is restored at load, `last_paid_unix` is accepted and ignored, and neither is
    written. `DerbyGatewayContent`'s doc says reward rows are absent. `GameplayState.derby`'s doc
    points at the predecessor-only role.
19. **Hot paths stay cheap.** No per-tick cost was added: the tick path is unchanged except the
    lobby removal packet now calls the existing helper. The close path clones the service once as
    before and does strictly less work (no grant, no inventory/profile replacement). Reset runs
    once per connection teardown.
