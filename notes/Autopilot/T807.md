# T807: the gateway starts from repo data alone, no captured reference folder (release blocker, lead brief 2026-10-27)

## Why
The first public release must not ship `lab/references/rust-gateway-reference`: 46 startup templates captured on 2026-10-08 from the
community server. They carry that server's own text (a welcome message of its name and test-build notice, a Halloween greeter named
after it), the capture character's and its pets' names, and a manifest with a home path. The gateway still required the folder
(`--reference`, `src/gateway.rs` `load_reference`): it hash-checked all 46 templates, took the initial character from the manifest,
parsed template 7 as the typed self-data base and found the typed startup snapshot through `configured_path`.

## Change
`--reference` is optional. Without it every startup message is built from `<content>/startup/` (new, in `data/content`):

| File | Holds | Source and scrub |
|---|---|---|
| `manifest.json` | client version `1.910.1.530630`, initial character (guid 1, zone 0, spawn pose), `provenance` notes | the old manifest's values; its capture paths and hashes are not copied |
| `self_data.json` | typed defaults of the self-data message (opcode 12, `startup_selfdata::SelfData`) as JSON; unnamed spans stay hex, exactly as the reader keeps them (R) | template 7 parsed by `parse_self`, then reduced to a fresh character: name `New Player` (R), `account.birthday` 1240963200 (2009-04-29 00:00 UTC, R), `identity.unknown_identity_u64` 0 (R), the server tag and the nine names in the variable (pet) rows (R) cleared, inventory emptied (slot rows stay), nothing collected, empty quest journal |
| `snapshot.json` | the typed startup snapshot of the other 45 messages (`StartupSnapshot`) | the lab snapshot; the MOTD is our own text (R), the Halloween greeter's nameplate loses the server name |

`tests/startup_content.rs` carries the scrub (`scrub_self`, `scrub_snapshot`), the exporter and the comparison, both lab-only
(`OSFR_GATEWAY_REFERENCE=<capture folder>`, `--ignored`): `export_scrubbed_startup_content` rewrites the three files and
`tests/fixtures/startup_golden.json`; `content_startup_equals_the_captured_startup_except_the_scrub` builds the startup with the
capture and from content and requires every message to match, apart from message 7 (compared field by field after the scrub), and
requires the unscrubbed 42 to carry the capture's own SHA-256 digests (not 6 and 7, built differently on purpose, and not 12 and 45,
the two scrubbed texts).

With `--reference` the old full validation of the 46 templates still runs (lab use); `OSFR_GATEWAY_STARTUP_SNAPSHOT` still
overrides the snapshot there. Content mode never reads that variable.

Launch without a reference folder: `osfr-gateway 127.0.0.1:PORT --state <save> --content <content dir that contains startup/>`.
Without `--reference` and without `--content` the gateway refuses to start. `scripts/run-local-baseline.py --rust-gateway --content DIR`
does the same for the native harness (`--rust-reference` unchanged).

Follow-up (coordinator, 2026-10-27): the capture account's `account.birthday` and `identity.unknown_identity_u64` are replaced by the neutral
(R) values above, and `tests/startup_content.rs` now fails if either capture number appears in the files or in a built message (JSON text and
little-endian wire form). 0 is safe for the identity: the client reader `00944fe0` stores the u64 at object +0x3c0 without checking it, and its
only accessor (`00ad16d0`) has no static caller or vtable entry. The claim codes and definition blobs stay. `AGENTS.md` now says the gateway builds
startup from `data/content/startup` and `--reference` is the optional lab validation.

## Structure
- `src/gateway/startup_source.rs` (new): `Source` (`Reference(dir)` | `Content(dir)`), `Base` (client version, initial character,
  self-data defaults) and the three constructors `Gateway::content_state`, `load_from_content`, `load_gameplay_from_content`.
  `Gateway::load_internal` takes `impl Into<Source>`, so `load`, `load_gameplay`, `load_with_startup_snapshot` and `reference_state` keep
  their signatures and every existing caller (about 150 test sites) is untouched. Hub budget (spine ratchet): `gateway.rs` 2127 -> 2124.
- `src/bin/osfr_gateway/startup_source.rs` (new): `Options::reference_dir`, `initial_state`, `load_gameplay` choose the source; the
  hub `osfr-gateway.rs` 4631 -> 4629. `Options.reference` stays a `PathBuf` (empty without `--reference`) so the bin test modules
  that assign it are unchanged.
- `src/startup_selfdata.rs`: `Serialize`/`Deserialize` on the `SelfData` tree; byte spans are hex strings (`hex`, `hex_rows`).
  The JSON of the captured template round-trips back to the identical packet (checked once in the lab).
- `scripts/content_check.py`, `scripts/build_item_catalogue.py` skip `startup/` (a typed snapshot, not authored records; it would
  add 60 false errors). `scripts/run-local-baseline.py` gains `--rust-gateway`.

## Threat note
- Input is repo content the operator names with `--content`: files are opened with `read_bounded` (regular file, no symlink, 64 KB
  manifest, 16 MB self data; the snapshot loader keeps its own 16 MB bound); hex spans are length-checked by `TryFrom`; a
  self-data file is serialized once at load inside `catch_unwind`, so a hand-edited file fails at start, not as a panic at the first
  login; the manifest's initial character goes through `CharacterState::validate`, and a snapshot of another zone is refused.
- Nothing in auth, roles, transport, admission or the account store changed. Login still checks the client version string, the
  ticket and the GUID the same way.
- Content mode ignores `OSFR_GATEWAY_STARTUP_SNAPSHOT`, so a stray environment variable cannot swap the shipped snapshot.

## Open gaps (R)
- The snapshot's welcome-screen claim codes (six promo codes with client-locale ids) and the item-definition and ability blobs are
  kept: they are client-referencing game data, not the server's text, but they are the biggest "capture-derived" part (1.9 MB).
- A gateway without gameplay (`load_from_content`) sends the fresh character, not the capture's inventory or quests (the live
  gameplay path overwrites both anyway). Native check with no `--reference` is the lead's.
- `tests/gateway.rs` `actual_original_client_capture_when_explicitly_configured` (ignored, lab) already fails on index 6 at the base
  commit: T437 sends `closeWindow` where the capture has `Exit`; its sibling `built_startup_sequence_matches_...` carries that exception.
