## Reconstructed rules

- `(R)` Two services built in one process must not share a generation seed;
  the per-service counter provides that deterministically.
- `(R)` Generations start in the high half and group ids ascend from 1, so an
  echoed token cannot alias a live group id while a process creates fewer
  than 2^31 groups.
- `(R)` A restarted process gets a fresh base; a held pre-restart token is
  refused with 40/5 code 3 (alias chance about 2^-31).
- `(R)` Pending invitations and generations stay volatile; no save format
  changed.

## Security threat note (secure-code-guardian)

Attack surface: family-40 40/1/40/4/40/5 packets from any authenticated
client.

- **Replay across a restart.** A client holds the 40/1 pop-up while the server
  restarts, then the leader re-invites the same target. The new process base
  makes the held token a mismatch with probability about 1 - 2^-31; the stale
  40/4 is refused with 40/5 code 3 and changes no live row or membership. The
  token is a pop-up discriminator, not a secret: an attacker who can replay
  it must already act as the authenticated target.
- **Forged token.** Any client u32 is compared with the single pending row
  for the session's authenticated character guid; zero, the group id,
  another invitation's token and a truncated body are refused. The high-half
  namespace does not skip that compare or address another invitation.
- **Group-id confusion.** A stale same-group pop-up cannot be accepted by a
  group-id guard: generations are disjoint from group ids (canary B).
- **Refusal state.** The changed refusal (full roster) still returns before
  the pending row is removed; canary C. There is no item, coin, XP, role or
  chat effect.
- **Amplification.** Unchanged: one 40/5 reply per refused 40/4, no fanout.
- **Arithmetic.** Wrapping add then OR; the result is nonzero and in the high
  half; no client value is used in arithmetic and there is no panic path.
- No chat budget was changed (lead note L016).
