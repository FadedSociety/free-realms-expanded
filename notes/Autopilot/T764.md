# T764 - Card Duelist launch tickets and the named 411 fields (lead build, security, 2026-10-26)

Stacked on T763. Decode: `lab/content/tcg/analysis/lead-login-decode-2026-10-26.md` (Slice A facts).

## Client facts

- FreeRealms.exe's card manager (`00ad47f0`) starts the DLL with `--ticket=%llu`, the 64-bit launch ticket the
  server sent in 39/0x28 (stored by slot 25 `00ad32e0`), and the character guid; the DLL's 411 carries them as
  the Ticket (+216) and CharacterID (+188) strings (names from the describe method `1017b4b0`).
- The type-16 manager sends 39/0x25 when it is ready for the ticket (`00ad4f50` state 2 -> 5).

## What changed

- `src/card_service.rs`:
  - `LaunchTickets` (lead security): `mint(character, now)` draws a non-zero u64 from `getrandom`, replaces any
    ticket the character still holds and drops expired ones (the table is bounded by live launches);
    `redeem(ticket, character, now)` parses both as strict decimals, spends the ticket whether or not it matches
    (no second guess), and succeeds only for its own character before expiry.
  - `SessionLogin` has a named field for every 411 field (platform, challenge key, parent-session flag, login
    client, locale, character name, character id, ticket, namespace) instead of a string list.
  - `reply` hands the whole `SessionLogin` to the caller's check, so the listener can redeem ticket + character.
- `tests/card_service.rs`: fixtures carry the real field values and order; ticket tests below.

## Gates run

- `tests/card_service.rs`: 7 passed - every 411 field decoded by name; a minted ticket logs its own character in
  once (81 success with account 42, then refused); another character's id spends the ticket; expiry; a second
  launch replaces the first ticket; malformed decimals (empty, "+n", " n", "nx", u64 overflow) never match and do
  not spend a real ticket; expired tickets are dropped on mint.
- Canary: a non-consuming `redeem` (`get` instead of `remove`) fails the single-use and wrong-character tests
  (restored).
- Still green: spine_rules 1, `cargo test --no-run` (every target compiles); rustfmt clean.

## Checklist

1. A refusal changes nothing but the presented ticket, which is spent by design (no retry on a guessed ticket).
2. Rollback: no transaction; the table is the only state.
3. Deltas: none.
4. Busy: not applicable here (the run gating lands in T765).
5. Entry paths: `redeem` is the only way a card login succeeds once wired; `mint` is server-triggered only.
6. Real path: wired in T765/T766; tests drive `reply` with a client-shaped 411 and the real store.
7. Reconnect: tickets are session-only and short-lived by design; a reconnect launches again.
8. Exits: an unused ticket expires (TTL) or is replaced by the next launch.
9. Economy: none.
10. Wire: Ticket/CharacterID positions cite `1017b4b0`/`1017b950`; fixtures follow the writer `1017b700`.
11. Ids: tickets are 64-bit OS-random, non-zero and unique among outstanding tickets.
12. Others: none.
13. End to end: pending T765/T766 and the native check.
14. Data: the TTL is a constructor argument; T766 reads it from data.
15. Canary: production `redeem`.
16. Session plumbing: untouched (T766 is the lead-only part).
17. Tick safety: not on a tick; randomness failure is an error to the caller, never a panic.
18. Type rules: ticket policy lives on `LaunchTickets`; the 411 layout on `SessionLogin`.
19. Hot path: one map operation per launch and per login.
