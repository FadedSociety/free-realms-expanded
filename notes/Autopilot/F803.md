## Threat note (secure-code-guardian)

Hostile input in reach: any client can send any family/subtype, including a forged `165/12` with an arbitrary sale
transaction id, or a short/long `165/12`. The change does not add a grant or a refusal path:
- A `165/12` still has to pass the Coin Store session gate: open shop, range and exactly 12 bytes; then
  `CoinShop::buy_back` must find a live sale, or it answers `165/13` with a failure. A forged transaction id grants
  nothing, so the skipped raise would have had nothing to count.
- The predicate is header-only, but a non-`165/12` packet cannot be misclassified as one except by its own first
  two u16 values (family/subtype). `66/43` starts `[66, 0, 43, 0]`, so a vendor buy still raises its event; the
  existing T794 tests buy through both `165/4` and `66/43` and count once.
- The skip can only suppress counting for a `165/12` that literally returned an item: that is the sell + buy-back
  loop T794 closed. Counting it would let a client loop a collect objective for free; refusing to count it costs
  the player nothing legitimate.
- The fixture writes only under the caller's test content directory; it never touches shipped content or a save.
  Refused buys still change nothing (`a_refused_buy_credits_nothing` covers both buy families).
