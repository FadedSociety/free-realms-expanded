## What changed

- `src/gameplay/npc_quests.rs` (10+/4-): `bind_npc_quest_catalogue` now loads
  the breadcrumb crosswalk and builds the `QuestEngine` before touching live
  state, then installs the engine, clears the saved copy and registers the
  crosswalk. It previously called `self.saved_npc_quests.take()` inside the
  fallible `from_split_content(...)?`, so a corrupt-content bind consumed the
  saved NPC quest progress; the later `load_crosswalk(...)?` was also after the
  engine swap. Neither fallible step can change anything now. The clone of
  `QuestState` is once per session bind, not a tick/packet path.
- `tests/wizard_entry_chain.rs` (75+/4-): new
  `a_refused_rebind_keeps_the_bound_catalogue_and_saved_progress`. It lets a
  chapter reach `[1, 0]`, refuses a zero-target rebind on the live game (state
  bytes equal, then the still-bound catalogue completes the talk step), then
  simulates the production reconnect order (`Gameplay::load` with the saved
  state, bind corrupt content, bind good content) and resumes the chapter to
  the held turn-in. Also uses the shared serialized reload (MINOR 6).
- `tests/support/npc_quest_chain.rs` (21+/4-): shared `accept` now asserts the
  `49/8` ObjectiveActivated for the first objective (MINOR 3); shared `offer`
  now asserts exactly one `49/1` and that it is the expected quest; new
  `Fixture::reload_serialized` so every chapter shares the JSON-round-trip
  reload.
- `tests/support/wizard_entry.rs` (4+/12-): deleted the chapter-local
  `reconnect` duplicate (MINOR 6) and the now-redundant offer filter in
  `offered_card`.
- `tests/shared_field_kill_quest_credit.rs` (12+/1-): the existing refusal test
  now pins the new contract (the refused bind keeps the saved state, binds no
  engine) and proves an accepted kill by that player still cannot credit the
  stale state; the other player's kill remains credited.
- `notes/Autopilot/F268.md`, `notes/Autopilot/T242.md`: corrected the review's
  false claims and the errand/pitch label (BLOCKER 2, MINOR 7). The F268 lab run
  report (`lab/autopilot/runs/F268-a2-20261020T130452Z/final.md`) still contains
  the old claims; it is outside this worktree and left as run output, so these
  notes supersede it.

## Security threat note (secure-code-guardian)

The change touches the content bind at session load and test helpers; no client
input parsing, save ordering, transport or session code changed.

- A hostile client cannot choose or alter the content directory, so it cannot
  trigger a rebind. A refused bind is returned as `Err`; it changes no state and
  no player can use the kept saved state to advance quests because no engine is
  bound. The updated shared-field test proves an accepted kill by that player
  leaves the stale state untouched while the other player is credited.
- The 49/2, 49/14 and 26/x paths are unchanged. Refusals still consume nothing
  (open menu, pending offer, held end screen); the full serialized state bytes
  are asserted unchanged around the new refused-bind cases.
- No client quantity or item id is read. The 49/8 assertion is server-generated
  (`QuestEngine::accept` -> `OutboundMessage::Quest(ObjectiveActivated)`), and the
  49/1 exact-one assertion uses the production decoder. No reward or coin
  arithmetic is touched.
- The clone of `QuestState` on the bind path is server-owned memory only; it
  does not widen the attack surface or persist anything.
