# T560: daily wheel, part 1 (offer the spin, open the movie)

World entry now sends the client its spin count for the wheel (143/1), and the wheel button (26/11) or
the Games window's Play for activity 8 opens a type-22 minigame run that launches `game_wheel.gfx`. No
prize and no spin is paid in this part; the run closes on the client's 39/6.

## Client facts (addresses in FreeRealms.exe)

- 143/1 body reader `00adafa0`: u16 143, **u8** sub (`00adae70` reads a word then a byte), five i32
  (`00adaed0`: id, count, consecutive, secs, secs), two length-prefixed strings, one i32. Handler
  `00adb990`: the same id updates in place (`00ada6f0`), else a node is added. The name lookup `00ada790`
  matches the second string; the count sum `00ada830` matches the first, so "wheel" goes in both.
- Lua `GetRepeatingActivityCount` / `NextTime`: table slots `0182ded8` / `0182dee0` -> bodies `00c17f80` /
  `00c18000` -> `00ada830` / `00ada8b0`. `NextTime` reads the first seconds field (+0x50 = now + secs).
  Which of the two seconds fields means "next spin" in the original is not settled; both carry the same
  value here.
- 26/11 = `CommandPacketInteractionStartWheel`, constructor `009aad80`, header only; the sender `009bdbd0`
  sends it only when the count of "wheel" is above zero.
- The 39/16 start-screen byte is `flags[3]` (+0x267): `009bfdb0` passes it as `a4` to `009beb70`, which
  with it off skips the start screen and calls `009be7d0` (39/5). Type 22 is in the list `009beb70` treats
  as loaded without a preload (1, 2, 22, 17).
- MiniGameData row 8: TYPE 22, NAME 409962, DESCRIPTION 409969, ICON 20985, no preload.
- The brief's addresses resolve: RTTI `.?AVRepeatingActivityAddPacket@@` at `01b55c0c`; the Lua names at
  `0182d770` (Count) and `0182d750` (NextTime) are registration strings, bodies above.
- ScriptsBase.lua: `startWheelMinigame` -> `MiniGameFlashC.StartWheel()`; `MinigameDetail.Populate`
  disables Play when the count is below 1; the Play button sends `RequestToJoinActivity(8)` (167/1/2), so
  the Games window needs the same start path as 26/11 (done).

## (R) choices

- One spin per UTC day; the day boundary is the server clock. A spin is available only when today is
  after `last_spin_day`, so a clock that goes back never grants a second spin.
- 143/1 id = the wheel's activity id (8), consecutive 0, last i32 0.
- `spins_per_day` is not in the data: with one day stamp the count is 0 or 1, and a knob that accepts one
  value is worse than none. Part 2 adds a counter if the original allowed more.
- Gates: the open wheel closes start (so also style cards) and warp; riding, pets and movement stay open
  (the wheel is a window, not a scene).
- A 26/11 or Play(8) in the opening campaign is refused; that branch never publishes the count either.
- The count is recomputed at each world entry only; a session that crosses UTC midnight keeps the old
  count until the next zone entry, but the server decision at 26/11 always uses the clock.

## Threat note (secure-code-guardian)

No coins, items or XP move in this part. A hostile client can forge 26/11 or Play(8) with no spin (refused,
state unchanged, one chat line), while busy (same), repeatedly while open (same), or with trailing bytes
(not the start packet; falls through as unknown). It can send lifecycle packets for the run (only length-15
packets naming the live or last instance are routed; the shared ledger rejects wrong states and returns
`Err` for malformed lengths, as for every minigame) or for another id (not named, not routed). A
disconnect, a zone entry or 39/6 ends the run and uses no spin (nothing about the run is saved).

   no spin, clock back, busy) and assert it equal, and assert no 39/16.
2. Rollback covers all state: the run and clock live in `Gameplay` (cloned by the gateway's staged commit);
   no shared cells.
3. Deltas, not snapshots: nothing pays or restores here.

   open gaps.
5. Every entry path gated: 26/11 and Play(8) both end in `start_daily_wheel` (opening, open, busy,
   knocked out / encounter via `warp_blocker`, no spin).

7. Survives reconnect: `last_spin_day` round-trips through `GameplayState` JSON (test); the run is
   session-only and a mid-wheel save keeps the spin (test).
8. Every exit restores: 39/6, a zone entry (`initialize_world` ends the run, tested) and a disconnect (the
   run is not saved) all leave the player free.
9. Economy: no rewards in this part.
10. Wire format: 143/1 and 26/12 byte-level in the tests; 39/16 offsets and flags asserted.
11. Unique ids: own range 62,000,001+, next id on reopen (tested).
12. Others see changes: nothing visible to others.
13. Content end to end: the shipped file loads; a bad movie, ids or version are refused at load.
14. Values live in data: ids and movie in `daily_wheel.json`; the UTC reset is code (R).
15. Canaries (production code broken, tests failed, reverted): spin count forced to 0 -> 9 of 11 fail;

17. One player's error: no arithmetic on client values; `to_reset` is bounded 1..=86,400.
18. Type rules: `DailyWheel` owns its day rule and count; `GameplayState::last_spin_day` is documented.
19. Hot path: `is_start_request` is a 4-byte compare, then a 167 header check; no allocation.
