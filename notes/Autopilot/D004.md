## Security threat note

A hostile client can forge the fishing family and subtype, replay start/cast/
reel messages, skip lifecycle steps, send malformed handles or send requests
for another player's GUID. The existing fishing service validates session
ownership, ordering, actor handle, phase and server timestamps; a refused frame
returns an empty outcome or `Err` and cannot supply a reward amount or item id.
No client-reported catch result exists.

This refactor adds no parser, selector, id or reward source. The missing-profile
failure occurs before `adopt_reward_state` assigns inventory or XP. The
Gameplay test snapshots coins, inventory, complete profile state and active job
and asserts equality after that failure. Production calls
`handle_in_world` on a cloned `Gameplay` and commits it only on `Ok`, so the
service's session-local mutation is discarded with the clone. No save or
session code was changed.

## Checklist

1. **A refusal changes nothing.** The no-profile test asserts coins, inventory,
   complete profile state (including XP) and active job are unchanged. The
   production gateway stages `Gameplay` and commits only on success.
2. **Rollback covers all state.** No new state container or side table was
   added. The shared adoption helper operates on the existing staged Gameplay;
   the new test also proves a live item grant is preserved.
3. **Apply deltas, never restore old snapshots over live state.** Fishing
   refreshes its reward snapshot from live inventory before every family-138
   request. The positive test grants an item after entry and asserts it survives
   adoption, so only the new catch is added.
4. **Busy rules are mutual.** No activity was added or changed. Fishing still
   enters through the existing busy check and `Occupation` table.
5. **Every entry path is gated.** No action path was added. The test uses
   `begin_fishing` and the existing in-world fishing route; chess remains on its
   existing route. App fuzz confirms dispatch coverage.
6. **Reachable in production, tested through it.** The test calls the production
   Gameplay entry and in-world handler rather than service internals. No new
   `application_handler` selector was added.
7. **Survives reconnect.** This deduplication adds no persistent state. Fishing
   sessions remain ephemeral; profile and inventory results use the existing
   character save path. The existing reconnect fishing tests remained green.
8. **Every exit path restores the player.** No exit or close path changed.
   Existing fishing cancel, escape, leash and reconnect tests passed.
9. **Economy safety.** Rewards still come only from the server-owned fishing
   service and chess result. No client quantity, item id or outcome is trusted.
   The positive test observes the catch item and Fisherman XP; the refusal test
   observes no economy change.
10. **Wire format matches the client.** The test builders are cited against
    client writers `0x00b69550`, `0x00b6a400`, `0x00b6a460` and `0x00b6a4d0`.
    No fields were added or removed. The existing `fishing_entry` wire suite
    passed.
11. **Unique ids.** No instance, GUID or lifecycle id was added or changed.
12. **Others see changes.** No outfit, job, mount, actor spawn or other visible
    state was changed.
13. **Content works end to end.** The Gameplay test unlocks Fisherman, starts
    the round, catches a server-priced fish, grants its item, reloads its XP and
    retains the active job.
14. **Values live in data.** No timeout, cap or payout constant was added. The
    test's fixed item definition and timestamps are fixtures, not gameplay data.
15. **Canaries break production code.** The canary changed production
    `handle_fishing`; the Gameplay XP assertion failed at `None` versus
    `Some(10)`, then passed after restoration.
16. **Hands off session plumbing.** No session, gateway transaction, save-order
    or binary file was changed.
17. **One player's error never stops the server.** No shared tick path was
    changed. Fishing errors still return to the existing per-session isolation;
    no new `unwrap` reads client-controlled data.
