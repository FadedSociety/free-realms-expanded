## Decisions for the lead (departures from the brief)

- **Default 250 m, not 50 m.** Re-measured this run (`%TEMP%\lead-L039\verify_l039.py`, read-only):
  of 3,297 rows in `data/content/npc_spawns_extra.json`, **103** stand more than 50 m under the
  `lab/terrain/zone_0.hgt` surface (the grid keeps the highest surface), 41 more than 100 m, 8 more than
  150 m, none more than 200 m. The deepest is 188.2 m: spawn 100000002757, a Chugawug miner
  (`chugawug_m_miner_01.adr`) at -904, -91, 2478 under ground 97.2, from Legacy
  `Scripts/Zone/FabledRealms.lua:1500` (the open-world zone script). With 50 m, a player who logged out
  in that mine would be moved, which breaks brief invariant 3 ("Interiors are never relocated"). 250 m
  leaves 62 m of margin. The cost: a pose 3-250 m under is left to the client's own 122 after 8.0 s of
  falling, or to the menu's "Teleport to Safety" (native PASS). The value stays tunable within 3..=500.
- **Off map is not just `height_at == None`.** zone_0.hgt has 18 small holes inside the map, at most
  32 m across, where the terrain mesh is cut. One spawn sits in one: the Rare Exploration Coin at
  897, 25, 1565 (spawn 100000004453). The brief's literal rule would move a player standing in such a hole
  (on the runtime object there) to a warpstone. (R): which objects fill these holes is not checked
  against the client.
- **Native check 2's point is on the map.** (-3060, -2040) is inside the grid's SW corner. For the
  off-map check, use a void such as (-2900, 2500), where there is no ground and all four probes miss,
  or any x < -3072.
- **Persist: save at once** (the brief left this choice open). It is the same pattern as the identity
  save that follows the same load. A crash before the save just recovers again at the next load.
- **Log: stdout event, not `security_log`.** `SecurityLog` has only refusal kinds (admission, auth,
  budget, dev command) and a recovery is not a refusal; the event line sits beside `character_saved`
  and `world_ready`, which log the same character fields.

## Security

Threat note (secure-code-guardian / security-reviewer):

- **Client input.** Recovery reads no packet. It reads only the server's own save, which holds a pose
  the server's movement validation accepted earlier (and `read_document` re-validates it as finite and
  within 1e6). A hostile client can walk or fall into a void and relog to reach the nearest warpstone,
  and standing there then attunes it. A `122` gives the same destination today (the nearest warpstone,
  attuned or not), so this opens no new travel or attunement. The arrival is the stone's server-side row;
  nothing comes from the client.
- **No oracle.** The client is sent nothing new: no notice, no reason, no packet. The reason and
  positions go only to the operator's stdout event log.
- **Refusals change nothing.** With no terrain, another zone, a good pose, a cave or a hole, nothing
  changes: tests assert the pose is unchanged and the save bytes are equal. Once logged in, recovery
  never runs; the client owns the pose then, and a silent server move would desync it.
- **Saves atomic.** `game_store::save` goes through `replace_bytes` and keeps the document's pets and
  housing. In the account path the existing duplicate-session check runs before the load, so no second
  session writes the save.
- **No secrets in logs.** The line is the character guid, the reason and two positions: no account id,
  name, chat or ticket.
- **Errors.** Recovery returns `Option` and never panics. A save failure fails that one session's load,
  the same as the identity save beside it, and never the server.

## Checklist

1. A refusal changes nothing. No terrain, another zone, a good pose, a cave, a hole, or already logged
   in: tests assert the pose is unchanged and the save bytes are equal. Canaries C2, C4, C5 and C7.
2. Rollback covers all state. Recovery is a pure function (`&self`) that returns a new pose. The gateway
   swaps `state` and `movement_state` together, and there is no side table.
3. Deltas, not snapshots. Only position and rotation are replaced, on the freshly loaded state, before
   anything else can change it. Inventory and coins are untouched.
4. Busy rules. Does not apply: this is not an activity. At world entry nothing is running (battles were
   already abandoned by `enable_gameplay`), and blockers are deliberately ignored.
5. Every entry path. Both production loads (local and account store) go through `load_gateway_from`.
   The startup check in `Server::new` passes there too and saves.
6. Reachable in production. The world-entry tests drive `Session::new` -> `load_gateway_from`, then
   login, `13`/`10`, and a `125` step.
7. Survives reconnect. The save is written at once, and the test reloads and finds the stone pose with
   unchanged bytes (idempotent).
8. Every exit path. The character is placed on the ground at a stone, and movement validation starts
   there (C9).
9. Economy. Does not apply: no items or coins. The destination comes only from server data.
10. Wire format. No new or changed message. Client fact 122 / 8.0 s cited above.
11. Unique ids. Does not apply.
12. Others see changes. Recovery runs before login, so other players first see the character at the
    stone through the normal join path.
13. End to end. The final outcome is asserted: the pose on disk and in the session, and an accepted
    step from it.
14. Values in data. `login_below_world_m` is a `WarpRules` field with sanity bounds, like its siblings.
    `WarpRules` has no content file yet (an existing gap, not widened here). `HOLE_PROBE_M` is a
    documented (R) constant measured against the grid.
15. Canaries break production code. C1-C9 all edit `src`, not tests.
16. Session plumbing. No change to session creation, teardown, transactions or save ordering. One save
    is added inside `load_gateway_from`, next to the existing identity save pattern. This task is
    lead-only for that reason.
17. One player's error. Recovery has no panics or arithmetic on client data, and a save error fails only
    that session's load.
18. A type's rules on the type. The margin and its bounds live on `WarpRules` (doc on the field and in
    `checked`). The hole rule is on `HOLE_PROBE_M` and `recover_login_pose`.
19. Hot paths. Once per world entry, nothing per tick or per packet.
