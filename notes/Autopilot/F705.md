Declined: `coin_edits_watch.retry()` after a failed apply. `tick_live_placements` retries because its
apply can fail on a transient packet build; here the only realistic failure is the merge refusing the
file, which is decided by the bytes. A retry would log the same refusal every second per session until
the file changes. Read failures and refused merges are reported once per file stamp; a comment at the
call site says so.

## Threat note

Only Admin reaches `realm coin` (existing role gate). A hostile or hand-edited overlay cannot reach
the client: `read_overlay` caps the read at 1 MiB, checks the schema and the `next_guid` band, and
`merge` validates every row (band, entry, tier, model, finite position, 512 rows). A command given a
bad file refuses and leaves it byte for byte.
