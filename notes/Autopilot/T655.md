# T655: tests/movement.rs runs in minutes

Brief: `tests/movement.rs` averaged 2,206.7 s over 11 suite runs and set every integrator batch's wall time.

## What was slow

The brief guessed real-time sleeps. There are none: the `Duration::from_secs(1)` and `from_secs(30)` at lines
238-264 are the `dt` argument to `validate`, never slept. Ten of the eleven tests are pure (0.04 to 0.06 s each).
All the time is in `replay_run`, used by `replay_all_recorded_native_baselines_without_rejecting_legitimate_positions`
(217 captures in `lab/runs/client-baseline-*`) and `real_developer_teleport_ignores_the_15ms_stale_position`.

Measured with a throwaway probe: reading the 1,544 one-datagram files of the developer-teleport run took 4.5 s
(about 2.9 ms per file, warm cache, so it is the Windows open cost with virus scanning, not disk throughput), while
SHA-256 of all of them took 14 ms and `Codec::decode` 15 ms. The same reads on 4/16/32 threads took
1.35 s / 0.35 s / 0.18 s: the wait is latency, so reads scale almost linearly.

## What changed

`tests/movement.rs` only (no production code, no Cargo change). `replay_run` now filters the manifest to the replayed
frames once (`is_replayed`), reads every datagram file side by side on up to 32 scoped threads (`read_datagrams`),
and then walks the frames in order exactly as before: same hash and length asserts, same timestamp-order assert,
same "missing captured gateway datagram" panic (the read result is unwrapped at the point the old read was).
Nothing is shared between threads but the paths.

## Before / after (same machine, loaded by other builders; both numbers inflated by the same contention)

| test | before | after |
| --- | --- | --- |
| replay_all_recorded_native_baselines_... (217 captures) | 2,868.4 s | 184.5 s |
| real_developer_teleport_ignores_the_15ms_stale_position | 3.95 s | 0.39 s |
| the other 9 tests | 0.04-0.06 s each | 0.05-0.13 s each |

Whole binary: about 48 min before, about 3 min after on a loaded machine (under the 5 min target; the before run
shared the disk with my after runs and with other builders). Both full runs print byte-identical per-run lines
(updates, rejects, clamps, ignores, teleports, zones for all 217 captures) and the same summary line
(updates=19019, rejects=0, clamps=0, ignores=108).

No test removed, ignored or weakened. No test needs real wall-clock time; none of them sleeps. The remaining 184 s
is thousands of small file opens in the many short captures (about 0.85 s per capture); running captures
concurrently as well would cut it further but is not needed for the target.
