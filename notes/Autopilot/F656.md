# F656: the owned-item refusal covers rides only, and a rental is not owned

Fixes the post-merge review of T484 (`3a632db`): the refusal and the 66/39 view-only flag hit all
808 non-earn-only Station Cash listings, so a second Candy Bag (17744) or Flair Shard (10330)
could not be bought. Lead decisions are (R), from the brief's intent that an owned ride cannot be
bought again.

## Summary

- `Listing.ride` (new): set in `Catalogue::build` from `MountCatalog::mount_for_item(item).is_some()`,
  the predicate the T482 Rides roster uses (`item_to_mount`). `Listing::owned_by` is now
  `ride && owns_item`, so every non-ride listing sells any number of times and is flagged 1 in 66/39.
  The deed special case is gone: a deed is not a ride.
- `owns_item` ignores a rental (`item.rental.is_none()`), expired or not: a rented ride never blocks
  buying the permanent one and is not flagged. The function also serves `gameplay/sc_earnings.rs`, so
  the first-clear ride award treats a rental as not owned too (it grants the permanent ride).
- `StoreCatalogue::load` reads the `mounts.json` beside `stores.json` (production: both live in the
  NPC content directory; `Gameplay` loads the same file for the roster) into a skipped field
  `rides`. No `mounts.json` (a fixture directory) means no listing is a ride. Cost: one extra parse of
  the 620 KB `mounts.json` per session when the shop loads, nothing per tick.
- Ownership stays by exact item id (finding 4): another tint is another purchase.
- Notes: the T484 note's "one row per ride" line, its 66/39 size (about 50 rows became 808 rows, about
  4 KB) and the missing ponytail statement are corrected.

## Tests (`tests/marketplace_owned_rides.rs`, 8 tests)

- Canaries (reverted): `owned_by` without the ride bit fails 3 tests (deed, stackable, flags); dropping the
