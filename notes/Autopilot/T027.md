# T027 - Live outfits, equipment changes and job switches

## Verdict

Other nearby sessions now receive live appearance changes:

- active-job equip: `35/6 EquipItemChange` with the real player GUID;
- active-job unequip: `35/6` with an empty attachment model;
- job switch: `35/7 EquippedItemsChange` with the complete new attachment group;
- a later viewer: refreshed `35/1 AddPc` presentation from the shared registry.

The two-session bot gate sees the unequip, re-equip and job switch from the other side. It also
reconnects the second session after the switch and verifies that the new `AddPc` contains the new
job's outfit. No native client run was available in this autopilot worktree.

Mount fanout already used the same `Outcome::nearby` path through `ride_fanout`; no mount code was
changed. The existing mount suites remain green.

## Changes

- `src/gameplay.rs`
  - Added `item_change_packet`: broadcasts an active-job equip's real `35/6`, rewrites its
    content-owned player GUID to the authenticated character GUID, and builds the unequip removal
    form.
  - Added `profile_switch_packet`: emits `35/7` with the newly active job's full attachment group.
  - Added `inventory_visibility`: suppresses neighbour and owner `35/6` replies for an inactive
    job, while keeping the other profile-local replies.
  - Wired both packets through `Outcome::nearby` in the opening and generic handlers.
  - Added an in-process test for equip, unequip, replay, inactive-job equipment and job switches.
- `src/bin/osfr-gateway.rs`: refreshes the registry's `PlayerPresentation` after a committed
  gameplay change, so later viewers' `AddPc` does not use the pre-change outfit.
- `src/players.rs`: added `PlayerRegistry::set_presentation`, with character-GUID and wire
  validation; a refused update leaves the old presentation intact.
- `src/gateway.rs`: documented the expanded `nearby` contract.
- `tests/bot_acceptance_1016.rs`: two-session live-wire gate, refusal/replay assertions, saved
  active-job assertion, and late-viewer `AddPc` assertion.
- `tests/players.rs`: registry refresh and refusal-purity test.

The saved `T027-a1.patch` was applied first. Two rejected `gameplay.rs` hunks were ported manually,
then the `.rej` file was removed.

## Reconstructed rules

- (R) An unequip is represented to neighbours by `35/6` with item `0` and an empty attachment
  model. This follows the native dispatcher's case-6 removal branch and still needs a native visual
  check.
- (R) A job switch changes the complete public attachment group, not one slot.
- (R) Changes to a non-active job's profile remain local; they must not alter the visible avatar.
- (R) A no-op or refused change sends no neighbour packet and changes no saved state.
- (R) The retirement rule for the trailing `35/7` integer remains zero pending stronger evidence.
