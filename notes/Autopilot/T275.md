## Threat note (secure-code-guardian)

A hostile client can send 26/8/26/10 for any target id (including a fabricated
one), a 66/43 with an arbitrary item id, quantity or transaction id without an
open shop or from outside the interaction range, and 165/5 for any item
instance it claims to own.

- 26/8 and 26/10 need a known spawned content key, the NPC's zone/position
  range, and (for 26/10) an option from the server-sent menu; a foreign or
  unknown target produces no menu, and out-of-range produces nothing.
- 66/43 needs an open merchant session for that NPC, the item must be in that
  NPC's server-owned `vendors.json` stock, and the character must still be in
  range. The price is read from `stores.json`; the 66/43 body has no price
  field, and forged context words are ignored (test 2 buys with forged context
  at the same 12-coin debit).
- `CoinShop::buy_vendor` checks the item definition, positive server price,
  quantity (zero/overflow refused), exact coins and bag capacity; a refusal
  answers 66/44 status 0 with no inventory/coin/menu/save change.
- 165/5 needs an owned, non-equipped, non-rental instance with a positive sell
  price and `no_sale == false`; the sale and 165/12 buy-back each pay once.
- No path grants a free ingredient, takes a client-reported result, or touches
  another session's inventory. The two-session test proves per-character coins
  and bags, and a shared, non-depleting stock list.
