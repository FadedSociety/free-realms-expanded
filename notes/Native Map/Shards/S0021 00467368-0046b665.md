## GDS display path

- 0046a924 installs vtable 0x176469c and calls 00467368. On the grid branch, 00467368 allocates one 0x3c record per cell, fills cell indices, destination coordinates and UV values, uses 0x1764650 for rectangle insets, stores grid dimensions/reciprocals, sets state 3, then calls 0046333c. It returns 0 for a null source or failed setup/allocation and 1 on either successful path.
- The alternate 00467368 branch gets a value from 004cd10a and passes it to an indirect virtual call. The virtual call's nonzero return supplies fields at +0x60..+0x6c; those fields are copied into this+0x24..+0x38. If this+0x20 is null, the function allocates and initializes a 0x28 record with 00462c36. 004cd10a itself returns the first dword of its receiver, and 00462c36 constructs a record with vtable 0x1764670; neither proves a texture-object identity.
- 00467770 expands format 0x17 using 0xf800/0x7e0/0x1f. Formats 0x18 and 0x19 use 0x7c00/0x3e0/0x1f and explicitly clear the output high byte: these are 555 fields, not evidence for a 1555 alpha channel. Other formats pass through unchanged.
- 00467824 and 0046785f are nested-field getters with guarded calls to 00466eb3, the draw-device frame-preparation routine. Their returned fields' semantic identities are unknown, so their names stay mechanical and confidence stays speculative.
- Twelve append/clip/bounds routines span 004689c4-00469cab; stream variants expand geometry before clipping/appending. The twelve short entry wrappers at 0046a71c-0046a89d call those routines with an extra fixed zero. 0046b665 is a separate 28-byte-record path: it offsets a local record, calls 0046556b to append it, then updates the accumulated rectangle directly or intersects it with a rectangle reached through opaque param_4[2]. Its return value reports append success, including when the intersection is empty; it does not report whether clipping matched.
- 0046a6d7 restores vtables 0x1764d40/0x1764d3c and tears down members. Those vtable identities and the constructor vtable 0x176469c have no recovered RTTI class names. 0046a987 drives a renderer at this+0x40 to draw a centered overlay, but that renderer interface is not identified.

The bounds-growing paths call locked dispatch wrappers such as 004056b6. The callee 004dbcb6 copies a small-inline/heap buffer representation and its count*16 elements; that body does not establish the earlier "state capture" interpretation of those wrapper calls.

## STL/container path

- The tree helpers instantiate 20-byte nodes with colour/nil bytes at +0x10/+0x11 and 24-byte nodes with bytes at +0x14/+0x15. Links are left/parent/right at +0/+4/+8, with the value at +0xc. Nine allocator forms, nine value-constructing forms, nine header initializers, seven clear paths and four recursive copy paths cover these layouts (00467df4-0046b617).
- Nineteen 12-byte wrappers save the iterator pointer from ECX, call a tree-iterator helper, restore that same pointer to EAX and return. Successor helpers allow ++rightmost to produce the header/end iterator; they reject a null container proxy or ++end. Predecessor helpers implement --end by selecting the header's rightmost link, reject --end only for an empty tree, and reject --begin when climbing reaches the header (00467ca4-0046b275). The helpers use both +0x11 and +0x15 nil-marker layouts.
- Fourteen checked-iterator pair helpers copy the pair before arithmetic. Raw x86 shows container at dword +0 and current pointer at +4. The element strides are 0x10 at 0046798b; 4 at 004679f4, 004681fe, 0046822b, 00468285, 004682b2, 004683c2, 0046841a, 0046b1d0, 0046b214 and 0046b2b1; 0xC at 00468380 and 0046b281; and 0x24 at 0046845d. Each helper checks the moved pointer against the container's bounds before the wrapper copies the updated pair to its output (0046798b-0046b2b1).
- Five pairs of checked vector-iterator adapters use the same container for both endpoints: the pointer at this+4 is begin and this+8 is end, as confirmed by the constructor bounds and the copy callers (00467a89, 00467ab1, 00467b48, 00467b5c, 00467bad, 00467bc1, 00467c29, 00467c3d, 00467cd4, 00467ce8).
- Nine ordered searches are lower bounds and two are upper bounds. 00467a5a walks with the interned-string comparator; the other reviewed lower-bound families compare the unsigned dword at node+0xc, while 0046b0c7 compares a 16-bit key. The upper-bound paths return the first key strictly greater than the searched key (00467ecc, 004680cf). Six additional wrappers combine one lower-bound search, an end iterator and an exact-key check; they copy either the matching iterator or end to the output (0046aa77-0046adc4).
- Sequence helpers cover dword, 0xc, 0x10 and 0x24 elements. The counted 0x24 loop at 0046a17a decrements the count at EBP+0x0c, copies from the fixed source at EBP+0x10 to the destination at EBP+8, advances only the destination, and returns void. 0046a37e copies four-byte reference-counted pointers through the element helper at 0045f1ff. Forward/backward pointer-move helpers call virtual slots +0xc and +0x10(0) on their respective source/destination values (0046a13f, 0046a4a4, 0046a52d).
- The adapter cluster at 00469ebd-0046a086, 0046a1c8-0046a218, 0046a3eb-0046a47f and 0046a59d had misleading decompiler argument lists. Raw x86 shows extra stack words sourced from saved-ECX/local slots; stosb clears only the low byte of those dwords. The actual callees consume their declared first three or four inputs, and wrappers discard helper return values where their own bodies return void. The callee's internal literal zeros are not trailing zeros supplied by these adapters.

## Review corrections and remaining unknowns

Corrections address the prior review disputes and their sibling patterns: 00467368 now distinguishes the indirect-call argument from its returned object; 00467770 describes 555 masks; 00467824/0046785f no longer claim a surface-entry identity; tree begin adapters now identify the head's left link and their erase-range callers; vector begin/end adapters bind both positions to the same container; iterator movement descriptions distinguish ++rightmost-to-end from invalid ++end and --end from the empty-tree error; copied iterator pairs use their verified field order and per-helper stride; the adapter cluster no longer treats saved local slots as zero arguments; 0046a17a reports the fixed source, advancing destination and void return; exact-key lookup wrappers use one lower-bound search; and 0046b665 ties its success flag to record append.

Open questions:

1. The class names behind vtables 0x176469c and 0x1764d40/0x1764d3c, plus the object identity of the 0x28 record created at 00467368.
2. The interface driven by 0046a987, the role of the extra seventh zero in the append entries, and the caller-level meaning of the optional rectangle handle used by 0046b665.
3. Exact key/value types for most STL instantiations and the downstream consumers of the equal-range pairs built at 0046af98 and 0046b10c.
4. Whether callers post-filter lower-bound results and how the draw-queue callers use the exact-key helpers.

No original server behavior can be inferred from these local rendering and container routines.
