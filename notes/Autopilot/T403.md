# T403 — Quest goal lines read "<STRING 0 NOT FOUND>"

Lead native run `client-baseline-20261021T143012Z` (`s5-tmt.png`): after accepting
Call the Crew! (3000059) the helper's Goals list held one line,
`<STRING 0 NOT FOUND>`, for a two-objective quest.

## Cause (client evidence)

The 49/3 objective record the server wrote was `[objective.id, 0, 0, 0]`: key,
**definition id 0**, **name 0**, **description 0**. Two bugs, both visible in the
screenshot:

- **Name 0.** `QuestHelper:PopulateHelper` (ScriptsBase.lua 15133) adds one goal per
  `BaseClient.QuestObjectiveData` row with column `Name` (Lua `QuestObjectiveDsColumn.Name
  = 0`). The datasource cell getter `0x00cf7fd0` (vtable `0x0183c69c` of
  `QuestObjectiveDataSource`, ctor `0x00cf82a0`, built by `0x00c7ca80`) returns column 0
  through the locale lookup `0x008ed320` on objective `+0x04`, and column 1 on `+0x08`.
  `0x008ed320` formats `off_1B3F6D8` = `0x01803980` `"<STRING %d NOT FOUND>"` when the id is
  missing. The objective reader `0x008fd770` (called per row by `0x0092b050` after the
  tuple key) fills `+0x00` definition id, `+0x04` name, `+0x08` description from wire
  dwords 2-4. So the goal line is the objective name locale id, a Global.Text id.
- **Definition id 0.** The runtime quest copy `0x00baf380` -> `0x00baba60` ->
  `0x00bab950` rekeys every objective by its definition id (`+0xf0 = raw +0x00`), as
  [[Research/Native Journal Live Objective Keys]] records. With 0 for all objectives,
  every runtime objective had key 0: the row builder `0x00cf7c30` appends one row per
  objective (`0x010c9050`, a plain append) all with id 0, so the helper (which passes the
  row `Id` to `addObjective`) showed one line, and `0x00c7a910` (49/8 mutation) never
  found key 1, 2... so activation, 49/9 and 49/10 updates were dropped.

## What changed

- `src/quest_engine.rs`
  - `quest_add_packet` writes `[objective.id, objective.id, text, text]`. The text is the
    objective's content `text_string_id`; with none, the quest description, else its title
    (R). Name and description carry the same id (R), as the opening journal's goal labels
    do (`tests/fixtures/quests/opening.json`: every labelled goal has `name_id ==
    description_id`).
  - `from_split_content` strips an optional per-objective `text_string_id` before the typed
    goal parse (the same pattern as the quest-level intro/description/end ids, and the same
    validator `take_optional_locale_id`: 0 or a non-u32 is a load error) and keeps it in a
    `(quest, objective) -> id` map beside `step_dialogue`.
- Content: every objective of every enabled quest (85 objectives, 50 quests, 14 files)
  gets `text_string_id` plus one provenance tag naming the Global.Text id, its text and
  why it was chosen. Disabled quests are untouched (they use the runtime fallback).
- `scripts/content_check.py`: `text_string_id` is a Global.Text field (a raw hash is an
  error), and an enabled quest objective without a positive `text_string_id` is an error.
- `tests/content_jobs.rs`, `tests/content_npcs.rs`: the ContentDb v1 adapters strip the
  new objective field, as they already strip the quest-level locale ids.
- `tests/miner_first_ore.rs` (attempt 2): T411's pin of Rush Order's bare objectives strips
  `text_string_id` with `source`; the goal text is display content checked by
  `tests/quest_engine.rs`.

## Goal text selection (per row; evidence is in each objective's new source tag)

Rule, in order: (1) the id/hash the objective's own evidence cites as its step text
(`client`); (2) a goal line in the quest's own locale block (title T .. T+14) that matches
the step (R); (3) a client goal line naming the bound target (R); (4) the quest
description (R). Every hash claim was rechecked with `jenkins_lookup2("Global.Text.<id>")`
(29 of 29 match). Notable rows:

- 3000059 Call the Crew!: 100080 (hash 1842066294) and 384143 (hash 1347845427), the
  brief's texts. The second cited hash 3304545061 is the older variant 94512.
- 3020003: the evidence's quoted text is 90123, but the hash it cites (3250596704) is 91135,
  a forging line; 90123's own hash is 3857116118. Used 90123 (exact text match).
- 3000034: the original block goal 90778 names Arestol; the server binds Arch Druid
  Camellia (T377 R), so the goal is 438284 'Speak to Arch Druid Camellia' (R).
- 3010006: 77037 (cited) also names the carve step, which the server skips (T194 R).
- 3110001/3110002: ids from the owner's field notes (helper 93206, journal goal 115023); tag
  kind `video`, like the existing tags they cite.
- 3000200 (scavenger hunt, a local event): all four lines are (R) client lines naming the
  stop's NPC/place.
