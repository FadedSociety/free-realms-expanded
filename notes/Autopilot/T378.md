## Method

1. **Every id is a `Global.Text` id, resolved three ways.** The test recomputes
   `JenkinsLookup2("Global.Text.<id>")`, finds the id behind that hash in
   `lab/reports/locale-id-map.json` `hash_to_ids`, checks the physical
   `en_us_data.dat` line with the harness's `str::lines()` convention, and
   compares the stock text to `lab/reports/locale-id-to-text.json`. A raw hash
   or an unknown id fails.
2. **Speaker proof.** A line is accepted only by one of three evidence shapes:
   - `GuideQuote`: the cited Build Guide table row names the NPC and contains
     the line's hash. Used for Carlos, Chloe, Postchug, Silverray, Therin,
     Geoffrey, Petra, Burt, Shakey and Camellia.
   - `QuestOffer`: the cited guide row names the NPC as the giver of the quest,
     and the production quest record binds that same `giver_npc_id` and
     `intro_text_string_id`; the record's own `source` note also names the id.
     Used for Sabastian Cabet and Mustang Alli. These two are the T315/T317
     quest-offer precedent, marked `(R)` because the T-1 intro slot is
     reconstructed; Sabastian's T+1 description names him independently, and
     Mustang's guide giver row and locale block name her quest.
   - `SelfReference`: the cited guide row names the NPC and the event quest, and
     the line claims that quest's object in the first person ("my spectral
     spectacles"). Used only for Greyli Dustywings, whose Super Spooktacular
     quest is not in the split quest catalogue.
   Third-person objectives and near-lines are rejected; the test includes a
   negative control that binds Carlos's valid line to Chloe's guide row and a
   known third-person Petra objective ("Petra would like for you to collect
   some silver dust...", 72497), both of which must fail.
3. **Fixed-default policy `(R)`.** Each row repeats the recovered line on every
   Talk. The original server greeting/phase table was not recovered, so a quest
   phase does not change the first-click body and no text is invented.

## Security threat note (secure-code-guardian)

- This slice changes no parser, save, coin, item, reward, role, chat, trade or
  session code. The only new values are static server-side `u32` locale ids and
  their evidence strings; the client never supplies a locale id.
- Hostile client input on the path is the existing 26/8 target GUID and the
  26/10 NPC GUID/option pair. The router resolves the runtime GUID through
  `NpcVisibility` (including extra-spawn GUID -> content key), requires an open
  menu for that exact NPC key, and rejects a malformed body (`InvalidPacket`),
  unknown NPC (`UnknownNpc`) or out-of-list choice (`InvalidOption`) with `Err`.
  The new refusal test sends `i32::MAX`, a truncated body and an unknown GUID,
  then selects Talk on the still-open menu (no second `interact`) and gets the
  unchanged empty body; the reopened menu's option list is identical.
- A client cannot choose or inject the body: `greeting_string_id` is a `u32`
  read from server content, so a hostile client cannot inject text, choose a
  locale id, or force an allocation from an attacker-controlled size. A blank
  row sends body 0 and never borrows another row's line.
- Every bound id resolves in the stock client locale, so no overlay or fallback
  path is introduced. The loader bounds (8 MiB/file, 32 MiB total, 20,000 rows)
  are unchanged and the real loaders are exercised. There is no per-player
  state and no new entry path; none of this runs in the shared tick.
