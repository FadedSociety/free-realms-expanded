## Security note (secure-code-guardian)

This change is notes plus a read-only data-pin test; it changes no client input parsing.
The threat note for the planned wire path stands and is now sharper:

- **Attack surface:** a hostile client can send forged `125` pose, `15/1` chat, and any
  application family; it cannot be trusted for its region, area name or zone. The gateway
  currently routes client family 47 only subtypes 12/13 and client chat only 15/1.
- **Rule:** region/place is computed server-side from the validated pose; a client
  `47/9` or `15/2` is **not** accepted as a request. A forged `47/9`/`15/2` must be
  refused/logged and change nothing (step (d) test).
- **Bounded output:** 47/9 zone ids are 2..10 with a known `*_notification.swf`; region 1
  has no banner and must not be sent. The 15/2 value is a content locale id, never client
  text. The Lua `t[zoneId]` has no range guard, so the server validates before send.
- **No state lever:** the banner/chat is per-player presentation; no rewards, items,
  coins, roles, saves or broadcast to other players. The test added here reads shipped
  content only and cannot be influenced by a client.
- **No secrets/player data:** the notes contain client system text and NPC/locale ids; no
  player names, chat text, account data or save data. The cited video frames stay in the
  lab.
