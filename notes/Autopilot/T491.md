# T491: Halloween decoration props show only during the Halloween season

## What changed

- `src/world.rs` (CRLF, +56/-0):
  - `ExtraNpc` and `VisibleNpc` gained `season: Option<String>` (`None` shows all year).
    Regional, placed and battle-spawner rows set `None`; only `npc_spawns_extra.json` rows can carry a season.
  - `NpcVisibility::load` is unchanged and keeps every row.
  - `NpcVisibility::retain_in_season(active: impl Fn(&str) -> Option<bool>) -> io::Result<()>`
    validates every seasonal row first; `Some(false)` rows are collected and dropped only after the whole
    table validates, and `content_keys` entries for dropped rows are removed. `None` means "season not
    defined": the call fails with `NPC spawn <guid> names season "<name>", which client_areas.json does
    not define`, and drops nothing. An empty drop set returns before the copy-on-write clone.
  - `NpcVisibility::load_in_season(dir)` is the production load: wall clock -> `load_in_season_at`.
    `load_in_season_at(dir, unix_ms)` is the same body with an explicit clock, so tests pass a fixed
    instant and never read today's date.
- `src/client_areas.rs` (LF, +9/-3): `ClientAreas::season_state(name, unix_ms) -> Option<bool>`
  (`None` = the content does not define the season); `is_season_active` is now
  `season_state(..) == Some(true)` and keeps its old behavior.
- `src/gameplay.rs` (CRLF, +1/-1, **hub net 0**): the one production NPC-table load now calls
  `NpcVisibility::load_in_season(npc_content)`.
- `data/content/npc_spawns_retired.json` (CRLF, +12/-0): the 12 Halloween rows carry
  `"season": "Halloween"`.
- `tests/halloween_season_props.rs` (new, LF): 4 tests, every clock/answer fixed.

## Security threat note (secure-code-guardian)

- A hostile client cannot name a season: the only season inputs are server content
  (`client_areas.json` and an extra row's `season` key). No packet, save or command reaches
  `retain_in_season`.
- An unknown season fails closed: the whole play-time load returns `Err` naming the spawn guid, and
  validation runs before any row is dropped. A corrupt/hostile content file can only refuse startup,
  never add an actor.
- A missing `client_areas.json` means "no seasons"; a tagged row then refuses the load. No fallback
  silently shows the prop.
- The clock is the server's `unix_now_ms`; no client value influences it. No coins, items, rewards,
  roles or saves are touched.
