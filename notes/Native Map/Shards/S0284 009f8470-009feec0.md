## Subsystems and code clusters

- **Loading-screen and TinyXML helpers**: `009f8470` initializes three typed list subobjects and two helper objects, then stores the `LoadingScreenMusicId` lookup at `+0x3c`. The owning class is not established. RTTI identifies the TinyXML visitor/printer paths (`009f86b0`, `009f8740`, `009f9170`, `009f9b70`, `009f9c00`). Counted-string helpers separate buffer allocation (`009f8660`, no payload copy) from C-string assignment (`009f9af0`, copies bytes but overwrites the output pointer without releasing its prior value).

- **Bug-report UI and data sources**: `009fbb60` loads `BugCategories.txt`, `BugCategoryMappings.txt`, and `BugSeverity.txt` into local linked/hash tables and refreshes the views. RTTI names the category, subcategory, and severity data-source classes (`009f8950`?`009f89b0`, `009f93f0`?`009f9530`, `009fc390`?`009fc680`). The manager-like component allocates three `0x258`-byte sources and registers/retains them (`009fc6a0`, `009f89d0`); its cleanup body unregisters the names, releases the references, and removes three maps (`009fc150`). No standalone `UiBugManager` RTTI vtable was found here, so those manager records use mechanical names and `class: null`. The form binding and `PlayerData` value-object builder are at `009fa950` and `009fad80`.

- **Bug-submission packet construction**: `009f9f40` cleans the two `IString` fields and restores `BaseBugSubmissionPacket`/`BasePacket` vtables; its scalar-deleting caller supports the derived `BugSubmissionPacketAddBug` label (`009fa330`). Serializer `009fc2e0` writes the 16-bit pair at `+4/+8`, bounded dword `+0x0c`, `IString +0x10`, bounded dword `+0x20`, and `IString +0x24`. Builder `009fc890` wraps that serialized buffer in `ClientGateway::PacketTunneledClientPacket`; constructor `0089adc0` supplies gateway opcode 5. The shard shows packet construction, not transport dispatch or a server response. The inner bug-record schema has no matching packet-catalogue class, so no original-server behavior is inferred. The confirmation UI at `009fcc30` is local and does not prove server acceptance.

- **Collection-category data**: `009fd4e0` loads the caret-delimited client resource into category nodes; `009fd050` selects a bucket using key modulo 10, and `009fd3e0` removes a head node. These facts agree with [Research/Pieces/074 Collections and collectibles](../../../../../project/notes/Research/Pieces/074%20Collections%20and%20collectibles.md): the category table has three client columns. The note separately marks collection progress, rewards, and native population as unrecovered; this shard does not change those limits.

- **GodBeam definitions and containers**: `009fe280` parses `GodBeams.txt` into a hash-list map. The range includes allocator/node removal, a red-black ordered tree, and `0x2c`-stride pool blocks (`009fdc00`?`009feec0`). Byte inspection confirms `009fe640` returns the in-order successor and `009fe680` the predecessor; `009fe810` returns the floor key and, among duplicates, the rightmost equal-key node.

## Review corrections and evidence limits

The byte recheck corrected several decompiler traps. `009f89c0` adds 4 to ECX before its jump, so it is an adjustor thunk. The tree-navigation functions return their candidate in EAX even though Ghidra shows no return expression. The first virtual call in `009fa000` has no stack argument; its later virtual calls receive each integer from the matched row list. The `DAT_01b839d8 ^ (uint)&local` values in string cleanup, data-source cleanup, and packet construction are SEH/GS bookkeeping, not call arguments. The string cleanup bodies (`009f9d50`, `009f9e40`, `009fd320`, `009fddb0`) first test positive stored length, decrement the buffer count, and call the release slot when the pre-decrement count is at most 1. Constructors `009f9cd0`, `009f9dc0`, and `009fd2a0` clear six dwords, not four. The hashed-list removers (`009fa3d0`, `009fa520`, `009fd3e0`, `009fba60`) proceed with ordered-list removal even when the head is absent from its hash chain.
