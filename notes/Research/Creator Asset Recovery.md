# Creator Asset Recovery

2026-10-08. Character creation reached the native scene but repeatedly requested nine missing `sg_dressing_room_*.gcnk` tiles. The supplied24 packs do not contain those names. Run061543 recorded local HTTP404 for them; this was an asset-loading failure after the login/creator protocol, not evidence that the creator protocol had failed.

The current [community Launcher](https://github.com/Open-Source-Free-Realms/Launcher), pinned at `e6a2674c516fe6062698440a1f37163132b4abca`, identifies `https://opensourcefreerealms.com` as its default host. `Server.cs` lines465–466 download a manifest entry from `<host>/client/<path>/<filename>` into `Client/<path>/<filename>`. Its file verification uses XXHash64 and exact length. The launcher launches with the Client directory as its working directory; no separate custom-path flag appears in its launch code.

The anonymously accessible [client manifest](https://opensourcefreerealms.com/clientmanifest.xml) explicitly lists a complete **custom** creator scene: one GZNE, nine GCNK and nine GCK2 files under `custom/`. All19 downloads returned HTTP200 and match the community manifest's lengths and XXHash64 values. SHA256 and CRC32 were additionally recorded. Total8,070,260 bytes. Verification used the standard `xxhash`3.6.0 package in a private tools directory, matching the launcher's XXH64 algorithm.

Files and source metadata remain outside Git in [asset-cache](<%USERPROFILE%/Documents/Projects/CartoonMMO/lab/references/asset-cache/cache-index.json>). That index maps each filename to its relative cached path, public source URL, documented install path, size, SHA256, CRC32, XXHash64 and original-manifest comparison. The cached files are flat; the documented installation is **disposable Client/custom/**. Neither original archives nor the preserved client were changed.

These are community custom replacements. None match the supplied original asset-manifest rows. For example, the custom0_0 GCNK is524,099 bytes/CRC1383523233; the original manifest requests15,301 bytes/CRC3617083543. Serving the replacement as though it satisfies that original row would misrepresent integrity. The matching custom GZNE/GCK2 files were fetched with parent authorization to keep the creator scene coherent.

The supplied `Assets_manifest.txt` independently verifies as CRC123886846, length9,479,368, SHA256`935bc0d9f8097df9909dc4d339770deb2e7596e3c61eb58876913431657778c8`. The community indirect server publishes a different CRC3387611285 at the same length. It was not substituted into the original client. Initial direct CDN tile paths returned403; the launcher-documented public client paths succeeded without authentication or access-control changes.

The parent installed the19 verified files into a temporary run's Client/custom. Run063016 then progressed through creator zone loading to StartUi, establishing that the supplied executable accepts the coherent custom scene override. It still stalled because the supplied starting-set resource is header-only; a manifest-verified populated community resource is now cached. See [[Character Creation Audit]]. Complete native creation and appearance persistence remain pending.
