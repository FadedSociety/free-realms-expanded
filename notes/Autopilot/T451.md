## (R) choices

- Restore = 2 on-foot speed, 64 = 0, 68 = 0 (both community servers clear 64 and 68; Sanctuary
  sets 2 back through its speed refresh). Glide fields 59-63/67 are not cleared at the end
  (GlideEnabled 0 is enough, and the next boarding always sends all nine).
- Bounds 0..=64 / 0..=10 / 0..=32 are sanity limits, not client constants; accel uses the speed
  range.
- "Trained" is the ride record's `is_upgraded` (false for every bundled ride), so only the Fire
  Hawk glides until glide training lands; OSFR sets IsUpgraded at purchase (lead note in brief).
- Mounted allowance: clamp(ride speed / 10, 1.0, 1.5); the Wolf (12.5) gives 1.25, the Lawn Chair
  (0) gives 1.0.
- Reply order: `ride_outcome` (moved unchanged) puts `private` before `shared`, so the owner gets
  the 38/7 just before the 168/2 on boarding and before the 168/4 on a ride end. Sanctuary sends
  the stats after its mount response. No client reader ties the two; a native run decides.

## Threat note

A client controls only the 168 request bytes and its position reports. Stat values come from
server data, never from the request; the target GUID is the session's own character, and the
38/7 goes only to the owner (`RideWire.private`, recipients `[owner]`). A refused board (wrong
actor, not owned, restricted, already seated) returns `Err` before any state or effect. The
allowance only grows while the server holds a boarded, owned ride, is capped at 1.5x by the
clamp and by the validator's own `mount > 1.5` refusal, and data bounds keep NaN and infinities
out of both the 38/7 builder (which asserts on NaN) and the clamp.
