# T434 — the coin store's Sell tab lists what 165/5 buys, at the price it pays

**Outcome.** One sale-price rule, `CoinShop::sell_unit_price`, now decides every 165/5 sale (and so
every buy-back refund, which repays the unit price the sale recorded). The shop-open 35/37 batch
that T362 added now also carries a ResellValue ("Worth") patch for each owned definition whose
client row shows something other than what 165/5 pays. The ring 75260 shows 37 and pays 37. The
bought necklace 75250 shows 375 instead of being hidden. The starter mallet 75030 and the starter
62473 drop off the tab (Worth 0). Copper Ore 2739 and the other 442 client-listed items that
`stores.json` never priced now sell for their own Worth instead of being refused silently.

Start check (step 0): T362 is merged (`04e1c8c`, `lab/autopilot/merged/T362-*.md`). Coin vendors
open with 165/10, and the 35/37 price-patch batch lives in `gameplay/npc.rs::coin_merchant_packets`.
The fleet research pack (tip `1e2def7`) said T362 was unmerged; that is stale. T429 (rides tradeable)
has not landed, so this task owns the one row walker in `inventory.rs` (lead amendment 2).

## What changed

- **`src/inventory.rs`**: one row walker. `skip_text` + `past_model_strings` replace the two
  hand-rolled string loops in `Requirement::from_wire` and `Inventory::presentation` (same
  results; a truncated row still gives no restriction / `Err`). `resell_value_offset` walks on past
  the tint alias. `Inventory::sale_flags(id) -> (no_sale, resell_value)` reads what `00cf08d0`
  tests, and `set_resell_value(record, worth)` writes only those four bytes. T429 can read the
  item type through the same `past_model_strings`.
- **`src/coin_shop.rs`**: `sell_unit_price(id)` evaluates, in order, (a) `stores.json` no_sale →
  `None`, (b) free issuance (all job starter items + the L040 Condo kit) → `Some(0)` with or
  without a store row, (c) `stores.json` sell price, (d) the client's Worth when NoSale is clear and
  ResellValue > 0 **(R)**, (e) `None`. `sell_with_merchant` uses it. The refusal codes are
  unchanged: no store row → `INVALID_ITEM`, refused row → `SERVICE_UNAVAILABLE`.
  `sell_worth_override(id)` returns the Worth the client must be told: the paid price when it is
  > 0 and differs from ResellValue, or 0 when the shop pays nothing (or 0) for an item the tab
  would list. The free set moved from `zero_starter_sell_prices` (which rewrote the catalogue's
  sell prices and could not cover items without a row) to `StoreCatalogue::free_items`. That
  function was deleted.
- **`src/gameplay/npc.rs`**: `coin_merchant_packets` takes the session's `CoinShop`. For each
  distinct owned definition with an override, it patches the Worth into the same record T362's
  price patch may already hold. The records are keyed by id in a `BTreeMap`, because
  `encode_definition_batch_v2` refuses two different rows for one id. There is still exactly one
  35/37 builder.
- **Tests**: new `tests/vendor_sell_worth.rs` (4 tests). The Roosey fixture moved out of
  `tests/vendor_coin_window.rs` into `tests/common/roosey_shop.rs`, so both suites share it
  (`vendor_coin_window`'s test body is unchanged apart from `Fixture::new(&[])`, `stock_prices()`
  and `fixture.open_shop`). `tests/vendor_sell.rs`'s "no store row" refusal fixture moved from
  instance 4 (definition 19522) to instance 67 (definition 60820). 19522 has no store row but a
  client Worth of 1, so it now sells by design. 60820 has no row and NoSale set, so it is still
  refused with `INVALID_ITEM`.

## Security note (secure-code-guardian)

A hostile client can send 165/5 with any instance id and quantity, and with any merchant. It
cannot name a price: 165/5 carries none (`00c75a70`). The server checks ownership,
`0 < qty <= available`, equipped and rental status, the price rule above and `checked_mul`
overflow (refused as `INVALID_QUANTITY`), then grants against the coin cap on a staged inventory.
New exposure: items without a store row now pay their client Worth. That cannot be turned into
coins from nothing:

1. Every Worth is ≤ its buy price (sweep test), so buying and reselling loses money.
2. The free re-granted items (job starters, the Condo kit) pay 0 even without a row, and that check
   runs before the fallback. A canary proves the order.
3. Rides and other NoSale rows stay unsellable.

Gathered and looted items selling for 1-coin-scale Worth is the intended economy. The 35/37
override is server-to-client and computed from server data only. A shop open costs one store
lookup per distinct owned definition (see Structure).

## Checklist

1. **A refusal changes nothing.** `rides_no_sale_rows_and_worn_items_are_refused_without_change`
   sells the no-row ride 7961, the store no_sale ride 76856 and a worn item that the tab would
   list. Each time it asserts a 165/6 failure and a `Gateway::snapshot()` equal to the one taken
   before. `vendor_sell`'s refusal table (19 tests) still passes. A refused sale returns before
   any state is staged; the sale itself still commits a staged inventory.
2. **Rollback covers all state.** There is no new mutable state. `free_items` is fixed at
   construction and shared through the existing `Arc<StoreCatalogue>`. The override is computed
   per open and never stored.
3. **Apply deltas.** Sales still consume and grant on a staged copy of the live inventory, and
   buy-back still refunds the recorded unit price. Nothing is restored.
4. **Busy rules mutual.** No new activity. The Shop path still passes the existing busy refusal.
5. **Every entry path gated.** The one price function sits under every 165/5 caller (4 in the
   graph). The override is built only on the 26/10 Shop selection, which is gated by range, the
   offered option and busy, as before.
6. **Reachable in production, tested through it.** The tests drive `Gateway::handle_at`: login →
   26/8 → 26/10 (165/10 + 35/37) → 165/4 → 26/10 → 165/5 → 165/6. Only the content sweep calls
   the production `CoinShop::sell_unit_price` directly over the shipped catalogue.
7. **Survives reconnect.** `granted_ore_sells_for_its_worth_and_survives_a_relog` round-trips the
   saved `GameplayState` through JSON into a new gateway: the coins (+1) and the remaining ore hold.
   The override is per session by design and is rebuilt on every open.
8. **Every exit path restores.** No new state or busy flag.
9. **Economy safety.** The client sends no price. Free starters and the kit pay 0 even without a
   row, checked before the fallback (canary 3). Worth ≤ buy for every priced row (sweep). Rides
   and NoSale rows are refused. Ownership, quantity and overflow checks are unchanged.
10. **Wire format matches the reader.** The pushed rows are decoded with `piece_096`'s 35/37
    reader layout (`008e3760` + `00919e10`). The test asserts each pushed row equals the login
    row except `resell_value` (and, for the stocked mallet, T362's `cost`), so exactly four
    bytes moved. The ring's offset (130 of 154) was checked by hand against the measurement.
11. **Unique ids.** None created.
12. **Others see changes.** Not applicable: the Sell tab is private UI.
13. **Content works end to end.** The ring sells for 37, the necklace for 375 and the ore for 1;
    the starters sell for 0; the rides are refused. All through the gateway, with final coin totals
    asserted (`10_000 - 750 + 37 + 375 + 1`).
14. **Values live in data.** Prices come from `stores.json` and the catalogue's own Worth. The
    free set comes from `profiles.json`/`houses.json`. No constants were added.
15. **Canaries break production code.** Three canaries, each in `src/`, each failing the named
    test (see Gates).
16. **Hands off session plumbing.** `gateway.rs` and `bin/osfr-gateway.rs` are untouched.
17. **One player's error never stops the server.** A shop-open error is that request's `Err`
    (refusal) and a sale failure is a 165/6. Nothing runs in the shared tick, and the arithmetic
    is checked.
18. **A type's rules live on the type.** `StoreCatalogue::free_items` documents what reads it.
    The sale rule is one method on `CoinShop`, and the row's sale fields are read by one
    `Inventory` method that cites the client offsets.
19. **Hot paths stay cheap.** Nothing per tick. Per Shop open: O(distinct owned definitions ×
    store rows), because the existing `StoreCatalogue::item` is a linear search. This is noted as
    a ponytail ceiling (index the store by id if shop opens ever show up in a profile).
