## Security threat note (secure-code-guardian)

- A hostile client can send 26/8, 26/10, 26/6, 49/2, 49/14 at any time. None
  of these is a new parser: each still goes through the existing router.
  Range, open-menu, job, prerequisite, reward-profile-unlock and
  once-per-grant-key checks stay server-side.
- A non-Archer cannot obtain Path: the offer returns no 49/1 and the whole
  `GameplayState`/save bytes are unchanged (tested; canary proves the test).
- A client cannot choose the end-screen actor. The 26/6 release uses the
  server-stored `runtime_guid` captured from the accepted 26/10 choice; the
  49/13 patch only replaces the server-built packet's speaker field. A
  rejected 26/6 changes nothing.
- Reward amounts come only from content; no client quantity reaches
  `apply_grant`. Duplicate 49/14 and replayed 49/2 after completion change no
  byte and pay nothing. XP can only be credited to an unlocked profile (35)
  and is keyed by the reward map, not by the active job.
- The recruit mapping is server content; a client cannot bind a runtime actor
  to a content key. `content_key` is not accepted from a request.
