## Findings

1. **BLOCKER - the "saved/reconnect" claim was an in-memory reload: fixed.**
   `Fixture::reload` passed the same `GameplayState` to `Gameplay::load`, so a
   save-codec regression could not fail the test. The chain test now uses
   `reload_serialized` (the same helper the Wizard and Missing Sisters reconnect
   tests use) and asserts the serialized bytes before/after are equal, then
   asserts `pending_turnin` survived. It then calls the production
   `update_npc_visibility` (the relog path wired in `src/gateway.rs:1477,1585`)
   and proves the held 49/13 is re-sent after the speaker's 35/2, names the
   runtime speaker, carries the debrief text and the 5/5 reward bundle. The
   client then answers 49/14 directly from that re-sent screen; no fresh Talk is
   needed. The post-completion reload is serialized and compares bytes too.
   **Failure scenario closed:** adding `#[serde(skip)]` to
   `QuestState::pending_turnin` broke the test (exit 101) at the serialized
   comparison, because the production loader's repair drops
   `pending_turnin_actor` when `pending_turnin` is absent.
2. **MINOR `[STRUCTURE]` - the audit mirrored the loader's geometry bound:
   fixed by deletion plus a loader-driving test.** `valid_visit_geometry` copied
   `src/quest_engine.rs:2545-2549` and its unit test only proved the copy.
   `from_split_content` rejects those values before the audit's
   `target_violations` runs, so the branch was dead on shipped content. The copy
   and the two geometry branches are gone; `visit_position` now appears in
   `unchecked_objective_kinds()` because only the loader decides it. The test
   name `visit_geometry_bounds_are_enforced` is in
   `lab/autopilot/protected-pass.txt`, so it could not be deleted; it now drives
   `Catalogue::load` (production `from_split_content`) instead: a valid
   `visit_position` fixture loads, while radius `0.0`, radius `1000.1` and
   position `1_000_001.0` are rejected. That is the review's "reuse the
   production bound" option, and it closes the loosened-bound failure scenario.
   No loader rule changed.
3. **MINOR - the temp-path claim was false: corrected.** The chain test's shared
   `Fixture` copies under `std::env::temp_dir()`; only the audit's `Scratch`
   fixture builds under `CARGO_TARGET_TMPDIR`. Both are test-only and remove
   themselves on drop. The F343 and T314 notes now name both paths. The shared
   fixture's base was deliberately not moved: dozens of chapter suites use it and
   changing its location is unrelated to the reviewed bug (`std::env::temp_dir()`
   is already used by most test fixtures in this crate).
4. **MINOR - the test bypassed the reward's profile-unlock gate: pinned and
   named, not papered over.** `a_locked_postman_profile_is_paid_nothing` runs the
   same production chain without unlocking Postman: the 49/14 is refused by the
   F249/T249 gate, no 49/4 is sent, coins and profile-4 XP do not change, the
   pending screen clears and the quest stays active for a later Talk. The content
   gap itself (no `job`/`min_level` on `3130032`) is pre-existing and unchanged;
   the guide places row 29 after the Postman level-20 gate (†), so adding a gate
   is a content decision outside F343/F365. The reward is no longer presented as
   universally grantable.
