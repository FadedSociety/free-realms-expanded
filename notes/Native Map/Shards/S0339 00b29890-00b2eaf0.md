## Data decoding and indexes

- Bounded cursor routines include scalar readers (`00b29bb0`, `00b29c10`, `00b2a090`, `00b2dd60`), record readers (`00b29890`, `00b29cd0`, `00b2b450`, `00b2b590`, `00b2b680`, `00b2de20`–`00b2e4b0`), and count-driven array/list readers (`00b29b20`, `00b2ddc0`, `00b2e2d0`, `00b2e620`, `00b2e910`). They advance the cursor, zero unavailable fields, and set a shared error byte on truncation. Several length-field helpers (`00b2b900`, `00b2ba20`, `00b2ea50`, `00b2eaf0`) validate signed lengths before advancing.
- Store definitions are indexed through linked lists and bucket tables: app-store bundle definitions use a 2048-bucket hash (`00b2d710`); store-bundle groups use 16 buckets (`00b2e780`); category groups use 64 buckets (`00b2e9b0`); app-store bundle records use 32 buckets (`00b2e820`). `00b2d760` removes a store-bundle-group node from both its hash chain and list. These are client-side lookup structures, not evidence of server-side storage semantics.
- `00b2a110` inserts integer-keyed nodes into a red-black tree and calls its fixup routine. `00b2d890`, `00b2d920`, and `00b2d9b0` link nodes into small hash tables. `00b2da70` sifts 0x60-byte records in a heap using a supplied comparator.
- `00b2a4d0` is anchored to `ItemRecord::vftable`; it checks a sequence of runtime conditions and returns 0, 1, or 2. The native body does not establish the semantic meaning of those codes. It is separate from the coin-store protocol and no packet/server rule is inferred from it.
