## Security threat note (secure-code-guardian)

Attack surface: a hostile client controls the chat family/subtype, channel, claimed sender
and target identities, message bytes, claimed position/area/guild id, and can drive
join/transfer requests by logging in, transferring and disconnecting. This change parses no
client field and adds no delivery path; it only observes server-owned membership for tests
and documents it.

Why the invariant is security-relevant: `joined` gates `ride_fanout` and the five
`Session::commit_outcome` transaction/entry/exit predicates. If a join path wrote the player
registry row (which owns zone/position) and the chat member but not `joined`, a live player
would be treated as not in the world: ride/pet fanout and the entry/exit predicates would
skip them while chat still found a member — silent divergence between who can see/ride and
who can chat. If a leave path skipped one of the three, a transferred or ended session could
remain visible to one subsystem. The new socket assertion and both canaries pin the
production `join_player`/`leave_player` writes, so that divergence now fails a test.

Refusal safety: F208 adds no refusal path. The existing refused transfers in
`two_bot_socket_membership_and_transfer` now snapshot the three-way membership tuple as well
as location/membership, and all three refusals (forged 41/103 entry, unknown target
instance, failed save) leave the tuple equal and write nothing. The probe is
`#[cfg(test)]`-only, so it is not reachable from the wire. No new `unwrap`/`?` on client data
and no change to parsing, saves, coins, items, rewards or roles.
