# T657: Station Cash Marketplace tiles: real description, icon, price and sale flag; each row in its own category

## Summary

The native finding (run `lab/runs/client-baseline-20261024T213325Z`, screenshot
`lab/reports/native-20261024-marketplace-rides.png`) had four client-side causes, all in the
66/5 bundle record. `src/station_cash.rs` wrote `0` in the description id (the `<STRING 0 NOT
FOUND>`), wrote empty image-set/tint strings (the empty icon box), wrote `1` in the field the
client reads as **IsOnSale** (so every tile showed SALE! and used SalePrice `0` instead of Price),
and put every non-ride row in the Rides category group. Its 66/7 count also counted only the
node's own group, not its descendants, unlike the client's own recompute.

Changes:

- `Listing` now carries the item definition's `description_id`, `icon_id` and `icon_tint`, read from
  `Inventory::presentation` in `Catalogue::build`.
- 66/5 writes the description at +164, the two image strings at the image object (+0x18), the price
  at +176, IsOnSale `0` at +243, the terms locale id `0` at +208, and MaxPerOrder `1` at +212.
  Image strings are decimal because the client `atoi`s them; `0` writes an empty string.
- `stores.json.station_cash.item_shelves` (new) names the client's real top-level categories for the
  non-ride rows: 45 Clothes & Armor, 59 Pets, 116 Housing. A row's `category_id` (the item
  definition's `CategoryId`) picks the shelf, else the item definition Type (2 pets, 16 lot deeds,
  29 housing fixtures). Rides and boomboxes keep their T495/T526 shelves.
- A listed row no shelf names fails the shop load; there is no Rides fallback. An untagged ride row
  still falls back to the Rides parent (item Type 19, the client's ride type). A package with the
  Station Cash block off keeps the old payment-free path: no catalogue is sent, so no shelf table is
  required.
- 66/7 now writes the node plus descendant count, the number the client recomputes (`00c37e70`).
- `StoreItem` reads the row's `category_id` and passes it as `StoreRow` to `Catalogue::build`.

The owned-ride 66/39 flag (T484/F656) is untouched.

Attempt 2 (this worktree) ported attempt 1's rejected hunk by hand and fixed its tip conflict: T528
had added the non-ride Training Saddle of Gliding (item 79150, type 80001) to the Winged child, so
the T526 empty-child test's "untag every Winged row" made a non-ride row fall through the new
no-Rides-fallback rule. The test now untags only rows whose `price_provenance.ride_id` marks a real
ride and moves the saddle to another child, so Winged is empty and every fixture row still maps.

## Security note (secure-code-guardian)

No new inbound selector or client-controlled field. The row category, description, icon, price and
sale flag are server content read at `CoinShop::new`; a client cannot choose any of them. The order
path still revalidates the store, bundle, server price, balance, bag and busy table on a clone.
`item_shelves` is deserialized with `deny_unknown_fields`; ids and item types are bounded and
cross-checked (unique shelf ids/orders, unique item categories/types, no collision with the
Rides/Boombox/ride-child ids and groups, max 64 shelves). A listed row with no shelf fails the
session's shop load with `Err`; nothing panics and no client value reaches a category, price or
definition lookup. The 66/5 writer emits only integers and the two decimal strings built from the
validated catalogue, so no client string is echoed.

   `StoreCatalogue::load`/`CoinShop::new` return `Err` before a shop or session state exists. The
   request-time refusals are unchanged (`refusals_change_nothing` snapshots inventory + wallet).
   Canary 2 breaks the duplicate check and the named test fails.
2. **Rollback covers all state.** No transaction or staged state is added; the category table is
   immutable content owned by `Catalogue`. A failed load produces no `CoinShop`.
3. **Apply deltas.** Nothing restores a snapshot; the order path is untouched and still commits the
   grant + debit on the existing clone.
4. **Busy rules are mutual.** No activity or busy gate is added; `place_order` still receives the
   shared busy answer.
5. **Every entry path is gated.** The category is derived once per shop in `Catalogue::build` and
   used by every 66/5/66/6/66/7 writer; there is no second category path. The order path is
   unchanged. A content set with Station Cash off returns the Rides group for every row and sends

   loads that package with no shelf table.
6. **Reachable in production, tested through it.** `tests/station_cash.rs` builds the real
   `stores.json` through `StoreCatalogue::load` + `CoinShop::new` and drives
   `marketplace_packets`/`catalogue_packets`; `tests/coin_store_siblings.rs` drives the gateway

7. **Survives reconnect.** Nothing new is persisted. The catalogue is rebuilt from
   `stores.json`/`mounts.json` every session; the wallet/replay tests are unchanged.
8. **Every exit path restores the player.** No activity, location or cooldown state is involved.
9. **Economy safety.** No price, grant or earn rule changed. The price written is still the
   server-side scaled `sc_price`; the sale flag is 0, so no discount/payout path opens. Earn-only
   rows still never reach 66/5. The category is server content, not a client input.

12. **Others see changes.** Nothing in this change is visible to other players.
