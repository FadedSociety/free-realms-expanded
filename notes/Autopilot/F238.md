## Client evidence (IDA, client 1.910.1.530630)

- Dispatcher `0x00b14350`: reads the shared two-u16 header with `0x00b0f550`, switches on the
  subtype, case 3 constructs `0x00b0f9d0` and calls `0x00b10a20`.
- `0x00b10a20` builds a reader context over the body and calls `0x00b0f5f0`.
- `0x00b0f5f0` reads: two u16 header words (`0x00b0f550`), a u32 byte length, that many text
  bytes (string setter `0x894b10`), then one flag byte at `+544`. That is exactly
  `[15,0,3,0][u32 len][escaped text][1]`, the bytes `chat::system` writes.
- `0x00b0f9d0` is the constructor (`sub_B0DA00(3)` + vtable), not the reader. The T199 code
  label was wrong; IDA wins over the earlier note.

## (R) reconstructed rules

- 200 characters / 2048 bytes are local defensive bounds (no recovered native broadcast
  command); the wire's 15/1 field cap (2048 bytes) refuses longer lines first.
- ASCII controls `< 0x20` and `0x7f` are refused; the refusal never echoes the input text.
- The command is matched on the first word after `realm `, so the message keeps its case.
- A combined bundle keeps the last broadcast text and never lets a later non-broadcast child
  clear an earlier one.
- The fanout is session-only and after a successful commit; a refused/failed transaction drops
  it.

## Threat note (secure-code-guardian)

Attack surface: a client's 15/1 body can carry any text, and any role that `command_refusal`
lets through reaches the parser.

- Player/builder: `broadcast` is not in the ordinary allowlist, so `may_run` refuses it before
  the command branch; one system refusal to the sender, witness silent, state/save unchanged
  (bin test).
- Control characters (CR/LF/tab/NUL/0x7f) are refused before encoding, so a hostile message
  cannot break the length-prefixed packet, forge a second packet or inject log lines.
- Oversized/UTF-8: 2048-byte pre-check then the 200-character bound, both before any packet or
  per-recipient allocation; the chat reader's 2048-byte field cap refuses longer wire lines
  first. A refusal shows only the fixed usage/error string.
- Markup: `chat::system` escapes `&`, `<`, `>`; no second encoder (exact bytes asserted per
  recipient).
- Identity: the client-supplied sender/recipient names and GUIDs in 15/1 are ignored; the
  session supplies the command identity.
- Fanout scope: only `chat_sessions` (world-entered sessions); a connected handshake session
  receives nothing (test). No offline player or other process is involved.
- Replay: a duplicated SOE reliable datagram is dropped by `ReliableReceiver` before gameplay;
  test sends the same sequence twice through `Session::handle` and each session receives one
  notice.
- Failure isolation: a failed save commits nothing and drops the notice; a recipient that
  leaves between commit and queue is skipped by the existing `queue_delivery` without failing
  the others. No new budget, role, security-log event or persistence.

## Checklist

1. **Refusal changes nothing** — bin rig snapshots character state and save bytes around role
   refusals and every invalid text, and asserts the witness receives nothing; the movie
   refusal asserts the loaded state is unchanged. No menu/offer/counter/cooldown is touched.
2. **Rollback covers all state** — the notice is one field on the staged `Outcome` /
   `GatewayOutcome`; no `Rc`/`RefCell`/`Arc` or side table. It is captured into a local in
   `dispatch_message_inner`, so a refused/failed transaction drops it.
3. **Apply deltas** — nothing here restores a snapshot; the fanout only appends deliveries
   after the committed world is live. `announcement_does_not_change_character_state_or_save`
   compares full gameplay + save bytes.
4. **Busy rules mutual** — no new activity or busy gate. A cooking movie owns the character and
   the existing intercept refuses the command before the parser (new test).
5. **Every entry path gated** — both realm paths call the same `world_notice::stage` after
   `command_refusal`/`may_run`; the opening (bin rig) and opening-less (`tests/world_notice.rs`)
   packs both have admin success and player/builder refusal tests. No parallel path.
6. **Reachable in production, tested through it** — the bin rig drives
   `Session::dispatch_message` → `Gateway::handle_at` → `commit_outcome` → `queue_delivery` →
   sender bytes; the replay case drives `Session::handle` with real SOE framing. No internals
   copied.
7. **Survives reconnect** — not applicable by design: the notice is session-only and never
   enters the save schema (`announcement_does_not_change...` pins byte-identical save bytes).
8. **Every exit path restores the player** — the command never moves, equips or locks the
   character; cancel/refusal/failure leave state identical; a recipient that leaves between
   commit and queue is skipped by the existing `queue_delivery`.
9. **Economy safety** — no coins, items, ids or rewards are touched or accepted from the
   client; only server-validated text is relayed; save bytes are pinned identical.
10. **Wire format matches the client reader** — 15/3 is reused; the client dispatcher, ctor
    and reader are cited above; the exact `[15,0,3,0][u32 len][escaped text][1]` bytes are
    asserted per recipient for a 200-character markup text.
11. **Unique ids** — not applicable; no instance/GUID/lifecycle id is created.
12. **Others see changes** — the existing directed chat path (`chat_sessions` +
    `queue_delivery`); every online session receives exactly one copy, including the sender; a
    session that has not entered the world receives nothing.
13. **Content works end to end** — each recipient's received text is asserted (not a flag), the
    sender is included, and no recipient gets a duplicate or the literal command.
14. **Values live in data** — 200/2048 are the task's explicit `pub const` spec, not tuning
    knobs; no timeout/window/cap was invented.
15. **Canaries break production** — F238's canary modified the production merge and failed the
    regression test (details above); the T199 canaries remain recorded in [[T199]].
16. **Hands off session plumbing** — the fanout is outside `commit_outcome` now; no change to
    session creation, teardown, transactions or save ordering. No lead-only file other than
    the existing hub call sites was touched.
17. **One player's error never stops the server** — the fanout runs in the session's own
    dispatch after commit; a queue error propagates to that session's `Server::step` `contain`
    boundary (disconnect for that player only). No `?` was added to a shared tick.
18. **A type's rules live on the type** — `Outcome.broadcast` and `GatewayOutcome.broadcast`
    have doc comments stating the session-only/no-save/after-commit rule; `world_notice::stage`
    is the one parse→assign/refusal rule both paths call; `absorb` is exhaustive.
19. **Hot paths stay cheap** — per packet: one `Option::or(..)` merge in the gateway (the dead
    guard is deleted); per tick: nothing. A staged notice encodes once after commit and clones
