# T240: field-enemy coin and active-job XP rewards (small T102 half)

## Result

Shared-world field kills now pay coins and active-job XP once per credited
player. The payout uses the existing `EncounterReward` -> `apply_encounter` ->
`grant_reward`/`award_job_xp` transaction, so nothing new touches the economy,
save or wire. The reward table is a separate content file, so
`field_enemies.json` keeps its schema and limits, and `src/encounter/field.rs`,
`src/encounter/shared.rs`, `src/gateway.rs` and `src/bin/osfr-gateway.rs` are
untouched.

Attempt 1's patch rejected only the `mod field_rewards;` hunk: the current tip
has `mod power_up_use;` between `mod field;` and `mod shared;`. The declaration
was re-added by hand in that position; no other hunk was rejected, the `.rej`
file was deleted, and the tree was rebuilt and retested from scratch.

What a credited player receives:

| Level band | Coins | Job XP | Source |
|---|---:|---:|---|
| 1-2 | 2 | 5 | `(R)` starter rate |
| 3-4 | 4 | 10 | `(R)` Highroad rate (220 HP kind) |
| 5-8 | 7 | 15 | `(R)` reserved band, no current actor |
| 9-13 | 12 | 25 | `(R)` reserved band, no current actor |

Definition override: `3156` (Hooligan Wolf, the three W102-F1 wolves) pays
`2/5` at any level, so raising the starter wolf's authored level cannot turn it
into a faucet. All numbers are reconstructed local balance, not recovered 2014
reward data; every row carries provenance in the JSON, and every reconstructed
row starts with `(R)`.

A `(0, 0)` row or a missing lookup pays nothing. The current field actors are
level 1 or 3, so the normal path is the 1-2 and 3-4 bands; the four
quest-gated Hooligans default to level 1 and now pay the starter band, while
their quest presence semantics are unchanged.

## Security note (secure-code-guardian)

Threat surface: client-crafted combat packets. A hostile client can send
`36/10` abilities, `26/8`/`26/10` interactions and `26/13` job switches, but it
cannot report a kill, damage, a definition id, a level, a coin amount or an XP
amount. The payout comes only from the server's own alive-to-dead HP transition
on a server-owned field actor row (`actor.definition_id`, `actor.level`) and a
loader-validated table.

Refused/ignored: replaying lethal damage or hitting a corpse (`s.health == 0`
guard), out-of-range/cooldown/evading/returning attacks, unknown or dead target
GUIDs, a bystander with no damage/target credit, a second claim for a consumed
credit, an expired credit (existing `CREDIT_TTL_MS`), a malformed/overlapping/
duplicate/out-of-bounds table (load error), and an unrepresentable payout
(checked against the live wallet/active job). The reward carries no items, so
there is no item grant, bag-capacity or trade surface. The table is trusted
local content read from a fixed filename; there is no client path into it.
All additions are checked/saturating, and a refused payout logs and returns
`Ok` instead of propagating out of the shared tick.

## Checklist

1. **A refusal changes nothing.** Test 1 replays the lethal hit and a corpse
   hit and asserts the live state, the field runtime and the save bytes are
   unchanged; test 3 asserts an expired credit and a bad table change nothing;
   tests 4/4b assert the refused payout leaves coins and XP untouched (no
   half-payment). Canaries 1/2 broke production code and failed the assertions.
   A refused *payout* does not undo the server-authoritative kill, by design.
2. **Rollback covers all state.** Pending pairs live in the cloned
   `SharedFieldState.kills`/engine `ledger` and are swapped with the field; the
   wallet/XP change happens on the staged `Gameplay` clone inside
   `apply_encounter`. No new `Rc`/`RefCell`/side table; the `Arc` is the
   immutable reward table.
3. **Apply deltas, never restore snapshots.** Coins/XP are checked-added to
   the live balance at application time; the credit carries the pair, never a
   cached profile snapshot.
4. **Busy rules are mutual.** No new activity, station or minigame; the
   `Occupation` table and all gates are untouched. Field combat already gates
   the attack.
5. **Every entry path is gated.** The only kill transition is `strike_damage`
   (basic attack, job abilities, DoT ticks, solo and shared paths); the only
   claim is `claim_kill_credits` through `shared_effects`. No new packet family
   or client-reported kill.
6. **Reachable in production, tested through it.** The tests drive
   `handle_shared_field` -> `shared_attack`/`handle` -> `strike_damage` and
   `tick_shared_effects` -> `shared_effects` -> `claim_kill_credits`, plus the
   production load and reload paths. No test-only copy of the logic.
7. **Survives reconnect.** Test 6 saves the character, drops the session,
   reloads through `game_store::load_or_create`, re-enters and claims once. The
   pending pair lives in the world-owned shared ledger, not the save; the
   existing `retain_casters` liveness prune is unchanged (a disconnect that
   spans a shared-field tick still drops the credit; process-restart durability
   remains lead task L010). The brief forbids editing `shared.rs`.
8. **Every exit path restores the player.** No new activity/location/control
   state; an unclaimed credit lapses on the existing TTL; respawn and the
   knockout paths are unchanged. Tests 3 and 6 cover expiry.
9. **Economy safety.** No client quantity/id/result reaches the economy; the
   payout comes only from the server HP transition and validated content; no
   items; the pair is paid once (canary 2); values are load-bounded.
10. **Wire format matches the client.** No new opcode or field. The existing
    38/19 (client ctor `0x0089e670`: one i32) and 38/14 (client reader
    `0x008d86e0`: six i32) are asserted byte-for-byte in tests 1, 2 and 5.
11. **Unique ids.** No new GUID/instance; the existing `(enemy guid, ms)` kill
    key plus player guid keys the credit; no public-world instance aliasing.
12. **Others see changes.** Coins/XP are private 38/19/38/14 replies. The field
    actor death and respawn packets are unchanged and still flow through the
    existing shared-field view; no new visible state.
13. **Content works end to end.** The shipped table loads (inline unit test),
    non-zero bands cover the current level-1/3 actors, the 3156 override is
    honoured, and the final wallet/active-job XP is asserted in tests 1/2/4/4b.
14. **Values live in data.** All rates live in `field_kill_rewards.json`; the
    code owns only the structural bounds from the brief (20 bands, 64
    overrides, 1000 per row, 1 MiB), not tuning.
15. **Canaries break production code.** Canary 1 removed the production reward
    push; canary 2 made the credit removal non-consuming; both failed the
    intended tests and were restored.
16. **Hands off session plumbing.** `src/gateway.rs` and
    `src/bin/osfr-gateway.rs` are unchanged; no session/save-ordering changes.
17. **One player's error never stops the server.** The representability refusal
    logs and returns `Ok`; tests 4/4b show the other player is paid and the
    shared tick still completes; no `?` propagates from the gate.
18. **A type's rules live on the type.** `FieldKillRewards` owns the loader
    bounds and lookup; `KillCredit.reward` is documented as carried until the
    claim; `apply_encounter_reward` documents the representability rule.
19. **Hot paths stay cheap.** Per non-kill hit the change copies one `u32`
    (`level`); per kill it does one `Option::and_then` + a binary search over
    <=64 overrides and a linear scan of <=20 bands and pushes at most one
    reward. The table is `Arc`-shared so a staged engine clone does not copy
    it. No per-tick allocation or clone was added; `claim_kill_credits` is the
    existing map removal. Per-kill cost is a few dozen comparisons; per-tick
    cost is zero when no credit exists.

## Open gaps

- All reward values and the override are reconstructed `(R)` balance; no 2014
  per-kill table was recovered.
- Levels 14-20 have no band, so a future field actor at those levels would pay
  nothing until the table gains a row (intentional: no guessing).
- A disconnect that spans a shared-field world tick still prunes the pending
  credit in the existing `retain_casters`; the T102 sign-off accepts in-memory
  durability and this brief forbids editing `shared.rs`.
- `content_check.py` validates JSON syntax/evidence but has no authoring rule
  for this table; the Rust loader + its unit/integration tests are the gate.
- The reward table is read at `EncounterEngine::load`; the existing `realm
  reload` path does not reload it (not required by this slice).
- The representability gate applies to every encounter reward (not only field
  kills); this is deliberate for checklist 17 and no existing test relied on
  the old `Err` path.
- No native client run. The IDA broker was available; no new wire field was
  added, so the cited pre-existing ctor/reader evidence above is the wire
  proof.
