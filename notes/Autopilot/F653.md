# F653: fixes from the review of T458 (`20a7a38`, world events part 1)

Brief: review findings 3 to 7 of `lab/autopilot/reviews/20a7a38-T458.md`. Findings 1 and 2 are
lead-only hunks the lead signed off; `src/gateway.rs` and `src/bin/osfr-gateway.rs` are not touched.

## What changed

- **Finding 3** (`world_event_routing.rs` `tick`, `world_events.rs`):
  - Once a session's queue refuses a packet, `tick` queues none of that session's later packets
    this tick and logs once for it (`world_event_delivery_refused`), not once per packet.
  - `WorldEvents::forget(session)` became `refused(session, undelivered)`. The host hands it the
    refused packet and every packet skipped behind it. The runner then:
    - keeps each undelivered removal owed: it goes back on `pending`, which the next tick sends
      first, so a refused `stop`, `remove` step or walk-out removal is never lost (no ghost);
    - owes a plain removal for every live actor the session was shown, then clears its
      `seen_by`. A session that took the AddNpc but refused the base animation therefore gets the
      removal before the second AddNpc.
    - `pending` is deduplicated, so a queue that stays full does not grow it: at most one copy of
      each removal per session.
- **Finding 4** (`world_events.rs` `load`): the file's size is checked against 1 MiB
  (`MAX_JSON_BYTES`, the bound `abilities.rs` and `power_ups.rs` use) before it is read; the
  error names `world_events.json`.
- **Finding 5** (`t458_world_events.rs`, `test_support.rs`): `test_support::lab_content()` is the
  one place that resolves `OSFR_APP_FUZZ_CONTENT` or the lab report path. `vendor_content` and
  `Rig::new` both use it, so a gate skips exactly when the content it would copy is absent.
- **Finding 7** (`gameplay/live_events.rs`): `realm_event` assigns `out.world_event` only in the
  start and stop arms.
- **Finding 6**: `notes/Autopilot/T458.md` has a "Skills applied" section naming ponytail.

## Threat note

Nothing a client sends reaches this code: the refused packets are the server's own, the runner only
re-sends removals it built. A hostile or merely slow client can fill its own queue; the effect is
bounded to its own session: `pending` holds at most one removal per actor per refusing session, and
the host drops packets for sessions that no longer exist. The file bound closes the admin-file
stall.

## Cost per tick

Idle: unchanged (empty `pending` and an empty `BTreeMap`, no allocation). With a refusing session:
one `BTreeMap` entry per refusing session per tick and a linear dedupe scan of `pending` (a few
entries).
