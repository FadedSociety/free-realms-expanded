# T743: a job_level goal may follow a Talk step; the turn-in stays at the quest's giver (3090027)

Brief: `lab/autopilot/running/T743-quest-job-level-later-step.md`. No earlier `T743-*.patch` existed; the Seaside
round-3 lane's draft (`%TEMP%\op-T725`, quest record and test, reference only) was reused where right, reordered to
the client's order (Beth's Talk first, then the rank goal).

## What changed

- `src/quest_engine.rs` (CRLF kept):
  - `validate_definition` no longer refuses an ordered quest whose `job_level` goal is not step 1 (F576's
    fail-closed rule, `notes/Autopilot/F576.md` finding 4). F576's reason was that nothing re-checked the goal when
    an earlier ordered step completed. That is now satisfied by the sync below, so the guard is deleted.
  - `QuestOutcome::activated_step()`: true when the outcome carries a 49/8 `ObjectiveActivated` (an ordered quest
    opened its next step). Client reader `0x00c7aeb0`, unchanged.
  - `on_event`'s `named_objective_target`: in an ordered quest only the FINAL step's Talk NPC is a named end-screen
    target. An earlier step's NPC (Beth) no longer opens the end screen once the quest is ready; the turn-in stays
    at `turnin_npc_id` (the giver, Callahan). Unordered quests are unchanged.
- `src/gameplay/npc_quests.rs`: `append_npc_quest_outcome_synced` = `append_npc_quest_outcome` plus
  `sync_job_level_objectives` when the outcome activated a step. `npc_quest_event` uses it, and so does the Talk arm
  of `gameplay/npc.rs::talk_to_npc` (the one `on_event` call that bypassed `npc_quest_event`). So a `job_level` step
  that becomes active is checked against the player's rank at that moment (rank 20 completes it at once), and the
  existing syncs (rank change, accept, turn-in, bind) keep crediting it afterwards.
- `data/content/quests/medic.json` (CRLF kept): 3090027 enabled, from `objective-specs-fixed.json q3090027`:
  `talk_to_npc` 9000000023 (Beth, text 387592) then `job_level` profile 11 level 20 (text 387591); giver and
  turn-in Callahan 9000000072; title 387577, offer speech 387576, description 387578, end 387579 (locale roles;
  `quest-lines/dialogs.json` has 387576/387578 swapped). Reward 5 coins + 25 Medic XP.
- `quest_engine.rs` also sets `outcome.changed = true` when `on_event` opens the end screen. Before, a Talk at the
  turn-in NPC of an already-ready quest opened the pending screen and sent 49/13 but reported `changed == false`,
  so the state change could be dropped from the save (it only worked when the Talk itself completed the last goal).
  A quest whose last goal is the rank goal is always ready before the turn-in Talk, so 3090027 needs it.
- Tests: `tests/zone_quests_seaside_round3.rs` (new, 5 tests), `tests/job_level_quest.rs` (the later-step case now
  loads), `tests/support/medic_entry.rs` (constant, enabled list, and the "stay disabled" loop) +
  `tests/medic_level_five_chapter.rs` (3090027 joins the enabled-Medic pins), `tests/npc_greetings_enabled_quests.rs`
  (Beth is a new enabled talk target with no first-person client line: one `BLANK_WITH_REASON` row).

- Offer gate `job 11`, `min_level 15`, prerequisite `3090006`: the guide's "Band 4: level 15 to 20"; the real

  after the minigame changes (no longer opens the end screen there; the giver still does). No test pins it.

pending turn-in is the server's). Forged 49/2 accepts and early Talks change nothing (tested).
