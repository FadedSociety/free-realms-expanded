## Threat note (secure-code-guardian)

No client input, save, packet, session or reward path was added. The audit is a
read-only test over shipped content; the fixture writes only under
`CARGO_TARGET_TMPDIR` and removes itself on drop. A hostile client cannot reach
any of this: it cannot choose a target id, quantity, result, reward or
serialized state, and nothing here grants coins/XP/items or starts a session.

The graded ids are a content-trust boundary: a bad dungeon, minigame, item or
recipe id now fails the gate instead of offering a quest whose reward is dead
content. The `finish_minigame` set is producer-derived, so a content row the
server can never emit (derby 39) is refused with the missing-producer reason
rather than trusted because it exists. The fixture's canaries deliberately
remove or corrupt scratch rows and assert the refusal; they do not touch
`data/content`. The only server constants mirrored in the test are the private
harvesting game id 111 and the three local gather keys, both commented with
their production owner.

## Open gaps

- **No derby `FinishMinigame` emitter.** Derby completion pays but never
  advances a `finish_minigame: 39` objective. The audit now refuses that target;
  adding the event (and its tests) is a production change for the lead.
- **No shipped item catalogue.** `data/content` has no `inventory.json` /
  `item-catalogue.json`, so the shipped item set is empty and the item branch is
  exercised only by the scratch fixture. When an enabled item quest or a
  catalogue ships, the audit grades it automatically.
- **`client_reported` remains residual.** Its `client_id` is a 45/7 trigger
  selector judged by the client, not a row in a shipped server id table.
- **`visit_position` is not graded here.** The split loader rejects
  out-of-range geometry (`visit_geometry_bounds_are_enforced` drives it), but
  there is no shipped zone/point id table to resolve the destination against.
- **Craft fallback constants are not mirrored.** The 46/77/139 job fallbacks are
  private `const GAME` values; the shipped recipe rows carry all three today, and
  the pinned set fails loudly if that changes.
- **Two enabled-but-unreachable records** (`3020014`, `3100020`) stay reported,
  not enabled or repaired; they need their disabled predecessors authored.
- **No native run.** The lead owns the client; this slice is a Rust content
  gate, and no client-visible behavior changed.
