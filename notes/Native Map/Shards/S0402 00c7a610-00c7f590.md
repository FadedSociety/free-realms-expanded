# S0402 findings

## Scope and classes

- `00c7a610–00c7ca80` covers client quest storage, selection, objective mutations, and quest-family packet readers/constructors. The quest map uses 256 low-byte buckets and runtime records linked at `+0x194` (`00c7a610`). Objective lookup uses 16 buckets; activation writes state/required at `+0xd0/+0xd8`, live update writes counter/progress at objective `+0xd4` and quest `+0x28`, completion writes state `2`, and failure writes state `3` (`00c7a910`, `00c7a990`, `00c7aa10`, `00c7aa90`). These agree with [[Research/Native Opening Quest Journal]] and [[Research/Native Journal Live Objective Keys]]; update keys match the runtime objective definition id.
- `00c7cd40` is the inbound quest dispatcher. It handles subtypes 1, 3–13 and 16, routes quest/objective changes into the mutations above, and updates journal/helper state. Quest completion removes the record and triggers removal bookkeeping (`00c7c130`, `00c7ab20`). End-blocked subtype 16 looks up localized text and displays a message window when found. Subtypes 14–15 are not dispatched in this function.
- Friend/ignore packet RTTI and family initializers appear from `00c7d870` onward. `BaseFriendPacket` stores family 74 and caller-selected sub-opcode; this range constructs FriendOffline(3), FriendRemove(7), FriendRename(10), FriendOnline(2), FriendStatus(9), and IgnoreAdd(2)/IgnoreRemove(3) objects (`00c7d870`, `00c7df20`, `00c7dff0`, `00c7e810`, `00c7e910`, `00c7ea20`, `00c7eec0`, `00c7e120`). The concrete constructors establish class and sub-opcode, not traffic direction. Typed FriendData/IgnoreData containers and a 0x28-byte FriendUpdatePositions entry array are present (`00c7e320–00c7e4f0`).
- The shard also contains IString reference-count cleanup and social-data ownership helpers (`00c7e2a0–00c7e2f0`, `00c7e6e0–00c7ebb0`), plus bounded short/byte and length-prefixed readers (`00c7ef80–00c7f590`). Names remain mechanical where the record shape has no RTTI or schema anchor.

## Packet and server-contract inference

The quest reader wrappers initialize a bounded cursor, call body readers, record short-read/NaN errors, and apply a trailing-byte policy (`00c7b3b0–00c7bbd0`, `00c7bd30`, `00c7cc80–00c7ccd0`). Quest packet class names are absent from `nmq packet`; therefore the JSON records leave `wire` empty for these functions and call out the catalogue gap rather than inventing catalogue entries. The client dispatcher proves that compatible quest-family records can update local journal state. It does **not** establish what the original server accepted, how it authorized progress, or which rewards it granted.

The social-family observations align with [[Research/Pieces/087 Friends and presence]]: family 74 and the listed friend sub-opcodes agree with the client constructors and supplied server enum. That note also documents the community model's FriendMessage discrepancy (community sub-opcode 8 versus client/server-enum sub-opcode 0) and that the emulator implements no roster/persistence behavior. This shard adds constructor evidence, not original captures or original server logic. No server behavior is inferred from these packet objects.
