# S0406 findings: UI data sources and backing containers

## Findings

- `00c90630`, `00c906f0`, `00c90790`, `00c8f830`, `00c90290`, and `00c8ff30` identify the `BaseClient.Profiles` data source and its filtered subtype. The base and filtered refresh paths rebuild row records; the virtual field reader at `00c8f830` switches across 16 column indices and resolves string IDs. This matches the 16-column `Profile_DS` / `Profile_Filtered_DS` schema recorded in `notes/Research/Pieces/031 Job catalogue.md`. The native code confirms a client reader and binding, not original server row contents or unlock logic.
- `00c90a80` registers `BaseClient.Acquaintances`. `00c90830` exposes five column labels (Guid, Name, Acquaintance Type, Elapsed Time, Online); `00c90930` returns their row values. `00c90890` dispatches the literal `SocialHandler:OnUpdateAquaintancesList` callback. The spelling is preserved from the binary. No packet (de)serializer in this shard establishes how the rows arrive.
- Lobby configuration UI code registers `BaseClient.LobbyGameOption%d` rows (`00c91670`). `00c91120` and `00c91310` expose option label/value/default columns; `00c912c0` refreshes linked records by key. These are presentation bindings and list updates; the source and historical server-side option set remain unresolved.
- `00c91ef0` constructs `BaseClient.Abilities`; `00c917a0` exposes Ability ID and Tooltip Description, and `00c91d30` returns the corresponding row fields. This is distinct from the separate `ItemAbilitiesDataSource` item-panel class documented under `Native Map/Classes/ItemAbilitiesDataSource.md`.
- `00c92700` / `00c928a0` provide an `InteractionDataSource`, with columns Id, Title, IconId, DefinitionId, Type, param1, param2, TooltipId, and Tooltip. Its storage uses 0x2c-byte rows (`00c920c0`, `00c92870`, `00c92a90`). The row schema is a client UI structure; it does not establish an authoritative interaction or server contract.
- Item-definition data sources share cache operations across `BaseItemDefinitionDataSource`, `AllItemDefinitionsDataSource`, `SingleItemDefinitionDataSource`, `FixtureItemDataSource`, `CustomizationItemDataSource`, and coin-store row sources. Their shared virtuals invalidate or remove cached rows (`00c93380`, `00c93990`, `00c942c0`); the column-name switch at `00c92c10` exposes 41 definition, display, inventory, and purchase fields. `ItemDefinitionDsUpdateDispatcher` is initialized and used to notify listeners (`00c93410`, `00c93c90`). The dispatcher and cache describe client-side update flow only.
- The shard contains several distinct container instantiations: 40-bucket integer maps (`00c917e0`-`00c91b50`), interaction-entry arrays, 1024-bucket item-entry maps and pools (`00c92e60`, `00c93520`-`00c953d0`), and a red-black tree/free-node pool (`00c948d0`-`00c951c0`). The tree successor/predecessor, transplant, rotations, insert/erase fixups, and pool grow/free routines form one allocator chain. This is consistent with the separate container patterns catalogued in `notes/Native Map/Systems/engine.containers.md`; the addresses are a different instantiation, not conflicting behavior.
