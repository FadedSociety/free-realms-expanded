## Systems and connections

This range does not expose file decoding or a concrete loaded asset.
- `0x009ce3f0` initializes two embedded `Vector4` list subobjects through `0x009cc1c0`, initializes state fields, looks up key `-0x606766c1`, stores the square of a matching or fallback value at `this+0`, and returns `this`. `0x009ce500` tears down the lists at `+0x474` and `+0x40` through `0x009ccbb0`. - `0x009cef40`, `0x009cf070`, and `0x009cf1c0` implement Win32 keyboard polling and a double-buffered, 256-entry key/action table. `0x009cf430` checks status/mana and emits `NoCast...` UI reasons. These are Lua/Flash UI calls, not network packets. Keep them distinct from the item-action-bar packet flow documented in [[Research/Pieces/048 Ability bar]].
- `0x009d0d70..0x009d22b0` contains SOE container/string support and name-plate state. `0x009d1d20` creates twenty `NamePlate%d` keys and initializes maps plus a debug-node list; `0x009d1eb0` allocates this object. `0x009d16d0` searches one hash bucket but unlinks the supplied node from the map list even if it is absent from that bucket; `0x009d17e0` repairs doubly linked-list endpoints and releases each node through its owner's allocator. - Vehicle-related work spans `VehiclePartProcessor` (`0x009d2530`, `0x009d2eb0`), its cached `ShipCombatAssetProcessor` factory (`0x009d25a0` constructs through `0x00c534f0`), and shutdown/update helpers (`0x009d2640`, `0x009d2670`, `0x009d2690`). Their mode-zero allocator policy can shrink an oversized buffer to about `6/5` of the request, while nonzero mode requests exact capacity (`0x009d2f30`, `0x009d3060`); the swap methods exchange pointer/capacity/count only for zero mode and otherwise dispatch through the source vtable (`0x009d2ff0`, `0x009d3120`).
