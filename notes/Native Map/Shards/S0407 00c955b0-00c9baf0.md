## Data-source cluster

The first part of the shard implements Scaleform-style GUI data sources. `BaseItemDefinitionDataSource` owns common cache, filter, and hash/list state (`00c956c0`, `00c963b0`, `00c96a30`, `00c968b0`). Its derived all-item and single-item sources name the tables `BaseClient.AllItemDefinitions` and `BaseClient.ItemDefinitionSelect` (`00c974c0`, `00c975c0`). The item-group data sources name their exposed columns directly (`00c96b70`, `00c96be0`) and resolve item definitions by id (`00c96ce0`). The exact vtable slots identify constructors, row/count access, field formatting, refresh, and destructors across these classes.

The same region includes the Adventurers Journal's region, hub, sticker, and miscellaneous-quest data sources. Constructors bind to `BaseClient.AdventurersJournal.RegionData`, `.HubData`, `.StickerData`, and `.MiscQuestData` (`00c98ad0`, `00c98b80`, `00c98c30`, `00c98ce0`). Their column-name and row-value methods expose chapter/map, quest, sticker, completion, and hub fields (`00c97710`, `00c977a0`, `00c97850`, `00c978c0`, `00c97f30`, `00c98170`, `00c98400`, `00c985f0`). `00c97de0` walks active quest records and excludes ids found in the hub-quest map; `00c97d70` counts that same filtered set. Existing `Research/Native Quest Journal UI.md` directly documents `00c97de0` and `00c98ce0`.

`OptionsDataSource` similarly binds to option rows and exposes setting columns and typed field values (`00c98db0`, `00c98e90`, `00c99250`, `00c99920`). No wire packet construction, parsing, or dispatch is visible in these functions, so this shard yields no server contract inference.
