## Security threat note (secure-code-guardian)

A hostile client still cannot name a reward amount, item, definition or
result: the payout comes only from the server's own actor HP transition or won
battle state plus the loader-validated content table, and this diff adds no
input field or request. The refusal is a fixed server text; no client string is
echoed. On a cap the whole reward is refused before any mutation, so the
player cannot mint a withheld component; the item, coin and job-XP surfaces and
the price/sale paths are untouched. The content read is local trusted data, not
client input, and the new helper bounds the allocation: a file that grows (or a
swapped symlink) after the metadata check reads at most `MAX_BYTES + 1` bytes
and is refused, instead of being allocated in full. Malformed/oversized content
still refuses the load rather than partially applying. No session, save, trade
or role surface changed; the gateway edit is a `#[cfg(test)]` module.
