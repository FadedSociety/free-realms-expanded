# D010: delete the captured-template startup fallback (S2)

2026-10-20

## Result

The gateway has one startup path again. Deleted from `src/gateway.rs`:

- `templates_for`, `initial_zone`, `template_fallback_enabled`, and the
  `template_fallback` field;
- the `Template` struct, the `templates`, `self_layout` and `zone_layout`
  `Gateway` fields, and the `creation_identity` helper;
- the fallback branches in `startup_for`, `load_internal` and `runtime_zone`.

`startup_snapshot: StartupSnapshot` and `self_data_template: SelfData` are now
non-optional. `load_internal` always loads the typed snapshot (an explicit
override or `lab/content/startup-snapshot/startup.json`) and always parses
self data from template 7. `startup_for`, `build_self_message`,
`quick_chat_catalog` and `public_look` lost their dead `ok_or_else`,
`.or_else` and `flat_map` fallback branches. `creation_identity` is inlined
into `set_identity`.

`load_reference` keeps its complete validation untouched: it still reads all
46 captured templates, checks every length/hash/opcode/phase, derives and
compares both field layouts, and checks GUID/position/rotation/zone against
the manifest's initial state. It now returns only template 7's bytes instead
of `Vec<Template>`; the manifest is still returned because the load path needs
`client_version` and `initial_state.zone_id` and `reference_state` needs the
initial state. The manifest's `templates`, `self_layout` and `zone_layout`
fields stay because the validation reads them.

`runtime_zone` now has one source after the gameplay scene: the typed
snapshot's login zone. `startup_for` no longer consults either an environment
variable or a second byte path.

No test was removed. Nothing in the repository ever set
`OSFR_GATEWAY_STARTUP_TEMPLATE_FALLBACK`, so no test exercised only the
fallback.

## Client evidence and IDA

No opcode, packet field layout, enum value or client behaviour changed. The
delete removes a server-side alternate byte replay; the remaining built
sequence is byte-identical to the pre-change default, which the ignored
`built_startup_sequence_matches_the_captured_character_byte_for_byte` oracle
proved again after the edit (46/46 messages match the private capture).

The startup facts the remaining code relies on are unchanged and were already
native-checked: index 07 is opcode 12 self data (dispatch `0x009471a0`, self
handling `0x00944fe0`, constructor `0x0089b240`) and index 03 is opcode 43
zone details, per `notes/Research/Startup Integration.md`. I tried a fresh
`ida_query.py func 0x00944fe0`; the IDA broker did not answer within 10
minutes, so there is no new IDA citation. No new field was guessed, and this
deletion has no new wire rule to verify.

## Security note (secure-code-guardian)

The fallback was never reachable from client input: it was selected only by
the gateway process environment
(`OSFR_GATEWAY_STARTUP_TEMPLATE_FALLBACK`), and no packet could choose it.
Deleting it removes a hidden server-side alternate startup path; a missing or
invalid typed snapshot now fails the load instead of allowing a replay. A
hostile client still reaches only the existing login parser (ticket, GUID,
client version), and the reference loader still validates the manifest's
relative paths, 46 hashes, phases, opcodes, proven field layouts and the
initial character before any bytes are used. The load path never trusts a
client quantity; `set_identity` still enforces the saved GUID before applying
identity, and the inlined `creation_identity` keeps GUID 1 for the
creation-identity type (the selected character GUID stays in the separate
self-data identity field). No item, coin, reward, chat, save or trade code was
touched. No refusal state exists in the changed paths beyond load errors
(which return before a `Gateway` is built) and the unchanged in-world
refusals.

## Checklist

1. **Refusal changes nothing.** No client refusal changed. The deleted
   fallback was server-env-only; the remaining `Gateway::handle` refusals are
   untouched. Existing refusal tests (`login_and_world_entry_are_validated_once_per_session`,
   the app_fuzz hostile corpus and the t3 malformed/bundle refusals) all pass.
2. **Rollback covers all state.** No transaction or staged state changed; the
   removed fields were read-only reference bytes and layout offsets. `Gateway`
   is still a plain owned clone; no `Rc`, `RefCell`, `Arc` or side table was
   added.
3. **Apply deltas, never restore old snapshots.** No payout, inventory, coin
   or position transaction was touched. The remaining self-data builder
   applies the live character's GUID/position/rotation and gameplay state to
   its copy; it does not restore a captured snapshot over live state.
4. **Busy rules are mutual.** No activity, busy gate or `occupation.rs` change.
5. **Every entry path is gated.** No new entry path. Deleting the fallback
   removes an ungated server-side alternate; `startup_for` keeps its login and
   ready callers and the same version/auth parser.
6. **Reachable in production, tested through it.** The real path is
   `Gateway::load*` -> `load_internal` -> `Gateway::handle(Login/Ready)` ->
   `startup_for`; the synthetic and private-oracle tests drive that path, and
   `app_fuzz` logs in and readies through `Gateway::handle`.
7. **Survives reconnect.** The snapshot and self-data are reference data, not
   session state. `reset_session` and a second login are exercised by
   `login_and_world_entry_are_validated_once_per_session`; no save field
   changed.
8. **Every exit path restores the player.** No cancel, disconnect, timeout or
   win path was touched.
9. **Economy safety.** No reward, item, coin or grant path changed. The
   deleted `templates_for` only formatted startup bytes.
10. **Wire format matches the client reader.** No field added, removed or
    reordered. The ignored byte-for-byte oracle passed for all 46 messages
    after the edit. Fresh IDA was unavailable (broker timeout), and no new
    fact was introduced; the existing addresses are recorded above.
11. **Unique ids.** No instance id, GUID or lifecycle id was added or reused.
12. **Others see changes.** Startup self data is per-player, not a
    directed-visibility broadcast; no fanout path was touched.
13. **Content works end to end.** The startup sequence still emits the 8 login
    and 38 ready messages; the private byte-for-byte oracle and
    `synthetic_startup_sequence_has_the_expected_phase_order_and_lengths` both
    pass. No content changed.
14. **Values live in data.** The deleted fallback switch was an environment
    flag, not a gameplay value; no timeout/cap/tuning constant was added. The
    snapshot path stays configurable through `OSFR_GATEWAY_STARTUP_SNAPSHOT`.
15. **Canaries break production code.** Yes: the canary changed
    `startup_for`'s login range and a real startup test went red; exact bytes
    were restored and the test passed.
16. **Hands off session plumbing.** `src/bin/osfr-gateway.rs` was not touched;
    `src/gateway.rs` changed only reference loading and startup message
    building, not session creation/teardown, transactions or save ordering.
17. **One player's error never stops the server.** No shared-tick or
    per-player reward code changed; no `?` was added to a tick. The removed
    fallback could return load-time errors only while the gateway was being
    created, not while the server was stepping.
18. **A type's rules live on the type.** The former `Option` fields carried
    the fallback decision in `load_internal`; now the field types are
    non-optional and `startup_for`/`build_self_message` cannot silently choose
    a second path. No new field was added.
19. **Hot paths stay cheap.** Startup building is not a tick path. Per login
    the change removes an `Option`/environment branch; the self-data clone is
    the same clone as before, and no whole state is cloned per packet/tick.
