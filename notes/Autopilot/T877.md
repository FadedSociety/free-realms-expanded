# T877: a committable item table for releases, built from the original item table

Skills applied: ponytail (full) with its review pass on my own diff, surgical-patch (one loader slot),
secure-code-guardian (threat note below).

## What changed

- `scripts/build_item_catalogue.py --release-table` writes `prototype/osfr-tools/data/release/item-table.json`
  from the pinned original table alone (SHA-256 checked, PS3 client `resources/itemdefinitions.txt`, via a
  community bundle 2026-10-28). No Legacy, Sanctuary or lab input except the committed release `inventory.json`
  (for the wield map, below). A rerun is byte-identical (two scratch runs and the committed file share SHA-256
  `8c604537f4a6...`).
- Format: one array per item, `[id, [22 ints + a flag-bit word], model, texture, tint alias]`, 57,925 rows,
  8,169,970 bytes (under the 10 MB upload limit; the lab catalogue's 69.7 MB shape was hex per row). Columns and
  flag names are repeated in the file and the loader refuses a file whose lists differ.
- `src/inventory_item_table.rs` (a child module of `inventory.rs`, like `v2_fixes`) rebuilds each item's
  serialized `ClientItemDefinition` row from the columns (field order: reader `008e3760`, extension `00919e10`,
  the same order `Inventory` already documents). The file's `wire_sha256` is the established Python encoder's hash
  over all 57,925 rows; a test hashes the Rust bytes and compares, so the two encoders cannot drift.
- Slot and precedence in `Inventory::parse_content`: `inventory.json` first, then `item-catalogue.json` (the lab
  catalogue), then `item-table.json`, each `or_insert`. **The lab catalogue wins where both define an id** (it
  carries Legacy's stats, abilities, wield types and the Legacy-only ids); the table fills what both lack. The
  content cache key now also stamps `item-table.json`.
- `read_catalogue_file` is the old size-bounded read of `load_catalogue`, moved out so both loaders use it.
- `tests/release_content.rs`: `item-table.json` joins `RELEASE_FILES` (the publishable test now covers it: UTF-8,
  under 10 MB, no absolute path, no capture-server words).

## What the table holds (R)

Every wire field the original table names comes from its row (the 32 columns of `PS3_COLUMNS`). Not named by the
table and left at zero: tint and unknown5, VIP rank, race set, equip requirement set, resell value, PARAM3, and
the stat and ability lists. So a release item has no stat list, and the sell Worth is set by the server as
before. `wield_type` is not in the table (the class-to-wield table is Sanctuary's): it comes from
`wield_by_class`, 17 classes, read from the committed release `inventory.json` rows that have no `source` tag
(captured rows; the generator refuses a class whose captured rows disagree). A class no captured row shows reads 0.
Follow-up: the wield type of the other weapon classes (a client or capture fact is needed; not Sanctuary).

## Step 4: the reconstruction-only ids

`reconstruction_only_ids` in `data/reference/item_table_ps3.json` holds 957 ids that are not in the original
table: 790 Legacy-only plus 167 captured baseline ids (the brief's 917 counts Legacy alone and is older than T875's
47-row overlay; T875 notes the same). Release content alone:

- the 167 baseline ids are already defined by the release `inventory.json`;
- of the 790 Legacy-only ids, **713 are referenced by shipped content** and do not resolve in a release: stores 713,
  housing fixtures 156, boomboxes 6, pets 3, mounts 1 (id 79150), SC rewards 2, collection catalogue 1 (79446)
  (counted per file; the union is 713). The other 77 are referenced by nothing shipped.
- No quest, vendor, recipe or collection-node reference is unresolved.
- They keep working in the lab: the lab `item-catalogue.json` is untouched and wins. No Legacy row ships; the test
  asserts every unresolved shipped id is in `reconstruction_only_ids`.

## Tests

`tests/release_item_table.rs` (6): the after counts and the reconstruction-only rule; the before counts (the
release `inventory.json` without the table); every row's Rust bytes hash to the generator's `wire_sha256`, plus a
sample price (320, `00cff140` case 27), texture and tint; the file is publishable (size, source hash, no Legacy,
Sanctuary or AGPL in the description); the lab catalogue wins and a lab-only id loads while a table-only id keeps
its table bytes; six malformed tables (schema, column order, duplicate id, flag bits, overlong text, id 0) are
refused. The generator self-check covers `release_table` and `wield_by_class`.

## Checklist

Threat note: the table is operator content, not client input; a hostile client sends only item ids, which index a
`BTreeMap` and never reach a path. A hostile or corrupt file is refused whole: schema, column and flag lists, id
> 0, duplicate ids, flag bits, text length (4,096), the row cap (65,536), the byte cap (32 MiB) and the file cap
(128 MiB) all apply.

1. Refusal changes nothing: a refused table fails `Inventory::load` before any state exists; the six-case test
   asserts the error and loads from scratch copies.
2. Rollback covers all state: not applicable (content load).
3. Deltas not snapshots: not applicable.
4. Busy rules: not applicable.
5. Every entry path gated: one loader (`parse_content`) serves every `Inventory::load`.
6. Reachable in production, tested through it: `Inventory::load` is the gateway's loader; the existing world-entry
   test in `release_content.rs` now loads the table through the real gateway (the overlay is copied whole).
7. Survives reconnect: not applicable.
8. Exit paths: not applicable.
9. Economy safety: more items become grantable (store, vendor, recipe, collection rewards); prices are the
   original table's cost column and the server still sets sell Worth itself. Items the table marks NO_SALE or
   NO_TRADE carry those flags in the wire row (`NoSale`, `NoTrade` bits).
10. Wire format: no packet layout changed. The row order is the one already pinned for the lab catalogue
    (`008e3760`, `00919e10`), and `wire_sha256` ties the Rust encoder to the Python encoder byte for byte.
11. Unique ids: duplicates are refused; id <= 0 refused.
12. Others see changes: not applicable.
13. Content end to end: the test asserts which store, vendor, recipe and collection ids resolve and that the
    unresolved remainder is exactly the known reconstruction-only set.
14. Values live in data: the whole table is data; the caps are the loader's existing limits.
15. Canaries break production code: both canaries edited `inventory.rs` and `inventory_item_table.rs`.
16. Session plumbing: untouched.
17. One player's error: not applicable (load time).
18. A type's rules live on the type: `COLUMNS`, `FLAGS` and `Row::wire` own the layout in one file; the generator
    repeats both lists in the file for the loader to compare.
19. Hot paths: nothing per tick; the parsed content is shared through `shared_content`.
