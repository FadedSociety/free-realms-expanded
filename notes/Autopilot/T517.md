## Security note (secure-code-guardian)

A hostile client can send any bytes as a 174/16 body, including huge/negative string lengths,
invalid UTF-8, trailing garbage, a wrong family/subtype or a system other than `Housing`. All are
refused with `None` before any state or save access; string lengths over 256 and invalid UTF-8 are
rejected before a string allocation, and a negative length is rejected. The reply decode is
test-only and bounds the count by the remaining body before allocating. The handler is read-only:
it never trusts the owner guid, candidate id or correlation for anything but building one 15-byte
reply; it touches no inventory, coins, save, lot, fixture or session state, and it sends nothing
to other players. One request produces at most one 15-byte reply, and the gateway's existing
packet budget bounds the rate. No `unwrap` runs on client bytes.
