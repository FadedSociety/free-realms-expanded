# F862: T790 review blockers fixed

Fixes the findings in `lab/autopilot/reviews/97077dc-T790.md` (commit `97077dc`, task
T790) on the autopilot tip. All seven code/structure/notes findings are fixed and each
real bug has a regression check; finding 8 is the reviewer's stated data-brief gap and is

## Findings and what changed

1. **BLOCKER [STRUCTURE] — re-declared scratch tree and JSON writer.**
   - New `prototype/osfr-tools/tests/support/scratch.rs` owns the one scratch content
     tree: `CARGO_TARGET_TMPDIR`, a per-process/per-call unique name, the `quests/` and
     `npcs/` directories the split loader reads, and removal on drop.
   - `tests/quest_any_of_objectives.rs` deleted its private `Scratch`, `static NEXT` and
     `write_json` (old lines 66-102) and now includes `support/scratch.rs` and
     `support/json.rs`; its JSON writes use the existing shared `json::write_pretty`.
   - The pre-existing `tests/support/quest_catalogue_fixture.rs` had the same duplicate
     `Scratch`/`write_json`; it now re-exports the shared `Scratch` (`pub use
     scratch::Scratch`) so `enabled_quest_reachability`'s import path is unchanged, and
     uses `json::write_pretty`. That removes the second copy the review's failure scenario
     named, not just the new one.
   - `json::read` got the same `#[allow(dead_code)]` marker the writer already had, because
     the two split fixtures include the module only to write.

2. **MINOR [STRUCTURE] — fishing inventory fixture duplicated.** `fishing_packets.rs` now
   owns `definition_row(id)`, `write_inventory(directory, player_guid, definitions)` (the
   player guid and any definition rows are parameters; it creates its directory) and
   `reward_state(directory, capacity)`. `tests/fishing_service.rs` deleted its local
   coins/items/equipment span writer, definition row, digest/hex helpers and profile
   construction, and calls the shared writer with the definition row for item 100 and the
   shared reward-state loader with its existing capacity 4. The any_of suite uses the same
   writer via `fish_inventory_rewards`.

3. **MINOR — the fish test measured bag capacity.** `fish_inventory_rewards` now takes the
   bag capacity. The any_of catch test passes 500 slots for its 500-attempt loop (the bag
   can never fill first, so every paid catch produces its `CollectItem` event), and
   asserts `bag_capacity >= 500` so a later edit cannot silently restore the old
   4-slot/release behaviour. `fishing_service` keeps capacity 4, unchanged.

4. **MINOR — missing lower/count bound tests.** `tests/quest_any_of_objectives.rs` adds
   `one_alternative_is_rejected_at_load` and `count_bounds_are_rejected_at_load`, each with
   positive controls on both loaders: the split loader (`from_split_content`, reached by
   `Gameplay::bind_npc_quest_catalogue`) and the flat loader (`ContentDb::load`). Count 1
   and 1_000_000 load; count 0 and 1_000_001 are refused; one alternative is refused while
   two load.

5. **MINOR — strict content gate did not know `any_of`.** `scripts/content_check.py` adds
   the kind to its known-kind table and `Checker::check_any_of` enforces the same shape as
   `content::validate_any_of`: 2..=8 alternatives; only `talk_to_npc` / `collect_item` /
   `gather_resource` leaves; positive ids with the Rust target bounds; unique targets; one
   family. The goal `count` uses the ordinary 1..=1000000 rule. `scripts/test_content_check.py`
   pins every clause (valid at both count bounds, one/nine alternatives, mixed family,
   unknown leaf, duplicate target, non-positive target, count 0 and 1_000_001).

6. **MINOR — false/overstated note claims.** `notes/Autopilot/T790.md` now says the
   split-loader tests use `from_split_content`, the flat-loader tests use
   `ContentDb::load`, `one_event_counts_once` uses `QuestEngine::new`, and that the Rust
   gates are green while the strict content gate is baseline-red at 218 errors. Its
   ponytail-review paragraph records the two cuts F862 made (shared scratch/write, `Vec`
   dedupe) and its open-gaps item for the content gate is marked fixed. The builder report
   that repeated the "all gates green" line lives under `lab/` outside this repository, so
   it cannot be part of this diff; this note is the persisted correction.

7. **MINOR [PONYTAIL] — `BTreeSet` for at most eight ids.** `src/content.rs`
   `validate_any_of` now dedupes with a `Vec<u64>` and `contains`; the `BTreeSet` import is
   gone. The alternative bound is 8, so the linear scan is smaller and allocation-free
   apart from the one eight-slot `Vec`.

8. **MINOR [SCOPE] — no shipped quest authors `any_of`.** Not fixed: the reviewer states
   this is a data-brief gap, not a code defect. The candidates the T790 note lists still
   need a drawable giver, non-empty objectives and a real reward; authoring those without
   cited data would fabricate content (and the strict gate would rightly grade it). Kept
   as an open gap for the zone/data brief.

## Threat note (secure-code-guardian)

A hostile client cannot invent an alternative, a count or a family: all three are
server-authored content loaded at startup and validated by both loaders (2..=8, one
family, positive unique targets, count 1..=MAX_COUNT). A client can only trigger the
ordinary existing events the plain goals already accept: an in-range NPC Talk, a
server-verified inventory grant, a server-graded gather, or a server-settled fishing catch.
`validate_event` still bounds every event id positive and every quantity 1..=MAX_COUNT; a
non-member id/family changes no counter and emits nothing (`non_member_changes_nothing`).
Progress saturates at `required`. This fix adds no packet parser and no client-controlled
quantity. `scripts/content_check.py` is a developer gate: it reads repository JSON only,
never network input, and an unknown alternative kind is a reported error, not an exception
(the regression covers both). The new `Scratch` dirs are test-only, under
`CARGO_TARGET_TMPDIR`, unique per call, and removed on drop.
