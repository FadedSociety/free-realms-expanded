## (R) rules and decisions

- A result is quest authority only when the value behind it was judged or measured
  server-side. A server-built 39/18 alone is not enough: the cooking and smelting
  movies put the client's `FRServer_GameWon` score and `game_stats` timer into that
  record, so those producers credit the game id only (F854). Forging measures both
  server-side; mining and harvesting take them from their own engine state. The
  client cannot report a win, placement or knock-out. Derby contacts stay the
  existing bounded 34/16 reports; damage/score/knock-out are resolved server-side.
- Derby placement ties share the better rank; the Results list's damage tiebreak is
  display order, not quest placement.
- Derby knock-out: any contact that reduced the participant to zero health during the
  match, counted on the transition; a health pickup does not erase it.
- Kart elapsed: last completed lap timestamp minus race start, from the session
  snapshot; a reconnect before the claim keeps it.
- A `require` on a fact the producer never reports can never complete, so the
  reachability gate refuses to certify it (fishing: no facts; kart: no placement;
  derby: no elapsed; craft: no placement).
- The shipped demo derby binding accepts one human participant, so its placement is
  the server's own ordering over that participant set; the service code is general
  (a two-driver test covers rivals), but the current package has no cross-player
  routing.

## Threat note (secure-code-guardian)

What a hostile client can send: `39/x` movie frames and `34/16` derby contacts.
- A crafted 39/18/39/14 frame cannot fabricate a result: `npc_minigame_win` and
  `npc_minigame_result` inspect only the server-built replies, and the movie engines
  accept only their own protocol messages. Score, elapsed, placement and knock-out
  come from server state or server-built packets.
- A forged 34/16 contact is already bounded by the derby service (fresh pose, range,
  cooldown, max damage, alive victim); score, knock-out and placement are computed
  server-side. A client can farm NPC knock-outs, but that is the existing match
  design and still requires a finished server-observed match; this task adds no
  reward.
- A `require` id is compared exactly; a fact the producer did not report cannot meet a
  bound; result fields are range-checked before `on_event`, and out-of-range packet
  values or derby scores are dropped to `None`, never an error.
- No item, coin, role, chat or persistence field is trusted from the client. Quest
  progress remains the engine's capped counters; result facts are never saved.
- `credit_minigame` returns `Err` only for a malformed authoritative event; producer
  ids are positive and content-validated (derby game id, kart speedway, recipe game
  id, 39/18 game id). The derby score filter keeps an absurd operator-configured
  score from turning a settled match into an `on_event` error.
- No secrets, keys, player names, chat text or absolute home paths are in this diff.
