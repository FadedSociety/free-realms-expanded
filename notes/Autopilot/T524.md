## Reconstructed rules (R)

- No job gate on a collection node; the click grants exactly one item; the node is personal (not
  shared between players).
- One drop is rolled by weight from the **pool's** table; the type tables stay empty for the
  imported file (validated at load).
- The roll is seeded from `(player guid, node guid, click now_ms)` with `Rng::seeded(Rng::mix(..))`:
  every click rolls afresh (Sanctuary rolls its shared stream per click), so a player can reach every
  item of a pool's table over repeated clicks and fill its collections. A first version seeded only
  from the guids gave one fixed item per node per player forever (review blocker; the shipped pools
  hold 64-258 drops on 3-18 nodes). The brief's "seeded the way power-up drops are seeded" is stale
  (power-up drops use `from_entropy` with no fixed-seed hook); a stateless time mix keeps "no RNG
  advance committed on refusal" trivially true. `now_ms` is the server's own clock (R: a player cannot
  steer it to the millisecond over network jitter; no client field enters the roll).
- `respawn_seconds` from the pool starts when the click consumes the node; it shows again at
  `now >= consumed + respawn`, personal to that player.
- The water companion (tag 4, model 271, non-interactable, extra effect) is (R): Sanctuary adds
  `ExtraCompositeEffectIds`, and the client's invisible cube is an effect-only actor.

## Deviations from the brief (say why)

1. **Guid tag 5, not 3.** T503 already uses tag 3 for `quest_nodes.json` (spawns 100-104, which
   would collide with collection spawn ids 79-927). Tag 4 is the brief's companion tag. Tag 5 is
   free, and the loader/guid-space design already gives each node file its own tag
   (`tests/quest_pickup_nodes.rs::same_spawn_id_in_the_mining_and_quest_files_stays_distinct`).
   The app_fuzz seed therefore uses a **tag-5** guid, not the brief's tag-3 wording.
2. **`consume`, not a new method beside `paid()`.** T503's `picked(guid, now_ms)` already did
   exactly "hide now, reuse the regrow map, no change when already hidden"; it is renamed and
   documented for both kinds rather than duplicated.
3. **Stateless roll** (see (R)). Tests "fix the seed" by pinning the click's `now_ms` (and the
   player and node guids); `every_click_rolls_afresh_from_the_pools_table` proves the spread.
4. The verify-first prerequisites held: `data/content/collection_nodes.json` (T523) and
   `src/gameplay/collection_pickup.rs` (T450) exist; collection-completion-rewards (T480) is merged
   and is reached through the same `record_collection_entry`.

## Threat note (secure-code-guardian)

Hostile client input is one 26/8 frame with a u64 target and one trailing byte. It can:

- name any guid: only a guid this session placed (`NODE_GUID_BASE | tag | spawn id`), currently
  shown, inside 12 m of the character, in the open world, and while `activity_busy()` is false is
  accepted. Every other target falls through to the existing NPC/node routes or is refused.
- replay a click on a hidden node: `shown` is false, so the existing `Gone` line is sent and
  nothing is granted, no regrow deadline moves.
- malform the frame (wrong length/flag): `decode_npc_interact_26_8` returns `Err` before any
  staging; the gateway's per-session isolation turns that into that player's `internal_error`
  disconnect, not a server fault.
- try to steer the item: impossible; there is no client item id or quantity. The item comes from
  the server's pool table and the server's roll.
- farm the node: intended (it regrows), but the collection entry is once-only on the saved ledger
  and the item cannot be sold for profit: none of the 1024 collection drop items nor the 8 mushroom
  drops appears in `stores.json` item rows or any `vendors.json` stock (checked 2026-10-25), so the
  vendor sell path has no price for them.
- overflow the bag: `grant_bundle` is run on a clone first (same start gate as Type8); a full bag
  or a stack/count failure refuses with `Your bag is full. Make room before gathering.` and changes
  nothing. All item arithmetic stays inside `Inventory` (`checked_add`, `MAX_ITEMS`).
- crash the tick: the pickup is per-request, not in a shared tick; a staged content error is logged
  (`collection_node_refused`) and refused, never propagated out of the player's handler.

## Checklist (GPT Sol / lead items)

1. **Refusal changes nothing** — tested: full bag, out of range, wrong zone and busy each compare
   `snapshot()` (saved `GameplayState` + NPC visibility revision) before/after and the item/ledger
   stay unchanged; duplicate click on the hidden node too. All staging is on a clone; chat replies
   are the only output.
2. **Rollback covers all state** — the item, the collection ledger, the visibility and the node
   timers all live inside the cloned `Gameplay`; no Rc/RefCell/side table escapes. The content
   `Arc`s are read-only.
3. **Apply deltas, never restore snapshots** — the grant goes through `grant_reward` on the live
   staged inventory, and the ledger mutation is applied to the staged `ProgressionExtras`; nothing
   captured earlier is written back over the player's bag.
4. **Busy rules are mutual** — reuse `activity_busy()` (`gameplay/occupation.rs`); the collect
   action is instant and adds no activity, so no new `Occupation` row is needed. The busy test
   starts a real Mining18 run and the collect click refuses; existing activities already refuse
   while busy because this path refuses when they run.
5. **Every entry path is gated** — the only entry is the 26/8 gameplay dispatch (Gateway ->
   `Gameplay::handle_in_world` -> `handle_gathering_node` -> pickup module); there is no NPC menu,
   auto or reconnect path that grants a node item. Relog only shows the node again.
6. **Reachable in production, tested through it** — `the_gateway_click_route_grants_and_records`
   drives `Gateway::handle_at` login + 26/8 and asserts the saved ledger; the other tests drive
   `Gameplay::handle_in_world`, the same hub function the gateway calls.
7. **Survives reconnect** — the ledger entry is in `GameplayState::progression_extras`; the relog
   test saves that state into a new `Gameplay` and still sees the entry. Nodes are session state by
   design (brief: personal, not saved): the relog test asserts the actor is sent again.
8. **Every exit path restores the player** — there is no activity to exit; a pickup hides only the
   node and grants no temporary state. A failed staged part returns before commit, leaving the
   player free at the same position.
9. **Economy safety** — no client ids/quantities; one server-rolled item; the entry is once-only on
   the saved ledger; every drop item checked against stores/vendors (no sell route). Duplicate bag
   stacks from regrown nodes are allowed by design (nodes regrow) but carry no sale value.
10. **Wire format** — reuses the recovered 26/8 decoder (`008b6bc0`/`0092efe0`), the AddNpc writer
    (reader `00921a10`), 38/2/38/3 grant packets and the 38/10 `AddEntry` (reader `008d8570`, T450).
    The new presentation fields are asserted byte-exactly through the production `parse_add_npc`.
11. **Unique ids** — collection nodes are tag 5 (separate from harvest 1, mining 2, quest 3), the
    companion tag is 4 and is derived from the same spawn id; the duplicate-guid loader check still
    refuses collisions. No id 1 reuse and no public-world instance aliasing.
12. **Others see changes** — nodes are personal (brief), so no broadcast is required; the node is
    hidden only in this player's `NpcVisibility` and its own `GatheringNodes`.
13. **Content works end to end** — the shipped file is loaded (166 placed of 847 hardpoints by the
    pool maxima), the drop table is used, the entry is written to the ledger, 38/10 and the node
    removal are asserted; the flower/water/mushroom/ore AddNpc fields are asserted.
    Each click rolls afresh (seed includes the click's `now_ms`), so every drop of a pool is reachable
    on its nodes; `every_click_rolls_afresh_from_the_pools_table` rolls 200 times on the busiest pool
    and asserts every item is in the table and more than 40 distinct items appear.
14. **Values live in data** — respawn, max active, weights, ranges, effects and the subtitle all come
    from `collection_nodes.json`; only the client model id 271 (invisible cube) and the guid tags are
    constants, with their client-file provenance.
15. **Canaries break production code** — the canary break was the production dispatch predicate

    canary, then was reverted.
16. **Hands off session plumbing** — no change to `bin/osfr-gateway.rs`, `gateway.rs`, session
    creation/teardown/save ordering.
17. **One player's error never stops the server** — the handler is per request; content/grant errors

18. **A type's rules live on the type** — the per-file tag lives in `NODE_GUID_BASE`'s doc + the

    `NodeActor`'s fields are individually documented, and `record_collection_entry` takes the origin

19. **Hot paths stay cheap** — no state clone before a successful admission/roll/bag check; `sync`
