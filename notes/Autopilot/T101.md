## Security threat note (secure-code-guardian)

A hostile client can send any `26/8` runtime GUID, any `26/10` choice, a forged
`26/6` dialogue row, a `49/2` quest id it was not offered, a `49/14` id that is
not the pending turn-in, an arbitrary `36/10` attack target, or replay a
confirmation or hit. The server refuses each because: the actor GUID must
resolve through the server's NPC content-key map and the open interaction, zone
and range checks; a menu choice must be one the server opened; quest ids must
match the pending offer/turn-in the server itself recorded; kills only advance
from an authoritative server defeat; and rewards use the idempotent
`quest:<character>:<quest>` grant. The tests snapshot the serialized gameplay
state before duplicate turn-ins and duplicate accepts, and assert byte equality
afterwards; canary 2 proved that snapshot can fail. The wrong-NPC and wrong-enemy
refusals are snapshot-tested after the F216 review; that review correctly found
the committed wrong-enemy check bypassed the production request path. No
production parser, save path or economy rule was changed.
