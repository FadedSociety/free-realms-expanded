# T443 - Launcher client overlay: pinned creator tables and custom/ (L024 part 2)

## What changed

- New `scripts/bundle/client_overlay.py`: the one list (`OVERLAY`) of the 22
  community files a client needs for the character creator, each as (cached
  file, client path, SHA-256 pin). `install(root)` pin-checks every source
  first and writes only when all pass. `build(out)` / `--out <new folder>`
  makes a W121 patch folder (files plus `manifest.json`) and prints the
  manifest pin, so a realm serves it through the existing pinned patching
  (no second download path, no launcher source change).
- `scripts/run-local-baseline.py`: the native harness now calls
  `install_client_overlay(client)` instead of its own copy loops (-20 lines).
  The three table pins are the harness's own, moved, not changed. The 19
  `custom/` files were copied by glob before; they are now pinned with the
  SHA-256 values in `lab/references/asset-cache/cache-index.json`.
- **Harness bug fixed.** The harness copied SkinTone and FaceType to
  `Resources/CharacterCreate/`, where the client never opens them, so native
  runs never had the trimmed creator. The client reads
  `Resources/CharacterCreateCustomization<Category>.txt` (evidence below).
- `launcher/README.md`: a "Client overlay" section with each file's
  provenance, the unstated licence, the client paths and how a host builds it.
- Tests: `tests/test_client_overlay.py` (2 tests) run by
  `prototype/osfr-tools/tests/client_overlay.rs` (same pattern as
  `bundle_activity_content.rs`), and the ignored
  `client_overlay_lands_byte_identical` in `launcher/tests/patch.rs`.

The overlay is not wired into `make_bundle.py`: whether friends may receive
these files is the lead's decision (licence not stated).

## Client evidence

- `0x0071efb0` sets `"./Resources/CharacterCreate/"` (`0x017e802c`);
  `0x00723e90` reads `"CharacterCreateItemStartingSets.txt"` (`0x017e8dc8`) in it.
- `0x008ec05d` loads `off_1B3AA6C` = `"Resources/"` (`0x017ed7d8`) and calls
  `0x00982f10`, which formats `"%s%s.txt"` from that prefix and the name from
  `0x0097f570` (`"CharacterCreateCustomization"`, `0x0180b638` via
  `0x01b43938`, plus the category suffix). The stock
  `CharacterCreateCustomizationCategories.txt` lists `SkinTone` (1) and
  `FaceType` (9). The stock client has those files directly in `Resources/`.
- `custom/`: the loose-file index scans every client subfolder
  (notes/Research/Native Character Selection Labels.md); every overlay path
  equals the community manifest's install path (cache-index URLs).

## (R) choices

- (R) Ship as a W121 patch folder a realm serves, not an overlay compiled into
  the launcher: the files are game data that must stay out of Git, and W121
  already pins and verifies each file.
- (R) The 19 `custom/` pins come from the cache index (recorded at download,
  length and XXHash64 matching the community manifest), not from the harness,
  which never pinned them.
