## What changed

- Finding 2 (BLOCKER, safety): `card_listener.rs` counted unknown commands with `self.unhandled += 1`, a client-driven `u32`
  on a connection that may live forever once logged in; the answered-event counter (`*answered += 1`) had the same shape.
  Both are now `saturating_add(1)`, so the 2^32nd frame cannot panic outside `contain`. The log cap (`LOGGED_PER_KIND`) is
  unchanged. Regression test `a_connections_counters_saturate_instead_of_overflowing`: both counters start at
  `u32::MAX - 1`, three unknown frames and three 414s arrive, the connection survives and both counters read `u32::MAX`.
- Finding 3 (BLOCKER, structure): the client request fixtures (`int`, `text`, `headers`, `gateway_request`,
  `session_login`, `frame`, `ping`) now live once in `tests/support/card_packets.rs`, hand-built in the DLL writers' field
  order. `tests/card_service.rs` and the listener's tests both include it by `#[path]` (the repo's pattern, e.g.
  `f160_field_views.rs`). The listener tests no longer build a client request with `put_headers`/`put_string`; they use the
  production decoder only to read server replies. The 414's session id in the listener test is now the shared "w-ticket".
  `int` still calls `put_int`: `compact_integers_match_the_dll_writer` holds it to hand-written bytes. The listener's
  body builders for later commands (update, status, join, avatar) still use `put_headers`, as before; they are server-reply
  shaped lobby commands and were not part of the review finding.
