# F324: Fix review blockers in T230 (commit ed48a98)

## Summary

F324 fixes the two blockers and the cheap minors from
`lab/autopilot/reviews/ed48a98-T230.md`.

The 66/5 Marketplace catalogue record was **31 bytes short per bundle**. The client reader
`00b41860` calls `00b3fa00` and then reads ten more fields; T230 stopped at the `00b3fa00` tail.
Every bundle after the first was misaligned on the real client, so the store screen could not list
a ride. `src/station_cash.rs::bundle_record` now appends the ten fields (all zero; names
unrecovered, (R)), and `tests/station_cash.rs` walks them with the reader's field types and asserts
the exact packet size (36 header bytes + 185 per bundle) as well as the exact last byte.

The second blocker was the unsigned change to the per-message transaction staging path:
`src/bin/osfr-gateway.rs` called `Gateway::staged(&world.trades, guid)` instead of
`self.gateway.clone()`. That is reverted; `Gateway::staged`, `Gateway::set_trading`, the
`Gameplay::trading` field and the `Occupation::Trade` row are removed. Trade mutual exclusion is
recorded as **deferred** in [[Design/Station Cash]] (it needs a lead-approved per-request input,
not a staged flag). The order still refuses while any in-Gameplay activity is active
(`Gameplay::activity_busy`). `src/gateway/trade_bridge.rs` now contains only the four W163 trade
forwarders.

Cheap minors fixed: a disabled-policy fixture test for 66/1/3/10/12; `member_price_coins` added to
the Station Cash row rejection plus a validation test and a shipped-data assertion; the vendor
stock floors tightened to the measured data with an assertion that only Cragara and Delvin were
intentionally emptied; the client order field names and self-order gift rule verified and pinned;
`busy` passed to `handle_marketplace` instead of a second `CoinShop` flag; the duplicate replay
lookup removed; the dead `REPRESENTATIVE_VENDOR` constant removed.

## Security threat note (secure-code-guardian)

A hostile client can send the Marketplace family: a fabricated bundle id; a quantity of 0, 2 or
2^32; an unknown store id; oversized, negative-length or trailing strings; a detail count above
16; a garbage tint; a gift recipient; a coupon; an earn-only or unlisted bundle; a replayed
order; a burst of 66/12 catalogue requests; or a disabled-policy order. Every one is refused or
bounded without state change: the price comes only from the data catalogue; quantity must be 1;
the store id must match the configured store; strings and counts are bounded before allocation
and the body must end exactly; the tint must parse; gift and coupon are refused; `earn_only` rows
are not in the listing lookup; a duplicate order is answered from the persisted replay record; the
shared busy answer refuses during an in-Gameplay activity. The client cannot set the wallet
balance. A successful order is one staged transaction: the inventory grant is cloned and only
committed with the debit and replay record. No coin path touches the wallet, and no SC path
creates coins; the new `member_price_coins` rejection closes the last way a row could be priced in
both currencies. Malformed orders return `Err`, so the gateway drops that application for that
session and the server continues; no tick path uses `?` or `unwrap` on client data. The 66/12
catalogue reply is 9,656 bytes for the 52 listed bundles (31 bytes larger per bundle than the
short record) of server-built content per request; the account action budget bounds the request
rate and the reply changes no state.

1. **Refusal changes nothing.** `tests/station_cash.rs::refusals_change_nothing` snapshots
   `(InventoryState, Wallet)` for short balance, full bag, unlisted, unknown store, earn-only,
   quantity, gift, coupon, busy and malformed orders; the new disabled test snapshots the gateway
   for 66/1/3/10/12; `wallet_survives...` and the replay test check unchanged state. The disabled
   branch canary failed when the production guard was removed. Busy refusal is exercised through
   `handle_marketplace(inner, true)`.
2. **Rollback covers all state.** `place_order` mutates a cloned inventory and writes
   `wallet.balance`/`wallet.orders` only after every check; there is no side table. The catalogue
   is an immutable `Arc`. The removed trade flag was the only shared-state escape; it is gone.
3. **Apply deltas.** The debit is `wallet.balance - total` on the live wallet; the order syncs the
   live inventory before the staged grant; no old snapshot is restored.
4. **Busy mutual.** The hub computes the one `activity_busy` answer per Marketplace packet
   (`gameplay/npc.rs`) and `place_order` refuses when it is set; the order is a one-shot atomic
   request, not an activity. Trade mutual exclusion is explicitly deferred (blocker 2 revert) and
   recorded, with settlement revalidation/inventory sync as the interim safety; this is the one
   known gap.
5. **Every entry path gated.** The only order path is 66/3 -> `handle_in_world` ->

6. **Reachable in production, tested through it.** `tests/coin_store_siblings.rs` drives

8. **Every exit restores.** An order is one shot; a refusal leaves the character exactly as it

9. **Economy safety.** No free grants in slice 1; the price is server data; the order grants once
