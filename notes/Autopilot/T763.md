## Client facts used

- Integers: the network codec's mode byte `1080205c` is 0 and never written (its three xrefs are reads), so every
  integer is compact: first byte = low nibble | complement flag 0x10 | following-byte count << 5, then the rest
  little-endian (`10097a40` write, `100977a0` read, `10097860` peek). Strings: compact length, text, NUL.
- Header: each class level writes `classId, version` through the virtual `+8` (`1019de90`), so a command three
  levels deep carries the same pair three times; the reader (`1019def0`) checks the id at every level and keeps the
  first version.
- Frames: client -> server `htonl(len)`, three routing words (`1018aa20`: 1000000000, 0, 0), body (`101921e0`);
  the gateway 414 alone is sent without routing words (`101935d0`). Server -> client `htonl(len)`, body
  (`10192500`).
- 414 (`10121d20`/`10121c60`, version 1): session id, user name, host, port, ok, error (default 87). The client
  fills the first two from `--sessionID`/`--username`; on `ok` it reconnects to host:port (`10121980` -> `101938b0`).
- 411 (`1017b700`/`1017b950`, version 8 from `1017b920`): `--sessionID` first, then the data-version map (pairs of
  compact ints, `1019dfa0`), then strings and a flag per the reader's version gates.
- 81 (`10179c70`/`10179530`): success, code (v>=3), account id, flag (v>1), word (v>3), session (v>4), zlib blob
  (v>5). This server writes version 5.

## What changed

- `src/card_service.rs` (new, pure): the codec, headers, frames, `ConnectionServer`, `SessionLogin`,
  `login_results` and `reply` (414 answered with this service's host/port; 411 answered with 81, a success only when
  the caller's `account_for` maps the session id, else success 0 and code 1 (R)). Unknown commands return `None`.
  Integers with more than four following bytes, oversized frames (64 KiB, R), bad class ids at any level and
  trailing bytes are refused.
- `src/lib.rs`: `pub mod card_service;` (CRLF like its neighbours).

## Checklist

1. A refusal changes nothing: the module is pure; a refused login is an 81 with success 0 and nothing else.
2. Rollback: no state.
3. Deltas: none.
4. Busy: not applicable until the listener and launch exist.
5. Entry paths: the only entry is `reply`; the ticket check is the caller's.
6. Real path: not wired yet (listener pending); tests drive `client_frame` + `reply` with client-shaped bytes.
7. Reconnect: no state.
8. Exits: none.
9. Economy: none.
10. Wire: every field cites its DLL reader/writer; byte fixtures follow the writers' order.
11. Ids: the account id comes from the caller's check.
12. Others: none.
13. End to end: pending the listener and launch (native check then).
14. Data: the frame cap and refusal code are named (R) constants; no tuning values.
15. Canary: the integer writer (production code).
16. Session plumbing: untouched.
17. Tick safety: not on a tick.
18. Type rules: each command's layout lives on its type (`ConnectionServer`, `SessionLogin`, `login_results`).
19. Hot path: per-frame parsing borrows the buffer; replies allocate once.
