## Findings and what changed
- **1-3. Lead sign-off for the hub, gateway and world hunks.** These are lead-only code, and T872 was the lead's
  own build. The sign-off is recorded in `lab/autopilot/lead-signoffs.md` (T872/F874), after this fix.
- **4. The friend rule read the wrong list. Fixed.**
  - The new `SocialService::house_friends(owner, visitor)` requires that both list each other (mutual, as
    `friend_positions` does) and that neither ignores the other (`ignores_either`, now public).
  - An owner's removal or ignore therefore revokes the visit, even though friend removal is one-sided in the
    social service.
  - The gateway's access rule is the pure `house_visits::may_visit`:
    - an ignore refuses everyone;
    - a house friend may always enter, lock included (reference HouseAccess);
    - anyone else only with a visit permission on an unlocked lot;
    - the owner is never a visitor.
- **5. Copies were kept after refusals and listings, and the lookup cloned every online lot. Fixed.**
  - **Copy only who may enter.** A lot is copied only when `may_visit` passes. A stranger never gets a copy, so a
    stranger's enter is refused exactly like an offline owner's (127/46 code 1).
  - **Clone one lot.** An enter clones one lot (`Gameplay::own_house_lot`, guarded by the cheap
    `HousingService::has_own_lot`). A listing clones only the named owner's lots, found by session guid.
  - **Drop copies after every message.** The new `house_visits::settle` runs after `handle_at` and calls
    `Gameplay::drop_unvisited_foreign_lots`, which keeps only the copy of the lot the visitor is inside. A listing
    or a refused enter therefore keeps nothing, and a revoked pass cannot linger.
  - **`end_visit`** drops copies before its early return.
- **6. The 127/46 codes revealed whether the owner is online. Fixed by 5:** a stranger can only ever see code 1.
- **7. Tests:**
  - `social_lists::tests::house_friends_are_mutual_and_not_ignored`: a one-sided list, the owner's removal, and an
    ignore.
  - `house_visits::tests::only_house_friends_and_permitted_visitors_may_enter`: stranger, friend under a lock,
    permission, a locked permission, level 0, ignore, and the owner.
  - `tests/housing_session.rs::a_listing_keeps_no_copy_and_a_visit_keeps_only_its_own`.
  - The vacuous code-2 stranger test is rewritten to the real path, code 1 with no copy.
- **8. The visit pass on refresh.** The parameter is gone: the gateway has already decided access, so every copy
  carries the visitor's level-1 pass and is unlocked and read-only.
- **9. Notes.** This file states the skills.
