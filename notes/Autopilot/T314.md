## Verify-first observations (confirmed in this worktree)

- **Loader rules.** `QuestEngine::from_split_content` already rejects duplicate
  quest ids, a quest missing from the `jobs.json` `quest_ids` union (or a job
  listing an absent quest), a prerequisite that is unknown or self, duplicate or
  zero NPC ids, a quest bound to two givers, an NPC listing a quest under a
  different giver, and empty runtime provenance. `new_with_disabled`'s
  `validate_definition` bounds coins to `i32::MAX`, item definitions/counts to
  positive `i32`, the job-XP total to `i32::MAX`, and `valid_objective_kind`
  bounds visit geometry (finite `|x| <= 1e6`, radius `0.1..=1000`) and positive
  objective targets. `definition_from_content` rejects an unknown positive
  job-XP profile. The audit therefore does not repeat reward bounds, the
  jobs-union check or the giver listing; those are the loader's answers.
- **What the loader does not reject.** It does *not* reject an enabled record
  with empty objectives (`QuestEngine::is_enabled` hides it), it does not inspect
  standard-goal provenance, and it does not bound `title_string_id`: the raw
  `u32` is cast with `as i32`, so `0xFFFF_FFFF` becomes a negative title field.
  The audit checks the raw title against `1..=i32::MAX` (F343 review finding 5)
  and `scripts/content_check.py --strict` covers the raw provenance rules.
- **Drawability.** F343 removed the test's copy of the loader filter. The audit
  now asks the production owner: `NpcVisibility::teleport_targets(OPEN_WORLD_ZONE)`
  lists exactly the actors the 35/2 update can send, and `content_key` maps each
  runtime guid to the content NPC the click path resolves. `NpcVisibility::load`
  puts every regional `legacy_data` row and every accepted extra spawn in the
  open-world zone; a loader skip rule (capture body, unshipped model,
  non-finite position, zero content key) is reflected without a second list.
  The AddNpc reader `0x00921a10` consumes the actor u64, name id and model id
  this set feeds.
- **Raw pass.** The audit re-reads quest JSON only for the `enabled` flag,
  prerequisites, objective target fields and the title id, plus NPC JSON only
  for the authored `quest_giver` role. `NpcInteraction` owns the role table but
  exposes no accessor, so that one raw field is reported rather than guessed.
- **Enabled count (T314 tree `1916c91`).** 42 enabled records, 40 reachable, 2
  unreachable, and **12** enabled quests not listed by their giver's
  `quest_ids_given`/`quests_given`. The missing record in the old manual count
  was the scavenger hunt `3000200` (Samantha, `scavenger_hunt.json`). The old
  41 enabled / 39 reachable / 11 unlisted figures are the job-file-only subtotal
  (41/39/2/11) with the non-job scavenger hunt omitted. The test prints the
  counts and hard-codes none; F343's own run prints the current tip's
  44/42/2/12 (job-file-only 43/41/2/11) because later commits added two enabled
  quests.
- **Unreachable records (reported, not turned on).** `3020014` (Blacksmith)
  requires disabled `3020013`; `3100020` (Miner) requires disabled `3100019`.
  Both have drawable givers and targets; only their reward rows are empty, and
  the reward gate does not grade them.
- **`3130032` (Postman).** Giver `9000000173` (Postmaster Lane) is a drawable
  `legacy_data` row in `npcs/shrouded_glade.json` with the `quest_giver` role and
  lists the quest in `quests_given`; the one real objective is a Talk to
  `9000000172` (Postchug Runalug), also a drawable `legacy_data` row. The title
  is 141829 (>0), there is no prerequisite, and the reward was empty. The guide
  row 29 reward cell is `unknown`.
- **Live path (F343/F365).** `postman_trail_of_mail.rs` offers from

- **Other objective kinds (reported gap).** Enabled content also has

## (R) reconstructed rules

- `(R)` `3130032` reward: 5 coins use the W110/T202 small-referral fallback and 5
  Postman (profile 4) job XP follows the T202 one-Talk referral rate. The guide's
  reward cell is unknown; a single row is used. No item is granted, so the quest
  creates no free, sellable or re-grantable gear.
- `(R)` reachability is structural: an enabled quest is reachable when every
  prerequisite (transitively) exists and is enabled. Level/job/membership gates
  stay the engine's `requirement_denial` (covered by `quest_offer_gates`); this
  gate does not simulate offers or T281's giver order.
- `(R)` the 49/13 end screen names the actor that completed the final Talk
  (`QuestEngine::on_event`), not necessarily the quest giver; `3130032` names
  Postchug Runalug, and the chain test asserts that runtime actor.
- `(R)` the title id is a client `i32` field; authored values above `i32::MAX`
  are refused by the audit even though the split loader accepts them.

## Tests

`cargo test --test enabled_quest_reachability` (5 passed):

1. `every_enabled_quest_has_a_drawable_giver` - loads the real split engine and
   NPC visibility; for every enabled record asserts the engine kept it, the
   giver has an authored NPC row with the `quest_giver` role, and the giver is
   in the production 35/2 draw set. Also asserts every enabled id was
   enumerated (no silent skip) and the count is non-zero.
2. `every_talk_target_and_visit_point_resolves` - every `talk_to_npc` /
   `interact_actor` target is in the production draw set; every
   `visit_position` (and explicit `reach_poi`) geometry is finite and bounded;
   every `defeat` `model_id`/`count` and `collect_item` `item_id`/`quantity` is
   positive. Classifies every enabled quest exactly once as reachable or
   unreachable, prints the unchecked objective kinds, and asserts no
   unreachable quest is graded.
3. `every_reachable_enabled_quest_has_a_real_reward_and_title` - over the
   reachable enabled set: the authored title is `1..=i32::MAX`;
   `empty_reward_quest_end_packet` returns `None` and `quest_end_packet`
   encodes the 49/13. Pins `3130032` in the graded set, so disabling the fixed
   record cannot make the gate pass silently.
4. `a_malformed_enabled_row_is_rejected_or_reported` - a clean scratch fixture
   is green, then each planted defect is caught: a missing giver is reported by
   the giver audit; an empty reward on a reachable quest is reported; a title of
   `u32::MAX` is reported (the loader accepts it); a disabled prerequisite is
   classified unreachable (recorded, not failed for its deliberately empty
   reward); an absent prerequisite is rejected by the production split loader.
   The scratch fixture is built under `CARGO_TARGET_TMPDIR` and removed on drop;
   the shipped tree is untouched.
5. `visit_geometry_bounds_are_enforced` - F343's version tested a copy of
   `from_split_content`'s visit bound. F365 deleted the copy and its dead
   branches; because the test name is in `lab/autopilot/protected-pass.txt`, it
   now drives the production loader (`Catalogue::load`) with a valid
   `visit_position` fixture and three out-of-range transforms, so a loosened
   loader bound fails even though the audit no longer holds its own copy.

`cargo test --test postman_trail_of_mail` (2 passed after F365):

## Threat note (secure-code-guardian)

Attack surface: no new client input path was added. The one reachable effect is
the `3130032` reward any client can earn by completing the server-driven Talk
objective and 49/14 turn-in.

- The reward is server-authored content (5 coins, 5 profile-4 XP, no items). No
  client amount, item id, result or score reaches the payout; the existing
  offer/accept/end-screen gates (`offer_denial`, `pending_offer`, the saved
  `pending_turnin`) are unchanged and covered by `quest_offer_gates`,
  `quest_engine`, `quest_job_xp` and `app_fuzz`. F343 adds no parser.
- The quest has no prerequisite and no item grant, so it cannot be re-granted
  for profit, cannot be sold, and cannot leave a stuck inventory. It also has no
  job/level gate in content (pre-existing gap): a profile that never unlocked
  Postman is refused at turn-in with no payout and the quest stays active; F365
  pins that refusal. A 49/14 replay settles only the saved pending turn-in once;
  the new chain test asserts the duplicate request changes no serialized state.
- The audit and chain tests are test-only and read-only over shipped content; no
  save, session, shared state or server tick is touched. The audit's scratch
  fixture writes under `CARGO_TARGET_TMPDIR` and removes itself on drop; the
  chain test's shared `Fixture` copies under `std::env::temp_dir()` and also
  removes itself on drop (F365 correction).
- `content_check.py --strict` stays at 0 errors after the provenance-tag
  corrections, so the authored JSON remains valid.
