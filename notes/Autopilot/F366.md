## Threat note (secure-code-guardian)

What a hostile client could send, and why it is refused:

- **26/6 dialogue row / 49/2 accept** — the handler uses the server's own
  pending quest choice and `QuestEngine::accept` requires a matching
  `pending_offer` for that quest id, an enabled definition and the offer gates
  (giver, prerequisite, level/job, membership, limit). A forged row or an
  unsolicited 49/2 is inert; existing tests `quest_offer_gates.rs` and
  `npc_interaction.rs` pin the refusals. The new test only sends the row/quest
  the server just offered.
- **Unknown quest id** — `QuestEngine::offer`/`accept` deny an unknown or
  disabled definition before any state change; no client payload is trusted.
- **Quest credit** — comes only from `EncounterOutcome::defeated`, which the
  server writes from the server's actor definition on a server-verified kill;
  test 9 asserts the resulting 2/4, never a client-reported result.
- **Rewards** — the Sheep Watch reward is the existing `EncounterReward` on the
  server-verified win; the new acquisition leg grants nothing.
- **Test-only builders** — no production input parser, save field, role check
  or action budget changed. No secrets.
