## Why no data file changed

- The 12 `reference_data` rows: `tests/sanctuary_named_npcs.rs::all_90_are_drawn_once` pins exactly
  90 `reference_data` rows, one extras body each, same position/heading, one drawn actor. Setting
  `placement: legacy_data` would add a second actor with the same GUID beside the extras body and
  fail that test; `tests/content_npc_placement.rs` also requires `reference_data` rows to keep
  `reference_spawn` and an extras body.
- The 6 T372 vendors: `tests/priced_vendors_drawable.rs` pins `non_legacy_priced` to the exact 25
  T372 ids (six of them here), so a conversion fails by construction. The extras body would remain,
  giving the same actor id two `AddNpc` entries; the brief does not allow editing
  `npc_spawns_extra.json`.
- Clark: `tests/sanctuary_named_npcs.rs::held_back_rows_stay_undrawn` asserts his row is neither
  `reference_data` nor `legacy_data` and the loader draws no body. His row's evidence ("At Rainbow
  Lake", client text 744473930) contradicts the Sanctuary spawn, which is the brief's third skip.

## Client evidence

- 35/2 AddNpc reader `0x00921a10` (IDA `func` + `decompile`, 2026-10-25): reads actor u64
  (`this+16/+20`), name i32 (`+24`), model i32 (`+28`), the flag/colour fields, scale (`+72`),
  then two 4-dword vectors through `sub_8E2410` (`this+96` position, `this+112` rotation). `sub_8E2410`
  reads four dwords. `src/startup_world.rs` parses the same sequence for `NpcSpawn` (position and
  rotation `[f32;4]`). The client therefore draws the actor at the row's position, which is what the
  test asserts.

## Security / threat note (secure-code-guardian)

The diff adds no runtime path and changes no save, coins, items, rewards, roles, chat or client
input parsing. The content it examines is server-authored JSON; a hostile client cannot send an NPC
placement or a spawn. The skip decision avoids creating a second `AddNpc` actor with an existing
GUID, which would alias one NPC's identity onto two bodies (the unique-id rule). The tests read the
shipped data files and the real loader, so a malformed or duplicate placement is refused by the
loader/test rather than trusted from the client.
