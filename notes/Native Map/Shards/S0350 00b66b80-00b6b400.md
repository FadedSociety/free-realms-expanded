# S0350 Native Map Findings

## What this range contains

S0350 is primarily the native client's fishing packet and state path. 00b69860 initializes FishingProcessor data sources and list members; 00b69d40 releases them. 00b6cd80, outside the shard, dispatches the fishing opcode family and is the caller anchor for several bounded readers and processor methods in this range. Packet-specific class names below come from binary vtables, including the registration response (00b695f0), FishInfoUpdate (00b69770), spawn-proxied-school (00b678e0), and SpawnFishRun (00b6a590).

## Receive and send paths

The receive wrappers create a bounded reader, call a body reader, and return success when the read-error flag is clear and the trailing-data condition passes. The newly mapped layouts include:

- Registration response: 00b6acb0 → 00b6a170, including nested configuration fields through 00b67240.
- FishInfoUpdate: 00b6ad20 → 00b691d0 → 00b673b0.
- Spawn school: 00b6a0c0 → 00b69130 → model-entry list reader 00b68a80.
- Compact response body: 00b68fb0 → 00b66f50.
- SpawnFishRun: 00b6aed0 → 00b6a2b0 → counted spawn-info reader 00b694e0 → record reader 00b67550.
- Update school, despawn school, and result bodies: 00b68ed0 → 00b66b80, 00b68e60 → 00b68810, and 00b68f40 → 00b66be0.

The native packet header writer 00b69550 emits two 16-bit fields. The four outbound wrappers 00b6b0d0, 00b6b1e0, 00b6b2f0, and 00b6b400 serialize their body writers, construct the emulator-catalogued PacketTunneledClientPacket, call gateway send helper 00925640, then call 00894560 to destroy the temporary byte-array buffer. 00894560 is cleanup, not a send operation. The community catalogue calls the corresponding outer receive tunnel PacketTunneledClientWorldPacket; those catalogue names are emulator evidence and do not establish original server implementation.

The body layouts and dispatch path support this **wire-compatibility hypothesis**: a compatible server counterpart must accept the emitted fishing request bodies and provide the response bodies the client dispatches. This inference depends on the native writer/reader call paths, the opcode/sub-opcode header, and the emulator tunnel catalogue. It does not establish original server state transitions, catch decisions, rewards, or field semantics; there is no original fishing server implementation to verify those.

## Gameplay, model, and container connections

00b67b80 references the model attachment strings sg_fishing_lure_bbe, mouth, and hinge_2 while updating fishing progress/presentation. 00b6a6e0 creates or updates overhead-text elements; 00b6a8c0 also builds overhead text for a collection, but has no identified caller or feature-specific string. These are static code paths, not runtime visual acceptance.

The range also contains reusable linked-list and hash-list operations. 00b66fe0 unlinks a record and destroys its IString member; 00b689e0 handles the two-string record variant. 00b68930, 00b690d0, 00b69410, and 00b6ada0 insert, copy, remove, and clear hash-list nodes. Fishing-specific list/map instantiations are visible in vtables at 00b68740, 00b692a0, 00b6a090, and 00b6a1f0.

Nothing in S0350 validates a catch authority or reward path.
