# T503 — Quest-only pickup nodes with a counted `collect_node` goal (A Booming Problem)

One mechanism, proved end to end by fork quest 3061 → `3000361` "A Booming Problem"
(Heddy Heathcliff, 5 tin ore). No new opcode: the click is the ordinary 26/8 interaction and the
count is the ordinary 49/9 objective update.

Skills applied: **Ponytail (full)** — the smallest change that works, reusing the existing node
loader, the existing 26/8/49/9 wire and `npc_quest_event`; the hub got only dispatch lines. The
**ponytail-review** pass cut the fixture's unused source tags and shortened `pickup_kinds` by
reusing `pickup_kind`. **secure-code-guardian** produced the threat note below (client input
validation, refusal-before-stage, no economy path).

## (R) rules reconstructed

- A pickup is admitted only while one of the player's active quests has an open `collect_node`
  objective for that node type (Lxzxrus dac754e; Ariel's 2026-10-16 playtest, behaviour only).
- "You don't need that right now." is the NotNeeded line; the client has no reader for it.
- Each pickup adds exactly 1, never past the objective's quantity; the count is saved quest
  progress and sent as the same 49/9 counter as other counted goals.
- A picked node hides for that player only and returns after the pool's `respawn_seconds` (30 from
  data); nodes are not saved, so a fresh login sees every node (existing GatheringNodes rule).
- No item is granted: the quest node file must have an empty drop table, enforced at load.
- Job XP goes to Adventurer (profile 1) whatever job is active (T202 rule); 25 is the T202 collect
  rung.
- Quest node types are 1..=64 characters and collect counts 1..=100, checked at load.

## Security threat note (secure-code-guardian)

A hostile client can send only the 26/8 click. Its target must be one of the caller's placed
pickup sites (`pickup_kind`), the packet must decode (13 bytes, 26/8 header, flag <= 1), and the
player must be non-busy, in zone 0, within the content interact range, with an active quest whose
ordered open step is a `collect_node` for that exact type. Every failure returns one chat line before
any clone is staged, so it consumes no menu, offer, counter, item or cooldown. The client cannot name
the node type, the quantity or the reward: all come from server content, `on_event` adds a constant
1 capped at the objective's `required`, and a second click on the same node is refused as Gone
(`shown`/`regrow`). Repeating a click cannot exceed the count or hide another player's node: nodes
are per-Gameplay state, and the visibility removal is in that session's own catalog. There is no
economy path from a pickup — an empty drop table is a load error, and only the quest's server-side
turn-in pays coins/XP. Inputs are length-checked before slicing and no client-derived value is
unwrapped; overflow is impossible (`saturating_add` then `min(required)`).

## Checklist

1. **Refusal changes nothing** — every refusal is returned before the staged clone exists; the
   tests snapshot `GameplayState` bytes before the click and assert equality after (no quest, full
   count, completed quest, wrong zone, out of range, busy), plus no 35/3 removal for the node.
   Canary 1 broke the gate and the test failed.
2. **Rollback covers all state** — the pickup path clones `Gameplay` (nodes' regrow/shown, quest
   engine, visibility) and assigns it back only after every step succeeds; a failed
   `npc_quest_event`/`refresh` returns Err with `self` untouched. The only shared value inside the
   clone is `GatheringNodes::sites: Arc<..>`, which is immutable content and never mutated, so it
   cannot carry a refused transaction's change.
3. **Apply deltas** — the pickup never restores an old snapshot: it applies +1 inside the live quest
   engine on the clone; no inventory/coin/position snapshot is captured or written.
4. **Busy rules are mutual** — `admit_pickup` refuses when `activity_busy()` (the shared occupation
   table, every current activity); a pickup sets no occupation because it is instant, so it blocks
   nothing. No new busy list was written (`tests/spine_rules` green).
5. **Every entry path gated** — there is exactly one entry path: the 26/8 click in
   `handle_in_world`; the NPC menu, opening, automatic and reconnect paths never emit
   `QuestEvent::CollectNode` (grep: one emitter, in `gameplay/quest_pickups.rs`).
6. **Reachable in production** — the gateway routes 26/8 to `Gameplay::handle_in_world`; the tests
   call that same method with the 26/8 body, and `tests/gathering_nodes.rs` already drives node
   clicks through the real `Gateway`. The bundle now ships `quest_nodes.json`.
7. **Survives reconnect** — the count is `QuestProgress.counts` in the character save; the test
   picks 3, `reload_serialized`, sees 3/5 and finishes the quest.
8. **Every exit restores the player** — playback has no session flag to clear: the node's regrow
   timer is the only state, a refused click leaves it untouched, a disconnect resets node visibility
   on the next login (test), and the quest count is saved.
9. **Economy safety** — no item, coin or XP is granted by a pickup; the node file must have an empty
   drop table (load error otherwise); the only payout is the quest's server-side 49/14 turn-in; the
   client cannot name a type or amount and each admitted click adds exactly 1.
10. **Wire format matches the client** — no new wire; 26/8 (`0x008b6bc0`) and 49/9
    (`0x00c7af60`) are cited above and unchanged; the tests decode the same 26/8 body and assert the
    49/9 quest/objective/current fields.
11. **Unique ids** — pickup guids use the existing `NODE_GUID_BASE | 3 << 32 | spawn id` scheme; the
    shipped 23 node guids are asserted unique and the fixture's spawn id 1 is in its own tag space.
12. **Others see changes** — a pickup changes only the picking player's personal node catalog and
    quest; nothing is visible to other players, so no broadcast exists (the two-player test asserts
    A's pickup leaves B's save and count untouched).
13. **Content works end to end** — the E2E test offers at Heddy, accepts, clicks five nodes with
    49/9 counts 1..5, talks, releases 49/13, pays 40 coins + 25 Adventurer XP through 49/14, and
    asserts Completed.
14. **Values live in data** — respawn 30 s in `quest_nodes.json`, range 12 in the node type, count 5
    in the quest record; new load bounds are 1..=64 characters and 1..=100 (R).
15. **Canaries break production code** — two production edits (admission gate, hide step) each made
    a real test fail, then were reverted; the reachability canary H patches content in a scratch
    tree.
16. **Hands off session plumbing** — `gateway.rs` and `src/bin/osfr-gateway.rs` are untouched; saves
    still go through the existing staged-gameplay commit. The only hub edit is the four dispatch
    lines in `gameplay.rs`.
17. **One player's error never stops the server** — all player-caused failures are refusals returned
    as `Outcome`, not `?`; the only `?`s after admission are server-content io errors inside the
    per-session handler (the gateway's isolation boundary). The tick regrow stays infallible apart
    from the unchanged visibility refresh.
18. **A type's rules live on the type** — `SiteKind` owns gather-vs-pickup, `GatheringNodes::picked`
    owns hiding+regrow, `admit_pickup` owns the pickup gate, and `Visitor`'s job fields are marked as
    `admit`-only. The quest engine's `wants_node` reuses `current_objectives` for the ordered rule.
19. **Hot paths stay cheap** — the 20 Hz tick path is unchanged (`tick_gathering_nodes` already
    cloned nothing when no change); a click allocates only after admission.
