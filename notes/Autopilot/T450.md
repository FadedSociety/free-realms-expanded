## Attempt 2: the `addpc_referee_flag_is_the_login_role` failure

The integrator's triage of T450 alone failed `gateway_runner::moderation::tests::addpc_referee_flag_is_the_login_role`
(`l042_moderation.rs:271:58`, `Option::unwrap()` on `None` in `Rig::drain`), and its log shows
`"reason":"idle_timeout"` for the first session (`127.0.0.1:37001`).

**Cause: a timing flake in the L042 test rig, not T450.**
- `Rig::send` calls `Session::dispatch_message` directly. That skips the packet path that refreshes
  `last_activity` (`osfr-gateway.rs:1269`, `:1295`), so each rig session's idle clock runs from `Session::new`.
- `Server::step` ends a session idle for over 60 s (`osfr-gateway.rs:3842`).
- In this test, Pip joins first and only drains. If the following joins (each a debug `Gameplay::load`) and the
  commands take more than 60 s under a parallel suite, the `step` after the first kick ends Pip, and the next
  `drain(pip)` panics.
- The same L042 tests were already flaking before this patch existed: the `integrator: flaky once` lines at
  19:22:06Z and 19:55:21Z (`lab/autopilot/logs/autopilot.log`, batches without T450) list
  `addpc_referee_flag_is_the_login_role`, `ban_kicks_only_the_target` and others. T450's own triage passed the
  test in 6 of the 7 binaries that run it.
- T450's added load cost is small. With a temporary probe (removed): a debug `Gameplay::load` on the gateway test
  content took 2.8-3.7 s; `CollectionCatalogueContent::load` took 17-35 ms and `CollectionCoins::load` 1.6-2.3 ms,
  under 1 %.

**Fix:** `Rig::step` refreshes every session's `last_activity` before `Server::step`. This is the same pattern
`isolation.rs:183` and `f160_field_views.rs:109` already use. Test code only; production idle handling is
unchanged.

**Proof:**
- Canary: setting `last_activity` to 61 s ago in `Rig::step` (a stalled host) reproduces the integrator's failure
  exactly (`l042_moderation.rs:277:58`, the same `drain` unwrap 6 lines lower, and `idle_timeout` for 37001-37005).
- With the fix, `cargo test --bin osfr-gateway moderation::tests` passes: 7 passed.

## What changed

    holds `npc_spawns_extra.json`. It is dormant unless both files exist. It then calls `exclude_actor_guids` for
    every coin whose entry the saved ledger already holds, so a relog never sends a collected coin.
  - `handle_collection_coin(inner, character)` returns `Ok(None)` unless `inner` is 26/8 with length >= 12 and the
    target is a coin guid. It then decodes the packet (exactly 13 bytes) and checks, in this order:
    1. The entry is already in the ledger, or this view has no such actor (excluded or removed): silent, no
       packets, nothing changes.
    2. `activity_busy()`: `Finish what you are doing first.` (`Denied::Busy`).

### Why `remove` and not "remove plus exclude" in session

`exclude_actor_guids` also drops the guid from `visible`. That makes it silent, so with it the next update would
never send the 35/3. `remove` keeps the guid in `visible` until the next update, as the gathering-node Hide path
does.

Nothing rebuilds `NpcVisibility` from disk inside a session:
- `content_reload.rs:20-35` clones and mutates;
- `placement_watch.rs:141-152,170-177` clones and mutates;
- `replace_placements` only re-adds guids from `npc_placements.json`, which start at 130e9 (coins are 1e11+id).

So a removed coin cannot come back before a relog, and the relog exclusion comes from the ledger. The test
`content_reload_keeps_coin_hidden` proves it with `realm reload all`.

## Threat note (secure-code-guardian)

A hostile client controls only the 26/8 bytes and its reported position.

- **Forged non-coin guid:** `Ok(None)`. The NPC route handles it exactly as before.
- **Coin guid from far away, or another zone:** refused. The coin position is server content
  (`actor_position`), never client data.
- **Replay or double click:** the ledger is once-only, and the coin is removed from the view, so it is a silent
  no-op.
- **Collected or hidden coin:** silent. No information leaks beyond what the 35/3 already told the client.
- **Malformed 26/8 on a coin guid** (12 or 14 bytes, flag byte > 1): `Err`, the same as the gathering and NPC
  26/8 decoders. The app_fuzz corpus runs every cut, every trailing variant and every byte mutation of the coin
  seed: no panic and no snapshot change.
- **Rewards:** the entry comes only from the server's coin map. `collect` cross-checks the wire ids against the
  ledger's own join. Nothing is granted, so there is no economy surface until T480.

## Checklist

1. **A refusal changes nothing.** The refusals are busy, too far, other zone, already collected and not visible.
   Each runs before any write. Tests compare `(state(), npc_visibility_revision())` before and after:
   `out_of_range_and_busy_refuse_without_change`, `second_click_does_nothing`, and the relog click. Canaries 4
   and 5 cover it.
2. **Rollback covers all state.** The ledger is staged inside `CollectionProgression` and assigned only on `Ok`.
   `remove` runs after and cannot fail. No shared `Rc` or side table: `CollectionWorld` is read-only content.
3. **Apply deltas.** The ledger only gains the entry and the view only loses the coin. Nothing restores a
   snapshot.
4. **Busy rules.** Uses `activity_busy()` from the occupation table and is tested with a live mining run. A pickup
   is instant, so there is no new occupation to gate other activities.
5. **Every entry path is gated.** The only path is the 26/8 dispatch, and every check is inside it. Reconnect
   rebuilds the hidden set from the saved ledger.
6. **Reachable in production.** Gateway, then `handle_in_world`, then the dispatch after `handle_gathering_node`.
   Tests drive `handle_in_world`. The app_fuzz canary proves the gateway reaches the route.
7. **Survives reconnect.** The ledger is in `ProgressionExtrasState`. `relog_keeps_coin_hidden` reloads from
   `state()` and checks `update`, `shared_view` and the click.
8. **Every exit path restores the player.** There is no activity state; the pickup is atomic.
9. **Economy safety.** Nothing is granted, so the empty grant sends no toast (canary 6). The entry comes from the
   server coin map, never the client.
10. **Wire format.** The 38/10 bytes are compared whole against reader `008d8570` order and catalogue row 1937. No
    new packet types.
11. **Unique ids.** None created; the coin guids are content spawn guids.
12. **Others see changes.** Not applicable by design (R): coins are personal. `other_player_still_sees_it` shows a
    second player still sees and collects the coin.
13. **Content works end to end.** `completing_a_set_records_completion_once` collects all 5 real Seaside Rare
    coins. `is_completed(267)` is true, `completed_count` is 1, and each click sends only its 38/10.
14. **Values live in data.** `pickup_range` stays in `collection_coins.json` with bounds 1..=50.
15. **Canaries break production code.** Canaries 1-7 above each edited `src`.
16. **Hands off session plumbing.** Production code in the gateway bin and `gateway.rs` is untouched. Attempt 2
    changes only the L042 test rig: `Rig::step` refreshes `last_activity` the way the real packet path does.
17. **One player's error never stops the server.** The route runs only for that player's request, never in the

18. **A type's rules live on the type.** `NpcVisibility::shown` decides the visible lookup for both `model_of` and
