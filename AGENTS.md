# Project instructions

Rewritten 2026-11-04: the earlier version described worker setups that no longer exist.

## Goal
Revive Free Realms as a fully playable game, with a Rust server for the original 2014 client. Players install through the launcher (repo `FadedSociety/free-realms-launcher`). It downloads the client from the community host and our server release from this repository's Releases page.

## Where things are
- **This repository:**
  - `prototype/osfr-tools`: the gateway, login and account binaries, the gameplay modules, tests and content;
  - `scripts/`: the harness, release and audit tools;
  - `notes/`: the vault.

  The code map is `notes/Project Map.md`, generated by `scripts/project_map.py`; rerun it after a merge, never edit it by hand.
- **The analysis lab** (`../lab`, never committed): originals, extracted client data, decompiles (`lab/decompiled/native`), the native function map (`lab/native-map/run/map.sqlite`, rendered in `notes/Native Map`), wiki harvests, the video archive, native test runs and the build pipeline (`lab/autopilot`).
- **Toolchain:** no global Rust. Use the private toolchain under `../lab/tools` (`scripts/cargo.ps1`, or set `CARGO_HOME`/`RUSTUP_HOME`).

## How to work
1. **Fresh data first.** Re-index the code graph at the start of work. Read the code, the decoded client functions, the fan wikis and gameplay video before planning. Notes in `notes/Research` and `notes/Design` are 2026-10-16 snapshots: verify every claim.
2. **Top down per system or minigame:**
   - the players' assets (packs or community CDN; lab-only files do not reach players);
   - loading to Go;
   - the rows, by level and difficulty;
   - enter and quit with the UI intact;
   - the match board;
   - the arena and actor assets;
   - the UI elements;
   - real input.
3. **Prove behaviour in the real client** with a launcher-like install and real input, and read the client's logs. Tests alone do not prove client behaviour.
4. **Keep code lean:** reuse what exists, keep hub files thin (`tests/spine_rules.rs`), keep gameplay values tunable in data, mark guesses (R), and never panic on client input.
5. **Each change:** targeted tests, an independent review, then the full suite before merge.

## Publishing (this repository is public, history included)
- Commits are authored `FadedSociety <FadedSociety@users.noreply.github.com>`.
- Only the lead pushes, tags or publishes releases.
- Run the upload gate (`../lab/autopilot/publish-check.sh`) over every new commit before a push.
- Never commit:
  - secrets or keys;
  - per-device state;
  - personal names or absolute home paths;
  - anything from `../lab`;
  - client binaries, packs, assets, screenshots or decompiler output (cite the client function and its address instead);
  - build output, or files over 10 MB.
- Licence AGPL-3.0-or-later. Code adapted from Sanctuary or FreeRealms-Legacy carries a credit header, and `NOTICE` lists the project.
