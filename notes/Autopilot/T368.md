## Threat note (secure-code-guardian)

Attack surface: any client can send 26/8 (click), 26/10 (choose), 26/13 (job select) and 36/10
(basic) with arbitrary ids, slots and positions at any time, from any range or state.

- Trainer/menu: the clicked id resolves through the server content map; a choice must be an
  option of the currently open menu for that exact NPC, and zone + 12 m range are rechecked on
  every selection. The client never names a profile id or trainer row; the option -> `Trainer`
  mapping is server content.
- Rank/prerequisite: the rank is server row data (`job_trainers.json`; loader bounds 1..=20); no
  client-supplied rank or XP is read, and the refusal chat text is formatted from that server row
  (`NeedsRank { rank }`). The rank-4 refusal is a per-request chat line that changes nothing; the
  menu remains usable. The service, gateway and inline S15 tests assert the whole state.
- 36/10: the field path rechecks the active profile, the job's weapon class in slot 7, the
  zone/engine state, target presence/range and the 600 ms swing clock. Forged, out-of-range or
  corpse targets are no-ops; damage, death and XP are server-side. A client-reported result is
  never paid.
- Starter grant: owned pieces are equipped, never re-granted; missing pieces come only from the
  server content, with no client item id or quantity. The two new fixture definitions grant
  nothing by themselves.
- Atomicity: learn/activate stages on the request `Gameplay` clone; the tests assert the full
  `GameplayState` JSON and `state_changed`/`gameplay_changed` are unchanged after refusals, for
  two independent characters. No new packet, permission, session, account, save or persistence
  field; no login/security path touched.

## Checklist

1. **A refusal changes nothing.** `service_refusals_change_nothing`,
   `gateway_refusals_leave_the_save_untouched` and the inline
   `gameplay::s15_npc_transactions::a_refused_learn_answers_end_dialog_then_chat_and_commits_nothing`
   snapshot the whole state and assert equality after the below-rank/wrong-job/out-of-range/
   forged/busy refusals; the gateway test repeats the refusal to prove the open menu was not
   consumed. The two-session case snapshots both characters. The code canary (removing the rank
   check) makes the rank-4 refusal assertion fail; the data canary (rank 20) makes the positive
   rank-5 assertion fail and also restores the inline `"level 5 Archer"` pin's old text.
2. **Rollback covers all state.** The tests use the production staged `Gameplay` clone; no
   `Rc`/`RefCell`/`Arc` or side table was added; the whole `GameplayState` JSON is compared.
3. **Apply deltas, never restore snapshots.** The learn/activate path inserts an unlock and
   equips/grants from the live inventory; no test or production code restores a captured
   inventory, coin or position.
4. **Busy rules are mutual.** No new activity was added, so no `Occupation` row is needed. The
   existing busy case in `gateway_refusals_leave_the_save_untouched` still passes, and
   `learn_job` rechecks the shared busy table.
5. **Every entry path is gated.** The matrix uses the 26/8 -> 26/9 -> 26/10 menu and 26/13; the
   only `Profiles::learn` production chain is `handle_in_world_inner -> handle_npc_packet ->
   jobs::learn_job -> Profiles::learn` (graph); there is no automatic/e reconnect trainer grant,
   and the reconnect test loads the saved state.
6. **Reachable in production, tested through it.** Real `Gateway` sessions, the real trainer menu
   labels and the real shared-field path; no `realm` command (`may_run("level"/"give")` is false
   and no chat packet is sent).
7. **Survives reconnect.** The matrix saves the post-kill Ninja progression through the real
   `game_store::save` envelope, reloads it with `game_store::load_or_create`, and asserts the
   active job, unlock and equipped starter weapon survive before switching to Archer and killing
   again; `warrior_trainer::warrior_unlock_survives_reload` (6/6 passed) covers the same envelope
   for the Warrior path.
8. **Every exit path restores the player.** Learning never switches the active job; a refused
   switch leaves the old job; the matrix ends in a supported zone-0 location with the field actor
   dead and no pending menu/activity state.
9. **Economy safety.** Starter pieces are server content; owned copies are equipped, not
   re-granted; field XP/coins come only from the server kill (`field_kill_rewards.json`); no
   client result, quantity or item id is trusted. The matrix asserts exactly +5 active-job XP and
   no other profile paid.
10. **Wire format.** No packet changed. The new test builds/decodes the exact 24-byte 36/10 body
    with the production codec and checks the 36/5 bar; the 26/8/26/10/26/13 shapes are the
    existing pinned tests. Readers/writers are cited above.
11. **Unique ids.** The field actor and character GUIDs are the existing shipped/reference ids;
    no instance or GUID was created.
12. **Others see changes.** A real 26/13 switch stages the existing 35/7 `nearby` outfit packet
    (asserted in the matrix). The actual two-session delivery and distance cap for 35/7 and 35/6
    is pinned by `live_outfit_fanout_respects_directed_visibility_cap`
    (`src/bin/osfr_gateway/tests.rs`): the near session receives both, the far session neither.
    The unlock itself is not visible to other players until activation, matching the existing
    behavior.
13. **Content works end to end.** Five trainer jobs (Ninja, Medic, Wizard, Warrior, Archer) reach
    the final outcome through the real menu label: unlock, 38/21 activation, a positive
    authoritative hit, death at 0 HP and active-job XP. Brawler is default-unlocked and is driven
    through 26/13, the hit and the payout without a trainer row. The level-5 bar is proven for
    Warrior only. The final outcome, not an intermediate flag, is asserted.
14. **Values live in data.** The two ranks are rows; no compiled rank constant or curve was
    added. `content_check --strict` accepts the rows (0 errors).
15. **Canaries break production code.** Canary 1 changes the production data row; canary 2
    removes the production `Profiles::learn` rank comparison. Both fail real assertions, and both
    files were restored byte-identically (SHA-256 above).
16. **Hands off session plumbing.** `src/bin/osfr-gateway.rs`, `src/gateway.rs`, transactions and
    save ordering are untouched.
17. **One player's error never stops the server.** The refusals are per-request chat lines on a
    staged clone; the two-session case shows one player's refusal leaves both characters and the
    process untouched. No shared tick or `?` path changed.
18. **A type's rules live on the type.** No struct field was added or reinterpreted; the rank
    stays on `Trainer`/`Profiles::learn` and the row data. The test-only fixture helpers are
    documented at their definitions.
19. **Hot paths stay cheap.** Zero production behavior change; the only `src/` edit is an inline
