# F131: T027 review blockers

## Verdict

All three findings against `17906d5` were correct.

- A same-job selection can repair a missing starter outfit after the active
  profile id check, so comparing only the profile id missed a visible change.
- Derby entry and exit changed the active job without consistently announcing
  the restored attachment group.
- `ride_fanout` used the spatial broad phase rather than the recipient's
  directed `AddPc` view, exposing live appearance packets to capped-out players.

The shared profile-outfit announcement now compares the complete active
attachment group before and after the committed operation. Derby entry, close,
cancel, tick, kart, opening-cave and explicit job-selection paths use it.
`ride_fanout` permits live `35/6`/`35/7` packets only for recipients whose
directed view already contains the actor.

## Security note

A hostile client can request only the existing `26/13` transition and inventory
operations. The server derives the character GUID, active profile, owned items
and attachment list; none of those values are accepted from an appearance
update. Explicit selection is staged on a clone, so a locked job, missing
required slots or malformed request commits nothing and announces nothing.

The visibility filter narrows disclosure: a live `35/6` or `35/7` reaches only
players whose directed view admitted the actor. It does not reveal an actor
outside that view. No reward, item, session, save-ordering or transport path
changed.
