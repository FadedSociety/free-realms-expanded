## Security note

Threat: a hostile client can put any bytes in the 26/13 body. The handler
requires exactly 8 bytes and reads one `i32` job id. With no class content the
request is refused before any profile, inventory or outfit read: no panic and
no state change. With class content, `stage_job_selection` stages a clone and
checks unlock, outfit repair and the required Chest/Legs slots before commit; a
refusal sends only a chat line and leaves the save unchanged. The 35/7
announcement is built from server inventory after the commit; no client-supplied
GUID, attachment or profile value is trusted. The move changes no wire bytes and
no visibility rule (the live-appearance filter still runs in `ride_fanout`,
which was not changed). No reward, coin, item, save-ordering or transport path
changed.
