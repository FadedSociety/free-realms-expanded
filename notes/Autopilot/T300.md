## Threat note (secure-code-guardian)

Attack surface: any client can send 26/8 (arbitrary u64 target + flag), 26/10 (arbitrary
target + i32 choice), 26/6 (arbitrary row), 49/2 (quest id + accept flag), 49/14 (quest id),
and forged 39/x Type8 payloads at any time from any position.

- 26/8 resolves only a spawned content actor through `NpcVisibility`'s content-key map. An
  unknown GUID has no menu; an extra spawn is static content. Canary 1 proves the drawable row
  is what binds 9000000217 to an interaction.
- 26/10 requires the choice to be an option of the currently open interaction and re-checks
  range/zone; 26/6 only continues the server-built dialogue.
- 49/2 accepts only an actually offered quest after `offer_denial` (enabled/objectives, giver,
  pending offer, prerequisite, active+unlocked job, limit). The job gate cannot be chosen by
  the client: `character_eligibility` uses the saved active profile only.
- 49/14 settles only the saved `pending_turnin`; a forged reply without the server-opened end
  screen, a wrong quest and a replay all pay nothing (full-state equality asserted). The ore is
  server-simulated: the gather event comes from the Type8 win transaction, never a client score
  or win report, and a stale replayed `OnNextLevelMsg` is inert.
- Rewards are content-authored (5 coins, 15 profile-14 XP, empty item list) and paid through the
  existing grant key / `RewardState`; no client amount, item id or result is trusted. There is
  no free item to sell or re-grant.
- The full-bag node refusal is fail-closed before `begin` (no run, no count, no ore, save
  bytes equal). A full-bag turn-in is coins/XP only and cannot fail on bag space, so a player
  never sees a server error for a reward that grants no item.
- Refusals are per-request results; no `?` from a shared tick was added (no production code).
