# T328: `realm goto` arrives in front of the NPC, on its facing side

## What changed

Developer tool only. `realm goto` now starts its arrival samples on the side the
target NPC faces instead of the side the character approached from, so native
Cobblestone/Sanctuary vendor checks can click the NPC from open floor. No
gating, zone, range, message, packet, save, item, coin, reward or quest state
changed.

| File | Change |
|---|---|
| `prototype/osfr-tools/src/dev_teleport.rs` | `Target` carries `heading: Option<f32>` (radians). `standoff` uses `(sin h, cos h)` when the heading is finite, else the previous `approach_direction`. `Target::from(OpeningActor)` fills it; `content_npc` takes it. Three unit tests added; the existing helper builds heading-less targets so the old-behaviour tests pin the fallback. |
| `prototype/osfr-tools/src/world.rs` | `VisibleNpc.heading: Option<f32>` filled from a regional row's `heading` or its Y-quaternion yaw (`2*atan2(y, w)`), an extra spawn's `heading`, or a Studio placement's `heading`. `ExtraNpc.heading` is now `Option<f32>` so a row without one is a real `None`; the spawn rotation still defaults to `facing(0.0)`, byte-identical to before. Battle markers are `None`. `teleport_targets` passes the heading. |
| `prototype/osfr-tools/src/encounter/field.rs` | Field enemies, battle spawners and arena enemies get `heading: None` (no content yaw exists for them; the approach rule is unchanged). |
| `prototype/osfr-tools/tests/dev_teleport.rs` | `fixture_facing` variant of `fixture` (existing `fixture` keeps `[1,0,0]`). New non-ignored integration test for Roosey (`9500000255`) and Bordon Cloo (`9000000028`) through `Gateway` -> gameplay chat -> `dev_teleport`: arrival is one `STANDOFF` from the row's position, in the NPC's facing half-plane, and the player faces the NPC. |

## Behavior

- `ANGLE_SAMPLES` is unchanged: `0, ±45, ±90, ±135, 180` relative to the base,
  with the same `MARGIN = 0.5 m` against every other loaded zone actor. Base is
  now the target's facing when finite, otherwise the character's approach side.
  Sample 0 is the NPC's front, so a repeated `goto` still lands in the same spot.
- The player's rotation is still `face(direction)` (the reversed arrival offset),
  so the character turns back toward the NPC.
- A missing (`None`) or non-finite (`NaN`, `inf`) heading is the pre-change
  result exactly: unit test `heading_less_or_non_finite_heading_keeps_the_approach_side`
  compares both the position and rotation arrays with the old angle-0 result.
- (R) **"Original NPCs face their customers, so the side an NPC faces is usually
  the open floor in front of its counter."** This is a heuristic, not a
  recovered rule; the command still does not parse collision geometry (the
  `STANDOFF` doc already says so) and the lead re-checks the two vendors natively
  after merge.
- Roosey/Bordon data used by the test (bundled, tracked `data/content`):
  Roosey position `[-1842.249, -41.38295, 411.1896]`, heading `-1.379954`;
  Bordon Cloo `[-1243.191, -14.34194, 408.6057]`, heading `-1.079174`. The lead
  run's content package (`lab/reports/native-20261020T223023Z/content`) has the
  same rows; Roosey's row there has only rotation
  `[0, -0.6365194433952605, 0, 0.7712606551483019]`, whose `2*atan2(y,w)` is
  `-1.3805`, so the quaternion fallback covers the native package too.
- **Observed with the real rows:** a nearby actor makes the exact-front sample
  fail the 0.5 m margin for both vendors (Roosey: an unnamed actor at 4.26 m
  from the front arrival; Bordon: one at 4.11 m and the Cooking Table at 3.63 m
  from Bordon). The sampler therefore takes the first passing sample, +45 deg
  from the facing for Roosey and -45 deg for Bordon; both are still in the front
  half-plane. That is the mandated "same MARGIN rule"; see Open gaps.

## Client evidence (IDA, 2014 client; checked this run)

| `0x0095dae0` | `SetHorizontalDirection` (`sub_95DAE0`) | `python -I lab/autopilot/ida_query.py decompile 0095dae0`: masks the input with the horizontal `[1,0,1,0]` constant, requires a horizontal squared length > 0.01, normalizes X/Z, stores the direction at `this+0x610..0x61c`, and when asked computes `atan2(this+0x610 X, this+0x618 Z)` and calls the model yaw setter `sub_7776B0`. This is the convention `Target.heading` documents: AddNpc rotation `(sin h, 0, cos h, 0)`, yaw = `atan2(X, Z)`. |
| `0x00921a10` | `PlayerUpdatePacketAddNpc_ReadBody` | Unchanged 35/2 reader (prior map/notes evidence, e.g. `notes/Research/Startup World Content.md` and `notes/Research/Native NPC Motion and Animation.md`): the float4 rotation is consumed as a direction, not a quaternion. This change only reads the already-loaded heading; it does not alter any packet bytes. |

No new opcode, field or enum value is introduced. The heading is server content
data; no client input reaches it.

## Security threat note (secure-code-guardian)

- **Attack surface:** the only entry is chat family 15 text `realm goto <name or
  GUID>`, already gated by `--dev-tools` plus an admin role and routed through
  `Gameplay::developer_teleport`; this change adds no selector, command or
  packet. A hostile client can send any name/GUID/extra text; the existing
  resolver refuses unknown, ambiguous, cave-only, empty and non-finite-character
  requests without mutating state (existing snapshot-equality tests, including
  the atomic-bundle test).
- **No new client-controlled value:** the heading comes from server-loaded
  content rows (regional `heading`/quaternion, extra-spawn `heading`, Studio
  placement heading, opening actor heading) or defaults to `None`. A hostile
  client cannot supply or change it.
- **Malformed content fails safe:** `f32::NAN`/infinite/missing heading falls
  back to the previous approach rule; the unit test asserts finite position and
  rotation. The existing finite checks for the target and character are
  unchanged.
- **No state mutation added:** the command still only sets position/rotation
  behind `relocation_block` (encounter/knockout/movie) and refreshes NPC
  visibility through the existing path. No inventory, coin, reward, save or
  roles code is touched. Refusals still change nothing (see Checklist 1).

## Open gaps

- The exact-front sample is rejected by the existing margin rule for Roosey and
  Bordon (see Behavior); the lead's native run will show whether the +45/-45

- Opening actors' 35/2 spawn uses the fixed `combat-template.bin` rotation, so
  the client-visual facing can differ from the content `heading` now used for

  acceptance target.
