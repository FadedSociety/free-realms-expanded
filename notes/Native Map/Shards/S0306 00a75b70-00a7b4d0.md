# S0306 — tooltip and inventory navigation code (00a75b70–00a7b4d0)

## Findings

- `00a75b70`, `00a75d50`, `00a761e0`, `00a76360`, `00a76930`, and `00a799b0` cover dual-string element destruction, array tail shrinking, node-array cleanup, and the TooltipDataSource destructor. The 32-byte node stores narrow and wide strings at offsets 0 and 0x10. TooltipDataSource's node array is at +0x270; its count is +0x278. `00a76470` replaces a row and can notify via virtual slot 4; `00a76a20` changes the count and can notify.
- The tooltip hook `00a76700` calls `TooltipMethods:OnTooltipRequest` with a Lua parameter array containing tooltip kind (`this+0x280`) and an argument. `00a790f0` is vtable slot 6 and refreshes by kind. Builders include InventoryItem (`00a76a60`), StoreItem (`00a771b0`), ClaimItem (`00a77680`), ItemGroup (`00a77b40`), AbilityItem (`00a77d40`), Collection (`00a78040`), Pet (`00a782d0`), PetTrick (`00a784e0`), Ability (`00a786d0`), Job (`00a78860`), Recipe (`00a78a40`, kind 6; `00a79620`, kind 13), ProxiedCharacter (`00a78ca0`), Trophy (`00a78e80`), and FactoryNpc (`00a79250`). These names are anchored by function strings.
- FactoryNpc rows (`00a79250`) are 21 total. Its timer value is reduced only when it exceeds `DAT_01762a30`; the code writes nine icon/text effect pairs in rows 3–20, not ten. Time interpretation and effect record layout remain unresolved.
- The item-by-id path (`00a799d0`) checks a 1024-bucket cache. On a miss, when its request flag is set, it constructs `PlayerUpdatePacketItemDefinitionRequest` and reaches the sender `00a3dca0`. This is the shard's packet send path. The likely reply `PlayerUpdatePacketItemDefinitions` (35/37) is a server-contract hypothesis only; it depends on the community packet catalogue and handlers outside this shard. Emulator packet names establish wire format, not original server behavior.
- Tooltip data-source lookups (`00a76210`, `00a76280`, `00a762f0`) hash names into 1000 buckets and checked-cast values to RTTI types. Their callers (`00a76520`, recipe builders) use strings including `Tooltips.ActiveAbilityEffects`, `BaseClient.ItemAbilities`, and `BaseClient.RecipeComponents`. Cast helpers (`00a75da0`, `00a75e80`, `00a75f60`) use the matching RTTI descriptors and a diagnostic string.
- The inventory navigation functions include CategoryNode construction (`00a7b2f0`), child-node assembly (`00a7b4d0`), visible-entry indexing (`00a7af90`), and two child aggregates (`00a7aaa0`). `00a7b4d0` includes category definitions only when the matched record's byte at +0x10 is nonzero; its category hash tables use the data-source argument, while item groups are reached through `this+0x270 -> +0x20c -> +0x48`. `00a7aaa0` returns the first sum with its low byte cleared, setting that byte to 1 only when the second stored sum changes. The first sum can change without setting that indicator.
- `00a7a870` and `00a7a910` delegate buffer sizing to array vtable slot 1. Their allocator out value becomes the recorded capacity; it need not equal the requested count. Array vtables in this range include BaseNode pointers (`00a7ab40`, `00a7abe0`, `00a7ac00`), ItemCategoryDefinition pointers (`00a7acb0`, `00a7ad50`, `00a7ad70`), and ordinary container teardown/growth helpers.
- `00a7b390` / `00a7b400` mutate bit pairs at +0x295 and set a dirty byte at +0x294 on a real change. Their shared exit still calls virtual slot 4 whenever that dirty byte was already nonzero, even if the current call changed nothing. `00a7b470` / `00a7b4a0` read those tri-state bit pairs. Owner class and game meaning are unknown.
