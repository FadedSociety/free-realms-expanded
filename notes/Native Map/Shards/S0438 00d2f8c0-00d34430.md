﻿# S0438 findings

Shard `S0438` covers 99 functions from `00d2f8c0` through `00d34430`. The client is a ForgeLight-family native x86 binary; these labels describe client behavior only.

## Systems and connections

- **TinyHttp (`lib.tinyhttp`)**: `HttpManager` construction initializes settings and a 512-bucket connection map (`00d33050`, `00d32ed0`). Route methods split URLs and enqueue GET, PUT, or POST requests (`00d30100`, `00d32100`, `00d32210`, `00d32330`). `HttpConnection` objects are pooled and inserted into the keyed list (`00d317e0`, `00d319f0`); manager ticks pump and retire them (`00d31890`, `00d31770`). On termination, sent requests return to the pending queue and retry counts are checked (`00d2f910`, `00d2f8c0`). The response handler parses HTTP status and headers, then copies fixed-length or chunked response bodies (`00d30680`). The `file://` route reads a local file and reports a local 200/404 callback (`00d32100`, `00d30240`).
- **Container and pool helpers (`engine.containers`, `engine.mem`)**: the connection map uses ordered-tree insert, floor-search, erase and balancing helpers (`00d32580`–`00d32ad0`). The pool indexes fixed-size chunks and tracks free slots (`00d32c80`, `00d32d50`, `00d32db0`, `00d32e20`); the observed slot stride is `0x2298`, matching the connection object allocation path. `00d32e90` and `00d32ea0` are ECX-adjusting thunks into the pool operations. `00d32f50` is a relative-jump thunk to `00d32450`; its inferred destructor body is not a separate implementation.
- **Client crypto (`net.client`)**: `CryptoBaseApi` owns a replaceable provider and exposes readiness, forwarding, secure-send, and inbound-unwrapping paths (`00d33270`, `00d333c0`, `00d33410`, `00d335d0`, `00d336f0`, `00d33900`). The generic `PacketUtils::WrapPacket` helper transforms opaque buffers and uses marker `-0xc2b5a37` (`00d33b10`, `00d33a60`). The shared virtual implementations also appear in ClientGatewayApi and Login external-login API vtables. The `SoeUtil::Array<unsigned_char,4096,1>` helpers provide inline storage, external-buffer release, and content swapping (`00d334b0`–`00d33570`, `00d33850`).
- **Asset definitions (`asset.definition`)**: `ParticleDefinitionAsset` creates a `TextureAsset` (`00d33d60`), checks child/resource readiness (`00d33e80`), handles unavailable assets (`00d341e0`), parses/notifies (`00d342a0`, `00d343d0`), and releases retained state (`00d33ff0`). `00d34430` is a shared refcount transition notifier: callers include particle-related code and `SoccerProcessor::SetTeamObject`, so it is not named as a particle-only method.

## Packet and server-contract boundary

This shard exposes generic HTTP bytes and opaque crypto-wrapped buffers, but no application packet class or opcode that can be tied to those buffers. The request builders (`00d31140`, `00d31310`, `00d31540`) format HTTP GET/PUT/POST requests; the crypto helpers (`00d335d0`, `00d336f0`, `00d33900`, `00d33b10`) wrap, transform, or unwrap buffers without identifying their inner application packet. Accordingly, all S0438 `wire` arrays are empty and `server_inference` is null. A server hypothesis would need a verified packet/opcode link plus the relevant client serializer/parser path; neither exists here. The original server is unavailable, and third-party emulator packet names cannot establish original server logic.

A bounded public search for the exact `TinyHttp::HttpManager`, `CryptoBaseApi`, and particle-log symbols did not find original-client symbol documentation. It surfaced the [OpenSourceFreeRealms](https://github.com/Open-Source-Free-Realms/OpenSourceFreeRealms) and [Sanctuary](https://github.com/Open-Source-Free-Realms/Sanctuary) emulator repositories; they remain reconstruction references, not evidence for the original server implementation.
