## Threat note (secure-code-guardian)

What a hostile client can send is unchanged: a 53/7 body is one attacker-chosen `u32` trick id
(and a 53/8 with the same id) for the pet the session has summoned. Why it still cannot abuse this
feature:

- Unknown/forged trick id: `PetService::try_trick` requires the trick row on the summoned pet's
  model and the pet to know it; otherwise `accepted_trick` stays `None`.
- No pet / another player's pet: the packet names no pet; the service uses the session's saved
  roster and the authenticated `character.guid`. The new two-gateway test proves one session's
  trick leaves the other session's quest state byte-equal.
- Running trick, blocked pet, water or another care action: `try_trick` refuses through
  `ActivePet::interacting`/`PetBusy`; the refusal test snapshots `saved(&game)`.
- A 53/8 carries no grade and never emits the quest event, so a client cannot report a quality
  outcome. The engine still clamps counts to `required` and compares the id exactly.
- This diff parses no new bytes, writes no save, pays no reward or coin, and changes no wire field.
  `trick_ids()` only exposes already-validated content ids to tests.
