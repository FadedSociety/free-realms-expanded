# T852 — a server starts with whatever gameplay content the folder carries

Release blocker from the clean-install test (2026-10-28): a fresh launcher install ships
`prototype/osfr-tools/data/content`, and the gateway exited at once with
`osfr-gateway: mining requires opening content` because `data/content` has `mining.json` and
`harvesting.json` but no `opening.json`/`profiles.json`. Gameplay had only ever run on lab
native packages, which add those captured modules.

This attempt starts from the a1 patch (`lab/autopilot/patches/T852-a1.patch`, applied with the
one allowed `git apply --reject`; it applied with line offsets and **no `.rej`/`.orig` files**),
then fixes the three failures the integrator reported:

- `harvesting_content_loads_fail_closed_and_binds_region_111`
- `mining_content_loads_fail_closed_without_a_bound_file`
- `spine_rules_only_ratchet_down`

## What changed

**New `prototype/osfr-tools/src/gameplay/content_presence.rs`** owns the policy:

- `Presence::has(directory, module, files)` — `true` when every file is present; otherwise
  the module is skipped and one event is logged:
  `{"event":"gameplay_module_skipped","module":"mining","missing":"opening.json"}`.
  Logged once per `(module, missing)` per **process** (the server builds its startup template
  and its first session in one start, and every later login re-reads content), and recorded
  in `Presence` so a test can assert what the server wrote without reading stdout.
- `Presence::minigame(...)` — a crafting/gathering movie needs its own file and the opening
  campaign; the file is named first, then `"the opening campaign"`.
- `Presence::record` / `record_skip` — the one place a skip is recorded and logged. The latter
  copy-on-writes the `Arc<Presence>` for the regional quest bind, so a staged session clone
  never mutates another session's records.
- `Dormant` — the save's state for every module this load skipped. `restore_skipped` writes
  each back in `Gameplay::state`, so a smaller content set never wipes progress. Only a module
  that did **not** load may be in `Dormant` (documented on the type).
- `core(...)` — categories / legacy quests / legacy combat: absent file → the module's own
  `without_content` constructor; present file → the same fail-closed load.
- `inventory(...)` and `battle_rows(...)` — the two remaining no-content decisions. Both were
  added in this attempt to keep `Gameplay::load` (the hub) small: the inventory helper chooses
  `Inventory::load` vs `Inventory::without_content`, and battle rows are published only when
  the encounter engine that runs them loaded (the same rule chess/soccer/cards already use).
- Module file lists (`PROFILES`, `OPENING`, `INVENTORY`, `QUESTS`, `COMBAT`, `CATEGORIES`).
  `OPENING` lists the files its loaders read: `opening.json`, `profiles.json`, `quests.json`
  (opening journal), `combat.json` (opening world actor template), `opening-abilities.json`,
  `encounters.json`.

**`Gameplay::load`** (hub, thin): the eleven `return Err("... requires ...")` guards become
skips; `profiles`/`opening`/`encounter`/`smelting`/`forging`/`cooking`/`mining`/`harvesting`
stash the saved state in `Dormant`; `inventory`/`quests`/`combat`/`categories` get a
no-content mode from their own module. Untouched fail-closed checks (present but
inconsistent) keep refusing: campaign marker hash mismatch/oversize, schema versions,
malformed JSON, saved enemy health > max, saved active recipe unavailable, equipment layout
mismatch.

**Owning modules** (each keeps its own rules on its own type):

- `inventory.rs`: `Inventory::without_content(state)` — empty catalogue (`Content::empty`),
  saved instances/coins kept, nothing defined so nothing is visible/grantable/equippable;
  `validate_content_state` recognises the empty catalogue by its empty proof spans (a loaded
  manifest always has `profiles + 2` spans, checked at parse).
- `quests.rs`: `QuestEngine.content: Option<Content>` + `QuestEngine::without_content(state)`.
  Every request answers like an empty catalogue; saved counters stay.
- `combat.rs`: `Combat.content: Option<Arc<Content>>` + `Combat::without_content(state)`; no
  actors, menus or attacks; the defeat counter stays. `spawn`/`near` take the content they
  use, so no `unwrap`.
- `gameplay.rs`: `categories: Option<ItemCategories>`; no 44/2 list is sent (the two
  initialization call sites `extend` instead of pushing an empty message).
- `gameplay/npc_quests.rs`: a missing split quest catalogue is a skip (`regional_quests`,
  missing `quests/`) that keeps `saved_npc_quests`, not a login error.
- Activity portal: battle rows are published only when the encounter engine loaded (see
  `battle_rows`), so the release does not offer a Play the server cannot run.

**Deleted:** `Gameplay.dormant_housing` (folded into `Dormant`), and the eleven
`... snapshot requires its content` / `... requires opening content` error branches, plus the
regional quest catalogue's `saved NPC quests require split quest content` guard.

**Tests:** `src/bin/osfr_gateway/t852_content_presence.rs` (3 tests) declared from
`src/bin/osfr_gateway/tests.rs`; shared `test_support::enter_world` (Ready+Loaded through the
production dispatch path) so the new module and future ones do not re-declare it.

## The rule, written down

1. A module whose **own file or a prerequisite file is missing** is skipped: one event, module
   inactive, no packet, no request handling. It is not fatal.
2. A skipped module's **saved state is written back unchanged** (`Dormant`), so a character
   moved between content sets keeps its progress. The module stays inactive (a save written
   with an opening campaign keeps its opening state but cannot play the cave until
   `opening.json` and its prerequisites return).
3. **Content that is present stays fail-closed.** A malformed file, an unknown schema
   version, a campaign marker whose `opening_sha256`/`cooking_sha256` no longer matches, a
   saved run naming a recipe the content no longer has, a saved encounter whose
   `content_sha256` disagrees with the present campaign, or a save whose equipment layout
   disagrees with the loaded inventory still refuses the load. A server must never run
   half-matching content.
4. `Presence` records the skip so the same load is observable to tests and to an operator
   (`Gateway::gameplay().skipped_modules()`); the JSON line is the production surface.

**Interpretation note (R).** T852 item 1's parenthetical lists "a saved snapshot whose content
is gone" among checks that stay errors, while item 2 says a saved character whose save holds
state for a skipped module keeps it while the module stays inactive. This change follows
item 2 for a module whose **own file is absent** (skip + keep), and item 1 for checks that
compare *present* content against the save (mismatch still errors). The lead note of
2026-10-28 explicitly confirms this for the mining/harvesting prerequisite case: "missing
prerequisite -> module skipped, logged, saved state kept". If the lead later prefers the
stricter reading, the only change is to turn the `dormant.x = ...` branches in
`Gameplay::load` back into errors; the skip log and the no-content cores stay as they are.

## Security note (secure-code-guardian)

What a hostile client could try, and why it is refused:

- **Choose which modules load / which content file is read.** The content directory is a
  server operator argument (`--content`); no packet field reaches `Presence::has` or the
  module file lists, and item/quest ids never become paths (the existing fixed-path readers
  are unchanged). A skip record contains only static module/file names, never player data, so
  the start log cannot be steered or used to leak paths.
- **Abuse an inactive module's request handling.** `Combat::handle`, `QuestEngine::interaction`,
  `handle_command`, `enemy_defeated` and `on_position` return empty outcomes when their
  content is absent: the client's bytes are dropped without packets, without an error, and
  without a panic (`let Some(..) else` instead of `unwrap`), so a malformed 26/10 or 36/10
  cannot reach a content-less engine.
- **Create value out of missing content.** With no item definitions, `Inventory::grant` /
  `grant_bundle` refuse (unknown definition) and change nothing; the no-wipe path keeps saved
  instances but withholds them from every wire packet, so a server without an item catalogue
  can neither create nor reveal items. No coin/item grant was added; saved coins are unchanged.
- **Use the skip to bypass eligibility.** The skip only suppresses modules; it never adds an
  acquisition path. Nothing in `occupation.rs` (busy gates), the transaction staging, or the
  save ordering in `bin/osfr-gateway.rs`/`gateway.rs` changed; no `fs::write` was added in
  `src` (the tests write only inside their scratch directories).
- Threat-model limits: the content directory is trusted operator input, as before; a file that
  is present is still fully validated (fail-closed), so a partially copied package cannot run
  half-matching content.

## Open gaps

- No item definitions in `data/content`: vendor/coin-shop rows cannot be granted, Station Cash
  listings drop rows they cannot present, quest item rewards are refused, and the client shows
  no item names. Publishing a definition set (T853's `data/release/inventory.json`) is the
  lead's content move; a server without it now starts.
- No `categories.json` in `data/content`: the 44/2 item-category list is not sent until the
  release overlay ships it.
- The encounter engine (field enemies, power-ups, job abilities, field battles) is still built
  in the opening block, so it is inactive without `opening.json`. Promoting it would need the
  job/profile bars (`profiles.json`), so it was left to a follow-up; battle portal rows are
  withheld so the client is not offered a dead Play button.
- `CoinShop` still constructs without item definitions; a sale path inside it re-reads
  `inventory.json` and fails closed if it is absent (no purchase can succeed anyway because
  nothing can be granted). A follow-up could refuse the shop instead of the sale.
- `Inventory::patch_gender` (a test-only self-data splice) still requires the captured "items"
  span; it is not on the login path (`Gameplay::patch_self`/`patch_gender` have no production
  caller). `initialization_patch` no-ops without spans.
- The skip log is once per process per `(module, missing)`, so a `realm reload` that makes a
  module unavailable again does not re-log it.
- A save *inside a skipped module's zone* is still refused at login: `Gateway::load_internal`
  keeps the existing `saved zone differs from gameplay encounter` check, so a character parked
  inside the opening cave cannot log in to a server without the opening campaign. The save is
  untouched and loads again when the content returns; it was not silently relocated because
  that would rewrite the character's position outside a valid gameplay transaction.

## Checklist

1. **A refusal changes nothing.** The refusal test snapshots every file (name + bytes) in the
   scratch content directory and asserts equality after each refused load; the no-wipe test
   asserts a refused `Inventory::grant`/`grant_bundle` leaves coins and items unchanged. No
   open NPC menu, offer, counter, item or cooldown is involved in these refusals (they happen
   at load, before any session exists). The two type8 tests add the inverse: an absent-file
   load *succeeds* and keeps the save.
2. **Rollback covers all state.** No transaction was added. `Dormant`/`Presence` live inside
   `Gameplay`, so the per-request staged clone carries them (`Arc`, copy-on-write only for the
   regional-quest skip); there is no shared side table that a refused transaction can mutate.
   The process-global log-dedup set only suppresses duplicate JSON lines; it stores no
   gameplay state.
3. **Apply deltas, never restore old snapshots over live state.** `restore_skipped` fills only
   fields whose module did **not** load (`Option::is_none`); every active module's live value
   wins, and `Dormant` entries are only created in the skip branches. Inventory/quest/combat
   no-content modes keep the saved state as the live value and normal grants/consumption apply
   deltas on top.
4. **Busy rules are mutual.** No activity was added; `gameplay/occupation.rs` is untouched.
   A skipped module has no run, so it cannot hold a busy gate, and the skipped movies are
   absent from every gate (their engines are `None`).
5. **Every entry path is gated.** The change gates the single load path every session uses:
   `Session::new` → `load_gateway` → `load_gameplay_from_content`/`Gameplay::load` (and
   `load_gateway_template` for account-store sessions). No parallel loader/feature path was
   added, and no action's level/job/budget/busy/eligibility check changed (a skipped module has
   no action). The bin test drives exactly that path (login, Ready, Loaded); the graph trace
   shows `Gateway::load_with_gameplay` is the only production inbound caller.
6. **Reachable in production, tested through it.** `tests::t852_content_presence` uses the
   real `Session`/`Scene` and `enter_world` (dispatch → staging → commit → save), not
   internals or a copy of the loader. The type8 assertions drive `Gateway::load_gameplay` on
   the same content path the gateway uses.
7. **Survives reconnect.** The no-wipe test writes a character save through
   `test_support::save_character`, logs in through a real `Session`, reaches world entry, then
   reads the save back with `load_or_create`: the skipped modules' state and coins are
   unchanged while the modules are inactive.
8. **Every exit path restores the player.** No activity lifecycle changed; skipped modules
   start inactive, and the empty-outcome paths leave the character free and in its zone (the
   world-entry test asserts the shipped NPC spawns, job list and chat and that the entry

9. **Economy safety.** The no-wipe test asserts `Inventory::without_content` refuses

11. **Unique ids.** Not applicable; no ids are minted.
12. **Others see changes.** Not applicable; nothing visible to other players changed.
13. **Content works end to end.** The world-entry test asserts the shipped content's NPC

18. **A type's rules live on the type.** `Presence` owns "what is skipped and what is
    logged"; `Dormant` documents that only a module that did not load may be stored and
    `restore_skipped` is the single merge point; `Inventory`/`QuestEngine`/`Combat` own their
    no-content constructors and state rules; `categories: Option<ItemCategories>` carries its
    rule on the field. `GameplayState`'s fields and serde shape are unchanged.
19. **Hot paths stay cheap.** `Gameplay` is cloned for every staged request; `dormant` and
    `presence` are `Arc`s, so those clones are refcount bumps, not copies of the skipped
    modules' saved state or the skip records. Per tick: no new work at all (no content check
    runs after load). `state()` runs only when a save is written.
