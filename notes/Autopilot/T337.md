# T337: S13 - one `FieldSim` and one swap

## Skills applied

- **Ponytail (full):** reused the existing `with_shared_fields` staging seam
  instead of a second helper; moved the existing `KillLedger` and
  `impl FieldEnemy` rather than adding modules or a public API. No new packet,
  content row, save field, selector or dependency. Review pass below.
- **secure-code-guardian:** threat note below.

## Result

`EncounterEngine` and `SharedFieldState` now each carry one `FieldSim`
(`enemies`, `wander`, `attacks`, `moving`, `kills`) instead of five parallel
collections. `with_shared_fields` swaps the whole value once before the action
and once after it (ten swap lines become two); `take_shared_fields` moves only
enemies and wander and starts attacks/moving/kills empty through
`..FieldSim::default()`, exactly as today. The dots/stuns/target_buffs staging,
`shared_sender` handling, `resets` map, `action(self)` call and the
invalidated-effect purge are unchanged.

`FieldSim` is defined in `src/encounter/shared.rs` next to `SharedFieldState`,
`take_shared_fields` and `with_shared_fields` (the brief allows this when the
module ownership is cleaner; it also keeps the type definition out of the hub).
The existing `KillLedger` moved with it because its only users are the sim and
the two shared methods; `KillCredit` stays in `field_rewards.rs`. The hub keeps
one private `field_sim: FieldSim` and imports the type.

Hub offset: the hub's `impl FieldEnemy` (`reset_motion`/`random`, called only
from `field.rs`) moved to its owning module, so `src/encounter.rs` stays net
negative after rustfmt wraps the longer `field_sim.*` chains.

No behaviour change is intended: the set of fields each method touches is the
same; the rename was compile-driven.

## Security note (secure-code-guardian)

Threat surface is unchanged: a hostile client can send `36/10`, `26/8`,
`26/10`, `26/13` and `41/108` on a shared field. This refactor changes only
which Rust values the engine borrows while it handles one such intent.

- The parse gates (`shared_action` lengths, bar/slot/kind, membership `known`,
  zone, `active`, `shared_sender`) are untouched, so the accepted set cannot
  widen.
- The swap is symmetric on success and error: the closure returns
  `io::Result`, and the second swap/restore and effect purge run before the
  result is returned. A malformed intent can leave neither the engine holding
  the world's sim nor the world holding the engine's.
- The malformed/NaN cases in `malformed_and_unknown_targets_do_not_mutate_or_consume_swing`
  snapshot health, position, attack clock and pending credits and assert
  equality after the refusals.
- No new `?`, `unwrap` or panic on client data; no save, coin, item, reward,
  role, chat or session-plumbing code is touched. No player names or chat text
  were added; the test ids are the suite's existing synthetic constants.
