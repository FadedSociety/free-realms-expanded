# F641: saved enemy health survives a combat_scale.json retune

Applied: ponytail (full), secure-code-guardian (threat note below).

## What changed

- **Blocker (finding 1).** `EncounterEngine::load` refused a save whose enemy `health` exceeded the scaled max, and
  `content_sha256` hashes only `encounters.json`, so lowering `enemy_health_scale` refused login for every saved character.
  `validate_enemies` is now `restore_enemies`: it clamps each saved world and cave enemy to the loaded `max_health`, then runs
  the same checks (guid, count, position). A full-health enemy loads full when the scale drops; a hurt enemy keeps its health.
- **Finding 2.** `notes/Autopilot/T639.md` now says the scale is read on every `Gameplay::load` (per login): an edit applies to the
  next login and a broken file refuses logins, not startup. `gateway.rs` and `osfr-gateway.rs` are untouched.
- **Finding 3.** `tests/power_up_drops.rs` and `tests/shared_field_state.rs` derive their numbers from
  `tests/common/combat_scale.rs` (heart heals from the base health, the DoT test's enemy health from the basic attack and the enemy scale).
  Findings 4 and the fixture/balance part of 3 are left to the lead as briefed.
- **Finding 5.** The oversize refusal in `combat_scale.rs` now names the file (`<path>: file too large`).
