## Client evidence (read-only IDA, rechecked this run)

- 32/7 reader `sub_A2A910` (`0x00a2a910`), handler `sub_A2BA40` (`0x00a2ba40`): after the int16
  pair it reads three 8-byte pairs (the second overwrites the first), then the dword results. The
  third pair is the target GUID, so the first post-GUID dword at packet offset 28 is the damage the
  decoder reads. Decompiled this run; matches `notes/Research/World Enemies.md`.
- 36/5: dispatcher `0x00a35cc0` case 5 -> serializer `sub_8FA5C0` (`0x008fa5c0`, reads the slot
  count) -> slot reader `sub_8E6760` (`0x008e6760`): kind dword at +0, definition id at +4; kind 0
  is 4 bytes, kinds 1/3 are 41 bytes (id, eight dwords, one byte). Decompiled this run.
- The T010 rows are the captured client definitions already documented in `notes/Autopilot/T010.md`
  (Wizard 4914 wand, Warrior 29963 cudgel). The helpers only write fixture definitions; the real
  starter grant still decides ownership.
