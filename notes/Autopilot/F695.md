## Security threat note (secure-code-guardian)

A hostile client can still only send 26/8 with a u64 target; it cannot name a node file, tag,
spawn id, type or reward, and nothing from the client reaches `node_guid` or `add_sites`. The
guid tag is server content: a reused tag could only collide two server-authored spawns, which made
`GatheringNodes::load` refuse and denied world entry (availability, not privilege). Tag 4 keeps the
collection import clear of the quest pickups, but it is not reserved from T524's effect companions,
which plan to use tag 4 and move the collection file to 5; `tests/node_guid_namespace.rs` catches
either collision on the live loader, so a tag-4 companion cannot alias a live node. The file
stays dormant: no packet, save, coin or item path reads it, and the 1 MiB + serde bound and
`add_sites` range/respawn/finite/duplicate bounds are unchanged. The collection drop tables are
still not granted by any code; when collection-node-pickups wires them it must grant from
server-owned tables after a server-verified outcome and check ownership, as T523's threat note
already says. No secret, no copied AGPL code (data rows only), no new client-triggered allocation.
