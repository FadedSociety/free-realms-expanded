# F149: T032 shared-world follow-ups

## What changed

1. **Same-zone transfer no longer keeps ground pickups.** `Gateway::stage_instance_transfer`
   (gateway.rs) clears the staged session's pickups through
   `Gameplay::discard_ground_pickups` -> `EncounterEngine::discard_ground_pickups`. The held
   power-up is untouched. The clear happens after every validation and on the session clone,
   so a refused transfer leaves the live pickups intact.
   Client evidence: opcode 31 (client begin-zoning) reader `0x008e4ae0`; the `0x1f` case in
   `lab/decompiled/client/FreeRealms/pseudocode.c` (around line 1108664) reads the new scene
   body and loads the new world, so actors from the old scene (including pickup actors) are
   gone from the client.
2. **Group-heal ledger keyed by instance.** `World::claim_group_heal(instance, kill)` stores
   `(instance, enemy_guid, now_ms)`; `Session::heal_group` resolves the picker's committed
   instance before claiming. A duplicate claim in one instance still refuses; the same
   authored guid/ms in another instance is a separate kill.
3. **Every seeded zone's public instance is shared.** `World::prepare_membership` uses the
   zone's one public instance for zone 0 and for every zone with a field seed, instead of
   allocating a solo child for nonzero zones. `World::enter_instance` now seeds any instance it
   enters from its zone seed, so `enter_public`/`enter_dungeon` are not inert. A private child
   that already owns the zone-derived id is refused with the new
   `WorldError::PublicInstanceTaken` rather than aliased as public.
4. **Late-join test.** Already fixed in F132 (42c030c): it re-reads `world.field(child)` after
   `commit_membership(second)`. I verified the guard canary: removing
   `ensure_field_from_seed`'s existing-field guard fails
   `t032_private_instance_field_is_one_shared_death_for_two_members` at
   `tests/shared_field_interest.rs:503` with HP 300 vs 200; restored. The socket test
   `t032_two_bot_private_instance_shared_death` also admits the second member only after the
   first hit. No F149 code change was needed for item 4.

## Reconstructed rules and evidence

- (R) A transfer into another instance of the same scene is a client scene reload; its ground
  pickups are not carried into the new instance, while the held power-up is player state and stays.
- (R) A big-heart group heal is claimed once per `(instance, enemy guid, kill millisecond)`.
  Seeding clones the same authored enemy GUIDs into each instance, so the instance is part of
  the kill identity.
- (R) A seeded scene has one public instance whatever its zone id; unseeded nonzero scenes
  (battle, dungeon, minigame) keep the per-entry solo child.
- (R) Public instance identity follows the zone id; if a private child already owns that id
  (a scene registered after child allocation), the entry is refused rather than aliased.
- Client: `0x008e4ae0` reads the opcode-31 begin-zoning body; the `0x1f` case in
  `lab/decompiled/client/FreeRealms/pseudocode.c` around line 1108664 calls it and then
  loads the new world/scene. The server sends opcode 31 through `zone_transition::decode` for
  the staged transfer.
- IDA queries actually run: `decompile 0x008e4ae0`, `xrefs 0x008e4ae0`,
  `decompile 0x00908430`, `func 0x008fa339` (not inside a function). The pseudocode case was
  read directly. IDA did not contradict any note.

## Security threat note (secure-code-guardian)

Attack surface: same-zone instance transfer, ground pickups, and the group-heal claim. The
transfer is host-authorized only (`stage_instance_transfer` is not reachable from raw client
packets), the pickup list is server-spawned from server kill events, and the instance comes
from server membership. A hostile client cannot name an instance, a kill id, a pickup GUID or a
drop table. The clear is staged on the session clone, so a failed/refused transfer leaves the
live pickup list, membership and ledger untouched; the socket test asserts pickup count 1
after a forced save failure. The ledger is bounded at 256 claims and keyed by
`(instance, enemy guid, server now_ms)`; replay in one instance refuses. `PublicInstanceTaken`
fails closed before any membership mutation instead of aliasing a private child as public.
No client quantity or id is consumed, no reward is granted, and no new save or wire format is
introduced.
