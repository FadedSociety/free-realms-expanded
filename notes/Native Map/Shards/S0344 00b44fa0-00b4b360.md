## Components and connections

- **InGamePurchase client (`net.coinstore`, 00b44fa0–00b49090).** `ClientInGamePurchaseManager` sends startup requests and handles opcode 66 sub-opcodes. The request gate at 00b46b90 checks its account, currency, country and state caches. The dispatcher at 00b48a10 routes responses to handlers including 00b45f60, 00b460c0, 00b46200, 00b46a50, 00b45560, 00b45660, 00b45ba0, 00b47690, 00b477e0, 00b47f20 and 00b48700. The code does not establish any required arrival order.
- **Store content requests (00b47b20, 00b48120).** Both detect missing local store/bundle entries and serialize request lists through 00b473f0. The community catalogue's `PacketInGamePurchaseStoreBundleContentRequest` (66/27) describes entries containing store id, bundle id and marketing item ids. This is a likely mapping for the client payload, not proof of server behavior; the inner serializer 00b41a30 is outside this shard. `00b48120` batches requests and logs “Streaming %d items per request.”
- **Store record parsing and sending.** `00b45340` reads a store definition; `00b453f0` serializes one. `00b484f0` is named neutrally as a bounded reader for two 32-bit fields and an optional payload because it has no recorded callers or dispatcher link. `00b46f10` sends the catalogued `PacketTunneledClientWorldPacket` wrapper around a list; its order-response caller runs before `OnOrderResponse` dispatch, but the inner packet id remains unknown.
- **Player titles (`net.packet`, 00b49140–00b4a3a0; `game.character`, title state).** RTTI identifies `BasePlayerTitlePacket`, add/remove/update-all/select/refresh subclasses and the `SoeUtil::HashListMap<int,PlayerTitleData,32,-1>` container. `00b4a3a0` dispatches title operations; `00b4a070` inserts a missing key and leaves an existing key unchanged. `00b4a280` reads two initial fields followed by four 32-bit words; no string payload is established. `00b49a10` updates a title id and calls its owner callback on change; 00b49a50 is an adjustor thunk to unresolved target 00cc55d0. `00b49ed0` constructs a hash list and a reference-counted member, but the allocated member's type is unresolved.
- **Screenshot and portrait support (00b4a9c0–00b4b360).** `00b4a9c0` constructs opcode 115 `PacketAddClientPortraitCrc`; it does not send it. `00b4b240` returns a cached default headshot pointer and length or logs an empty-buffer condition. `00b4b360` copies five words and a separate word; its caller inserts the result into a linked/bucketed node, with no proven screenshot-state meaning. Hash-list/map allocation, cleanup and scalar deleting destructors are grouped under `lib.soeutil`.

## Wire and server-contract hypotheses

1. Opcode 66 responses are dispatched by sub-opcode in 00b48a10. Request/response pairs for account, currency, country and state data align with the catalogue and their client handlers. The client may retry requests when local caches are empty (00b46b90); this does not prove whether the original server required ordering or tolerated repeats.
2. The missing-content paths at 00b47b20 and 00b48120 likely send `PacketInGamePurchaseStoreBundleContentRequest` (66/27), based on the list-building behavior and community serializer shape. Expected responses are a reconstruction hypothesis pending direct confirmation from original traffic or a complete client serializer trace.
3. Player-title packet constructors write opcode 152 and sub-opcodes 1–5. The community catalogue contains 152/3 and 152/4, while this binary also constructs add/remove/refresh forms. This establishes client packet construction and dispatch, not the original server's accepted semantics.
4. Opcode 115 is written by the portrait CRC constructor at 00b4a9c0. The catalogue has no matching row, and this shard does not show its send point or server meaning.

## Contradictions and open questions

- No consulted vault note covers this address range. Existing notes therefore supply no independent address-specific confirmation or contradiction.
- `00b46200` compares parsed country entries with a built-in country-name table. That does not show the server sent English display names; locale source and matching semantics remain unknown.
- `00b46f10` is called by the order-response handler, but sends before that handler dispatches its UI event. The tunneled world packet's inner type and list meaning are unresolved.
- `00b484f0` has no callers in the map, so it cannot safely be assigned to the store-bundle-base packet despite its delegate being the store record reader.
- `00b49ed0` zeroes +0x98 and +0x9c before installing a ref-counted object. Any claim that +0x9c is already an owner callback pointer conflicts with this constructor path.
- The store serializers at 00b45340/00b453f0 delegate many record layouts to functions outside this shard. Their inner field semantics remain partly unknown.
- The title map's exact specialization is proven at its destructor vtable (00b49bb0); helper names such as `00b4a070` remain mechanical because they carry no direct RTTI reference.
- The default headshot helper does not show that a server portrait failed. Portrait fallback policy and the screenshot node payload copied by 00b4b360 remain open.
