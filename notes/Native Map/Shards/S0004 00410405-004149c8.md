## What the range contains

**1. Control drawing and hit testing (00410405-00410d0c).** Methods over one object layout: point
at +0x10/+0x14, hit byte at +0x18, flags at +0x1c (bit 2 = enabled), draw offsets at +0x20/+0x24.
00410405 tests the point against a list of cell origins; 004104a3 clips the requested region
against the source size and the caller's rect, computes the source index with the per-flag shift
table DAT_01af51ec and calls FUN_004963f2 and FUN_004a698d (the draw role is inferred, not
verified); 0041068c runs a 32-byte-item sprite list through 004104a3 switching the current colour
at +0xf0 per item; 00410733 tiles one source across a destination rect using flag bits
0x1000/0x4000. 00410b17 and 00410bb6 are the rect and segment hit tests; both set +0x18 only when
the object's state predicate (FUN_00406aad on this+0x60/0x64/0x68 or this+0xb4/0xb8/0xbc) accepts.
00410d0c dispatches four-dword records through virtual slot +0xec.

**2. A shared state-change protocol.** 00411506 (38 callers), 0041177a, 00411cba and 004130f9 all
build a state record (flags + payload + five zero dwords + trailing static short at +0x1c) and
hand it to virtual slots +0x110/+0x114; when the returned flags word has any bit of `0x24924` set
they call FUN_004d93a3, which behaves as the pending-change flush. 00411601 additionally walks the
enclosing object chain (FUN_00406665/FUN_004063d8), compares the four rect fields +0x94..+0xa0 of
the nearest layout owner, invalidates it via +0x228 and fires FUN_00411506(7).

**3. The property/theme interface layer.** 00411de6 and 00411f26 are the two constructors of a
`GPropertyInterface` sub-object (vtable written at object+0x14, owner interface kept at +0x18 with
AddRef; the final +0x14 vtable is the unnamed override 0175d73c, so this is the implementation
object, not a bare GPropertyInterface); 00411e80 is its destructor. 004110e2 and 00411259 manage
per-state cached interfaces (this+0xc8 for state 1, this+0xcc otherwise) and, on a miss, fill the
caller's record fields +0x14..+0x34 by querying the interface at this+0x24 with six 16-bit
`GPropertyId`s per state (id tables `&PTR_DAT_01af3198..31ac`, default colour 0xffffff). 0041154d
queries one named property (DAT_01bc36cc) and otherwise answers defaults per size mode (0/0 for
<3, 0x7fffffff for 4); 00411c16 is its relative that falls back to this object's own rect.

## How it connects

The control draw path (group 1) consumes colours and state predicates that groups 3/4 load; the
state protocol (group 2) tells a control that a theme value changed; `GObjectIterator` (group 5)
walks display trees; the chain dispatch (group 7) routes a property change to the objects that
implement it; `GDataAccessWrapper` (group 9) carries "(data access, property id, owning object)"
through all of it. 00411601 is the meeting point: it invalidates an ancestor's rect and then posts
state change 7 through 00411506. The containers used by 00412bd8 (this+0x140), 004132c5
(this+0x1d0), 004135fc (this+0x1e0) and 00412c48 (the vector owned by *(this+0xe4)) are fields of
the control, not globals.

  code, callee/caller, string and vtable anchors only.
- Only four real class names exist in this range (GObjectIterator, GPropertyInterface, GInterface,
  GDataAccessWrapper, plus the GDSGeneric/GBitmapCtrlThemeLoader/GCtrlTheme_Infinity strings).
  Every other name is a mechanical description, not recovered RTTI.
- The `GCtrl*` strings name property *groups*, not the classes owning the functions that load them.
- The dirty-state mask 0x24924 (bits 2,5,8,11,14) appears in five functions; individual bits are
  unnamed.

  freeing it; 00412a69/00411e80 tail-jump to their base destructors; four list walks were field
  containers, not globals.

   FUN_0040a782/0040a795).
