## Security threat note (secure-code-guardian)

A hostile client can send 66/43 with an arbitrary item id, quantity and transaction id, or
26/10 for an NPC it is not next to. The server trusts none of those fields for
authorization: a purchase requires an open shop opened through a **role-bearing** NPC whose
stock is the explicit server-owned `vendors.json` list with a positive `stores.json` price,
plus the existing zone/range, wallet, bag and quantity checks. This diff makes authorization
stricter than F307: `NpcInteraction::load` refuses a mapping for a role-less NPC and the menu
opens only for role-bearing NPCs, so a content regeneration cannot convert a dropped role
into a live sale. No client field selects the role or the mapping; the loader returns `Err`
(no panic) for malformed or unauthorized content. No client packet parser changed; only the
server-owned content loader did. No save, coin, item, session or account-role path changed.
The temp fixture is test-only and never aliases the public world.
