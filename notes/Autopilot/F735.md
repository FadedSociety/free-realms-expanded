## Threat note (secure-code-guardian)

Hostile client input is still one 26/8 frame with a u64 target and one trailing byte. It can:

- name any guid: only a node this session placed, currently shown, in the open world within the
  node type's integer range, while `activity_busy()` is false, is accepted. Everything else falls
  through to the existing NPC/quest routes or is refused with the shared line. No client item id,
  quantity, seed or time reaches the roll or the ledger.
- replay a hidden node: `shown` is false, so `Gone` is answered and no draw, item, ledger entry or
  regrow deadline moves. The RNG is advanced only inside `consume`, on the staged clone.
- steer the item: impossible. The item is one `pick_weighted` draw of an OS-entropy-seeded stream;
  the test-only seed hook is never called by the gateway. A client cannot learn the next draw
  before committing a click.
- exploit missing content: a node file without the catalogue, or a drop with no entry, refuses
  before staging; the item is not granted and the node is not hidden.
- overflow the bag: `Inventory::accepts_reward_bundle` preflights the exact grant on its internal
  clone; the canonical helper bounds the bundle and does checked arithmetic.
- crash the tick: the pickup is a per-request handler; errors are logged and refused, never `?`
  out of a shared tick. `tick_gathering_nodes` work is unchanged apart from the `Hide` shape.
