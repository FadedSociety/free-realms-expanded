## Security threat note (secure-code-guardian)

- **Attack surface.** Test-only change. The suite drives hostile fields through
  the real gateway: any item id (`i32::MAX`), quantity (`u32::MAX`, over-owned),
  merchant GUIDs (foreign, `0`), sale instance ids (unowned, replayed) and the
  server-unread 66/43 price dwords. No production parser, route, reward, save
  field or content value was added, so no new trust boundary exists.
- **Why a hostile request cannot profit.** The suite re-proves the production
  gates: item in the open vendor's authored stock, `stores.json` price,
  sufficient coins, bag capacity, owned instance and available quantity, the
  open-shop merchant rule, and the wire `i32` coin ceiling (near-cap sale
  refused). A refused request now also proves it requested no save
  (`!gameplay_changed`, `!state_changed`), so the session cannot be told to
  persist a refusal.
- **Canaries.** The 165/5 wire pin canary was re-run this session and failed the
  pin before restoration; the T374/F397 production canaries (buy-back
  `remaining`, coin cap, refusal `changed`) were run in the earlier F397 attempt
  with the same suite and reverted with recorded SHA-256 values.
- **Isolation.** Refusals are per-request result packets; the suite keeps using
  the same open shop after every refusal, and `app_fuzz` stays green.
- The `shared_world_membership` change only widens a test's wait for the
  sender/listener copies; it cannot mask a lost echo (a real loss now waits
  `PATIENCE` and fails the exact-count assertion).
