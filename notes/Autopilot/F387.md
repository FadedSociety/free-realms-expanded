# F387: Fix review blockers in T329 (commit b1d0299)

## Summary

T329 (`b1d0299`) delivered the Station Cash ride catalogue to the real client, but the review
(`lab/autopilot/reviews/b1d0299-T329.md`) found two blockers: the delivery hook and the accepted-traffic
labels both lived in lead-only `src/gateway.rs` with no lead sign-off. F387 moves the delivery into the
merchant owner and removes the routing change:

- `CoinShop::marketplace_packets` (renamed from `world_entry_packets`) is the one gate
  (`station_cash.enabled && marketplace.enabled_on_handshake`) and the one byte set (66/24, 66/33,
  66/7, 66/6, 66/9, 66/5). The 66/10 wallet reply now carries it; 66/12 reuses the same helper.
- `Gateway::startup_for(Kind::Ready)` is back to its pre-T329 shape with no append, and
  `Gameplay::world_entry_marketplace_packets` is deleted. World entry sends no Marketplace packet for
  any package.
- 66/29 and 117/41 are back on the pre-T329 `gameplay.handle_in_world` path: no reply, no state change
  and not added to `outcome.applications`, so the binary's shared router never sees them.
- No session creation, teardown, transaction, save ordering or accepted-traffic change remains in the
  diff; `src/gateway.rs` is 2,221 lines (ceiling 2,242).

The lead signed this design off on 2026-10-21 in `lab/autopilot/lead-signoffs.md` (T329 `b1d0299` /
F387): catalogue on the 66/10 wallet reply, no world-entry stream change, 66/29 and 117/41 unrouted,
native re-check pending. The two review blockers are therefore also resolved against the register,
not only in code.

The three `tests/coin_store_siblings.rs` renames remain because the lead added matching

The only source change since attempt 1 is that test name and its doc comment.

## Security threat note (secure-code-guardian)

A hostile client can send 66/10 (body length-checked exactly 4), 66/12 (4 bytes), 66/29 (any bounded
body; observed 69 bytes) and 117/41 (observed 6 bytes). 66/10 now returns the server-built catalogue: no
client field selects a row, price, quantity or grant, and the reply is content-bounded (~9.6 KiB). The
66/12 path already returned the same set before F387, so the amplification surface is unchanged; the
per-bundle reply budget still bounds a bundle. 66/29 and 117/41 are not parsed, allocate nothing, send
no reply and change no state; they are dropped before the binary's shared router (asserted). The order
path, price checks and `earn_only` exclusion are untouched. Malformed requests still return `Err` and
drop only that message for that session. The catalogue is server content; no file, network or secret
I/O is added.
