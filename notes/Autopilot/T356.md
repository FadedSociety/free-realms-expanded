## What changed

Test-only consolidation. Five suites now include the shared greeting harness
exactly as the migrated model does:

```rust

```

- `tests/npc_greetings_starting_road.rs` (493 -> 370 LF lines)
- `tests/npc_greetings_lakeshore_wilds.rs` (710 -> 590)
- `tests/npc_greetings_job_hubs.rs` (768 -> 651)
- `tests/npc_greetings_sanctuary.rs` (809 -> 634)
- `tests/npc_greetings_seaside_briarwood.rs` (1125 -> 956)

Each suite imports `content_dir`, `gameplay_dir`, `gameplay_talk_body`,
`npc_record`, `select`/`interact`, `service`, `service_talk_body`, the
`GREETING_HEADER`/`MENU_HEADER` it uses, and (where it cites locale rows)
`lab_report`, `locale_id_to_text`, `locale_path`, `locale_rows`, `npc_position`,
`npc_records`, `read_json`. The local copies of those helpers, the local packet
builders and the local 26/3/26/9 constants are deleted. Every data table, quest
pin, blank control, refusal block and test function name is unchanged.

Suite-specific reductions that reuse the harness without changing assertions:

- `sanctuary`: `sanctuary_records()` -> `npc_records("sanctuary.json")`; the
  local `gameplay_talk_body(game, npc_id, position)` (an otherwise identical
  copy that took a pre-fetched position) -> the common
  `gameplay_talk_body(game, "sanctuary.json", npc_id)`. All 20 target rows are
  in `sanctuary.json`, so the file parameter is exact.
- `seaside_briarwood`: local `records(file)` -> `npc_records(file)`; the local
  `position()` copy (which additionally asserted a finite position) -> common
  `npc_position()` plus the same finite assertion in the suite's
  `assert_drawable`, so the finite-position check is preserved at every call.
- `job_hubs`: keeps one suite-local `locale_rows()` (CRLF index; proof below)
  and imports the common `locale_path()` for it. The local file already had no
  other helper after the migration.
- `tests/common/npc_greetings.rs`: +3 `#[allow(dead_code)]` attributes
  (`locale_path`, `locale_rows`, `greeting_bindings`) because different include
  sites use different subsets; the harness keeps its one behaviour. The module
  is not a test binary (it is only `#[path]`-included), unchanged convention.

`npc_greetings_highroad_farnum.rs` and `npc_greetings_merry_vale_stillwater.rs`
are untouched and stay green. No production source, content, `Cargo.toml`,
gateway, save or lead-only file changed.

## Job-hubs CRLF locale index (invariant 2 proof)

`en_us_data.dat` (raw bytes): 6,926,629 chars, 113,286 CRLF line endings and
**38 lone LF** line endings. Rust `str::lines()` counts every `\n` as a line;
`split("\r\n")` does not, so the two indexes diverge after the first lone LF.

Check over the exact `(hash, dat_line)` pairs each suite uses
(script `%TEMP%\T356\locale_rows_check.py`, outside the worktree):

| Suite | pairs | common `str::lines()` line == `dat_line` | `split("\r\n")` line == `dat_line` | same text |
|---|---|---|---|---|
| job_hubs | 20 | 0/20 | **20/20** | 20/20 |
| sanctuary | 20 | **20/20** | 2/20 | 20/20 |
| seaside_briarwood | 23 | **23/23** | 1/23 | 23/23 |
| merry_vale_stillwater | 17 | **17/17** | 1/17 | 17/17 |
| highroad_farnum | 7 | **7/7** | 0/7 | 7/7 |

Job-hubs deltas are `{12, 14, 16, 17, 21, 23, 33, 34, 36, 38}` lines. The
seaside count is 22 targets plus the deliberately wrong line in
`another_npcs_valid_locale_line_is_rejected`.

Conclusion: the rows resolve to the **same text** under either index, but
T299's `dat_line` pins are CRLF physical lines and the content `client` evidence
cites those numbers. Content is out of scope for this slice, so job_hubs keeps
its own CRLF lookup with a comment; editing the content evidence to the
`str::lines()` numbers would be a separate content change. The other four
suites' pins match the common `str::lines()` index exactly.
