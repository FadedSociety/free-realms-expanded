  id was resolved through `lab/reports/locale-id-map.json` (`hash_to_ids`), the

  `giver_npc_id` is the NPC and `intro_text_string_id` is a first-person offer

  attributes their first-person line directly. Raeya's line is the offer
  immediately before the Flickering Flames title and matches her campfire.

  strings that name him are a bear-keeper's third-person complaint and the
  "Return to Sam Durango" hand-in objective, neither of which is his own speech. He

## Client evidence (re-verified with IDA for T298)

- Handler `0x00aa12e0` (decompile) calls reader `sub_A9EF10` then display
  `sub_9F5AE0`.
- Reader `0x00a9ef10` stores the first payload dword at object `+16`
  (`*(this + 16) = *v3`) before the rest of the 26/3 fields.
- `0x009f5ae0` passes `*(_DWORD *)(a2 + 16)` to the Lua lookup `sub_97C1E0`
  immediately before `":SetDialogText"`; that is the first dword after the
  four-byte family/subtype header, matching `encode_dialogue_26_3`'s
  `initial_dwords[0]`.
- `gameplay/npc.rs::dialogue_packet_with` writes `context.body_string_id` into
  that dword; `patch_npc_actor` only overwrites bytes 12..20 with the runtime
  actor GUID. The 26/3 byte order is pinned by
  `tests/npc_interaction.rs::dialogue_26_3_synthetic_fixture_round_trips_exact_native_field_order`.

## Security threat note (secure-code-guardian)

- The hostile input on this path remains the existing 26/8 target GUID and the
  26/10 NPC GUID/option pair; none of it is new. The greeting id never comes
  from client bytes: it is a `u32` read from server content, so a client cannot
  inject text, choose a locale id, or trigger an allocation from an
  attacker-controlled size.
- A refused choice changes nothing: the test sends an out-of-range 26/10 choice
  and then selects Talk on the same still-open menu (no second `interact`), and
  gets the same empty body; an unknown NPC id is `UnknownNpc`. The service test
  is the same path the router calls; the router stages the menu clone and only
  the gateway commits a successful request.
- No save, coins, items, rewards, roles, chat, trade or position state is
  touched; this is static content read at load. Loader bounds (8 MiB/file,
  32 MiB total, 20,000 rows) are unchanged and asserted.
- `content_check.py` verifies every `greeting_string_id` resolves as a
  `Global.Text.<id>` in the stock client locale (a raw hash would warn); no
  HTML, path, player name or chat text enters the content (only the numeric id
  and provenance strings).

## Checklist

1. **A refusal changes nothing.** `a_zero_or_missing_greeting_falls_back_to_no_body`
   sends an invalid 26/10 choice, asserts `InvalidOption`, then selects Talk on
   the same menu without reopening it and gets the unchanged body; an unknown
   NPC id is refused. Canary zeroes a real greeting on production data and the
   26/3 test fails. No menu, counter, item or cooldown is consumed.
2. **Rollback covers all state.** No transaction, save or shared mutable state
   is added. The menu-clone staging in the router is existing; the service
   refusal test proves the open menu survives. No `Rc`/`RefCell`/`Arc` side
   table escapes.
3. **Apply deltas, never restore snapshots.** No payout, exit, inventory, coins
   or position logic is touched. N/A.
4. **Busy rules are mutual.** No new activity; `occupation.rs` untouched and
   `spine_rules` green.
5. **Every entry path is gated.** The body is read only by
   `dialogue_context`, which both the service and the real router call; the
   graph trace shows no other caller. Both paths are tested for all 19 rows.
6. **Reachable in production, tested through it.** `NpcVisibility::load`'s real
   35/2 packets are asserted for every edited row; the 26/3 test drives
   `Gameplay::handle_in_world` and the real `NpcInteraction`.
7. **Survives reconnect.** The greeting is static content, not per-character
   state; a fresh loader sends the same body (asserted in test 2). No save
   schema change.
8. **Every exit path restores the player.** No activity or exit path is added;
   dialogue open/close (26/4/26/6) is unchanged. N/A.
9. **Economy safety.** No items, coins, rewards or grants. The body is
   server content; invalid/unknown client selections are refused.
10. **Wire format matches the client reader.** Decompiled `0x00a9ef10` stores
    the first payload dword at `+16`; `0x009f5ae0` passes `*(a2+16)` to the Lua
    lookup before `:SetDialogText`; `encode_dialogue_26_3` writes
    `initial_dwords[0]` at bytes 4..8. The test asserts that dword for every
    row; the existing synthetic fixture pins the full byte order.
11. **Unique ids.** 19 distinct greeting ids asserted; the NPC ids are unique
    in the content test. No instance/GUID is created.
12. **Others see changes.** A greeting is a per-click dialog; nothing visible to
    other players (outfit, job, mount, spawn) changes. N/A.
13. **Content works end to end.** The body is actually emitted in 26/3 for all
    19 rows through the real router; the blank control emits 0.
14. **Values live in data.** The ids live in the NPC JSON, not compiled
    constants; `content_check.py` resolves them as `Global.Text` ids in the
    client locale. The test constants are pins, not production values.
15. **Canaries break production code.** The canary edited Fizzlesticks' content
    row, not the test; three test gates failed (the 26/3 body, the source gate
    and the exact greeted set); bytes restored.
16. **Hands off session plumbing.** The diff touches two data files, one new
    test and two new notes; no `osfr-gateway.rs`, `gateway.rs`, save or session
    ordering change.
17. **One player's error never stops the server.** No shared tick or
    cross-player code is touched; a hostile selection is refused per request
    and the greeting read is a plain `u32` copy.
18. **A type's rules live on the type.** The field's rule already lives on
    `NpcRecord.greeting_string_id` and `dialogue_context`'s comment ("NPCs
    without a recovered greeting stay empty"); the provenance rule is the
    existing `field_sources` gate in `tests/content_npcs.rs` (one source entry
    per top-level field). No new struct or inline special case.
19. **Hot paths stay cheap.** Zero per-tick cost: Talk copies one `u32` through
    `dialogue_context`; no allocation is added to the per-packet path. Load
    parses 19 small extra fields in the existing bounded JSON load.
