## What changed

- **BLOCKER 1 (damage tier, `encounter/power_up_use.rs`).** The damaging hit now indexes `damage_by_tier` with the active fight's battle tier: `EncounterEngine::battle_tier()` looks the active dungeon up in the loaded `field_battles` rows and uses `difficulty` clamped to 1..5; the overworld and the cave are tier 1. The multiplier applies once to the current basic (which already carries the job level's weapon scale). The review's suggested `self.dungeon().map_or(1, |d| d.difficulty...)` does not compile: the encounter `Dungeon` row has no `difficulty` (only the `FieldBattle` row that produced it does), so the lookup goes through `self.battles` by `d.id`.
- **BLOCKER 2 (`gameplay/jobs.rs`).** `restore_job` sends the toolbar with `ability_activation_for(job)` instead of `abilities.activation(...)`, so a derby return cannot hide a held kind. The `is_some()` guard described above stays.
- **BLOCKER 3 (duplication, `encounter/skills.rs` + `encounter/power_up_use.rs`).** The copied target/effect loop is gone. `encounter/skills.rs` now owns `living_enemies`, `area_targets` (nearest-first, capped, optional primary for a job ability's selected target), `apply_dot`, `apply_stun` and `apply_caster_buff`, and both `job_ability` and `use_power_up` call them. The only differences left are the power-up's no-target/no-energy/no-cooldown flow, its battle tier, and the Super Shield buff + HUD tag.
- **BLOCKER-class 4 (shield rule).** The shared `apply_dot`/`apply_stun` check `!self.shielded(guid)`, so the Troll Summoner cannot be burned or stunned while its minions stand. `tests/power_up_use.rs` asserts both.
- **BLOCKER 5 (hub structure).** The per-tick held comparison and resend moved into `Gameplay::refresh_power_up_slot` in `gameplay/power_up_use.rs`; `tick_world` keeps the pre-tick snapshot and one dispatch call.
- **MINOR 6 (interest).** `handle_shared_field` restricts the shared field to the sender's known set around the power-up call (only for slot `power_ups::SLOT` while a kind is actually held) and restores presence on success and on `Err`, so an unseen enemy is neither damaged nor leaked and a normal job-bar action keeps its old single restriction pass.
- **MINOR 7 (tests).** Added gateway-path tests for: level-15 overworld damage, difficulty-5 tier damage, Earth Shard stun + expiry, Super Shield window + expiry in the shared field and in an instance, the shielded summoner (stun and burn), the shared-field interest exclusion, the derby return, and the pre-existing six. The field-battle tests use the real client route: 26/8 marker -> 41/114 start screen -> 41/108 Go -> `initialize_world` zone-ready.
- **MINOR 8/9 (notes).** `notes/Research/Power-up Use Key.md` now states the dispatcher's `SLOBYTE(v64)` alternate-bar flag and modes 1/2 (mode 0 was wrong); the T222 rule and line-ending claims are corrected in `notes/Autopilot/T222.md`.

## (R) reconstructed rules

- The battle tier is the active field battle's `difficulty` (1..5); the overworld and the opening cave have no recovered battle difficulty and count as tier 1. Power-up damage = current basic x `damage_by_tier[tier]`, applied once. The authored `damage_by_tier` is the final-era x1.75 curve; the current basic already includes the job-level weapon scale.
- Burn damage remains `current basic x burn.multiplier` (the authored relationship to the base, as for a job ability); it is not multiplied by the battle tier in either path.
- The held kind stays session-only (W158): never saved, cleared by a reconnect, never tradable or duplicable. The T222 slot/definition design is unchanged.
- The derby package in the tests is synthetic (same rules as `tests/derby_route.rs`); its values are reconstructed test policy, not recovered server data.

## Security threat note (secure-code-guardian)

What a hostile client can send at the changed paths, and why it is refused or harmless:

- **A forged kind, tier, multiplier or quantity:** impossible. The request remains `36/10` bar 1 slot 2; the kind comes from the server-owned held state, the tier from server-loaded `field_battles.json`, and every magnitude from `power_ups.json`. The new `battle_tier` reads content, not client bytes, and is bounded to five entries by the clamp/index.
- **A forged target or ground position:** still ignored; the effect is centred on the server's own player position. `abilities::unsupported_cast` rejects the 32-byte ground modes before this code, and the shared action parser validates the 24/32 shapes first.
- **A replay or burst:** the kind is consumed before any effect; repeat requests fall through to the job slot and fail closed. The tests cover the repeat and the knocked-out refusal with exact state equality.
- **Shared-field reach:** `handle_shared_field` now applies `restrict_to(known)` for the power-up action exactly as for a job ability, and `restore_presence` runs before an error propagates. A hostile or merely stale interest set can therefore not make the server damage an enemy the sender was never told about; the regression test asserts the target's health is unchanged.
- **Derby return:** the bar is server-built from the held state; no client data enters it. The NPC menu, staging and busy gates are unchanged.
- **Economy/persistence:** no coins, items, rewards or saves are touched; the held kind has no trade/drop/bag path. The tests use only server-rolled drops from killing a server-spawned enemy.
- **Failure isolation:** the new code runs inside the per-session staged `Gameplay`; a refusal or error is returned, never ignored. No session/transport/role code was touched.

## Open gaps

- The tier-5 damage test enters a real bundled `field_battles.json` row in its own fixture with the level floor patched to 0 and prizes stripped; the real client route (marker -> 41/114 -> 41/108) is used, but a level-1 character entering a difficulty-5 arena is a test-only condition.
- The 2014 client's overworld power-up damage tier is still unrecovered; overworld/cave = tier 1 is (R), and the final-era x1.75 curve is the existing reconstruction.
- **Tier-multiplier reading.** The review's "in a difficulty-5 dungeon it is 88x instead of 9.38x" can be read two ways. The code follows the review's literal fix instruction: the battle tier indexes `damage_by_tier`, and one multiplier applies to the current basic, which already carries the job-level weapon scale. A level-15 Brawler in a tier-5 fight therefore deals 938 x 9.38; a level-1 Brawler deals 100 x 9.38; the level-15 overworld deals 938 x 1.0. No test pins the level-15/tier-5 combination. If the intended rule is instead that the battle-tier curve is a floor (the higher of the player's weapon tier and the fight tier wins), the formula becomes `max(level scale, damage_by_tier[tier])` and needs a new pin; that is a design call, not a compile or test fix, so it is left to the lead.
- Super Shield's `speed_pct` remains display-only (no server movement-speed model); the invulnerability is the existing `taken = 0.0` mitigation fold.
- A held kind is still lost on reconnect by design (W158). Persisting it would need a save-schema decision.
- The synthetic derby package is duplicated between `tests/derby_route.rs` and `tests/power_up_use.rs`; a shared test-only module would cut ~50 lines but adds cross-test coupling, so it was left alone.
