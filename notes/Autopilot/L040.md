## Open

- **Stacking (L031 behaviour, kept per the brief).** Pickup returns a unit through
  `grant_with_tint`, which merges equal units: picking up two kit blocks (or Pick Up All) leaves a
  stack of 2+ blocks, and place refuses a stack (`StackedInstanceUnsupported`). The first block
  picked up places again (tested). The client's Move is pickup + 127/1 + 127/2 (build guide step
  5), so moving blocks one at a time works, but a second pickup before re-placing blocks
  decorating with those blocks. Fix needs a lead call: stack-aware place, or unstacked returns.
- **Counter-less saves, general case (pre-existing).** `Inventory::consume` does not set
  `next_instance_id`, so on a save with no counter an ordinary later grant can reuse a placed
  fixture's id; the reload then refuses the save (`PlacedInstanceStillOwned`). The kit itself is
  floored above the lots' ids and sets the counter, but the general gap is in inventory/place.
- The Chicken is tradeable (70429 NO_TRADE 0 per L031's notes); alts can funnel free Chickens to
  a main, worth 0 coins at any vendor. Decor only; not changed.
- Native: during the tutorial the tray shows the Chicken first; the blocks stand in the Condo;
  they can be moved; untextured or misplaced blocks would mean the spawn-height y is wrong.
- Characters already holding the Condo from L030/L031 playtests keep their 7466 block and get no
  kit (the kit rides only a new lot grant). Use a new character.
- Graph: the codebase-memory index of `autopilot-int` predates L031 (no `request_grant`), so
  callers were found with `rg`.

## Security

Trust boundaries (secure-code-guardian, security-reviewer):

- **127/23 (hostile client, empty body).** Nothing the client sends reaches the kit: items,
  count, positions and ids come from validated content and the server's own inventory counter.
  A repeat ask, a replay or a flood grants nothing: the kit rides only a newly granted lot
  (`granted`, decided on the saved lots keyed by owner and property), so it is once per
  character (tested; canary 1). 127/23 is latched once per client session by the client.
- **Refusals change nothing.** The service stages a clone (lot, standing fixtures), the bag
  changes last through `grant_kit`, which validates the whole bag before committing, and
  `Gameplay::handle_housing` stages the session and inventory again and drops both on any `Err`.
  A full bag refuses the whole grant with the existing fixed chat text and the save stays
  byte-equal; a retry after freeing a row grants the kit (tested; canaries 2b, 3).
- **Ids.** Kit ids are at or above the bag's counter (no live row, nothing handed out before),
  above every id this character's lots hold, strictly ascending, and the counter moves past the
  last one, so the next grant cannot reuse a standing block's id. A collision would make the save
  unloadable (`PlacedInstanceStillOwned`), so each rule has a canary (5, 6, 7, 8) and the
  reload is asserted. Arithmetic is checked (`checked_add`, `try_from`, `adopt_state`'s range).
- **Economy.** Free issuance resells for 0 at the Coin Shop sale and is advertised as 0 in the
  66/42 window (tested through the gateway; canaries 10, 11). Buy-back of a 0-coin sale costs
  0, so selling and buying back gains nothing. The Chicken arrives as its own count-1 row (never
  merged into a bought Chicken; canary 4).
- **No new oracle, no logs.** The refusal text is the existing fixed literal; it echoes no id.
  Nothing new is logged. No secrets, player names or chat text in code, tests or notes.
- **Saves.** Unchanged path: lots and bag are one `GameplayState` document written atomically by
  the existing `character_store::replace_bytes`; the reload re-runs the conservation check
  (tested after a grant, a pickup and on a counter-less save). No new file write.
- **Content.** `houses.json` is operator content: positions must be inside the starter lot's
  build area and at most 16 (and at most `max_fixtures`), ids positive, both items with fixture
  rows, or the content fails at load (canary 9). The coin shop parses the same file through the
  same bounded `HousingContent::load` (1 MiB cap).
