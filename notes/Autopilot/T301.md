## Security threat note (secure-code-guardian)

Attack surface: a hostile client can send arbitrary 26/8, 26/10, 26/6, 26/13, 49/2,
49/14, 45/7, 39/x and 50/1 bodies, choose a target GUID, position and timing, and replay
any of them. The suite asserts the rewarded outcome comes only from server state:

- **Turn-in authority.** 49/14 pays only when `QuestState.pending_turnin == quest_id`;
  the pending value is set only by the server's own completion Talk (`on_event` ready +
  giver), the reward amount/item/profile come from the saved quest definition, and
  `rewards::apply_grant` is keyed `quest:<character_id>:<quest_id>`. Premature, wrong
  quest, wrong NPC, repeated and post-relog replays were all asserted to change no byte.
- **Kill authority.** Quest credit is `QuestEvent::KillActorKind` emitted by
  `apply_encounter` from `EncounterOutcome.defeated`, which the engine fills only on its
  own alive-to-dead HP transition for a positive production definition. A forged target
  GUID, an out-of-range attack, a zero definition and a client claim (45/7) advanced no
  counter; a forged 39/18/39/14 and a forged 50/1 bundle did nothing.
- **Economy.** Coins, item and job XP are granted only by `finish_turnin` ->
  `apply_grant`, which uses checked arithmetic and the production bag capacity. The
  full-bag case is refused atomically (no coins/XP/item, pending kept, state and save
  bytes equal). The reward item exists in the real inventory catalogue and is not
  already owned, so the +1 assertion is about a real new stack; a replay cannot
  double-pay.
- **Refusals.** Every refusal path in tests 2/3/4/7 is asserted to change the whole
  `GameplayState` and its serialized bytes; a refusal `Err` is only accepted when it is
  `InvalidData`, never a panic or a partial write. No `unwrap` is applied to
  client-controlled data in production by this task (no production change).
- **No dev command.** The suite's local packets are checked not to be chat requests
  (family 15), and the fresh character cannot run any developer command
  (`Gameplay::may_run` false for offer/teleport/here/broadcast/cheat/give/npx).

## Checklist

1. **A refusal changes nothing.** Tests 2/3/4/7 snapshot the whole `GameplayState`, its
   `saved()` bytes and (where relevant) a real `game_store` file before each forged/
   premature/full-bag/out-of-range/zero-definition refusal, then assert equality. Canary
   A shows the kill-credit assertion bites; canary B shows the save/reload dependency
   bites. The full-bag refusal is the production `apply_grant` error; the pending screen
   and all pending values stay.
2. **Rollback covers all state.** The production turn-in stages `QuestEngine` + inventory
   + profiles on clones (`finish_turnin` on a cloned engine and `next_state`) and only
   assigns after success; the test asserts all of those fields plus the serialized bytes.
   No shared side table or `Rc`/`RefCell`/`Arc` escape was added (test-only change).
3. **Apply deltas, never restore old snapshots.** Test 1 compares the turn-in against the
   live post-kill state (which already includes the field reward and the Archer switch),
   not an entry snapshot; the assertions are exact deltas, and the relog asserts the
   saved values. Nothing restores a captured inventory, coin or position.
4. **Busy rules are mutual.** No new activity or `Occupation` row; test 6 proves the
   character is free after the turn-in by accepting the next quest through the ordinary
   menu, which the shared busy gate would refuse if any other activity were running.
5. **Every entry path is gated.** The suite drives the only production accept/turn-in/
   kill entries (`handle_in_world`, `handle_shared_field`) and adds no parallel path or
   bypass. The offer still runs the NPC/giver/range/eligibility checks; the attack still
   runs the profile/weapon/zone/range/cooldown checks.
6. **Reachable in production, tested through it.** Gateway -> `Gameplay::handle_in_world`
   / `handle_shared_field` -> gameplay/NPC/quest/encounter modules. No internal reward
   helper is called; the 49/1 offer is decoded with the production reader. The shared
   field request is the same parsed 36/10 `SharedFieldAction` `commit_outcome` runs.
7. **Survives reconnect.** The accepted quest, objective counter and pending turn-in live
   in `GameplayState.npc_quests`; tests 1 and 5 save through `game_store` and reload
   through the real loader/bind, asserting Completed/counter/coins/XP/item and the pending
   turn-in across two reconnect points. A replay after the relog pays nothing.
8. **Every exit path restores the player.** The turn-in clears `pending_turnin`; test 6
   asserts no pending offer/turn-in, no encounter/mount/soccer/derby, a finite zone-0
   supported position, and a usable NPC menu for the next quest. No new exit path was
   added.

   by `finish_turnin`; the field reward is the existing 2 coins/5 XP table. A repeated
