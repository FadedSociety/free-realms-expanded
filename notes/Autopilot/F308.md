## Canaries

All three break production code and fail the new test at the expected line.

1. **Save path drift** (the review's failure scenario): replaced
   `npc_quests: self.npc_quest_state()` in `Gameplay::state` with
   `self.saved_npc_quests.clone()`. `cargo test --lib
   the_save_and_a_live_rebind_read_the_same_bound_quest_state` **failed** at
   `src/gameplay/w64_regional_quest_tests.rs:168` with `the save took the stale
   saved copy instead of the bound engine` (left empty state, right offered
   quest 3000021; exit 101). Restored `gameplay.rs` byte-identically (SHA-256
   `D98BD4AC780E20894E0F52749B04CC37CBD5041067289A2598788D8195750C7D`).
2. **Helper precedence**: swapped `npc_quest_state` to saved-copy first. The
   same test **failed** at `w64_regional_quest_tests.rs:167` (left empty state,
   right offered quest; exit 101). Restored `npc_quests.rs` byte-identically
   (SHA-256
   `10455B96BE5D6CF9C1B9206BDC338E05602966F6DCAC562A87FC3E6359F89DC7`).
3. **Bind path drift**: re-inlined `let state = self.saved_npc_quests.clone();`
   in `bind_npc_quest_catalogue`. The same test **failed** at
   `w64_regional_quest_tests.rs:175` with `a live rebind rebuilt from the stale
   saved copy` (exit 101). Restored to the same SHA-256.

After each restore the new test was re-run and passed. Note for reproduction:
restoring a backup with `Copy-Item` keeps the older mtime, cargo does not
rebuild, and the stale test binary fails again; forcing `LastWriteTime` after
the byte-identical restore fixed it (same trap F295 recorded).

## Security threat note (secure-code-guardian)

What a hostile client could send, and why it is refused:

- Nothing new is client-triggered. `bind_npc_quest_catalogue` is called from
  `Gateway::load_gameplay` with the server-selected content directory (graph:
  the only production caller); a client cannot choose content or invoke a
  rebind. `Gameplay::state` is a server-side read used when saving.
- The new method only selects which server-owned state is cloned: the bound
  engine first, the saved copy only when no engine is bound. It reads no client
  field, quantity, id, coin or reward.
- A hostile save still cannot inject quest state past validation:
  `from_split_content` runs `validate_state` (version, character id, quest
  count, statuses, counters, pending offer/turnin consistency) and returns
  `Err` before any field write. The wizard/shared-field refusal tests still
  assert full save-byte equality around a refused bind.
- Refusals consume nothing: no menu, pending offer, attempt counter, item or
  cooldown is touched on this path. The bind still runs both fallible loads
  before any write.
