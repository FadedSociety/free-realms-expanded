# F165 Fix the F130 review blockers (commit `12f155d`)

Review: `lab/autopilot/reviews/12f155d-F130.md`. Both BLOCKERs were real and are fixed
in the bundle gate, with one negative regression per reviewed mutation. No Rust
module, hub file or content file changed.

## Changes

- `scripts/bundle/bundle_common.py`
  - `_f32_bytes` now normalizes every conversion failure to `ValueError`: a
    finite Python float outside the `f32` range makes `struct.pack("<f", ...)`
    raise `OverflowError`, an integer past the double range makes
    `math.isfinite` raise `OverflowError`, and an oversized integer float
    conversion raises `struct.error`. Previously `context.scene.rotation[0] =
    1e100` was only `math.isfinite`-checked, passed the gate, and then
    `zone_transition::encode` (called by `KartGateway::load`) refused the
    non-finite `f32`, stopping server startup.
  - `check_activity_content` now runs the position, the rotation and
    `update_radius` through that one conversion. The radius is the third `f32`
    in the same `ZoneTransition` that `encode` checks, so it belongs to the same
    root cause.
  - `_is_shape_code` and `_check_board_shape` mirror `mining::validate_spec`
    (`src/mining.rs:1196-1273`), the validator every startup board passes
    through `Type8Engine::load`: the recovered `ServerGrid.buildMap` grammar,
    at least one playable cell, a >=6x6 full rectangular playable area, and a
    complete dropzone row with no stray `4` cells. An all-zero shape now fails
    with "no playable tiles".
  - `_check_board` requires every `spec.tiles` row to be an object carrying
    `value: u16`, `category: u16` and `icon_id: i32`, the fields `Type8Kind`
    deserialization needs. `spec.tiles = [{}]` now fails instead of passing on
    the array-type check alone.
- `tests/test_bundle_activity_content.py` adds
  `test_reviewed_scene_and_board_mutations_are_refused`: rotation `1e100`,
  shape code `7`, an all-zero shape, a broken dropzone row and `tiles: [{}]`.
  Each refusal asserts the mutated file's bytes are unchanged afterwards.

## Security note (secure-code-guardian)

- Attack surface: the gate reads bundle JSON that becomes server-startup content.
  A hostile or corrupted package controls scene floats, board shape codes, tile
  rows and reward output mappings. Before this diff it could publish a rotation
  or shape/tile document that the server refuses to load, which is a
  startup-denial and a gate-integrity bypass.
- Why it is refused now: rotation/position/radius must round-trip through the
  same finite-`f32` conversion the Rust encoder applies; shape codes must be
  values the shared engine can spawn; the playable rectangle and dropzone row
  must be full; tile rows must carry the loader-required fields and widths.
  Refusals raise `ValueError` before the file is copied into a bundle; the gate
  never writes content, and each test snapshots the file bytes to prove a
  refusal changed nothing.
- This is build-time validation, not a network trust boundary. No client id,
  quantity, score or payout is trusted by this diff, and the in-game Mining
  payout still derives grants from server-verified board state. No secrets,
  auth, session or dependency changes.
