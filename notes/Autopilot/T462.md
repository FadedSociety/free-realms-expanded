# T462: World events, part 3: wall-clock slots

Parts 1 and 2 (T458, T460) are on the tip, so the brief's prerequisites hold; the fleet research pack
(it said they were missing) was stale. No client packet is new: the kickoff line is the part-2 `broadcast`
packet (`chat::system`, 15/3, as T199), so no IDA trace was needed.

## What changed

- An event row in `world_events.json` may carry `schedule {slot_minutes 5..=1440, offset_minutes 0..slot,
  season?, announce_lead_ms?, announce {text, locale_id}?, skip_if_slot_matches [keys]}` (`world_events/schedule.rs`).
  The lead and the line come together, the lead is under one slot, and an event cannot skip itself.
- The world tick (`WorldEvents::tick`) now first runs `run_schedule`: one comparison of the wall clock with
  `wake_ms` (the earliest due time of any entry), and nothing else while idle. A due entry either sends its
  kickoff line to the sessions in the event's zone instance, or starts the event with the same `begin` an
  admin start uses. A start for a key that is already running changes nothing (skipped, never queued).
- `world_events::load_scheduled(dir)` reads the scheduled events, one row at a time: a broken row is logged
  and left out, so it never stops another event's schedule. `load` is the strict whole-file loader as before
  (the file is now parsed to rows first, so an error message no longer carries a line and column).
- The gateway host reads the schedule once at startup (`world_event_routing::schedule`, called after
  `client_areas` loads) and passes the wall clock into `world_event_routing::tick`.
- `ClientAreas::utc_offset_minutes()` exposes the offset local time uses.
- Admin `event start|stop` and the part-1 and part-2 behaviour are untouched.

## (R) choices

- Local time is unix time plus the one `utc_offset_minutes` of `client_areas.json`: no daylight saving.
  Sanctuary reads the host's local clock (`EventSchedule.lua`); the offset is the brief's choice.
- Slots restart at local midnight: a slot starts at each minute-of-day where `(minute - offset)` divides by
  `slot_minutes`; a slot size that does not divide 1440 has a short last slot.
- The season gate is judged at the slot's start, so a slot that opens after the season ends neither starts
  nor announces.
- An overlap skip is plain slot arithmetic against the named events' slots (the other event's season, offset
  and run state do not count). A skip naming an event without a schedule leaves that event unscheduled, logged.
- A clock jump forward starts only the latest slot at or before now, and only if that slot runs: when the
  latest slot is a skipped one, the earlier due slots are not run late. The line of a slot is sent only if
  its moment is still ahead when the slot is chosen (a restart or jump inside the lead announces nothing).
- Nothing is saved. At startup the first slot is the first one strictly after the clock, so a slot that fell
  while down is never run late.
- The schedule is read at startup only (an edit to a schedule needs a restart). A search for the next
  running slot looks at most 4096 slots (a closed season costs one step per day, ~11 years); if none runs
  the entry stays dormant and one log line says so.

## Structure

- Graph queries: none (the codebase-memory index is not available to this worker); used `rg` over
  `world_events`, `client_areas`, `begin`, `tick` and the gateway call sites.
- Owner: `src/world_events.rs` (schedule field, loader, `schedule`, `run_schedule`); the slot rules are a new
  focused child module `src/world_events/schedule.rs` (slot math, entry state, tests).
- Gateway glue: `world_event_routing.rs` (+~20), `osfr-gateway.rs` (+1 line, one changed line; ceiling 4659,
  file 4626), `t458_world_events.rs` (rig `tick_at`, one test).
- Cost per tick: with nothing scheduled one `is_empty`; with entries one integer comparison until a moment is
  due. A due moment costs O(1) slot arithmetic per entry (plus the skip checks) and one `Arc` clone on a start.
- Deleted: nothing dead; `WorldEvents::begin` now takes the `Arc<WorldEvent>` so a start does not copy an event.

## Threat note

Nothing here parses client input: the schedule comes from the operator's content file, bounded at load
(slot 5-1440, offset < slot, line <= 256 bytes with no control characters, <= 8 skip keys, season <= 64 bytes),
and the file keeps its 1 MiB cap. A hostile client cannot trigger a start or a line. All clock arithmetic is
`i64` with `checked_*` or `rem_euclid`/`div_euclid`; a clock at either end returns no slot instead of
panicking (test).

## Checklist

1. Refusals change nothing: a start for a running key returns false before touching state (test: the serial
   and the run do not move). A broken or dangling row never alters the other entries (test).
2. Rollback covers all state: the schedule is only in-memory entries beside `runs`; no shared cells.
3. Deltas: not applicable (no inventory, coins or position).
4. Busy rules: not applicable (no player activity).
5. Entry paths: the schedule starts through the same `begin` as an admin start; the admin path is unchanged.
6. Reachable in production: tested through `Server::new` and `world_event_routing::tick`.
7. Reconnect: not applicable; a run is in memory only, as in part 1.
8. Exit paths: not applicable to players; a stop or end removes actors as in part 1.
9. Economy: not applicable.
10. Wire format: no new packet; the line is part 2's 15/3 (`chat::system`), golden-tested in part 2.
11. Unique ids: a scheduled run takes the same wrap-safe serial as an admin run.
12. Others see changes: the line goes to every session in the zone instance; actors use part 1's visibility.
13. Content works end to end: the gateway test asserts the line, then the AddNpc, then no repeat.
14. Values live in data: slot, offset, season, lead, line and skips are all in the file; the 4096-slot search
    bound and the bounds above are sanity limits.
15. Canary breaks production code (the season check), see above.
16. Session plumbing untouched.
17. One failure never stops the tick: no `?` in `run_schedule`; a failed start is a no-op; one bad row is
    dropped at load.
18. A type's rules live on the type: `Entry` owns when it wakes, announces and starts.
19. Hot path: see "Cost per tick".
