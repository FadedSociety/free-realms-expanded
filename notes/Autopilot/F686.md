## Threat note (secure-code-guardian)

- New surface: none. The press path (42/6 bind, 36/10 cast, 42/16 info) and all its refusals are
  unchanged; the changed code runs inside `Boomboxes::tick` off server state.
- A hostile client can only move its own pose in/out of range. That can start/stop its own dance;
  clip ids, lengths, song effects, models and bounds all come from the server catalogue row, and
  every packet is built from server data.
- The new single-entry shape removes the only count that could ever have been driven by another
  player: each independent 35/63 has exactly one entry, and the count written is the literal 1.
  No client-supplied length or id reaches a packet.
- Content is bound-checked at load (64 rows, 256 KiB, <=256 clips/model, positive unique animation
  ids, ms 1..=600000, kind/shape agreement); a bad row is refused before any state exists and
  leaves an empty catalogue, never a panic. The two new refusal cases change nothing (pure load).
- The RNG remains visual variation only and is not a security boundary (OS-seeded SplitMix64; the
  seed is 0 if the OS read fails).
- No new `fs::write`, no hex formatting outside `trace.rs`, no raw activity-state reads. The `Arc`
  shares an immutable table only.
