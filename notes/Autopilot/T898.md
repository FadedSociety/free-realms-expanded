# T898: name the unresolved quest givers

The census found 134 `npcs_unresolved.json` slots as the giver of 199 hollow quest records (29% of the
server's 689). This pass names the giver wherever the evidence does, repoints the quest records to the NPC
row, and records the evidence tried on every slot a quest still points at.

## What changed

- `data/content/quests/*.json`: `giver_npc_id` edited in place on 100 records (13 files, only that line),
  from an `npcs_unresolved` slot to the census row id. 56 of the 134 slots resolved.
- `data/content/npcs_unresolved.json`: each of the 134 slots a quest used gained a `resolution` object
  `{npc_id, basis}`. `npc_id` is the row the giver was named as, or `null` with the evidence tried in `basis`.
  The 170 slot rows stay in the file (`tests/content_npcs.rs` pins 295 resolved and 170 unresolved
  references, and `jobs.json` trainer ids still use some slots), so no alias or count moved.
- `tests/quest_giver_resolution.rs` (new, 2 tests): a resolved slot names a real `npcs/*.json` row and no
  quest still names the slot; a quest whose giver is still a slot has a `resolution` with `npc_id: null`
  and a non-empty `basis`.
- `tests/zone_quests_wilds_part2.rs`: `the_other_wilds_rows_stay_off_with_a_blocker` pinned five Soccer
  Star quests as "giver has no drawn row". Coach Eddie (9000000053) is drawn (T665), and those quests named
  his unresolved slots, so the pin is now "giver is drawn, and the quest still has no objectives" (same test
  name, the constant is renamed `NO_OBJECTIVES`).

- `tests/warrior_entry_chain.rs` `the_two_spawns_and_quests_load_with_real_targets` pinned the Warrior records
  3150002 and 3150003 to the unresolved Dewey slot 9000000302 ("fields the generated content already carried").
  The whole suite caught it. The test keeps its name; the expected giver is now Drill Sergeant Dewey's row
  9000000076 (client npc_name 22435 on the quest-lines answer). No test was deleted or renamed.
