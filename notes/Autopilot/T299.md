  `en_us_data.dat` line. All 20 ids resolve; no locale overlay is needed. The

- Speaker proof used the T246 rules: (a) the line is first-person speech and a
  quest record binds the NPC as `giver_npc_id` and the line as the 49/1
  `intro_text_string_id`; (b) the job/region guide names the NPC and quotes the
  first-person line; or (c) the region guide's quest row quotes a first-person
  offer and the NPC row lists that quest under the NPC. Third-person referrals
  were rejected (for example Smitty's row hash 2618187357 -> 414616 is the
  guide's location sentence, and 717007106 -> 93195 is Mayor Crystalline's Key
  to the City reward line naming Smitty in the third person; neither is used).
- Reachability: 17 targets are `legacy_data` rows the visibility loader spawns.
  Dewey, Morninglory and Steele are `poi_anchor` rows with no model of their
  own, but T201/T257 added `npc_spawns_extra.json` actors whose
  `spawn_guid` and `content_key` are the row key (9000000076 / 9000000155 /
  9000000208) and whose model/name ids are positive. The production
  `NpcVisibility::load` resolves all three actor GUIDs to the same row
  (`content_key(id) == Some(id)`), and the 26/3 test proves the body. Without
  that proof they would have been left blank. Therin remains `poi_anchor` with
  no extra spawn and stays blank.
- The camp recruits Bollylog, Hrugagu and Brugadug are `unanchored` with no
  model or position, so they are not spawned and were not bound (the brief
  forbids binding a row that is not drawable, and this slice adds no spawn).
- Identity is the `npc_id`, never the name. The only duplicate name here is
  "Dewey": the drawable Warrior row 9000000076 is bound, while the unresolved
  key 9000000302 in `npcs_unresolved.json` (which the Warrior quest record
  3150003 points at) is not.

## Method and (R) rules

1. One greeting per NPC, chosen because the line's speaker is proven, not
   because it is nearby.
2. The 13 quest-record rows use the quest's 49/1 `intro_text_string_id`
   (Blacksmith 3020002/3020007/3020014/3020015, Miner 3100004/3100017, Archer
   3010003/3010007, Warrior 3150005, Wizard 3160016, Ninja 3110023, Card
   Duelist 3040037, Adventurer 3000024). The intro binding itself is
   reconstructed content (`scripts/quest_text_backfill.py`), so the speaker link
   is inferred from the quest record's `giver_npc_id` and the guide's row.
3. Dewey's link is the Warrior guide's quoted newcomer pitch (the guide marks
   its wording match with a dagger). Morninglory's link is the Warrior guide's
   explicit W3 attribution; note the quest record 3150003 binds the same intro
   to the unresolved key 9000000302 ("Dewey" in `npcs_unresolved.json`), which
   is a data inconsistency, not a second speaker.
4. Glugmort, Burnetta and the three counselors have no quest records in
   `data/content/quests`; their proof is the region guide's NPC row plus the
   quoted first-person quest row.
5. `(R)` every row uses one recovered speaker line as the fixed default Talk
   greeting; the original server greeting/phase table is not recovered, so a
   quest phase does not change the first-click body and no text is invented.
6. `(R)` Dewey/Morninglory/Steele reachability relies on the T201/T257 extra
   spawns keeping `spawn_guid == content_key == row npc_id`; the test pins that.

## Client evidence (IDA, read-only broker)

- 26/3 handler `0x00aa12e0` calls reader `sub_A9EF10` and then display
  `sub_9F5AE0` (decompile confirmed both calls).
- Reader `0x00a9ef10` stores the first payload dword at the object `+16`
  (`*(_DWORD *)(this + 16) = *v3`) and advances the cursor by 4.
- Display `0x009f5ae0` passes `*(_DWORD *)(a2 + 16)` to the locale lookup
  `sub_97C1E0` immediately before `:SetDialogText`; the body is the first dword
  after the four-byte family/subtype header, matching
  `encode_dialogue_26_3`'s `initial_dwords[0]`.
- No wire field was added or changed. The 26/3 byte layout stays pinned by
  `tests/npc_interaction.rs::dialogue_26_3_synthetic_fixture_round_trips_exact_native_field_order`.

## Security threat note (secure-code-guardian)

- This slice changes no parser, save, coin, item, reward, role, chat or trade
  code. The only new values are static server-side `u32` locale ids and their
  evidence strings; the client never supplies a locale id.
- Hostile client input on the path is the existing 26/8 target GUID and the
  26/10 NPC GUID/option pair. The router resolves the GUID through
  `NpcVisibility::content_key`, requires an open menu for that exact NPC key,
  and rejects an unknown GUID (no menu) or an out-of-list option
  (`InvalidOption`). The test asserts a refused `i32::MAX` option does not
  consume the menu and the next Talk still returns the recovered body.
- The greeting is a server content id; no player name, chat text, HTML, path
  or arbitrary locale id is introduced. The source gate requires
  `Global.Text.<id>`, recomputes the Jenkins hash and finds it on the cited
  `en_us_data.dat` line, so a raw hash (which would render blank) fails the
  test.
- Loader bounds (8 MiB/file, 32 MiB total, 20,000 rows) are unchanged and
  asserted. All 20 ids resolve in the stock client locale, so no overlay or
  fallback path is introduced. No per-player state and no new entry path.
