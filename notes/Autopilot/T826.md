# T826: fixture guids the client can act on (native 2026-10-27, after T806)

## Why
Native 2026-10-27 15:04Z (T806 merged): the Condo draws its fixtures through their 35/2 actors, decorate mode opens and
selecting a fixture opens the radial menu (Up, Rotate Left, Remove, Rotate Right). Clicking its options froze the whole client and
the client sent no 127 packet. The client then exited by itself with 0xC0000005 (`client_exit_code` 3221225477) 87.9 s into the
run, 32 s after its last application packet, having sent SOE session disconnects at 70.7 s and 87.8 s.

## Root cause
Every radial action reached the client's housing code as fixture guid 0, and Rotate with guid 0 reads through a null edit object.

- The menu is Lua: `Housing:OnRadialMenuClick` calls `House.PickupFixture`, `MoveFixture`, `MoveFixtureVertically`,
  `RotateFixtureClockwise` or `RotateFixtureCounterClockwise` with `currentItemGuid`, which
  `BaseClient_Housing_Instance_SelectedFixture_OnDataUpdate` reads from `ds:GetData(0, 0)` (client UI Lua, `ScriptsBase.lua`).
- The data source prints the guid with `%lld`: `SelectedFixtureDataSource::GetValue` (`00cbd700`) calls `sub_82ECD0` with the wide
  format at `01817394`, `%lld`; "-1" is its none value. A fixture guid with bit 63 set prints as a negative decimal.
- Each of those bindings (`00c0c000`, `00c0c050`, `00c0bfb0`, `00c0c0f0`, ...) reads its argument with `sub_BFEA90` (`00bfea90`),
  which returns 0 when the string starts with `-` (0x2d). Our minted fixture guids had top byte `ff` (`FIXTURE_GUID_MASK`
  `0xff00...`), so all of them printed negative. Retail fixture guids are `07f5...` (positive).
- The radial menu still opened because selection goes by actor: `sub_AB5910` finds the fixture through the NPC-guid index
  (`sub_105C8C0`) and the definition list, never through the printed guid; `IsActionPermitted` (`sub_AB5AF0`) answers yes
  for an unknown guid, so the menu offered everything.
- With guid 0, `sub_105BFA0(0, 0)` finds no fixture. Rotate (`sub_AB1E30`) then reaches `00ab20f4`: the edit object
  `[this+0x40bc]` is 0, `sub_AAB230` (`00aab230`) builds none (no fixture, so no entity lookup), and `00ab2112`/`00ab2118` read
  `[0 + 0x16c]`: an access violation. (R: the stall is the client's exception path; the trace shows the 32 s gap, the two
  disconnects and the exit code, not the faulting address, which is read from the code.) Move (`sub_AB0D60`) and Up (`sub_AB2250`) are null-safe and do nothing for guid 0; Remove (`sub_AC42D0`) sends a 127/3
  for guid 0. So no 127 left the client, as traced (`frames/`: the last c2s housing packets are the 127/6 toggles).
- Ruled out, with the trace and the client: the pre-T806 saved rotation `[1, 0, 0, 0]` (a finite angle; the rotate math runs on
  it without a loop); an actor the client cannot pair back (selection pairs it; the 26/19 clicks and the radial menu both resolved
  the actor); the definition list (the 127/40s push the definitions `sub_1070770` looks up); the retail p2.pcap records, which have
  the same fields as ours.
- Timeline from the client's own `ime.log`: six clicks on the radial menu (09:05:03 to 09:05:05 local), then no more input events;
  the last application packet left at 55.7 s.

## Change
- `src/housing.rs`: `FIXTURE_GUID_MASK` is `0x7f00...` (bit 63 clear, bit 55 still clear for the actor), with the client addresses.
- `src/housing_service.rs`: `migrated_lot`, applied by `HousingService::from_state` before `Housing::restore_lots`: a saved fixture
  guid loses bit 63 (old top byte `ff` becomes `7f`, which is what the minter now yields for the same inputs), and the
  pair rotation `[1, 0, 0, 0]` with tilt `[1, 0, 0, 0]` (what the old identity mapping stored for an unrotated placement; as Euler a
  one radian yaw, and no placement since T806 can store it because the tilt is always the rotation's facing) becomes zeros with
  tilt `(0, 0, 1, 0)`. Idempotent and keyed on the old shapes, so the save schema version stays. The save change is lead-reviewed.
- Notes: `notes/Research/Housing Core.md` (new section).

## Structure
One constant and one pure function; no new state, no schema bump, no new module. The actor guid keeps deriving from the fixture guid
(`fixture_guid | bit 55`), so a migrated lot's actors follow.

## Security-relevant decisions
- The migration only clears bit 63 of a persisted guid and rewrites one transform shape; it cannot name another player's fixture
  (fixtures stay in the lot of their saved `house_guid`, and a collision after clearing, two guids that differed only in bit 63, makes
  `restore_lots` fail closed with `CorruptSnapshot`).
- Client-sent guids are unchanged: 127/3 and 127/5 still carry fixture guids, checked against the acting player's lot.
