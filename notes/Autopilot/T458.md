# T458: world events, part 1 (event NPCs an admin starts and stops)

An admin can now run a scripted world event: `realm event start <key>` spawns the event's
actors in the open world and plays its timeline, and `realm event stop <key>` removes them.
Events are content data, so nothing about a show is compiled in.

- `data/content/world_events.json` ships as `{"events": []}`. It is read from the admin
  session's content directory (the one that holds `mounts.json`) at every start, so an edit
  applies to the next run without a restart or a reload command.
- The shape is the brief's: `events [{key, actors [{key, model_id, name_string_id, npc_name,
  position, heading, stand_animation_id, hide_nameplate, source}], timeline [{at_ms, op}]}]`.
  The ops are `spawn {actor, effect_id?}`, `remove {actor, effect_id?}`, `base_anim {actor, id}`,
  `play_anim {actor, id}`, `effect {actor, id}`, `tag_on {actor, effect_id}` and
  `tag_off {actor, effect_id}`, written as `{"at_ms": 0, "op": {"spawn": {"actor": "a"}}}`.
- Each command answers with one chat line: started, stopped, already running, not running, not
  an event in the file, or the file could not be read. Every refusal changes nothing.

- PlayClient checks the graceful removal's composite effect (`cmp [esp+208h], 0` at
  `0x0093083b`) and plays it when it is nonzero. Re-checked in attempt 3: the packet object is
  at `esp+1E4h` (the `0x00930770` call to `sub_8F7770`, which runs `0x008d6a60`), so `+208h`
  is field `+0x24`, the fourth i32 after the guid; `+1FCh`, `+200h` and `+20Ch` (animate,
  delay, duration) go to `sub_96B520`. So a `remove` poof is that field on the one
  35/3, not a separate 35/16.
- The 35/42 reader takes the tag id, so `tag_off` sends the tag id that its `tag_on` was assigned.

## Reconstructed rules (R)

- Runs use the public open world, zone 0, instance 0, which is the id `World::stage_public`
  keeps for zone 0. Runs live in memory only: a restart mid-run leaves nothing behind and
  nothing respawns.
- Event actors are scenery: `is_interactable` and `interact_range` are 0, as for rides. Every
  other AddNpc field comes from `world::content_spawn_template`.
- The spawn poof is a 35/16 sent after the AddNpc, at the actor's position. This follows the
  pattern of Sanctuary's `BroadcastSpawn`, which was read as reference only.
- The remove poof uses the graceful 35/3 with `duration` 0, the bytes the encounter already
  sends. Sanctuary defaults the duration to 1000 ms, and whether 0 cuts the poof short is the
  native check. `stop` removes each live actor with the poof of that actor's last `remove` step.
- A session that leaves the 100 m registry radius but stays in the instance gets a plain 35/3,
  and walking back shows the actor again. A session that left the instance or the registry is
  forgotten without a packet.
- Tag ids come from one runner counter that starts at 1 (`ponytail:` comment at the counter).
- `name_string_id` 0 means no locale name, as in `world::Placement`.
- Sanity bounds, not tuning values:
  - Event keys are 1 to 32 characters of `[a-z0-9_-]`, because chat is lowercased. Actor keys
    follow the same rule.
  - `npc_name` is at most 64 bytes, and every actor needs a non-empty `source`.
  - The brief's limits apply: 32 events, 32 actors and 512 steps per event, `at_ms` at most
    2 h, every id above 0, finite poses and `deny_unknown_fields`.
- An op the actor's state does not allow is skipped and logged as `world_event_step_skipped`:
  anything but spawn before the actor is live, spawn while it is live, `tag_on` of a tag that is
  already on, or `tag_off` of one that is not.

Where this differs from the brief's signatures:
- `start` takes the loaded `WorldEvent` rather than the key, because the host reads the file.
- `stop` needs no clock: its removals are queued and the next tick sends them.

## Threat note (secure-code-guardian)

- A hostile client can send `realm event start|stop <anything>`.
  - `command_refusal` runs first, and `may_run` needs `--dev-tools` or server-owned roles plus
    `can_run_realm_command(role, "event")`. That is admin-only by default, and no lead-only file
    was edited.
  - For an admin, the key only selects a row in a fixed file
    (`<content_dir>/world_events.json`). It never touches a path, and it is never echoed beyond
    the chat reply.
- Nothing else of the client's reaches the runner. Every packet is built by the server from
  validated content, and viewers send nothing.
- A refused delivery (a full queue) is logged as `world_event_delivery_refused`. Only that
  session is forgotten and later shown the actors again; the tick and the other sessions keep
  running (rule 17).
- No save, coin, item or reward is touched.

## Checklist

1. **A refusal changes nothing.** Unknown key, a running key, a stop of an event that is not
   running, a player or builder, and an unreadable file all reply and stage nothing.
   `t458_refused_commands_change_nothing` compares the snapshot, and the already-running
   canary failed it.
2. **Rollback covers all state.** The runner changes only after the commit (`apply`) and in the
   tick. A staged `SharedWorld` clone carries it unchanged, and there is no shared `Rc` or
   `Arc` state that can change.
3. **Apply deltas.** There are no old snapshots: the runner only adds and removes its own
   actors.
4. **Busy rules.** Not an activity: no player is occupied, and the actors are scenery.
5. **Every entry path is gated.** The only entry is the chat command, behind
   `command_refusal`; there is no automatic path in this slice (part 3 adds the clock).
6. **Reachable in production.** The tests use a real `Server` and `dispatch_message`, call the
   production `world_event_routing::tick`, and run `Server::step` once.
7. **Survives reconnect.** Runs are in memory only by the brief's (R). A reconnecting session
   is a new registry member, so it is shown the live actors again. Nothing is saved.
8. **Every exit path restores.** Stop, natural end (last step run, no actor live) and the
   per-viewer walk-out and leave all clear the state. A disconnected session is dropped from
   `seen_by` on the next tick.
9. **Economy safety.** Not applicable: no rewards.
10. **Wire format.** The client readers are listed in the table above. Byte tests:
    `tests/piece_056.rs::play_effect_and_graceful_removal_follow_their_client_readers` and the
    expected bytes in `t458_world_events.rs`.
11. **Unique ids.** `EVNT | serial << 8 | index` gives unique guids per run, and a wrapped
    serial skips the live ones (`a_wrapped_serial_never_reuses_a_live_guid`). There is no
    instance id of its own.
12. **Others see changes.** Every op goes to each session in `seen_by`, and late viewers are
    covered by the tick's view pass.
13. **Content works end to end.** The fixture event spawns, animates, tags and leaves through
    the real path. The shipped file is empty, as the brief asks.
14. **Values live in data.** Every timing and id is in `world_events.json`. The bounds are
    sanity limits marked (R).
15. **Canaries break production code.** All three edited `world_events.rs` or the routing,
    never a test.
16. **Hands off session plumbing.** No session creation, teardown, transaction or save order
    changed. The post-commit call sits beside `admin_move`, and the tick sits beside
    `tick_shared_fields`.
17. **One player's error never stops the server.**
    - A refused delivery is logged and forgotten per session, and the test proves the other
      viewer is still served.
    - A step that is not allowed is skipped, not a panic.
    - The ids are validated at load, so indexes stay in bounds.
18. **A type's rules live on the type.** Each `Shown` field is documented, and `stop` takes its
    effect from `Actor::remove_effect`.
19. **Hot paths stay cheap.** See the per-tick cost under Structure.
