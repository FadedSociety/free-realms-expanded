## Client reader check (IDA, this run)

- `decompile 008db310` (35/10 row): reads the 8-byte guid, the compact bool (`+40`), the type dword
  (`+28`), then for a non-compact row five dwords in the order object `+8`, `+16`, `+12`, `+20`, `+24`
  (row bytes 13, 17, 21, 25, 29), a bool (`+32`, row byte 33), a dword (`+36`, row byte 34) and the final
  bool (`+41`, row byte 38). The row is 39 bytes and the name string id is row byte 25, which is what the
  shared decoder reads.
- `decompile 008db550` (35/11 row): guid (8) + two dwords = 16 bytes, matching the decoder.
- The AddNpc guid is not re-parsed by the shared decoder: `spawn_index` calls the production
  `startup_world::parse_add_npc` (reader `00921a10`), so the test follows the same field parser as the server.
