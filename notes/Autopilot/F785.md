## What changed

- Finding 2 (BLOCKER, safety): `card_listener.rs` counted unknown commands with `self.unhandled += 1`, a client-driven `u32`
  on a connection that may live forever once logged in; the answered-event counter (`*answered += 1`) had the same shape.
  Both are now `saturating_add(1)`, so the 2^32nd frame cannot panic outside `contain`. The log cap (`LOGGED_PER_KIND`) is
  unchanged. Regression test `a_connections_counters_saturate_instead_of_overflowing`: both counters start at
  `u32::MAX - 1`, three unknown frames and three 414s arrive, the connection survives and both counters read `u32::MAX`.
  These two lines are production code in the lead-only T770 listener; the lead accepted them on 2026-10-28
  (`lab/autopilot/lead-signoffs.md`, F785/F837 entry). See the F837 correction below.
- Finding 3 (BLOCKER, structure): the client request fixtures (`int`, `text`, `headers`, `gateway_request`,
  `session_login`, `frame`, `ping`) now live once in `tests/support/card_packets.rs`, hand-built in the DLL writers' field
  order. `tests/card_service.rs` and the listener's tests both include it by `#[path]` (the repo's pattern, e.g.
  `f160_field_views.rs`). The listener tests no longer build the 414/411/ping requests with `put_headers`/`put_string`
  (the later command bodies did until F837); the fakes use the production decoder only to read server replies. The
  414's session id in the listener test is now the shared "w-ticket".
  `int` still calls `put_int`: `compact_integers_match_the_dll_writer` holds it to hand-written bytes. The listener's
  body builders for later commands (87 update, 137 status, 92 join, 503 avatar, 86 complete) still used `put_headers`:
  that claim was wrong, they are client requests, and F837 rebuilt them with the shared hand-built `headers` plus a
  byte-level golden (`the_client_sync_update_and_avatar_requests_match_the_dll_readers`).

### Security threat note (secure-code-guardian)

The F785 production change is two log counters in the card listener: `self.unhandled` saturates, and the per-kind
`Answered` counters saturate, so 2^32 frames from one connection cannot panic the gateway outside `contain`. It reads
no packet field, adds no reply, changes no bound and logs nothing new; `ticket` and `session id` still never reach an
event, and the per-kind log cap (`LOGGED_PER_KIND`) and the 30 s login deadline are unchanged. The fixture move
(F785's other half) is test-only: it removes the server's `put_headers`/`put_string` from client request construction,
so a hostile client still faces the same parser and the same caps; the tests only drive the real listener. Full
enumerated threat note: `F837.md`.
