## Client evidence (checked in IDA this pass)

- `Pet.StartGroom` sender `00b5f8c0`: refuses locally in water (the handler's in-water byte at +0x1300) or with the owner flag `+0x143 & 0x20`;
  otherwise builds the packet with ctor `00b51610` (subtype 18, two dwords at +0xc and +0x10: the active pet id from
  `00a10970` and a default 0) and sends it with `00b5c070`. The body is 8 bytes, the same shape as feed.
- 53/20 dispatcher `00b5ce60`, subtype 20 case: the packet is read by `00b58220` -> `00b55cc0` (six dwords at +0xc..+0x20).
  Kind (+0x10) selects: kind 3 (`00b5ec14`) writes the pet handler's state word `+0x12ac` = 2, calls
  `PetTactile::RefreshSpots` `00cce960`, `00b53710(1)`, fires `PetsHandler:BeginInteraction`, then calls
  `FlashTimerSetTimer` `00a8eff0` with the dword at +0x14 (the third word). `00a8eff0` adds `1000 * arg` ms to the
  current time and shows the display with `10 * arg` tenths: **the timer word is seconds**.
- Kinds 2, 4, 6 (`00b56850`, `00b56920`, `00b56a00`) all fire `PetsHandler:UnlockUtilities`, call `00b53710(0)` and clear
  `+0x12ac`. Kind 4 also releases the grooming spot effects (`00cce490`), so kind 4 is the end of a groom session.
- 53/22 sender `00ccebc0` (thiscall; arg 0 = the packet object, arg 1 = a send flag): the packet ctor `00ccdb70` sets
  subtype 22 and zeroes the words at +0xc, +0x10, +0x14, +0x18; the base writer `00b595d0` writes the u16 family and u8
  subtype; `00ccea80` writes those four dwords. **Wire: `53 00 | 22 | u32 mode | u32 unknown | u32 time | u32
  movement`** (19 bytes).
- Both senders fill it the same way (`00ccecf0` at 0x00ccf0ad..0x00ccf0c7, `00ccf260` at 0x00ccf311..0x00ccf32d): mode =
  the pet handler's state word `+0x12ac` (so 2 while grooming, 0 otherwise), unknown = constant 3, time = controller
  `+0x200`, movement = controller `+0x22c` (both integers; sent only once `+0x200 > 250`, then both reset to 0).
  `00ccecf0` (spot walk, grooming) divides movement by time as integers for its own progress. `00ccf260` (reached from
  `00ccf3c0` <- pets handler `00b589c0`) sends the same packet with no spot, which is the petting stroke. So the
  "fishing" callers named in earlier notes are pet code (as notes/Build Guides/Gameplay/Fishing.md already says), and
  the grooming and petting senders are both traced. The unit of movement is not recovered.

## Behaviour

- 53/18 starts a session when: the pet is summoned (the id is the active pet's), not vanity (R), the owner not in water and
  not busy (`Gameplay::blocks(pets)` via `PetBusy`), no feed or session running, the groom bar below the maximum (R: no
  shampoo wasted on a clean pet), a shampoo (utility slot 1) and a brush (slot 4: the definition slot 203 minus 199) fitted
  and owned. A fitted conditioner (slot 2) is spent too. Shampoo and conditioner are consumed once, at the start, on
  copies of the bag and roster that commit together with the session (R: an interrupted session cannot be replayed for
  free; the locale says the brush is kept). Answer: the bag's replies, then 53/20 kind 3 with the configured seconds.
  Every refusal answers kind 6 and changes nothing.
- 53/22 with mode 2 during a session adds `min(stroke_gain * min(movement / time, max_stroke_speed),
  max_gain_per_message)`, further bounded by what is left of the current one-second window's `max_gain_per_second`, to
  groom (decayed first, mood recomputed). The client's own consumer divides movement by time, so the ratio is the
  "stroke movement" (R: a deviation from the brief's bare `clamp(movement)`: a long, slow report no longer scores like a
  fast one). Words that are negative as the client's signed ints, and a zero time, count as 0.
- A full bar ends the session at once: 53/3 (final needs), the dry-off animation 35/8 (shared writer
  `piece_052::animation_packet`, for the owner and the viewers), then 53/20 kind 4. The time running out does the same on the
  world tick. Dismiss, a replacing summon and zoning send kind 4 only (no animation); entering water sends kind 4 and
  marks the save. After any end, no further gain.
- 53/22 with mode 0 and no session is petting: play + `petting_gain` (<= 2), at most once per
  `petting_min_interval_ms`; the live-needs path sends the 53/3. Not saved per message.
- A tactile message that counts for nothing while a session is live (busy, an unknown mode) is dropped silently: kind 6
  would clear the client's state word under that session. A mode-2 report with no server session is a stale client lock
  (it missed kind 4) and is answered with kind 6 instead (F796); with no pet out the pet id word is 0, which the kind-6
  handler does not read (`00b56a00`: `PetsHandler:UnlockUtilities`, `sub_B53710(0)`, `+0x12ac = 0`).

## Threat note (secure-code-guardian)

A hostile client can: send 53/18 for a pet it does not have out (refused, kind 6, nothing spent); flood 53/18 (each is a
cheap kind-6 answer, like feed); send 53/22 with any four words (negative-as-signed and zero-time words count 0, the speed
is clamped, the gain is bounded per message and per fixed one-second window, so the best a cheat gets is a fast groom:
the cap per second, or two caps over a span that straddles a window boundary (2x worst case, accepted and pinned by
`a_stroke_span_across_a_window_boundary_sees_at_most_two_caps`); flood 53/22 petting (the min-interval check runs first
and costs one comparison); send the wrong mode (ignored); send a stale mode 2 with no session (answered with kind 6, which
only clears the client's own lock and touches no state); send strokes while a session is live and the owner is busy
(ignored). Pet id, actor guid and item ids never come from the stroke message. Nothing is granted but need points; items
are spent only from the owner's own fitted, owned stacks. Per-message work: one `Arc` clone, one pet patched in place, no
roster clone; the start clones the roster once per session.

## Open (R) and gaps

- All `care.groom` numbers (R); the unit of movement is not recovered, so `stroke_gain` and `max_stroke_speed` are first guesses
  (live-tunable). The 60 s length is the locale's "a minute" (OSFR uses 25 s). Animation 5505 and the petting rate are from
  OSFR (R). The brush as the slot-203 row is read from the catalogue's 15 slot-203 rows (class 73) and the locale.
- The shampoo's and conditioner's `restore` values (25, 35) are not used by a session, and a conditioner does nothing but get
  spent. Idea for the lead: make their `restore` the session's pool (strokes drain it, the session ends when it is empty), so
  tiers matter and a session cannot give more than its items are worth.
- A clean pet refuses grooming (R, unspecified by the brief).
- Not driven through `Gameplay` or a real client; the native check is: fit shampoo and a brush, press Groom: the panel
  locks with a one-minute timer, brushing raises the bar, a full bar plays the dry-off and unlocks; petting a pet raises play.
