## Threat note (secure-code-guardian)

Hostile client capabilities on family 40/sub 4 and why they are constrained:

- **Forged body identities.** The parser consumes the inviter and target
  GUID/name fields to reach the fixed body end and discards them. The actor is
  `self.character_guid` from the authenticated session
  (`src/bin/osfr-gateway.rs:2164-2166`). The forged-body router test proves a
  body naming C cannot accept for C.
- **Forged or stale token.** Only the echoed invitation generation reaches the
  service, and it must equal the actor's pending invite's `invite_id`
  (`src/social_lists.rs:806-811`). A mismatch returns 40/5 result 3 before any
  change, so a body cannot select another party or another character's invite.
- **Stale invitation.** A character already in another party keeps the older
  pending invite; accepting it returns 40/5 result 1 before the invite or either
  roster is touched (`src/social_lists.rs:826-832`).
- **Full group.** The result-2 refusal returns before the invite is removed
  (`src/social_lists.rs:833-837`), so the refusal consumes nothing. The invite
  still expires under the configured TTL.
- **Replay.** A repeated 40/4 has no pending invite and gets 40/5 result 3;
  state is unchanged (`src/social_lists.rs:803-805`). A successful first accept
  or a decline is what removes the invite.
- **Malformed body.** `WireReader` bounds every field and
  `parse_social_request` calls `r.end()?`, so a short or trailing-byte body is
  refused before the service. Client-controlled names are length-bounded.
- **Economy and saves.** 40/4 carries no quantity, item, coin or reward, and no
  save file is written by this path. The refusal is one 8-byte result packet.
- **Trust boundary.** The service trusts only the session GUID, its own
  pending-invite map and the generation match.
- Existing exposure (not introduced here): there is no per-account action budget
  in `SocialService` for the group family; repeated 40/1/40/4 packets are bounded
  only by transport/session limits, the invite TTL and the binary-level social
  action budget. Adding a service-level group budget is a lead security
  decision.
