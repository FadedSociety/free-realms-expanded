# T554: Take Me There breadcrumbs follow FabledRealms.map instead of a straight line

2026-10-28

## Result

The 98/1 breadcrumb and Take Me There replies no longer sample a straight line when a
road route applies. A new `src/road_graph.rs` loads `data/content/road_graph.json` (the
client's own `FabledRealms.map` road graph, zone 0), snaps each request end to the
nearest road node within `snap_radius_m`, runs A* over the recomputed edge lengths, and
`Pathing` resamples that polyline every `STEP` metres with the existing `Terrain` ground
snap. Every fallback case (no graph, another zone, no node in range, no path, route
longer than `max_route_m`) answers exactly today's straight line.

Production wiring (attempt 2): `Gameplay` owns the graph next to `terrain`
(`road_graph: Option<Arc<RoadGraph>>`, loaded in `Gameplay::load` from `npc_content`) and
passes `self.road_graph.as_deref()` into `Pathing::answer`, exactly as it passes `terrain`.
`Pathing` stays the per-session request budget and nothing else. `gameplay.rs` grows by 4
lines (one field with its doc line, one load, one argument), inside the 40-line hub budget
and the 5,168 ceiling. The `data/content/road_graph.json` is generated, not hand-edited: 2,019 nodes, 2,151
undirected edges (4,302 directed adjacency entries), 108,176 bytes (cap 1 MiB).

Prerequisite T404 was already merged: both kinds go through the same `breadcrumb` and
already echo kind 2. No wire change.

## Data

Shape: `{schema_version, source: {asset, sha256, decoder}, zone, snap_radius_m,
max_route_m, nodes: [[id, x, y, z, [neighbour ids]]]}`. `snap_radius_m` 40 (R, bounds
5..=200), `max_route_m` 600 (R, bounds 50..=5000); the loader refuses values outside
those bounds, a non-1 schema, non-finite positions, a non-finite recomputed length, a
dangling neighbour, or a one-way edge. Node ids must be `0..n` in array order (also makes
the lookup cheap and deterministic). Neighbour lists are sorted; positions and ids are
the decoded asset's.

Provenance gate: `source.tag` (`client: ...; (R) snap_radius_m and max_route_m`) is what
`scripts/content_check.py` already understands (`source` object with a `tag`), so the file
now counts one client and one reconstructed entry and is off the "files without sourced
evidence" list (17 -> 16 files), with no new finding. A later edit to the geometry or the
two tuned values still shows in the file's hash and in review; the checker does not audit
node positions for any content file.

Generated by a scratch script in `%TEMP%\T554\` (not in the repo) from the decoded JSON:
sort by id, drop the decoded `distance` (the loader recomputes it), sort and dedupe
neighbour ids, write one node row per line. Content hash of this generated file:
`0a671de6665a69b05d74e88fc2f1ce6b300bcdfc5882efd5ce7c9bf3b3c23e1f`.

## (R) rules

- Snapping is planar x/z distance; A* edge lengths are 3D Euclidean, recomputed at load.
- Node positions in the reply carry w = 1.0 (from/to keep the client's own w).
- The reply is the client's from point, then the resampled road polyline (whose ends are
  the snapped nodes where they differ from from/to), then the client's to point; interior
  samples use the ground height with the previous height held across a grid hole.
- Uniform x/z arc-length resampling can cut a bend corner by at most half the sample
  spacing; each sample itself is on a road edge. Above `STEP` * (`MAX_POINTS` - 1) = 395 m
  the unchanged point cap coarsens the spacing (up to about 7.6 m at `max_route_m` 600).
- The whole route length cap includes the two straight snap legs, measured planar, while
  the A* path length is 3D.
- The original server's route is not recovered; this is the client's data walked by our
  own A*, not a reimplementation of the client's route finder.

## Security note (secure-code-guardian)

Attack surface: a hostile client sends 98/0/1 with arbitrary kind/aux and four floats per
point. It can choose any from/to and any rate. It still gets only the existing checks,
because the road lookup runs after them: parse length (malformed refused), finite values,
4D 300 m bound (overflow refused), the start within 300 m of the server's own player
position, both ends on the zone height grid, and the shared 4-per-second budget. Nothing
in the request chooses a graph file, node, radius or path bound; the graph is server
content keyed to zone 0. A refused request is silent and spends no budget, and the road
code only reads immutable content.

Cost bound: the graph is validated once at load (2,019 nodes / 4,302 directed edges); a
request does two nearest-node scans (2 x 2,019) and at most one A* over 4,302 directed
edges. The route is capped by `max_route_m`, and the reply by the unchanged
`MAX_POINTS` = 80 (15 + 80 x 16 = 1,295 bytes) for a 55-byte request. No indexing is
client-controlled: neighbour indices and ids are validated at load, `nearest` returns an
in-range index, and the request arrays are converted through the same `parse` as before.
No reward, item, coin, save or position changes.

## Checklist

   budget spend, so no refusal path changed. The existing refusal tests
   (`refusals_each_have_a_canary`, `refused_requests_leave_the_rate_budget_alone`,
   `take_me_there_is_refused_and_rate_capped_like_the_breadcrumb`) stay green; the
   fallback tests assert the reply equals the no-graph straight reply. Canary: the empty
   graph break fails the road tests (above).
2. **Rollback covers all state.** There is no transaction and no player state. The only
   mutable state is the two budget fields; the graph is an immutable `Arc<RoadGraph>`.
   No `Rc`/`RefCell`/side table.
3. **Apply deltas, never restore snapshots.** Nothing restores old state. The rate-window
   reset in `Pathing` is untouched (same `*self = Self { .. }` as the tip), because the
   graph no longer lives in it.
4. **Busy rules are mutual.** Not applicable: answering a path request starts no
   activity, moves nobody and changes no busy state. No busy-table row was added.
5. **Every entry path is gated.** Both client entry points (objective breadcrumb and Take
   Me There, `009cd010`/`009ce560`) reach the server only as the single 98/0/1 request
   through `Pathing::answer`; there is no second path to the road code.
6. **Reachable in production, tested through it.** `a_loaded_game_answers_road_routes_from_its_content_set`
   calls `Gameplay::load` on the shipped content directory and drives
   `Gameplay::handle_in_world` with 98/1 kind 1 and kind 2 packets on zone 0: the replies
   follow the shipped graph, and a zone with no height grid gets the failure reply. Its
   canary (`road_graph: None` in `Gameplay::load`) fails it. The shipped-data gate
   drives `Pathing::answer` with `RoadGraph::load` of the real file.
7. **Survives reconnect.** No persisted state was added. The graph is content, reloaded
   per session; the request budget is per session as before.
8. **Every exit path restores the player.** Not applicable: nothing is moved, flagged or
   locked; a fallback is still a normal reply.
9. **Economy safety.** Not applicable: no items, coins or rewards; nothing is granted.
10. **Wire format matches the client reader exactly.** Layout unchanged: header, kind,
    aux, i32 count, count vec4s, read by `0x008faf30` then `0x008e7710` (re-decompiled
    this run). The existing byte-for-byte take-me-there reply test still passes (it asks with no
    graph); the road tests decode the count and check the first/last points are the
    client's own. A fallback reply has the same layout and endpoints as before; interior
    samples now come from `along`, so float rounding of the interior points may differ in
    the last bit from the old per-axis lerp.
11. **Unique ids.** Not instance ids. Graph node ids are required to be the unique dense
    `0..n`; the reply has no new id field.
12. **Others see changes.** Not applicable: the reply is to the requester only.
13. **Content works end to end.** The shipped file is present and loads; a zone-0 request
    between nodes 316 and 851 (213 m apart) returns a non-empty 80-point reply whose

14. **Values live in data.** `zone`, `snap_radius_m` (40) and `max_route_m` (600) are in

15. **Canaries break production code.** The canary was a production `RoadGraph::from_content`

16. **Hands off session plumbing.** No session, teardown, transaction or save ordering

17. **One player's error never stops the server.** The new code returns `Option`/`Err`
