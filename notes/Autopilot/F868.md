## What changed

### 1. BLOCKER — STRUCTURE/WIRE: one exact set of packet readers

- New `prototype/osfr-tools/tests/support/pickup_packets.rs` holds the only implementation of
  the three readers the node suites use, with the client layouts in its module doc:
  - 35/2 `AddNpc` (reader `0x00921a10`): four-byte header, guid at `4..12`.
  - 35/3 removal (reader `0x008d69f0`, base `0x008d6830`): header, `u16` at `4..6`, guid at
    `6..14`.
  - 15/3 system chat (reader `0x00b0f5f0`, base `0x00b0f550`): header, `u32` length at
    `4..8`, that many text bytes, one flag byte.
- `tests/support/pickup_fixture.rs` no longer defines `added`/`removed`; it re-exports the
  shared readers. `tests/support/npc_quest_chain.rs` no longer defines the loose
  `windows(8)` removal match: `said`/`added`/`removed` are one-line `Outcome` wrappers over
  the same shared module, and their comments state the real field offsets.
- `tests/quest_pickup_nodes.rs` loses its own 35/2 `added` (also a `windows(8)` match) and
  imports `npc_quest_chain::added`; `tests/collection_node_pickups.rs` loses its own `said`.
  T503, T539 and the collection suites now agree on one reader each.

IDA re-check this run (the review's claim is correct; IDA did not contradict a note):

- `sub_8D69F0` calls `sub_8D6830` (two `i16` = the four-byte header), then reads one `i16`

  `4..6`, guid at `6..14`.

## Security threat note (secure-code-guardian)

No production parser, wire writer, save shape, coin/item path, role or reward changed. The
attack surface is unchanged: a hostile client can send 26/8 for any guid from any claimed
position. Production refuses an unknown/unshown guid, busy player, non-open world,
out-of-range click, full bag and a node type no open objective wants, each with one 15/3 line
and no state change; the suites still assert `changed == false` and a byte-identical save.

- The changed readers are test-only parsers of **server-emitted** 35/2/35/3/15/3 packets; they
  never feed production, so they cannot widen input trust. They are now strict about the
  field offsets the client reader uses (`0x00921a10`, `0x008d69f0`, `0x00b0f5f0`) instead of
  scanning for the guid anywhere, so a future 35/3 variant cannot be misread as a removal.
- Quest pickup counts still come from the server's own event count, capped at the required
  quantity; no packet supplies a count, an item or a reward. Every quest node type still ships
  an empty drop table (asserted by the content pin) and the loader refuses a quest node with
  drops.
- The display-name change is content text (a server-side label, name id 0); it does not reach
  the 35/2 body (the AddNpc name string id is separate and still 0/-1 as before).
- No secret, key, account data, player name/chat text or absolute home path is in the diff.
