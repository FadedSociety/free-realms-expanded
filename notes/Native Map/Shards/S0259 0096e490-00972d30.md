## ProxiedCharacter and rider lifecycle

- `0096fa70` constructs `ProxiedCharacter` and initializes its actor state, collections, strings, and manager fields. The vtable directly identifies the class. `00972570` performs teardown, calls `009710b0` (`RemoveRider`), and frees its mount-state allocation. `009707a0` and `009707b0` are distinct this-adjusting scalar-deleting thunks into `009731e0`; `00970790` and `009707e0` likewise adjust `ECX` before forwarding. These are jumps, not the target bodies.
- `00972d30` is the clearest mount entry: its exact log string names rider and mount identities, it validates the requested seat, allocates mount state, and calls `009722d0`. `00971250` logs a seat-index/model-seat-count error and computes/apply seat/model transforms. `009722d0` updates seat transition state and actor transforms. The sequence supports a client-side mount/seat lifecycle; it does not establish server authority or a wire contract.
- `009710b0` resolves the stored rider identity, logs removal, updates related actor state, invokes action helpers, and frees the mount-state block. Its callers include ProxiedCharacter teardown and two actor-processing paths.
- `00970b60` updates timers/state and dispatches helper calls; `009708f0` builds a temporary `IString` list and argument record before calling `0078b390`. `00972c90` and `00972cf0` use `007aa6f0` to look up values for keys 0xc and 0x13. The former adds a global counter modulo 12; neither function generates a random action ID. The downstream semantics remain unknown.
- `0096e490` is a per-frame motion/state routine called by `00973200` (`ProxiedCharacter::Process`): it scales delta time, checks status/related-object state, advances stored motion fields, invokes helpers, and updates transforms. The caller supplies the character context; this body does not establish its owning class. It is not a packet parser or sender.

Allocation inserts that address; `0096f120` searches by a returned slot address and verifies its offset against the block's slot count. The pool's owner and semantic users are not identified in this shard.
- `0096f540`, `0096f620`, and `0096f680` construct/destroy `OverHeadTextElement`; the base vtable restoration is visible in the destructor. `0096f6e0` is a `PlayerAnimationEvent` virtual method with conditional animation/context updates.

## Shared actor methods and evidence limits

- `009706d0`, `009706e0`, `009706f0`, and `00970700` are shared vtable implementations across `ProxiedObject` and several derived actor classes. They return pointers at `+0x20`, load the first stack argument and pop eight bytes, return the dword at `+0x48`, and return a pointer at `+0x4c`, respectively. In particular, `009706e0` is not an ECX identity getter: bytes are `mov eax,[esp+4]; ret 8`. `00970760` is a shared `+4` getter across unrelated vtable families, so it has no single class assignment.
- `00970770`, `00970780`, `009707c0`, `009707d0`, and `009707f0` provide mechanical ProxiedCharacter field access/update. Field semantics remain unnamed. `00970810` and `00970880` create `IString<char>` results from fields `+0x56c` and `+0x58c`.
- `0096f330` returns an indexed address using a 0x54 stride. Its helper gate is `(count <= index) && (count < wrapped(index+1))` under signed comparisons, so `INT_MAX` wraps and skips the helper. `0096f6a0` has the same two-comparison gate, then calls `006f9e60` with `param_3`; `006f9e60` is the refcounted IString assignment/copy helper, not a callback. `0096f360` cleans up `Array<StringFixed<64>>` buffers. The exact effect of the guarded helper `0096b1d0` remains open.

## Wire contract, note comparison, open questions

No target in this shard builds, sends, parses, or dispatches a network packet, so every `wire` list is empty and no original-server inference is justified. Mount-state operations and generated action values are local client behavior only; any server-side mount relationship contract requires independent packet/parser evidence elsewhere.

The findings do not contradict `notes/Research/Native NPC Motion and Animation.md` or `notes/Research/Stage7 NPC Grounding Semantics.md`. Those notes establish movement/grounding behavior on other paths; this shard adds actor processing and mount/seat transform logic without revising their wire or collision findings.

Open questions: semantic names for many actor fields and keys 0xc/0x13; the identity/ownership of the 0xd0 pool; exact mount seat coordinate spaces and transition values; whether the ordered tree helper's duplicate-key edge is first/last among equals; and the true return convention of `0096e8a0`/`0096e8e0`, whose pseudocode traverses to a candidate but infers `void`.
