## Threat note (secure-code-guardian)

A hostile client can send 26/8, 26/10, 26/6, 49/2 and 49/14 with arbitrary actor and quest ids. This change adds no
parser and trusts no client field. Offers still need a live 26/6 choice and pass `offer_denial` (giver, prerequisite,
exclusion, level, job, membership, limit); 49/2 needs `pending_offer == quest` plus the same requirement checks; 49/14
needs the saved `pending_turnin` and pays once through the existing reward key. The new content field is a server-side
locale id sent in the 49/1 card; it cannot be set by a client. Tests prove the forged/duplicate requests leave the
serialized state equal.
