# T481: starting a gather, craft, chess or fishing activity ends the ride

## What changed
- `src/gameplay/occupation.rs`: the `ride` gate is now true for Forging, Smelting, Cooking, Mining,
  Harvesting, Chess and Fishing (their row equals Encounter's: start, warp, ride, pets; not
  location). `ride_restrictions` (`gameplay/rides.rs`) reads that gate, so `settle_mounts` ends the
  ride once the activity is active and a summon or board is refused while it lasts. No other
  production code. The pin `gates_reproduce_the_replaced_busy_lists` lists the new ride row.
- `tests/mount_wired.rs`: gateway-level tests `starting_a_gather_ends_the_ride`,
  `a_refused_gather_keeps_the_ride`, `no_ride_can_be_summoned_while_gathering`,
  `starting_a_crafting_station_ends_the_ride`.

## (R) choices
- Order in the replies: the gather's own replies come first, then 168/4 and 35/3, because the
  gateway binary appends `settle_rides` after the handler. The reference dismounts before the
  reward; the client does not care.
- Chess and fishing are covered by the table row only; the tests drive a gather and a forging run
  through their real entries (26/8 node click, 26/24 recipe start at the world anvil).

## Checklist
1. Refusal changes nothing: a refused gather (out of reach, wrong job) keeps the ride and sends no
   168/4 (`a_refused_gather_keeps_the_ride`); a refused summon during a gather leaves the snapshot,
   ride and activity unchanged (`no_ride_can_be_summoned_while_gathering`, snapshot equality).
2. Rollback covers all state: no new state; the gate only reads existing activity state.
3. Deltas not snapshots: n/a, nothing restored.
4. Busy rules mutual: only the ride gate of the table row changed; start/warp/pets/location are
   pinned unchanged by the pin test.
5. Every entry path gated: summon and board both read `ride_restrictions`; the end path is
   `settle_mounts` after every message and tick. Tested through the gateway.
6. Reachable in production: tests use `Gateway::handle_at` for the real 26/8, 26/24 and 168 requests
   and `settle_rides`, as the gateway binary does.
7. Survives reconnect: a disconnect resets the session, which already clears the ride (unchanged).
8. Every exit restores the player: leaving the activity reopens the gate, so a summon works again
   (the table is stateless).
9. Economy safety: no items or coins touched; a refused summon leaves inventory unchanged.
10. Wire format: no packet changed; 168/4 and 35/3 are the existing `settle_mounts` replies.
11. Unique ids: n/a. 12. Others see changes: 35/3 goes to `nearby` (asserted). 13. Content: n/a.
14. Values in data: n/a, a boolean gate in the table. 15. Canary: with only the Harvesting row
    set back to `ride = false`, `starting_a_gather_ends_the_ride` and
    `no_ride_can_be_summoned_while_gathering` fail (`mount_wired.rs:418`); reverted.
16. Session plumbing untouched. 17. No per-tick failure path added. 18. The rule lives on the
    `Occupation::gates` table. 19. No hot-path cost.

activity that closes the ride gate is active, and the server (not the client) ends the ride.
