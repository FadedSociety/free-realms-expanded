# T495: the Marketplace sells the client boomboxes in their own category

## Summary

The brief's premise was partly stale at the tip. T634 had already priced 7 boomboxes from the wiki
(878, 1180, 1913, 48244, 76927, 76930, 76935), so they were listed, but under **Rides**, in the one
category the catalogue wrote. What was still missing:

1. a Boombox category (66/7 node, 66/6 group, per-bundle group key) so they list under their own
   category and not under Rides;
2. prices for the Marketplace boomboxes T634's name match missed: Tiki (76928), Hootenanny (76933),
   Xylophone (76934, no store row at all) and Lovelectric (77329).

Changes:

- `src/station_cash.rs`: `Shelf` (category id, name id, group id), `Config::boombox_shelf`
  (optional, validated: nonzero and distinct from Rides), `RowKind { Ride, Boombox, EarnOnly }` as the
  row source (replaces the `reward_only` bool), `Listing::group`, `Catalogue::shelves()`. The 66/7
  tree and 66/6 groups write one entry per shelf; each bundle record names its own group. A boombox
  row with no configured shelf is refused at load. `place_order`, the wallet, the replay window and
  the busy rule are untouched.
- `src/coin_shop.rs`: `StoreItem::boombox` (tag), refused unless the row has an `sc_price` and is not
  `earn_only`; maps to `RowKind`.
- `data/content/stores.json`: `station_cash.boombox_shelf` (category 89, name 151365, group 89), the
  `boombox: true` tag on 11 rows, 4 new prices with provenance (3 wiki, 1 estimated), one new row
  (Xylophone).
- `tests/station_cash.rs`: the world-entry walk now checks both categories; navigation test walks two
  categories and two groups; four new tests (see Checklist).

## (R) choices

- **Category id 89, name 151365 ("Boombox"), group 89**, not the brief's locale 6489 ("Boombox!").
  Legacy `StoreBundleCategories.json` has `Id 89, Comment Boombox, NameId 151365, ParentId 136`, and
  every boombox bundle in Legacy `StoreBundles.json` has `CategoryGroupId 89`, so this is the original
  server's own id set (values only, no code copied). 151365 is in the client locale
  (`lab/reports/locale-id-to-text.json`: "Boombox"); 6489 is "Boombox!" and has no category use I
  could find. It is live data (`stores.json`), so switching to 6489 is one value. The node is
  top level (parent 0): Legacy's parent 136 ("Supplies") is not in our tree.
- **Tiki 500, Hootenanny 150, Xylophone 400**: the regular price on each wiki page (revisions 37212,
  46296, 37250). Tiki's page writes "500 SC" and Xylophone's "{{SC|400}} SC", which is why T634's
  parser missed them.
- **Lovelectric 299 (estimated, basis E)**: its page (46307) says it was sold in the Marketplace
  during Festival of Hearts but gives no price. The nearest documented tier is the other seasonal
  client boombox, Jingle Bell at 299.
- **Totem 8185, Clockwork 35759, Hip-Hop 56774, Chiller 69825 stay unpriced and unlisted.** The wiki
  says they are TCG, Mystery Chest and quest-pack prizes, not Marketplace items, and the research pack
  advised against inventing prices. The brief said to give them the nearest tier; I did not. Adding
  a price and the `boombox` tag to the row sells it: no code change. Lead decision.
- Chiptune (not a client item) is skipped as the brief says; Chicken, Plants Dance, Ballet and Robot
  are Sanctuary-only ids, not client items (T459), and are not imported.
- A second copy is sold. F656 narrowed T484's owned refusal to rides (`Listing::ride`, from the mounts table), and a
  boombox is not a ride. No client item definition marks a boombox unique: the Realms Roll row
  (`ClientItemDefinitions.json`, Id 1180) has MaxStackSize 1 and no unique column. The brief's "unless unique" branch
  therefore does not occur; the order test pins the second sale (one more debit, one more boombox).
- The last dword of each 66/7 node is written as index+1 (it was a constant 1). I read it as a display order
  (Legacy has a DisplayOrder column); 0x00b3b080 does not show its meaning, and the mapping of the three
  trailing dwords to parent, count and order is inferred from the writer (R).
- The wiki also notes Marketplace prices fell to 1 SC on 18 March 2014 (`16525-45216`); the 0.25 scale
  and pre-2014 prices stay as T230/T634 settled them.

## Threat note (secure-code-guardian)

A hostile client can send any bundle id, store id, quantity, tint, gift or coupon string in 66/3.
The listing is looked up by bundle id in the server catalogue only; unlisted ids (including the four
reward-only boomboxes), other stores, quantities other than 1, gifts and coupons are refused by
`price()` unchanged, and the refusal changes nothing (tested). The price, the item and the group
all come from `stores.json`, never from the packet.
