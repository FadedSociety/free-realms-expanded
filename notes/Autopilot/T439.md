## Structure

Graph queries: none (the code is one tick loop in one file); every use of `kiting`,
`field_sim.attacks` and `field_sim.moving` was found with `rg` instead.

Moved into `src/encounter/arena.rs` (new, 336 lines, about 105 of them tests):
- `ArenaSim { attacks, moving, kiting }`: enemy attack clocks, walk set and skittish run/rest state of one run.
  Runtime only, never saved, rebuilt empty on load, `begin` and `reset_session`.
- `Kite` (enum) and `kite_turn` (now `ArenaSim::kite_turn`, two fewer arguments, no clippy allow).
- The enemy loop of `tick_encounter` (stun skip, skittish kiting, chase, reach, attack clock, damage) as
  `ArenaSim::tick_enemies`, reading the engine through the small `ArenaTick` borrow struct and returning the
  damage the player takes. The caller still applies the damage, knockout and results.
- `EncounterEngine::with_arena(&mut ArenaSim, action)`: swaps the one value in and out (FieldSim rule).
  Its first non-test caller is the group arena (T441), so it carries `#[allow(dead_code)]` and a `ponytail:` comment.

Stays in `EncounterEngine` (brief step 3): player health, energy, cooldowns and `last_attack` (the player's own
clock), knockout, results screen, prize wheel, return pose. `ActiveEncounter` and `EncounterState` are untouched
(decision 2): enemies, dormant minions, phase and instance still live in `ActiveEncounter`, so the save bytes,
`deny_unknown_fields` and the content-hash check are unchanged and old saves load as before. Dropped as named
(decision 5): "contributors" and "summoner shield" (the shield is derived in `skills.rs`).
`state.world_enemies` (the opening stage) is not owned by ArenaSim (decision 3), but it runs through the same
tick loop, so its clocks use the same maps.

Other edits: engine field `kiting` became `arena`; `strike_damage` clears `arena.kiting` on a kill;
`reset_session` resets `arena` and still clears the field's `attacks`/`moving`; `skills.rs::apply_stun` clears
the walk flag in both the arena and the field set (the GUID sets are disjoint). The `shared.rs` test module and
its `engine()` fixture became `pub(in crate::encounter)` so the arena tests reuse them.

Line counts: hub `encounter.rs` 3121 -> 2957 (-164; ceiling 3156). No other hub touched.
`arena.rs` +336 (new), `skills.rs` +2, `shared.rs` +0 (visibility only).

GUID ranges (decision 1). The arena's clocks used to share `field_sim.attacks/moving`, keyed by GUID, so the sets
must not overlap. GUIDs are authored in content and every loader refuses a clash:
- encounter content load (`encounter.rs`, "duplicate actor GUID"): world enemies, dungeon guides and dungeon enemies share one set.
- `load_field_enemies` (`field_content.rs`): one set seeded from world enemies, dungeons (and guides) and battle spawners.
- `load_field_battles`: seeded from world enemies, field enemies and dungeons; battle enemies join the dungeons.
- `reload_field_battles` drops its own dungeon rows first, then re-checks against the field enemies.
So no path leaves an arena actor and a field enemy with the same GUID. The test `arena_and_field_guids_are_disjoint`
pins it (loaded sets are disjoint; a field enemy reusing an arena GUID is refused and nothing changes). Shipped
content is covered by the existing GUID tests in `bandit_hideout_dungeon` and `bixie_hive_dungeon`.
