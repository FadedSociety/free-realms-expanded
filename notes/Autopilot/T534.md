## Format `OSFROBS1`

Little endian: `8s` magic, `u32` version 1, `f32` cell (8 m), `f32` min x, `f32` min z,
`u32` cols, `u32` rows, `u32` triangles, `u32` bucket items; then the triangles as nine
`f32` each; then `cols * rows + 1` `u32` bucket starts; then the `u32` triangle ids.
The file is self-contained and versioned; the bake writes it with
`character_store::replace_bytes`, so a crash keeps the previous file.

Bounds enforced by the loader and the writer: 256 MiB file, 2,000,000 triangles,
4,096 cells per side, 4,000,000 buckets, 32,000,000 bucket references, at most 4,096
triangles in one bucket, finite coordinates, monotone bucket starts, and every id
inside the triangle array. A bad file prints one `obstacles: <file>: <reason>` line
and leaves that zone without obstacles; it never fails `Terrain::load` and never
panics. The loader keeps at most 512 MiB of parsed files and logs a skipped zone.

Query bounds: `surface_below` scans one bucket (<= 4,096 items); `segment_blocked`
walks the cells in the segment's x/z box and stops after `MAX_QUERY_TRIANGLES` =
8,192 triangle tests, answering "blocked" when the budget runs out. Neither query
allocates.

## Reconstructed rules `(R)`

- **Placement transform:** local point scaled, then rolled about z, pitched about x and
  yawed about y, then translated. The pinned MIT reader
  (`ForgeLightToolkit/Editor/LoadWorldWindow.cs`) passes `(stored.y, stored.x, stored.z)`
  to Unity `Quaternion.Euler`, i.e. z/x/y order with radians converted to degrees.
  Data rules out a quaternion (above); the exact order is not recovered from the client.
- **Content limits:** `pets.json` `follow` has `body_height_m = 1.8`, `step_up_m = 1.0`
  (also the obstacle clearance), `step_down_m = 3.0` (also the surface probe drop) and
  `sample_m = 0.5`; all four are tunable with load-time bounds.
- **Blocked segment:** the exact body band from `ground + step_up_m` to
  `ground + body_height_m`; a non-degenerate triangle is tested as a height field, a
  vertical one with the lifted Moller interval.
- **Surface below:** the highest triangle at `(x, z)` at or below `from_y`, at most
  `step_down_m` below, whose normal is within 50 degrees of vertical. Non-finite triangle
  vertices are ignored (the shared helper rejects them), so a malformed CDTA/`.obs`
  triangle is never a surface and never produces a NaN.
- **Mounting a deck from below** is not modelled: `surface_below` only looks below
  `from_y`, so a pet already on the deck stays on it, but a deck more than a step above
  the lower ground is not climbed onto.
- `MAX_SLOPE_DEGREES` = 50 is a compiled (R) collision-analysis policy shared by the
  bake analysis and the server walk; it is not a `pets.json` value. The query caps
  (`MAX_QUERY_TRIANGLES`, `MAX_BUCKET_ITEMS`) are format-cost safety bounds, not gameplay
  tuning.

## Threat note (secure code guardian)

- **Hostile client input:** the 53/26 target is the only new input path (it already
  existed). A forged target behind a wall is refused by the baked mesh; the target
  still has to pass the client's 8-40 m 4D band, the 10 m step band and the 40 m pet
  path cap. The click's y is never used as the pet's height. Non-finite targets,
  clearance, body height and sample spacing are refused before any query.
- **No rate limit added:** the previous attempt clock was a lead-only input rate
  limit and was removed. A refused click writes no session or gameplay state (canary
  and test), so it cannot consume a pending offer, attempt counter, item or cooldown.
- **Denial of service:** query cost is statically bounded. `surface_below` scans one
  bucket of at most 4,096 triangles; `segment_blocked` inspects at most 8,192
  triangles and refuses (blocked) past that. A click-length path makes one swept
  query plus at most six surface probes (one per 8 m cell), so the worst case is
  ~32,768 triangle tests per click; the real bake's mean is about 1.6 k per click.
  At the 200 packets/s budget that is a bounded few million tests per second even for
  an adversarial click stream, versus the previous unbounded 80-sample walk. A 20 Hz
  follow step makes two short `walkable` calls (2-3 surface probes and one small
  bucket each) and no allocation.
- **Server-local data:** the `.obs` file is not client input. The loader bounds file
  size, triangle/per-bucket/total counts and every coordinate, rejects non-finite
  values and broken indices, caps the total loaded bytes, and logs and skips a bad
  zone. No `unwrap` is used on parsed data. The bake skips an outlier placement and
  refuses a stale `.obs` pair beside a new grid.
- **Per-player failure:** the queries refuse invalid input (`true`/`None`), the pet
  path has no new `?`, and a refused click never touches the destination, pose,
  inventory or roster.
- No coins, items, XP, roles, chat or saves are touched.
