## Method and (R) rules

1. One greeting per NPC, chosen because the line's speaker is proven or the
   inference is stated. A third-person objective line was never used, and no
   line was borrowed from a neighbour.
2. The 17 lines are the row's own recovered speech: a quest/offer line whose
   content names the NPC's unique role or relationship, a named audition turn,
   or a delivery/welcome reply.
3. `(R)` marks an inferred speaker link (8 of 17): the source note says exactly
   what is inferred (locale-block adjacency, audition cue, welcome-tour list,
   contest winner, cotton-candy hand-out plus name-id block, bouquet delivery,
   sponsor offer). The other 9 carry exact speaker proof.
4. `(R)` every row uses one recovered speaker line as the fixed default Talk
   greeting; the original server greeting/phase table was not recovered, so a
   quest phase does not change the first-click body and no text is invented.
5. The lines are server content; a client never supplies a locale id.

## Security threat note (secure-code-guardian)

- This slice changes no parser, save, coin, item, reward, role, chat or trade
  code. The only new values are static server-side `u32` locale ids and their
  evidence strings; the client never supplies a locale id.
- Hostile client input on the path is the existing 26/8 target GUID and the
  26/10 NPC GUID/option pair. The router resolves the GUID through
  `NpcVisibility::content_key`, requires an open menu for that exact NPC, and
  rejects an unknown GUID (`UnknownNpc`) or an out-of-list option
  (`InvalidOption`). The new suite re-asserts that a refused `i32::MAX` choice
  leaves the open menu usable and the next Talk returns the unchanged blank
  body.
- A greeting cannot be borrowed from another row: the body is the clicked
  row's own `greeting_string_id` (None for a blank row) and the in-world packet
  carries 0 for a blank. The source gate requires `Global.Text.<id>`,
  recomputes the hash and finds the cited physical dat line, so a raw hash or
  a third-person objective line fails. The cross-file check rejects a reused
  id.
- The client cannot inject text, HTML, a path or an arbitrary locale id. No
  player state, no new entry path and no allocation from attacker-controlled
  size. Loader bounds (8 MiB/file, 32 MiB total, 20,000 rows) are unchanged and
  asserted by `service()`. All 17 ids resolve in the stock client locale, so no
  overlay or fallback path is introduced.
