## Security note (secure-code-guardian)

Attack surface: a hostile client can send `26/8`, `26/10`, `26/13`, `36/10`,
`42/3`, a truncated `26/42`, or chat while a movie is active, send a 20-byte
`36/10`, or spam the gathering actor with the wrong job or before the objective
is accepted.

Why each is refused and changes nothing:

- Every refusal that returns a `GatewayOutcome` asserts its exact reply text
  (F214 also pins the negative gather's switch-job text), a byte-equal
  `Gateway::snapshot()` (character plus the whole `GameplayState`) **and** the
  new `GatewayOutcome` side channels, so a spurious `nearby`/shared-field/
  group-heal/pet-roster/zoning action or a staged commit cannot hide behind an
  unchanged snapshot. The bundled terminal refusals return `Err`, so they assert
  the exact error string and snapshot equality instead of a reply text.
- The malformed 20-byte `36/10` is rejected by `unsupported_cast` before any
  combat state is read; the new unit test proves the error, and the S6
  movie-gate case proves the gate handles the valid 24-byte form.
- Bonus drops remain server-owned and paid only for newly counted accepted
  progress on the active job. The new desync guard test asserts the whole
  inventory is unchanged (F214 added the comparison; F193's note claimed it
  without the assertion). The wrong-job negative asserts no item and no count.
- No client-reported score, result or item id creates a grant in any test.
  Refusals do not consume items, ingredients, movie state or counters.

No new client-input parser is introduced; the change is tests plus notes.
