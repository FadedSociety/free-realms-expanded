## Threat note (secure-code-guardian)

- Hostile input: a client can put a combat/NPC child beside 165/2 reads and any other child in one
  `[0, 25]` bundle, including a child that begins a zone transfer. The refund is not client
  reachable as a "success": it runs only after `prepare_membership`/save fails inside a real
  transfer, and it only *subtracts* bytes that `stage` added for that same child in the same
  dispatch. A client cannot raise the cap, avoid the over-budget refusal, or make the counter
  smaller than the replies actually queued: `release` uses `saturating_sub` and earlier children's
  charges stay.
- Refusals: the over-budget child still fails before commit and ends only that player's session
  (existing policy). A refused precommit transfer still changes no location, membership or save
  (the test asserts the zone is unchanged and no refund-less bytes leak).
- No new auth, role, item, coin, reward, shop or save path is touched. The budget remains a
  session-local value with no shared `Rc`/`Arc`/`RefCell`. No player names or chat text are used.

## Checklist

1. **A refusal changes nothing.** The split test asserts the refused read left `snapshot().gameplay`
   equal to the pre-bundle gameplay (the pose's movement is the only committed effect and is the
   documented W116 per-child commit). The transfer test asserts the refused transfer did not change
   `zone_id`, the budget charge was released, and the dispatch continued. Each refusal has a canary
   (A, B, C) that breaks production code; each canary failed its regression.
2. **Rollback covers all state.** No shared state is added: the budget is a session-local
   `Option<usize>`; `release` only adjusts it. The refused transfer's replies are dropped; nothing
   escapes the staged `Gateway`/`World` clones.
3. **Apply deltas, never restore old snapshots.** Not applicable: no payout or exit path is
   introduced; the refund updates a counter and leaves live inventory/coins/position alone.
4. **Busy rules are mutual.** Not applicable: no new activity or `Occupation` row.
5. **Every entry path is gated.** The refund is inside `commit_outcome`, the one place every path
   (client request, every split child, `tick`, automatic) stages replies; `trace_path` confirms the
   callers. No parallel path was added; the later child in the new test drives the same dispatch.
6. **Reachable in production, tested through it.** Both tests call `Session::dispatch_message` with
   real `[0, 25]` bundles. The refund test uses the production `realm race` route (real kart scene
   transfer) and the production precommit save failure; it does not call a copied helper.
7. **Survives reconnect.** Not applicable: no persisted state, ledger or progress changed; the
   budget is per message and the refused transfer writes no save.
8. **Every exit path restores the player.** The refused transfer leaves the live zone/position and
   membership untouched (asserted); the budget refusal is the existing per-session end, unchanged.
9. **Economy safety.** The changed paths touch no coins, items, rewards or prices. The 165/2 reads
   are read-only; the transfer test's read is a small definition read after a refusal. No free
   grant and no client-reported outcome is trusted.
10. **Wire format matches the client reader.** No production wire bytes changed. The two layouts
    the new tests build were re-decompiled: 125 at `008e5940` and the 26/10 constructor
    `00a36f80`; 165/2/165/3 remain as cited in F179.
11. **Unique ids.** Not applicable: the diff allocates no instance, GUID or lifecycle id; the kart
    instance in the test is the existing allocator and is refused before commit.
12. **Others see changes.** Not applicable: the refused transfer publishes nothing; the split
    test's session is not joined, so no fanout changed.
13. **Content works end to end.** Assertions check final outcomes: the over-budget error, the
    surviving pose, unchanged gameplay, the refunded charge (`released > 0`, then 0), the unchanged
    zone, and the later child still dispatched.
14. **Values live in data.** No new constants; the test's row counts are fixture sizes and the only
    policy value is the lead-signed 8 MiB cap.
15. **Canaries break production code.** A changes the production split condition, B removes the
    production reset, C removes the production release. Each failed the matching regression and
    was reverted (the tests pass again after each revert).
16. **Hands off session plumbing.** Session creation, teardown and save ordering are untouched. The
    change is inside `commit_outcome`'s existing precommit-transfer branch and the budget type. The
    8 MiB budget with pre-commit refusal is lead-signed (2026-10-19); this refinement keeps that
    policy and only stops charging discarded bytes, matching checklist item 1.
17. **One player's error never stops the server.** The branch still returns `Ok(false)`; no shared
    tick code changed and no `?` was added outside it. The over-budget error still ends only that
    session, as before.
18. **A type's rules live on the type.** `BundleBudget` owns staging, releasing and observing the
    charge; `stage`'s doc says the returned amount is for `release`, and `release`'s doc names the
    discarded-reply case. The test-only `Session.bundle_refusal` field is documented. No persisted,
    compared-for-change or sent field was added.
19. **Hot paths stay cheap.** `stage` computes the same sum and returns it (no new allocation);
    outside a bundle it returns 0. `release` runs only on a precommit transfer refusal (rare) and
    is one `Option` test plus `saturating_sub`. `used()` is only used by tests. Per dispatch the
    change adds one `usize` local; per tick nothing.
