## Threat note (secure-code-guardian)

Attack surface: the public TCP card listener, one unauthenticated 411 per connection, any source
address. What a hostile client could send and why it is refused:

- **A guessed ticket.** Tickets are 64 random bits from the OS, single-use, live only for the
  launch block's TTL (1 s-10 min, bounded in `card_game::Content::validate`), one outstanding per
  character, at most `MAX_TICKETS` (64) per session. A wrong, spent or other session's ticket gets
  the same 81 code 63 as every refusal, consumes nothing, and does not reveal whether it existed.
- **A ticket minted in another session.** The scan stops only at the session that holds it; a
  session without it returns `None` and cannot spend, expire or mark it. The test asserts each
  ticket is absent from the other session's store, and that a refusal before the real logins leaves
  both tickets redeemable.
- **An empty or forged character id.** The empty id is accepted because the retail exe sends none
  (IDA below); the character returned is the ticket's owner, never the presented id, so it cannot
  select a victim's character. A non-empty id must be the owner's strict decimal; anything else is
  `character_mismatch` and (as before) does not spend the ticket.
- **Malformed input.** `SessionLogin::decode` bounds the version map (<= 64 entries), bounds every
  string (`MAX_STRING`, length checked before slicing) and refuses trailing bytes; `client_frame`
  caps a frame at `MAX_FRAME` (64 KiB); a bad frame closes only that connection
  (`bad_frame`/`bad_message`), never the process.
- **Logging.** `card_login` carries `ok`, `reason`, `version` and field `lengths` only; no ticket,
  session id or character-name value (existing `card_login_events_name_the_character_never_the_ticket`).
- **Cost.** The scan runs only when a 411 arrives: at most `MAX_SESSIONS` (16) `BTreeMap` lookups,
  each O(log tickets <= 64). Nothing on the tick path beyond the existing `card.take()/put`.
