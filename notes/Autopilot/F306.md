# F306 — Fix the T258 review blockers (commit 4007f1b)

Review: `lab/autopilot/reviews/4007f1b-T258.md`. The only BLOCKER was structural: the T258
test rig re-implemented the canonical gateway test helpers, so the shared encoders and the
fixture copy could drift from the real wire/body and the fixture rig. Findings 2–8 are
test-hygiene/evidence MINORs; 9 is a stale report measurement.

No production code changed. The full test suite was not run here (the integrator runs it).

## Finding-by-finding

### 1. [BLOCKER] [STRUCTURE] — duplicate test rig (fixed)

- **Packet bodies.** `interact`, `select` and `login` now come from
  `tests/common/gateway_vendor.rs` (which includes `gateway_packets.rs`) via `#[path]`,
  exactly as `l011_vendor_save_failure.rs` does. Deleted the local `interact`, `select`,
  `login` and the deliberate ticket difference: the local login used `t258-synthetic-ticket`,
  the shared one uses `synthetic-ticket`. The gateway's local (no account store) login path
  compares only the character GUID (`Gateway::parse_message` login arm); the ticket is not
  read unless `options.account_store` is set, which `test_support::options` leaves `None`.
  That is why the shared body is the right one, not a copy.
- **`Scene`.** The local `Scene` (struct + `new` + `dispatch` + `drain` + `enter` + `snapshot`
  + `break_next_save` + `repair_save`) is deleted. `test_support::Scene` is the owner and now
  carries the missing pieces once: `exchange` (send + drained replies), `drain`, `snapshot`,
  `break_next_save`, `repair_save`, plus the free `save_character` helper. `l011`'s private
  `save_character` copy is deleted too and calls `test_support::save_character`.
  `l011`'s older local `Scene` is pre-existing and outside the T258 diff; it still has
  `open_shop`-specific methods and was deliberately not reshuffled here.
- **`count_definition`.** Now `gateway_vendor::count_definition(&state.inventory, id)`.
- **Content file list.** New shared `tests/common/round70_content.rs` owns the round70 base
  copy and the 69 MB catalogue hard link (`build(root, label, extra)` + `source()` +
  `reference()`). `VendorFixture::new` and the T258 fixture both use it; T258 passes
  `extra = ["profiles.json"]` and `VendorFixture` passes `&[]` (its previous list).
  The T258-specific JSON (zones, stores, giver NPC, two quests, jobs) stays in the test.
- **Kept test-specific:** `quest`, `dialogue_choice`, `quest_reply`, `quest_end_reply`,
  `accept_quest`, `complete_quest`, the wire assertions and the two production-path drivers
  (`stage_pending_turnin`, `fixture_gateway`). The result is 1,142 lines (was 1,173): 4 rig
  helpers and the packet encoders are gone, but the server case now stages both sessions
  through the real dispatch path and the fixture JSON is unchanged, so the reviewer's
  "-150–200 lines / under 1k" estimate did not fully hold. No duplicate encoder remains.

## Security threat note (secure-code-guardian)

- **Surface:** test-only files plus a test helper. The exercised production path is the
  existing 49/14 turn-in. No parser, route, save ordering, economy, chat, role or session
  plumbing code changed (`git status` shows only test files; `test_support.rs` and the new
  `tests/common/round70_content.rs` are test-only modules, excluded from
  `spine_rules::production_sources` by the `#[cfg(test)] #[path]` registration).
- **Hostile client could send:** 49/14 with an arbitrary quest id, at any time, repeatedly,
  before completing an objective, with a full bag, or while another turn-in is pending. None
  of those fields choose the save path or the reward amount: `finish_turnin` requires
  `pending_turnin == quest_id` and a completed definition, and `apply_grant` is keyed by
  `quest:<character_id>:<quest_id>` inside the server-side `Gameplay` clone.
- **Why refused / no profit:** the failed-save test asserts the whole `Snapshot` and the
  on-disk good save are byte-identical after a save failure; the full-bag test asserts no
  client reply, no coin/item/XP/quest/pending change and no save write; both replay cases
  assert a second 49/14 pays nothing in-session and after reconnect. The verifier is the
  server's own staged grant, never a client-reported result.
- **Isolation:** a save error is returned as `Err`, never `unwrap`ped; `Server::step`'s
  `contain` ends the victim only. The test now also proves the victim's membership row is
  removed and B commits and saves afterwards.
- **Test-rig change is security-neutral:** the shared fixture copy and encoders only make the
  test read the same bytes/content the production path does; no new client-controlled input
  reaches the server.
