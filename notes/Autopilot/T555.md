# T555 - 35/10 notifications for warpstones and copper veins (Sonnet builder)

Paths are under `prototype/osfr-tools/`. Farm plots are not drawn on this tip (no plot content in `data/content`),
so the brief's "once that brief has merged" part is not built.

## What changed

- **`src/npc_notifications.rs` (new).** The one 35/10 `PlayerUpdatePacketAddNotifications` encoder and the content
  row `Notification` (`kind`, `image_id`, `state`, `name_id`, `subtext_id`, `hide_overhead`, `enabled`), with
  `validate` bounds. `quest_markers::encode_add_notifications` now delegates to it (bytes unchanged, the 9 packet
  tests and 15 marker tests still pass), so there is one element writer.
- **Warpstones.** `npc_spawns_extra.json` rows may carry `notifications`; the three Sanctuary-main stones (Sanctuary,
  Lakeshore, Snowhill) have one each. `world.rs` keeps them on the actor (`VisibleNpc`) and `draw_packets` sends the
  35/10 right after that actor's 35/2 in both visibility paths (`shared_view`, the shared fan-out the gateway uses,
  and `update`, the per-player batch).
- **Veins.** `HarvestNodeType.notifications` (mining_nodes.json, type `snowhill-copper-vein`) rides on
  `NodePresentation`; `apply_node_changes` hands it to `NpcVisibility::set_notifications` after the node is drawn.
  The old invented `copper-vein` pool sends none.
- **Tests.** `tests/npc_notifications.rs` (6 tests); `tests/support/quest_marker_packets.rs` `Marker` gained `kind`,
  `state`, `subtext` (the one decoder, not a copy); two refusal cases in `tests/world.rs`.

## Client evidence (IDA, 2026-10-28)

- Element reader `0x008db310`: u64 guid, u8 compact (+40), i32 (+28), then only when compact is 0: i32 +8, +16, +12,
  +20, +24, u8 +32, i32 +36; then u8 +41 **outside** the branch (read for both). Confirms the brief's layout.
- Count `0x0090aa90` (i32, refused when negative or past the bytes left); case 10 at `0x009320ac`, ctor `0x008d06d0`,
  body `0x009213e0`. The brief's "0x00932100" is the loop inside the case, not a function.
- Handler loop `0x00932100`..`0x009321d7`, stride 0x30. Per element: look the guid up (`0x00984960`), skip if absent.
  Compact: `0x00a90430(actor, +28)` places a minimap indicator. Full record: **`+16 <= 0` skips the whole
  notification** (`0x00932157`); otherwise, unless the u8 at +32 is set, `0x00960170(actor, +16, +8, typeString(+28))`
  draws the overhead icon; then `0x01025670(+16)` resolves the image (the `NotificationImages.txt` `#ID` key;
  -1 when absent) and `0x00a91800(actor, +28, image, +20, +24)` places the minimap indicator with `+20`/`+24` as locale
  ids (name, sub-text). `+36` nonzero goes to `0x0096d2e0`, `+12 > 0` is stored at actor+0x718, `+41` is never read
  by the handler.
- Brief corrections: the u8 at +40 is "compact", not "remove" (compact still places an indicator); `+41` is outside
  the branch.

## (R) choices and the open question for the native run

- **Sanctuary's labels are swapped against this client.** Its `IconId` is written at +8 and `IconState` at +16; the
  client keys the icon on +16 and skips a row whose +16 is 0. Sanctuary's warpstone and vein rows are (IconId 3 or 340,
  IconState 0), so sent literally they would draw nothing here. The content rows therefore put the icon id in **both**
  slots (`state` and `image_id`), (R). `NotificationImages.txt` (client baseline) has `#ID` 3 with a minimap layer
  (image 17) and `#ID` 340 with one layer (image 36595, no minimap flag; `0x01025670` still returns it).
  If the native run shows the wrong icon, the fix is data only (`image_id`/`state` in the two JSON files).
- `hide_overhead` is false and `enabled` true, as Sanctuary sends. Whether warpstones and veins should also show an
  overhead bubble in the original is unknown; set `hide_overhead` per row to get the minimap only.
- Value bounds in `Notification::validate` (image id 1..10000, kind 0..255, sub-text >= -1) are typo guards (R).
- Farm plots (IconId 36, IconState 61 in Sanctuary) are not built: for those rows +16 is already 61, which has a
  minimap layer; copy them with `image_id` 61, `state` 36 when plots exist.
