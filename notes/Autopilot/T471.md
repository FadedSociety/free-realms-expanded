**IDA wins over the brief (and over this note's first version) on the record's +0x30 byte.** The
brief calls it "catchable"; the first version of this note said "the brief matches IDA on every
point". It does not: the client treats +0x30 as "this record is the thing on the hook" (item
style), per the rows above. The field is now `RunFish::on_hook`. Sending 1 is still the right
choice for this task (see (R) choices), but it has the side effects listed there.

One note correction: `notes/Build Guides/Gameplay/Fishing.md` line 193 calls the record's sixth
field an f32; the reader moves it as a raw dword and case 18 does not read it, so it is sent as
`0` (same bytes).

## (R) choices

- 138/18 header flag = 1, header texture alias empty, record tint/texture aliases empty, +0x2c = 0.
  The review traced case 18 and found no read of the header flag (+0x0c), so its value has no
  visible effect (R).
- Header model 1673 (the lure). Drawn only on the `on_hook` = 0 path (`loc_B6D9F9`,
  `0x00b6da36`), so it is never drawn while we send 1; kept valid because that path reads it
  unchecked.
- One record per attempt, the head record, with `on_hook` = 1. Why 1: our hook 138/10 (first
  flag) sets +0xD9 (`0x00b6de7c`), and with the byte at 0 state 4 then refuses to send 138/7
  (`0x00b6cbd5`), so nothing could be caught. With 1 the reel gate is bypassed. Side effects of 1,
  both visible in the native client:
  - **At-hook spawn.** The fish appears already at the hook in state 6 (`0x00b6d4fe`,
    `0x00cd3a70`), with the line tied to its `hinge_2` bone and no lure; it does not swim to the
    hook.
  - **'Item Lost' on every escape.** `escape()` sends 138/10 0,0 then 138/14 0, on every path
    that uses it: an early reel (casting or nibbling), the reel-window timeout, the line-snap or
    missed catch roll, a fish with no bound size, the catch cap and a full bag. With +0x10 set
    the client shows `bbe_fishing_item_lost` instead of `bbe_fishing_fish_escaped`
    (`0x00b6df48`).
- Record grade = argmax of the species' `size_weights`, ties to the smaller grade
  (`(1..=4).rev().max_by_key`). Model = `fish_by_grade[grade - 1]`. The catch card keeps the
  size `settle_catch` rolls.
- Motion values and tail from the reference hint; integers would freeze the fish.
- Bounds: ids > 0 (client fact); motion `0.0..=100.0` (sanity bound only).

## Threat note (secure-code-guardian)

A hostile client controls only the 138/6 cast (handle, target vector, flag). The target is checked
finite and within the cast range before anything changes, and it only reaches 138/8's position.
Every 138/18 field is server-chosen: the id is the server's fish key, the models and motion come
from bundled content. A refused cast returns `Err` with no replies and no state change (tested).
138/18 goes only into the caster's `Change.replies`; it carries no handle, so relaying it to
another client would act on that client's own fishing entry. No reward, odds or item path changed.
