## Threat note (secure-code-guardian)

The code documented here takes client input on a TCP socket, so a hostile card client can send:
wrong or partial class ids, truncated or trailing bytes, oversized frames, a ping before login, and
repeated bad 411s. The documented path refuses all of them without changing state: `client_frame`
bounds the frame at 64 KiB, `ping_echo` requires class id 112 and exact length before echoing, a
refused 81 is written and the connection is closed (one ticket guess per socket, and a refused 411
spends no ticket), and a ping before login is unhandled. The echo is the same shape as the request,
so it is not an amplifier. Tickets and session ids are never logged (the launch-ticket `Debug` is
redacted and listener events name only lengths/ids). The account id is not a secret. This diff
changes none of that logic, so the threat surface is the same as the lead-signed T808 state.
