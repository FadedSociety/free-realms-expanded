spoof runtime targets or quest ids, replay a completed turn-in, or disconnect
and reconnect while the 49/13 is held. This change trusts none of it:

  NPC router; range, open-menu, job, prerequisite, reward-profile and
  once-per-character grant-key checks remain server-side.

  choose the turn-in actor. The 26/6 release uses the saved
  `pending_turnin_actor`; the 49/13 patch only replaces the server-built
  packet's speaker field with the runtime GUID already captured from the
  accepted 26/10 choice.

  now checks both (canary 5). A wrong job, wrong NPC, out-of-order Talk,
  duplicate 49/14 and replayed 49/2 all change no save byte and pay nothing.
- The reward is the existing content grant keyed by
  `quest:<character>:<quest>`; no client-reported result, quantity or item id
  reaches the payout. No inventory/coin path was added.
- No other player sees a new actor or transform: the three Legacy actors
  already spawned; the data change only adds their quest binding, name/end text
