## Blocker decision: infrastructure-only slice (review option B), not the rehome

The review's BLOCKER is correct: the 12 rows live in `npc_spawns_retired.json`, `world.rs` reads
only `npc_spawns_extra.json`, so production shows no Halloween prop; the old test built a 13-row
scratch table, and the record claimed a production table it did not build. F683 fixes the record and
the gate and keeps the T491 rule as the review's option B.

I did **not** rehome the 12 rows into a Halloween area (option A) because:

- T468 retired them on community evidence (Lxzxrus 9c5ef6b removes them as out of bounds;
  Sanctuary 10f129e spawns none) and its pin asserts every retired GUID is absent; a rehome needs a
  deliberate pin change.
- There is no recovered placement for these props at the Halloween areas: the rows are a housing
  demo cluster at x -2591..-2618, z 38..97 (the cake at z -461), while the client's Halloween areas
  are at x -1207..-1283, y -14, z 131..453 (`FabledRealmsAreas.xml:3156-3195`). Inventing
  coordinates and the ground height needs in-game validation, which only the lead's game window
  can give.

So option A remains an open lead/content decision, and the shipped path is deliberately unchanged
(no prop is spawned). Review MINOR 6 offered deleting the gate/test/tags when there is no rehome; I
kept them because the blocker's own fix explicitly allows the infrastructure-only slice with honest
docs/tests, deleting T491 would discard the gate the rehome needs, and no production behaviour
changes either way. `load_in_season_at` is kept as the fixed-clock seam; MINOR 6's optional fold
would move the wall-clock read into the `gameplay.rs` hub and grow it. The builder report at
`lab/autopilot/runs/T491-a3-20261025T020930Z/final.md` is outside this worktree and cannot be
edited; the test doc and `notes/Autopilot/T491.md` carry the correction.

## Security threat note (secure-code-guardian)

The change touches no client input parsing, save, coin/item, reward, role, chat or session plumbing.
The only inputs the rule reads are server content files at load: `client_areas.json` seasons and a
row's `season` string. A hostile or corrupt content file can only fail the load closed (the error
names the spawn GUID) or drop the row; it cannot add an actor, and no packet or command reaches
`retain_in_season`. The tests only read the shipped content and write scratch directories under
`CARGO_TARGET_TMPDIR`.
