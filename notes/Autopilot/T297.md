## Security note (secure-code-guardian)

Attack surface: a hostile client can send a forged node GUID in 26/8, click while busy or
out of range, send `realm mine` / `realm harvest` chat, or send 39/x frames while a run is
live. Why it is refused:

- The node GUID is looked up in the per-player `GatheringNodes` set (`is_node`), decoded,
  and admitted by `admit` (shown, range, busy, unlocked, active job) before any engine;
  `payout_fits` is checked before the staged begin. Forged ids never reach the engine.
- The developer path is still behind `dev_tools`/role (`may_run` /
  `command_refusal`) and the existing `!self.dev_tools` lines; this slice does not widen it
  and does not add a caller.
- `begin_gather` does not unwrap the engine; a missing content file returns the existing
  refusal string (developer path) or the existing "Gathering is not available" string
  (node path), with no clock or engine change.
- Every start path is staged (node clone; `handle_in_world_inner`'s clone for chat), so an
  error or refusal changes neither live state nor the save. Rewards still come only from
  `apply_type8`'s server-side transaction; no client result is trusted.
- Deleted guards were unreachable behind S8's live-movie gate, so removing them does not
  open a path to two simultaneous runs. The encounter guard remains because encounters are
  not movies.
