## Threat note (hostile client)

`secure-code-guardian` applied to the combat reward/prize path. No new client
parsing code was added; the existing parsers and gates are reused.

- **Forged 167/1/2 Play** with an unknown, zero, huge or unlisted id: the
  catalogue lookup refuses with "That activity is not available." before busy,
  job or level checks; no encounter, coins, items or save change (existing
  `activity_portal_route` plus T282 test 4).
- **Play at level 4 or on a non-combat job**: the portal's existing
  `level_refusal` / combat-job gate returns the existing chat messages and
  changes nothing; T282 test 4 snapshots the save bytes before and after both
  refusals.
- **Forged 41/108 Go** with a fabricated encounter/instance or a replayed
  start-screen packet: `take_pending_battle` requires an open marker screen and
  the 8 m marker radius; otherwise it is inert. The existing
  `field_battle_roster` tests cover forged Go, out-of-reach Go, knockout Go and
  a closed screen.
- **Client-reported kills or wins**: the payout advances only from the
  server-owned encounter state when its own attack path reaches the won phase;
  a melee or `realm win` replay on a won run pays nothing (T282 tests 3 and 6).
- **Item ids and quantities**: the client sends none for this content. The prize
  rows are fixed server data; the loader rejects non-positive ids or quantities
  over 100, and T243's whole-bundle preflight refuses a start whose previewed
  bundle cannot fit the player's bag. T282 test 5 asserts the refusal leaves
  the 4096-stack bag, coins, encounter and save bytes unchanged and that a bag
  with four free stacks starts.
- **Duplicate result/Close**: the same won run cannot pay twice, and a
  reconnect drops the abandoned run and returns the player to the marker; T282
  test 6 proves one payout across save/reload.
- **Cross-player**: encounters are per session; one player's hit and win never
  change the other's snapshot, and a malformed Play on one session leaves the
  other running and payable (T282 test 8).
- **No client strings or quantities are trusted**: the marker nameplate is a
  locale id, and no in-game player name or chat text appears in the content or
  tests; the "Owner Field Notes" provenance label is the same citation used by
  existing content rows.
