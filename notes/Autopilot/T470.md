# T470: 90 named NPCs drawn at Sanctuary-main's placements

The brief's 96 named NPCs are all drawable at this tip: **6 were already drawn** by
T467 (Sam Potts, Poe Tatters, Bry, Garrison Gold, as `legacy_data` rows) and T500
(Dani, Honey, also `legacy_data`). This task draws the remaining **90** and leaves
their quests disabled. No production Rust changed; no hub file changed.

## Retry (attempt 3): what broke and what this run changed

- The patch applied on tip `18f2fcdc` with four rejected hunks in
  `npcs/sanctuary.json`, all for Dani `9500000467` and Honey `9000000107`.
  T500 (`76eed5ee`) had already moved both rows to `legacy_data` at the same
  Sanctuary-main position/heading, with model, client name id and sources.
  The rejects are obsolete: porting them would overwrite T500's rows and hide the
  actors behind a second body with the same actor id. The two extras rows the patch
  added for Dani and Honey were **removed**: both would have been a second AddNpc
  actor `9500000467` / `9000000107` beside T500's drawn regional row. Rejects and
  `.orig` files were deleted.
- Integration failure from attempt 1 (`tests/content_npcs.rs:65`,
  `regional_npc_batch_and_resolved_job_references_validate`) was the temporary
  `ContentDb` adapter's `validate_sources` refusing the new `reference` kind. The
  patch adds `reference` to that test-side allowlist and to its position-source
  rule. The kind lives only in `field_sources` and in the extras rows; the
  regional top-level `source` arrays keep the production `SourceTag` kinds
  (`client`/`wiki`/`reconstructed`/`legacy-data`), so `ContentDb::load` is unchanged.
- Count pins were re-derived for 90, not 92 or 96: extras `2,675 -> 2,765`
  (T468 left 2,675), regional total stays 1,205, `reference_data` rows 90.
- This run recomputed the selection from the read-only inputs (below) rather than

## Threat note (secure-code-guardian)

A hostile client can send 26/8 with any u64 target, from any position, repeatedly.
The task adds static NPC rows, not a new parser: `check_range` looks up the
regional row by id and refuses a target outside `INTERACTION_RADIUS` (12 m) or in
another zone; an unknown id is refused. The test sends the same forged click from
the old POI position and asserts the serialized save and `GameplayState` are
byte-equal before and after, so the refusal consumes no menu, offer or counter.
No item, coin, reward or quest flag is granted by a click; the eight vendor-role
NPCs keep their existing stock checks. The extras `content_key` map is server-side
data; a client cannot choose a different regional row than its actor id names.
No name, chat text or player-controlled string is written to content.
