# T359 - S14: one field-AI locomotion path and staged field reloads

2026-10-21. Pure refactor of the overworld field AI and the two developer
field reloads. No packet, timing, radius, aggression, reward, save, busy or
selector behaviour changes; the eight original ordered-wire pins passed on the
unmodified tip, and all nine pass again after the conversion.

## What changed

- `src/encounter/field.rs` (owner; LF, **1,033 -> 1,082 lines, +49 net**):
  - `EncounterEngine::staged<T>` is clone, run, swap on `Ok`. Both reloads use
    it and the manual field-by-field rollback is gone.
    - `reload_field_battles`: drops the old battle dungeons and rows on the
      clone, re-reads with the same bounds/validation, then clears
      `pending_battle` and the marker `wander` map. A refusal drops the clone,
      so content, battles, resolved behaviours, the start screen and the walks
      are untouched.
    - `reload_field_enemies`: keeps the pre-load GUID vector and builds the
      despawn packets before staging; on success only, loads, then runs the
      per-GUID `moving` / `attacks` / `skills.forget_target` cleanup and appends
      `field_initialization()`. A refusal returns `Err` and neither the packets
      nor the cleanup.
  - Free helpers at the bottom of the module, used by `tick_wanderers_for` and
    `tick_field`: `heading`, `advance`, `stand`, `walk`. `advance` returns
    `Result<snapped, integrated>` so the caller's "home leash before moving"
    check keeps its old precedence even when the same step would also fail the
    ground check (`Err` carries the integrated point the old code checked).
  - Documented exceptions kept inline: the `WANDER_RADIUS` waypoint-arrival
    heading, `kite_turn`'s negated facing (untouched in `encounter.rs`), and
    the bare `Ground::snap` walk in `tick_wanderers_for`.
- `tests/field_ai_packets.rs` (new, 9 tests, 824 lines): ordered frame table
  (movement position/heading bytes, 35/8 ids, 35/5 HP, 38/1 player HP, 32/7
  hit, 62 rules, 41/132/133 flags) for chase start, non-axis heading, stop in
  reach then attack, evade/return/heal, leash refusal, leash-before-ground
  precedence, ground refusal, marker walk + notice, marker arrival/pause/resume.
- `tests/field_reload_atomicity.rs` (new, 4 tests, 339 lines): malformed
  battle file leaves battles/dungeons/behaviours/pending/wander unchanged;
  same-file reload keeps `battle_spawners`; omitted battle dropped; mid-fight
  reload refused. Each drives the real `EncounterEngine::reload_*` methods the
  `realm reload` path calls and checks state/spawners before and after.
- Hubs, `SharedFieldState`, `encounter/shared.rs`, the gateway, saves, content,
  trade and Cargo are untouched. Spine: hubs net **0**.

## Security note (secure-code-guardian)

Attack surface on this slice: the reloads are developer/role actions, not
client packets; the only untrusted input they read is an operator-supplied
content file. A hostile client can send arbitrary positions and combat/field
actions, which still enter through the unchanged `tick` / `attack` /
`shared_*` paths.

- Non-finite or out-of-bounds player positions are refused by `tick_encounter`
  before `tick_field`; the new helpers add no parsing, no `?`, no panic and no
  per-player state, so a bad actor cannot propagate out of the shared tick.
- A malformed reload file is bounded (128 KiB), schema-checked, GUID-checked
  and behaviour-resolved on a clone; `Err` drops the clone and the pre-built
  despawn packet list, so a refused file changes neither the live field nor
  the wire. No client-supplied id or quantity is trusted by the reload.
- The despawn list comes from the server's current roster, never from the
  file; `staged` introduces no `Rc`/`RefCell`/`Arc` side table that could
  escape a refusal (the content `Arc` is only made mutable on the clone).
- No new selector, no new grant/reward path, no save write.

## Deliberate deviation noted

The notice-face used to divide its facing by `near.max(0.01)`. `heading`
divides by the true 3-D distance above a 1 mm coincidence guard and the caller
sends a zero facing below it. The direction is the same (the client normalizes
X/Z before yaw); only a sub-centimetre magnitude changes, and no gameplay
decision reads it. The golden pins cover the normal notice case; this edge is
not reachable in the pinned fixtures.
