## (R) rules

- One row per item definition; `fixture_definition_id` is the item id except the seven captured
  rows, which keep their captured ids. The generator refuses a collision with a captured fixture
  id.
- (R) A placement-derived row exists only when the item's **own** `ModelName` equals the reference
  `ASSET_NAME` (case-insensitive) and that name is in `Models.txt`. The reference `Id` column is
  not our item id; its extra ids are runtime-generated Lxzxrus items that collide with real client
  items.
- (R) The T518 item-derived row wins when both sources name the item, so the 12 added rows are the
  only placement-sourced rows and item 16874 keeps its T518 model 564.
- Placement `TYPE` is a precondition, not a row field: only `TYPE 1` assets source fixture rows,
  and the fixture definition still hardcodes placement type 1 (T783). No other type exists in the
  reference today.
- An added row takes `TextureAlias`/`TintAlias`/`Icon.TintId` and `category` from the item's own
  pinned row (the boombox rows carry their own texture aliases). The reference supplies only the
  model name.
- Surfaces (Type 17, `Param1 2`, categories 51/55/59/60) are not fixture rows: no surface apply
  path or surface store is implemented, the reference gives them placement type 2 and model id 0,
  and our loader refuses model 0.

## Security threat note (secure-code-guardian)

- **What a hostile client could send.** Only family 127 decorate requests: a selection id,
  fixture guids and transforms (127/1, 2, 3, 4, 5, 6). None of them names an item definition, a
  model id, an alias or a tint; the table is server content and the row is chosen from the
  inventory instance the server already owns. `offer` still requires an owned single-unit item on
  the actor's own editable lot; `place` still requires a resolved selection and an owned instance.
  The 12 new rows are real items already in the pinned item data and are reachable only by owning
  that item.
- **Why bad data is refused.** The 467 KB table is read once, bounded at 4 MiB + 1, parsed with
  `deny_unknown_fields`, and validated whole: schema version, row bound 4,096, positive ids,
  unique item and fixture ids, non-negative tint and bounded aliases. The generator refuses a
  repeated reference id, a malformed line, an empty asset, a duplicate item/fixture id and any
  zero model id before it opens the output; a refused run creates no output and leaves an existing
  output byte-identical (tested). A refused table fails the housing session load (fail closed).
- **Economy.** Placement metadata only: no grants, prices, stock, coins or rewards. Pickup returns
  the same item definition and tint it consumed, so conservation is unchanged. No item id is
  invented; the five reference ids absent from the pinned data are refused, not generated.
- **Review risk from attempt 1 is gone.** The old join could map an unrelated item (military boots)
  to a furniture model. The new join requires the item's own model to be the reference asset, so
  no look-alike placement of an unrelated item can be introduced.
