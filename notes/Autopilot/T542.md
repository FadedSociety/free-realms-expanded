## Evidence (IDA, 2014 client)

- 49/15: ctor `0x00a86580` stores the id at `this+3`; payload writer `0x00a91730` (queried again this
  run) calls `sub_A8F860`, copies `*(this + 3)` into a local, and `sub_7CC400` writes `v6 = 4` clamped
  bytes from it into the packet. The request is `[49,0,15,0,0,0]` + one `i32` id, which is what
  `quest_journal::decode` reads.
- 147/1: wrapper reader `0x00be6f20` → row reader `0x00be5360` (count then per-row fields). The layout our
  `encode` writes (key = ProfileId, ProfileId, QuestId, IconId, BadgeId, Title, Description) is pinned
  byte-for-byte against our own capture (`tests/fixtures/job_browser/op147-sub1-capture.bin`, sha256
  ab3ec4f7…712d3e) by `job_browser::packet_matches_the_capture`; the column mapping is T497's (getter
  `0x00ceab40`, Lua `JobBrowser:StartJobQuest` → `Ui.StartBreadcrumbQuest` `0x00c18aa0`). The client
  sends the row's QuestId, i.e. the original id the crosswalk maps.
- Crosswalk: `breadcrumb_quests.json` also lists 1881 "Snowhill Soccer Field" → 3140001, so the POI
  breadcrumb and the Jobs window (1965) now reach the same enabled record; the loader only requires
  originals to be unique (T497's flag).

## Threat note (secure-code-guardian)

A hostile client can send any `i32` in 49/15 and any 49/2 accept / 49/14 end reply id. 49/15 is answered
only through the existing crosswalk: an unlisted id (including 0/negative) gets one refusal chat line and
changes nothing; a listed id whose regional quest is disabled is refused the same way (tests
`job_browser::start_quest_with_a_disabled_or_unmapped_id`, `zero_or_negative_breadcrumb_is_refused_politely`,
and the new `completed_become_a_is_refused_again` snapshot the saved state). An enabled listed id can only
make the engine's normal 49/1 offer; accepting still runs the engine's own prerequisite/level/limit gates,
and completion pays only the server-authored 5-coin row — no client-reported outcome, quantity or id is
trusted. The records live in content, are bounded by the loaders (`jobs.json` union, one objective, 5
coins), and a refused request changes no state (asserted). The 147/1 list stays static, bounded (64
rows/64 KiB) and carries no player state.
