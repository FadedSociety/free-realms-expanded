# D009: SkillEffects (S12)

2026-10-18

## Result

Replaced `EncounterEngine`'s three hand-written skill maps (`skill_dots`,
`skill_stuns`, `skill_buffs`) with one `SkillEffects` owned by
`src/encounter/skills.rs`:

- `dots: BTreeMap<(u64, i32), SkillDot>` (target guid, ability definition);
- `stuns: BTreeMap<u64, u64>`;
- `caster_buffs: BTreeMap<i32, SkillBuff>` (definition id, no guid-0 sentinel);
- `target_buffs: BTreeMap<(u64, i32), SkillBuff>`.

`SkillEffects` owns `clear`, `forget_target`, `expire`, `stunned`, `damage`,
`mitigation`, `crit_bonus` and `crit_damage_bonus`. All six clear/forget sites
and the two hand-written stun reads call it; `initialization` keeps its
`SharedFieldState.stuns.contains_key`. `SharedFieldState.buffs` is renamed
`target_buffs`. `with_shared_fields` now swaps `dots` (per sender), `stuns` and
`target_buffs` by value; the old caster-buff clone/merge dance is gone and the
evade/defeat dot purge after it is unchanged.

Preserved on purpose: per-sender field DoTs survive a job change or knockout;
`receive_field_damage` never clears skill state; `clear()` stays field-wise and
never touches energy or cooldowns; the stun animation 1401 is still emitted;
target buffs stay shared and caster buffs stay personal.

## Step 0 pins (green on unmodified code)

- `tests/shared_field_state.rs::caster_buff_is_personal_and_target_debuff_is_shared_until_expiry`:
  two players on one `SharedFieldState`, A casts a caster buff and a target
  debuff. B is unaffected by A's caster buff, the debuff applies to either
  attacker until its 2 s expiry, and A's caster buff survives `shared_motion`
  and `shared_effects` (A's next hit is still doubled).
- `tests/encounter_job_skills.rs::knockout_clears_skill_effects`: caster buff,
  target debuff, DoT and stun are all observable, then the player is knocked out
  and revived; the DoT no longer ticks, the stunned enemy attacks again, and the
  player's hit is unbuffed and unde-buffed.
- `tests/encounter_job_skills.rs::reset_session_clears_skill_effects`: same four
  effects, reset, then no DoT, a live enemy and a normal hit.
- `tests/shared_field_state.rs::refused_shared_ability_leaves_skill_effects_untouched`
  (added with the refactor): A's caster buff and a shared target debuff stay
  active after B makes one `Err` shared cast (invalid position) and one 286
  refused cast (unavailable ability); A's next hit is still 2x caster x 2x
  debuff = 400. This pins the `with_shared_fields` restoration on both error
  paths.
- Job change: existing
  `tests/encounter_job_skills.rs::critical_buff_affects_chance_and_damage_and_clears_on_job_change`.
- `tests/field_enemies_runtime.rs::kill_then_respawn_forgets_skill_effects`:
  kill with a target debuff, respawn, then no DoT, no stun and a normal hit.
- `tests/field_enemies_runtime.rs::evade_completion_forgets_skill_effects`: pull
  the actor home, heal, then no DoT, no stun and a normal hit.
- `tests/field_enemies_runtime.rs::reload_field_enemies_forgets_skill_effects`:
  hot reload, then no DoT, no stun and a normal hit.

The pins were written first and passed on the unmodified engine. During pin
development the 10,000-HP fixture enemy was killed by its debuffed DoT before the
knockout; the final pin gives it 20,000 HP so the knockout, not the DoT, ends
the effect state. The same tests stayed green after the refactor.

Skills applied: Ponytail (full, smallest working change), ponytail-review on the
finished diff (no production cut found; the three field pins keep their explicit
setup so each scenario reads on its own), secure-code-guardian (threat note

## Client evidence

No opcode, packet field layout or enum changed. The only packet involved is the
existing 36/10 ability request parsed by `shared_action`; the client writer is
`0x00a342e0` and the sender is `0x00a35150`, per
`notes/Build Guides/Gameplay/Combat and Abilities.md` lines 207 and 263. Stun
animation 1401 is `com_stunned` in the client animation resources (line 236);
stunned is client status bit 6 (line 220) and is in the cast-gate mask
`0x1542c6`. This refactor changes where the timestamp lives, not what the client
sees.

IDA could not be used for a fresh check: `lab/autopilot/ida-broker.pid` names PID
6204, which was not running, and the request queue held 12+ unanswered requests
from 22:00 to 22:26. A read-only `strings "com_stunned"` query sat in the queue
until it was cancelled. The addresses above are the recorded native-guide
provenance; no new field was guessed.

(R) Rules retained, not changed: the strongest caster modifier wins; repeated
casts refresh one entry per target/definition; DoT cadence and duration come
from ability content; target buffs modify damage taken by any attacker; caster
buffs modify only their owner's outgoing damage, incoming damage and crit
numbers.

## Security note (secure-code-guardian)

A hostile client can send a forged 36/10 with any bar type, slot, mode, target
GUID or position. The existing parser accepts only the exact 24-byte targeted or
32-byte ground shape, bar 1, slots 0..=9, known field GUIDs and the character's
current zone. `job_ability` then checks the server-loaded ability content, fight
phase, player health, cooldown, energy, the 600 ms swing gate, target
liveness/range and the summoner shield. Buff, DoT and stun multipliers,
durations and intervals come from `job_abilities.json`, never from the packet,
and no client quantity reaches a reward. This change adds no parser, selector,
reward, item, trade or save path; a refused shared action restores the swapped
field and skill maps before returning its error, so it cannot consume a stun,
DoT or buff. `malformed_and_unknown_targets_do_not_mutate_or_consume_swing` and
`two_players_share_hp_and_keep_independent_cooldowns` pin that. Skill state stays
session-only, as before.

## Checklist

1. **Refusal changes nothing.** No new refusal path was added. The existing
   `with_shared_fields` restores every swapped map before returning the
   action's `Result` on both `Ok` and `Err`. A new pin,
   `refused_shared_ability_leaves_skill_effects_untouched`, makes one `Err`
   cast and one 286 refused cast, then asserts both the personal caster buff and
   the shared target debuff still apply. The pre-existing shared malformed and
   duplicate-cast tests also pass. New effect-clearing sites are outcomes
   (knockout, kill, evade, reload, reset), not refusals.
2. **Rollback covers all state.** `SkillEffects` is plain owned `BTreeMap`
   fields inside the cloneable engine / runtime; no `Rc`, `RefCell`, `Arc` or
   side table was added. `with_shared_fields` swaps whole maps by value and
   restores them. Session staging in `gameplay`/gateway is untouched.
3. **Apply deltas, never restore old snapshots.** No payout, inventory, coin or
   position code was touched. The shared swap restores only the per-sender
   effect maps it removed, not player state. Not applicable to an economy
   transaction.
4. **Busy rules are mutual.** No new activity or busy gate; `occupation.rs` is
   untouched.
5. **Every entry path is gated.** No new entry path. `job_ability` and the
   shared ability route keep their existing server-content, phase, health,
   cooldown, energy, range and target checks.
6. **Reachable in production, tested through it.** The refactor is used by the
   real `EncounterEngine::job_ability`, `tick`, `shared_job_ability`,
   `shared_effects` and `shared_motion` paths. The pins call those public
   methods, not a copied implementation. `app_fuzz` covers routed handlers.
7. **Survives reconnect.** Skill effects are deliberately session-only in this
   design; nothing was moved into the save. The task says to preserve that, and
   reconnect does not clear or resurrect them. Not applicable as new persisted
   state.
8. **Every exit path restores the player.** The knockout, reset, kill/respawn,
   evade and reload paths are pinned; the refactor does not change exit,
   revive or zoning logic.
9. **Economy safety.** No rewards, items, coins, grants or client-reported
   results changed. Effect values are server content ids and numbers; no client
   quantity is trusted.
10. **Wire format.** No fields added, removed or reordered. The existing 36/10
    parser and byte-level tests are unchanged; writer `0x00a342e0`, sender
    `0x00a35150`. A new byte test is not applicable because there is no new
    bytes.
11. **Unique ids.** No new instance/GUID/lifecycle id. Definition ids key the
    caster buffs and the `(target guid, definition id)` keys; no id is reused or
    aliased to the public world.
12. **Others see changes.** Stuns and target buffs remain in `SharedFieldState`
    and are seen by every participant exactly as before; caster buffs are
    intentionally personal. The two-player pin asserts both halves.
13. **Content works end to end.** No content changed. The existing
    `medic/warrior/wizard/ninja/brawler/archer_wins_using_skills` tests still
    defeat the field pack; the six clear/forget pins assert the final
    observable outcome, not an intermediate flag.
14. **Values live in data.** No new timeout, window, cap or tuning constant.
    Durations, intervals and multipliers still come from `job_abilities.json`.
15. **Canaries break production code.** The stun canary changed the production
    `SkillEffects::stunned`; a real stun test went red; exact bytes were
    restored and it passed.
16. **Hands off session plumbing.** `src/bin/osfr-gateway.rs` and
    `src/gateway.rs` were not edited. Only encounter modules and their tests
    changed.
17. **One player's error never stops the server.** No shared-tick code or error
    propagation changed; `with_shared_fields` still returns `Result`, and no new
    `?` was added to a tick. Per-player behavior is unchanged.
18. **A type's rules live on the type.** `SkillEffects` owns the four maps and
    every rule that decides them: `clear`, `forget_target`, `expire`,
    `stunned`, damage, mitigation and crit accessors. The struct doc says the
    state is session-only and which parts are personal vs shared. A future field
    must be handled in those methods and the doc says so.
19. **Hot paths stay cheap.** The shared path no longer clones caster buffs
    twice per action (the old dance cloned them on swap-in and merge-out). It
    swaps maps by value and calls `SkillEffects::damage`/`mitigation`, which
    scan only the usually-empty caster/target maps. Per shared packet/tick cost
    is lower than before; no whole-state clone was added.
