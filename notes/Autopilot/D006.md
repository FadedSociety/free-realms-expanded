## Security note (secure-code-guardian)

Threat: a hostile client controls only the i32 recipe id in 26/24. It can send
an unknown, unlearned, wrong-job, out-of-range or under-material recipe, a
truncated body, or a non-finite position. All those refusals live in
`recipe_book::start` and are unchanged; every check still happens before any
mutation. The type unification does not add a field or a path from a
client-reported result into a grant: `CraftTransaction` is still built only by
the server-owned movie services from content and server-verified victory. The
opening-actor lookup only maps a server-loaded trigger id to a job; no id is
taken from the client. No save format or persisted state changed.
