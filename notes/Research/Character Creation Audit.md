## First-world appearance dependency

Run `client-baseline-20261008T065152Z` contains the actual successful manual submission and saved identity, then a first-profile asset failure. Its log requests `human_m_head_caucasian_08.dds` and the loopback URL `/642/human_m_head_caucasian_08.dds.z?2961482716`; repeated404 responses precede a clean client exit. The original manifest requires raw CRC32 **2961482716** and compressed-envelope length8996. The saved appearance is preserved; no different texture or skin was substituted.

All108,547 supplied catalog entries and supplied loose filenames were checked. This texture is absent. The unmodified pinned DbgPack parser then scanned all ten public launcher packs and eight different public Git-LFS world packs from [Bik182/Free-Realms](https://github.com/Bik182/Free-Realms), revision `9dec1fae7dcf2033bb448085123b36f5253412cc`, using bounded anonymous HTTP206 ranges. None contains the missing texture or any of the18 unique logged missing assets. The exact current CDN URL returns404 and the old `osfr.editz.co.uk` host no longer resolves. This is a bounded search result, not proof that no surviving copy exists anywhere. Range checks establish readable indexes; they do not establish the whole remote pack's advertised hash.

The current public [SkinTone table](https://opensourcefreerealms.com/client/Resources/CharacterCreateCustomizationSkinTone.txt) provides a concrete compatibility correction: it removes eight extra creator rows that select skin7/8 and preserves all24 standard skin1–6 choices. The public [FaceType table](https://opensourcefreerealms.com/client/Resources/CharacterCreateCustomizationFaceType.txt) removes four extra face rows and preserves12 standard choices.
