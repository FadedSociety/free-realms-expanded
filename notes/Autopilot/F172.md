# F172: Fix the D005 (2db9408) review blockers

## Review findings

1. **BLOCKER, malformed 36/10 packet. Confirmed.** The D005 test sent
   `[36,0,10,0] + u64 + i64` (20 bytes), a length neither the client writer
   `0x00a342e0` nor `abilities::unsupported_cast` accepts. The S6 movie-gate
   test now sends the client's 24-byte mode-0 form
   `[36,0,10,0] + i32 bar + i32 slot + i32 mode(0) + u64 target`. A separate
   test (`ability_request_is_the_clients_24_byte_mode_zero_form`) sends the
   same bytes in a bundled request with no movie active, so a malformed shape
   would surface as `malformed ability cast request` instead of hiding behind
   the gate.
2. **BLOCKER [STRUCTURE], duplicate movie drivers. Confirmed and fixed.**
   The packet-path tests moved from `src/gameplay/s6_characterization.rs` to
   `tests/s6_characterization.rs`. They now drive the real Gateway path and
   reuse `tests/common/forging_movie.rs`, `tests/common/cooking_movie.rs` and a
   new shared `tests/common/smelting_movie.rs`. The smelting sequence was
   removed from `tests/smelting_gameplay.rs` and `tests/opening_gateway.rs`,
   which now use the shared driver. `prepare_terminal`, `payload`, `instance`
   and the bounded forging/smelting transcripts are gone from the private
   module.
3. **MINOR, direct applier bypasses the real path. Partially not constructible
   as asked; addressed and explained.** The real `39/14` terminal is now driven
   in `tests/s6_characterization.rs`
   (`smelting_completion_advances_opening_craft_and_grants_every_bar`), which
   asserts the opening count delta and the 5-bar inventory grant. The review's
   "scratch content with two 21785 product rows" cannot be built without a
   production schema change: `recipes.rs::RecipeOutput` and
   `smelting.rs:511-516` model exactly one product row; a `recipes.json` copy
   still yields a one-element `grants` vector. The only way to execute the
   summing branch is the production applier with a two-row transaction, which
   `opening_craft_quantity_sums_every_copper_bar_grant_row` does (it calls
   `Gameplay::apply_smelting` itself, not a copy of its logic). That test stays
   as the documented exception.
4. **MINOR, bonus-drop test did not test "only". Confirmed and fixed.** The
   positive drops are asserted through the Gateway, and two negative cases now
   send the same interaction with the wrong job and with the stage unaccepted;
   both assert a byte-equal snapshot and an unchanged opening count. A canary
   that removed the drop guard made the wrong-job case pay 2739/879 and the test
   failed.
5. **MINOR [PONYTAIL], dead 5/1 unwrap. Fixed.** `chat_texts` in the private
   module no longer has the 5/1 branch (its callers get unwrapped
   `Gameplay::handle_in_world` replies). The branch now lives only in the new
   Gateway test helper, where it is live: `Gateway` wraps every inner reply.
6. **MINOR [PRE-EXISTING], real NPC menu bypasses the movie gate. Kept as a
   reported lead decision, not fixed here.** `handle_npc_packet` still runs
   before `handle_opening_inner`, so a real regional NPC answers 26/8 during a
   Forging movie. The characterization test
   `real_regional_npc_reaches_the_npc_router_before_the_movie_gate` stays in the
   private module because it needs `npc_visibility`/`npc_interaction` and an
   active movie away from a station; it cannot be driven through the Gateway
   without inventing a cross-zone movie. This remains a production behaviour
   decision for the lead (refuse 26/8/26/10 for every actor while a movie runs,
   or move the movie check ahead of the NPC router). The review itself defers it
   to a separate production commit.

## Security note (secure-code-guardian)

Attack surface: a hostile client can send a truncated `26/42` leave, a spoofed
NPC GUID in `26/8`/`26/10`, any `26/13`/`36/10`/`42/3` during a movie, finish a
movie from outside the station, trade ingredients away mid-movie, or spam the
gathering actor with the wrong job or before the objective is accepted.

Why each is refused and changes nothing:

- The movie gate tests assert the exact refusal text **and** that
  `Gateway::snapshot()` (character plus the whole `GameplayState`) is unchanged
  for every packet, including the now-valid 24-byte `36/10`.
- The malformed leave is sent as a bundled child so the handler error surfaces;
  the test asserts the exact `invalid <job> leave request` string and an
  unchanged snapshot.
- Station refusals (wrong job / not accepted / shortage) assert the exact text
  and snapshot equality.
- Outside-station and changed-ingredient terminal attempts assert the exact
  production error strings through the bundle path and an unchanged snapshot.
  The changed ingredients are applied on the live inventory through the real
  `Gateway::adopt_trade_inventory` seam (a trade settlement is a legitimate way
  for the inventory to change under a movie), never by mutating the applier.
- Bonus drops are paid only on newly counted, accepted server progress for the
  active job; the negative wrong-job and unaccepted cases assert a byte-equal
  snapshot and a zero count. The canary proved the test detects a removed guard.
- Rewards still come only from the server-owned movie transaction
  (`smelting.rs` `FRServer_GameWon` -> `SmeltingTransaction` ->
  `apply_smelting`). No client-reported score or result creates a grant in any
  test.

No new client input reaches a new parser; this is a test-only change.
