## Range summary

The first part implements an ordered tree and a block-backed free list (00719de0–0071a510). The block field at `piVar[6]` changes down when a slot is popped (0071a340) and up when a slot is returned (0071a3b0); returning a slot frees the block when this field reaches its capacity field `piVar[5]`. The evidence therefore identifies it as a free-slot count, not a live-entry count. The list wrapper adjusts `this` by 16 bytes and jumps to the pop/push bodies (0071a420–0071a430). Its RTTI name ties the specialization to `SoeUtil::List<ClientAccountManager::AccountInfoGameCharacterAndFriendsDetails,8>`; the shared block-container's own type remains unknown.

`ClientAccountManager` construction and teardown are at 0071a530 and 0071a8f0. The client-account interface has its own constructor/destructor at 0071cec0 and 0071cb20. Character-creation code filters customization records, copies matched record fields, emits item/category UI data, groups first-name and surname data, and dispatches the `CharacterCreate` and `CharacterNameScreen` events (0071b000–0071b2b0, 0071d030, 0071daa0, 0071e770, 0071efe0). The screen setup routine at 0071efb0 requests `./Resources/CharacterCreate/`, sets a byte latch, and calls the name-data builder; it does not check a load result or prove completion.

The range also contains reference-count and asset lifetime code (0071ac50–0071af40, 0071b520–0071bcb0), aligned storage policies for arrays (0071b620–0071b810), and inline `ClientLuaParam` arrays (0071b880–0071b8a0, 0071c930–0071cdc0). The two array virtuals at 0071ccc0 and 0071cdc0 operate on two arrays and helper routines, but the pseudocode does not establish source/destination direction or whether payload ownership is copied or transferred. The random range helper at 0071ad50 uses an inclusive upper bound only when lower <= upper; reversed-endpoint behavior is unresolved.
