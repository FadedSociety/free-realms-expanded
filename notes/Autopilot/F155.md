## Changes

- **Blocker 1 (activation before outfit repair).** `Profiles::select` was split into
  `activate` (validate unlocked, set the active job) and `activation` (build 38/21).
  `stage_job_selection` now activates, repairs the outfit through `ensure_outfit`,
  validates required slots, and only then serializes the activation from the repaired
  inventory. The client reader is `0x0091b080`; `ProcessProfileSwap` (`0x00bfb620`)
  rejects a group missing a required slot. The same select-before-repair order existed
  in kart entry, derby entry and `restore_job`; all now use `activate`, repair, then
  `activation`, which is the same root-cause fix for the other callers of the helper.
  Reply ordering (38/21 first) is preserved.
- **Blocker 2 (menu consumption escapes rollback).** `NpcInteraction` was
  `Arc<Mutex<_>>`, so a cloned `Gameplay` shared the open menu. It is now split into
  immutable `NpcContent` behind an `Arc` (NPC, price and vendor tables) and an owned
  per-session `active` menu. `Gameplay` owns `Option<NpcInteraction>` directly and the
  `Mutex` is gone. `src/gameplay/npc.rs` stages a selection on a cheap interaction
  clone, assigns it back into the staged `Gameplay`, and consumes the menu only there;
  a failed later child drops the clone and the live menu is untouched. The cached
  `shop_items` copy was removed: buy-stock checks read the immutable content.
  `close_dialogue`/26/6/26/4 mutations now also roll back with the request.
- **Blocker 3 (hub growth).** The job transaction, trainer learning, starter-outfit
  grant/ensure, and job restore moved to new `src/gameplay/jobs.rs`; `gameplay.rs`
  keeps only the two 26/13 dispatch arms and the existing call sites. Net hub change:
  -207 lines (`gameplay.rs` 6,580 -> 6,373); no other hub changed.
- **Blocker 4 (trainer duplicate grants).** `learn_job` passed `reuse_owned=false`, so
  every starter definition was granted even when owned. It now passes `true`: an owned
  piece is equipped instead. Regression asserts the owned quantity stays 1.
- **Blocker 5 (documentation).** This note has the Structure and Checklist sections;
  the F155 report carries all 19 checklist items including item 17. `F110.md` gets a
  short correction because its economy claim was false at the time.

## Security threat note (secure-code-guardian)

A hostile client can send 26/13 with any i32 profile id, replay 26/10 trainer choices,
send a 26/10 for a choice that was never offered, forge runtime GUIDs, or wrap a
successful choice with a malformed later child. The server rejects unknown or locked
ids before touching state, matches the choice against the stored active menu and its
range/zone, stages every change on the request clone, and commits only when the whole
request succeeds. The 38/21 attachment list now comes from the repaired inventory, so
a hostile id cannot produce a profile swap the client would reject. Learning re-reads
the trainer row from content (not the client), grants only content starter definitions
once, and a refusal consumes neither the menu nor items. No client item, price or
quantity is trusted in this path.
