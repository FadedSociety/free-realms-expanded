# T230: Station Cash slice 1

## Summary

T230 adds a per-character Station Cash (SC) wallet, lists the rides in the client's Marketplace,
and sells them for SC. The client protocol is documented with IDA addresses and the corrected
66/5 bundle tail in [[Design/Station Cash]]. No coin path creates SC and no SC path creates coins.

This run re-applied `T230-a2.patch` to the newest tip. Three hunks were rejected and ported by
hand: the `stores.json` policy block replaced the removed W169 `ride_price_policy`, the
`vendors.json` coverage counters were recomputed for this tip (1,051 mapped rows, 1,049
priced/runtime rows, 95 runtime vendors), and `src/gateway.rs` needed `mod trade_bridge;` because
the patch context expected a `pickup_seed` module this tip does not have. No `.rej` or `.orig`
files remain. The trade bridge stays in `src/gateway/trade_bridge.rs`; the hub deltas are
`src/gateway.rs` 2,238 -> 2,214 (-24), `src/bin/osfr-gateway.rs` 4,693 -> 4,693 (0),
`src/gameplay.rs` 6,110 -> 6,113 (+3) and `src/encounter.rs` unchanged, so the spine ratchet passes
with headroom. All catalogue packets were rechecked against the client readers this run (see the
evidence table); the 66/9 entry-map fix and the 66/5 tail fix are unchanged and their byte tests
pass.

- New `src/station_cash.rs`: wallet save type, data-configured catalogue, 66/1/3/4 order
  parser/response, 66/11 wallet packet, and the 66/5/6/7/9 catalogue encoders. It owns the staged
  order transaction and the bounded persisted replay history.
- `src/coin_shop.rs`: Marketplace wiring. `66/10` returns the wallet; `66/1/3` preview/order
  through `station_cash`; `66/12` answers the store status and pushes the catalogue; `66/5/7/9/6/24/33`
  are emitted from the real ride catalogue. `CoinShop::load` is the one place that builds the
  session shop, keeps the 100-stack bag capacity and refuses a saved wallet with no Marketplace.
- `data/content/stores.json`: the `station_cash` policy (`sc_price_scale` 0.25, price/balance/
  replay bounds, store/category/name ids), a first-class `sc_price` on all 54 ride rows, no coin
  purchase/member price on them, and `earn_only: true` on the Chrome Drake and Polar Bear. The
  W169 `ride_price_policy` coin conversion is gone.
- `data/content/vendors.json`: Delvin and the Mysterious Merchant (Cragara) no longer stock rides;
  both records are empty because all 54/3 of their rows were rides. This tip measures 1,049
  grantable rows (baseline floor 1,026) and 94 fully grantable vendors; the coverage counters are
  pinned at 1,051 mapped / 1,049 priced / 95 runtime vendors.
- Shared busy table: `Occupation::Trade`; `Gateway::staged` (new `src/gateway/trade_bridge.rs`) derives it
  from the read-only `TradeService::session_id_for` before dispatch. `src/trade.rs` is untouched
  (lead-only module).
- The wallet and replay records are in `GameplayState::sc_wallet`; a successful order also adopts
  the live inventory in the hub. The wallet and order state are staged with the character save.

## Client behaviour after a successful order

`00b3b6d0` raises `OnOrderResponse` with success, tracking id, discount and total; the granted
item arrives through the normal inventory update packets. The order handler does not request the
wallet again, so T230 pushes a fresh 66/11 after a successful order (R). Native acceptance is not
run.

## Reconstructed rules (R)

- Station Cash is per character. The original wallet was account-wide and real-money funded; the
  revival has no payment flow and the character save is the atomic unit.
- A package with the policy disabled leaves a saved wallet untouched; the ceiling and replay-window
  repair run only when the policy is enabled, so a content toggle cannot silently rewrite it.
- Ride price = `round(sc_price * sc_price_scale)`, bounds and scale in `stores.json`.
- The catalogue is pushed after the client's 66/12 store-status request. The community reference
  pushes it at zone entry; native client acceptance is still needed.
- The order result codes 2 (order failure) and 5 (balance not enough) are confirmed by
  `00cc5470`; result 1 is success.
- `tint` -1 is mapped to 0 (the inventory grant accepts >= 0); other strings must parse.
- The replay window is `order_history` (default 256, capped 4096). A duplicate within the window is
  paid once; a packet older than the window is outside this slice's proof.
- Gift orders and coupons are refused; the client cannot turn them into a free grant.
- A row with `sc_price` cannot have a coin purchase or sell price and must be `no_sale`; the two
  currencies never meet in one store row.
- `Chrome Drake` (79454) and `Polar Bear` (79447) are `earn_only`; slice 2 makes them rewards.
  There is no SC source in slice 1, so a fresh character starts at 0 and tests seed the save.
- `currency_type` is 0 from data. The client's price/currency display mapping is not recovered;
  native acceptance must confirm the SC symbol.

## Open gaps

- Native client acceptance of the 66/12 catalogue push and the order result is not run. The
  bundle field positions are reader-derived; field names beyond the reader order are (R). Bundle
  launch/expire are zero (no time-bounded sale assumed) and `currency_type` is 0; the client's
  date filter and price/currency symbol mapping are unrecovered.
- Tradeability (goal B): the ride rows in the generated item catalogue have NO_TRADE at +44. The
  rows come from Legacy `ClientItemDefinitions.json` (`legacy+client-if-present`), not a captured
  client packet, because rides are absent from the 302-row shipped `ItemDefinitions.txt` and from
  the 1,703 captured definitions. The existing trade gate refuses a bought ride. Overriding the
  flag is a lead economy decision. Pinned for all 54 rows by
  `tests/station_cash.rs::bought_ride_catalogue_row_is_no_trade`.
- The replay window is bounded; a replay older than the data window would be paid again.
- No Station Cash-specific save-failure fixture: an order mutates the staged session gateway and
  the existing `l011_vendor_save_failure` / `quest_reward_save_failure` tests prove that shared
  commit path leaves the save unchanged and ends only that session.
- The welcome screen's `starting_wallet_balance` stays 0; 66/11 is the authoritative display.
- Slice 2 (earning) is not implemented.
- A trade request and an order in the same bundled client application batch can be processed
  before the trade flag updates; ordinary sends are separate messages and see the flag.
- The trade busy flag is session-only and derived per request; it is not saved.
- The 66/6, 66/7 and 66/9 packets each carry exactly one category/group in this slice; their
  leading `1` is the counted map size and must change with the catalogue if it ever grows.
- The 66/5 catalogue is ~8 KiB and is sent on every 66/12. Inbound action budgets bound the
  request rate; the reply is server-built content and changes no state.

## Security threat note (secure-code-guardian)

A hostile client can send: a fabricated bundle id; a quantity of 0/2/2^32; an unknown store id;
a huge/negative/trailing string; a detail count above 16; a garbage tint; a gift recipient; a
coupon; an earn-only or unlisted bundle; a replayed order; an order during a trade/minigame; or a
burst of 66/12 catalogue requests. Every one is refused or bounded without state change: the price
comes only from the data catalogue; quantity must be 1; the store id must match the configured
store; strings and counts are bounded before allocation and the body must end exactly; the tint
must parse; gift/coupon are refused; `earn_only` rows are not in the lookup; a duplicate order
fingerprint is answered from the persisted replay record; the shared busy table refuses during a
trade. The client cannot set the wallet balance; the server sends it. A successful order is one
staged transaction: the inventory grant is cloned and only committed with the debit and replay
record. No coin path touches the wallet, and no SC path creates coins. Malformed orders return
`Err`, so the gateway drops that application for that session and the server continues; no tick
path uses `?` or `unwrap` on client data. The 66/12 catalogue reply is ~8 KiB of server-built
content per request; the existing account action budget bounds the request rate and the reply
changes no state.

## Checklist

1. **Refusal changes nothing.** `tests/station_cash.rs::refusals_change_nothing` snapshots
   `(InventoryState, Wallet)` and compares for short balance, full bag, unlisted, unknown store,
   earn-only, quantity, gift, coupon, busy and malformed. Gateway full-bag/trade tests snapshot
   the gateway. Canaries this run: removing the debit (`balance = wallet.balance`) in the
   production `place_order` made the success-path test fail (balance 200 != 63); changing the
   production busy guard to `if false && busy` made the busy refusal succeed (result 1 != 2). Both
   were reverted and `station_cash.rs` was restored byte-identical (sha256 checked).
2. **Rollback covers all state.** The order stages an inventory clone and only writes
   `wallet.balance`, `wallet.orders` and the inventory on success. The catalogue is an immutable
   `Arc`; the replay history is in the wallet; no side table escapes. The trade flag is derived
   per request, not shared.
3. **Apply deltas.** The debit is `wallet.balance - total` on the live wallet; the grant applies
   to a clone of the live inventory that the hub syncs before the request. No old inventory or
   position snapshot is restored.
4. **Busy mutual.** `Occupation::Trade` is in the one table; its gates close start/warp/ride/pets,
   and every activity's `activity_busy` sees it. The order gate uses `activity_busy`. The
   `gates_reproduce_the_replaced_busy_lists` pin includes Trade; the gateway trade test drives the
   real `handle_at` dispatch with the same mirrored flag the binary sets.
5. **Every entry path gated.** The only order path is 66/3 -> `handle_in_world` ->
   `handle_npc_packet` -> `handle_marketplace` -> `place_order`. It requires the listed catalogue,
   balance, store, quantity 1, no gift/coupon, not busy. The preview path does not mutate. There
   is no second order handler.
6. **Reachable in production, tested through it.** The gateway tests in `coin_store_siblings`
   drive `Gateway::handle_at` with a full synthetic content package: wallet, order, replay,
   insufficient, full bag, trade, catalogue and reload. The binary clones through `Gateway::staged`
   (the same `set_trading` the test drives) before that call, so production and test share the path.
7. **Survives reconnect.** The wallet and replay records are in `GameplayState::sc_wallet`; the
   gateway reload test serializes the snapshot, parses it back and reconnects, then checks the
   balance, the owned ride and the replay refusal. A package with the policy disabled preserves a
   saved wallet verbatim (pinned in `wallet_survives_serde_and_restores_under_the_data_ceiling`).
8. **Every exit restores.** An order is one-shot; a refusal leaves the character exactly as it
   was. The trade/busy flag is session-only; a disconnect ends the session and the save keeps only
   successful orders. No ongoing activity owns the character.
9. **Economy safety.** No free grants in slice 1; the price is server data; the order grants once
   and the replay is paid once; the bag and balance are checked before the debit; `earn_only` is
   not listed. The order test asserts coins are unchanged. The ride NO_TRADE catalogue flag is
   pinned for all 54 rows and the existing trade gate refuses it (goal B blocked by item data,
   reported).
10. **Wire format.** Cited readers in the table above. Byte-level tests cover the wallet,
    order/preview and result layouts, the full 66/5 record field by field, and the 66/6/7/9
    navigation packets to the last byte. The 66/9 entry map was missing the entry's own bundle id;
    the new navigation test failed before the fix (natural canary) and passes after it.
11. **Unique ids.** The grant uses the inventory's instance-id allocator; the bundle id is the
    positive item id and unique in the store map; the tracking id is client-supplied and the
    replay is keyed on the full order, so it cannot alias a different paid order. The store and
    category ids are data-configured.
12. **Others see changes.** A granted ride is visible through the existing inventory update path
    (`Outcome.changed` -> `npc_inventory_events`); the mount service lists the owned item (the
    ride test asserts `owned_mounts`). The order itself sends no world broadcast and needs none.
13. **Content end to end.** The real `stores.json` has 54 rides, 52 listed and 2 earn-only; the
    ride test buys every listed ride and asserts ownership; content_check is strict-clean; the
    coin vendors no longer stock rides.
14. **Values in data.** Scale, price bounds, wallet ceiling, replay window, store/category ids and
    name ids are in `stores.json.station_cash`; `Config::validate` enforces sanity bounds. No
    tuning constant is compiled into the order path.
15. **Canary breaks production.** This run's canaries broke the production order path: the removed
    debit failed the success-path balance assertion, and the disabled busy guard failed the busy
    refusal. The earlier wire canaries (appended 66/5 byte, missing 66/9 entry id) broke the
    production bundle writer and failed the reader-derived tests. All were reverted.
16. **Hands off session plumbing.** No session creation, teardown, transaction or save-ordering
    change. The binary's added lines are now one `Gateway::staged` call that clones and mirrors the
    session-only trade flag, replacing the existing clone call; the save remains the existing staged
    character commit.
17. **One player's error never stops the server.** The order parser returns `Err` on malformed
    data; the gateway drops that application and continues. Arithmetic is checked
    (`balance >= total` before subtraction, price bounds/rounding checked). The `app_fuzz` hostile
    corpus and the gateway refusal tests pass.
18. **A type's rules live on the type.** `Wallet`/`OrderRecord` carry the persistence and replay
    rules; `GameplayState::sc_wallet` is documented as the save form and inlines the CoinShop
    accessor; `Config` owns the catalogue policy; `Occupation::Trade` owns the busy rule;
    `Gameplay.trading` carries a field comment.
19. **Hot paths stay cheap.** No per-tick work. The catalogue is an `Arc`, the wallet is small, the
    order parser is bounded, and the catalogue is built only for a 66/12 request. A 66/3 request
    clones the inventory once before parsing (the same cost as the existing coin-shop request
    path); a preview or wallet read does not. `Gameplay::state()` clones the wallet only when it is
    non-empty, so a character with no Station Cash pays nothing. The ~8 KiB catalogue is built only
    on 66/12.
