## Deviations from the brief (evidence wins)

- **PARAM1 5 is not only facial hair.** Stores sell 21 PARAM1 5 cards whose PARAM2 is a wing row
  (e.g. 36030: gender 2, PARAM2 7 = `fairy_f_wings_butterfly.adr`; gender 1 PARAM2 13-18, 31-36,
  38, 40 = `fairy_m_wings_*`). The brief's "PARAM1 5 needs a `human_m` model" would refuse them, so
  the rule is: a non-empty string must fit the model (below); only Clean Shaven (PARAM2 0, the
  empty string that clears) needs `human_m`.
- **One `fits` rule replaces the separate hair and prefix rules.** A fixed prefix must be the model
  stem plus `_` (`human_m_facialhair_*`, `fairy_f_wings_*`, and also the fixed-race hair rows 54-83
  such as `fairy_f_hair_FRCcurly_*`, which the brief's hair rule missed); after `<race>_` a fixed
  `m`/`f` must be the model's gender letter (R) unless it is `<gender>`. It applies to head, hair
  and model customization strings; skin tone and face paint are texture aliases. The separate
  "wings need a `fairy_` model" check is implied (every wing row starts `fairy_m_`/`fairy_f_`).
- Record 8 in 35/65 is the model id (`00958460`; Legacy sends `Model` too), not an unknown body value.
- 35/65 is `customization_data(look, tables)`: the tables decide record 7 for a pixie.
- `Refusal` has no chat text yet; part 2 adds `message()` when it routes.

## Threat note (secure-code-guardian)

- Hostile input is only the 8-byte 42/10-42/12 body. `decode_request` matches the exact 8-byte
  shape (header, one i32); short, long, wrong family or opcode bodies are refused. The id it yields
  only selects an item; part 2 must check the player owns it.
- Nothing in a record comes from the client: slot, mapping and gender come from our catalogue row,
  strings from the client's tables. An unknown mapping id is refused, never sent; a table string
  over 512 bytes or with NUL is refused (the `CharacterIdentity::validate` bound). No arithmetic on
  any value.
- A refusal is a returned `Err`; `record` takes `&Look`, so it cannot change state (asserted).
- Cross-model assets (wings on a human, facial hair on a pixie, male hair on a female) are refused,
  so a bought card cannot produce an asset the client would fail to load.
