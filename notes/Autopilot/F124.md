## Client evidence

- 45/7 is exactly `u16 45, u8 7, i32 objective id`; `0x00cffba0` builds it
  through `0x00cff7d0`, sends through `0x00cffa70`, and only then sets the
  object's completed byte (+0x1d). Losing the claim is permanent, so the
  server must process it during an unrelated end screen.
- `0x00c43870` constructs 45/11 with the isMouse byte; `0x00cf39e0` compares
  the movement flag and calls `0x00cffba0` on a match. The shipped goal uses
  `first_movement` with `mouse: false`.
- 45/10 UIEvent is id, i32 byte length and the event bytes. IDA re-checked
  `sub_C437A0`, which logs "Adding UIEvent objective %d - name %s";
  `sub_C436B0` is the separate LookAt constructor.
- IDA re-checked these addresses on 2026-10-18. `sub_C43870` logs "Adding
  FirstMovement objective %d - isMouse %d"; `sub_CFF7D0` stores family 45 and
  subtype 7; `sub_CFFBA0` calls `sub_CFFA70` and then writes the completed byte
  at +0x1d. `0x00cf39e0` is a code label (not recognized as a function by
  IDA); its disassembly compares `[ecx+0x20]` with the movement flag and calls
  `sub_CFFBA0` only on a match.

## Security note (secure-code-guardian)

A hostile client can send a forged, negative, oversized or duplicated 45/7 id,
or an unlisted 49/15 original id. The decoder requires exactly 7 bytes and a
positive i32-range id; the engine matches only the character's own active quest
and open goal. Refusals change no quest, inventory, coin or cooldown state: the
bot test asserts the whole `npc_quests` object and later the whole gameplay
save are equal. No reward path runs from a claim; rewards only come from the
server's turn-in transaction. No client-supplied text is reflected.
