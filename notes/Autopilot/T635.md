# T635: weapon and attack reference tables, live-ratio check of job ability multipliers

## What changed

- `scripts/build_weapon_reference.py` (`python -I`, deterministic: two runs give identical bytes) writes
  `prototype/osfr-tools/data/reference/weapons.json` and `attacks.json` (`schema_version: 1`) from the wiki harvest
  (`lab/references/freerealms-wiki/harvest/lists/`), the W84 client item catalogue and the client locale.
- `weapons.json`: 653 rows (one per wiki page). Each has url, `rev_id`, `source` (`wiki`, plus `client` when matched),
  the wiki's power, level, jobs, coin and Station Cash prices and resell values, abilities (name, locale id, damage,
  heal), the matched client items (`id`, `power_rating`, `min_profile_rank`, `cost`, `resell_value`) and `agree` flags
  (`all` / `some` / `none` of the matched ids carry the wiki number; null when either side has no number).
  - Match: item name through the client locale (`Global.Text.<NameId>`, Jenkins lookup2), weapon rows only (client
    slot 7). 500 matched (many names have several ids: one per variant), **153 unmatched**, listed in `unmatched` with
    a reason: 115 "no client item has this name" (wiki-only pages: mostly retired or renamed weapons and category pages),
    38 "the client has this name only on non-weapon items" (flair shards, packs, biscuits).
  - Flags over matched rows: power all 567 / some 56 / none 30; level all 509 / some 81 / none 63. Cost and resell value
    mostly disagree (wiki coin prices 750/850/1055/1504/2152 vs client `Cost`; client `ResellValue` is 0 for most
    weapons while the wiki states a tenth of the price): cost all 137 / some 26 / none 63, resell all 110 / some 12 /
    none 231. Reported, not reconciled (no gameplay use yet).
- `attacks.json`: 238 attacks (`name_locale_ids`, jobs, tags, `weapon_count`, `damage_x` and `heal_x` with median, min,
  max and sample count n), `tier_base`, and `job_basic` (each combat job's profile id, its basic attack and that
  attack's `damage_x`). 21 harvest rows whose "name" is a tooltip description are listed in `rejected`.
  - Locale ids: tooltip readings plus the server's own ability name ids, each kept only if the client locale text of
    the id equals the attack name (180 of 238 attacks have an id; the rest are wiki-only names).
  - Job basic attack = the attack most weapons of the job list first (Archer Barrage, Brawler Glancing Blow, Medic
    Incision, Ninja Flame Flash, Warrior Sweeping Slash, Wizard Zap). Profile ids from `jobs.json`.
- `data/content/job_abilities.json` (`damage_multiplier` and its source text only): 8 values corrected, 3 explained.
- `tests/weapon_reference.rs`: the tables load and every row has a source (the power flag is recomputed from the row);
  every job ability multiplier is within 2% of `attack damage_x median / job basic damage_x` or its source says
  `wiki ratio`, or (no wiki attack of that name) carries an `(R)` tag. The check ran against the old
  `job_abilities.json` and listed exactly the ten rows below (it fails without the fix); a canary mutates Zap back to

## (R) choices and open points

- (R) Wiki numbers are the final-era values (harvest README, derived); the locale's early-era rank text (Target Vitals 133,
  Shock Paddles 50) is a different era and a different scale, so it is not used.
- (R) The denominator is the wiki basic attack's median `damage_x` per job (0.314 or 0.286; the 0.286 jobs are the
  Brawler and Ninja, the x1.1 pair of the harvest README). Tooltip "Deals N damage" on a multi-hit attack (Pummel) is
  read as the total of all blows, as the server aggregates blows.
- Zap 1.8 -> 1.0 makes the Wizard slot-1 skill equal the basic attack, which is what the wiki says it is. Lead: if the
  slot-1 skill should stay a distinct stronger variant, restore 1.8 and add `wiki ratio` to its source.
- The absolute damage scale (profile_stats basics 70..130) is untouched (T637).
- `python -I scripts/content_check.py --strict` exits 1 with 217 errors, all `image_missing` in `collection_catalogue.json`
  (icon ids absent from Images.txt); no finding names `job_abilities.json`.
- Harvest, locale and catalogue paths are read from `lab/` (private); regenerate with
  `python -I scripts/build_weapon_reference.py`.
