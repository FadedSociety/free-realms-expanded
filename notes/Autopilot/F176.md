## Security Note

What a hostile client can send across this boundary, and why it is refused:

- **Replayed `41/108` after closing or leaving the screen.** The pending
  battle is server-created only by a marker interaction that passed the 8 m
  check; Close/Leave clears it, and `begin` clears it on every start path.
- **A `41/108` from elsewhere in the world while the start screen is open.**
  Go consumes the pending battle only within 8 m of the marker's current
  (wandered) position; otherwise the screen is dropped and nothing starts.
- **A forged `41/108` body naming another encounter/instance.** The handler
  ignores the body and uses only the server-pending battle; the test's packet
  bytes are the client's, but the decision input is server state.
- **`41/109` with arbitrary ids.** It is accepted only when the active
  instance matches (or the encounter id is zero, as the native leave sends);
  with no active encounter it can only clear the open start screen.
- **Go while knocked out.** `begin` refuses before mutating the encounter or
  inventory; the player gets a chat refusal and the same screen, not a
  disconnect. No reward is granted.
- **Portal Play / developer start while a screen is open.** They still pass the
  catalogue, level, busy and prize gates; the successful `begin` consumes the
  old screen so it cannot be replayed.
- No player names or chat text were added to code, tests or notes. Refusal
  copy is the server's own text.
