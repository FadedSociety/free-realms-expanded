## The display-element trio (engine.gds)

00422dcc, 00422f4d, 0042308d share one class layout: flags dword at +0x10 (bits 0/1/4/5 plus 0x20000000 and
0x40000000), rectangle at +0x14..+0x20, display object pointer at +0x24, stored parameters at +0x28/+0x2c,
display/manager pointer at +0x44 (after the +0x3c object), current-pointer field at +0xd0 (get/set via
004114ce/004114d5), and focus short/object at +0xdc/+0xe0 adjusted by 00419a70/00419ad8.

Mechanics (names in out.jsonl are neighbour-inferred, hence `likely`): each method keeps the host argument
alive, takes or releases input focus through S0007's FUN_0042280f (writes owner+0x164/0x168, notifying via slot
+0x8c) or FUN_00422996 (releases only when owner+0x164 == this), and then sends a 7-dword record {0, code, ...}
to the host's vtable slot +0x110. The code is 2 in 00422dcc, 0 in 00422f4d and 1 in 0042308d. After the call the
first dword is tested against 0x24924; on any bit the shared error path FUN_004d93a3 runs.

00422dcc additionally fetches its rectangle through the element's own vtable slot +0x38, copies the host's
16-bit field at +0xDC through 00406798 (GetWordDC) into +0x40, refreshes the display-list object at +0x24 via
FUN_0040f8df + FUN_00406607, and registers in the +0xd0 slot. 00422f4d adds a rectangle invalidate through
004072e2 (which forwards to FUN_0042f518 with flag 0x10000). This trio is the cross-shard contract
interface between this UI range and S0006/S0007.
