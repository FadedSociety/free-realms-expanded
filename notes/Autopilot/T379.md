- **`placement_source` vocabulary.** `content_npc_placement.rs` accepts only `reconstructed_zone_center` or `reconstructed_unanchored_default` for an unanchored row, so the row uses `reconstructed_unanchored_default` and records in `position_reason`/field sources that the transform itself is copied exactly from the extra row, not reconstructed. No production code changed to add a new placement class.
- **Greeting.** Locale `Global.Text.401156` resolves in the stock client to the repair man's first reply (JenkinsLookup2 hash 769285313 / `0x2dda5cc1`, `en_us_data.dat` line 20259), beside the `Car Repair Guy` name id 94010. - **No kart gate.** `kart_gates.json` is untouched and neither content key is a gate. The test proves a real gate (Spud Edgins) still publishes label 3052 in the same fixture while the repair guys list only Talk.

## Security threat note (secure-code-guardian)

- **Attack surface:** any client can send 26/8 (u64 target + bool) and 26/10 (u64 target + i32 choice) at any time, from any position, while busy. The server resolves the runtime GUID through `NpcVisibility::content_key`; a client cannot name a content key directly.
- **Unknown/forged target:** a GUID outside the content-key table takes the existing `unknown_runtime_guid` branch and returns no menu and no packet; `a_far_or_wrong_target_refusal_changes_nothing` asserts both the whole `GameplayState` and the serialized save are byte-equal afterwards. The deliberate canary (below) reproduced the branch on the real actor.
- **Range:** the correct GUID from 1,000 m away is refused by the existing 12 m `NpcInteraction::check_range`; the state and save bytes are unchanged.
- **Forged option:** a 26/10 choice that is not in the open menu is refused (`InvalidOption`); `the_repair_guy_is_not_a_kart_gate` sends choice 2 (the race slot on a real gate) and asserts the error plus byte-equal state. A repair guy cannot start a race.
- **Busy:** the shared busy table refuses the click while Mining is active, opens no menu, sends no 26/3 and changes no save bytes.
- **Isolation:** no shared-tick code, no `unwrap` on client input, no new persisted state. Malformed 26/8 bodies stay per-session refusals (existing decoder); `app_fuzz` green. One player's error cannot stop the server.
- **Economy:** no item, coin, XP, reward, job or position change. The successful click/Talk test asserts the whole `GameplayState` serialization is unchanged; no client-reported quantity or id is read. Nothing is granted for free or sellable.
- **Secrets/text:** no secrets, player names or player chat text were added. The locale line is client NPC content and is cited in the row's source.
- **Test-only guard change:** the T316/T378 foreign-file check reads `HEAD` and the working tree; it adds no runtime surface and still refuses a foreign file whose top level changed, that lost a row, or whose existing row changed outside its greeting (guard canary 2).
