# T550: Sanctuary-main harvest plants and props imported as decoration

Data-only change. 309 rows were appended to `npc_spawns_extra.json`: 194 harvest plants and
115 static props from Sanctuary-main-20261019@10f129e's 895 new spawns. No production code
changed and no hub line moved. Positions and headings are the zone script's own values, so this
is not a 2014 placement claim (see the `(R)` rules).

## (R) rules

  ours, not recovered facts.
- `spawn_guid` is Sanctuary's Lua capture guid (100000000000 + Npcs.json Id), not a captured

- The nameplate gap is inherited from the `ExtraNpc` schema (same as T549).

## Threat note (secure-code-guardian)

The rows are server-authored content; a hostile client cannot inject or edit them. The only
client-triggerable surfaces are the 26/8 click and the visibility fan-out:

- A 26/8 click on any of the 309 guids resolves through `Gameplay::content_npc_key`; none of the
  rows carries a `content_key`, so every one is the existing `unknown_runtime_guid` no-reply
  refusal. It cannot open a menu, consume an offer, grant an item or coin, or start a cooldown;
  `tests/gathering_nodes.rs::a_plant_click_opens_nothing_and_changes_nothing` asserts no reply,
  an unchanged snapshot and unchanged save bytes, and no mining or harvesting run.
- No ability, interaction list, item, reward, vendor or quest is bound to a row. The snowball
  InteractionList/Ability are not imported, so clicking a pile cannot obtain a snowball.
- Every guid is unique among extras and disjoint from regional actor ids (tested), so no row
  aliases an interactive actor or the public-world instance.
- The loader's existing bounds apply: finite positions, alias rules and scale 0.1..=10; imported
  scales are 0.8, 1.0 and 1.5.
- The fan-out is a read-only nearest-64 view sorted by distance then actor id. The content-actor
  visibility invariant still passes after adding the rows.
