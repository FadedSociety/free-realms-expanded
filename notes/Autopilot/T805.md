# T805: card login finds its session by the launch ticket alone (lead brief, native 2026-10-27)

## Why
Native runs 2026-10-27 ~07:30Z and ~07:46Z (with T798 and T804 in): the card window logged itself in, and the card service
still refused it (`card_login ok:false`, "Authentication Failure"). Every link of the ticket path was traced:

1. Mint and commit: the 39/37 is staged on a clone of the session's `Gameplay` (`gateway.rs` `staged_game`) and committed with
   the staged gateway (`osfr-gateway.rs` `commit_outcome`: `self.gateway = staged_gateway` comes before any `app_out` line). The
   native trace has exactly one 39/0x28 `app_out`/`sent`, about 1 s before the client's TCG start: the ticket was live.
2. Client read: the launch ticket in the client's `ClientTradingCardGameManager::Startup` log line equals the two little-endian
   halves the server's 39/0x28 carried (compared in the run's trace; no value recorded here). `--ticket=%llu` is our number.
3. DLL 411: the session dialog `103c9140` builds the command with ctor `1017bac0`, which copies the DLL login state `+0xE8`,
   `+0x104`, `+0x120` (getters `1017c290`, `1017c2d0`, `1017c2f0`) into CharacterName `+160`, CharacterID `+188` and Ticket
   `+216`. `1037bba0` fills those from `--character=` (`1037aca0` -> `1017c280`), `--characterID=` (`1037adb0` -> `1017c2c0`) and
   `--ticket=` (`1037aec0` -> `1017c2e0`) before it calls `1037b200` and opens the dialog (`1037b5f0`). Writer `1017b700`
   writes `+4`, the map, `+44`, `+72`, bool `+100`, `+104`, `+132`, `+160`, `+188`, `+216`, `+244`: the order
   `SessionLogin::decode` reads. So the 411 carries the ticket as decimal text and an empty CharacterID (the exe passes no
   `--characterID`).
4. Redeem (the fault): `Server::redeem_card_ticket` (`src/bin/osfr_gateway/card_listener.rs`) parsed the 411's character id as
   the guid keying `active_sessions` and refused when it did not parse. An empty id was refused before any ticket check; T804
   only relaxed `LaunchTickets::redeem` behind it. TTL (60 s in the native package) and the shared clock (`Server::start`
   elapsed for both mint and redeem) were not the cause.

## Change
- `card_listener.rs` `Server::redeem_card_ticket`: scan the live sessions; the one whose `Gameplay` holds the ticket redeems it.
  Other sessions answer `unknown_ticket` and are skipped, so only the minting session's table changes.
- Refusal reasons: `LaunchTickets::redeem` (and `Launches::redeem`, `Gameplay::redeem_card_ticket`) return
  `Result<u64, &'static str>` with fixed words: `no_ticket_field`, `ticket_not_decimal`, `unknown_ticket` (never minted,
  spent, or its session ended; `card_service::UNKNOWN_TICKET`), `expired`, `character_mismatch`.
- Diagnostic: the `card_login` event now carries `reason` (null on success), the 411 `version` and `lengths` of its session id,
  character name, character id and ticket. Never a value. `SessionLogin` keeps its header `version`.

## Threat note
The launch ticket stays the only credential: 64 random bits from the OS, minted per launch in the player's own session, single
use (spent only on a matching, unexpired presentation; a refusal spends nothing, F779/F821 signed off 2026-10-27), TTL from
the launch block, one outstanding per character.
Finding the session by ticket instead of by the (non-secret) character id widens nothing: a guess still needs a live unspent
ticket, now out of every outstanding one (at most one per online card player) instead of one character's, i.e. a few in 2^64
per try. The event log carries reason words and lengths only.

## Structure
No new file or type. One loop replaces the guid lookup (`ponytail:` linear scan, one per card login; a server-wide ticket
index if the player count ever makes it show). Reason words are literals at the one place they are decided; only
`UNKNOWN_TICKET` is a const because the scan matches on it.

## Gates

  in-world sessions on a card-enabled content copy each mint through Play (167/1/2) -> 39/37; `Server::redeem_card_ticket`
