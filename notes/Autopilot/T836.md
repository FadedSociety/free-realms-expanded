# T836: a refused NPC click never disconnects the player (lead hotfix)

Native 2026-10-27 18:39Z: clicking an NPC ended the session ("NPC interaction is unavailable");
the session-ending error also hid the house list (the client asked for it after the session was
gone). `Gameplay` mapped a refused 26/8 `interact` (unknown NPC, out of range) and a refused 26/10
menu choice to io errors; the gateway turns a handler `Err` into a session end when the request
rides a combined `[0,25]` datagram (`src/gateway.rs` `handle_at`, `combined`). T836 makes both
refusals answer nothing and keep the session. About 38 assertion sites in 26 `tests/` files plus
the inline `src/gameplay/s15_npc_transactions.rs` changed from "the error" to "refused, nothing
changed".

This note was a three-line stub; F843 (2026-10-27) adds the 19-item checklist, the structure and
the threat note, corrects the counts (the stub said "about 25 assertions in 18 suites"; the commit
touches 29 files: 26 under `tests/`, `src/gameplay/s15_npc_transactions.rs`, `src/gameplay/npc.rs`
and this note) and fixes the review's findings 2-4. Review:
`lab/autopilot/reviews/8af9e6d-T836.md`, lead resolution 2026-10-27.

## Client evidence

- 26/8 constructor `0x008b6bc0` (this run): the shared preamble stores family 26 and subtype 8; the
  constructor keeps the target in two dwords at `+4`/`+5` (u64) and the trailing bool at `+24`.
  `decode_npc_interact_26_8` requires 13 bytes, the `[26,0,8,0]` header and a 0/1 flag.
- 26/10 constructor `0x00a36f80` (this run): the same preamble stores family 26 and subtype 10; the
  target is two dwords at `+4`/`+5` and the i32 choice at `+6` dwords (wire `u64 target + i32
  choice`, 16 bytes).
- Shared preamble `0x008a2820` (this run): writes family `26` at `+4`, subtype at `+8`.
- No wire field, opcode or layout changed; the existing `tests/common/gateway_packets.rs` builders
  (`interact`, `select`) still match, and `npc_interact_26_8_decodes_and_reencodes_captured_request`
  covers the 26/8 bytes.

## Threat note (secure-code-guardian)

A hostile client can send a 26/8 with any u64 target and flag, or a 26/10 with any target and i32
choice. Both are still validated before anything is read or changed: the 26/8 body must be 13 bytes
with the 26/8 header and a 0/1 flag (`decode_npc_interact_26_8`); the 26/10 body must be exactly 16
bytes and its target must map to a content key (`content_npc_key`, which excludes opening-actors);
the shared busy gate runs next; then `NpcInteraction::select` re-checks the NPC's zone and 12 m
reach before reading the open menu, requires the open menu to belong to that NPC, and requires the
exact choice id the server itself built. The request never names coins, items, a reward or a save:
it only picks an offered option, and a refused pick leaves a clone that the router never assigns
back. The new telemetry carries only ids the client already sent (guid, content key, option) and a
fixed reason name; no text, no path, no secret. There is no new network, file or session surface.

## Checklist

1. **A refusal changes nothing.** Both branches return before any write: 26/8 before
   `self.quest_conversation = None`, 26/10 before the `selected.is_ok()` write-back of the menu.
   Tested by snapshot equality in `medic_entry_chain::refusals_and_replay_change_nothing`
   (with the fixed `is_ok_and` helper), `priced_vendors_drawable::
   two_players_see_and_open_the_same_vendor` and the new bundle test. Canary: reverting either
   branch to `Err` failed both the bundle test and the medic `far interact` / `far menu select`
   assertion (recorded, reverted).
2. **Rollback covers all state.** No transaction or shared side table is involved: the 26/10 path
   works on a cloned `NpcInteraction` and only writes it back on `Ok`; the gateway has already
   staged `Gameplay` and keeps it only when the handler answers. Tests as item 1.
3. **Apply deltas, never restore snapshots.** Neither refusal pays, moves or restores anything. No
   inventory, coin or position value is captured or written.
4. **Busy rules are mutual.** Unchanged: `busy_interaction_refusal` still gates both 26/8 and 26/10
   before the refusal points, so a live activity still gets its chat refusal. No activity added.
5. **Every entry path is gated.** 26/8 and 26/10 have one entry each (`route_npc_packet` from
   `handle_in_world_inner`); both keep the content-key, busy, zone, range and offered-option gates.
   No parallel path.
6. **Reachable in production, tested through it.** The changed tests drive `Gameplay::handle_in_world`
   and, for the new bundle test, `Gateway::handle_at` with the real `[0,25]` framing and the real
   `interact`/`select` bytes; the canaries broke the production branches, not the tests.
7. **Survives reconnect.** The refusal persists nothing and the menu is session state; no new save
   field. `medic_entry_chain::relog_preserves_completed_history` and
   `priced_vendors_drawable::a_reconnect_keeps_the_vendor_drawable_and_shop_openable` are green.
8. **Every exit path restores the player.** A refused click starts no activity, opens no dialog
   camera and closes nothing; the session keeps serving and the open menu (if any) stays usable
   (`medic_entry_chain` reuses the same menu after the far refusal).
9. **Economy safety.** The refusal is before any shop or quest write; no reward, item, coin or
   quantity is produced from client input. The pre-existing 165/4 rejection (review finding 8) is
   outside this change and is listed as an open gap.
10. **Wire format matches the client reader.** Unchanged; 26/8 and 26/10 bytes are the constructors
    cited above, and the byte-level builders and round-trip test are unchanged and green.
11. **Unique ids.** No id is minted by this change (the refusal only echoes the target it was sent).
12. **Others see changes.** Nothing visible to others is produced or changed by a refusal.
13. **Content works end to end.** Not a content change; the accepted menu/choice flows are asserted
    by the existing npc/vendor/quest suites that were kept green.
14. **Values live in data.** No new tunable; the reason strings are fixed telemetry labels, not
    balance data. The 12 m reach and the content tables are unchanged.
15. **Canaries break production code.** Three canaries edited `src/gameplay/npc.rs` (the 26/8
    return, the 26/10 return and the `out_of_range` name); each failed a production-driven test and
    was reverted.
16. **Hands off session plumbing.** No edit to `src/gateway.rs`, `src/bin/osfr-gateway.rs`, session
    creation, teardown, transactions or save ordering; no lead-only module.
17. **One player's error never stops the server.** This is the point of the change: a refused NPC
    packet no longer returns `Err`, so a bundled request no longer ends the session. The new
    `refusal_reason` is total over the error enum (compile-enforced) and cannot panic.
18. **A type's rules live on the type.** The reason table is an exhaustive match over
    `NpcInteractionError`, so a new variant fails to compile until it gets a name; it decides no
    struct field (persisted/compared/sent/reset), only the log label. This item is otherwise not
    applicable.
19. **Hot paths stay cheap.** Refusals only run for refused requests (not per tick, not per normal
    packet); the change removes two allocations on that path and adds none elsewhere. Per-tick
    cost: 0.
