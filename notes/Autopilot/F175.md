## Client evidence

printed nothing and was still waiting after 180 s, so I stopped it (the same outage
F162/F170/F175-a1 recorded). I did not retry a second query. The layout is instead confirmed
from the client-derived native map, built from the same 2014 binary:

- `python -I scripts/native_map/nmq.py show 00c7b990` -> `QuestEndPacket::ReadFields`
  (`0x00C7B990`): common prefix (u16 family/subtype + u32), then one 8-byte value stored at
  `+0x10/+0x14`, then three dwords at `+0x18/+0x1c/+0x20`, the reward bundle, and a float.
  Packet offsets: actor `6..14`, 49/14 reply id `14..18`, end-text locale `18..22`,
  animation `22..26`. This is the shape `put_end_screen_ids` writes.
- `00C7CD40` (`DispatchQuestPacket`): reads the quest-family prefix and dispatches subtypes
  1-13 and 16; subtype 13 parses that record and reaches `00A95420`.
- `00A95420` (`ShowQuestEndScreen`): formats `QuestNpcEndTextMessage` with a `player` and
  `speaker` string, emits `QuestHandler:ShowEndScreen`, and calls `0096C780`
  (`PlayOrQueueActorAnimation`); it needs the actor to resolve the speaker/animation.
- `00984960` (`HashList100_FindNodeByKeyPair`): looks up an actor-table node by a two-dword
  key pair, which is the actor pair the 49/13 carries; an absent actor is not retried, which
  is why the 49/13 must follow the AddNpc.
- `35/2` AddNpc reader `0x00921A10` reads the actor id; the tests parse the same bytes rather
  than inventing a layout.

Save/content binding `(R)`: the saved actor is the content NPC key, and current content maps
content key == client actor GUID (all 3,266 `npc_spawns_extra.json` rows have
`content_key == spawn_guid`; regional rows use `npc_id` as `actor_id`). A future spawn that

## Reconstructed rules `(R)`

- It is server policy to replay the saved 49/13 only after the opening actor's directed
  35/2, once per new visibility of that actor.
- Reopening an already pending screen at its opener (Talk, menu turn-in, or reconnect) is
  server recovery policy; it grants nothing and consumes nothing.
- The saved opener, not the formal turn-in NPC, is authoritative for the 49/13 actor; the
  formal NPC remains the turn-in gate for a new screen.
- The current content key doubles as the client actor GUID; a future split needs a map.
- The C3-C5 five-coin rewards and the trainer placement remain authoring fallbacks from
  F133/F135, not recovered retail values.
