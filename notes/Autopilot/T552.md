# T552: talking townsfolk, child idle cycles and dogs that look at players

Attempt 2: the first attempt's review (`pre-T552-a1`) is answered at the end
("Review findings").

## What changed

`src/npc_ambient.rs` (the T507 owner) now carries the three Sanctuary row kinds
slice 1 skipped, split into `npc_ambient/schedule.rs` (the schedules fixed at
load and their `due` rules), `npc_ambient/wire.rs` (the three wire bodies) and
`npc_ambient/tests.rs` (the unit tests):

- **Conversation groups** are fixed at gameplay load from the placed content
  actors. Talkers within 6 m XZ of each other, directly or through a chain of
  neighbours, form one group (connected components, union-find over the pairs;
  a lone talker is no group). Members are ordered by runtime GUID; member `n`
  speaks after the gaps of the `n` members before it in each group cycle. A
  speaker's gap is drawn from its row's `ConversationMin/MaxGapMs` with a
  GUID-stable hash, so every viewer and every restart sees the same turn order
  without a persisted cursor. A window returns only the latest firing, never a
  backlog. A conversation member does not also play its row's random emote.
- **Idle rows** fire `35/26 UpdateIdleAnim` at `IdleIntervalMs` and follow it
  with `35/8 SetAnimation` with flags bit 0 (the base animation). The idle id
  cycles from index 0 in a GUID-stable phase.
- **Look-at rows** fire `35/17 SetLookAt` at `LookAtIntervalMs`. The gateway
  resolves the nearest ready player of the same instance within `LookAtRadius`
  through `PlayerRegistry::nearest_session` (grid candidates, exact 3D distance,
  character GUID then session id break ties), so every viewer gets the same
  target. The target is sent only to a viewer that is that player or whose
  directed AddPc already contains it; otherwise nothing is sent. With no player
  in range the packet carries target 0 (the client's null GUID), which clears
  the look-at.

Content (`data/content/npc_ambient.json`) gains the Sanctuary values for these
fields plus the idle-only `dog_small_pointy.adr` row that T507's import
skipped, the 6 m grouping radius, and provenance tags. The loader bounds them:
conversation gaps 0..=60000 ms, idle/look-at intervals 500..=600000 ms,
look-at radius 1..=30 m, grouping radius 1..=30 m, per-viewer cap 1..=16. An
idle update costs two packets against that cap.

Wiring: `NpcVisibility::ambient_actors()` lists the non-excluded content actors
(runtime GUID, client model, position); `Gameplay::load` passes them to
`NpcAmbient::load` after field enemies are excluded. Season is deliberately not
applied there: the schedules are keyed by GUID and every firing is gated by the
live `model_of` lookup (which does apply season and exclusion), so an actor
whose season starts later plays from then on. The shared tick calls
`ambient::queue_due` with the player registry and membership so a look-at can
resolve a target. No new application handler, family or transaction.

## Client evidence (IDA)

The opcode-35 jump table is at `0x0092f540`; the header reader `0x008d6830`
reads two i16 (family and subtype). The packet readers:

- **35/17 SetLookAt** reader `0x008d75d0`: header, u64 actor GUID, u64 target
  GUID, 20 bytes. Case 17 is at `0x00931f99` (ctor `0x008b4440`, wrapper
  `0x008f7e00`). The target pair is stored by `0x0095a460`, which compares it
  with the null-GUID pair at `0x01be5128`/`0x01be512c`. Those addresses are in
  the zero-filled BSS tail of `.data` (the section's file bytes end before the
  pair; nothing initializes them non-zero), so target 0 takes the clear branch
  (`0x00782f20(0,0)`). **Client-confirmed; not (R).**
- **35/26 UpdateIdleAnim** reader `0x008d77a0`: header, u64 GUID, i32 animation
  id, 16 bytes. Case 26 is at `0x00932fa9` (ctor `0x008b4770`, wrapper
  `0x008f7fc0`). **Client-confirmed.**
- **35/8 SetAnimation** reader `0x008e5dd0`: header, u64 GUID, i32 animation,
  i32 zero, u8 flags, 21 bytes (already used by T507). Case 8 is at
  `0x009315c7`; the flags bit-0 branch at `0x0093163d` stores the animation as
  the base animation, so T552 sends flags 1 for an idle base. The exact meaning
  of bit 1 is not recovered here.

The fleet research pack said `nearby_sessions` returns positions; it returns
session ids only, so the look-at resolver looks each id up in the registry.
Nearest (not random) look-at is a design choice per the brief.

## Security threat note (secure-code-guardian)

Attack surface: this feature has no client request. The only inputs are
operator-owned content JSON and the shared player registry. A hostile client
cannot choose a look-at target, an actor, an interval or a packet count.

- **Hidden-player disclosure.** A look-at target guid is sent only to a viewer
  that is that player or whose directed AddPc already contains it
  (`knows_character`); otherwise the hook sends nothing. A clear packet carries
  target 0 and no player identity. A client cannot learn a player it cannot see.
- **Unknown/invalid content.** The loader validates every id is positive and
  unique, every interval/gap/radius is in its bound, and a row schedules
  something; `deny_unknown_fields` rejects unrecognized keys. The content gate
  checks every slot and model id against the client tables.
- **One player's failure.** The hook turns a full reliable queue into a refusal
  for that session only and returns; no `?` escapes the shared tick, no state is
  changed, and other viewers still receive the same firing.
- **No secrets, names or absolute paths** were added to code, tests, content or
  this note.

## Checklist

1. **Refusal changes nothing.** The only refusal is the reliable-queue error in
   `ambient::queue_due`; it returns after `refuse_field_delivery`, and the
   existing T507 test drives a due firing into a 1-byte queue and asserts the
   known-NPC set and gameplay snapshot are unchanged while the other viewer
   still receives the packet. The loader refuses malformed content before any
   table is published (unit test).
2. **Rollback covers all state.** No transaction or mutable player state is
   touched; the pass only queues packets. Not applicable.
3. **Apply deltas, never restore snapshots.** Nothing captures or restores
   inventory, coins or position. Not applicable.
4. **Busy rules are mutual.** A decorative NPC tick, not a player activity: no
   busy gate. Not applicable.
5. **Every entry path is gated.** The shared tick is the only path. A viewer
   must know the NPC (passive visibility, season included); a look-at target
   must be a ready member of the same instance and inside the radius; content
   bounds are enforced at load.
6. **Reachable in production, tested through the real tick.** The gateway tests
   call `Server::tick_shared_fields`, which reaches `sync_field_views` and
   `ambient::queue_due`, and assert the exact bodies in the viewer senders.
7. **Survives reconnect.** Schedules derive only from content, actor GUIDs and
   positions; there is no cursor or per-session state to persist. A reconnect
   reloads gameplay and recomputes the same groups and phases.
8. **Every exit path restores the player.** The feature never changes the
   character, position, busy state or a menu. Not applicable.
9. **Economy safety.** No items, coins, rewards or client quantities. Not
   applicable.
10. **Wire format matches the client reader.** Readers cited above; the unit test
    asserts exact 21-byte 35/8, 16-byte 35/26 and 20-byte 35/17 bodies,
    including the target-0 clear.
11. **Unique ids.** No ids are created. The target is an existing character
    GUID; actor GUIDs come from placed content.
12. **Others see changes.** The pass is per-viewer over the existing directed
    visibility and queue path; the two-viewer tests assert both viewers receive
    the same conversation/idle bodies and the same look-at target; the unit
    tests assert an unknown target is not sent.
13. **Content works end to end.** The content gate validates the rows; the
    gateway tests drive a real child conversation pair and a real dalmatian
    actor through the tick and assert the emitted bodies; the look-at test
    asserts a nearby target and then a target-0 clear after the players move
    out of range.
14. **Values live in data.** Conversation gaps, idle/look-at intervals,
    look-at radius, grouping radius and the per-viewer cap are in
    `npc_ambient.json` with loader bounds; the tests exercise the invalid cases.
15. **Canaries break production code.** Four canaries listed under Gates; each
    changed production code, failed its test, and was reverted.
16. **Hands off session plumbing.** `sync_field_views` gained one context tuple
    and its existing call's arguments; session creation, teardown, transactions
    and save ordering are untouched (the lead sign-off for the tick change is
    open, review finding 2).
17. **One player's error never stops the server.** The hook has no `?`; a queue
    error refuses that session and returns. Look-at resolution has no unwrap on
    player data and no state.
18. **A type's rules live on the type.** `AmbientUpdate::packets` owns the wire
    bodies; `AmbientRow` validation lives in the loader; each schedule type owns
    its `due`; `NpcVisibility::ambient_actors` owns the actor listing rule;
    `PlayerRegistry::nearest_session` owns the nearest-player rule.
19. **Hot paths stay cheap.** Groups, idle actors and look-at actors are fixed at
    load (O(n^2) over the talkers once). The per-tick pass iterates the viewer's
    known set (at most 64) and the fixed groups with no state clone; the grid
    query runs only for a due look-at (at least 500 ms apart), once per viewer.
