# S0334 findings

## Recovered structure

- **Client area definitions and geometry (`00b0a370`–`00b0c3d0`; `engine.area`).** The shape readers and writers directly bind to the RTTI-backed `ClientAreaDataShaped` specializations. The code serializes sphere, box, and dome geometry (`00b0a370`, `00b0a410`, `00b0a560`, `00b0a650`, `00b0a730`); containment methods test stored four-component bounds (`00b0b0b0`, `00b0b1c0`, `00b0b570`). `LoadAreaDefinitionShapes` (`00b0a7d0`) reads `AreaDefinition` and `shape` children, and `ClientAreaDataManager::CreateShape` (`00b0c140`) selects the concrete class for `sphere`, box, dome, or `floor`. `00b0bc70` reads either `GlobalClientAreas.xml` or a local datasource and materializes matching definitions.
- **Spatial queries (`00b0b210`, `00b0b720`, `00b0bbc0`, `00b0c2d0`).** Two recursive traversals test bounded 4D regions and collect or remove overlapping nodes. The box virtual query at `00b0c2d0` calls the first traversal. The target/result node layout and exact tree semantics remain unknown; `00b0bb90` and `00b0bbc0` are deliberately left unlabeled because their wrappers alone do not establish the searched domain. `00b0c3d0` calls the query-shaped `00b0bbc0` from a dome vtable slot; whether that slot is destruction or another geometry operation needs disassembly review.
- **Minimap tile assets (`00b0c400`–`00b0d7a0`; `engine.asset`).** The `MiniMapImages` owner maintains hash-list indexes and requests a name formatted as `%s_TileInfo.txt` (`00b0cd30`). Its load callback parses numeric tile records and rebuilds an index (`00b0d7a0` → `00b0d3e0` → `00b0d140`). Bounds, hashed names, and tile-grid addressing are visible, but grid units and the exact file grammar remain open.
- **Chat packet construction and generic containers (`00b0d9a0`–`00b10840`).** `BaseChatPacket` initializes application type 15 (`00b0d9a0`, `00b0da00`). `PacketChat`, `ChatPacketDebugChat`, and `TellEchoPacket` constructors set modes 1, 3, and 5 (`00b0f8f0`, `00b0f9d0`, `00b0fa40`). The community packet catalogue names these as 15/1, 15/3, and 15/5. Their constructors establish packet objects, not successful transmission or server acceptance. Many neighboring functions are reusable array, list, string, and allocator routines; the record leaves domain-uncertain helpers unknown.
