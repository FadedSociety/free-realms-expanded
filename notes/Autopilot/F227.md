## Security note (secure-code-guardian)

Client-triggered surface: arbitrary runtime GUIDs in `26/8`/`26/10`, wrong-job or out-of-range
opening selections, interaction while an activity runs, and replayed menus/choices. Unknown GUIDs
resolve to no content key and produce no menu or progress (and no busy-oracle feedback). Wrong-job
and out-of-range opening selections are refused before the `InteractNpc` event, so no quest
counter, inventory, wallet or save changes. The busy gate runs before
`NpcInteraction::interact`/`select` and before any quest event, so no attempt counter or open menu
is consumed and the same choice works after the activity closes. Replayed accepted interactions
cannot re-advance a saturated objective (asserted). No economy grant, client-reported outcome or
echo of client text is added; the refusal is a fixed server string. No new persisted or session
state, so reconnect is unaffected. Malformed frames still return the existing `Err` handled by the
gateway isolation boundary; no `unwrap` on client data was added.

## Checklist

1. **Refusal changes nothing** — wrong-job select compares whole save, inventory, wallet and
   `npc_quests`, and asserts `!changed`; busy `26/8` and `26/10` compare the whole save and quest
   state; the gateway busy click compares the whole gameplay JSON and asserts no `26/9`. Canaries
   A and B break production code and fail these assertions.
2. **Rollback covers all state** — no transaction state added; both refusals return before mutating
   `NpcInteraction` or `Gameplay`; `accepted` is a per-call bool on the owned outcome. No
   `Rc`/`RefCell`/`Arc` side channel.
3. **Apply deltas, never restore snapshots** — the diff only withholds an event or returns a chat
   line; tests compare state, never replace it.
4. **Busy rules are mutual** — one `Occupation` table via `activity_busy()`
   (`blocks(|g| g.start)`); crafting, gathering, chess, encounter, derby, fishing, soccer and kart
   all refuse NPC interaction, and NPC learn/race/derby/fish still ask the same helper. The table
   pin test `gates_reproduce_the_replaced_busy_lists` passes in `--lib`.
5. **Every entry path is gated** — regional `26/8` (menu) and `26/10` (choice) check the shared
   gate after the content key resolves; opening actors keep the five opening-handler activity
   refusals plus the new acceptance gate for the quest event. The only other `on_interaction`
   caller is the developer `OpeningEngine::handle_command`, which emits no quest event, so it
   cannot bypass the gate. No new path was added.
6. **Reachable in production, tested through it** — tests send real wrapped `26/8`/`26/10` frames
   through `Gameplay::handle_in_world`; the gateway regression drives `Gateway::handle_at`. No test
   calls the fixed logic directly.
7. **Survives reconnect** — no new persisted or session state; `quest_save_tolerance` (9 passed,
   1 ignored) covers saved quest state.
8. **Every exit path restores the player** — the busy test cancels the Mining18 run with the real
   `26/42`, asserts the run is gone, then completes the earlier refused interaction. A wrong-job
   refusal never enters an activity.
9. **Economy safety** — no grants or rewards added; wrong-job and busy tests assert inventory and
   coins unchanged; quest progress comes only from the server-side interaction event.
10. **Wire format matches the client reader** — constructors `0x008b6bc0` (26/8) and `0x00a36f80`
    (26/10), readers `0x00c7af60`/`0x00c7b070` with common prefix `0x00c7acd0`; byte-level builder
    test against the captured `application-0066.bin` frame plus exact 49/9 (27-byte) and 49/10
    (23-byte) assertions.
11. **Unique ids** — no runtime id is created; the synthetic opening actor uses one fixed GUID
    (`9_000_000_901`), distinct from regional NPCs and node ids.
12. **Others see changes** — not applicable: opening acceptance, NPC menus and quest counters are
    private; nothing visible to other players changed.
13. **Content works end to end** — the accepted controls reach 1/1 through the menu/dialogue and
    interact packets, and the dungeon path still passes; the acceptance assertion is on the final
    counter (1) and emitted 49/9/49/10 bodies, not an intermediate flag.
14. **Values live in data** — no timeout, cap or tuning constant added; the refusal is a fixed rule
    string, not a tunable.
15. **Canaries break production code** — canary A edits `opening.rs`, canary B edits `npc.rs`; both
    fail production tests and were reverted byte-identically (hashes above).
16. **Hands off session plumbing** — no change to `src/bin/osfr-gateway.rs`, `gateway.rs`, session
    creation/teardown/transactions or save ordering.
17. **One player's error never stops the server** — every refusal returns `Ok(Outcome)`; no new
    `?`/`unwrap` on client data; malformed frames still return the existing `Err` handled by the
    gateway isolation boundary.
18. **A type's rules live on the type** — `accepted` is documented on `OpeningOutcome`; the busy
    decision remains `Occupation::gates`/`is_occupied`; the refusal is one `Gameplay` method.
19. **Hot paths stay cheap** — the gate is one 12-variant boolean scan per `26/8`/`26/10` with no
    clone; the refusal allocates one chat line only on refusal (`bool::then` is lazy). Nothing runs
    per tick.
