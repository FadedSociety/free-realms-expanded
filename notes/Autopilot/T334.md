## Threat note (secure-code-guardian)

Attack surface: any client can send 26/8 (arbitrary u64 target + flag), 26/10
(arbitrary target + i32 choice), 26/6 (arbitrary row), 49/2 (quest id + accept
flag) and 49/14 (quest id) at any time from any position.

- 26/8 resolves only a spawned content actor through `NpcVisibility`'s content-key
  map; Smitty/Trixi are static content rows. The wrong-NPC test proves a Talk at a
  non-target actor cannot advance the Trixi step or offer 3100003.
- 49/2 accepts only an actually offered quest after `offer_denial`
  (enabled/objectives, giver, pending offer, prerequisite, active+unlocked job,
  limit). The job gate cannot be chosen by the client: `character_eligibility`
  uses the saved active profile only, and the non-Miner / inactive-Miner cases are
  asserted.
- 49/14 settles only the saved `pending_turnin`; a forged reply without the
  server-opened end screen, a wrong quest id and replays all pay nothing (whole
  state and save bytes compared).
- Rewards are content-authored (5 coins, 15 profile-14 XP, empty item list) and
  paid through the existing grant key / `RewardState`; no client amount, item id
  or result is trusted. There is no free item to sell or re-grant.
- A near-cap balance is a clean `InvalidData` refusal for that player: the
  gateway records it as a rejected application and discards the staged clone
  (`src/gateway.rs` 1662-1677), so the player stays connected, the held end
  screen remains for a retry, and no coins/XP/item/save byte change.
- Refusals are per-request results; no production code was added and no `?` in a
  shared tick.
