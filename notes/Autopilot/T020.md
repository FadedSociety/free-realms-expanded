# T020 Grouping: invite, accept, leave, kick, group chat

## What changed

- `src/social_lists.rs`: `invite_to_group` now rejects a self-invite before creating a
  group and performs pending-invite, leader and capacity checks before any group is
  created. A refused cross-group invite can no longer leave the inviter in a phantom
  one-member group.
- `src/bin/osfr-gateway.rs`: added a two-session-plus-observer router test covering
  family-40 invite, accept, roster fanout, channel-4 party chat, non-member refusal,
  non-leader kick refusal, leader kick and leave/dissolve. It also verifies that the
  server rebuilds the chat sender from the authenticated session.
- `src/bin/osfr-gateway.rs`: `SharedWorld::social_disconnect` now refreshes every
  survivor's chat membership after a disconnect. Without this, the last member of a
  dissolved party retained the old group id and could address itself on channel 4.
- `tests/social_lists.rs`: added a focused refusal test for self-invite, repeated
  invite, cross-group pending invite, membership and pending-invite preservation.

No application handler selector was added, so the existing `app_fuzz` family-40 seeds
remain sufficient.

## Reconstructed policy

- (R) A character cannot invite itself. The refusal uses 40/2 code 3
  (already grouped) and performs no mutation.
- (R) A target with any pending invitation refuses a new invitation with 40/2 code
  4 from another group or code 6 from the same group. The inviter is not placed in
  a new group as a side effect.
- (R) Only the group leader invites or kicks; a group falling to one member
  dissolves; leaving or disconnecting clears party chat and pending invitations.
- (R) The configured local party cap remains 17, and membership remains volatile.
