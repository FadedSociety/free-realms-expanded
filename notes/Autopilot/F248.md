## Secure-code-guardian threat note

This change still touches coins, items and client-triggerable shop traffic, so:

- **165/5 sell** (client sender `sub_C76DD0`): a hostile client chooses only the merchant GUID
  pair, item instance, quantity and replay. It has **no price field**; the server resolves the
  owned instance, refuses positive/oversized/consumed/stored/equipped/rental/no-sale ids, and
  reads the unit price from the loaded catalogue after the starter rule. Buy-back credits the
  recorded unit price (0 for a starter), so sell/buy-back cannot mint coins. Nothing in this
  diff reads a client price or grants a free reward.
- **66/42 merchant window** is server-to-client. The starter substitution happens on the
  server after selection; a client cannot request a window field. The wire layout is
  unchanged; only the value the server writes changes.
- **Starter ids** come from content (`profiles.json`), not from a client packet, a save or a
  compiled list. A newly added starter is covered when the play package's profile table is
  loaded; no client input can add an id to the set.
- **`--content` and the fixture** are developer tooling, not runtime paths. The checker only
  reads `stores.json`/`vendors.json` and reports; it never edits content, and every row keeps a
  `type(x) is int` guard.
- **Denial of service:** `starters` is a `BTreeSet` built once per `CoinShop` construction and
  once per Shop selection (77 ids); no unbounded growth, no per-packet scan, no new lock.

## Client evidence

  `a2/a3` (merchant GUID pair), `*a4` (item instance) and `a5` (quantity) into the request
  struct and calls `sub_C76820`; there is no client price. The server remains price-authoritative.
- **66/42 entry reader `0x00b29cd0`** (`sub_B29CD0`): reads six dwords per entry (then the
  flag and three more dwords), matching the 38-byte entry the test decodes. **Counted list

  `header 4 + initial dword 4 + six group dwords 24 + count 4`; the entry's first three dwords
  are the server's item/purchase/sell convention (R), as `gameplay/npc.rs::merchant_packet`
  documents. No field order changed.
- No new opcode, enum value or selector. No new app_fuzz seed is needed.
