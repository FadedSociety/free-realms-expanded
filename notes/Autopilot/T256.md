# T256: shared-field kills credit the killer's active kill quests

## Result

A shared-field kill now reaches the killer's own quest engine exactly like a
solo kill already did. `EncounterEngine::strike_damage` used to push the
defeated definition into `EncounterOutcome.defeated` only when
`shared_sender.is_none()`, so every shared-world kill (the live open-world
path through `with_shared_fields`) produced an empty `defeated` vector and
`Gameplay::apply_encounter` never emitted the killer's
`QuestEvent::KillActorKind`.

The change is one guard in the existing `hp == 0` block: the self-only
`remove(guid)` reply still depends on `shared_sender.is_none()` (the shared
field owns the removal broadcast), `boss_display`, `forget_target`, the drop
roll and every T240 reward line are untouched, and the definition is pushed
only when positive. A shared kill therefore now drives the existing
`apply_encounter` -> opening `Defeat` event and
`npc_quest_event(KillActorKind { actor_kind_id, count: 1 })` path; no second
quest path, packet family or persisted state was added.

Killer-only, deliberately: the other player's engine never runs A's `strike`,
so B receives no `defeated` event. The shared field's HP/death/respawn
broadcast is unchanged; group-wide quest credit is the later slice named in
the brief.

T240 (commit 4876383) is merged in this tree. Its `KillCredit` and
`claim_kill_credits` reward path still pays coins and active-job XP exactly
once per credited player and was not duplicated or restored.

A definition of 0 is now skipped at the producer. The content loader allows a
field actor with `definition_id: 0` (`validate_actor` refuses negatives only),
and `OpeningEngine::on_event(Defeat)` refuses a non-positive definition; before
this slice the solo path would have errored on such a kill, and the shared path
would have hidden it behind the guard. The filter makes both paths ignore it
without an error, a panic or a quest advance.

## Client evidence (IDA available, no new wire bytes)

The slice adds no opcode, packet field or actor field. A kill reaches the
client through the existing quest objective packets, and the tests pin their
layout byte-for-byte:

- 49/9 QuestObjectiveUpdate: common header `0x00c7acd0` (u16 family/subtype =
  `49,0` then an i32 subtype = `9`), reader `0x00c7af60` reads quest id,
  objective key, current counter, progress float, a bool and one trailing dword
  in that order; apply `0x00c7a990` stores the counter at objective `+0xd4` and
  the progress at quest `+0x28`. Test helpers use the 6-byte header and the
  `6..10`/`10..14`/`14..18` offsets.
- 49/10 QuestObjectiveComplete: reader `0x00c7b070` (same prefix, then quest id,
  objective key, progress float, one dword, bool). The fifth kill's 49/10 is
  asserted in test 1.
- 49/8 ObjectiveActivated: `QuestMessage::ObjectiveActivated`, header + quest,
  objective, required. The fifth kill asserts the Talk objective activation.
- 49/4 QuestComplete: reader `0x00c7b420` -> body reader `0x00c7b230` (common
  prefix plus one i32 quest id). The reconnect turn-in asserts the 49/4.
- 49/13 QuestEnd: reader `0x00c7b990` (two dwords = u64 actor, quest id, end
  text, animation dword); dispatcher `0x00c7cd40` case 13 calls
  `ShowQuestEndScreen` `0x00a95420`. The reconnect test asserts quest id at
  `14..18` and end text at `18..22`. 49/14 QuestEndReply constructor
  `0x00a864c0`, sender `0x00a97ef0` (existing pin).
- The brief labels `0x00c7bd10` a "49/3 objective update" reader. IDA and the
  Build Guide both show `0x00c7bd10` is `ApplyQuestAddPacket` for 49/3
  QuestAdd; objective progress is 49/9/49/10 above. IDA wins; the server still
  emits the 49/3 QuestAdd unchanged on accept/login, and this slice adds no
  49/3 traffic on a kill.
- Combat/actor packets are unchanged and untested for new fields: 32/7
  AttackProcessed, 35/5 enemy HP, 35/8 animation, 35/3 remove, 38/19/38/14
  T240 rewards, 41/114 reader `0x009bdd70`, 35/2 AddNpc constructor
  `0x0091cac0` / body reader `0x00921a10`.

## Security note (secure-code-guardian)

Threat surface: a hostile client can send `36/10` abilities, `26/8`/`26/10`
interactions and `26/13` job switches on the shared field. It cannot report a
kill, a definition id, an actor's health, a quest id or an objective count. The
definition pushed into `defeated` is the server-owned field actor row's
`definition_id` from trusted content; the kill is the server's own
alive-to-dead HP transition; the quest event is generated by the server with
`count: 1` and the quest engine caps the counter at the objective's required
count. The sender used for the field simulation is the authenticated session
GUID (`handle_shared_field` receives `character.guid`), never a body-supplied
guid or the enemy's last-hitter list.

Refused/ignored: a non-lethal hit, an evade/return-home actor, a corpse hit
(the existing `s.health == 0` early return), an out-of-range/cooldown/weapon
refusal, an unknown target, a definition of 0 (skipped at the producer), a
replay of the lethal request, a repeated shared tick and a second turn-in. A
per-player apply failure still returns the request error, and the gateway
commits only its staged `Gameplay`/field clones, so the other player's session,
the shared field runtime and the save are unchanged. No coin, item, reward,
trade or save-ordering code was touched, and the `defeated` event is private to
the killer's session (no new fanout).

## Checklist

(Numbered 1-19 against `lab/autopilot/worker-rules.md`; see the final report
for the same list.)

1. **A refusal changes nothing.** No new refusal path; `defeated` is pushed
   only on the existing `hp == 0` transition after the existing guards. Test 3
   replays the lethal request on the corpse and runs the shared tick twice,
   asserting the counter, the save and the field HP are unchanged. Test 7
   refuses A's malformed position and asserts the field HP is unchanged; the
   stale quest save is refused at bind and leaves A's `npc_quests` empty.
2. **Rollback covers all state.** The defeat event lives in the existing
   `EncounterOutcome` inside the gateway's staged `Gameplay`/field clones; no
   new `Rc`/`RefCell`/`Arc` or side table. The quest counter is the engine's
   own state.
3. **Apply deltas, never restore snapshots.** The quest engine increments the
   live active quest's counter with `saturating_add(1).min(required)`; nothing
   restores a captured inventory, coins or position.
4. **Busy rules are mutual.** No new activity, station, minigame or
   `Occupation` row; the busy table and its pin test are untouched.
5. **Every entry path is gated.** The only kill transition remains
   `strike_damage` (basic attack, job abilities, DoT ticks, solo and shared).
   The shared request still passes `handle_shared_field`'s profile/zone/active/
   weapon checks and the gateway's known-NPC/instance checks before the kill.
   No new NPC menu, automatic or reconnect path reaches the action.
6. **Reachable in production, tested through it.** Tests call
   `Gameplay::handle_shared_field` (the request `commit_outcome` runs),
   `Gameplay::tick_shared_effects`, `Gameplay::load` +
   `bind_npc_quest_catalogue` and `handle_in_world` for the non-shared path.
   No test-only copy of the logic; no internal engine-only kill is used for the
   shared credit assertion.
7. **Survives reconnect.** The kill counter lives in
   `GameplayState.npc_quests` (serialized with the character save). Test 5
   serializes `GameplayState`, loads it through `Gameplay::load`, rebinds the
   catalogue exactly as the gateway does, asserts the counter/status survive,
   then turns the quest in once.
8. **Every exit path restores the player.** No new location/control/stuck
   state; the existing knockout, revive, respawn and close paths are unchanged.
   The shared kill's own HP/removal handling is untouched.
9. **Economy safety.** This slice grants nothing. The turn-in test asserts the
   shipped 18 coins / 25 job XP are paid once; a repeated 49/14 changes nothing.
   The only reward still riding the outcome is T240's existing, already-claimed
   payout. No client quantity, id or result reaches the economy.
10. **Wire format matches the client.** No new field. The added assertions are
    byte-level for 49/9 (`0x00c7af60`), 49/10 (`0x00c7b070`), 49/8, 49/4
    (`0x00c7b420`/`0x00c7b230`) and 49/13 (`0x00c7b990`); the unchanged
    32/7/35/5/35/8/38/19/38/14 replies are pinned in test 8.
11. **Unique ids.** No new instance/GUID/lifecycle id; the synthetic field
    actors use distinct GUIDs and the production quest uses the existing
    content ids.
12. **Others see changes.** A kill is already visible through the shared
    field's existing spawn/HP/removal broadcast; the new `defeated` vector is
    private to the killer's engine and is not fanned out. Test 2 asserts B's
    counter and save stay unchanged and B receives no 49/3/49/9/49/10.
13. **Content works end to end.** Tests use the shipped T241 quest 3000009:
    five `3156` field kills advance the defeat goal, the fifth produces the
    Goal Complete and activates the Talk step, the Talk opens the end screen
    and 49/14 pays 18 coins/25 Brawler XP once.
14. **Values live in data.** No tuning was added. The quest, its counts and
    reward, the field actors and the reward table are content. The only new
    constant is the structural rule that a defeat names a positive definition.
15. **Canaries break production code.** Both canaries were edits to the
    production `src` files (the old shared guard; a T240 credit that carries
    the defeat into `claim_kill_credits`), not test-side failures; both failed
    the intended test and were byte-restored.
16. **Hands off session plumbing.** `src/gateway.rs`, `src/bin/osfr-gateway.rs`
    and session creation/teardown/save ordering are untouched.
17. **One player's error never stops the server.** The kill apply returns the
    request error for A and never a `?` out of a shared tick; the gateway
    discards its staged clone. Test 7 refuses A's stale quest save and A's
    malformed request, then B kills and is credited in the same field. T240's
    per-player reward refusal (logged, `Ok`) is unchanged.
18. **A type's rules live on the type.** `EncounterOutcome.defeated` now
    documents that it carries positive definition ids; the producer enforces
    it. The quest counter/cap rule stays in `quest_engine`.
19. **Hot paths stay cheap.** Per lethal hit the change is one `i32` comparison
    and the existing `Vec::push`; a non-lethal hit, a tick or a packet with no
    kill allocates nothing new. No state clone was added.

## Open gaps

- Group-wide credit for other group members is deliberately not in this slice;
  only the engine that lands the lethal hit receives `defeated`.
- No native client run. The wire is unchanged and every packet layout the
  tests assert is pinned to the client reader above.
- The content loader still admits `definition_id: 0`; this slice makes the
  kill path ignore it, but a future content rule could reject it at load.
- The names of the two pre-existing shared-field tests
  (`w127..._no_personal_credit` and
  `area_and_dot_damage..._never_deliver_personal_credit`) now describe T240
  reward credit, which they still pin; this slice gives a *quest* kill event
  to the lethal hitter. Renaming was avoided because the integrator's
  protected-pass list pins passing test names.
