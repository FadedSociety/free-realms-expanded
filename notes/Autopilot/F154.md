## Security note (secure-code-guardian)

Threat: a hostile client can send a forged `41/108` Go, replay it, forge the
`26/8` target GUID, or send a forged `167/1/2` battle id at any job level; an
admin-only developer command can also ask the engine to start a battle.

Why it is refused: the accepted level is always the server-owned active-profile
XP (`Gameplay::job_level`), never a client value. The battle id must resolve to
a row loaded from `field_battles.json`; an unknown id yields no required level
and `EncounterEngine::begin` still fails the content lookup. The pending battle
id and instance are server state. `admit_battle` runs before the pending screen
is consumed, so a low-level Go leaves it usable; an unknown marker GUID creates
no pending state. Rewards still come only from the encounter engine's
server-owned kill completion. `realm sim` operates on a cloned engine and was
asserted (snapshot equality) to change nothing. The shared predicate does not
read any client-provided field.
