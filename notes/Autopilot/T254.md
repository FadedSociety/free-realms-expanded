## Threat note (secure-code-guardian)

A hostile client can send a 26/10 body with a forged target GUID, an option id never offered, a
replayed choice, a choice for another NPC's menu, a body of the wrong length, or a burst of
choices in one bundle. Every one is refused before a commit: length is checked first; the runtime
GUID must map through `content_npc_key`; the shared busy gate refuses while any activity runs;
`NpcInteraction::select` requires an open menu for that exact NPC and a currently offered option
in range/zone; a `NeedsQuestEngine`/`Invalid` selection is answered with a refusal or an error
without committing. The staged choice runs on a clone and commits only when the service reports
`changed`, so a failed/refused service cannot consume the menu, spend a pending offer or write a
save. The change adds no new parser, no new persistent field and no new wire surface; the pure
event builders take only IDs/counts and never raw client text. The zero-GUID test input is a
test-only forged session; production `CharacterState::validate` rejects a zero GUID at the trust
boundary.
