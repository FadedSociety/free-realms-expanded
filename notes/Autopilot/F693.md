## Security threat note (secure-code-guardian)

A hostile client can send only 26/8 with an arbitrary u64 target. The body must decode (13 bytes,
family 26/sub 8, trailing flag <= 1); the target must be a site in this session's own node catalog
and, by the file tag, one of that file's spawns — it cannot name a type, a count or a reward. A
pickup is admitted only when the site is a `quest_nodes.json` pickup, shown, the player is not
busy (shared occupation table), in zone 0, within the content interact range, and the player's own
active quests have an open `collect_node` step for the site's type. Every refusal returns before
the staged clone exists, so no menu, offer, attempt counter, item or cooldown is consumed. The
credited amount is the server's constant 1 (saturating, capped at the objective's required), and a
pickup grants no item and no coin; the quest file's empty drop table is a load error, so there is
no second economy path. Node visibility and regrow state are per-`Gameplay` (one session), and
guids never come from the client. The guid fix removes a data-triggered denial-of-world-entry: a
future mining/quest pool numbering spawns from 1 would otherwise fail `GatheringNodes::load` and
`Gameplay::load`. No new file write, no persistence change, no unbounded slice or unwrap on client
data; `now_ms` arithmetic was already the existing server clock and the respawn bound (1..=86400 s)
is enforced at load.
