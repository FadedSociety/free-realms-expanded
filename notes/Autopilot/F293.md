## The regression without a test-only seed

`tests::f261_pickup_reload::f261_the_commit_clears_a_revive_reloads_ground_pickups` now:

1. copies a real campaign with `test_support::vendor_content`, then adds two synthetic 1-health
   field enemies on the world checkpoint with the shipped guaranteed `boss` power-up table and
   copies the bundled `data/content/power_ups.json` (both deterministic and data, not code);
2. installs that population exactly as `Server::new` does (`load_gateway_template` ->
   `take_shared_fields` -> `World::install_field_seed(0, ..)`, `src/bin/osfr-gateway.rs:3406-3408`).
   **F305 correction:** at F293 this install ran after `Scene::new`, i.e. after the session
   existed; F305's `Scene::with_field` installs it before the session, as `Server::new` does;
3. logs in and drives `[13,0]`/`[10,0]` through `Session::dispatch_message` (the commit path);
4. switches to Brawler with the real 26/13 request so the equipped starter weapon makes a basic
   attack legal (the campaign's default profile 1 has no basic weapon);
5. kills enemy A with the real 36/10 targeted request through the socket-shaped dispatch path:
   `Session::commit_outcome` -> `Gateway::handle_shared_field` -> `EncounterEngine` kill ->
   `drop_power_ups("boss", ..)`. The pickup is the server's roll, not a fixture shortcut. The
   test marks the two GUIDs in `known_npcs` first, the interest set a field view would publish,
   because the bare session never runs the Server's field view pass;
6. knocks the player out (`Gateway::receive_field_damage`) and sends the client's free revive
   (41/122). The revive returns to the same world instance, so only the commit's
   `outcome.began_zoning` can clear the drop: assert health restored and `pickup_count() == 0`.
   **F305 correction:** F293 assumed the instance was unchanged but did not assert it; F305
   asserts the membership instance id is identical before and after the revive;
7. re-sends the ready handshake, ticks on the spot and asserts the stale heart does not heal.
   **F305 correction:** F293 ticked at full health, where `heal_with_number` heals zero, so this
   assertion was vacuous; F305 wounds the player first and asserts the health is unchanged;
8. kills enemy B after the reload and asserts the same spot tick **does** pay that live heart
   (positive control), so step 7 cannot pass as an inert tick.

The F261 API surface (`Gateway::seed_power_up_drop`, `Gameplay::encounter_mut`,
`EncounterEngine::seed_power_up_drop`) is not used by any test now; there is no new public API to
sign off.

## Security threat note (secure-code-guardian)

Attack surface: the client's 36/10 ability request, 26/13 class selection and 41/122 free revive,
and the session-only ground pickups the revive commit clears. No production request path changed
in this diff; it only removes test/diagnostic APIs.

- A hostile client can send 36/10 freely. The server accepts slot 0 only for targets the session
  already knows (`known_npcs`), resolves the target against the server-owned field population,
  range-checks it at the player's committed position and the drop comes from the content table on
  the server's roll. A client cannot name a pickup, table, kind, amount or position.
- 26/13 only switches to an already-unlocked job with a valid outfit; it grants no item or coin.
  The test uses Brawler 43 because the campaign unlocks it and its starter weapon is already
  equipped, exactly the production condition.
- 41/122 is accepted only while the session is knocked out; the header ids carry no authority, the
  destination is the content checkpoint, and a paid value is refused by the existing window path
  (unchanged; `tests/free_revive.rs` re-ran the refusal tests green).
- Refusals change nothing: this task adds no refusal path; the new test's steps are accepted. The
  existing free-revive/paid/replay refusal tests were re-run and still assert no mutation.
- No auth, role, session creation/teardown, save ordering, wire format, persisted value, content
  value or dependency changed. No client value selects or fabricates a drop: the pickup is the
  server's own `boss` roll for a server-owned kill.
