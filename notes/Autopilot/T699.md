## (R) rules

- **(R) Reference pairing**: `actor_kind_id` is the `Npcs.json` definition that
  shares the target's model. Where the reference has no `NameId` (mostly quest
  variants such as 1638/1639, 3115, 4857), the row takes the target's own client
  name id from `lab/reports/locale-id-to-text.json`; the pairing of definition
  and name is reconstructed.
- **(R) Stats**: level, `max_health` and `damage` follow the W58 final-era ladder
  already in `enemies.json` (level 5 180/15, 9 260/23, 13 340/31; boss 5 540/30,
  9 780/46, 13 1020/62); `move_speed` 3.0, `aggro_radius`/`leash_radius` 40.0,
  `attack_range` 2.5, `attack_cooldown_ms` 1000 and `respawn_ms` 30000 are the
  existing prototype defaults. Rewards are 0 coins / 0 XP: no recovered drop
  table exists for these targets, and a quest target must not become a free
  farm.
- **(R) Field spawn values**: the shipped field ladder (level <= 5: 100 HP / 8
  damage; 7-9: 180/8; 13: 200/10; respawn 60-120 s; aggro 8 m). Those stay
  inside `field_enemy_budget`'s 90 s lone / 30 s camp floors and
  `field_camp_separation`'s band clearance.
- **(R) Quest gating**: every new field actor is present only while one of the
  worklist quests is active, following the four quest-gated Hooligans of quest
  3030007 and the owner's field note that overworld enemies belong to active quests.
  The quest ids exist in `data/content/quests/*.json`; the quests themselves stay
  disabled until step 5 of `OBJECTIVE-PLAN.md` wires them.
- **(R) Thugawug Fumbler and Sneak share level 5**: their reference spawns
  (`FabledRealms.lua:405/406`) are 5.6 m apart with the same ground height, i.e.
  one reference camp, so they must not sit on bands more than two levels apart.

## Security threat note (secure-code-guardian)

What a hostile client could try, and why it is refused:

- **Claim a kill it did not make.** The kill event is emitted only by
  `EncounterEngine::strike_damage`/the shared-field claim from server-side HP
  (`out.defeated`), never from a client message. The new rows add no request
  selector and no client-settable field; `app_fuzz` seeds are unchanged because
  `application_handler` is untouched.
- **Farm the new rows.** Every new definition grants 0 coins and 0 XP; the field
  actors carry the `standard` power-up table only and are quest-gated, so they
  cannot be farmed before the quest exists. The field kill payout still comes from
  `field_kill_rewards.json` by level band (unchanged).
- **Duplicate or alias an id.** All 22 ids are unique across `enemies.json`,
  `field_enemies.json` and `field_battles.json` (asserted by the new test); the
  field GUIDs are `100e9 + definition_id`, outside the 130e9 placement and
  131e9-132e9 live-coin ranges.
- **Inject bad content through a reload.** The loader validates every field
  (`deny_unknown_fields`, level 1-20, positive health, finite radii, known
  behaviour preset); the new test proves a bad row is refused and the live field
  is byte-identical afterwards (no partial reload).
- **Crash a session.** No `unwrap` on client data was added; the rows are read
  once at load and a malformed file is an `Err`, not a panic.

## Checklist

1. **A refusal changes nothing** — applied to the only refusal this change has,
   the field reload: `a_refused_new_row_leaves_the_live_field_unchanged` snapshots
   the live `(guid, position)` set, writes a level-0 T699 row into a private
   content copy, asserts `reload_field_enemies` errs, and asserts the set is
   unchanged. No request/offer/cooldown path exists here.
2. **Rollback covers all state** — the reload goes through
   `EncounterEngine::staged` on a clone (`field_content.rs`); no new shared state
   is introduced, no `Rc`/`Arc`/side table added.
3. **Apply deltas, never restore snapshots** — not applicable: the change moves
   no inventory, coins or position.
4. **Busy rules are mutual** — not applicable: no new activity or handler.
5. **Every entry path is gated** — the new actors are quest-gated
   (`quest_ids`), which is the same gate the existing quest enemies use. The gate
   is applied on every path: `Gameplay::sync_field_quests` (`gameplay.rs:2025`)
   derives the active set from the saved quest state on each world tick, and
   `bin/osfr-gateway.rs:3046` does the same for the world; the catalogue rows are
   inert data read at load.
6. **Reachable in production, tested through it** — the new suite drives the
   real `EncounterEngine` (shipped content, `on_zone_ready` + `set_active_quests`
   + `attack`) and asserts the defeat carries `definition_id`, which
   `Gameplay::apply_encounter` turns into `KillActorKind`. The catalogue is loaded
   with the real `EnemyEngine::load`. No internal copy of the logic is tested.
7. **Survives reconnect** — not applicable as new state: nothing new is
   persisted. Presence is derived from the already-saved NPC quest progress
   (`Gameplay::sync_field_quests`), so a reconnect with the quest active
   re-spawns the target on the next world tick and a reconnect without it stays
   hidden; the rows themselves are content, re-read at load.
8. **Every exit path restores the player** — not applicable: no player state.
9. **Economy safety** — new rows grant 0 coins/0 XP and no items; no free grant
   and no sellable reward. Every id is server-authored from the client tables.
10. **Wire format matches the client reader** — not applicable: no writer
    changed. The rows reuse the verified AddNpc writer; the actor kind is
    server-only.
11. **Unique ids** — asserted in the new test (no duplicate `actor_kind_id` /
    `definition_id` across the catalogue, and no field GUID collision inside
    `field_enemies.json`; the GUIDs sit outside the 130e9 placement and

13. **Content works end to end** — the new test kills each live spawn and

14. **Values live in data** — every value added is content data; no constants in

15. **Canaries break production code** — ran three canaries against the shipped

16. **Hands off session plumbing** — `src/bin/osfr-gateway.rs` and `gateway.rs`

17. **One player's error never stops the server** — no shared-tick code changed;
