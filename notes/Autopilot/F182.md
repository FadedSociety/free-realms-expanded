   The `enter_public` regression keeps the protected name
   `t032_a_private_child_never_aliases_a_seeded_public_instance` (see the integrator follow-up).
5. **MINOR 6 (pre-existing refused-transfer save ordering) — left to the lead, unchanged.**
   `Session::commit_outcome` still writes the character save before

### Deviation from the review's proposed F4 fix

The review proposed `available_instance_id` plus `next_instance_id` staging for public instances.
That allocator is seeded above the registered zone ids and belongs to private children. Using it
for public space (a) breaks the pinned `tests/world.rs` contract that zone 7's public instance is
id 7, and (b) regresses
`shared_world_membership::conversions_cap_and_ready_mismatch`: a zone id near `i32::MAX` seeds the
cursor at `i32::MAX`, so `enter_public` fails with `InstanceIdsExhausted`. The helper therefore
keeps the scene-derived id when free and falls back to a lowest-free-id probe for public space
(skipping ids in use and registered zone ids). This still removes both failure modes the review
names — a private child is never aliased, and a legitimate entry is never refused for a taken id —
and public ids never consume private-child capacity. No test expectation was changed.

## Security threat note (secure-code-guardian)

Attack surface: the big-heart group heal, ground power-up pickups, and public-instance entry.

- The heal is reachable only from a server event: `EncounterEngine` spawns the drop from a
  server-observed kill, the pickup is applied from the server position, and
  `GroupHeal { percent, kill }` is generated server-side. A hostile client cannot name a kill
  guid/millisecond, a percent, an instance, a player or a drop table. The claim instance comes from
  `World.players` (server membership), not from any packet; a player with no committed place
  returns `None` and writes nothing, so replay cannot consume another group's kill. The ledger is
  bounded at 256 and keyed by `(instance, enemy guid, now_ms)`.
- The pickup clear runs on the cloned gateway during `commit_outcome`; a refused transfer discards
  that staged clone before the live session is replaced, so the live pickup list, membership and
  ledger are untouched. Only the session's own ground pickups are cleared; held power-ups and saves
  are not touched, and no wire packet is emitted.
- Public-instance entry never accepts a client instance id; targets are server-authorized. The new
  staging helper can only reuse a free id: it never overwrites a `ZoneInstance`, never returns an
  id that is in `instances`, in `public_instances`, or a registered zone id, and `make_instance`
  revalidates the zone. That removes the cross-instance/field-key reuse hazard.
- No new client input parsing, save field, wire format, role or secret path was added. No
  arithmetic can overflow: the public-id probe ends at `i32::MAX` and returns
  `InstanceIdsExhausted`; the ledger pop is bounded.
