# T399: Games > Battles finder lists the battles

2026-10-21 (Opus lane)

## Result

The 167/1/1 writer filed every battle row under **category 18**. In the client
that category is **"Micro-Games"**, not "Battles". **Battles is category 10.**
Games > Battles opens the finder on `Activities.Category10`, which no published
row ever reached, so its strip was empty. The fix sends battle rows with
category 10 and that category's art (`bandit_hideout_detail.dds`) in place of
the Micro-Games art (`hacknslash_detail.dds`). Everything else in the row is
unchanged: wire layout, title/description ids, icon, difficulty,
`CanPlayerJoin` (combat job + `required_combat_level`), entry type and the
167/1/2 Play path into `begin()`.

The brief's premise was half right. The rows were accepted (the wire is
reader-exact). The fault was not in the shared row layout but in the category
id. **Cooking being empty is expected:** the server publishes no cooking rows
(category 12). The policy "only battles, chess and soccer are listed" is
unchanged.

Predicted native check (for the lead): Games > Battles now shows the ten field
battles. Before this fix the same rows would have appeared under Games >
Micro-Games.

Changed files:

- `prototype/osfr-tools/src/activity_portal.rs`: `COMBAT_CATEGORY` 18 -> 10,
  `ART` -> `bandit_hideout_detail.dds`, and the module doc records the category
  binding with addresses.
- `prototype/osfr-tools/tests/activity_portal.rs`: the byte-level pin now
  expects category 10 and the category-10 art.
- `prototype/osfr-tools/tests/common/field_battle_fixture.rs`: the shared
  reader-faithful `decode_list` now also returns `category` (+0x10), `icon`
  (+0x14 ImageSetId) and `name` (+0x28 NameId, the name the strip shows).
- `prototype/osfr-tools/tests/activity_portal_route.rs`: a new test,
  `world_entry_lists_every_battle_under_battles`.

## (R) choices

- Battle rows use category 10's table art (`bandit_hideout_detail.dds`) for
  both detail and thumbnail. This is the same rule soccer uses: the table's
  THUMBNAIL column holds the detail image. `bandit_hideout_thumb.dds` exists
  (`AssetsW_009.pack` 2449), but nothing ties it to these battles.
