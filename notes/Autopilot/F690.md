## Review findings -> change

1. **BLOCKER, the committed 35/14 client evidence was wrong.** Corrected
   `notes/Autopilot/F686.md` (client-evidence section and its "IDA contradicts no note" line). The
   35/14 reader `008d6830`/`008d6890` reads the header (two u16), then the packet's **model as an
   i32 at object +0x18** and the **guid u64 at +0x10**; `0096bd90` takes that model from `a2+24`
   (0x18). The actor's **+324** temporary-appearance field is written by the AddPc reader
   `0091aa10` and `0096bd90` only sign-tests it (`*(this + 324) < 0`) to end the temporary
   appearance. No code or wire change; the module doc's AddPc `+324` statement and
   `PlayerPresentation::display_model` were already correct.
2. **MINOR `[STRUCTURE]`, the transform row carried dead dance data.** `Boombox::valid` now
   requires `dance_sequence`/`clip_ms` exactly on `Synchronized` rows, and the transform row
   (item 1180) no longer carries them: `"dance_sequence": [3541]` and `"clip_ms": {"1941":
   [12667]}` are deleted (`clip_ms` is `{}`; the field is required by serde). The one-source-per-
   kind rule is now complete for all three kinds: synchronized = sequence + clip lengths,
   independent = `clips`, transform = neither. The test comment in
   `every_dance_is_a_client_animation_slot_or_group` says so, and the loader gained two refusal
   cases ("transform with a dance sequence", "transform with clip lengths"). The stale F686
   finding-7 text is amended.
3. **MINOR `[STRUCTURE]`, per-press copy of the clip table.** The catalogue now stores each row as
   `Arc<Boombox>`; `Catalogue::get` hands out `&Arc<Boombox>`, `ItemBar::boombox` clones that
   pointer, `Gameplay::boombox_row` returns it, `Boomboxes::spawn` takes the `Arc`, and
   `Independent` holds the same `Arc<Boombox>` (reading `row.clips`, `row.blend_ms`,
   `row.standing_animation_id`, `row.priority`, `row.range_m`) instead of building a fresh
   `Arc<BTreeMap>`. A press now copies no clip table at all (was two ~250 KB copies), and the
   per-message `SharedWorld` clone is one pointer. Tests: `a_boombox_row_lookup_returns_the_shared_
   catalogue_row` (gameplay hands out the catalogue's pointer twice) and `a_live_box_points_at_the_
   pressed_catalogue_row_instead_of_copying_its_table` (the live box holds that pointer).
