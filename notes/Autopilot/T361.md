## Security threat note (secure-code-guardian)

What a hostile client can send and why it is refused:

- 49/2 with a forged/unknown quest id, or 49/2 for a quest not currently offered: the
  engine requires `pending_offer == id` and a server-created offer; refused, no state
  change (snapshot test).
- 49/14 before completion, a replayed 49/14, or a forged 49/14 id: `finish_turnin`
  requires the exact `pending_turnin`; refused and the 15 coins are not paid
  (snapshot/replay tests).
- 45/7 with the W5 objective id: 45/7 can only name `ClientReported` goals; the job-level
  objective has no client id, so the forged claim advances nothing (snapshot test). No
  packet can claim a job level.
- Out-of-range 26/8: the production NPC range check refuses before any menu; the gateway
  drops the staged clone.
- A busy encounter occupation: the shared occupation table refuses the NPC menu before an
  offer or turn-in can be consumed (snapshot test).
- Content with profile 0, an unknown positive profile, level 0/21, a duplicate objective
  id or missing provenance is refused by the whole split-catalogue load (fail-closed).
- A near-cap wallet refuses the 15-coin payout atomically (existing reward path; the test
  asserts the save, wallet and pending turn-in are unchanged).

No client value reaches `QuestEvent::JobLevel`: the event carries only the server-owned
`Profiles::rank` (1..=20), so there is no forged level or profile path.

## Open gaps

- Only the Warrior W5 record is enabled. Other job guide level gates remain disabled and
  empty, as scoped; a later slice authors them without another engine change.
- The 15-coin reward is a reconstructed gate payout; the historical guide reward is
  unknown.
- `realm level` is developer-only and can lower a level; the objective never regresses
  because a completed goal is no longer open.
- A job-level goal that becomes current later in an *ordered* multi-step quest (after a
  non-level event completes the previous step) is credited at the next accept/level/
  load/turn-in sync, not at that instant. W5 is single-step, so this is unreachable in the
  shipped content; a future multi-step gate should call the helper when opening the step.
- There is no central notification seam beyond this helper: a future XP site must call
  `sync_job_level_objectives`. All current sites do (real XP, developer level, opening
  reward, both kart claims, quest turn-in, accept, bind).

## Checklist

1. **Refusal changes nothing** — `refusals_change_nothing` snapshots bytes/coins/counts
   for 49/14-before-completion, forged 49/2, forged 45/7, wrong-NPC Talk, out-of-range
   26/8 and busy-menu refusal; `the_progress...` checks a replayed 49/14 pays nothing.
2. **Rollback covers all state** — every client-triggered path (accept, turn-in, level
   command, kart reward) runs on the session's staged `Gameplay` clone; the gateway drops
   the clone on `Err`. The load-time bind runs before the character is exposed and keeps
   the session's `client_objectives` across its sync so no half-registered state escapes.
3. **Apply deltas** — `a_live_change_before_the_turn_in_survives` grants 7 coins between
   accept and turn-in and asserts 7 + 15 remain; no snapshot is restored.
4. **Busy rules are mutual** — no new activity; the existing `occupation.rs` table is
   used, and the busy encounter refusal is tested through the NPC menu.
5. **Every entry path gated** — the goal can complete only from the server rank on a
   level/award/turn-in/accept/bind path; 45/7 cannot. `refusals_change_nothing`, the
   accept/level tests, the turn-in test and the engine-level
   `a_job_level_event_is_profile_exact_and_uses_at_least` cover the paths.
6. **Reachable in production, tested through it** — the tests drive
   `Gameplay::handle_in_world` (NPC Talk/accept/turn-in), the production field-kill
   reward path, the real catalogue bind and `realm level`; no engine-internal shortcut is
   used for those.
7. **Survives reconnect** — `the_progress_and_reward_survive_a_reload` round-trips the
   serialized save mid-quest, after completion and after payment;
   `a_reconnect_at_a_late_level_completes_it_on_load` proves the bind-time credit and the
   re-sent 49/10.
8. **Every exit path restores the player** — the change adds no location, movement or
   occupation state; cancel/refusal returns the same state.
9. **Economy safety** — 15 coins only from the server's 49/14 pending turn-in once; a
   replay pays nothing; `a_near_cap_wallet_refuses_the_turn_in_atomically` proves a
   near-cap wallet refuses atomically; the reward is content, not client-reported. The
   turn-in job XP that completes another gate is server-paid and bounded.
10. **Wire format matches** — no new fields; the exact 49/10 bytes are asserted against
    reader `0x00c7b070` (re-decompiled this run) and 49/9 was re-decompiled too. The other
    cited readers are the existing pinned ones the unchanged encoders use; the late IDA

11. **Unique ids** — no new instance/GUID/lifecycle ids; the content objective id 1 is
    unique per quest and the catalogue rejects duplicates.
12. **Others see changes** — nothing in this change alters another player's visible
    outfit, job, mount or actor; level XP packets are the existing 38/14 path to the same
    player.
13. **Content works end to end** — the tests offer W5 at Steele, accept, complete at rank

14. **Values live in data** — profile 32, level 5, quest id, giver, prerequisite and 15

16. **Hands off session plumbing** — no changes to `src/bin/osfr-gateway.rs`,
