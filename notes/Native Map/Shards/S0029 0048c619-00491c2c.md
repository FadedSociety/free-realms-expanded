## Findings

- **Bitmap and color helpers (0048c619–0048de51).** Function 0048c619 fetches source pixels through slot +0x198, packs rows with 0048c220 and writes them through a local writer at +0x18. Caller 0048c8ca writes a TGA header first, so 0048c619 is the row payload emitter rather than a decoder into its source object. 0048d380 searches a 549-entry named-colour table beginning with AliceBlue; its external standard/provenance is unproven. The remaining functions cover color conversions and property access.
- **Color-combine and matrix mismatch (0048ca8f, 0048d7c9, 0048d866).** Function 0048ca8f looks up GColorCombine but uses keys at 01769f28 and 01769f24, whose bytes are UTF-16 x and y, not ColorOp/AlphaOp. It writes both values through slot +0x4c. This contradicts notes/Native Map/Systems/engine.gfc.fx.md. Callers 0048e15b and 0048e7c2 use this helper for effect combine fields, leaving schema intent unresolved. The matrix pair formats M%d%d for 25 calls but passes only the name to slots +0x40/+0x44; neither body visibly moves cell values. Their load/store roles remain speculative, correcting stronger claims in notes/Native Map/Systems/engine.gfc.core.md.
- **Field and cursor helpers (0048dba8, 0048dcf8, 0048ddd7).** The indexed field param_1[0xc] is byte offset +0x30, not +0x0c. Both query functions have three outcomes: flagged slot +0x10c call; clear-flag eligible outcome (return 0 without output writes in 0048ddd7; return 1 without writes in 0048dba8); or alternate stored-field path when +0x30 is nonzero or +0x14 is negative. The alternate 0048ddd7 path calls param_2 slot +0x110 with the +0x30 value and conditionally copies two output groups. These correct the field and branch descriptions in notes/Native Map/Systems/engine.gfc.core.md. Function 0048dcf8 deletes GetIconInfo bitmaps and destroys a temporary icon only on success; failure zeros outputs without that cleanup.
- **Driver registry (0048eaa1, 0048ebd6, 0049141f).** Draw and font resolvers query the shared registry for their named driver classes. On a miss each passes GDraw_GDI.dll to 00546169, but that mapped callee is a stub that returns zero; retry is gated on its return. The functions establish registry lookup/attach mechanics, not successful DLL loading. Function 0048ebd6 unregisters two stored identifiers. Helpers 00480983/00480a1b fill local outputs unused as queried IDs; 004cd10a supplies the identifier used for the support query.
- **Text and formatted-string methods (0048ef55–0048fc7d, 00491570–0049162f).** Function 0048f01f acquires the incoming interface before releasing the old +0x1c pointer. Function 0048f07f releases/clears +0x1c, acquires the incoming pointer, then releases/replaces +0x20. Function 0048f120 copies its local pair on a zero virtual return and writes {0,-1} on a nonzero return. Constructor-shaped function 0048f3fe writes the range word +0x38=0xffff, +0x3c=0, +0x40=0x7ffffffe, +0x44=0, +0x48=0, plus +0x20=0x100 and +0x24=0x20; its concrete class is not established by a temporary GPropertyInterface base-vtable write. Function 0048f2df releases two interfaces then tail-jumps to 004e78f5; 0048f768 calls it and tail-jumps to 004dc61b. Functions 0048f67f–0048f69f subtract four from ECX and jump to their targets; vtables bind them to GFormattedStringAccess, with several shared by GFormattedString. Functions 0048f612/0048f62a/0048f642 are ordinary helper-call wrappers, not variadic thunks. Range helpers 0048f6a7, 004916ac and 0049162f preserve the caller's start on negative length and use 0x7ffffffe only for the end. Function 0048fc7d copies selected dwords and individual bytes at +0x1c, +0x34 and +0x58..+0x5b, rather than copying every field as a dword.
- **Font and glyph path (00490072–00491c2c).** Font property codecs lead into Win32 glyph drawing/metrics and a paged cache. Function 00490fd5 reads byte +2 of each four-byte pixel, converts it, and writes byte +3; channel meaning is unknown. Function 00491295 folds ABC widths only after GetCharABCWidthsW succeeds, not in the fallback branch. The property-key mismatch remains: 00490b29 fetches GGlyphInfo, while 00490cc0 fetches GFontInfo; this may be a key convention or copy/paste defect. Function 00490f7c computes ((count-1)+index)%count without checking zero count. Function 004918fa allocates a null page, but its existing-page cleanup frees without clearing the receiver's pointer; 00491966 also leaves its array entry unchanged after free. Function 00491824 conditionally AddRefs param_9 but calls its slot +0x10c unconditionally, and divides by param_7/param_8 without zero checks. Function 00491713 has no caller; its association with glyph-cache fields is a field-shape hypothesis.
