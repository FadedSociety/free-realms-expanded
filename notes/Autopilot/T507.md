# T507: townsfolk, critters and children play ambient animations (35/8)

## Summary

Passive content NPCs now play per-model idle and emote animations. A new library module
`src/npc_ambient.rs` loads `data/content/npc_ambient.json` (50 rows imported from Sanctuary
`NpcAmbient.json` at `Sanctuary-main-20261019@10f129e`), validates it, and computes a stateless
per-actor schedule. `Gameplay` loads the table with the other NPC content and exposes it through
`gameplay/npc.rs`. The gateway's shared-field tick (`Server::sync_field_views`, one call per valid
session) queues at most `max_packets_per_viewer_per_tick` 35/8 packets per viewer, lowest GUID

## Data and schedule

`data/content/npc_ambient.json`:

- `schema_version` 1, a Sanctuary `source`, `max_packets_per_viewer_per_tick` 4 (R; bounds 1..=16).
- 50 rows, one per Sanctuary row with `AnimationIds` (the 51st row has only `IdleAnimationIds` and
  is the later T552 slice). Each row has every client `Models.txt` id bound to its file name
  (case-insensitive), 1..=16 `AnimationSlot` ids, `500 <= min <= max <= 600000` ms, and a row source
  naming `ModelFileName=<file> (R)` plus the client slot names.
- Imported values only: the conversation, idle and look-at fields stay out.
- The runtime loader refuses structural bounds (ids, intervals, cap, duplicate model binding,
  unknown JSON fields). The client-slot rule ("unknown slot is a load error") is enforced by
  `tests/content_npc_ambient.rs`, which reads the lab `AnimationTypes.xml`, and by
  `content_check.py`'s `animation_missing` error; production must not read client resources.
- The table loads with `Gameplay::load` at start; no content reload path exists for it (documented).

Schedule (R): `period = min + mix64(guid) % (max - min + 1)`;
`phase = mix64(guid ^ PHASE_SALT) % period`; a firing is any `t` with
`(t - phase) % period == 0`; the k-th firing plays `ids[h3(guid, k) % len]` where
`h3 = mix64(guid ^ (k + 1) * FIRING_SALT)`. `due` returns the latest firing in `(from, to]`
so a long stall never replays a backlog; `None` for an unknown model or an empty window.
The table's per-viewer cap is applied in `due_for_known`, iterating the `BTreeSet` ascending.

## Client evidence (IDA, 2014 client)

- `0x00908a50` is the validity gate around the real reader: it calls `sub_8E5DD0` and checks the
  cursor (`decompile 0x00908a50`). The field reader is **`0x008e5dd0`**: after the header it reads
  two dwords as the GUID (`+16`/`+20`), then the animation id (`+24`), a dword (`+28`) and a byte
  flags (`+32`).
- The header reader is **`0x008d6830`**: two `__int16` fields (family, subtype) = 4 bytes.
- The opcode-35 dispatcher's jumptable is `0x0092F540`; case 8 is at **`0x009315c7`**. It constructs
  subtype 8 through `0x008b3ee0` (which calls `sub_89FBB0(8)`), calls the gate, resolves the actor
  through `0x00984960`, and at `0x0093163d` tests flag bit 0: set writes the animation id to the
  actor's base slot `+0x51c` and destroys the packet; clear calls `sub_96C780`
  (PlayOrQueueActorAnimation) with bit 1 as a separate boolean. Ambient sends flags 0 = play now.
- The 21-byte layout is therefore `u16 35, u16 8, u64 guid, i32 id, i32 0, u8 flags`, matching the
  non-test Rust writers (`encounter::animation`, `enemies::animation_packet` and
  `restoration::piece_052::animation_packet`) and the pre-existing fourth copy in the T458 test
  (`t458_world_events.rs:48`); this commit reuses `encounter::animation` and adds no fifth. The new
  byte-level test builds these bytes and the gateway test asserts the exact queue body.
- Nuance vs `notes/Research/Native NPC Motion and Animation.md:46`: that note calls `00908a50` "the
  native reader"; IDA shows it is the gate around `008e5dd0`. The layout it records is correct.
  The dispatcher address in the fleet note (`0092f460`) is the opcode dispatcher region, not a
  function start in the IDA database; the case-8 label at `0x009315c7` is what was verified.

## Threat note (secure-code-guardian)

- Ambient is server-to-client only. No client packet creates, targets or chooses an animation; the
  ids, intervals, model binding and per-viewer cap are server content read once at load.
- The only client-influenced input is its own validated position (opcode 125, speed/bounds checked
  by `movement::validate`), which decides which passive actors are in its view. It cannot make a
  packet name another player or a field actor: the hook iterates `session.known_npcs` and asks
  `NpcVisibility::model_of`, which returns `None` for excluded field actors.
- Content is bounded and fail-closed: regular file <= 1 MiB, <= 512 rows, 1..=16 ids per row,
  positive distinct ids, 500..=600000 ms with `min <= max`, cap 1..=16, one row per model id (a
  duplicate binding is refused),
  unknown fields refused. A malformed file fails `Gameplay::load`; it never reaches the tick.
- A full reliable queue refuses that viewer's packet, logs `field_delivery_refused` through the
  existing helper, and does not touch that player's state or fail the shared tick. Tested.
- No secrets, saves, coins, items, rewards, roles or chat are involved; other players only see the
  same NPC animation, which is public content.

## (R) rules

- Intervals (Min/MaxIntervalMs), the 4-packet default cap, the phase/firing hash scheme and the
  "latest firing in a stalled window" choice are reconstructed. Upstream names no source for the
  measured-looking intervals.
- The model->row binding is factual: every client `Models.txt` id bound to a Sanctuary
  `ModelFileName`.
- Field-actor exclusion is a server rule: field enemies are excluded from `NpcVisibility`, so
  `model_of` returns `None`; battle spawners are passive visibility rows and may animate.
- A window's firing is one animation per viewer; when a long stall spans several periods only the
  latest is played (R, chosen over replaying a backlog).

## Open gaps

- The hook lives in the shared-field tick. A zone instance with no field seed (no encounters/field
  content) never reconciles `known_npcs`, so it also gets no ambient. The open-world zone 0 is
  seeded by `Server::new` in production and in the test; other deployments without a field seed
  would need a tick hook outside `sync_field_views` (out of scope here).
- The table loads from the same `npc_content` directory as `npc_spawns_extra.json`/`npcs`. A play
  package that ships NPC rows but no `npc_ambient.json` gets no ambient (fail-safe, not an error);
  a freshly built bundle copies every committed `data/content` file, so it includes the table.
- T548 (critter wander) and T552 (talk/idle/look-at, extended 35/8) will extend this module; T548's
  moving-actor skip and T552's extra fields are not implemented.
- The schedule is absolute from the server's start clock, not per actor spawn; a restarted server
  starts a new phase. The brief accepts this: nothing is persisted and a reconnecting viewer sees
  the next firing.
- `content_check.py --strict` stays red on the pre-existing tip errors; see the gate above.
- Native visual confirmation (Sanctuary townsfolk waving/fidgeting) is the lead's run.

   snapshots `known_npcs` and the gateway snapshot before a refused firing, forces a 1-byte queue,
   enables the Studio inspector, ticks, and asserts both equal, `faulted_fields` empty, the firing
