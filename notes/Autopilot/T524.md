## Reconstructed rules (R)

- No job gate on a collection node; the click grants exactly one item; the node is personal (not
  shared between players).
- One drop is rolled by weight from the **pool's** table; the type tables stay empty for the
  imported file (validated at load).
- The roll is one draw from the player's per-session stream, seeded from OS entropy when the node
  set loads and advanced only when a click commits (the staged clone rolls a refusal back). No
  client-supplied value reaches the seed or the draw, so a modified client can neither select an
  item nor learn the stream ahead of time, and the weighted table always applies. The shared
  `power_ups::pick_weighted` helper performs the pick. Tests inject a fixed stream through
  `Gameplay::seed_collection_rolls` / `GatheringNodes::seed_rolls`; the gateway never calls them.
  (F735 fix 1 replaced the former `(player, node, click now_ms)` seed, which a client could time.)
- `respawn_seconds` from the pool starts when the click consumes the node; it shows again at
  `now >= consumed + respawn`, personal to that player.
- The water companion (tag 4, model 271, non-interactable, extra effect) is (R): Sanctuary adds
  `ExtraCompositeEffectIds`, and the client's invisible cube is an effect-only actor.

## Deviations from the brief (say why)

1. **Guid tag 5, not 3.** T503 already uses tag 3 for `quest_nodes.json` (spawns 100-104, which
   would collide with collection spawn ids 79-927). Tag 4 is the brief's companion tag. Tag 5 is
   free, and the loader/guid-space design already gives each node file its own tag
   (`tests/quest_pickup_nodes.rs::same_spawn_id_in_the_mining_and_quest_files_stays_distinct`).
   The app_fuzz seed therefore uses a **tag-5** guid, not the brief's tag-3 wording.
2. **`consume`, not a new method beside `paid()`.** T503's `picked(guid, now_ms)` already did
   exactly "hide now, reuse the regrow map, no change when already hidden"; it is renamed and
   documented for both kinds rather than duplicated.
3. **A per-session stream, not a per-click time seed** (see (R)). Tests inject a fixed stream with
   `Gameplay::seed_collection_rolls`; the production seed is OS entropy and no client value enters
   it. `every_click_draws_afresh_from_the_pools_table` consumes 200 draws on one node and
   `the_collection_roll_follows_the_pools_weights` pins the weight distribution on a synthetic
   three-weight pool.
4. The verify-first prerequisites held: `data/content/collection_nodes.json` (T523) and
   `src/gameplay/collection_pickup.rs` (T450) exist; collection-completion-rewards (T480) is merged
   and is reached through the same `record_collection_entry`.

## Threat note (secure-code-guardian)

Hostile client input is one 26/8 frame with a u64 target and one trailing byte. It can:

- name any guid: only a guid this session placed (`NODE_GUID_BASE | tag | spawn id`), currently
  shown, inside 12 m of the character, in the open world, and while `activity_busy()` is false is
  accepted. Every other target falls through to the existing NPC/node routes or is refused.
- replay a click on a hidden node: `shown` is false, so the existing `Gone` line is sent and
  nothing is granted, no regrow deadline moves.
- malform the frame (wrong length/flag): `decode_npc_interact_26_8` returns `Err` before any
  staging; the gateway's per-session isolation turns that into that player's `internal_error`
  disconnect, not a server fault.
- try to steer the item: structurally impossible. There is no client item id, quantity or seed;
  the item comes from the server's pool table and one draw of the player's OS-entropy-seeded
  stream. The test-only `seed_collection_rolls` hook is never called by the gateway. (F735 fix 1:
  the former `(player, node, now_ms)` seed let a modified client time its click to a chosen item.)
- farm the node: intended (it regrows), but the collection entry is once-only on the saved ledger
  and the item cannot be sold for profit: none of the 1024 collection drop items nor the 8 mushroom
  drops appears in `stores.json` item rows or any `vendors.json` stock (checked 2026-10-25), so the
  vendor sell path has no price for them.
- overflow the bag: `Inventory::accepts_reward_bundle` runs the same grant on its internal clone
  (the canonical preflight, same start gate as Type8); a full bag or a stack/count failure refuses
  with `Your bag is full. Make room before gathering.` and changes nothing. All item arithmetic
  stays inside `Inventory` (`checked_add`, `MAX_ITEMS`). The preflight does copy the inventory
  once; it is not free, but it no longer re-implements the grant outside the type.
- a content set with the collection node file but no catalogue, or a drop with no catalogue entry:
  refused with the generic line before staging, so the item is never granted and the node never
  hides without its ledger entry (F735 fix 4).
- crash the tick: the pickup is per-request, not in a shared tick; a staged content error is logged
  (`collection_node_refused`) and refused, never propagated out of the player's handler.
