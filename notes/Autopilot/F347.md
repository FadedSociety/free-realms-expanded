## Review finding disposition

1. **BLOCKER, false "verified" claim.** Fixed in the test, not by weakening the claim:
   `let a_before = saved(&a);` is taken before B's far 26/8 and
   `assert_eq!(saved(&a), a_before, "B's refusal changed A's state")` follows it, next to
   the existing B snapshot and A's pending-offer check. The comment no longer claims B has
   an open menu; it says B has no pending offer yet. Canary 1 breaks the production range
   gate and fails the test, proving the refusal branch is exercised.
2. **MINOR, moved 39/5 comment lost its client citation.** Fixed: the shared helper now cites
   39/5 `0x009be7d0` -> writer `0x009bdc60` and 39/14 `0x009be6b0` -> constructor
   `0x009b09d0`.
3. **MINOR, near-duplicate `Models.txt` parser.** Fixed with `tests/support/models.rs`;
   both content gates use it. The helper keeps the "every numeric row has a filename"
   assertion (it panics on a missing second cell) and trims both cells like the canonical
   Python reader `scripts/content_check.py::load_caret_ids`. It lowercases names because
   both gates compare model file names case-insensitively.
4. **MINOR, two-viewer test does not use server sessions.** The premise needs correcting
   for static spawns: there is no shared-world fanout for them. Each gateway session calls
   `Gameplay::update_npc_visibility` for its own character (`src/gateway.rs:1477` on
   `Event::Loaded`, `:1585` on a location change), so two independent `Gameplay` sessions
   are exactly the production input; the osfr-gateway shared-field path
   (`shared_npc_view`/`field.initialization`) is for field actors, not static spawn rows.
   The test comment now says explicitly that the gateway session loop and the shared-field
   fanout are not exercised. No test rename was needed: the test name is about content
   resolution.
5. **MINOR, `save_and_reload` hardcodes `CHARACTER`.** Fixed: it reloads under
   `character.guid` and documents that rule. Regression proof: the new B reconnect in
   `two_miners_progress_independently` fails under the old hardcoded id (canary 2).

## Threat note (secure-code-guardian)

Attack surface exercised by the changed tests: any client can send 26/8 with an arbitrary
target from any position, or 49/14 with any quest id at any time. No production parsing,
save or reward code changed in F347.

- The far 26/8 is refused by the existing range gate; the test now asserts **both**
  sessions' serialized `GameplayState` stay byte-identical (and A's pending offer remains),
  so a refusal cannot silently consume another player's offer or mutate a nearby session.
- The forged 49/14 is refused by the existing `pending_turnin` guard; both sessions remain
  byte-identical, B's held end screen survives, and B's own reply pays once. Canary 1 in
  F333 removed that guard and failed the test; F347 leaves the guard untouched.
- The B reconnect proves the save envelope reloads the refusing/second character under its
  own id; a bound-to-the-wrong-character reload fails closed instead of silently binding
  the fixture default.
- The `Models.txt` reader is a content-integrity gate, not a trust boundary: it prevents a
  wrong `model_id` from shipping a different body while the file name looks valid.
- No client amount, item id, model id, quest id or result is trusted by the changed tests;
  there is no new reward, save or broadcast path.
