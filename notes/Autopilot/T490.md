## Client evidence (IDA, this pass)

Sender `00b5fcf0` (`SendPetFollowLocation`, caller `00b60770` on message kind `0x1000`) was
decompiled and disassembled again:

- It copies the four incoming floats to `this+0x12d0..0x12df`; the cached vector is the next
  `__m128` at `+0x12e0`.
- Gate A: the 4D distance from the new vector to the cache must be at least `0x01b5d878` =
  `0x41200000` = **10.0 m** (`disasm` of the data address).
- It clears the can-go byte at `+0x12f9`, then `008a7d50` fills four owner floats.
- Gate B: the 4D distance from the owner vector to the click must be in **[8.0, 40.0]** (inlined by
  the compiler; the operands are `0x0176b1b0` = 8.0 and `0x017ed93c` = `0x42200000` = 40.0).
- Gate C: `a3[2] <= 0.5` (`0x017649d4` = 0.5). The vector `a3` is not the click and is not sent to
  the server; there is no server counterpart.
- Gate D: the delta from `007027f0` (`timeGetTime`, milliseconds) through `008b0e20` must be greater
  than `0x01b5d874` = `0xC8` = **200 ms**.
- Packet ctor `00b51b20` zeroes the byte at +32; serializer `00b5a530` writes the 16 bytes at +16
  through `sub_91A640`, then that byte (`sub_7CC400`). Request body: four f32, one u8 0 (17 bytes).
- Reply reader `00b578d0`: `sub_B55280` base header, `sub_8E2410` reads **four dwords** into
  +16..+31 (not "the u64"; F850 re-read it), and the byte at +32 becomes the can-go flag at
  client `+0x12f9`. A body shorter than 16 payload bytes sets the stream's bounds error
  (`sub_8E2410`), `sub_B58300` returns false, and the case-26 handler at `00b5ce60:0xb5edc0` never
  sets the flag. The reply is therefore header + four dwords + flag (17 body bytes); the server
  echoes the click's four floats there and the client handler reads only the flag.

The fourth float's meaning is not recovered (R). All four take part in the client's own 4D gates;
**(F850 corrected)** the server now measures the same 4D distance for the owner band (with the
owner's fourth component taken as 0, R), requires the click finite, and never uses the clicked y as
the pet's height (the heightfield does). IDA wins over
`src/restoration/piece_091.rs:42-46` and the fleet research pack, which both said these constants
were unresolved.

## Threat note (secure-code-guardian)

A hostile client can send 53/26 with any bytes. The decoder checks the length before indexing,
requires the one flag value the client writes, and rejects non-finite or >1e6 coordinates with `Err`
(the session logs a refused pet request; no panic and no state). A well-formed click is still refused
with flag 0 unless it is 8-40 m from the server's live owner position (4D, so a forged fourth
component counts), at least 10 m from the last accepted click, at most one `click_max_m` path from
the pet, and walkable on the server's heightfield. The cost is bounded by 81 ground samples (0.5 m
spacing over a 40 m path; F850 corrected the old "80") and one 20-byte reply; the 200 ms interval and
10 m step (F850) rate-limit accepted moves, and the cheap band/interval refusals run before any
sampling. A flood of refused clicks allocates one small packet each and touches no state (neither the
interval nor the last accepted click is consumed by a refusal). **(F850 corrected)** The client's
clicked y is not the pet's height and its flag must be 0, but the y does take part in the 4D band and
the pet's walk height comes only from the heightfield; the actor guid and owner position come from
the session; nothing is granted (no coins, items or XP). A gridless zone cannot be used to move the
pet arbitrarily because every click there answers 0.

## Open (R) and gaps

- Not driven by a native client. The client's can-go flag (`+0x12f9`) and the pet's walk animation
  are the native check: summon a pet, click terrain 8-40 m away, watch the reply 1, the walk and the
  wait; click a cliff and watch 0. **(F850)** The reply now carries the 16 payload bytes the client
  reader consumes, so the flag can be set at all; the native run is still owed.
- The fourth float's meaning is not recovered beyond "the same 4-float vector's fourth component";
  the server only requires it finite and uses it in the 4D owner band (R). All four words take part
  in the client's own 4D gates (F850 corrected the old "the server uses the horizontal (x, z) band").
- **(F850)** The client's gate A (10 m minimum displacement between sends) is now enforced against
  the last **accepted** click (`FollowConfig::min_click_step_m` = 10.0), the server's nearest
  stand-in for the client's own cache: a click the client computes but does not send (a failed owner
  band, direction or interval gate) updates the client's cache and not the server's, so the server
  can be the stricter side (R).
- `step_up_m`/`step_down_m`/`sample_m`/`resume_m`/`go_timeout_ms` are (R) (OSFR PR #152 for the
  first three, first choices for the last two). The walk is a straight-line height check, not a
  pathfinder: an obstacle blocks the pet and the no-progress warp brings it back after
  `warp_far_ms`.
- The pet walks a click at the pace its actor spawns with (`movement_speed`, 5 m/s since T827 (R);
  `min_speed` 2 m/s before it); no run pace and no arrive animation beyond the stop frame.
- The client's third gate (`a3[2] <= 0.5`) has no server counterpart: the vector it tests is not
  sent, and its slot/axis meaning is unresolved. The server's heightfield check substitutes.
- **(F850, F858 corrected)** In a zone with a height grid, a step whose two ends are both unknown (a
  hole, or outside the grid), whose endpoint is unknown, or whose endpoint differs from the ground
  under the pet by over `step_up_m`/`step_down_m` (a hole or dip narrower than `sample_m`) is
  refused; the T455 owner-height fallback now applies only to a zone with no height grid at all
  (`terrain_height` returns that fact next to the closure). F850 checked only the lookahead, so the
  point the pet moved to was untested until F858 restored the endpoint check.
- **(F850, F858 corrected)** The step's walk check covers both the endpoint the pet moves to and at
  least one `sample_m` ahead along the movement direction, and `walkable` samples at fixed
  `sample_m` intervals plus its endpoint; the first pass's folded sampling missed a cliff between a
  short step's two samples. Canary A2 reproduced the old descent (the pet at y=3.42 after crossing
  x=0); F858's canary reproduced the review's dip step (the pet at y=-4.0 at the first tick).
