# T695: Snowhill NPC rows drawn at their one reference spawn

The lead's `placements/snowhill.json` names 55 regional rows matched to one reference spawn
by client name. At this tip 49 of them are already drawn, so this task binds the remaining
**6** Snowhill rows to the spawn's position, heading, model and NameId. No production Rust
changed; no hub file changed; no new wire shape.

## What changed

- `data/content/npcs/snowhill.json`: 6 records moved from `poi_anchor` to `legacy_data` /
  `legacy_data_spawn` with the Legacy spawn transform and model. `position_reason` cites the
  Lua line + `Npcs.json` row and carries the required
  `matched by the spawn's client name (talk_spawns.py) (R)` marker. Confidence `medium`.
  Every other row in the file is byte-identical (95 records before and after; CRLF kept).
- Fields updated per record, following the file's existing `legacy_data` rows and the
  `content_npcs.rs` / `content_npc_spawns.rs` loader rules: `position`, `rotation` (Y
  quaternion of the spawn heading), `placement`, `placement_source`,
  `placement_confidence`, `placement_candidates: []`, `position_reason`, `name_string_id`
  (the spawn's `Npcs.json` NameId, which resolves to the row's name), `name_string_id_reason`,
  plus the new `heading`, `model_id`, `model_file_name` and their `field_sources`. The
  record-level `source` array (each regional row's own) gains a `legacy-data` tag and a `(R)` T695 tag. `name_string_ids`,
  `zone`, roles, quest/vendor fields are untouched.
  - `name_string_id` also had to change on 4 rows (Derp, Jeni, Sakka, Shimmer) whose value was
    a ucdt table id, not a Global.Text id: a `legacy_data` row must name a locale id
    (`content_npc_spawns.rs`). The old ids stay in `name_string_ids`.
  - `capture_match`'s field source said "regional rows currently have no model_id"; that is no
    longer true, so it now says no startup actor was identity-matched (value still null).
- New test `prototype/osfr-tools/tests/snowhill_reference_placements.rs`:
  - selects this brief's six rows by npc_id (`PLACED`; asserts each is `legacy_data` /
    `legacy_data_spawn`, positions come from the data), loads the real `world::NpcVisibility`, runs `update` from each
    row's position, parses the 35/2 AddNpc bodies and asserts exactly one actor for the row,
    its position, model id and name id, and no other drawn actor within 1 m;
  - scans every `legacy_data` row plus every extras body whose `content_key` is a regional
    row (the actors the client draws), asserts unique actor ids and no two within 1 m
    (732 actors, 0 pairs at this tip).

## Threat note (secure-code-guardian)

What a hostile client can send: nothing that reaches these values. NPC placement is static
server content read at `NpcVisibility::load`; a client only moves (validated by
`movement.rs`) and therefore only chooses which already-built AddNpc bodies it is sent. There
is no new request, save, coin/item, reward, role, chat or other-player-triggered state, and
no new application selector (no app_fuzz seed needed). The values are still bounded by the
existing loader/tests: non-finite positions are skipped at load, model ids/names are locale-
and Models.txt-checked, and the test asserts one actor per id at the recorded position. No
new trust boundary; the change cannot be driven by client-supplied data.
