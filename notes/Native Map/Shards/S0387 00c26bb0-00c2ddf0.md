## What this shard is

Two coherent layers, in address order:

1. **Lua bindings for the GFC/Gui control classes** (00c26bb0..00c28980). Each
   control has a userdata-to-C++ accessor (`luaL_checktype` tag 7 +
   `luaL_testudata` + `luaL_error "<X> is NULL."`), a set of method bodies, and a
   `luaopen`-style registration that runs from the client Lua initialiser
   `00976070` (it passes `*(Client+0x94)` as the `lua_State`). Method names are
   recoverable mechanically: every registration calls `00e39e40`
   (`luaL_register`) with a `{name, function}` pair array in `.rdata`
   (`nmq bytes` on the array decodes name pointers and function pointers
   directly). Recovered modules: **TableControl** (00c26e10; getSelectedRow
   00c26d10, getData 00c26fb0), **LabelControl** (00c27320; getText 00c274c0,
   setText 00c271b0), **EditControl** (00c27c50), **Button** (00c28470),
   **WebBrowser** (00c288d0, three IME-entry methods), **Window** (00c28e60), and
   the ImageControl methods that spill in from the previous shard (00c26bb0
   `getSize` -> +0x70/+0x74, 00c26bf0 `getPosition` -> +0x68/+0x6c).
2. **The client DataSource layer** (00c294a0..00c2ddf0), built on the
   `GuiDataSource`/`GuiDsTable` interfaces (RTTI descriptors
   `GuiDataSource` 0x01b34a78, `GuiDsTable` 0x01b36d7c inside 0084cfc0), plus
   the `ItemSearchEngine` and SoeUtil string helpers at the tail.

## Server-contract inferences (hypotheses)

No function in this shard builds or parses a packet, so all `wire` arrays are
empty by evidence. What these classes *expose* nevertheless constrains the
original server contract, and each hypothesis names the local pieces it depends
on:

- **Server list** (`BaseClient.ServerList`, ctor 00c2a020): columns
  Name/Online/Locked over rows built from the client's server array
  (`*(client+0x2203c)`, next at row+0x2c); status text 00c29d00 maps state 0 ->
  "Invalid session token", 2 -> "No servers available", -1 -> "Unable to get
  list of servers (unknown error)". Hypothesis: the original server validated a
  session token and returned a server list carrying per-server online/locked
  flags; the request itself is issued by 0070d040 from the kick-off helper
  00c29d50, whose packet belongs to a net.* shard.
- **Account/character info** (`BaseClient.AccountInfo`, ctor 00c2a760): columns
  IsMember/MaxCharacters/IsAdminAccount/HeadshotUrl/CharacterGuid/CharacterName/
  CharacterModelId/... read from the client character array (count at
  client+0x22298, stride 0x62b0, name byte gate); status 2 -> "Account has no
  characters". Hypothesis: a login-time account-info message carried membership,
  admin flag, max characters and the character list whose fields fill these
  columns; the fetching function 0070d000 (from 00c2a220) is the packet-side
  dependency.
- **Character create**: the customization-category source composes the Lua
  binding name of each category's data source as `BaseClient.<suffix>`
  (00c2ae60 case 3 through 0097f5d0 with literals "BaseClient" and "%s.%s"; the
  name-category source does the same through 0097f940, literal "BaseClient.%s",
  at 00c2bb70 case 2). That is a real naming contract worth reusing when the
  reconstruction publishes per-race/per-category name and item data sources.
- **Equip screens**: `BaseClient.Inventory.CurrentlyEquipped` (00c2c750),
  `BaseClient.VehicleList` (00c2bf00), `BaseClient.Vehicle.LoadoutList`
  (00c2c560), `BaseClient.Vehicle.CurrentlyEquipped` (00c2cc00); the can-equip
  predicate 00c2c8f0 ends in the client check 00ae1a40 whose own log string is
  "ClientPcProfile::CanEquipItemInSlot invalid slot %d", so slot validation is
  client-side. The vehicle list adds an "Active Vehicle" column
  (name 00c2c000, predicate 00c2c050, cell 00c2c160) over the shared inventory
  item columns.

  Deletion through these tables would crash free only if wrong; keep them on the
  re-map list rather than assuming the export is complete.

  slot [4]), 00c2ce40 (active-vehicle setter), 00c2c020/00c2c730/00c2c860/
  00c2cd10 (notification setters) are recorded with `class: null`; only the
  shared field offsets and callers tie them to the data-source classes.
- **Dead helper**: 00c273b0 (`FindGuiLabelCtrlByName`, hashes a name and
  dynamic-casts a `GObject` to `GuiLabelCtrl`) has no callers and no table entry
  in the export.
- **No packet anchors**: the whole shard is UI/Lua-facing. Do not infer packet
  behavior from these records; the state they read
  (`Client+0x53d9c`, `+0x22280`, `+0x22290`, item table at `+0x20c`) has to be
  linked from net.* shards before this data is called "server-driven".
- Subsystem choice: control bindings were recorded as `engine.gfc.control`
  (reusing the existing GFC-control subsystem), and the DataSource family as
  `ui.datasource` (new; the classes are the Lua-facing UI data providers, and
  `ui.*` is the established home for Lua-facing code such as `ui.coinstore`).
