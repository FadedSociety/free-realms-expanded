## Threat note (secure-code-guardian)

- The tracking id is client-controlled but only echoed: never a lookup key on its own, never a
  wallet, inventory, lot or history change. The replay key is still the whole order (tracking
  id, store, bundle, quantity, tint). A hostile client can make its own reply carry any u32; the
  only effect is on its own client's pending-order match.
- The disabled path now parses the body with `decode_order`, the same bounded parser the enabled
  path uses: the 4 KiB cap and `marketplace_request_is_well_formed` run first, every string
  length is bounded, at most 16 details, checked cursor arithmetic, no `unwrap`. A malformed body
  costs one bounded parse and gets the same disabled reply as before.
