## Security note (secure-code-guardian)

This change adds no input parser. The hostile-client surface is the existing
one and the tests exercise its refusals:

- **26/8 with a forged actor GUID**: only a server-owned battle spawner can
  open the screen; an unknown GUID produces no 41/114 and no state change.
- **41/108 Go with a forged battle/instance or with no open screen**: the
  pending screen is session-owned and never saved; a forged frame is inert (no
  reply, no zoning). The screen is consumed by Go, by the 26/42 close, by the
  41/109 leave and by any other start; a genuine refusal (level, combat job,
  prize preflight, knocked out) re-creates it byte-for-byte, while Go from
  outside the 8 m marker radius deliberately drops it (F176) so a screen left
  open while walking away cannot start the arena.
- **167/1/2 with an arbitrary activity id**: catalogue lookup refuses unknown
  ids; published battle rows still require a combat job, the level floor, the
  shared busy table and the whole-bundle prize preflight before any state or
  packet is published.
- **36/10 with an arbitrary target GUID**: not an arena actor -> inert, no
  defeat and no payout. A replayed 36/10 after the win and a replayed 26/42
  pay nothing.
- **Client numbers/items are never trusted**: the 68 coins, roster stats and
  prize rows all come from server content; the client sends no quantity, item
  id or result. Prizes are preflighted against the live catalogue/bag before
  Go; a full bag (or an unresolvable previewed prize) refuses with
  `UNAVAILABLE_BATTLE_PRIZE` and changes nothing.
- No new `unwrap` on client data. The row parser is the existing
  `load_field_battles` with its difficulty/actor/prize/GUID/size bounds.

## Checklist

   forged portal id, a wrong marker, an arbitrary 36/10 target and a full bag;
   `a_non_combat_job_is_refused`, the knocked-out case and the busy test assert
