## Security threat note (secure-code-guardian)

A hostile client can send any `26/8` runtime GUID, any `26/10` choice, a forged
`26/6` dialogue row, a forged/replayed `26/10` Attack choice against any field
GUID, a `49/2` quest id it was not offered, or a `49/14` id that is not the
pending turn-in. The server refuses each because: the actor GUID must resolve
through the server's NPC content-key map and the open interaction; a menu
choice must be one the server opened; a field attack must name a live,
present spawn in range and past the cooldown; a kill only counts when the
server's own enemy state reaches zero and `apply_encounter` forwards that
definition; quest ids must match the pending offer/turn-in the server recorded;
and rewards use the idempotent `quest:<character>:<quest>` grant. The new tests
prove the wrong enemy definition cannot satisfy C4 and that a replayed lethal
request changes no saved byte. They add no parser, trust boundary or economy
rule; no production validation was weakened.
