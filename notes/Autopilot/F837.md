## Security threat note (secure-code-guardian)

The attack surface is the card TCP listener (`card_listener.rs`, loopback or the private address with `--allow-lan`):
an unauthenticated client can send 414, 411, 112, 86, 87, 92, 137, 503 and unknown frames. This diff is test-only:
it changes no parser, no bound, no log and no reply, so it neither widens nor narrows what a hostile client can do.
The properties that matter, and are unchanged, are:

- 411 login: only a live session's one-time, TTL-bound launch ticket redeems (T764/T804/T805); a wrong/empty
  character id or an expired/spent ticket is refused with message 63 and spends nothing, and the connection closes
  after the refused 81 (T808). A guessed 64-bit decimal is `unknown_ticket` and changes nothing.
- 414 is answered only with this listener's own `host:port`, and the request's strings are echoed, which the client
  itself supplied over its own connection. `LOGGED_PER_KIND` (16) caps each event kind per connection; the two
  counters saturate (the lines behind finding 1), so a client that sends 2^32 frames cannot panic the gateway outside
  `contain`. `ticket` and `session id` never reach an event (T782/T808 tests).
- 92 is logged (group/role ids) and not answered; 503's image is dropped; 137 is echoed only for the connection's own
  account, never the account the client names; 86/87 only advance the server-driven sync.
- The fixtures now being hand-built means a server writer change can no longer silently move a "client request" with
  it: the golden test fails instead. That is the security-relevant direction change in this diff (test trust), not a
  new input path.
