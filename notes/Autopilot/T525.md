# T525 — Live coin placement: `realm coin place|move|unbind|list`

Status: implemented and re-verified on the newest autopilot tip. `T525-a1.patch` applied with one
reject in `collection_pickup::load` (the patch was cut before T522's meta block); `apply_view` was
ported by hand after that block. Focused gates, the whole `--lib` target and `app_fuzz` are green.
Native check (place 1950 in Snowhill, relog, collect) is the lead's.

## What changed

- `src/collection_coins.rs` (+291 net)
  - Adds the live overlay `collection_coin_edits.json`: one row per authored coin holding the
    actor (`spawn_guid`, `model_id`, `name_string_id`, `position`, `heading`) and its binding
    (`collection_id`, `entry_id`, `tier`, `pairing: live`) together, plus
    `source: {kind: reconstructed, recorded_ms, character_guid}` and an optional `replaces`
    content GUID.
  - `CollectionCoins::load` now merges the overlay beside the shipped map; `load_with_overlay`
    also returns the shipped base so a session can apply later overlay edits without re-reading
    the map.
  - Merge validation: overlay GUID in `131_000_000_000..132_000_000_000`; unique GUID and entry;
    catalogue owner, exploration tier, `pairing: live`, source kind, finite position/heading,
    positive i32 model; `name_string_id` = 386170 (rare) / 4412 (elite); `replaces` must be a
    content coin bound to the same entry/collection; at most 512 rows. A replaced content coin is
    removed from the merged map.
  - `read_edits`/`edits_bytes` are the bounded reader and the exact one-write bytes.
- `src/gameplay/coin_authoring.rs` (new, 405 lines)
  - `realm coin place <entry>`: exploration entry only, no bound coin, model copied from the
    collection's existing coins, tier/name from the collection; new GUID `max+1` from the live
    base; writes one row at the caller's position/heading; adopts it for the acting session.
  - `realm coin move <guid>`: content coin → new row + `replaces`; live row → old row removed and
    its `replaces` carried over. A new GUID is always allocated, so the client never misses the
    move.
  - `realm coin unbind <guid>`: removes a live row only; an empty overlay file remains.
  - `realm coin list [radius 1-200]`: nearest 10 coins with entry, tier and pairing.
  - All commands are zone 0 only, like `realm place`; every refusal returns text and changes no
    file or view. `save_and_apply` validates, writes via `character_store::replace_bytes`, then
    applies; a failed write leaves the old file and old view.
- `src/gameplay/collection_pickup.rs` (+61 net): `CollectionWorld` keeps the shipped base and the
  merged view; `apply_view` adds overlay actors with `NpcVisibility::add_static_actor`, excludes
  every `replaces` GUID and every coin whose entry this player collected, and returns the
  existing 35/2/35/3 refresh packets.
- `src/gameplay/placement_watch.rs` (+29): `realm placements` body moved out of the hub unchanged
  (`Gameplay::placements_listing`). T525 reuses the same generic one-stat-per-second
  `PlacementWatch::poll_with` for the coin overlay.
- `src/world.rs` (+11): `NpcVisibility::authored_spawn(actor_id)` returns model/position from the
  loaded content row even when this viewer has already collected or replaced it.
- `src/gameplay.rs` (+14/−31, net −17): `mod coin_authoring`, `coin_edits_watch`,
  `tick_live_coin_edits` after the placement poll, `reload_coin_edits` after `set_world_dir`, the
  one-line `["placements"]` arm, and the `["coin", rest @ ..]` dispatch arm. `place`/`unplace`
  behaviour is unchanged.
- `tests/coin_authoring.rs` (new, 577 lines): 11 tests through the real chat path
  (`Gameplay::handle_in_world`) with an Admin role.

## (R) reconstructed rules

- Live positions/headings are the caller's server-known values; the authoring workflow itself is
  our reconstruction, not recovered 2014 server behaviour.
- The overlay is the tuning layer; `collection_coins.json` is never rewritten in game.
- Live exclusion is add-only, so unbinding a row that `replaces` a content coin removes the
  overlay actor at once but the content coin returns only in a new session.
- The 512-row cap is a local sanity bound, not a recovered limit.
- `pairing: live` is our marker for a binding chosen in game; it is not captured content.

## Security threat note (secure-code-guardian)

- Who can trigger: only Admin. `may_run` keys on the first word, so the new `coin` route is
  unknown to `can_run_realm_command` for Builder/Player and fails closed; tested through
  `handle_in_world` for both roles with `role_commands` true. `account_store.rs` untouched.
- Hostile fields: the only inputs are an `i32` entry, a `u64` GUID and an `f32` radius (finite
  1-200). Every other row value is server-derived (tier/model/name id from the collection and its
  existing coins, position/heading from the server-known character, source character GUID from
  the session). No names or free text are recorded. Invalid/forged entry, GUID, radius, zone,
  role or subcommand is refused before any write.
- Shared file: a hand-edited overlay is validated on load and on every poll; duplicate bindings,
  out-of-band GUIDs, non-finite positions, non-reconstruction sources, wrong tier/name/owner,
  oversized files and more than 512 rows are refused. `realm coin` validates the whole merged file
  before its one write, so the command path cannot create such a file (cap test). A malformed
  hand-edited file makes `set_world_dir` fail for that login, the same way a malformed
  `npc_placements.json` does; the watch path keeps the old view and logs once per stamp. A failed
  write leaves the old file and view; writes are atomic `replace_bytes` and bounded by the
  loader's 1 MiB reader.
- No economy effect: the command grants no items, coins, XP or rewards, and collection entry
  awards still use T450/T480's server-verified click path and saved ledger.
- One session's view failure is logged (`coin_edits_watch_error`) and the old view kept; the tick
  never propagates it.

## Open gaps

- Unbinding a row with `replaces` restores the content coin only in a new session (add-only
  exclusion); the reply says so.
- The overlay row's `heading` is recorded but `add_static_actor` faces 0; the coin is a floating
  icon, so this has no visible effect today. Extending the actor path for a heading is a lead
  decision if a placed model ever needs it.
- Model derivation reads the collection's loaded content actors; after a session collects every
  coin of a collection, moving one of the already-collected coins from that session refuses
  ("no placed coin to copy a model from"). Other coins in the collection, or a restart, supply it.
- `realm reload all` does not re-read the overlay; the one-second watch does.
- Builder access to `realm coin` is the lead's follow-up; `account_store.rs` was not edited.
- Native acceptance for 1950 in Snowhill is the lead's.
