## What changed

### Finding 2 (BLOCKER): first-wins across multiple packs

- `scripts/asset_delivery.py` no longer keeps one pack entry per name. The catalog index
  keeps **every** `(pack, offset, size, crc)` row per name, and `_pack_entry` returns the
  first entry whose CRC equals the announced row's CRC (and, for a raw row, whose size
  equals the row's wire length). A row the first pack holds at an older CRC now resolves
  from the pack that holds the announced bytes.
- `notes/Autopilot/T859-launcher.patch`: `read_pack_index` returns every entry;
  `pack_entries` indexes `Vec<PackEntry>` per name; `admit` selects the matching entry
  instead of the first one.
- Regression tests: `tests/test_asset_delivery.py::test_pack_row_resolves_from_the_pack_holding_the_announced_crc`
  (pack `_000` holds the name at an older CRC, `_001` holds the announced one);
  launcher `tests::launched_client_gets_the_card_art_its_own_pack_holds` builds the same
  two-pack case and asserts the announced bytes are served.

### Finding 4 (BLOCKER, structure): third pack-index reader

- The canonical reader is `prototype/osfr-tools/src/main.rs::read_index` (a private
  function in the `osfr-tools` binary). It is Rust-only; the Python harness cannot link
  it, so the harness now consumes the canonical reader's **output**. `catalog.tsv` (the
  existing `lab/extracted/client-assets/catalog.tsv`, produced by `osfr-tools catalog`)
  already lists the TCG pack's 2,128 rows as `assets\assetpack000W_000.pack` rows. The
  Python `read_pack_index` (a near-verbatim port) is deleted; the harness has no pack
  parser. The catalog's `pack` column is reduced to its basename, and only
  `assetpack000w_*.pack` rows are indexed.
- The launcher is a standalone repository by design (`Cargo.toml`: "do not couple
  launcher dependencies to the server crate"), so its patch cannot link the server
  reader; it keeps one local reader, documented as such at its module header. That reader
  now pins the bounds policy the review asked for: blocks must move strictly forward and
  each block's entries must fit before the next block (`17` = smallest 4+1+12-byte
  entry), so total work is bounded by the pack size; a 65,536-block cap remains. The
  16 MiB per-pack-row bound is the same in both readers (`MAX_PACK_ASSET` /
  `ENTRY_LIMIT`), and raw rows must also match the announced wire length in both.
- The old Python cycle/truncation test is gone with the reader; the canonical reader
  keeps those tests (`main.rs` `rejects_out_of_bounds_asset_and_truncated_header`,
  `follows_linked_blocks_and_rejects_cycles`). Python tests now pin catalog-driven bounds:
  an entry outside the pack and an oversized entry are not offered, and a pack that loses
  bytes after startup raises (never delivers). The launcher test pins the strict block
  rule with a backward-linked pack.

## Threat note (secure-code-guardian)

The new surface is the same loopback asset responder as T859 (harness `AssetsHandler`,
launcher `Responder` on `127.0.0.1`), plus a lab-owned `catalog.tsv` that now supplies
pack offsets. A hostile local process or a crafted client install can send:

- Arbitrary GET targets: refused by the numeric bucket, then the name allowlist
  (`_pack_path` in Python, `valid_path` in the launcher) before any lookup; pack names are
  never resolved as filesystem paths. The pack bytes selected by a catalog row are bounds-
  checked against the actual pack file at admission and again on read.
- A catalog row naming a pack path outside `assets/` or a non-`assetpack000W_*.pack`
  file: not indexed. Python additionally resolves the pack path and requires it under the
  client's `assets/` folder (symlink escape refused); the launcher uses `regular` and
  `hard_link` and rejects links.
- A wrong or missing `?crc`: refused. A client-pack row whose CRC disagrees with the
  announced row, a raw row whose size disagrees, an entry over 16 MiB, or an
  in-pack name absent from the manifest: not offered. A forged or stale query cannot
  get bytes for another version.
- A crafted pack: Python no longer parses directory blocks (catalog rows only); the
  launcher rejects cyclic, backward or overlapping links and counts that do not fit
  before the next block, then CRC-checks every served row.
- Refusals change no state: the manifest, sources and pack index are built once at
  start; `get` only reads and caches bodies. The Python tests snapshot the served
  manifest and the row count before and after every refusal, including a pack that is
  truncated after startup (ValueError; a lab asset still serves).
- No client art is committed: the diff carries names, CRCs, offsets and code only; bytes
  are read from the player's own install at runtime.
