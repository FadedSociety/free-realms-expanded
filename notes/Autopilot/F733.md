# F733: fix the T698 review blockers (commit 90cac97)

The review `lab/autopilot/reviews/90cac97-T698.md` found one STRUCTURE blocker and
four MINOR findings. All five were valid; none is rejected. This run fixes all of
them, adds a regression test for each, and binds the spawn `NameId` on **all 16**
T698 rows (the review's concrete failure named five rows; the other eleven were
already null before T698 and are bound too, so no T698 row draws nameless).

No production Rust changed. The four hub files (`src/gameplay.rs`,
`src/bin/osfr-gateway.rs`, `src/encounter.rs`, `src/gateway.rs`) are untouched:
**0 net lines each**.

## What changed

### Review 1 (BLOCKER, STRUCTURE): re-declared test helpers

- `tests/npc_reference_spawn_placements.rs` now includes the canonical
  `tests/support/placement.rs` (`xyz`, `distance`, and the new shared

  `spawnNpcWithGuid` shape `sanctuary_talk_spawn_placements.rs` parses. They are

## Threat note (secure-code-guardian)

A hostile client can send 26/8 with any u64 target (and bool), 26/10 with any
target/choice, 26/6 with any row, and 49/2 with any quest id, from whatever
position the session process reports. This task adds no parser, handler, opcode,
menu path, save write, item/coin grant or reward. The 16 rows are static server
content: the name id comes from the cited client locale row, not from a packet,
and the client cannot choose the display name, model or position. The existing
`npc_interaction::check_range` still refuses an unknown id, another zone or a
target outside the 12 m radius; those refusals send no menu and change nothing
(covered by the unchanged `npc_interaction` and greeting refusal tests in Gate
B). The new 1 m check is a test-only content gate, not runtime client input
handling. No client-controlled string is written to content.
