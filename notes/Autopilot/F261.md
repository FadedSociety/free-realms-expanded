## Security threat note (secure-code-guardian)

Attack surface: the free-revive request (41/122) and the session-only ground pickups its commit
clears.

- A hostile client can send 41/122 at any time, with any header ids or paid value. The engine
  accepts a free revive only while the session is knocked out; an alive request is inert, the paid
  value is refused with the window re-shown, the header ids carry no authority, and the destination
  is the content's safe location, not a client value. Unchanged here and pinned by
  `tests/free_revive.rs` (`malformed_resume_is_rejected_without_mutation`,
  `paid_revive_is_refused_and_the_window_comes_back`, `replay_and_alive_requests_change_nothing`).
- `scene_reload` is server-generated (`revive_at_safe_location` / `stage_instance_transfer`); a
  client cannot fabricate a begin-zoning commit fact. The commit still stages on a clone and clears
  only the staged engine.
- The new seed methods grant nothing and are unreachable from any packet, handler or chat command
  (`grep`: only the regression calls them; the gateway never does). The drop is rolled server-side
  from `data/content/power_ups.json`; the clear removes a stale actor/payout, it does not create
  one. The seed takes a table id, a position and a timestamp, none of which come from a client.
- No auth, role, session, trade, account, save-ordering or wire bytes changed; no new persisted
  state, save field or dependency. The only production additions are test/diagnostic accessors.
