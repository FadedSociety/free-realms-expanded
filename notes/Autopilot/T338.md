# T338 — S16: split `handle_npc_packet` into one private method per packet family

Behaviour-preserving dispatch split in the NPC router owner (`src/gameplay/npc.rs`). The old
~660-line ordered `starts_with` chain is now a 55-line dispatcher that only selects, plus twelve
private `Gameplay` methods, one per packet family. Every family body was moved verbatim (same
bytes, same order, same replies); only method headers, the trailing `Ok(None)` fall-through and
three leading `//` comments (now `///` doc comments) were added.

## What changed

- **`src/gameplay/npc.rs`** (owner; 1244 → 1340 lines, +96, all plumbing):
  - `handle_npc_packet` now runs: `refresh_npc_quest_eligibility(current_unix_seconds())`, the
    existing overworld field-actor skip for 26/8/26/10, then an ordered chain of
    `if let Some(out) = self.<family>(..)? { return Ok(Some(out)); }` for
    26/6 → 26/4 → 45/7 → 49/15 (also 47/12, 47/13) → 49/2 → 49/14 → 26/23 → 26/8 → 26/10 →
    165/x → 66/x → 66/43, and the unchanged final `Ok(None)`.
  - New private methods `npc_dialogue_26_6`, `npc_dialogue_close_26_4`,
    `npc_client_objective_45_7`, `npc_journal_49_15`, `npc_quest_reply_49_2`,
    `npc_quest_end_49_14`, `npc_quest_abandon_26_23`, `npc_interact_26_8`, `npc_select_26_10`,
    `npc_store_165`, `npc_merchant_66`, `npc_merchant_buy_66_43`. Each owns its guard, decode
    and refusal; the dispatcher never parses a body.
  - The 165/x family keeps its explicit `Ok(None)` when the coin shop, interaction or visibility
    service is absent; the 66/x family keeps its `Ok(None)` for an unlisted sub-opcode and for an
    absent shop. Both now surface as `Ok(None)` from the method, i.e. the next family is tried and
    the dispatcher ends at `Ok(None)` exactly as before (a 165 packet can never match a 66 arm, so
    the observable result is identical).
  - The 26/8/26/10 field-actor skip stays before every family (a field enemy still returns
    `Ok(None)` from the dispatcher, never the NPC menu).
  - `END_DIALOG_26_4` placement, the `pending_quest_choice`/`pending_choice_packets` handling,
    the action budget (`activity_busy`/`busy_interaction_refusal`), the `commit_if_changed`
    staging, the 26/10 `consume_menu && out.changed` rule, and all 165/66 shop state are untouched.

- **`tests/npc_interaction.rs`** (743 → 1150 lines, +407): nine S16 routing tests that drive the
  real request path `Gameplay::handle_in_world`, reusing the shared
  `tests/support/npc_quest_chain.rs` fixture (no new heavy fixture, no copied content):
  `dialogue_26_6_choice_still_opens_the_quest_offer`,
  `dialogue_close_26_4_consumes_only_that_menu`,

  `unlisted_66_x_falls_through_to_ok_none`. It lives in the existing S15 NPC-router test module

## Threat note (secure-code-guardian)

The change is a pure dispatch split, but it is the code every hostile NPC request passes through,
so the trust boundaries were re-checked. A hostile client can send: a 26/8 with a forged or
unknown runtime GUID (refused with a `null` content key and no menu); a 26/10 for a menu it never
opened or an option never offered (the clone is only committed when the menu service reports
`changed`; otherwise `Err` with no save); a 26/6 row for another NPC's dialogue (no pending choice
→ 26/4 close, no offer); a 45/7 client id for a quest it does not own (the engine only advances an
open goal of an active quest); a 49/15 original id outside the crosswalk (one chat line, no
change); a forged 49/2/49/14 for an unoffered or uncompleted quest (engine refusal, state
byte-equal); a 165/4 or 66/x request naming another merchant or an unstocked item (the open session
merchant is the authority, the item must be in the content stock, the price is server-side); a
malformed/oversized body (each family's decoder returns its existing `Err`/refusal). No parser was
added or reordered, no client quantity/price is trusted, no new persistent field exists, and no
family can reach a service without its guard.
