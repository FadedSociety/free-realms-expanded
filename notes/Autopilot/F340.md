## Security threat note (secure-code-guardian)

A hostile client can send 66/43 with an arbitrary item id, quantity and transaction id, or
26/10 for an NPC it is not next to. The server trusts none of those fields for authorization:
a purchase requires an open shop opened through a role-bearing NPC whose stock is the explicit
server-owned `vendors.json` list with a positive `stores.json` price, plus the existing
zone/range, wallet, bag and quantity checks. This diff changes no client packet parser and no
wire rule; the only loader change is the documentation of an existing fail-closed gate. The
test fixture is test-only, lives in a private temp directory and never aliases the public
world. No save, coin, item, session or account-role path changed. No new sign-off is claimed
beyond `lead-signoffs.md:32`.
