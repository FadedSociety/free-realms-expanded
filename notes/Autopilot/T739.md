# T739: four clickable quest props placed from the resolved reference spawns

The lead's brief (`lab/references/quest-lines/wiring/spawn-objects.json`, 23 `status: resolved`
rows) matched quest objectives to one reference spawn each. At this tip **16 of the 23
objective targets are already drawn** (11 on `legacy_data` regional NPC rows, 2 on a
`reference_data` row plus its extras body, 3 on plain `npc_spawns_extra.json` prop bodies), and
**1** (the archer tree stump) is skipped because the client does not ship its model and its
position contradicts the quest text. This slice places the remaining **4 props covering 6
objective ids** as `legacy_data` regional rows. No production Rust changed; no hub file changed;
no packet shape changed; no new application selector (no app_fuzz seed needed).

Registered skills: **ponytail (full)** and its review pass, **secure-code-guardian** (threat
note below). IDA was used for the draw and click wire evidence.

## Open gaps

- **Three already-drawn props are not clickable through the NPC router.** Spectrum Anvil
  (100000003853), Wellington's Dig Site (100000002732) and Fireworks Cart (100000004059) exist
  only as `npc_spawns_extra.json` bodies with no `content_key`, so `Gameplay::content_npc_key`
  returns `None` for their actor GUIDs and a click logs `unknown_runtime_guid` (the anvil, also
  a station model, opens the crafting menu). Rule 3 of the brief says skip an already-drawn
  spawn, and a second regional body at the same spot would fail the 1 m rule. Binding them
  needs a lead decision: either an interaction-only regional row for a **Legacy** extras body
  (the T470 `reference_data` pattern, whose `content_npc_placement` gate currently requires
  Sanctuary-main provenance) plus a `content_key` on the extras row, or retire the extras body
  and draw the prop as a `legacy_data` regional row.
- The archer tree stump (q3010006-o0) stays blocked: it needs a stump model the client ships
  (or a capture of the real prop) and a position that matches the quest text.
- No quest is enabled here; the four props are drawn and clickable, which removes the
  placement blocker for q3040010, q3070037, q3070046 and q3130003.
- Placement is `(R)` medium: a spawn/model/name join from the reference table, not a captured
  transform, collision proof or native appearance check. No native run was made.
- Integration note: this diff appends rows to `sanctuary.json`/`snowhill.json` only, so the
  Merry Vale/Stillwater change guard (`npc_greetings_merry_vale_stillwater`) returns early on a
  commit that does not touch its two owned files. If a batch commit ever combines these appended
  rows with a `merry_vale.json`/`stillwater_crossing.json` change, that guard's commit mode
  rejects appended rows in foreign files; the lead should commit this diff alone (the rows are
  allowed in a builder workspace, where the guard reads the working-tree diff).

## Threat note (secure-code-guardian)

A hostile client can send 26/8 `CommandPacketInteractRequest` with any u64 target and any
claimed position, and 26/10 choice ids. This task adds no parser, handler, selector, save field,
coin, item, reward, role, chat or other-player-triggered state. The four new rows are static
content; the existing `npc_interaction::check_range` refuses an unknown id, a wrong zone (unless
the open world 0) and any target outside the 12 m radius, and the new test asserts a refused
click leaves the open menu byte-identical. Clicking a placed prop opens only the generic Talk
menu (role `ambient`), so a row can offer no quest, vendor stock, trainer, race or reward; the
rows carry `quests_given`/`quests_accepted`/`vendor_stock` empty and no `greeting_string_id`.
Every value (model, name id, position, heading) is server-side content checked against the
client's own `Models.txt`/locale and the cited spawn; no client-controlled string reaches
content. No new trust boundary, so no app_fuzz seed is required.
