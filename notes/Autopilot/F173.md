# F173: test scratch folders are removed after each run

## What changed

Tests only. No production module, dispatch, save, packet or content code changed.

- `tests/quest_objectives.rs`: `split_fixture` now returns a `Scratch` guard instead of a bare
  `PathBuf`. The split copy is created under `env!("CARGO_TARGET_TMPDIR")` as `<pid>-<n>` (same
  per-run name as before) and `Drop` removes it with `fs::remove_dir_all`, ignoring the error. A
  `Deref<Target = Path>` keeps every existing `from_split_content(&path, ...)` call unchanged.
- `tests/quest_save_tolerance.rs`: `SplitFixture` keeps its struct and name; the path moves from
  `lab/build/w114/cases/<pid>-<n>` to `CARGO_TARGET_TMPDIR/<pid>-<n>`, and the struct implements
  `Drop` (same ignored-error removal). `manifest` is now used only for `data/content`.
- `src/gameplay/w64_regional_quest_tests.rs` (unit test module): a local `Scratch(PathBuf)` helper
  (unit tests do not get `CARGO_TARGET_TMPDIR`) creates `std::env::temp_dir()/eligibility-<pid>` and
  `.../<label>-<pid>`, removes a stale copy first, and cleans on `Drop`. `level_three_world_game`
  returns the guard in its tuple; the three manual `remove_dir_all` calls are gone.
- `tests/shared_field_state.rs` (CRLF file): one top-level `Scratch` helper wraps the existing
  `w116-<pid>-<n>` unit-test fixture under `CARGO_TARGET_TMPDIR`. `Scratch::path` is shared by the
  private socket `Fixture`, whose root moves from `lab/build/w116/socket-<pid>` to
  `CARGO_TARGET_TMPDIR/socket-<pid>-<n>` and is removed in `Fixture::drop` after the server thread
  joins. The receipt no longer claims the scratch is durable evidence. The old
  `assert!(!root.exists())` setup guard was only there to protect the one shared socket path; the
  serial-numbered private name makes collisions impossible, so a stale copy is cleared instead and a
  crashed earlier run cannot wedge the fixture. This file is `include!`d by
  `tests/shared_field_interest.rs`, so that target's per-run socket fixtures now also clean up
  through the shared `Fixture::drop`; its tests pass unchanged.
- `tests/load_players.rs`: investigated, no change. `registry_scaling` is in-memory and writes no
  folder; `w106/registry-scaling.log` is a manually redirected log named in the module comment. The
  ignored `gateway_sixteen_players` writes the fixed, reused `lab/build/w96/gateway-probe`, not a
  per-run folder.
- Fixed read-only inputs (`lab/build/w104/scratch/content`, `w88/fixtures`, `w100/server/debug`,
  `w172-fixtures`, `w90`) are untouched. No `lab/build` path remains in the changed files.

## Behavior

Every per-run copy now lives in the test's private build scratch (`CARGO_TARGET_TMPDIR`) or the
OS temp directory, not in the shared lab tree. The guard removes it on normal return and while a
panicking assertion unwinds. Folder names remain unique per process and serial, so parallel tests
still do not collide. Test names, assertions and outcomes are unchanged. There is no production
hot-path cost; the only new work is one directory removal at test end.

## Evidence and reconstruction

No client opcode, packet field layout, enum value, client reader/writer or client-visible behaviour
is involved, so no IDA trace applies to this task.

The helper reuses the pattern already in this repository: `struct Scratch(PathBuf)` with a
`Drop` that ignores `remove_dir_all` (`tests/quest_breadcrumb.rs`, `tests/content_jobs.rs`,
`src/gameplay/t013_objective_events.rs`, `src/bin/osfr_gateway/f120_fishing_hour_reconnect.rs`).
Per the brief there is no new shared crate module; each test file carries its own small guard. No
reconstructed gameplay rule was added, so there are no new `(R)` markers.

Ponytail (full) and ponytail-review were applied: the existing `Scratch` guard shape was reused
instead of inventing a new helper, and the review pass found nothing further to cut (the `Deref` and
`AsRef` impls each remove more call-site churn than they add; no shared module was introduced).
The design principles applied were subtract-before-you-add (deleted the manual cleanups and
duplicated path construction), minimize-reader-load (one clearly named guard owns cleanup in each
file), test-behavior-not-implementation (no assertion or test name changed; the tests still drive the
real content loaders), and idempotent operations (`Scratch::new` clears a stale same-name folder
first, so a rerun converges).
