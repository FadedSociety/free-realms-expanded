# F688 - Fix the F685 review blockers (commit 132b916)

Brief: read `lab/autopilot/reviews/132b916-F685.md`, fix every BLOCKER and the cheap MINOR findings,
with a regression test for each real bug. No finding was wrong; all four are dispositioned below.

## What changed

**BLOCKER 1 (the full-bag note claimed a test pin that did not exist).**
`a_bag_with_no_slot_loses_only_the_drop` now pins the silence: it decodes the 15/3 system lines of the
one-free-slot run and the full-bag run and asserts they are equal (only the shared "Battle won." line)
and non-empty. Any full-bag-only chat line now fails. The assertion sits in the existing test, so the
claim in `notes/Autopilot/F681.md`, `notes/Autopilot/F685.md` and the earlier reports is true from
F688; those notes now say F688 added the assertion rather than pretending F685 had it.
- Wire evidence: the 15/3 body is `u32 length`, that many text bytes, one flag byte. IDA
  `0x00b0f5f0` (dispatched through `0x00b14350`, constructor `0x00b0f9d0`) decompiled this session:
  `sub_B0F550` (header), `v5 = *v3` signed length, `sub_894B10` string setter, then one byte stored at
  `this + 544`. `chat::system` emits the same body, and the test's `system_lines` helper cites the
  reader.
- Canary A: adding `chat::system("Your bag is full; the chance drop was lost.")` in the full-bag
  branch made the test fail with
  `left: ["Battle won. Close the results to return.", "Your bag is full; ..."]`,
  `right: ["Battle won. Close the results to return."]` (exit 101). Reverted byte-for-byte
  (sha256 `5a61dcb1...` equal) and the test passes again.

**MINOR 2 (stale spine measurement).** Re-ran `cargo test --test spine_rules -- --nocapture` on the
current tip and recorded both the pre-integration base and the current numbers in
`notes/Autopilot/F685.md` (gameplay 5173/5209 was the `d7c46ae` base, 132b916 was 5152/5195, current
is **5134/5192**; encounter 2972/2997; gateway 2104/2144; osfr-gateway 4610/4643). The line-ending
counts in the same note now match the current tree (`gameplay.rs` 5134/5134 CRLF).

**MINOR 3 (the economy guard copied production content selection and forced the shop on).**
`src/content.rs` now owns the path rules `Gameplay::load` binds:
- `content::bundled_content()` - the server's `data/content` path (one source; also used by the
  soccer/station fallbacks in `Gameplay::load`).
- `content::npc_content(directory)` - the save's own directory when it carries the NPC package
  (`npc_spawns_extra.json` + `npcs/`), else the bundled content.
- `content::npc_shop_enabled(npc_content)` - `npcs/`, `stores.json` and `vendors.json` all present.
`Gameplay::load` calls them (its net line count fell), and `the_shipped_rows_are_data_driven_and_grantable`
calls the same two functions instead of the deleted local `npc_content()` copy and a hard-coded
`true`. It can no longer validate a shop or content set production would not build.
- Canary C: making `npc_shop_enabled` return `false` failed the guard at
  `the shipped content enables the shop` (exit 101). Reverted (sha256 `327ebfd3...` equal).

**MINOR 4 (pre-existing: `realm exit`/`retry` still unwrapped the engine `realm win` now guards).**
`Gameplay::active_encounter` is the one no-engine guard; `developer_win`, `developer_exit` and
`developer_retry` in `src/gameplay/encounter_rewards.rs` all go through it and return `Ok` with one
`chat::system("No encounter is active.")` line when no engine is loaded. The hub's two match arms are
one line each. `retry` passes the real active job when profiles are loaded (the engine ignores the id
today) instead of the old `unwrap`. New lib test
`realm_exit_and_retry_without_an_encounter_engine_are_refusals` drives the real
`Gameplay::handle_in_world` chat path with the engine removed and asserts the line, no zoning and an
unchanged bag for both commands.
- Canary B: replacing the guard with `self.encounter.as_mut().unwrap()` made that test panic at
  `encounter_rewards.rs:31` (exit 101); the earlier canary on the old hub arms panicked at
  `gameplay.rs:4079`. Reverted (sha256 `d4eb3e24...` restored; the file was touched so cargo rebuilt).
- Behaviour with an engine present is unchanged; the existing `developer_cheat_console_drives_a_battle`
  and the suites that use `realm exit` (opening cave, Kart, Type8, earnings, s6) still pass.

## Threat note (secure-code-guardian)

- What a hostile client can send: `realm exit` / `realm retry` are ordinary chat strings (15/1); the
  parser only compares the lowercased text and never reads ids, quantities or results from it. With an
  engine loaded the routes behave exactly as before. With no engine they now get one bounded local
  line and no state change instead of a panic that the gateway's `contain` would turn into an
  `internal_error` disconnect for that player.
- The full-bag assertion is test-only and reads server-emitted 15/3 packets; no client value reaches
  it. The reward path itself is unchanged: a capped wallet still refuses the whole reward with one
  line and `Ok`, and a full bag still skips only the chance drop.
- Content helpers use only server-side paths derived from the save directory and `CARGO_MANIFEST_DIR`;
  no client-supplied path, name or id is involved.
- No new packet, opcode, persisted field or `unwrap` on client data was added. The 15/3 layout used by
  the test was re-checked against the client reader `0x00b0f5f0` (see above).

## Checklist (the review's 19 items)

1. **A refusal changes nothing.** The exit/retry test snapshots the bag before both commands, sends
   them through `handle_in_world`, and asserts the exact same bag and no zoning; the only effect is
   one chat reply. Canary B shows the old code panicked instead. The full-bag path is not a refusal
   (it applies the rest of the reward) and its test still asserts the bag did not grow.
2. **Rollback covers all state.** No transaction state was added; the refusals return before touching
   any state, and the engine-present routes keep using the existing exit/retry owner methods and
   `apply_encounter`. No `Rc`, `RefCell`, `Arc` or side table escapes.
3. **Apply deltas, never restore snapshots.** Nothing restores a captured inventory/position; the two
   new routes delegate to the engine and the existing payout. The test only reads live state.
4. **Busy rules are mutual.** No new activity or busy flag; `gameplay/occupation.rs` is untouched.
5. **Every entry path is gated.** The change adds no action and no parallel path: `exit`/`retry` keep
   their existing ordinary-command status and only gain the no-engine refusal; `win` keeps its
   dev-tools/role gate. No level, job, budget or eligibility rule was changed or bypassed.
6. **Reachable in production, tested through it.** The new test drives the real
   `Gameplay::handle_in_world` chat path (the gateway's inner call) with the engine removed; that state
   is not produced by content loading today, so it is defense in depth, as with `realm win`. The shop
   guard now calls the production content helpers, not a copy.
7. **Survives reconnect.** No new persisted state; the existing forced-drop save/reconnect test still
   passes.
8. **Every exit path restores the player.** The engine-present exit/retry behaviour is unchanged and
   exercised by the opening cave, Kart, Type8, earnings and s6 suites (all pass). The refusal returns
   with the player where they were (asserted: no zoning, unchanged bag).
9. **Economy safety.** The guard still uses the production `CoinShop::sell_unit_price` and now also the
   production content/shop selection; canary C proves the guard consults that rule. No free grant,
   quantity or id handling changed.
10. **Wire format matches the client reader exactly.** No new packet or field. The only wire use is the
    existing 15/3 encoder; the test decodes it with the same `u32 length + text` layout as client
    reader `0x00b0f5f0` (dispatched from `0x00b14350`), re-decompiled this session.
11. **Unique ids.** No ids are minted; nothing touches instance ids or GUIDs.
12. **Others see changes.** Nothing here is visible to other players; inventory and chat are private.
13. **Content works end to end.** The shipped content enables the shop and every shipped drop row is
    grantable and unsellable (the existing guard passes); no content file changed.
14. **Values live in data.** No compiled tuning value was added; the only new constants are local
    refusal text in the same place as the existing ones.
15. **Canaries break production code.** A, B and C break production functions (`apply_encounter_reward`,
    the old hub arms and the shared `active_encounter` guard, `npc_shop_enabled`), each made the intended
    test fail, and each was reverted byte-for-byte with matching hashes.
16. **Hands off session plumbing.** `src/gateway.rs` and `src/bin/osfr-gateway.rs` are not in the diff;
    no session creation, teardown, transaction or save ordering changed.
17. **One player's error never stops the server.** Both new refusals are one `chat::system` line and
    `Ok`; they never panic. Canary B reproduces the old panic this removes. No `unwrap` on client data
    and no new `?` that can escape the tick.
18. **A type's rules live on the type.** The content-selection and shop-enabled rules now live on
    `content::npc_content` / `content::npc_shop_enabled` (doc comments state the conditions);
    `EncounterReward::bonus_items` now states the silent full-bag loss at the field; the test doc
    states that silence is the pinned rule.
19. **Hot paths stay cheap.** Nothing runs per tick or per packet: helpers run at load, the developer
    routes on a chat command, and the 15/3 parsing only in the test. No clone or allocation was added
    to a hot path.
