## What changed

Finding 1 (BLOCKER, non-atomic join then invite removal). The removal after `commit_outcome` is gone. The invite is
now removed inside `World::commit_membership` (the single infallible install after the saves, `world.rs`) through
the new `Invites::forget(invitee, run)`: when a membership install places a player in the run they hold an invite
to, that invite goes in the same step. There is no window between the join and the removal, no `Ok(false)`
dependence, and any other path that puts the invitee in the run (a reconnect that loads the saved run) clears it
too. `answer` keeps only the Decline consume (nothing else changes on Decline). No change to `osfr-gateway.rs`
(rule 16) and no new sign-off needed: `commit_membership` is not session plumbing.

Finding 3: `Server::test_has_invite` (tests only). The integration test now asserts the invite is still there after
malformed replies and after a refused Accept, gone after Decline and after the committed join. A World-level test
(`the_membership_install_that_places_the_invitee_in_the_run_removes_the_invite`) pins `forget`: another move or
another player entering the run keeps the row, the invitee landing in the run removes it.

Finding 5: module doc in `tests/shared_instance_invites.rs`, and T440 notes ("only a Decline or a committed join
consumes", "no message beyond ambient actor traffic") corrected.
