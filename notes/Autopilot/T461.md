# T461: pressing a boombox on the item bar spawns the box

Attempt 2, Sonnet builder (Opus lane rules). The earlier patch was ported by hand onto 1549c8e (its
`gameplay.rs` hunks conflicted with T474's move of `handle_item_bar` to `gameplay/item_use.rs`). Builds on T459 (catalogue, merged).

## What changed

- **Item bar** `src/item_bar.rs`.
  - `activate` on a bound catalogue boombox runs the usual checks through `usable` (owned, count > 0, alive,
    recast, not a rental) plus the caller's `Player::can_place_box`. On success it stamps `last_used` (keyed by
    definition, recast = the row's `recast_ms`) and returns `Reply::boombox = Some(definition)`. It never calls
    `inventory.consume`, and `changed` stays false: nothing is saved.
  - Every refusal is the old 36/1 (`abilities::unsupported_cast_failure`) and changes nothing.
  - `recast_ms(definition)` now serves both consumables and boxes, so `usable`, `cooldown_left` and `slot_update`
    share one rule; `slot_update` shows a box enabled with its recast (it was shown disabled in T459).
  - 42/15 and 42/16 still match only `use_wire::consumable`, so the potion path and its consume are untouched.
- **Gameplay** `src/gameplay/item_use.rs` (T474 had already moved `handle_item_bar` there). It now
  computes `can_place_box = zone 0 && !is_mounted() && !blocks(|g| g.start)`; it carries the definition out in the new
  `Outcome::boombox` (absorb rule: last staged value wins, like `broadcast`). `Gameplay::boombox_row` gives the host
  the catalogue row.
- **Gateway** `src/gateway.rs`: `GatewayOutcome::boombox`, copied from the gameplay outcome like `admin_move`.
  `src/bin/osfr-gateway.rs`: `SharedWorld::boomboxes`, the value taken before the commit and handed to
  `boombox_routing::place` only after `commit_outcome` returned true, and one `boombox_routing::tick` next to
  `tick_shared_fields` in `step`.
- **`src/boombox.rs`**: `Boomboxes` (the live boxes) and the packets. `spawn(row, owner guid, zone, pose, now, players)`
  returns the AddNpc, poof and song for everyone in range; `tick(now, players)` shows the box (no poof) to sessions
  that came into range, removes it from those that left, and ends boxes whose time is up.
- **`src/bin/osfr_gateway/boombox_routing.rs`** (new): the glue (owner pose from the registry, queueing per
  recipient, log and skip a refusing queue) and the gateway tests.
- **Shared helpers, nothing moved**: the tip already holds the one 35/16 writer, `abilities::effect_packets::
  encode_play_composite_effect` (moved there by T458; client reader `0x008e5f50`), plus the 35/41, 35/42 and 35/3
  encoders. The boombox calls those; attempt 1's move of `composite_effect` out of `encounter.rs` is dropped, and
  `encounter.rs` and `encounter/shared.rs` are untouched.

## Reconstructed (R) choices

- Left of the owner is `(-cos h, 0, sin h)` for the repo's facing `(sin h, 0, cos h)` (the same rotation Sanctuary
  applies to -X, checked at heading 0 and pi/2), `spawn_offset_m` away, at the owner's height, facing as the owner.
- Mounted, busy (start gate of the occupation table) and outside zone 0 refuse a press (mounted: the Mounts guide's
  wiki rule; zone 0: the brief's own rule).
- Song = the row's first effect, 35/41 with the owner's guid as source, tag = the box counter (unique per live box).
  The AddNpc does not carry the song (Sanctuary also sets it on the NPC itself; the brief sends only the tag).
- A viewer that moves out of range gets the removal (35/3) and sees the box again, with its song and no poof, on
  re-entry. Without this the client would keep a stale actor. A viewer that left the zone or the server is not told.
- One box per owner: a second press before the first ends (possible only if `recast_ms` is tuned below
  `duration_ms`) ends the old box first. This bounds memory and per-tick work.
- A box outlives its owner's session until it expires. The recast resets on relog, as for potions.

## Threat note (secure-code-guardian)

A hostile client can send 36/10 on bar 2 with any slot, a foreign target guid, or a slot bound to an item it no
longer owns, or spam presses. A forged target is refused (`on_self`); an unbound or stale slot is refused (`bound`,
`reconcile`); a rented, empty or unlisted item is refused (`usable`, `owned_action`); the recast bounds the press rate
and `MIN_RECAST_MS` is 3 s; a box needs an owned catalogued box, so nobody can place one for free except by owning
the item; the live set is one box per owner so a player cannot grow it. Nothing is consumed or saved, so there is no
item or coin to duplicate. A refusing viewer queue is logged and skipped. The box is never written to the character
save, so a crafted save cannot carry one.

## Checklist

1. Refusal changes nothing: every refusal is one 36/1 before any stamp; tested at three levels (item bar, gameplay,
   gateway for mounted and knocked out) with inventory/bar snapshots and the recast read back as unchanged.
2. Rollback covers all state: the recast lives in `ItemBar` (cloned with the staged gameplay, dropped on a refused
   transaction); the box is spawned only after `commit_outcome` returned true, so a failed commit places nothing.
3. Deltas not snapshots: nothing is consumed or paid; n/a.
4. Busy rules mutual: a press refuses on `blocks(start)`; placing a box does not occupy the player, so it blocks no
   other activity. No new `Occupation`.
5. Every entry path gated: the only route is 36/10 on bar 2 through `ItemBar::activate`; 42/15 and 42/16 match only
   `use_wire::consumable` (existing test: no confirm dialog for a box). No level or job gate exists for boxes.
6. Reachable in production, tested through it: `Session::dispatch_message` -> staging -> commit -> post-commit
   `place`, and `tick`, in `boombox_routing::tests`.
7. Survives reconnect: nothing must; recast resets on relog (R), tested with a second session; the box outlives its
   owner (tested).
8. Every exit path restores the player: nothing about the player changes. Viewers: range exit, zone change,
   disconnect and expiry each leave no stale seen-set entry (tested for range, disconnect, expiry).
9. Economy safety: never consumed or granted; owned, non-rental, count > 0 and the self target are checked; test for
   no change in inventory and no stamp on refusal.
10. Wire format: 35/41 and 35/42 verified at `008c4d50` and `008b51c0`; AddNpc through the existing writer; 35/3 and
    35/16 use the tip's cited readers; byte-level tests for the poof, the song, the stop and the removal.
11. Unique ids: `0x424f_4f4d_0000_0000 | counter`, skipped while live, unit test across the wrap; no other tag range
    overlaps (pets 0x40.., rides 0xc0.., pickups 0x5057.., nodes 0x4e4f.., housing 0x0f..).
12. Others see changes: spawn, arrival, range exit and expiry all fan out to the registry's nearby sessions.
13. Content works end to end: only 1 of 15 catalogue rows (item 1913) has a song id; the others spawn, bounce and
    poof but send no 35/41. See open gaps.
14. Values in data: duration, recast, offset and the song list come from `boomboxes.json`; the poof effect 21 and the
    bounce 2100 are constants with their client table cited.
15. Canaries break production code: yes (stamp line and `can_place_box`), see Gates.
16. Hands off session plumbing: no change to session creation, teardown or save order. The only hub touch in
    `dispatch_message_inner` is a call after the commit, like `admin_move`.
17. One player's error never stops the server: `tick` returns nothing and runs under `contain`; a refusing queue is
    logged and skips only that recipient (tested); arithmetic is `saturating_add` and `wrapping_add`.
18. A type's rules live on the type: `Placed` owns its show/end packets; `Boomboxes` owns the one-box-per-owner and
    guid rules; the recast and `can_place_box` rules sit on `ItemBar`/`Player`.
19. Hot paths cheap: zero boxes returns immediately; with boxes one registry query per box per 20 Hz tick, no
    whole-state clone (the world clone at staging copies at most one `Placed` per owner).
