## Classes and subsystems

- **Coin-store GUI data sources (`ui.coinstore`, `ui.datasource`).** `00cf2440` constructs named children including PlayerSell, SearchResults, ActiveFilters and TransactionHistory. `00cf1940`/`00cf17a0` perform typed GUI datasource lookup/cast; `00cf1ac0` and `00cf2120` rebuild filtered rows; `00cf1e70`, `00cf2140` and `00cf2170` refresh row providers. The vtable-backed methods at `00cf1b60`, `00cf1d90`, `00cf1ee0` and `00cf1f70` expose item, selling, filter and transaction-history fields. `00cf2230` and `00cf22c0` return counts. This aligns with piece 084's separately recovered column names, but this shard's transaction-history switch alone does not identify the names of fields 0..8.
- **Client objectives (`game.objectives`).** `00cf35e0`/`00cf3890` initialize location/actor look-at objectives; `00cf36a0` checks target range and camera alignment before invoking the shared completion helper. `00cf3920` stores a UI event string and `00cf3900` completes on match. `00cf3a00` initializes a first-movement objective. `00cf3aa0` stores two fixture/action identifiers and `00cf3a70` accepts matching identifiers or zero wildcards. These corroborate the objective mechanisms discussed in the original-opening and housing-discovery notes; they do not establish campaign bindings or server policy.
- **Action bar (`ui.actionbar`).** `00cf3b20` exposes nine column names. `00cf3bc0` finds a slot in an eight-bucket map and supplies its GUI fields, including enabled/usable, refresh, quantity, targeting and tint. `00cf3d60`/`00cf3dd0` destroy/construct its datasource.
- **Trade UI/state (`ui.trade`, `game.trade`).** `00cf5ce0`/`00cf61c0` manage the trade inventory datasource; `00cf5d60` names Available Count and No Trade Message; `00cf5ca0` logs which trade side updated. `00cf61e0` updates the other coin amount and logs it. `00cf6240` reads the partner coin amount when state bits equal two; `00cf6260` writes a trade field and triggers a callback. `00cf65b0`, `00cf68d0`, `00cf6800` and `00cf6850` cover tracker cleanup/initialization and available-count calculations. Existing piece 086 identifies trade coin packet families, but these functions do not serialize or parse them.
- **Vehicle event resources (`game.vehicle`).** `00cf4230`, `00cf5040` and `00cf5ae0` resolve literal jump/bounce, terrain-hit, drive-on, skid and drafting resource names. Neighboring functions update random/interpolated values and grouped objects (`00cf45d0`, `00cf47b0`, `00cf5480`, `00cf5670`). Resource bindings are direct evidence; the unnamed virtual state machine's purpose remains tentative.
- **Shared containers and ownership (`engine.containers`, `engine.refptr`, `engine.util`).** This range includes fixed arrays and strings, a 20-bucket `HashListMap<int,ItemInstance,20,-1>` (`00cf5ee0`, `00cf6360`, `00cf63a0`), reference cleanup routines, and a large wide-string search/matching implementation (`00cf26c0..00cf34d0`). The latter is identified mechanically; no game feature is attributed to it.

## Contradictions and qualifications

- The Ghidra note says slot zero is *normally* a scalar deleting destructor. `00cf36a0` is mapped to `ClientObjectiveLookAt::vftable[0]`, but its body performs the look-at completion check. Body behavior takes precedence over that convention; it is labeled `CheckCompletion`, not a destructor.
- `00cf5ae0` resolves `Vehicle_Skid_Dirt` twice for adjacent slots. The binary's repeated literal is preserved; whether the duplicate is intentional or a source/config error is unknown.
- Methods in the CoinStore/Trade GUI do not verify the server ledger implementations. Sanctuary and FreeRealms-Legacy remain third-party reconstructions, as project instructions require.
