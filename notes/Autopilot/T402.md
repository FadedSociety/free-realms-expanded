# T402: the paid revive works ("Revive here: 1000 coins")

2026-10-21

## Result

A paid `41/122` at an overworld knockout now charges the window's price and
revives the player where they fell. Before, the client enabled the button for
any wallet at or above 1,000 coins and the server always refused the click.

- **Charge.** Exactly the published price, from data, once. The coins and the
  revive commit in the same staged `Gameplay` (the opening request path clones
  it and commits only on success), so either both happen or neither does.
- **Revive.** Full health, the free revive's 8 s field grace, the knockout
  cleared, and the free revive's packets (`38/1` health, `41/126` hide), plus
  the `38/19` coin balance. No zoning. Both revives now share one `revive()`
  helper, so the packets are the same by construction.
- **Refusals.** Not knocked out, already revived, or replayed: one line ("You
  are not knocked out."), nothing changes. Below the price: one line ("You need
  1000 coins to revive here.") and the window comes back, because the client hid
  it on the click. Inside a battle instance (the client never offers the paid
  button there): the existing "Paying to revive is not available" line. Every
  refusal charges 0.
- **Free revive unchanged.** Same checks, destination, grace, packets and
  silence when alive. Its tests are unchanged and green.
- **Price in data.** `data/content/field_enemies.json` gets one block,
  `paid_revive: {cost: 1000, source: [...]}`, with client, wiki and `(R)`
  provenance. The loader refuses a cost above 1,000,000 and refuses missing or
  unmarked provenance. A package without the block (old test fixtures) keeps the
  retail 1,000. `realm reload enemies` re-reads it wherever that reload is
  allowed (it is refused while a shared field is live, as before).

### Why `field_enemies.json` and not `encounters.json`

`encounters.json` is hash-pinned: its SHA-256 is stored in every saved
`EncounterState` (`content_sha256`, checked in `EncounterEngine::load`), and
`tests/bundle_activity_content.rs` pins its bytes. One extra field there would
refuse every existing character at login. `field_enemies.json` is the
overworld field's own file (the paid button only exists in the overworld). It
is not pinned, it is loaded for every world (the bundled copy is the fallback
for packages without NPC content), and it already hot-reloads.

## Security note (secure-code-guardian)

What a hostile client can send, and why it is refused:

- **Paid 41/122 while alive, after a revive, or repeatedly:** the engine checks
  its own health first; the request charges 0 and changes nothing (state
  equality tests at engine and gateway level). Spam only produces lines for the
  sender, under the existing transport token buckets.
- **Paid 41/122 below the price:** refused before any state change. Even if a
  future change skipped the engine's wallet check, `Inventory::spend_coins` uses
  `checked_sub` and returns `Err`; the opening request path then drops its
  staged `Gameplay` clone, so neither the revive nor a negative wallet commits.
- **Forged header ids, a price or a place:** the packet has no price or place,
  and header ids are not read in the world (existing
  `client_supplied_ids_carry_no_authority_in_the_world`).
- **Malformed length or flag > 1:** not intercepted by Gameplay (it matches only
  the exact 13-byte paid packet); the engine returns `Err` with no mutation
  (existing `malformed_resume_is_rejected_without_mutation`).
- **Inside a battle instance:** refused; the client never offers it there.
- The price comes from server content only. Coins only go down by that price,
  and only in the same commit as a real knockout revive.

## Checklist (19-point review)

1. **A refusal changes nothing.** Applies. Engine tests snapshot
   `e.state()` before each refusal (alive, replayed, below price, wallet-less)
   and assert equality; the gateway test asserts coins and health unchanged for
   alive (1,000 coins), below price (999) and replay. Canaries
   `no_wallet_check` and `no_charge` failed these tests.
2. **Rollback covers all state.** The only path is the opening request path,
   which clones the whole `Gameplay` (inventory and encounter engine, including
   `paid_revive_cost`, `knocked_out_at`, `field_grace_until`) and commits once.
   No shared `Rc`/`Arc` state is written.
3. **Deltas, not snapshots.** `spend_coins` subtracts from the live balance;
   the revive sets health to the current max. Nothing captured earlier is
   restored.
4. **Busy rules mutual.** Not a new activity; the knockout state is the gate,
   as for the free revive.
5. **Every entry path gated.** The client 41/122 is the only paid entry; the
   engine's own `resume` routes a paid flag to the same `paid_revive` with an
   empty wallet. Tested through both.
6. **Reachable in production, tested through it.** Wired in
   `handle_opening_inner` next to the 41/108 intercept;
   `gateway_paid_revive_charges_once_and_revives_in_place` drives
   `Gateway::handle_at` with the private content package and the shipped
   `field_enemies.json`.
7. **Survives reconnect.** The gateway test reloads the saved `GameplayState`
   after the paid revive: coins stay spent, health stays full. A disconnect
   while knocked out keeps the existing wake-on-reload rule (no charge).
8. **Every exit path restores.** Paid revive clears the knockout like the free
   one; a refused paid revive leaves the knockout and its 15 s fallback armed
   (`paid_revive_below_the_price_changes_nothing`).
9. **Economy safety.** The price is server data; the client sends none. Coins
   only go down, by that price, with a real revive; `checked_sub` refuses a
   short wallet.
10. **Wire format.** 38/19 (`0x0089e670`, one i32), 38/1, 41/126 and 41/125
    (`0x008d6730`/`0x00904300`, cost at bytes 16..20) are byte-checked in
    `free_revive.rs`.
11. **Unique ids.** Not applicable.
12. **Others see changes.** Not applicable: health and knockout are not
    broadcast, and the player does not move.
13. **Content works end to end.** The shipped block loads (gateway test uses
    it: price 1,000 on the window and in the charge); the final coins and health
    are asserted.
14. **Values in data.** The price is in `field_enemies.json` with a sanity
    ceiling (`the_paid_price_comes_from_field_content` tunes it to 250 and
    refuses nonsense). The timer, grace and fallback stay `(R)` constants, moved
    unchanged (not in this brief).
15. **Canaries break production code.** Four, all in `src/`: `no_charge`
    (`spend_coins` keeps the coins) failed the gateway test; `no_wallet_check`
    failed 5 tests; `no_data_price` failed the data test; `zones` (paid revive
    uses the safe-location revive) failed both in-place tests. All reverted.
16. **Session plumbing.** Untouched.
17. **One player's error never stops the server.** Request path only; an `Err`
    ends that request for that session. No tick work added.
18. **A type's rules live on the type.** `revive()` documents what both
    revives restore; `PaidRevive` and the engine field document the price and
    its source; `paid_revive` documents its refusals and the charge contract.
19. **Hot paths stay cheap.** Per tick: nothing new. Per window: one `u32`
    field read instead of a constant.
