## Activity launch

- Manager setup/teardown is visible at 009c2fc0 and 009c2cc0; invite-details packet teardown at 009c30d0 releases the string subobject at +0x38, member list at +0x14, then restores `BasePacket` at +0. Scalar-deleting wrapper 009c3200 supports the derived packet identity.
- `Research/Pieces/020 Multiplayer activity grouping.md` establishes family opcode 175 (`0xaf`), with sub-opcode 1 for InviteDetails and 6 for ActivityCanceled. Dispatcher 009c3590 routes those discriminators to 009c3270 and 009c29d0. In 009c3270, "merge" means logging and removing the earlier keyed request; it is not a fieldwise merge. Processor callbacks use distinct vtable offsets +0x0c and +0x18, and the decline path sends an invite response through 00c4dfe0.
- The activity note records no captured 175 traffic and leaves launch bodies open. No matching activity-launch packet class appears in the community catalogue; this shard does not establish original server membership or launch policy. The response helper's packet class/opcode is still unresolved.
- Raw bytes disambiguate Ghidra's cookie artifacts: 009c30d0 calls cleanup with ECX = this+0x38; wrappers 009c45b0, 009c4780 and 009c47d0 forward their incoming ECX; initializers 009c4820, 009c4880 and 009c48e0 use their object in ECX. ## Client timers

- Timer definitions, saved records and active entries use 32-bucket maps (009c3700, 009c3770, 009c37e0; manager initialization at 009c65e0). Local files are `ClientTimerDefinitions.txt` and `SavedClientTimers.txt`; the saved file is caret-delimited and written using `%llu^%s^%f^%llu^%d` (009c5990, 009c5cd0, 009c6670).
- The saved-timer loader compares two client identifiers, but both branches call `00705bc0(local_134)` and converge on insertion at 009c4f00. The code does not filter rows by that comparison (009c5cd0).
- Timer event creation builds four tagged parameters, but constructs `ClientTimerEvent` only when lookup 00d833a6 returns nonzero; it then selects a sink, inserts active state and releases temporary values (009c5350). Restoration and auto-start paths are at 009c5f60 and 009c6000.
- Manager teardown first calls save routine 009c6670 with the manager in ECX, then drains four embedded map instances: definition +0x10, saved data +0xa4, active data +0x1cc and a second saved-data map +0x138. Cleanup calls are definition once, saved data twice and active data once (009c6ac0). The displayed cookie-XOR value is not the save call's argument.
- Allocation slots 009c3bf0, 009c3c90, 009c3d00, 009c7540, 009c75f0 and 009c7660 use the current manager when present, otherwise the global manager when present, and call fallback only when neither manager object exists. A present manager's null allocation result does not fall through. Timer file field meanings, overflow and invalid-input handling remain open; this shard shows no timer packet or original server contract.
