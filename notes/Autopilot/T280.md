## Method (T246 reproduction)

1. Speaker proof, strongest first:
   - **Quest offer (12 rows):** the client locale stores each quest as intro `T-1`, title `T`,
     description `T+1` (documented in `scripts/quest_text_backfill.py`). The chosen id is `T-1`,
     first person, and the description or title names the NPC as giver. Verified case by case on
     the locale block, not inferred from names.
   - **Guide-labeled quote (4 rows):** the job guide quotes the line as that NPC's speech
     (Warrior W14 Glowlight side; Blacksmith quest 27 `Nirvi: "..."`; the Jacque delivery speech in
     the Sanctuary row; the Jili post-match line cited by the Card Duelist row).
   - **Return response (2 rows, Anura and Arnie):** the recovered first-person response follows the
     client return objective `Return to <NPC>...` in the same locale block; the giver link is (R).
2. Every chosen id was resolved three ways: `lab/reports/locale-id-map.json` `hash_to_ids`, the
   `lab/reports/locale-id-to-text.json` row, and a direct `Global.Text.<id>` line in the stock
   `lab/working/OSFR.Client/OSFR Client/locale/en_us_data.dat`. The test asserts all three agree
   (the hash maps to the id, the physical dat line equals the recorded line, and its text equals the
   id-to-text row), so the table below is machine-checked, not transcribed.
3. Drawability: every edited row is `legacy_data`, positive `model_id` and `name_string_id`, finite
   position, and present in `NpcVisibility::teleport_targets(0)` (the 35/2 spawn list).
4. No text was invented; `(R)` only labels the fixed-default policy and any inferred giver link.

## Threat note (secure-code-guardian)

Client-visible content, but no client input is trusted with it:

- The 26/3 body id is server content (`NpcRecord.greeting_string_id`); a hostile client cannot make
  the server echo a string, an id, or another player's data into it. 26/8 and 26/10 carry only a
  target and a choice id, both range/zone/session-checked by `NpcInteraction` (`UnknownNpc`,
  `OutOfRange`, `WrongZone`, `InvalidPacket`, `InvalidOption`).
- A hostile 26/10 can at worst select an existing menu option; an invalid id is refused without
  clearing `active` (test 3), so it cannot consume the menu or desync another player (each session
  owns its `NpcInteraction`; the content table is shared and immutable).
- A malformed/short 26/10 body is `InvalidPacket` before any state change; an unknown target is
  refused. A zero/absent greeting is `None` and encodes 26/3 body 0, never a fabricated id or a
  locale text. No save, coins, items, roles or rewards are touched.
- IDA re-check for T280: 26/3 handler `00aa12e0` calls reader `00a9ef10` (first payload dword stored
  at object `+16`) then display `009f5ae0`, which passes `*(a2+16)` to the `Global.Text.<id>` lookup
  before `:SetDialogText`. 26/8 reader `008b6bc0`, 26/10 writer `00a36f80`.
