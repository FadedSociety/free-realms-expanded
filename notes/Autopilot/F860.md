## Threat note (secure-code-guardian)

The changed production code is operator-supplied content loading at startup, not client input.
The new `embedded_bytes` rule closes the one new surface: an embedded hex field can never name a
path (hex wins), and a file field must be one normal local component (no separator, backslash or
colon), read through `read_file`, which rejects symlinks and anything over the loader's bound;
the read itself is capped. A malformed, oversized or mismatched field fails the content load
closed before a session starts, with the existing per-loader SHA-256/header proofs still in
force. The content rows are static JSON: no packet reader, save path, coin/item grant, role or
session code changed, and no client-controlled quantity or id is read. Item 1843 is only granted
through the existing server-verified quest-completion path; it resells for 0 (catalogue row).
Nothing another player can trigger was added.
