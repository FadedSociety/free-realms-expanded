# T511: food auras and transformation treats in `consumables.json`

Skills applied: **Ponytail (full)** — the generator, the row file and the test reuse T510's schema,
loader and effect stack; no new Rust path, dependency or abstraction. The `ponytail-review` pass
cut an unused parameter and a redundant helper (net −12 lines). **secure-code-guardian** — the
threat note below. **codebase-memory** — graph-first ownership check before touching the file.
The client readers were re-traced with the read-only IDA tool (not a generated guess).

## What changed

- `scripts/build_consumables.py` (new, 428 lines, stdlib only, `python -I`): the offline generator.
  It takes all eight paths as required arguments (`--sanctuary-consumables`, `--sanctuary-items`,
  `--legacy-items`, `--models`, `--composites`, `--images`, `--locale`, `--output`), prints its
  counts and every dropped row, and writes deterministic LF JSON.
- `prototype/osfr-tools/data/content/consumables.json`: replaced T510's four-row seed with **94
  rows** — potions 2173 and 11002 first (unchanged values), then 23 food auras and 69
  transformation treats sorted by definition id. 70,055 bytes, under the loader's 256 KiB bound.
- `prototype/osfr-tools/tests/consumables_content.rs` (new, 145 lines): loads the shipped file
  through `ItemBar::load` and `Effects::load`, pins the potion rows, 2982, 4042, the exclusions,
  the retained counts and every row's provenance.
- No Rust runtime, hub, content-schema or item-bar logic changed. T510's
  `tests/item_bar_gameplay.rs::electric_veal_meat_consumes_one_and_shows_its_thirty_minute_aura`
  already drives item 2982 from the bundled `data/content` through `Gameplay::handle_in_world` and
  asserts 35/41 with composite 5030 for the player and nearby players; it was run rather than
  duplicated. The same file's `bark_berries...` test covers 4042.

## Threat note (secure-code-guardian)

Hostile client input: 42/6 and 42/9 assignments with any slot/instance/definition/tint; 36/10
bar use with any slot, target or guid; 42/16/42/15 immediate use with any instance id; plus
truncated/oversized packets. The new content widens the set of usable definitions; it adds no
client-controlled values.

Why it is refused: every use still needs an owned instance in the authenticated player's own
inventory, a loaded row for that definition, quantity > 0, a non-rental stack, an alive player,
an elapsed per-definition recast, an admitted effect spec, and (for transforms) no live transform;
42/15 needs the pending 42/16 for the same instance. The spend is one item, server-side, only for
a `single_use` row. A client cannot add or edit rows: the file is read once at startup from the
fixed content directory, `Effects::new` validates every row (positive ids, bounds, unique
definitions) before returning, and a malformed file fails startup rather than loading partially.
The exclusion sets keep boomboxes, cakes, random-transform foods, party favors and OSFR synthetic
abilities out of the bar; this matters because some ability ids are shared with other systems
(for example 4370 Stone Heart), and the item id exclusion is what prevents a bar press from
reaching that shared effect. No reward, coin, XP or grant path is touched. The generator reads
only pinned offline files; it has no network or server input. `source` is provenance text the
server never parses or sends.

  section. If the lead intended an additional exclusion (for example Bat Cupcake 69839, which the
  brief lists as a known (R) item), the generator needs one more rule; the current file includes

  the effect is not a loop (Can of Beans); the client plays a non-loop once and stops, which is the
  intended OSFR behavior.
