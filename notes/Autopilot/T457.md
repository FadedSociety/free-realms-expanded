# T457 - Client areas (opcode 89): the Sanctuary jump pad, the Halloween season, event toggles

## What changed

- `src/client_areas.rs` (new, library): `ClientAreas` loads `client_areas.json`, builds the 11-byte
  opcode-89 packet, and answers four questions:
  - `is_season_active(name, unix_ms)`: inclusive month/day window; a start after the end wraps the
    year end. An unknown season name is never active.
  - `world_ready_packets(unix_ms)`: one enable per held area (always-on, active season, event toggle).
    Always-on and season areas send elapsed 0 (R). A toggled area sends `now - enabled_at`.
  - `set_area(area_id, on, now_ms) -> Option<Vec<u8>>`: event toggles. Ids outside `switchable` are
    refused (None, state untouched). A repeat returns None. When an always-on row or an active season
    still shows the area, the toggle is recorded and None is returned, because clients see no change.
  - `season_changes(unix_ms)`: evaluates at most once per wall-clock minute. The first call only
    records the baseline. After that it returns a disable/enable for each area whose held state flipped
    with the season set. A backwards clock is just another date, so nothing is enabled twice in a row.
  - `unix_now_ms()`: the wall clock all of the above use.
  - Date math: Howard Hinnant's public-domain `civil_from_days` after `utc_offset_minutes`. No new crate.
- `data/content/client_areas.json` (new):
  - `switchable`: the 138 `AreaEnabled="0"` ids of FabledRealmsAreas.xml.
  - `always_on`: 4173.
  - `seasons`: Halloween, 9/20 to 11/11, areas 3992-4004.
  - Every row has a `source`. Loader bounds: schema 1, `deny_unknown_fields`, offset -720..=840, at
    most 256 unique positive ids per list, at most 64 seasons (one bit each), unique non-empty names,
    valid month/day pairs (Feb 29 allowed), and always-on and season ids must be in `switchable`.
    A missing file means no areas. A bad file fails startup with the file name in the error.
- `src/bin/osfr_gateway/client_area_routing.rs` (new, gateway glue):
  - `load`: from `--content`; no content means no areas.
  - `world_ready`: on the commit whose client just finished loading (`outcome.entered_world`) in
    zone 0 with the world loaded, the wrapped packets join that commit's replies.
  - `season_tick`: wrapped season changes go to every session with the open world loaded. A refused
    queue is logged (`client_area_send_failed`) and skips only that session.
- `src/bin/osfr-gateway.rs` (hub, thin dispatch):
  - `SharedWorld.client_areas`, loaded in `Server::new`.
  - One line in `commit_outcome` before the bundle budget stages replies.
  - Two lines in `step` under `tick_due`.
  - `queue_delivery` moved unchanged to `delivery.rs`, its home ("application-delivery framing").
- `scripts/content_check.py`: `check_client_areas`. Every id in `client_areas.json` must be an
  `AreaDefinition` with `AreaEnabled="0"` in the lab XML. If the XML is missing, a note is written
  instead.
- Not changed: zone transitions, the 46 startup messages, NPC visibility, saves, session plumbing.

### Hook choice

The brief's two candidate anchors were the post-commit `if outcome.entered_world` (event log only)
and the staged join (`join_player`). I chose neither. The hook is a single line in
`commit_outcome`, before `self.bundle_budget.stage(&outcome.replies)`, keyed on `outcome.entered_world`:

- It fires on every world load, independent of the join bookkeeping. Returning from an instance
  loads again and resends.
- The packets are charged to the bundle budget and traced as `app_out` with the other replies.
- A refused commit (`Err(_) if transfer`) drops them along with everything else.

The send happens on Loaded, not Ready, because the area objects exist only after the client loads
the zone. Sanctuary also sends on `OnClientFinishedLoading`.

## Client evidence (IDA via `lab/autopilot/ida_query.py`)

| Fact | Address |
|---|---|
| Reader: u16 to +4 (opcode), i32 to +8 (area id), byte to +0xc as `!= 0`, i32 to +0x10 (elapsed). A short read zeroes the field and sets the error flag | `0x008d5c60` |
| Wrapper: succeeds when there is no error and (`a4 != 0` or the cursor is at the end) | `0x008f6c70` |
| Case 89 calls the wrapper with `push 1`, so trailing bytes are tolerated. We still send exactly 11 bytes | `0x00948835` (case start `0x00948821`, jump table `0x00947227` in `0x009471a0`) |
| Area lookup by id; an unknown id skips the apply | `0x008b80a0` call at `0x0094885e`, `jz` at `0x00948865` |
| Apply: stamps now; changes state only if the byte at +0x1a9 differs; enable sets start = now - elapsed and calls vtable +0x60; disable calls +0x64 | `0x00bead80` |
| "now" is `timeGetTime()` (ms), so elapsed is milliseconds | `0x007027f0` |

The research pack's caveat ("trailing bytes only with the flag") is settled: the flag is 1 at
`0x00948835`. The brief and IDA agree on every field.

Golden bytes in the tests: 4173 enable = `59 00 4D 10 00 00 01 00 00 00 00`, framed
`05 00 01 0B 00 00 00 59 00 4D 10 00 00 01 00 00 00 00`; 4285 enable/disable = `59 00 BD 10 00 00 01|00 00 00 00 00`.

## (R) choices

- Always-on and season areas send elapsed 0.
- `utc_offset_minutes` 0 for the whole server.
- Halloween dates 9/20 to 11/11 (Sanctuary data; the wiki only says October).
- `season_changes` evaluates once a minute; its first call only sets the baseline.
- Refusal scope: `set_area` only accepts the 138 `AreaEnabled="0"` areas. This is stricter than "any
  AreaDefinition": default-on areas cannot be switched by events.
- An event cannot switch off an area that an always-on row or an active season shows.
- A full send queue in the season tick is logged, and that client misses the change until its next load.

## Checklist

1. **A refusal changes nothing.** `set_area` with a non-switchable id, a repeat, or an off that was
   never on leaves `world_ready_packets` identical (asserted in
   `an_event_toggle_reports_elapsed_time_and_unknown_ids_are_refused`). A load error leaves nothing
   behind.
2. **Rollback covers all state.** `ClientAreas` lives inside `SharedWorld` and is cloned with the
   staged world. The `Arc` holds only immutable content. Toggles and the season baseline are plain
   fields.
3. **Deltas, not snapshots.** Not applicable: no inventory, coins or position.
4. **Busy rules.** Not applicable: no player activity.
5. **Every entry path.** Every world load goes through `commit_outcome`'s `entered_world`: first
   entry, reconnect, and return from an instance. The tick covers the rest. Tested through the real
   dispatch (`Scene::send`).
6. **Reachable in production.** Production calls the same functions the tests drive: `Server::new`
   to `load`, `commit_outcome` to `world_ready`, and `step` to `season_tick`. The load test fails
   when the hub line is removed.
7. **Survives reconnect.** Nothing is saved, by design. A new session recomputes the areas (asserted
   in the load test). `world_ready_packets` from a fresh load also matches.
8. **Exit paths.** Not applicable: no state on the character.
9. **Economy.** Not applicable.
10. **Wire format.** Matches `0x008d5c60`, 11 bytes. Byte-level tests cover inner and framed forms.
11. **Unique ids.** Not applicable.
12. **Others see changes.** Season changes fan out to every loaded zone-0 session. `set_area` returns
    the packet for the event caller (T460) to fan out.
13. **Content works end to end.** The shipped file sends 14 packets on 2026-10-21 and only 4173 on
    2026-11-12. The lab-XML test checks that every id is a client area.
14. **Values in data.** Dates, ids and offset are in `client_areas.json`, with bounds.
15. **Canaries break production code.** All four canaries edit `src/`.
16. **Session plumbing.** No change to session creation, teardown, transactions or save ordering.
17. **One player's error.** A refused queue is logged and skips only that session (test with a 1-byte
    queue). Season and date math cannot panic: the cast is bounded and elapsed saturates.
18. **Rules on the type.** Doc comments on `ClientAreas` fields say what is saved (nothing) and what
    each one holds. `Content` documents `switchable`.
19. **Hot paths cheap.** See Cost under Structure.

## Threat note (secure-code-guardian)

No client request reaches this code. Opcode 89 is server to client only. The inputs are operator
content (bounded and validated at startup) and server events through `set_area`, which refuses ids
outside the client's 138 switchable areas. A hostile client cannot toggle areas, pick an elapsed
value, or make the server broadcast.

## Open gaps

- `realm reload` does not reload `client_areas.json`; a restart does. Add it when events need live
  edits.
- Within one minute of a season boundary, a client that loads between the boundary and the next tick
  can get the same enable or disable twice. `0x00bead80` ignores an unchanged state.
- Season-tick packets are not written to the `app_out` trace. World-ready packets are.
- Native acceptance (lead): Pixiewood shows Halloween effects; the Sanctuary entrance pad 4173
  launches the player.
