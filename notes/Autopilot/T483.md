# T483: the ride actor looks like the owned item and mount and dismount play the teleport flash

The ride's AddNpc (35/2) now carries the owned item's texture alias, tint alias and tint id and hides its nameplate. A live
board (168/2) and a live dismount (168/4) carry composite effect 46; the 168/2 a late joiner gets carries 0. Skills used:
ponytail (full), secure-code-guardian (nothing a client sends reaches the new fields), lean-structure.

## Structure

- Graph: not queried (no graph tools in this run); `rg` found every user of `add_ride_npc`, `encode_mount_response`,
  `encode_dismount_response`, `ActiveRide`, `MountEffectKind::SpawnRide`, `RideView` and `MountCatalog::new`.
- Owner: `src/mounts.rs` only (plus `data/content/mounts.json`). No hub file changed.
- `RideLook { texture_alias, tint_alias, tint_id }` is computed once in `spawn_instance` by `MountService::ride_look` from the
  summoned instance (T482) and the `looks` map T482 already built from `Inventory::look`. It lives on `ActiveRide`, rides
  on `SpawnRide` to `wire`, and is cloned into `RideView`, so the live fan-out and the late joiner draw the same ride.
- Tint rule is `write_attachment`'s (`inventory.rs` `tint == 0 ? default_tint : tint`): the instance dye, else the item's
  default. An item with no catalogue row falls back to the ride row (empty texture, the row's alias and tint), as before.
- `mount_effect_id` is `MountCatalog` state, loaded from `mounts.json` `mount_effect {id, source}` (same shape as
  `on_foot` and `trained_glide`), bounded 0..=100000, 0 = off. `MountCatalog::new` takes it as a fifth argument.
- Deleted: nothing; the old `0` literals in both encoders became the effect argument.

## Client evidence

- `00b06100` case 2 reads through `00b04c80`: rider u64, mount u64, seat i32, queue i32, an i32 passed to `Mount` as its third
  argument, an i32 stored at `rider+0x17bc` (`v5[1519]`), an f32. `Mount` (`00972d30`) tests `+0x17bc`, looks it up through
  `007c4710` and calls `00969590` (the play step). Our encoder's fourth i32 after the guids is that slot (byte offset 31).
- Case 4 reads through `00b04dc0`: rider u64, then one i32 stored at `rider+0x17c0` (`*(v18+6080) = v41`). `Dismount`
  (`00973050`) reads `+0x17c0` (`this[1520]`), looks it up through `007c4710` and calls `00969590` with it, so case 4's
  i32 does reach an effect player. The brief's inference holds; it is no longer only a guess from the field position.
- That the id is a composite effect (and that 46 is PFX_Teleport_Flash) is from Sanctuary naming, not the client's effect
  table: (R). `ProxiedCharacter` has a pending-composite-effect list (`0096e7d0`), which fits.
- The fleet research pack said Sanctuary sends 0 on dismount. That was Sanctuary-PC2009 (`PacketDismountRequestHandler.cs:33`).
  Sanctuary-main-20261019 `Player.cs:306-310` (`Dismount`) sends `CompositeEffectId = 46` on the live 168/4, which is the
  brief's reading; both are in `mounts.json` provenance. Its `Mount.cs:74` writes 0 on the replayed 168/2, as we do.
