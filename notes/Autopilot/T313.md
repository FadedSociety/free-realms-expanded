## Completion policy (T219, unchanged)

full 39/16 -> 39/5 -> 34/6 -> phase/countdown exchange. The package's amount never depends on a
contact, damage or score. `paid_matches` in the character save records the instance, so a repeated
results record, a close replay or a reconnect cannot pay twice; `next_instance` resumes above the
ledger so a paid id is never reissued. Unfinished matches pay nothing.

## Threat note (secure-code-guardian)

A hostile client owns the 26/8, 26/10 and whole 34/* stream. It can click any runtime GUID from any
position, forge a menu choice, replay 39/5/34/16/34/6, claim results early, or hand-edit a save ledger.
Why it is refused or harmless:

- **Gate authority.** The menu option exists only for NPC ids read from server content
  (`derby_gates.json`) and only after the NPC router proves the 12 m reach and zone. A forged target
  produces no menu (`unknown_runtime_guid` in the refusal test); a non-gate target has no derby row.
- **Choice authority.** The selected option id must be one of the open menu rows; a forged id is
  rejected without consuming the menu. Starting runs on a staged `Gameplay`; a refusal writes no save.
- **State authority.** The client cannot name an instance, phase, score, reward or result. The
  server allocates the instance above the saved ledger, runs the phase machine, and pays only from
  `Results`. Contacts are validated for reporter identity, finite impact, pose freshness, radius and
  damage caps.
- **Replay/reconnect.** `paid_matches` is the once-per-instance guard; the save encoding carries it.
  Test 2 replays the results-driving contact and the close; both pay nothing.
- **Content trust.** The package is read through the existing bounded, regular-file,
  `deny_unknown_fields` loader; every rule is bounded before the service is built. Malformed content
  fails the load, never a payout. The file has no executable or path fields.
- **Concurrency.** Two sessions have independent gateways, instance counters and ledgers; test 4
  asserts one session's entry does not move the other.
- **Economy.** The grant is a flat content amount, never derived from a client quantity, id or
  report; it is applied through the existing reward path with checked coin arithmetic. Free grants
  are unchanged (the starter outfit path is the existing unlock-once path).
