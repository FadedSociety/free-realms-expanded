## Findings

- Packet constructors at 00a59520, 00a595b0, 00a59660, and 00a59700 call the shared base initializer 00a4ec00 with discriminators 0x0d, 0x15, 0x1a, and 0x1c. They install their class vtables and initialize member data. The existing base-constructor evidence associates the family with outer opcode 0x5e; these four constructors do not by themselves establish send or receive direction.
- The bounded readers are mechanically field-oriented. 00a5a0a0 reads the shared two-short header. 00a5af10 reads four float dwords, ten checked float dwords, a boolean, three unchecked dwords, six more float dwords, and a length-prefixed member. 00a5b510 reads seven dwords and a byte span; 00a5bc10 reads a float4, one dword, and a length-prefixed string; 00a5c090 reads a dword, a length-prefixed string member, and a trailing dword. 00a5b660 reads vector/scalar fields and three bounded spans. These helpers report truncation or malformed lengths through the reader state.
- Caller chains connect several helpers to receive handlers without supplying a packet class or opcode inside each helper. 00a62140 constructs the 0x0d CameraConfig object and calls 00a615b0, which calls 00a5af10. 00a665e0, the UpdatePlayer body reader, reaches 00a618a0 and 00a5b510. 00a67350 decodes RenderDebugData through 00a61a00 and 00a5bc10; the caller handler 00a67a70 is the render-debug message path. These associations support client-side parse context, not original server rules.
- The container code uses several distinct intrusive layouts. List append/removal helpers use +0x70/+0x74, +0x40/+0x44, and +0x200/+0x204 links (00a5d0f0, 00a5d210, 00a5d400, 00a5bca0). ## Packet and server-contract hypothesis

The existing `notes/Native Map/Systems/net.packet.shipcombat.md` records outer opcode 0x5e and previously mapped sub-opcodes. S0300 adds constructor discriminators 0x0d, 0x15, 0x1a, and 0x1c, which are not identified in that note's current table; this extends the mapping without contradicting its established entries. Hypothesis: the original server sent at least some outer-0x5e ship-combat payloads that the client routes to these packet bodies. This depends on the base initializer at 00a4ec00, the dispatcher at 00a6d270, and the receive-handler/body-reader chains above. The 0x0d chain has a concrete client parse path; this shard does not prove direction for 0x15, 0x1a, or 0x1c. No original server validation, persistence, balance, or reward behavior is established here.
