## What changed in attempt 3

- **a2 blocker 1 (lead-only save/transaction) removed.** The world tick's `participate` no longer
  clones the session gateway, saves it, or installs it (`save`/`session.gateway = staged` are
  gone from `world_event_routing.rs`). It records the team in the in-memory run and calls
  `Gameplay::queue_dance_off_join(serial, team)`, which only stores a transient
  `Option<(serial, team)>` on the live gameplay. The player's **own** `Session::tick`, later in
  the same server step, runs `Gameplay::pet_tick` -> `credit_dance_off_join`, which emits
  `QuestEvent::JoinDanceOff` on the tick's staged gameplay; the existing `commit_outcome` saves
  it like any other tick change. The world tick writes no save and installs no gateway. A hook
  that fails is logged (`world_event_join_hook_refused`) and dropped; the join pass re-queues a
  participant whose session has not credited the run (a reconnect), and nothing is saved or
  timed from the shared tick.
- **a2 blocker 2 (refused vote changed run state) fixed.** The bin route no longer handles
  client 26/4 at all, so a client echo cannot clear the prompt; `WorldEvents::vote` sends no
  close (and changes nothing) on an out-of-range/foreign-instance/dead-box refusal, and only a
  counted vote consumes the prompt. `gameplay/npc.rs` now remembers when the last 26/8 named an
  actor the NPC router does not own (`NpcInteraction::foreign_click`): the next 26/6 belongs to
  the bin's event route, so the fallback close no longer answers a vote (the open NPC menu it
  may have is not consumed, which the existing T773 test pins). The bin end-to-end test now
  walks out of reach, answers (no reply, state unchanged), sends the client 26/4 echo (state
  unchanged), walks back and answers the same prompt without re-clicking (counted).
- **a2 blocker 3 (duplicated decoder) fixed.** The route calls
  `npc_interaction::decode_dialogue_response_26_6`, the canonical reader.
- **a2 minor 4 (boundary leak).** `DanceTeam` moved from `world_events` to `quest_engine` (the
  event payload's owner); `quest_engine.rs` no longer imports a feature module. The
  participation module split (`world_events/dance_off.rs`) is deferred; the state is part of
  `Run`'s private timeline and the file is not a hub (see Structure).
- **a2 minor 5 (compiled rules/data).** The vote row id is now per team in
  `world_events.json` (`vote_response_id`), and the join scan cadence is `join_scan_ms` in the
  same block (loader bounds 50-10000 ms). 401/402 are marked `(R)` in the content source (above
  the NPC rows).
- **a2 minor 6 (canary).** `LiveDanceOff.tally` records the per-side count at the decision and
  `votes_decide...` asserts `[2,1]`, `[1,1]` and `[0,0]`. The brief's "count each vote twice"
  canary now fails the winner test (see Canaries).
- **a2 minor 7 (run selection).** Every join/vote lookup is keyed by the run **serial**:
  `open_dance_offs()` returns `(instance, serial)`, `dance_off_area/team/participant/
  join_dance_off` take the serial, and `prompted` maps character -> owning serial. A two-run
  unit test joins, prompts and votes in two same-instance dance-offs independently.
- **a2 minor 8 (dead lookup).** `dance_off_participant` is production-live now: the join pass
  reads a participant first (no equipment scan) and re-queues a lost hook by serial.
- **a2 minor 9 (notes).** This file and the report are rewritten; the false claims about save
  ordering, refusals and the "no parallel path" line are corrected.

## Reconstructed rules ((R))

- The dance area is a 30 m sphere around the Sanctuary script's `DanceSpot`; the client song
  area is larger. The Voting Box model (1661, the event boombox) and its placement are `(R)`:
  no original box was recovered.

  in content order (vampire). The team is keyed by character guid for the run.

  draw made at the run's start. Votes are not limited to costume participants; the costume
  decides participation for the cake.

  decides the grant (the brief's verify-first).

  vote click cannot advance a server-open NPC dialogue.

  outfit, so no packet can claim a join.

## Threat note (secure-code-guardian)

Hostile client input: any 26/8/26/10/26/6/26/4 with any guid, id or payload; the client cannot
name a team, a vote count or a winner.

- A 26/8 outside the `EVNT` range is left to the existing routes; inside it the guid is split
  into run serial + actor index, the run must exist, be in the player's committed registry
  instance, have the actor live, and the committed registry pose must be within the existing
  12 m NPC reach. A guessed, stale, foreign-instance or post-ending guid answers nothing and
  changes nothing.
- The vote prompt opens only from that validated box click. A 26/6 counts only when the
  character has a prompt, the run serial in the prompt matches, the response id is the run's
  own team row, the instance/box/reach still hold, the run is not decided and the character has
  not voted. Everything else is silent and leaves the prompt and run unchanged.
- The costume join is server-side only: visible profile (slot 17 of `Profiles::shown`), committed
  registry pose/instance, content team mapping. A disconnected character keeps the team/vote for
  the run by guid; no save is written from the world tick.
- The cake checks the live winning cake actor, reach and the server-recorded participation; a
  non-participant gets 432505, a second use 432430, and neither changes the used-cake set. No
  economy is touched. A future grant must use the existing inventory grant and its full-bag
  refusal, and a full bag must leave the cake unused.
- The foreign-click flag only suppresses the NPC close for the next 26/6; it is set by any
  non-content 26/8 and cleared by a content-NPC interaction, so it cannot select an action.

## Checklist

1. **A refusal changes nothing.** Unit tests pin the vote/prompt/join/cake refusals; the bin
   test snapshots the whole `WorldEvents` around the out-of-reach answer, the 26/4 echo, the
   second vote, the reconnect vote, the second cake use, the non-participant use and the
   post-ending vote. The join queues only an `Option`; no save/install exists in the tick.
   Canaries 2-4 each turn a refusal/echo rule into a failure.
2. **Rollback covers all state.** Teams/votes/prompts/cakes and the tally live in the in-memory
   run inside `WorldEvents`, which the packet transaction clones and discards on failure. The
   queued hook is a transient field on the session gameplay; the quest change is emitted on the
   staged gameplay and saved only by `commit_outcome`. No `Rc`/`RefCell`/`Arc` side table.
3. **Apply deltas, never restore snapshots.** No snapshot is restored anywhere. The join hook is
   an event; a later quest change is saved from the live staged state, never from an older
   inventory/coin/position capture.
4. **Busy rules are mutual.** N/A: this adds no activity, lock, timer or `Occupation`; voting
   and the cosmetic cake start nothing. The existing NPC busy refusal still applies because the
   only new packets are on event guids.
5. **Every entry path is gated.** One join path (world tick: committed instance/pose, visible
   slot-17 costume, content team) and one packet route (event guid: run/instance/live
   actor/reach/prompt/row, one vote). Reconnect reuses the same scan and re-emits the hook once.
6. **Reachable in production, tested through it.** `tests`/bin test drive
   `Session::dispatch_message` -> `route_application` (26/8 and 26/6), `world_event_routing::tick`
   (the `Server::step` call) and a real `Session::tick` (`commit_outcome`). No internal shortcut.
7. **Survives reconnect.** All per-character state is keyed by character guid; the bin test
   drops the voting session, re-adds the same guid and its second vote is still refused; the
   unit test ticks a different registry. The join hook has no persisted checkpoint; after a
   reconnect it is re-emitted once for the same run, which an objective completes once.
8. **Every exit restores the player.** The event never moves, locks or times the character; stop,
   end, disconnect and timeout leave the character free and in place. A run's end clears its
   prompts; another actor click clears the prompt; a refused answer keeps it.
9. **Economy safety.** No item, coin or reward is granted; the cake only shows its 15/4 line.
   Every id/quantity is server-side. A future grant is the brief's deferred decision and must
   use the existing inventory grant and full-bag refusal (documented).
10. **Wire format.** 26/3 has a byte-level test for `93 + 20*2 = 133` bytes against reader
    `00a9ef10`; 26/6/26/8/26/4 use the existing constructors (`009f5890`, `008b6bc0`,
    `009f5760`); 15/4 is the existing `chat::string_say`. No field was added to any packet.
11. **Unique ids.** Event guids are the existing per-run serial + actor index; a live serial is
    never reused (`a_wrapped_serial_never_reuses_a_live_guid`), and event guids never alias the
    public-world instance.
12. **Others see changes.** The Voting Box and the winning cake are `AddNpc` actors sent through
    the runner's existing directed-visibility `view` on every path that spawns them; a late
    viewer gets them on the same path. Teams, votes, prompts and cake use are intentionally
    private (the client has no model for them).
13. **Content works end to end.** The shipped dance-off compiles with the box, both cakes, the
    prompt, the labels, the 401/402 rows and the 500 ms cadence (loader test). The bin test
    spawns the box, joins by costume, refuses and counts votes, decides 2-1 and serves the
    winning cake once; the quest content that listens for `JoinDanceOff` is the separate task, so
    the hook has no objective to complete yet.
14. **Values live in data.** Centre, radius, prompt/labels/refusal lines, costume `NameId`s, cake
    actors and lines, the 401/402 response ids and the join cadence are in
    `data/content/world_events.json`; compiled values are the loader's sanity bounds and the
    existing 12 m interaction reach.
15. **Canaries break production code.** All four canaries changed production code and failed the
    intended test; each was reverted and the tests rerun green. The brief's named canary now
    fails on the recorded tally.
16. **Hands off session plumbing.** No change to `Session::tick`, `commit_outcome`, session
    creation/teardown or save ordering in `src/bin/osfr-gateway.rs` or `src/gateway.rs`. The
    world tick does not save or install a session gateway (the a2 blocker). The packet route is
    five lines of thin dispatch in `route_application`; the hub is net -5 vs the tip.
17. **One player's error never stops the server.** `participate` cannot return an error and has
    no `?`; a quest hook error is logged and dropped; the packet routes refuse by returning
    `None`/empty. No `unwrap` on client data; the only checked endian reads are fixed-length
    slices guarded by the length match.
18. **A type's rules live on the type.** `LiveDanceOff` documents each map's key (including
    `prompted` character -> run serial), the decided/tally rule and the cadence; `DanceTeam` owns
    the team order; `TeamCostume` owns its vote row and cake branch; `TickState` documents its
    transient fields; the cake-to-ending mapping is derived from the spawn branch, not a second
    flag.
19. **Hot paths stay cheap.** With no dance-off, one run scan per world tick and no allocation.
    While one is open: every `join_scan_ms` (content, 500 in the shipped row) a pass over open
    runs and the registry rows in their instance (float area math only); equipment is read only
    for characters inside the area that have not joined (one or two `presentation` parses); a
    joined participant costs one map lookup to re-check the hook. The packet route runs on
    packets only; the session tick consumes an `Option` (`pet_tick` returns `None` when nothing
    changed, so idle sessions allocate nothing extra).
