# F707 — Review fixes for T529 (commit 8b71e48)

Review: `lab/autopilot/reviews/8b71e48-T529.md` (verdict BLOCKER). All six findings were real; each
is fixed below. No production behaviour changed except finding 3 (same value, one owner).

## What changed

1. **BLOCKER, duplicate 165/12 builder.** `tests/shop_sale_safety.rs` drops `buy_back_165_12` and
   calls the shared `gateway_vendor::buy_back_packet(transaction, 0)` (client writer `00c759c0`).
2. **165/4 and 165/13 builders.** Moved into `tests/common/gateway_vendor.rs` as `coin_buy_packet`
   (writer `00c75ed0`, request `00c77230`) and `buy_back_reply` (reader `00c71e40`); the suite
   reuses them. The older local copies in `tests/coin_shop.rs` and `tests/coin_store_siblings.rs`
   (that suite has its own `send`/`sell_packet` and does not include the harness) are left alone:
   folding them is a separate test refactor, not part of this fix.
3. **Deed type constant.** `CoinShop::sale_block` matches `station_cash::DEED_ITEM_TYPE` (the
   documented L046 constant) instead of a literal 16; the ride/lot test pins the lot's type to that
   constant too.
4. **Vendor view.** The shipped-content gate iterates `item_ids`, the list the loader stocks
   (`npc_interaction.rs` `VendorRecord`), not the wiki-shaped `items` rows. NPCs 9000000024 and
   9000000027 have one `items` row and an empty `item_ids` (pre-existing); only the loader's list
   counts. The reviewed list is unchanged (three Pet Pals).
5. **Unreadable definition.** New test `a_priced_item_with_an_unreadable_definition_is_refused_and_
   not_advertised` adds a defined id with a truncated serialized row (id plus 8 bytes, valid hash)
   to the fixture's own `inventory.json` copy, then drives the real 165/4 buy: invalid-item reply,
   snapshot unchanged, no save, not advertised. It asserts the row is defined and that
   `presentation` errors, so it is the unreadable case, not an unknown id. The old
   `sale_block(i32::MAX)` assertion (an unknown id, refused earlier by `buy_once`) was removed.
6. **Notes.** T529.md checklist 10 and 19 corrected (shared builders; two pets parses per session;
   two `presentation` calls per advertised row).
