  loops `survivor_sockets.iter().zip(&survivor_keys)`. For each survivor it drains the
  leave fanout, builds that session's reliable login datagram from its own gateway guid,
  sends it, sets `next_tick_ms = 0`, runs `Server::step`, and asserts both
  `gateway.is_logged_in()` and at least one `RELIABLE_DATA`/`RELIABLE_FRAGMENT` reply on
  that survivor's own socket. The assertion messages name `survivor_key.connection_id`, so
  a failure says which survivor died. `World::active_sessions` is a `BTreeMap`, so the
  survivors are deterministic: guid 302 (session 18) then 303 (session 19); the F285 code
  only used socket 0 (session 18). The reviewer's alternative wording fix is also applied:
  `notes/Autopilot/F285.md` and `notes/Autopilot/T250.md` now say the F285 check covered
  one survivor and F294 covers both.
- **Minor 2 (TESTS) — `connect_with` ignored its character.** It now captures

  `login(guid)`. New regression test

  character with guid 7, reconnects through the helper, and asserts the gateway keeps guid
  7 and is logged in. Against the pre-fix helper (`login(1)`) it fails with the gateway's
  real refusal, "login selects another character".
- **Minor 3 (STRUCTURE) — duplicate 165/12 builder.** Added
  `tests/common/gateway_vendor.rs::buy_back_packet(transaction, context)` (documented

  `SEEDED_ITEM` instead of `75_060` in the "pre-login item survived" assertion. The

  definition ids.
- **Minor 5 (DOCS) — stale claims.** `gateway_packets::login`'s doc now says the
  **gateway** compares the ticket guid (`src/gateway.rs` `parse_message` login arm).

## Security threat note (secure-code-guardian)

- **Attack surface:** a hostile client can send 66/43 with an arbitrary item id,
  quantity and transaction id, and 165/12 with an arbitrary transaction/context. This
  change adds no production parser, route, save, session, role or budget code; it only
  broadens the existing save-failure test to the second survivor and adds shared test
  packet bytes.
- **Why it is refused:** 66/43 still needs a server-opened shop, the vendor's authored
  stock/range and the server `stores.json` price; the client price is ignored. The
  failed-save test asserts the whole canonical `Snapshot`, coins/item counts and the good
  save bytes are unchanged, and that the same transaction replays with a charge and grant
  (no idempotency-cache leak); the pre-failure sale still buys back at the data price.
  The new `buy_back_packet` serialises two `u32`s and never interprets a client value.
- **Persistence:** the poisoned `state_path` is host-side only; no client field selects
  it, and the failed save leaves the old bytes untouched.
- **Isolation:** the save error is returned, never `unwrap`ped; the two-survivor test
  proves each surviving session keeps its key/rows and still handles and answers its own
  next datagram through the existing `contain`/`end_session` boundary.
- No player names, chat text, secrets or new content values were added.
