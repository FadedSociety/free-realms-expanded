## Mini-game and objective paths

- `009bd650` always constructs `PacketDismountRequest`; `client+0x280` controls whether it is sent. The function then chooses `ShowMicro` or `Show` and emits the selected UI event. There is no mounted-state test. `009beb70` separately constructs and conditionally sends a dismount request while applying a mini-game start.
- `009bdc60` resolves state id `-1` to the current state (or zero if absent), returns for other negative ids, builds family 39 from a caller-supplied sub-opcode and ids, and sends when connected. `009be7d0` sets a one-shot start flag, emits `GameEvents:OnPlayerStartMiniGame`, and calls this sender for `39/5`. `009bf190`, reached from dispatcher case `0x13`, performs local state/UI cleanup and then calls the sender for `39/7`. `Research/Pieces/016 Minigame loss and retry.md` cites `009be7d0` and `009bf190` and records the matching `39/5` and `39/7` vectors.
- `009bf890` is the secondary family-39 switch for cases `0x0e`, `0x11-0x13`, `0x16`, `0x28-0x29`, `0x2f`, `0x36`, `0x41`, and `0x42`. It has no group-info or wheel branch. Those appear in primary dispatcher `009bfea0`: group-info is case `0x32`, loot-wheel handling is `0x2d`; it also routes join `0x10`, reward `0x44`, and other explicit cases, forwarding default-path messages to `009bf890` only when the state lookup succeeds.
- `009be6b0` gates on manager count at `+0x20 > 0`, not on payload length. It constructs `MiniGamePayloadPacket` using the current state id (or zero), copies exactly the supplied byte count even when zero, attempts a connected send, and destroys the temporary packet. External constructor `009b09d0` identifies this as family `39/0x0e`.
- `009bead0` sends `MiniGameFlashCommandAdminPacket`; external constructor `009b3110` identifies family `95/63`. The client packet path is established, while the feature effect is not. Other external constructors identify `009bda80` as `39/0x2e`, `009bdaf0` as `39/0x26`, and `009bdbd0` as command family `26/11`; their wrapper bodies show the transport gates and local checks.
- `009bdd70` reads a composite mini-game info record with scalar/boolean fields, strings, a count-prefixed reward-entry array through `009bc380`, and trailing fields. `009bfc50` consumes it in the join-record path. `009bfd30` has a separate reward-update predicate: reader error clear and either `param_4 != 0` or signed `(end-current) <= 0`; its policy meaning remains unknown.
- `009bfdb0` parses the join body and initializes local state only when the reader error flag is clear and `(end-current) <= 0`. That accepts a cursor at or past the end, including a cursor beyond it. The earlier description that this enforces no overrun was incorrect; intended acceptance policy remains open.
- `009be130` dispatches objective-family 45 sub-opcodes `1-6` and `8-12` into objective state, UI events, movement, and fixture handling. This proves client-side routing and local effects, not server validation, completion policy, or rewards.

## Activity-launch messages and local state

- `009c0bc0` initializes the family-`0xaf` base packet; its shown callers are receive parsers. `009c0c30` is the shared parameterized family constructor, and `009c0d00` initializes the canceled subtype with sub-opcode 6. Dispatcher `009c3590` routes family `0xaf` sub-opcode 6 to `009c29d0`.
- `009c29d0` parses the cancellation id, searches the request list and processor map, invokes a matching processor callback, logs a missing request, then removes the request. Hypothesis: the original server sent `0xaf/6` to cancel a pending launch. This depends on dispatcher `009c3590`, constructor `009c0d00`, parser `009c2780`, and handler `009c29d0`; server logic is unavailable.
- `009c19a0` searches requests by id and, on a match, calls `00c4dfe0` with acceptance 1 and decline reason 0. ## Separate list and hash-map layouts

- The request list uses `+0xb8/+0xbc`; `009c1540` appends and `009c1860` repairs reciprocal links/endpoints before destroying and freeing the request.
- The processor list is separate. `009c2880` stores the old tail at new node `+0x4c`, clears new node `+0x48`, and sets old-tail `+0x48` to the new node. `009c27f0` repairs those links, destroys a `StringFixed<char,32>` at node `+0x10`, and frees the node. These are list links, distinct from hash-bucket links handled by `009c25e0` and `009c2690`.
- `009c2920` registers processors using a 32-bucket name hash and replaces an equal-key entry. `009c0e00` and `009c2b50` identify and clear the typed hash map. `009c2350` constructs a processor-stub object and stores an extra scalar at `+0x48`; that scalar's meaning is unknown.

## Wire-field constraint and open questions

- The packet catalogue has no relevant mini-game or activity-launch packet classes. `validate.py` also checks every slash-separated `wire.opcode` number against constants in that individual function's pseudocode. Thus a proven pair such as `39/5` or `0xaf/6` fails the validator when its family comes from an external constructor or caller. Where the target has only a sub-opcode literal, the structured `wire` field is left empty rather than labeling that sub-opcode as a complete opcode; where both components are external or dynamic, it is also empty. The exact pairs and their code paths are recorded above and in `open_questions`. This leaves a validator/schema gap before those tuples can be represented in `wire` while retaining `errors=0`; no packet class or in-function constant was invented.
- No contradiction was found with `Research/Pieces/016 Minigame loss and retry.md` or `Research/Pieces/020 Multiplayer activity grouping.md`: they support the `39/5`, `39/7`, and family-`0xaf` constructor paths, but do not establish original server policy. Corrections in this shard address prior overclaims about a mounted-state test (`009bd650`), payload-size gating (`009be6b0`), group/wheel cases in the secondary dispatcher (`009bf890`), logging an instance id (`009bf0f0`), and join overrun validation (`009bfdb0`).
- Open questions include the accepted meaning of the signed join cursor predicate (`009bfdb0`), payload field semantics in activity-launch records, local flags at `+0xb4/+0xb5`, processor scalar `+0x48`, and original server handling for mini-game and activity-launch operations.
