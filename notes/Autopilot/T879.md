# T879: combat markers (35/10 kind 3) for field enemies and battle spawners

Field enemies and field-battle spawners now send a full 35/10 notification of kind 3 ("Combat", the red
minimap dot and the on-screen direction label with the name) right after their 35/2. The row is content:
`combat_marker` in `field_enemies.json` and `field_battles.json` is the shared default; an actor may carry its
own `combat_marker` row or `"off"`. No file row means no marker (dormant by default).

## Client facts used (IDA, 2014 build)

- 35/10 handler `0093213a`-`009321d1` (dispatch `0092f460` case 10): guid not spawned is skipped, full record needs
  `image_id` > 0, minimap placement via `00a91800` with the record kind and the name locale id. Layout is the one
  `src/npc_notifications.rs` already encodes (unchanged).
- `01025670` (decompiled this task): resolves the key to the `NotificationImages.txt` row whose `USE_ON_MINI_MAP`
  byte (+20) is set. Key 24 has one such row, image 1345 (`24^1345^2^...^1^0`), the same 1345 as
  `Minimap.CombatIconId` in `StringHashToValue.txt` that the client itself draws for hostile players (`00a8ffe0`).
- The marker dies with the actor (`00972570` destructor path), so respawns resend it and despawns need no 35/11.

## Structure

- Graph/search: `npc_notifications::encode_add` (one encoder, reused), `NpcVisibility::set_notifications` (existing
  per-actor row, used for the per-player battle view), `EncounterEngine::initialization` (shared view),
  `field_initialization` / `set_active_quests` / respawn tick (the three solo spawn sites).
- New `src/encounter/field_marker.rs` (`MarkerSetting`: Shared | Off | Row, `resolve`, `packet`). A row whose
  `name_id` is 0 takes the actor's own name id; an actor with no name id gets none.
- `encounter.rs` (hub, +20 lines): the data fields only (`combat_marker` on `FieldContent`, `FieldActor`,
  `FieldBattleFile`, `FieldBattle`; resolved `marker` on `FieldEnemy`, `FieldBattle`). `field_content.rs` resolves them
  at load and refuses a bad row (`Notification::validate`); a refused `reload_field_enemies` stays staged.
- Spawn sites send the packet after the 35/2: `field.rs` (zone-ready batch, quest unlock, respawn), `shared.rs`
  (`initialization` for field enemies and battle spawners).
- `world.rs`: `NpcVisibility::add_battle_spawners(engine)` replaces the two duplicated spawner loops
  (`gameplay.rs` -3 net, `content_reload.rs` -5 net) and sets each spawner's notification; `battle_markers()` in `field.rs`.
- Net hub lines: `gameplay.rs` -3, `encounter.rs` +20, `osfr-gateway.rs` 0, `gateway.rs` 0. Nothing deleted otherwise.
- Cost: one 20-byte packet per spawn (zone ready, respawn, observer join), nothing per tick.
- Data: `field_enemies.json` and `field_battles.json` each gain one top-level `combat_marker` object.

## (R) choices

- Image key 24 (above); community kind-3 mob rows (third party) also use key 24 in the image slot.
- Full record, not the compact one: the video shows named red labels, and only a full record carries the name.
  The compact branch (`00a90430`, `ind_enemy` symbol, no name) is not wired.
- `hide_overhead` true (the brief's default): no evidence of an overhead icon over field enemies in first-party
  material. The community rows leave it unset, so flipping the data flag is the whole change if the owner disagrees.
- `state` 0 and `subtext_id` -1 (none); both unused with the overhead icon hidden / no sub-text.
- Battle label "Battle": locale id 425259 (English "Battle", sits beside the NPC-range strings "Fight!" and the
  Frostfang Caverns cave-in entry). A second string with the same text, 436635, is a menu topic label in a list of
  activity names, so it was not used. Which of the two the original sent is not recorded; the id is data in
  `field_battles.json`. Community Troll Summoner rows use the spawner's own name id instead.

## Not wired (listed, per the brief)

- Dungeon entrances: the 75 `data/content/dungeons/*.json` entrances (T878 positions in `dungeon_data.entrance`) are
  data only: no spawned actor exists to attach a 35/10 to (a marker needs a spawned guid). Video dungeon names
  (Tanglewood Fort, Haunted Mines, Forgotten Caves, Darvon's Descent, Bone Bog Cemetery) wait for entrance actors.
- Per-battle dungeon names: all 11 field battles (96, 12370, 12340, 12301, 12302, 12303, 12350, 12310, 12311, 12400,
  12360) share "Battle"; a battle can take its own name by adding a `combat_marker` row to its entry.
- Dead-corpse and world (opening-scene) / arena enemies get no marker; only overworld field enemies and spawners.

## Checklist

1. Refusal changes nothing: a bad marker row (`image_id` 0) is refused by `reload_field_enemies` (staged clone) and
   a second zone-ready batch equals the first (`a_bad_marker_row_is_refused_and_a_refused_reload_changes_nothing`).
2. Rollback covers all state: the resolved marker lives on `FieldEnemy`/`FieldBattle`, inside the cloned engine.
3. Deltas not snapshots: no player state touched. n/a.
4. Busy rules: no new activity. n/a.
5. Every entry path gated: the marker follows every spawn path (zone ready, quest unlock, respawn, shared
   `initialization`, per-player battle view); tests drive each.
6. Reachable in production: tests use the production engine entry points (`on_zone_ready`, `set_active_quests`,
   `tick`, `take_shared_fields().initialization`, `NpcVisibility::update`) and the shipped content.
7. Survives reconnect: the marker is derived from content on every spawn, nothing to persist. n/a.
8. Exit paths: no player state. n/a.
9. Economy: none. n/a.
10. Wire format: unchanged encoder; the decoder test reads each packet through `support/quest_marker_packets.rs`
    (reader `008db310`, 39-byte rows); the byte-level pin remains `tests/npc_notifications.rs`.
11. Unique ids: the marker uses the actor's own runtime guid. n/a.
12. Others see changes: shared view and per-player view both send it; tested both.
13. Content works end to end: shipped file marks every always-on enemy (`shipped_content_marks_every_always_on_enemy_as_combat`).
14. Values in data: kind, image, name, overhead flag are content; no pinned literals (tests read the files and an
    edit test changes shared/override/off rows and sees the packet change).
15. Canaries: removing the `field_initialization` send, the shared battle send and the `set_notifications` call each
    made 4 of the 9 tests fail; reverted.
16. Session plumbing untouched (no login/session/save/teardown file, no `gateway.rs`/`osfr-gateway.rs` edit).
17. One player's error never stops the server: markers are built from validated content at load; the send path has no
    `?` that can fail (`encode_add` returns `None` and nothing is sent).
18. Type rules on the type: `MarkerSetting` documents the three cases and `resolve` owns name fallback and validation.
19. Hot path: nothing per tick; one small allocation per spawn.

Threat note: nothing a client sends reaches this path (content-only, server-initiated), so there is no hostile
input; a malformed content row is refused at load by `Notification::validate`.
