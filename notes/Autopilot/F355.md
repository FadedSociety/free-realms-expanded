- **MINOR 2 (no-op HEAD guard) fixed.** The old test compared the working tree
  to `git show HEAD:`, which compares each file to itself once the commit is
  HEAD. `change_under_test` (`tests/npc_greetings_merry_vale_stillwater.rs:359-412`)
  now identifies the change under test:
  - uncommitted NPC edits (`git status --porcelain -- .../npcs`) are compared
    against `HEAD` (a builder worktree is private, so any NPC path outside the
    two owned files is this slice's spill);
  - otherwise, if the HEAD commit touched one of the two owned files
    (`git diff-tree ... HEAD`), its changed paths are checked (the committed
    review state);
  - a tip whose change touches neither owned file has no content change for
    this suite to check.
  The test then asserts the change's changed NPC paths are only
  `merry_vale.json` and `stillwater_crossing.json` (`:757-766`). This is the
  review's changed-path alternative to comparing every out-of-scope file to
  `HEAD^`: a clean tree's out-of-scope file differs from `HEAD^` only if the
  commit touched it, so the two checks are equivalent, without re-reading
  23 MB. Every other region file stays owned and pinned by its own suite (the
  T246/T280/T298/T299/T315/T317 rows), so this gate cannot stale when another
  slice lands first. The row-level baseline comparison was deliberately dropped:
  a later slice (e.g. Stone Heart) legitimately adds a greeting to a non-target
  row, and T316's target pins already guard its own 17 rows.
- **MINOR 3 (exact-set assertion) fixed.** The "`found == expected`" block is
  deleted. The test now proves only that the 17 target rows carry their pinned
  ids and that the two pre-existing owned-file bindings are unchanged, and
  uses `greeting_bindings()` for the cross-file uniqueness the old test missed:
  no other binding in `npcs/*.json` may reuse one of the 17 ids

- **MINOR 4 (zero case) fixed.** `zero_greeting_fixture` (`:420-478`) copies
