## Security threat note (secure-code-guardian)

- **Attack surface:** the suite exercises the existing client input paths —
  26/8, 26/10, 26/6, 49/2, 49/14, 26/13 and authoritative movement via
  `on_location` — for two plus one characters. No parser, selector, packet
  family, wire field, reward amount, role, save field or transport was added.
- **Hostile claims refused:** 26/8/26/10 must name an NPC content key, pass the
  12 m/zone check and choose an option from the server menu; 49/2 must match
  the server's `pending_offer`; 49/14 must match `pending_turnin`, set only by
  a server Talk that completed every objective and the released 49/13; 26/13
  is the existing job switch. The suite sends unoffered/wrong/forged/replayed
  variants and snapshots the whole `GameplayState` **and** its serialized save
  bytes (tests 1, 3, 4, 5, 6); an out-of-range 26/8 is asserted `Err` before a
  menu exists.
- **Dev command:** a `realm broadcast` 15/1 line is refused by the production
  role/dev-tools gate; the reply has no 49/3, 49/4 or 50/1 and the character's
  state and save bytes are equal. No event path needs a chat command.
- **Economy:** the only grant is the content row through the per-character
  grant key, once per character; no client quantity or item id is read; the
  test asserts A's payout leaves B's wallet/XP untouched and vice versa, and
  that a third character with no hunt gets no offer or reward. Near-cap
  atomicity is covered by the existing two-player
  `an_over_cap_reward_is_refused_for_that_player_only` in
  `tests/scavenger_hunt_quest.rs` (A's over-cap 49/14 is refused with equal
  state/save bytes and `pending_turnin` preserved while B is paid) — cited, not
  duplicated, because it already runs in gate 2.
- **Pre-existing turn-in range gap:** once `pending_turnin` is set, 49/14 does
  not recheck the speaker/range (F272 pin kept). It still cannot forge
  completion, and enforcing a range is a lead-approved 49/14 change, out of
  scope.
- **Isolation:** a refused or bad request on A never affects B (tests 4 and 7);
  no shared tick or session code changed, so no per-session panic path was
  added.
