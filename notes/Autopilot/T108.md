## Threat note

A hostile client can send 66/43 with an arbitrary item ID, quantity or
transaction ID, can send it without an open shop, and can name a foreign or
unknown NPC in 26/8 or 26/10. The server refuses those inputs before touching
inventory:

- 26/8 and 26/10 require a known NPC, the 12 m range check, an active
  interaction and an offered option; a foreign merchant or option is refused.
- 66/43 is decoded only for the exact family/subtype and the bounded body.
  `NpcInteraction::validate_merchant_item_66_43` requires the active merchant,
  the same zone/position and the item in that vendor's server-owned stock.
- `CoinShop::buy_vendor` re-checks the item definition, the positive server
  price from `stores.json`, the quantity against the stack, bag capacity and
  coins. The client price is not on 66/43; it cannot override the catalogue.
  Transaction IDs are cached for idempotency with a bounded client-controlled
  cache. Refusals answer 66/44 with status 0 and do not commit inventory.
- `NpcInteraction::load` rejects vendor rows with unknown or nonpositive
  prices, duplicate IDs or a non-vendor role. The coverage test additionally
  requires a positive price, `no_sale == false`, a valid category/stack and a
  runtime definition for every added row.

No client string becomes a path, no reward is taken from a client-reported
result, and no refusal changes the gateway snapshot (tested).
