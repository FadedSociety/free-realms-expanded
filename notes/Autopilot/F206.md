## Security note (secure-code-guardian)

Threat: a hostile client cannot write save files or content, but it can cause a save/load cycle
mid-match and it owns the derby `34/*` stream. A tampered or stale save can carry any
`previous_job` value; a stale operator package can carry the retired `reward` and
`reward_cooldown_s` keys. The new fields are inert: the reward value is never read, the cooldown
is never applied, and the active-job restore goes through `Profiles::activate`, which refuses ids
that are not unlocked. A refused restore is logged and skipped, so no error path returns a partial
profile and no coins, items or counters are touched. `Gameplay::state()` still writes `derby:
None`, so a saved derby marker is never trusted as a live match. No client quantity or item id
reaches the economy in this change, and the derby still pays nothing (existing fabricated-contact
regression). Unknown fields inside the derby save marker and the derby content documents still
fail closed through `deny_unknown_fields` except the two documented legacy keys.
