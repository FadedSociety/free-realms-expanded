## Security threat note (secure-code-guardian)

Attack surface: the normal NPC/quest frames (26/8, 26/10, 26/6, 49/2, 49/14) plus
server-validated movement. This slice adds no parser, selector, packet family,
reward amount or client-supplied quantity; it enables one content row.

- A hostile client can forge `49/2 accept`/`49/14` for 3160005: refused unless
  the server set the matching `pending_offer`/`pending_turnin`; the tests assert
  the whole serialized `GameplayState` is byte-identical for forged accept,
  forged turn-in without a pending screen, premature turn-in, and replays after
  completion.
- It cannot skip the objective order: `talk_to_npc` progress comes only from a
  real 26/10 Talk event, the loader marks the quest `ordered`, and the tests
  prove the Fizzlesticks Talk before Nurble advances nothing (and a repeated
  Talk does not increment twice).
- It cannot buy the offer by naming the quest: the offer is selected from the
  NPC's giver list plus `QuestEngine::offer_denial` (giver, range/zone, enabled,
  prerequisite, job, pending state and quest limit). Non-Wizard and
  prerequisite-in-progress cases are tested with a snapshot before/after.
- Rewards are the fixed content row, granted only by the server-side completed
  turn-in through the idempotent `quest:<character>:<quest>` grant key; a
  replayed 49/14/49/2 pays nothing. No client quantity or item id is read, and no
  item is granted.
- Malformed reward rows remain content-load errors (T242's
  `a_malformed_wizard_record_fails_at_load`, re-run green); content_check
  `--strict` is 0 errors.
- A player in an encounter gets the shared busy refusal before any menu/offer;
  busy rules are the existing `gameplay/occupation.rs` table (untouched).
