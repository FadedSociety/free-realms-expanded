# T804: card login redeems by launch ticket alone (lead build, native 2026-10-27)

## Why
Native 2026-10-27 ~07:35Z: with T798 the card window logged itself in, but the card service refused it ("check login info").
The exe's TCG command line is `--sessionID --character=<name> --ticket=<n> --host --lang --country`: no `--characterID`
(the DLL can parse one: argument readers `1037a970`..`1037aec0`, `notes/Research/TCG Client Protocol.md`), so the 411's `character_id` is empty and
`LaunchTickets::redeem` (decimal id must equal the owner) refused every real login.

## Change
`src/card_service.rs` `LaunchTickets::redeem`: the ticket alone identifies the character; an empty `character_id` is accepted,
a non-empty one must still be the owner's decimal guid. Ticket rules: random 64-bit, single use and spent only on a
matching, unexpired presentation (F779/F821, signed off 2026-10-27: a refusal spends nothing), TTL from the card launch
block, one per character.

## Threat note
The launch ticket was already the only secret: the character guid is not secret. Dropping the empty-id requirement does not
widen access: a forged login still needs a live, unspent 64-bit ticket minted for that character in its own session.

## Structure
One condition in an existing function; no new helper. Test added to `tests/card_service.rs` beside the existing redeem tests.

## Gates
card_service, card_launch, app_fuzz, spine_rules, `--bin osfr-gateway card`; native: Card Duelist logs in (card_login ok:true).
