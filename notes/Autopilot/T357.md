# T357: bind the enabled quests to their giver NPC rows

F343's open gap recorded twelve enabled quests missing from their giver NPC
row's `quest_ids_given`/`quests_given`. The split loader's offer union made them
reachable, but the row and the catalogue disagreed. Three are the deliberate
union controls pinned by `tests/scavenger_hunt_quest.rs` (`3000059`/`3000060`
Ricky Danger 9500000254, `3000200` Jacque 9500000497); this slice binds the
other nine, leaves those three empty, and adds `tests/quest_giver_rows.rs` so a
new unbound enabled quest or a stale row fails.

The Sheep Watch brief's `3000061` had **not** landed at this tip (`3000061` is
absent from the catalogue), so the bindable set is the brief's nine, not ten.

first, then `QuestEngine::quest_ids_for_giver`, and returns the first quest

Auguste's `3050004` is deliberately appended **after** `3050011`/`3050013`
instead of sorted into the first position: `quest_ids_given` is the Talk
first-offer priority list, so sorted insertion would have moved Cooking 101
ahead of Chef: Ranger Requisition, which `tests/quest_job_xp.rs` (real Talk
path: `offer(... AUGUSTE, RANGER_REQUISITION)` in three tests) pins. The brief
asked for ascending arrays, but its stronger invariant is no offer change; the
priority order wins and the `quests_given` object is appended to match. All
other arrays are ascending. The offered ids are pinned by the gate suites
(`archer_entry_chain` 3010003, `wizard_entry_chain` 3160003, `quest_job_xp`
3050011 + 3000020, `farnum_starting_quests`/`shared_field_kill_quest_credit`
3000009), all green. The minimal `quests_given` entries carry no
`title`/`title_string_id`, so the 26/3 dialogue title list is unchanged.

## Threat note (secure-code-guardian)

No client input parsing, save, coin/item grant, reward source, role, chat or
other-player-triggered path was added. The NPC rows and quest records are
server-authored content loaded once at startup; a hostile client cannot choose
a row, giver or quest id. A Talk reaches the offer only through the existing
`Gameplay::talk_to_npc` / `npc_select_26_10` path and the server's
`NpcInteraction::offerable_quest_for_talk` -> `QuestEngine::can_offer` gate
(giver match, enabled, pending/status, prerequisites, level/job/membership,
quest limit); the row binding does not bypass any gate, it only decides which
already-authorized quest the loop tries first. The bound quests keep their
existing server-verified rewards; the minimal `quests_given` objects add no
text, title, item or reward. Malformed or mismatched content is refused at load
(`InvalidData`), not trusted at runtime. The new test only reads shipped
content.
