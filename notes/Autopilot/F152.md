  win: both are inert; the win test asserts no second payout and no state
  change.

  ignored (F140 test) and the reply comes from the server's own scoring and

  cannot affect rewards; `ChessService::settle` remains the only grant site

  paths stage a clone (`Gameplay::handle_chess`, `ChessService::route`) and the
  tests compare the full state.

## Checklist

1. **Refusal changes nothing.** `active_chess_blocks_recipe_start...` and
   `active_chess_refuses_a_real...` snapshot the full `GameplayState` before a
   refused 26/24/26/10 and assert equality after; `refusals_and_illegal...`
   covers unknown ids, a second Play, an illegal move, a wrong-instance
   payload and an early GameOver. Canaries for the two busy refusals fail the
   tests.
2. **Rollback covers all state.** `Gameplay::handle_chess` stages a clone and
   `ChessService::route` stages its own clone; no shared `Rc`/`RefCell`/side
   table is introduced. The refusal tests compare the whole persisted snapshot,
   and the service-level ledger is inside the cloned service.
3. **Apply deltas.** `apply_grant` clones the live reward state and adds the
   content coins; it never restores an older inventory/position snapshot.
   The route win starts at 0 coins and asserts exactly the content award; the
   F140 cap test starts at 7 and ends at 17.
4. **Busy rules are mutual.** Chess already has an `Occupation` variant and the
   shared `activity_busy`/`blocks` table; the new tests prove chess blocks both
   the recipe-book and the world-interaction craft path, and the existing
   `occupation` pin test covers every gate. No new activity was added.
5. **Every entry path is gated.** 26/24 -> hub handoff -> `recipe_book::start`
   busy check; 26/10 -> chess interaction guard; portal Play ->
   `ChessService::begin` `is_active`; payout -> `ChessService::settle` + daily
   cap. The tests drive `Gameplay::handle_in_world`, the real request path.
6. **Reachable in production, tested through it.** `chess_route` sends raw
   inner packets through `Gameplay::handle_in_world` from portal Play to close;
   it does not call chess internals for the win. `seed_chess` only chooses the
   offline table stream.
7. **Survives reconnect.** No new persisted state; the F140 chess ledger lives
   in `GameplayState::chess`. `chess_route` round-trips it through serde and
   `Gameplay::load`; the route win asserts the ledger after payout.
8. **Every exit path restores the player.** Quit is covered by the existing
   route test; the win test closes with 26/42, leaves the run inactive and
   starts a fresh table; a malformed start is refused without disturbing the
   live run; refusals leave the chess table playable.
9. **Economy safety.** Only a server-verified checkmate plus the client's
   `FRServer_GameOver` acknowledgement pays; duplicate acknowledgements and
   late moves pay nothing; awards are content-bounded and daily-capped; tests
   assert the exact award and ledger. No free grant or client-reported result

10. **Wire format matches the client reader.** No wire change. The route win

    IDA re-queries stalled (recorded above).

12. **Others see changes.** Chess is single-player and publishes no other-player

13. **Content works end to end.** The route test reaches checkmate, emits the
