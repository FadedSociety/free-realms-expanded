# T371 - S19: move the crafting, gathering and movie machinery out of gameplay.rs

Restructure plan S19 (Phase D), pure move. No packet, refusal string, timing,
order, reward, profile, busy rule, save field, dependency or test name changed.
`src/gameplay.rs` is the CRLF hub; the new child module is LF like the other
`src/gameplay/*.rs`.

## What changed

- New `src/gameplay/crafting.rs` (LF, 467 lines): `use super::*;`,
  `use super::movie::{Movie, elapsed_if_due};`, then `impl Gameplay` with the
  moved methods, bodies, doc comments and `(R)` tags verbatim:
  - movie gate, cancel and tick: `running_movie`, `cancel_movie`,
    `route_movie`, `tick_gather`, `movie_tick`;
  - tutorial/station view: `start_tutorial_craft`, `opening_craft_pending`,
    `near_craft_station`, `crafting_stations`;

  - appliers and engine accessors: `apply_craft`, `type8`, `type8_mut`,
    `apply_type8`, `consume_materials`.
- Visibility is mechanical: `pub(super)` only where the hub or an inline test
  calls in - `running_movie`, `cancel_movie`, `route_movie`, `movie_tick`,
  `start_tutorial_craft`, `near_craft_station`, `crafting_stations`,
  `gather_count`, `material_count`, `apply_craft`, `type8`, `type8_mut`,
  `apply_type8`. `tick_gather`, `opening_craft_pending` and
  `consume_materials` stay private to the module.
- `src/gameplay.rs` (CRLF): **5,954 -> 5,493 lines (net -461)**; `git diff
  --numstat` is `+1/-462`: one `mod crafting;` line, the removed
  `use self::movie::{Movie, elapsed_if_due};` (the remaining hub code does not
  use either name) and the five moved line ranges. Kept `begin_gather` (S9

  else. `src/gameplay/movie.rs` still owns `Movie`, `Movie::ALL`, the per-movie

  `start_forging`; the enum is not duplicated.

  `use super::Movie;` and `s6_characterization.rs` `use super::movie::Movie;`.
  Both used to get `Movie` from the hub's private glob import, which the brief

  `t013_objective_events.rs`, `t018_station_refresh.rs` and
  `w104_quest_tests.rs` needed no edit; `pub(super)` is visible to the hub's
  child test modules.

Net: gameplay hub -461; new module +467; `movie.rs` +1; `s6_characterization.rs`
+1. No other hub file changed (`src/bin/osfr-gateway.rs` 4,663,

## Security note (secure-code-guardian)

A hostile client can still send the same frames: `39/x` movie payloads, the
four-byte `26/42` close, `26/8`/`26/10` interactions and the blocked
`26/13`/`36/10`/`42/*` families while a movie runs, plus chat `realm ...`
commands. The move adds no parser, no new field, no `unwrap` on client data and
no new `?` in a shared tick; the gate order (Forging, Cooking, Smelting,
Mining, Harvesting), the static refusal strings, the clock-write-after-apply
rule and the staged-clone boundary are byte-for-byte the old code. `apply_craft`
and `apply_type8` still consume only server-derived transactions, keep the
active-job checks, and return `Err` before any mutation; a refused request
changes nothing (the existing S6/S10 characterization and type8 suites assert
state, clocks, inventory, opening counts and saved bytes after each refusal).
No persisted field, id allocator or session plumbing changed.
