## Threat note

A hostile client can send an unknown `26/8` actor, an unoffered `26/10` choice,
a `TurnInQuest` selection for an incomplete quest, a forged quest id in
`49/14`, or replay `49/14`. The existing gates still hold:

- The NPC menu must be open for that exact NPC; the choice must be an option the
  server generated, and zone/range are checked before `select`.
- `begin_turnin` requires the content-bound turn-in NPC and the quest's exact
  eligible/active state. The new content rows only change which server-generated
  option appears and which content actor validates it; the client never supplies
  the actor or the quest id for that option.
- The reconnect replay is built from the saved server `pending_turnin` and the
  content definition, and only follows a server-emitted `35/2` for that speaker.
  A stale/missing definition fails closed without trusting client bytes.
- `finish_turnin` requires the exact saved pending quest and settles through the
  idempotent `quest:<character>:<quest>` grant key, so a replay or a forged id
  cannot pay twice.
- The refusal tests snapshot the serialized state; an unoffered menu choice and
  a replayed hit change nothing and leave the menu usable.
- No new item, coin, role, reward path or client quantity was added.
