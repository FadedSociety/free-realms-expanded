## Security note (secure-code-guardian)

Hostile client while a movie is live can send a truncated/extended 26/42,
arbitrary 39/x, the five blocked families, `realm exit`, or other `realm`
text.

- Wrong-length 26/42 returns the same `Err` as before; the caller stages on a
  clone and drops it on `Err`, so run, clock, inventory and opening state are
  untouched. The private and public matrices assert snapshot equality, and the
  non-ignored Type8 test asserts it through the gateway.
- Blocked families and other `realm` text answer with the same fixed strings and
  change nothing (asserted). The reply strings are now `&'static str`, so a
  hostile spam loop no longer creates an intermediate `String` per refusal.
  `chat::system` still allocates the reply packet, as it always did.
- `realm exit` and the valid close cancel only through the engine's `cancel()`
  plus applier; a cancel carries no transaction and the matrix asserts the
  inventory is unchanged, so Close/exit cannot earn.
- No new `unwrap` on client data: engine `Option`s are unwrapped only after
  `running_movie()` proved the movie occupied, and lengths are checked before
  any parse.
- Isolation: a handler error is contained per session by `Server::step`; the
  test proves one malformed close ends only that session while two others and
  the server keep running. No new packet, selector, save field or trace field is
  written.
