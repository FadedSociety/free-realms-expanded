## Threat note (secure-code-guardian)

No new client parsing code was added. The row feeds the existing 167/1/1
catalogue, 26/8 marker, 41/108 Go, 36/10 attack and 26/42 Close handlers. A
hostile client could send:

- a forged 167/1/2 Play id: it must be in the published catalogue; the busy
  table, combat-job and level checks run before the whole-bundle prize
  preflight, and every refusal is a chat line with an unchanged
  snapshot/save (tests 5, 6, 14);
- a forged 26/8 marker GUID: only a battle spawner within 8 m opens a screen;
  an arbitrary GUID is inert (test 6);
- a forged/out-of-range 41/108 Go: only the pending screen's encounter and
  instance, with the player still within 8 m, can start; an out-of-reach
  screen is dropped, a forged Go has no reply, and a refused Go changes
  neither the pending screen nor the save (tests 1 and 6);
- an arbitrary 36/10 target GUID: only the active arena enemy within the
  profile's weapon range and the swing cooldown can be hit; damage is computed
  from the server profile, never the client payload (full-route test);
- a replayed 39/46 wheel acknowledgement or 26/42 Close: 39/* is inert, and
  only a Won/Lost active run exits; a consumed pending screen cannot be
  replayed (full-route test);
- a full bag: the four-row whole-bundle preflight refuses before the encounter
  starts (tests 5 and 6);
- an over-cap coin balance: the checked payout refuses the reward alone with a
  chat line, leaves coins/items unchanged and does not stop the other session
  (test 14).

Rewards come only from server-verified kills; no client quantity, item id,
coin amount, win flag or impact is trusted. The static marker is shared by all
sessions (no per-player alias). The content file is bounded at 128 KiB, 64
battles, 1..=16 enemies per battle, 4 prizes, quantity 1..=100, unique actor
GUIDs across every encounter actor and a battle id unique against
`encounters.json`; a malformed or duplicate row is refused at load (test 10).
No save field changed and no player name or player chat text is in the content,
tests or this note (the only chat strings are server refusal lines).
