## Evidence and (R) choices

- **R: the rule is `max(1, Cost // 10)`, not the brief's plain `Cost // 10`.** The community server data stores
  `ResellValue == max(1, Cost // 10)` for 1,229 of 1,230 priced rows
  (`OpenSourceFreeRealms/ofrserver/Customize/ClientItemDefinitions.json`, measured by
  `scripts/pieces/piece_084.py`; cost 1, 2, 4, 5, 6 and 10 all resell for 1). Our data has 108 rows at price 5
  (member price 4): plain `// 10` pays 0 for them, and the sell tab drops an item whose paid price is 0
  (`CoinShop::sell_worth_override` sends Worth 0; client `CanSellItem` `00cf08d0`). Price-10 rows stay 1 either
  way (wiki tooltips: 9 of 9 pay 1). The floor changes exactly those 108 price-5 rows against the brief's formula.
- Wiki tooltips: reproduced the brief's counts exactly: 396 items, 426 pairs, 341 at `// 10`, 0 at `/ 2`.
- Client: no retail value exists (the catalogue `ResellValue` is a reconstructed 0 for most definitions;
  among inventory-baseline rows with a real value, 193 of 551 priced ones equal `max(1, Cost // 10)`, none equal
  `Cost // 2`, the rest are other eras). The client reads Worth from the definition (`00cf08d0`, `008e3760`
  into `+0xf0`); the server decides what 165/5 pays, so this is server policy (R). No new client claim was
  made, so no IDA query was needed.
- Cap: the generator skips a row whose new price would exceed its cheapest buy price (0 rows at this tip).

## Structure

- Queries: `rg sell_price_coins|sell_unit_price|sell_worth_override` over `src` and `tests`. The owner of the
  sell price is `coin_shop.rs` (`sell_unit_price`; `StoreCatalogue::load` already rejects `no_sale` with a sell
  price) and it needed no change: the rule is data. The codebase-memory graph tools were not available to this
  worker, so rg was used.
- Modules touched: data only (`stores.json`, `vendors.json`), one script, tests. No `src/` change, so no hub
  file grew (0 net lines in `gameplay.rs`, `osfr-gateway.rs`, `encounter.rs`, `gateway.rs`). Deleted: the
  `SELL_PRICE` constant and pinned literals in six tests.
- Line endings: `stores.json` LF, `vendors.json` CRLF (47,640 CRLF of 47,640 lines before and after), tests
  and notes LF; the generator writes bytes.
