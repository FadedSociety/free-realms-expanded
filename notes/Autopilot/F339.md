## Security threat note (secure-code-guardian)

Attack surface: a hostile client can send arbitrary 26/8, 26/10, 26/6, 26/13, 49/2, 49/14,
45/7, 39/18, 39/14 and 50/1 bodies and (through the gateway's shared action) a 36/10 body,
choose a target GUID, position and timing, and replay any of them. This task changed test
code only; it adds no production parsing and no new attack surface.

What the suite proves:

- **Turn-in authority.** 49/14 pays only with the server-set `pending_turnin`; premature,
  wrong-quest and replayed turn-ins leave the whole `GameplayState` and `saved()` bytes
  equal. The full-bag refusal at the exact 100-stack boundary is atomic.
- **Kill authority.** A forged target GUID and an out-of-range attack change neither the
  gameplay state nor its bytes (canary C), and the later successful kill proves no hidden
  attack cost. A zero-definition kill is accepted but credits no quest and emits no
  49/9/49/10.
- **Client-reported results.** Well-formed 39/18/39/14 packets cannot pay: the production
  consumer reads only server settlement replies. A 45/7 can move only a client-judged goal
  (W175); this quest has none, so a claim matching its defeat objective id advances nothing.
- **Economy.** Coins/XP/item come only from the server's `finish_turnin` with the authored
  reward map; the item is a real catalogue definition not already owned, and a replay pays
  nothing. The client-supplied 50/1 bundle is ignored with state unchanged.
- **No dev command.** Every request shape is not a 15/x chat packet, and the loop replies
  contain no chat/system line, so no `realm` command can run in this loop.
- **No panic path.** No production code changed and no test `unwrap`s a client-controlled
  value; refusals are asserted to be `InvalidData` where the handler errors.
