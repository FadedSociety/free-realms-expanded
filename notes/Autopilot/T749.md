## Recovered facts (client evidence)

- The client zones by **scene name**, not a numeric zone id. The 174 `*.gzne` entries in
  `lab/extracted/client-assets/catalog.tsv` are the scene table; the name is the pack entry
  name. `PacketClientBeginZoning` reader `FUN_008e4ae0` (pseudocode line 1029104; opcode
  `0x1f`) carries scene name, type, instance id, geometry id; `FUN_009386f0` logs
  `"Loading zone %s type %d ..."`. `FUN_008a7840` maps type 0..3 to `ZoneType`
  `TileStatic`/`TileSeamless`/`RuntimeSeamless`/`Mesh`.
- `FUN_008a78d0` stores the **geometry id** at `client+0x194` and calls `FUN_00a44b70`,
  which selects the journal region row whose `+0x14` equals the geometry id (default
  region 1). The client constructor also loads a default `GeometryId` (`FUN_00910880` at
  pseudocode line 1091144). The geometry id is a region selection/geometry value, not a
  scene index. Captured: `FabledRealms` 2, `sg_random_encounter_clearing` 96,
  `sg_kt_track` 101, `hsg_emptylot_seaside_beach_01` 214.
- `ChatPacketEnterArea` is `BaseChatPacket` mode 2, client receive dispatcher `0x00b14350`
  case 2; reader `0x00b109b0` -> `0x00b10580` reads one `u32`; display `0x00b10250` uses
  `EnteringChatArea` (numeric id **3604**, `Now entering [*area*].`) and binds the value
  as the `area` parameter.
- The on-screen banner is `BaseUiPacketDispatch` `0x00a91bf0` case **47/9** at
  `0x00a92121`, which calls Lua `NotificationHandler:LoadingZone` at `0x00a921a9`; the
  payload reader `0x00a8da50` -> `0x00a8b360` reads two length-prefixed strings and passes
  both to Lua. IDA correction to `notes/Research/World Object Catalogue.md`: `0x00a92121`
  is the case arm, not the reader. Lua (`ScriptsBase.lua:11642-11664`) maps zone ids 2..10 to the nine
  `*_notification.swf` movies, `note_nowEntering` (numeric id **406408**) and sound 16125.
- The first-party region ids are 1 (default; `Newbiezone` has the only
  `RegionOverride="1"`) and 2..10 (Blackspore, Briarwood, Merry Vale, Sanctuary, Seaside,
  Shrouded Glade, Snowhill, Wugachug, Sunstone Valley). Client numeric name ids (locale
  `ucdt`): 3500, 18140, 4428, 3499, 3501, 3502, 3961, 3505, 3793.
- The wiki map labels are a name source, not a scale source. Only `Map seaside.png`
  passed an affine fit with an independent anchor set (max residual 22.8 m). Wugachug,
  Merry Vale and Shrouded Glade are 3-anchor exact but unvalidated; Sanctuary (96.6 m),
  Snowhill (49.8 m), Blackspore (93.0 m) and world-0 (488.8 m) are bad fits and were not
  used. Pony Vale is a client-named, asset-backed place in Sunstone Valley (name id 1646;
  Mystical Barrier 8802), not a `.gzne` scene or area row.

## Security note (secure-code-guardian)

This task changes no code; the threat note applies to the build plan.

- **Attack surface:** a hostile client can send forged position reports (`125`), forged
  chat (`15/1`), and possibly an application `47/9`/`15/2`; it cannot be trusted for its
  region, zone or area name.
- **Rule:** region/place is computed server-side from the validated pose
  (`movement.rs`), never from a client field. A client `47/9` or `15/2` is not accepted as
  a request; the gateway currently routes only family 47 subtypes 12/13 to quest_engine
  and client chat only 15/1. Add a refusal test for a forged 47/9/15/2 and assert no state
  change.
- **Rate/abuse:** banner/chat is sent only on a confirmed region/place change, once, with
  a data-driven minimum interval; a client that moves back and forth can only trigger its
  own session's UI, and the server must not fan it out to other players. No rewards,
  coins, items or save state are involved.
- **Validation:** region ids 2..10 and name ids are from content, not client input; the
  47/9 zone id is formatted from a bounded integer; the second string is a server name,
  never client text. The Lua `t[zoneId]` has no guard for an out-of-range id, so the
  server must refuse before send.
- **No secrets/player data:** the note contains no player names or chat text; raw video
  frames stay in the lab.

## Checklist

1. **Refusal changes nothing.** No code; the build plan's (c)/(d)/(e) tests snapshot
   position, inventory and quest state before a refused teleport/packet and assert equal,
   with a canary. This note itself changes no state.
2. **Rollback covers all state.** N/A for the note; the plan derives region from the
   server pose and writes no transaction/save state.
3. **Apply deltas, never restore old snapshots.** N/A for the note; the plan never
   restores a captured snapshot over live inventory/coins/position; teleport uses the
   existing movement apply path.
4. **Busy rules are mutual.** N/A: the banner/chat is presentation, not a startable
   activity; it must not add a busy state. The plan does not touch `occupation.rs`.
5. **Every entry path is gated.** The plan's region lookup is called from movement, NPC
   menu/teleport, automatic/zone entry and reconnect, through the same function; no
   parallel path. Tests in (c)/(d) cover the real dispatch.
6. **Reachable in production, tested through it.** The note traces the real client
   readers and the server owners; the plan's tests drive gateway -> gameplay -> world, not
   a copied helper.
7. **Survives reconnect.** Region/place is derived from the saved position; no new
   persisted state. On reconnect the plan recomputes and sends the current banner/chat
   once; test in (d). No save ordering change.
8. **Every exit path restores.** No character state changes; a refused/failed teleport or
   dungeon entry leaves position/zone free; the plan tests win/cancel/disconnect/timeout.
9. **Economy safety.** N/A: no rewards, items, coins or client-reported outcomes; the
   banner/chat touches no inventory.
10. **Wire format matches the client reader.** The note cites the 47/9 reader
    (`0x00a8b360`, two strings) and the 15/2 reader (`0x00b10580`, one `u32`); the 47/9
    string semantics and 15/2 id semantics are explicitly `(R)` pending native check.
    Byte-level tests are required in step (d); no code in this diff.
11. **Unique ids.** The plan uses region ids 1..10 (1 is the default region, not an
    instance zone), unique place keys and unique instance zone ids outside 0/1..10, never
    aliasing the public world 0; test in (a)/(b)/(e).
12. **Others see changes.** N/A: banner/chat is per-player presentation; no outfit, job,
    mount or actor spawn change. No broadcast path is added.
13. **Content works end to end.** The plan asserts the final banner/chat/native entry, not
    an intermediate flag; this note records the data gaps (no POIs, 29 no-scene dungeons).
14. **Values live in data.** Shapes, priorities, cooldowns, grid size, banners and name
    ids live in `regions.json` with sanity bounds; no compiled gameplay constants in the
    plan except a documented grid default.
15. **Canaries break production code.** The plan's canaries change a real data row/bound
    or packet field and must fail the production test; no test-only copy.
16. **Hands off session plumbing.** No session creation/teardown/transaction/save ordering
    change; the plan only calls the existing movement/teleport entry. If a future builder
    needs session plumbing, it must end NEEDS-LEAD.
17. **One player's error never stops the server.** The plan returns `Option`/`Err` for an
    unknown region/place, logs a per-player refusal, and never `unwrap`s client data; test
    an invalid/overflowing id leaves the server and other players running.
18. **A type's rules live on the type.** The plan puts region/place membership, name id
    and banner id as methods/fields on `Region`/`Place` with doc comments; no inline
    special case in a caller.
19. **Hot paths stay cheap.** The plan uses a 10 m precomputed grid: one O(1) lookup per
    moving player, no allocation/clone when unchanged. Cost per tick is bounded by
    moving players, not by `players x shapes`; reload rebuilds the grid atomically.
