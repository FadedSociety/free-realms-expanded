## Systems and connections

- **Lua/client adapters (`00c17390-00c1b3d0`, `00c1b7c0-00c1b960`, `00c1c790-00c1f0a0`).** Callbacks cover camera auto-adjustment (`00c17cf0`), activity count and remaining time (`00c17f80`, `00c18000`), client flags and lookups (`00c18a60`, `00c1b310`), display-resolution parsing (`00c1b7c0`), and string conversions. `00c190f0` remains conservative: raw bytes show a converted value in ESI and a thunk call with no explicit push of that value. The sound-format-looking Lua callbacks (`00c1cbb0`, `00c1cd20`, `00c1ce60`, `00c1cf70`) lack an in-function SoundDefinition anchor and are described mechanically.
- **Travel and player packets.** `00c17bb0` calls the local POI validator/sender, which sends catalogue packet `PacketZoneTeleportRequest` (family 90). `00c1a5e0` constructs `PacketWorldTeleportRequest` (opcode 58, two GUID words). These are distinct client requests. `00c188f0` reaches `PlayerUpdatePacketRequestStripEffect`; `00c18c80` conditionally reaches `PlayerTitleRequestSelectPacket`.
- **Chat and command packets.** `00c1af80` routes changed channel-9 values through `00b97580`, which builds/sends `QuickChatSendChatToChannelPacket` (family 67) when its row/session guards pass. `00c1db80`, `00c1dc10`, `00c1dcb0`, and `00c1dd60` construct family-26 command packets with sub-opcodes 15, 30, 32 and 33. `00c1dc10` copies a structured record of three strings and three dwords, then stores a flag at object+0x98; it does not initialize one identifier. These constructors' send direction is supported by their gateway callers.
- **Activity launch (`00c1b160`, `00c1b1c0`).** The adapters parse then discard argument 1, use argument 2 to select an activity-list node, and call MemberQuit or MemberReady senders only when a node is found. The cited native review identifies `00c1b1c0` as `Ui.ReadyForActivity`, family 175/subtype 18, and distinguishes it from the conditional mini-game start 39/5 flow. The activity packet names are absent from the packet catalogue and the wrappers contain no opcode constants, so their `wire` arrays remain empty with that limitation recorded.
- **SoundGroup and SOE arrays (`00c1b490-00c1bb40`, `00c1bc10-00c1d5f0`, `00c1da10-00c1db60`).** `00c1b490` implements the replacement-buffer sizing policy; `00c1bd70` compares entry pointers and returns an index or -1. `00c1d2f0` releases matching entries and compacts the pointer array. `00c1db30` substitutes the current count for a negative index, conditionally updates external registration through `007cd920`, then delegates storage to `00c1dac0`.
- **GUI data-source checks (`00c1d710`, `00c1d7f0`, `00c1d8d0`).** Each performs an RTTI cast and returns its result. A requested failure path formats the shared mismatch string but passes it to `00821dd0`, whose body is only `return`; this range does not prove that the message is logged or displayed. `GuiDsTable` is a string argument, not evidence of an owning class.
- **UI logging (`00c1e7f0`, `00c1e910`, `00c1ea30`, `00c1eb50`).** All accept any positive argument count, use argument 2 as an optional category, ignore later arguments and log argument 1 at levels 5, 4, 3 and 2 respectively.
