   `test_location` restores guid/zone/pose/rotation, and one session exists. A

   save bytes do not change, and the owner still speaks.
2. `the_smoke_uses_no_dev_commands_or_roles` - the account role is `Player`
   (read from the account store); the flow sends only the ordinary login 1 /

   `budget_refusal` row and does not echo the character name, login ticket or
   the client's peer address.
3. `a_player_role_session_refuses_a_realm_command` - a real server running the
   existing opening play content (so the session loads a `Gameplay`) binds the
   account store's `Player` role through `select_character_from_login` /
   `bind_account_role`; a `realm give 10` chat is refused by the live session
   with the server's role-denial system line, records one
   `dev_command_denial` audit event, changes neither the pose nor the save
   bytes, and the session still speaks afterwards.
4. `a_bad_packet_or_abrupt_disconnect_ends_only_that_session` - a
   parseable-but-gross pose (10,000 units) is refused with the server's 38/12
   location message, changes neither the live pose nor the save bytes, and
   leaves the session alive. A truncated 125 body ends that session with a
   contained error and the save bytes stay unchanged. A fresh session then
   logs in, moves and speaks. Separately, a logged-in session's UDP socket is
   dropped while another session stays live: the abandoned session remains
   until the existing idle timeout (a relog of that character is refused and
   changes nothing), the server keeps stepping, the live session still moves,
   a new visitor session logs in and speaks, and shutdown writes every
   session's final deferred pose through the normal path.

## (R) rules and open gaps

- **No new (R) gameplay rule.** The test drives existing reconstructed rules;
  the only values it adds are synthetic fixture strings, a synthetic pose and
  the test's own connection ids.
- **(R) In-process harness has no trace sink.** `Server::new(Options)` does not
  accept a trace and `Server.trace` is set only by the binary's `run()`. The
  brief allows the fallback: the test asserts the real server/session flags and
  the absence of a refusal reply instead of `rejected` rows, and uses the
  security log for the developer-command audit.
- **The role gate is exercised through the real session (F391).** A no-content
  gateway session deliberately has no `Gameplay`, so
  `a_player_role_session_refuses_a_realm_command` starts a server with the
  existing opening play fixture (`tests/support/npc_quest_chain.rs`; no new
  content authored) and sends `realm give 10` as an ordinary 15/1 chat. The
  refusal therefore proves `select_character_from_login` ->
  `bind_account_role` -> `Gateway::refresh_role` -> `Gameplay::may_run` on the
  live session, not a separately constructed predicate. Cost is the fixture
  copy/load (~6 s) in that one test.
- **Abrupt-drop reaping is the existing 60 s idle timeout.** On Windows the
  server does not see a closed UDP port immediately (the existing
  `a_vanished_client_does_not_stop_the_server` pins this), so this test does
  not wait 60 s. It asserts the abandoned session is still present (two
  sessions, and a relog of its character is refused and changes nothing), the
  server keeps stepping, the live session still moves, a new session logs in
  and speaks, and shutdown writes the abandoned character's deferred pose.
- No native client run; the session is lead-controlled. This slice is
  server-side and test-only.

## Security threat note (secure-code-guardian)

- Surface: the test is a hostile-client-shaped driver of the real server (SOE
  handshake, login, movement, chat). It sends only fixed synthetic values:
  no user names, no chat logs, no environment data.
- What a hostile client could send and why it is refused (existing production
  rules, asserted here where applicable): a movement body with a non-finite or
  over-`1_000_000` coordinate is refused by the gateway reader (that refusal
  ends the session with a contained error, as test 4 shows); a parseable but
  gross pose is refused by `movement::validate` and answered with the server's
  own 38/12; a truncated 125 body is refused and contained; a duplicate login
  or an abandoned session's relog is refused before the save is read or
  written and cannot take over the live session; a `Player` role with dev tools
  off cannot run `realm give 10` on the live session (refused, audited, and
  changing neither pose nor save). Chat is the ordinary 15/1 budgeted path; the
  ordinary-flow test shows no developer-command denial, budget refusal, name,
  ticket or peer address in the log, while the role test shows exactly the
  expected `dev_command_denial` row.
- No new parser, save, coin, item, reward, role, chat, session or gateway code;
  no secret, key or name is written to code/notes. The account fixture uses the
  existing synthetic names from `tests/multiplayer.rs`, not a player's.
- Refusals change nothing (item 1): the test asserts save bytes and live pose.
