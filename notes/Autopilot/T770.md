# T770: Card Duelist card service listener (lead build, security)

The card window (`tcg/FreeRealmsTCG.dll`) talks to its own TCP service. T770 gives the gateway that service.

- `src/bin/osfr_gateway/card_listener.rs`: a TCP listener on the gateway's own address (loopback, or the private
  address `--allow-lan` admits). It answers the unrouted 414 `GetConnectionServer` with this listener's host and port,
  and the routed 411 login with an 81 result. The login's launch ticket and character id are redeemed once in the live
  session of that character (`Gameplay::redeem_card_ticket`, T764/T765), so a login needs the 64-bit ticket the
  server sent that character in 39/0x28, before it expires. The 81's account id is the character's low 31 bits (R).
  Commands after login are logged (`card_command_unhandled`, at most 16 per connection), not answered yet.
- Limits (R): 16 connections, 4 per address, 30 s to log in, at most 64 KiB read per poll, frames over 64 KiB or
  malformed close the connection. A refused login keeps the connection until the deadline.
- The port lives in the card content's `launch` block (`port`, 0 or absent = off). The shipped `card_game.json` still
  has no launch block, so card rows keep saying the game is unavailable until the lobby and duels exist; native runs
  turn it on in their content package and point the client's `tcg/host.svr` at it (`ghost <ip>`, `gport <port>`).
- Hub cost: the module declaration, one field, the open call and one poll call in `osfr-gateway.rs`;
  `Gateway::gameplay_mut` for host services.

Tests (`cargo test --bin osfr-gateway card_`): the 414 comes back with this listener; a login is accepted only for
the ticket redeem names (a refused one sends a failed 81 and keeps no character); a silent connection closes after the
deadline; one address holds at most four connections; an oversized frame closes the connection; the server refuses a
login for a character with no live session.

Threat note: a stranger on the network can open at most four sockets that close within 30 s unless they present a
live one-time ticket, which only the character's own session receives. Nothing here writes a save.
