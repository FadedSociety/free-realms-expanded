## Threat note

A hostile client controls the runtime NPC id in 26/8/26/10, the menu entry in
26/10, the row value in 26/6, the quest id and accept flag in 49/2, and the
quest id in 49/14. The production route refuses rather than trusting any of
them:

- The NPC id must resolve through the server's `NpcVisibility` content-key
  binding; unknown ids return `Ok` with no menu. The NPC must be in the same
  zone or the open-world zone and within the existing 12 m interaction radius.
- The 26/10 entry must be an option in the currently opened server menu. Any
  other id returns `Err`, and the test proves the open menu is not consumed by
  selecting the valid option afterwards.
- A `26/6` row can only release a server-created `pending_quest_choice`; no
  other row value grants an offer or an end screen.
- `49/2` accept is valid only when it matches `pending_offer` and the server's
  eligibility/prerequisite checks; `49/14` is valid only when it matches the
  persisted `pending_turnin`. The payout is the server-authored five coins from
  content, under the existing idempotent `quest:<character>:<quest>` grant key.
  Forged and replayed packets leave the whole `GameplayState` byte-equal.
- Malformed lengths are errors; every test refusal is checked with a
  before/after state comparison. The tests do not assert an exact error string.
