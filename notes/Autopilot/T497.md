## What changed

- New `src/job_browser.rs`: loads `data/content/job_browser.json` (12 Become-a rows), builds the 147/1 packet once at
  bind (`encode`), and returns the original-to-regional entries for the 49/15 crosswalk.

- `src/quest_journal.rs`: a 49/15 whose id is 0 or negative decodes to `Breadcrumb { quest_id: 0 }` instead of
  `Malformed`, so `translate` finds no crosswalk entry and `npc.rs` answers `BREADCRUMB_REFUSED`. Before, `Malformed`
  became an `io::Error` that ended the session. A wrong-length 49/15 and 47/12 with a bad id stay `Malformed`.
  `read_crosswalk` returns the file's listed originals too; `load_crosswalk` wraps it.
- `src/gameplay.rs` (hub): one field `job_browser_packet` plus its initialiser, +3 lines.
- Tests: new `tests/job_browser.rs` (8), `tests/quest_journal.rs` updated (two ids moved from the malformed list, one new
  test), checked-in capture `tests/fixtures/job_browser/op147-sub1-capture.bin` (434 bytes, sha256 ab3ec4f7...712d3e).

## Threat note (49/15)

A hostile client can send any i32 in 49/15. Wrong length is refused as before (session error, existing behaviour). 0, -1
and `i32::MIN` now get the refusal chat line and change nothing (tested, save byte-equal). A positive id the crosswalk
does not list, or whose regional quest is disabled, gets the same line and changes nothing (tested). A mapped, enabled
id only makes the regular 49/1 offer through the engine's own gates; nothing is awarded. The 147/1 packet is static data
loaded at bind, carries no player state, and is bounded (64 rows, 64 KiB, ids 1..=i32::MAX).
