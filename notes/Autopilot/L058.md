# L058: new names accept every length the creator's picker offers (lead)

Native run `lab/runs/client-baseline-20261022T143820Z` (tip f7d0abe) picked "Jessica Grittycandle" (7 + 12) in
the creator. Check-name answered 5 (TotalLengthInvalid), and the client showed locale 432109
(`client/Logs/ClientAccountManager.log` lines 28-37). The cause was the 2026-10-15 rule "first + last <= 15".
The picker builds names up to 11 + 16 = 27 letters, so about 54% of picker combinations were refused.
Picker last names of 15-16 letters also hit "last <= 14".

## What changed

- `src/account.rs`:
  - New constants `MAX_FIRST_NAME_CHARS = 14` and `MAX_LAST_NAME_CHARS = 16`, with the client evidence
    cited in their doc comment. Both are (R).
  - The combined cap is removed.
  - The length and letter rules that `valid_client_name` (create) and `check_name_status` (check-name) each
    copied now live in one function, `name_shape_status`. It is the old `check_name_status` body without
    the combined cap and without the taken check. `valid_client_name` is `name_shape_status == Available`.
    `check_name_status` adds Taken only on Available, so the answer order is unchanged: length, then
    Invalid, then Taken.
  - `NameCheckStatus::TotalLengthInvalid` stays as the client's code-5 row (like Profane and ServerFailure,
    which are also never produced). It now has a doc comment saying so.
- `tests/account.rs`:
  - Two new tests (below).
  - `name_check_and_create_return_client_status_codes`: the 16-letter "too long" sample became an 18-letter
    one, and the combined-cap assertion became a code-5 mapping assertion.
- `tests/login.rs`: one new test drives check-name (opcode 16 / 210) and create (opcode 5) through
  `LoginService::handle`. It puts the pick in the temporary pair, as the client does.

Unchanged:
- the L049 rules (`new_name_part`, `identity::valid_name`, folded uniqueness);
- the 2-letter minimum;
- every wire reply and status code;
- `login.rs`, saves, `CharacterIdentity::validate`.

Reading of the evidence:
- The only per-part numbers the client states are for *Custom* names (under 15, so 14).
- The only combined number (432109) is a *minimum* of 15. The picker's own 9-letter names break it, and
  the brief reports "Jayda Auraheel" (13) going through in the same session. So no client number supports
  a combined cap. Code 5 is left unproduced.
- First stays 14: the custom limit, above every picker first name.
- Last becomes 16: the custom limit raised to the longest picker last name.

## (R) choices

- `MAX_FIRST_NAME_CHARS = 14`, `MAX_LAST_NAME_CHARS = 16`, no combined cap. The original server's checks are
  unknown. These are the smallest limits that admit every picker length and keep the client's custom limit
  where the picker allows it.
- A typed (custom) last name of 15-16 letters now passes, although 432096 says custom parts must be under
  15. The server cannot tell a typed name from a pick:
  - create (`NativeCreation`) carries no glossary ids;
  - check-name's three definition strings are read and dropped in `login.rs`.
  This build's creator never sends the typed field outside China mode (Next sends the wheel slots), so only
  a modified client can send a typed 15-16 letter last name. A stricter rule needs the server to resolve
  picks against the catalogue (`restoration::piece_050::NameCatalogue`, unregistered). That is a design
  decision; see Open gaps.

## Security

Threat note (secure-code-guardian, security-reviewer):

- **Hostile client input.**
  - Check-name strings are bounded at 128 bytes each by the reader (`login.rs` opcode 16). Creation strings
    are bounded by `NativeCreation::decode` (128 each).
  - The new limits only widen the accepted length window, from at most 15 letters in total to at most
    14 + 16. Every name still passes `identity::valid_name` (at most 32 characters and 128 bytes, trimmed)
    and `new_name_part` (Latin letters, single separators).
  - Lengths count characters, not bytes. The test checks 16 two-byte `é` letters pass and 17 are refused.
- **Look-alike and impersonation.** Uniqueness is unchanged: `character_name_taken` and `name_key` folding
  run on both pairs. `name_key` now runs on at most 16 characters per part (was 14), still bounded.
- **No new oracle or enumeration.**
  - The reply codes are the same set.
  - Over-limit parts are still answered 9/10 before any taken lookup. Invalid still comes before Taken
    (L049 order).
  - Check-name already says taken or available for any name in the window; a wider window adds no new
    kind of answer.
  - Timing: one more `match` arm, no new I/O.
- **Refusals change nothing.** `create_character` returns before `insert_character` on every refusal. The
  login path stages on a reloaded clone and saves only on Created (L055). The new over-limit test refuses
  four creates (display first 15, display last 17, temporary first 15, temporary last 17) and asserts
  `store == before`.
- **Saves stay atomic and loadable.** The save path is untouched (`AccountStore::save` → validate →
  `replace_bytes`).
  - Saved names now reach 14 + 16 letters, inside `CharacterIdentity::validate` (32 characters per part).
  - Downstream name buffers hold: `player_radial` truncates the full name at 64 bytes, and 30 letters of at
    most 2 bytes plus a space is 61. `social_chat`/`social_lists` bound name parts at 128 bytes.
- **Logs and secrets.** No logging added or changed. No keys or names in logs.

## Open gaps

- **Native check after merge:** the picker's default and Random names, including a 15-16 letter last name,
  should be accepted.
- **Trailing-space catalogue rows (pre-existing, not changed).** Four first names are stored with a trailing
  space: `Mei `, `Mia `, `Max `, `Tom `.
  - L049 already noted that `identity::valid_name` refuses a padded part.
  - `sub_70CC80` splits the composed name at the first space (`sub_706720(…, 32)`). Whether the client
    sends `Max` or a padded part is not verified.
  - The brief leaves the L049 rules as they are, so this needs a native pick of one of these four.
- **Custom versus pick (design, for the owner or the lead).**
  - Enforcing the client's "custom under 15" while still admitting 16-letter picks needs the server to
    verify picks against `CharacterCreateNames.txt`, for example by registering `piece_050::NameCatalogue`
    and keeping the check-name definitions.
  - Create carries no definitions, so this would also need a catalogue lookup by name.
  - Not done here.
