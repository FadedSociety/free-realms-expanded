## Reconstructed rules (R)

- Buy-back quantity zero means all units still outstanding; partial quantity is limited to the
  recorded remainder. Buy-back price is the sale's unit price times the restored quantity.
- A session retains the configured number of recent sales. The default remains ten and the
  configured maximum is 100.
- Uncapped catalogue delivery is not performed. Uncapped requested 35/37 payloads are split at
  60 KiB; the item decoder bounds one row to 65,536 bytes, so an oversized single row is sent alone.
- Station Cash, gifts, wallet funding and paid orders remain refused or empty.

  - A hostile 165/2 can send up to 4,096 arbitrary, duplicated or undefined ids, and can repeat
    the request in up to 128 bundle children. Malformed or oversized lists get one empty
    incomplete 165/3; more than 4 MiB of requested records gets the same answer before any row
    is copied; a bundle over 8 MiB of replies is refused with the outbound-budget error and is
    not committed.
  - 165/4, 165/5 and 165/12 validate the merchant, shop-open state, owned instance, quantity,
    remainder and server-side price. The client's price and reported result are ignored.
  - Free gifts, Station Cash, wallet funding and orders stay refused or empty, so the reply
    paths cannot mint coins or items.
  - Limits: 4,096 ids, 4,096 tracked client transactions, 65,536-byte row, 32 MiB catalogue,
    60 KiB batch, 4 MiB single definition answer, 8 MiB bundled reply budget, buy-back window
    default 10 with an accepted range of 1..=100.

## Checklist

1. **A refusal changes nothing.** Malformed, oversized and unknown-id 165/2 cases assert
   `counter.state()` is unchanged in `item_definitions_are_answered_from_the_item_catalogue`;
   no-shop and malformed buy-backs assert the gateway snapshot in
   `gateway_buy_back_refusals_answer_the_client_and_change_nothing`; the rejected bundle test
   `gateway_bundle_failure_rolls_back_buy_back_history` keeps the sale history and snapshot.
   The partial buy-back canary changed production behavior and failed the test.
2. **Rollback covers all state.** `CoinShop` is an inline `Option` in `Gameplay`
   (`gameplay.rs:202`), so cloning `Gameplay` stages inventory and the sale deque together; no
   `Rc`, `RefCell`, `Arc` or side table escapes the transaction. The bundle-failure test proves
   it for buy-back history.
3. **Apply deltas, never restore old snapshots.** `src/gameplay/npc.rs` calls
   `shop.sync_inventory(self.inventory.clone())` before each shop request, so the shop starts
   from live coins/items. Buys and sells stage a modified copy of the live state, and buy-back
   removes the outstanding quantity and grants the restored amount.
   `an_unaffordable_buy_back_keeps_the_sale_available` syncs live coins after the sale and
   proves the retry sees them; the ignored `w95_vendor_coin_store_regressions` covers a
   post-login reward when private play content is available.
4. **Busy rules are mutual.** No activity was added. The coin shop is an NPC service gated by
   the open interaction; it does not enter the `Occupation` table, so there is no new busy
   state to check against encounters, crafting, gathering, minigames, kart or trade.
5. **Every entry path is gated.** 165/2, 165/8 and the Marketplace reads are session-free
   read-only requests (tested with no shop open). 165/4, 165/5 and 165/12 pass through
   `NpcInteraction::handle_coin_store`, which checks the open merchant/range before the shop is
   called; the no-shop refusal is in the gateway buy-back test. The definition budget lives
   inside the single 165/2 handler both callers reach.
6. **Reachable in production, tested through it.** The gateway tests send tunneled application
   packets through `Gateway::handle_at`:
   `gateway_definitions_list_update_and_gifts_are_answered_without_state_change`,
   `catalogue_only_definition_is_delivered_before_the_coin_store_ack`,
   `gateway_sell_then_buy_back_once_then_replays_pay_nothing`.
7. **Survives reconnect.** Sale history is still session-local and is listed above as an open
   gap; this change does not claim persistence. Definitions are content, and no new saved field
   was added, so there is nothing else that must survive a reconnect.
8. **Every exit path restores the player.** Shopping never moves or locks the character.
   `buy_back_keeps_the_open_shop_and_range_checks` covers closed-shop and range refusals; the
   shop stays open for a valid retry and no activity state exists to restore.
9. **Economy safety.** Buy-back restores at most the recorded remainder
   (`partial_buy_back_consumes_only_the_requested_quantity`), charges the sale's unit price, and
   refuses an unaffordable restore without consuming the sale. Selling only touches owned,
   non-rental, non-consumed/non-stored copies; prices come from stores.json. Gifts stay refused.
10. **Wire format matches the client reader.** 165/2 is `i32 count` plus `count x u32`
    (`00c75580`, `00c75620`; sender `00c76b10`); 165/3 is `u8 complete`, `i32 count`,
    `count x u32` (`00c74e40`, `008e8230`); 165/13 is three dwords after the header
    (`00c71e40`); 165/6 is the 56-byte record read by `00c71f30`. Readers were rechecked with
    IDA on 2026-10-18. `parse_definitions`, `parse_definition_batch` and `parse_completion`
    assert exact sizes with no unread bytes.
11. **Unique ids.** Buys use the allocated per-shop transaction id; buy-back reuses the sale's
    original id and the client's request id for replay detection. No instance or lifecycle ids
    are allocated by this change.
12. **Others see changes.** Not applicable: shop inventory, sale history and definition
    answers are private to the requesting player; no actor, outfit, mount or job state changes.
13. **Content works end to end.**
    `catalogue_only_definition_is_delivered_before_the_coin_store_ack` asserts the generated
    35/37 row precedes the 165/3 acknowledgement;
    `sell_then_buy_back_once_restores_the_stack_and_the_exact_coins` asserts the item and coin
    outcome.
14. **Values live in data.** `buy_back_window` is read from stores.json with a default of 10
    and a 1..=100 sanity range (`buy_back_window_is_bounded_store_data`). The new definition and
    bundle caps are protocol/memory limits, not gameplay tuning.
15. **Canaries break production code.** The partial buy-back canary (always restore the full
    remainder) changed `coin_shop.rs` and failed
    `partial_buy_back_consumes_only_the_requested_quantity`; it was reverted. The F144 budget
    canaries changed the production constants and failed their regressions before reverting.
16. **Hands off session plumbing.** No change to `src/bin/osfr-gateway.rs`, session creation or
    teardown, save ordering, login, transport or account modules. F144's only gateway change is
    a reply-budget check inside `handle_at`.
17. **One player's error never stops the server.** An over-budget 165/2 returns `Ok` with a
    refusal packet; an over-budget bundle returns `Err` from `handle_at`, which the server step
    turns into `end_session` for that one player. No shared-tick or cross-player work changed;
    the existing `osfr_gateway/isolation.rs` tests remain the isolation evidence.
