## How the dance-off gate is reused

`world_events/schedule.rs` starts a scheduled event only when
`ClientAreas::is_season_active(name, slot_start_ms)` is true; the shipped
`halloween_dance_off` row names `"season": "Halloween"`. `NpcVisibility::season_shown` calls the
same `ClientAreas::is_season_active` for each tagged row at the wall clock, and the boundary
signal reaches the gateway tick through the same `ClientAreas` instance. So the NPCs appear and
disappear on exactly the season clock the dance-off uses; there is no second schedule, flag or
copy of the season dates. Inside its season the event NPC is present all season (the retail
event window); the dance-off's own actors are the part of that event that exists only for its
10-minute slot.

## Security threat note (secure-code-guardian)

- A hostile client can send 26/8, 26/10, 45/7 or 49/x for the runtime GUID of an out-of-season
  actor. `content_key` first requires the row to be shown, so the actor has no content key and
  the router's existing unknown-guid refusal answers without opening a menu or changing state.
  `actor_position` (the click-reach check) is also `None`, and `marker_targets`/`model_of` never
  expose the row.
- No packet, save or command carries a season: the only season inputs are server content
  (`client_areas.json` and a row's `season` key) and the server wall clock. A client cannot
  choose or move the clock.
- An unknown season tag fails closed: the play-time load returns `Err` naming the spawn guid
  before a table exists, so it can never draw the row. A missing `client_areas.json` means "no
  seasons", so a tagged row refuses the load rather than silently showing all year.
- The removal diff is server-driven through the existing 35/3 path; the admin commands, saves,
  coins, items, roles, chat and trade modules are untouched.

## Checklist

1. **Refusal changes nothing.** No client-facing transaction was added. An out-of-season actor's
   click is refused by the existing unknown-guid path (`content_key` None), and the new test
   asserts it has no position, model or content key; a malformed/typo season refuses the whole
   content load before a table exists (protected T491 test asserts the plain `load` table is
   unchanged). Canary above breaks the gate and fails the season suites.
2. **Rollback covers all state.** The table lives in `NpcVisibility`, inside the per-player
   `Gameplay` clone; no `Rc`/`Arc` side table escapes a refused transaction. The season table is
   an `Arc<ClientAreas>` shared read-only, as the earlier load-time rule was.
3. **Apply deltas, never restore snapshots.** A boundary changes only the row-visibility decision;
   the remover re-diffs the live `known` set and sends 35/3 per guid. No inventory, coins or
   position is copied or restored. Test: `after == wanted - pumpkins`, the untagged neighbours
   stay.
4. **Busy rules are mutual.** N/A: passive NPC content, no activity start/stop. `occupation.rs`
   is untouched.
5. **Every entry path is gated.** The shared view, per-session update, interaction key, marker,
   scene-fixture, teleport and ambient model readers all call `season_shown`/`shown`; the only
   season input is server content plus the server clock. The synthetic-package test asserts the
   model, position, content key, marker target, teleport target and scene-fixture row are all
   absent outside the season and present inside it. A reconnect rebuilds the table at the
   current clock (test: `load(HALLOWEEN_OVER_MS)` is disjoint).
6. **Reachable in production, tested through it.** Production loads through
   `Gameplay::load -> NpcVisibility::load_in_season`; the gateway re-diffs through
   `Server::sync_field_views -> Gameplay::shared_npc_view -> NpcVisibility::shared_view`.
   `tests/seasonal_npc_clock.rs` drives `shared_view` and `update` on the real shipped rows; the
   gateway trigger is driven through the real `season_tick` in `client_area_routing`.
7. **Survives reconnect.** Nothing is saved; every login recomputes from the clock. Test:
   reconnecting after the season sends none; the returning season re-adds them.
8. **Every exit path restores the player.** N/A: no player state changes; a session that leaves
   or re-enters gets the ordinary 35/2/35/3 reconciliation. Sessions in another instance are
   refreshed when they next load/update the open world.
9. **Economy safety.** No item, coin, reward, quantity or ownership path is touched. The actors
   are passive props/merchants; out-of-season they have no content key, so no shop or quest menu
   can be opened.
10. **Wire format matches the client reader.** No new packet. AddNpc body [35,0,2,0], reader
    `0x00921a10` (`sub_921A10`); removal [35,0,3,0] submode 1 with the u16 count then the u64 guid,
    reader `0x008d69f0` (confirmed by decompiling `sub_8D69F0`: it reads the u16 then the two
    dwords) and `0x008d6a60`; encoder `encode_remove_gracefully`
    (`restoration/piece_056.rs`) has the same layout. The test parses the bytes at those offsets.
    The client has no season field, so the tag never reaches the wire.
11. **Unique ids.** No id is created or reused; the 14 rows keep their Legacy/Sanctuary GUIDs and
    the test pins them uniquely.
12. **Others see changes.** Every viewer's shared diff is rebuilt from the same wall clock at the
    boundary; the trigger is server-side, so no path aliases one player's decision. The gateway
    test asserts every loaded open-world session is forced; the NPC test asserts one nearby
    viewer's removals.
13. **Content works end to end.** The shipped rows are tagged and drawn inside their season and
    absent outside; the final outcome is asserted on the real AddNpc bytes, not a flag.
14. **Values live in data.** Season names and windows stay in `client_areas.json`; tags are in
    `npc_spawns_extra.json`. No season name or date is compiled in the source; only fixed test
    clocks use constants.
15. **Canaries break production code.** The canary changed `season_shown` (production), not a
    test; 3 tests failed; reverted; rerun green.
16. **Hands off session plumbing.** `src/bin/osfr-gateway.rs` and `gateway.rs` are untouched; the
    tick module only clears the existing `npc_visibility_revision` field (no creation, teardown,
    transaction or save-order change).
17. **One player's error never stops the server.** The tick change runs inside the existing
    `season_tick`; a full queue in one session is logged and skipped (`client_area_send_failed`),
    and the shared view path already logs per-viewer rate errors. No new `?` leaves `step`.
18. **A type's rules live on the type.** `VisibleNpc.season` documents the show-only-in-season
    rule; `NpcVisibility` owns `seasons`/`season_clock`, `season_shown`, `validate_seasons` and
    `set_season_clock` with comments; `ClientAreas.season_changed` documents the boundary rule.
    Placement/static actors still set `season: None` with the T491 comment.
19. **Hot paths stay cheap.** See Cost per tick above; a boundary forces one re-diff, an unchanged
    view is still skipped, and no state is cloned per tick.
