# L075: public realms (port forwarding and server hosts)

Owner 2026-10-30: "switch the launcher to allow setting up a server with port forwarding ... so players can set it up on
server hosting sites to run a server long term". Lead build, lead-only files (login, gateway hub).

## Change
- `src/net_policy.rs`: `bind_allowed(bind, allow_lan, allow_public)` opens the wildcard bind (0.0.0.0 or ::) only with
  `--allow-public`; `admits(bind, peer, allow_lan)` admits every peer on a wildcard bind, else the existing rule.
- `osfr-gateway --allow-public`: may bind 0.0.0.0 (still account-store mode, never `--dev-tools`, the existing exposed
  rule); UDP peers and portrait uploads (TCP on the gateway port) follow `admits`.
- `osfr-login --allow-public --advertise <public IP:port>`: login and broker may bind 0.0.0.0; `--advertise` is the gateway
  address handed to every non-loopback player (behind port forwarding the router's public IP); loopback players (the
  host's own client) keep `--gateway`, so a router without NAT loopback still lets the host play.

## Security (lead)
Security Model decision 2 (2026-10-16) kept public addresses closed; the owner opened them for hosted realms. Unchanged
protections: key-pair login (AUTH2, no password on the wire), server identity pinning in the launcher, one-use expiring
handoff tickets (L3), per-IP and global admission buckets (L6), enrollment caps (3 claims an hour per address, 64
accounts) and the whitelist, `--dev-tools` refused on any exposed bind. The legacy wire stays unencrypted (fixed client),
as the original game ran. Remaining Security Model items I11/I12 (amplification measurement, handshake cookie, gate runs)
stay open on lead-queue 4k.
