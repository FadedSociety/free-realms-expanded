## Security threat note (secure-code-guardian)

Attack surface: family-40 40/1/40/4/40/5 packets from any authenticated
client.

- **Replay across a restart.** A client holds the 40/1 pop-up while the server
  restarts, then the leader re-invites the same target. The process-random
  base makes the held token a mismatch with probability about 1 - 2^-32; the
  stale 40/4 is refused with 40/5 code 3 and changes no live row or
  membership (F203's restart test). The base is not a cryptographic secret
  and the token is not used as one: it only distinguishes pop-ups, and an
  attacker who can guess or replay it must already act as the authenticated
  target.
- **Forged token.** A 40/4 carries any client u32. The server compares it to
  the single pending row for the session's authenticated character guid; a
  mismatch, zero, another invitation's token or a truncated body is refused.
  The client guid is never taken from the packet.
- **Full roster.** The 40/5 code-2 refusal runs before the row is removed, so
  a hostile client cannot make the server consume a valid replacement and
  then report a refusal. There is no item, coin, XP, role or chat effect.
  Canary D moves the check back after the removal and the snapshot test
  catches it.
- **Amplification.** Each refused 40/4 produces at most one 40/5 reply to the
  sender; no 40/4/40/8/40/9 fanout occurs on a refusal.
- **Arithmetic.** `next_invite_id` advances by one with wrapping addition and
  `.max(1)`, so zero is never emitted. No client value is used in arithmetic.
  The generation is volatile; group ids remain a separate counter.
- No chat budget was changed (lead note L016).
