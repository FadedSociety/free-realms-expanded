  - a temporary copy of the real `quests/`, `npcs/` and `jobs.json` with an

  - the content table pins all 12 `job_xp` maps, the 7 job gates, the `(R) T202:`

## Verify-first observations

- Reward merge: `quest_engine.rs` `definition_from_content` sums rows with
  `checked_add(u32)` and `rewards::apply_grant` stages a clone. Before this
  slice the loader rejected a single `job_xp` value above `i32::MAX` and an
  unknown profile id was not checked at all; an over-budget multi-entry map
  loaded and failed only when the end-screen bundle was encoded.
- Eligibility: `CharacterEligibility.job_levels` is built by
  `gameplay/npc_quests.rs::character_eligibility` only for the **active**,
  already-unlocked profile. `QuestEngine::offer_denial` checks prerequisites,
  level and then the job gate. `QuestEngine::accept` rechecks
  `requirement_denial` (unless this is the developer `realm offer` override).
- Turn-in: `QuestEngine::finish_turnin` does **not** recheck the job. The
  content map is explicit, so a player who accepted as Ninja and switched to
  Brawler is still paid profile 2; `xp_follows_the_quest_job_not_the_active_job`
  asserts that observed behavior.
- Profile ids in `jobs.json`: Adventurer 1, Ninja 2, Chef 45, Kart Driver 48
  (Brawler 43 is used only by the disabled `3000009` and by the job-switch
  test).
- `scripts/content_check.py` validates a quest's `job` field against
  `jobs.json` but does **not** validate `reward.job_xp` at all (no `job_xp`
  string exists in the script). The authoritative split loader now performs
  both missing checks; `--strict` remains at 0 errors.
- The shipped content files use CRLF; all four were rewritten with a JSON
  round-trip that preserves indentation and adds only a final CRLF. A
  structural comparison against `HEAD` shows exactly the 12 intended records
  changed.

## Client evidence (IDA, 2014 client)

Queries were run with `lab/autopilot/ida_query.py` against the pinned database;
every opcode/field this slice relies on was checked against the actual reader.

- `decompile 0x008e7930` — reward-bundle reader: success byte, then the coin
  dword, the displayed-XP dword, two more dwords, reward kind, two dwords, the
  float multiplier, two dwords, source/player `u64`s, icon/name/row-count
  dwords, the row loop (each row is a type id then an entry reader) and a
  trailing i32. `rewards::encode_display_bundle` /
  `quest_engine::encode_quest_reward_bundle` already match this layout; the XP
  values now written there are summed from `job_xp`.
- `decompile 0x00a86400` — 49/2 `QuestReplyPacket` constructor stores the quest
  id in the first body dword and the accept byte at `+16`; the test uses
  `u32 quest + u8 accept`.
- `decompile 0x00a864c0` — 49/14 `QuestEndReplyPacket` constructor stores one
  quest id in the first body dword.
- `decompile 0x008d86e0` (38/14) — reader consumes six dwords after the old
  header: profile, rank, progress, three zero dwords. `decompile 0x008d8910`
  (38/18) consumes profile and rank. `rewards::experience_packets` is
  unchanged and matches.
- `decompile 0x00c7b990` (49/13 `QuestEndPacket::ReadFields`) — base reader,
  then an 8-byte actor pair, three dwords (quest id, end text, animation),
  `sub_8E7930` for the reward bundle and a trailing dword. This confirms the
  test's speaker at 6..14 and quest id at 14..18.
- `decompile 0x00c7b7a0` (`QuestInfoPacket` body reader reached through
  `00c7bb60`) — the first body dword is the quest id at wire offset 6..10.
- `find 'Rank|Progress|Experience|JobLevel|Profile'` returned only two mangled
  Chess symbols; the named functions above were located from the existing
  native map addresses and decompiled directly. No IDA statement contradicted
  the existing notes or code.

## Security threat note (secure-code-guardian)

- Attack surface: a hostile client can send 26/8, 26/10, 26/6, 49/2, 49/14 and
  49/15 at any time. No new parser, selector, packet family or client-supplied
  amount was added.
- The job gate is server-side: `job_levels` comes from the saved active profile
  and its unlocked flag, never from the client. Forged 49/2 accepts for an
  unoffered/gated quest are denied and change nothing; a gated offer is not
  returned by the 26/6 choice.
- Turn-in remains gated by the open `pending_turnin` (set only by server Talk
  events) and the existing reward grant key
  `quest:<character>:<quest>`. Replayed 49/14, replayed 49/2, wrong quest and
  missing objective do not pay or mutate.
- XP/coins come only from content rows; no client amount or item id is read.
  The three new zero-coin rows grant no item, so there is no free item to sell
  or re-grant. `apply_grant` still refuses a locked profile.
- The loader now rejects bad content at bind time (profile id and i32 total),
  so one bad authoring value cannot become a runtime error for a live player.
  The validation is fail-closed and returns `InvalidData`; no
  `unwrap`/`expect` on content values was added.
- Range, zone, open-menu, prerequisite and save-before-send behavior is the
  existing NPC/quest path; the tests assert the refusal leaves the save bytes
  equal.

## Skill review

- **Ponytail (full).** Reused the existing `QuestEngine` reward merge,
  `RewardState`/`apply_grant` transaction, job eligibility map, NPC router and
  grant key. The
  smallest production change is the two checks in the loader that the brief
  assumed already existed; no second reward path, flag or abstraction was
  added. Content stays data-driven; the only test fixture change promotes the
  captured default outfit so the Kart/Ninja job switch can pass the client's
  Chest/Legs gate.
- **ponytail-review on this diff.** The new test file is self-contained rather
  than sharing the Medic/Archer harnesses, because those constants, profiles and
  fixtures are job-specific; a generic harness for one user would be YAGNI. The
  review pass cut the single-use `profile_state`/`base_state`/`has_dialogue`
  helpers, the unused `Outcome` return of `assert_no_change`, and the unused
  `Outcome` returns of `offer`/`accept` (net −18 lines possible, applied). No
  unused helper or speculative config was left.
- **secure-code-guardian.** Threat note above; the loader is now fail-closed and
  every refusal has a save-equality assertion.
- **Principles applied:** model-the-domain (the explicit content `job_xp` map is
  the source of truth; the active job is not inferred at payout),
  subtract-before-you-add (one stale assertion removed, no parallel path),
  test-behavior-not-implementation (all tests drive packets, not `QuestOutcome`),
  make-operations-idempotent (duplicate 49/14 and relog replays),
  minimize-reader-load (the validation sits where definitions are built).
