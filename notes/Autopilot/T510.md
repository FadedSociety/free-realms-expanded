# T510: item bar schema-2 effect rows (food auras, transformation treats, size effects)

Skills applied: **Ponytail (full)** — the smallest change that reuses the existing bar, effect
stack and hook; no new abstraction or dependency; the ponytail-review pass was run on the final
diff (no line cuts worth making; `Effects::rows`/`Effect::spec` are the minimal content-gate
surface T511 needs). **secure-code-guardian** — threat note below.

## What changed

- `src/item_bar.rs`: `consumables.json` schema 2 rows (`definition`, `name_id`, `description_id`,
  `cooldown_ms`, `single_use`, `effect`, `source`) with four effects (`heal`, `aura`, `transform`,
  `scale`). Schema 1 still loads (same potion-only shape; names/descriptions from the recovered
  catalogue). Bounds: 512 rows, 256 KiB file, cooldown <= 86_400_000 ms, durations
  1..=86_400_000 ms, unique positive definitions/name/description/icon ids, heal 1..=100, stack
  scale/delay bounds. The `use_wire::consumable` gate is replaced by a row lookup for slots, the
  42/16/42/15 route and the 42/16 confirmation text. The effective cooldown is
  `max(row, 3_000)` in every consumer, including the 38/25 `total_refresh_time`. `Reply` gains the
  non-heal `effect: Spec`; `Player` gains `can_heal` and `transformed`.
- `src/consumable_effects.rs`: the pure admission check is now `pub fn admits(&Spec)` and
  `EffectStack::admits` delegates to it, so the item bar can run the same check before spending an
  item; added `has_transform()` (O(1), no allocation).
- `src/gameplay/item_use.rs` (the hook): removed the no-encounter early return. `alive` is true
  without an encounter, `can_heal` is false there, and `transformed` comes from the stack. On an
  accepted non-heal row the hook calls `apply_consumable_effect` with the same spec; the bar
  admitted that exact spec in the same call, and `apply` re-runs the same pure check, so the spend
  cannot happen before a failed apply.
- `src/gameplay.rs` (hub): `ItemBar::load` now reads the effect table from the same content dir as
  the boombox catalogue (`npc_content`), and the no-opening path routes the item bar before the
  legacy `handle` inventory branch. The 2-line dispatch-order comment moved into the hook's doc.
  Net hub growth: **+1 line** (the opening path's movie gate and route order are unchanged).
- `data/content/consumables.json` (new): schema 2 with 2173 and 11002 (heal 35%, 10 s, exactly the
  built-in table), 2982 Electric Veal Meat (aura 5030, 30 min) and 4042 Bark Berries (transform
  169, poof 21, 30 min). T511 replaces this file with the generated ~90-row version; the row shape
  and `source` string match T511's brief.
- Tests: `tests/item_bar.rs` (schema 1 load, schema 2 bounds/refusals, 3 s floor, aura/transform
  use, already-transformed, pending preservation, rentals, no-health rule, shipped-row invariant),
  `tests/item_bar_gameplay.rs` (real `Gameplay::handle_in_world` route: 2982 aura on self and
  nearby, 38/16 icon 3843/name 277, 1_800_000 sweep, second-use refusal with a full state
  snapshot, relog resets the cooldown/stack, 4042 transform with a live-transform refusal and the
  chat line, no-encounter heal refusal), `tests/boombox_catalogue.rs` (`Player` fields).

## (R) rules

- A transform row is refused while a temporary appearance is live (treats never replace a
  transform; cakes may). The 42/16/42/15 refusal text is "You are already transformed.".
- Non-heal rows do not need the encounter engine; the player counts as alive without one, and a
  heal row is refused instead. Heal rows keep the encounter requirement.
- A row with `single_use: false` is not consumed (cooldown and effect still apply).
- Cooldowns and the pending 42/16 confirmation stay in memory; a relog resets the sweep. (R,
  question for the owner.)
- A refused 42/16 check keeps an earlier pending confirmation (a refusal consumes nothing); a
  confirmed 42/15 attempt consumes the pending confirmation even when the use is refused.
- Value choices that are content, not code: row list, durations, cooldowns, icons, effect ids.
  Only the 3 s floor and the sanity bounds are compiled.

## Threat note (secure-code-guardian)

Hostile client sends: 42/6/42/9 with any slot/instance/definition/tint, 36/10 bar 2 with any
slot/target/mode/guid, 42/16/42/15 with any instance id, plus malformed lengths (the existing
app_fuzz corpus covers every truncation/trailing byte).

Why it is refused: an instance must exist in the authenticated player's own inventory; the
definition must have a loaded effect row; the bar slot is 0..4; the target must be self or 0; the
count, knocked-out state, rental, per-definition recast, effect-stack admission and live-transform
state are all checked before any mutation; 42/15 additionally needs the pending 42/16 for the same
instance. No client quantity, definition, slot target or effect value is trusted. Items are
consumed server-side exactly once (single_use), no item is ever granted, and malformed packets
return `InvalidData` before state changes (isolated to that session). Content rows are sanity
bounded at load (512 rows, 256 KiB, positive ids, duration/cooldown/delay/scale/percent bounds), so
a bad content package fails startup rather than creating an out-of-bounds effect. Nearby players
only receive the 35 family packets the effect stack emits; they cannot be targeted by the client.

## Checklist

1. **Refusal changes nothing.** Every new refusal is tested with a snapshot of the inventory, the
   bar (including the in-memory cooldown map and pending id) and the live effect stack equal before
   and after: cooldown (aura and transform), already transformed (36/10 and 42/16), heal without
   health, rental, plus the existing empty/knocked-out/no-row cases. The canary removes the
   transform check and both refusal tests fail.
2. **Rollback covers all state.** `usable` runs every check before `inventory.consume` and before
   `last_used.insert`; `Inventory::consume` stages a clone internally. The effect stack is only
   touched after the spend, and only via `apply` on an admitted spec. No `Rc`/`RefCell` side table
   escapes.
3. **Apply deltas.** No snapshot is restored over live state; the handler only consumes one item
   and applies the row's effect. The relog test reloads the saved state and starts a fresh effect
   stack rather than restoring an old one.
4. **Busy rules mutual.** The item bar is not an activity and adds no busy gate; consumables stay
   usable while busy as before (the opening movie gate still blocks 42/0 during a movie because the
   opening route is unchanged). No activity was added.
5. **Every entry path gated.** 36/10 bar 2, 42/16 and 42/15 all reach `consume`/`usable` through
   `ItemBar::handle`; the same handler is now routed in both the opening and no-opening paths, and
   `check` uses the same `usable`. No parallel path.
6. **Reachable in production, tested through it.** The tests drive `Gameplay::handle_in_world`
   (opening content for the potion test; an inventory-only content set for the food tests), and the
   no-opening route is exercised by the new tests. The packets are decoded and asserted at the
   wire level.
7. **Survives reconnect.** The bar save format is unchanged; the new gameplay test reloads a bound
   2982 slot, sees quantity 1 and `total_refresh_time` 1_800_000, sees an empty effect stack, and
   can use it again (the cooldown reset is (R)).
8. **Every exit path restores.** Expiry, cancel (35/33) and reconnect paths are T473/T474's and are
   unchanged; the new rows use the same apply/tick/retire paths. A refused use changes nothing.
9. **Economy safety.** No grants, no rewards, no client-reported quantities. One item is spent
   server-side per accepted single-use row; unknown/consumed instances cannot be used.
10. **Wire format.** No new packet layout: the rows feed the already pinned 35/13/14/15/16, 35/41,
    38/16, 38/25, 38/30 encoders. The test decodes 35/41 composite 5030, 35/14 model 169, 38/16
    icon/name, 38/25 total_refresh_time, and the 38/30 name/description. The client readers (IDA)
    are cited above and in the module docs.
11. **Unique ids.** Buff and world tag ids are T473's `EffectStack` allocator (disjoint ranges,
    checked add, wrap); this change mints no ids.
12. **Others see changes.** Aura/transform/scale go through `Emit::both` to `Outcome.nearby`; the
    tests assert 35/41 and 35/14 for self and nearby. No new visibility path.
13. **Content works end to end.** The shipped content file loads, 2982 emits the aura and buff row,
    4042 emits the model, and `the_shipped_rows_all_fit_the_effect_stack` proves every shipped
    non-heal row passes `admits`.
14. **Values in data.** Durations, cooldowns, icons, composite/model/poof ids and percentages are in
    `consumables.json`; the only compiled numbers are the 3 s client floor and the sanity bounds.
15. **Canaries break production.** The canary deleted the production already-transformed check and
    the two behavior tests failed; it was reverted (see Gates).
16. **Hands off session plumbing.** No session, teardown, transaction, save-ordering, gateway or
    lead-only file was touched. `src/gameplay.rs` only gained the item-bar route in the existing
    in-world dispatch.
17. **One player's error never stops the server.** Malformed client input returns `Err` (session
    isolation); no `unwrap`/panic on client data. Saturating/checked arithmetic comes from T473.
    Content errors fail startup, not a player action.
18. **Rules live on the type.** `Effect` owns `valid`, `effective_cooldown_ms`, `heal_percent` and
    `spec`; every `Player`/`Reply`/`Use` field has a doc comment saying what it decides. The
    row-shape decision is on `EffectKind`.
19. **Hot paths stay cheap.** Nothing new runs per tick; `has_transform` is O(1) and
    allocation-free; a packet does at most a 512-row scan and no state clone. The effect stack's
    empty-tick path is unchanged.

## Open gaps

- `Gateway::tick_at` only ticks gameplay for opening/kart/derby/soccer; a no-opening session's
  effects therefore do not expire. This is T474's pre-existing MINOR (lead decision, session
  plumbing) and was deliberately not touched. The no-opening route added here makes the bar usable
  there, but the expiry gap remains for that legacy content set.
- The buff-row blob offsets (icon at +72, name at +77) are T472/T473's pinned piece_056 layout; IDA
  confirms the reader and the data-source columns but not the raw offsets independently.
- The other five recovered potion definitions (35, 1195, 3021, 65820, 68989) can no longer take a
  slot because the row table is now the gate and the shipped file intentionally carries only the
  built-in potion rows (T511's rule 1). This follows the brief's "any owned item whose definition
  has a row" rule; flag it to the lead if the disabled-but-assignable potions were wanted.
- `source` is required provenance text and is not interpreted; T511 generates the full file.
- The 3 s floor is (R) OSFR data; no client function was found for it.
