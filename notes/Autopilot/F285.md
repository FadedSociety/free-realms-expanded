## Security threat note (secure-code-guardian)

- **Attack surface:** a hostile client can send 66/43 with arbitrary item id, quantity and
  transaction id, and 165/5 / 165/12 around it. This change adds no production parser,
  route, save, session, role or budget code; it proves the existing purchase transaction's
  failure behavior.
- **Why a hostile request cannot profit:** 66/43 still requires a server-opened shop and
  the vendor's authored stock/range (`NpcInteraction::validate_merchant_item_66_43`); the
  client price is ignored and `stores.json` supplies the Coin price. The test proves a
  failed save drops the staged Coin Shop, including its `vendor_transactions` idempotency
  cache and `sales` buy-back record: the same transaction replayed later charges and
  grants, and the pre-failure sale still buys back once at the data price.
- **Persistence:** the poisoned `state_path` is host-side only; no client field selects
  it. The failed save leaves the good bytes and the old `Snapshot` untouched.
- **Isolation:** the save error is returned, never `unwrap`ped; the server test proves it
  ends one session through `contain`/`end_session` while other sessions keep handling and
  answering datagrams.
- No player names, chat text, secrets or new content values were added.
