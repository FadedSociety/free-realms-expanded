## Threat note (secure-code-guardian)

The change is test and notes only; it adds no parser, save, reward, role, chat or session code.
Trust boundaries are unchanged from T245.

- What a hostile client could send: still only the ordinary field actions (26/8 interact, 26/10
  select, 36/10 cast, 49/x quest replies). None carries a level, definition, reward, spawn centre or
  quantity used here. The new tests drive the same request bytes the client sends; they do not add a
  server entry point.
- Why nothing new is refused: F283 changes no production code, so it cannot widen what a client may
  do. The economy assertions pin server-owned rewards (definition->level-band table, shipped content)
  so a future content edit that would turn the level-5 camp into a faucet fails a test instead of
  shipping silently.
- Reward provenance: the pinned 2/5 pair comes from the shipped `field_kill_rewards.json`
  definition override, not from client input. The kill is server-authoritative
  (`EncounterEngine::strike_damage`), and the client cannot name a different definition or level.
- No logging, secret, session or trust-boundary change.
