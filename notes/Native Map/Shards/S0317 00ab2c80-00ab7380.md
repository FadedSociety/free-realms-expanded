## Packet and server-contract evidence

The cited compatibility review and capture analysis establish the 133-byte record order, while 127/40 captures contain an additional 94-byte tail. That tail remains unknown; do not treat the reader as a full response codec. See `notes/Reviews/Housing Fixture Tail Compatibility Review.md` and `notes/Research/Housing Placement Responses.md`.

The placement response note corrects a direction ambiguity: observed subtype 2 is client-to-server (eight sends); subtype 40 is server-to-client (nine captured updates), paired with subtype 44 house-info updates. This evidence comes from captured traffic plus client code, not original server source. A server that supports this path would need to answer placement with a fixture update and house-info state, and issue removal updates on pickup; this remains a reconstructed contract, not a recovered original server rule.

`HousingPacketFixtureItemList` uses subtype 43 in the client constructor and is present in the community packet catalogue. Subtype 39's instance-list reader is visible at 00ab7250. These establish client framing/decoding paths, not server-side authorization, ownership or persistence.
