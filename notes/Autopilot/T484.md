# T484: Marketplace refuses a second Station Cash order for an owned ride and greys it out

## Summary

- `station_cash::owns_item(&InventoryState, item_id)`: any item of that definition with count > 0,
  in any tint (R: colour variants are separate item ids, e.g. Scaled Dragon 7960-7965, and the
  168/5 list has one row per ride; if ride-variant-appearance later lists tints per instance this
  rule must be revisited). One rule, also used by `gameplay/sc_earnings.rs` (T229's inline check
  is replaced).
- `Listing::owned_by(inventory)`: `owns_item` except for a deed (a deed never enters the bag; its
  owner check is the lot grant).
- `price` (shared by `preview` and `place_order`) takes the inventory and checks in this order: the
  listing, the replay (a paid duplicate still answers success), ownership (`ORDER_FAILURE`, 2), the
  balance. An owned ride answers 2 even when the balance is short.
- `requirements_packet(catalogue, inventory)` writes 66/39: i32 count, then per listing a u32
  bundle id and a u8 flag, 0 for an owned ride, else 1. 66/38 (store open) answers with it
  (T380's empty list is replaced); a successful non-replay order appends it after the 66/4, so the
  bought ride greys out without reopening the store. Refusals and replays append nothing.
- `gameplay/npc.rs` hands the shop the live bag before opcodes 1, 3 and 38 (was 3 only): the shop
  is built with the login-time inventory and ownership must see rides given in the session.
- The pinned tests that saw the old behaviour changed: `coin_store_siblings` (66/38 list, a short
  balance on an owned ride is 2), `station_cash` (66/4 is found by header, it is no longer last),
  `lot_deeds` (a deed order is followed by an all-1 66/39).

## Notes for later

- A ride traded away or lost is buyable again at once on the order path; the client's flag
  refreshes on the next 66/38 (store reopen). The order path is the authority.
- Earn-only rides are never listed, so never appear in 66/39. With Station Cash disabled 66/38
  gets no reply and no 66/39 is appended.
- Cost: one inventory scan per listing per order and per 66/38, nothing per tick; 66/39 is bounded
  by the number of listings (about 50 rows, 5 bytes each).

## Threat note

A hostile client can resend an order for an owned ride, replay a tracking id, preview an owned
ride, or send 66/38 with a forged inventory view. Ownership is read from the server inventory
only, never from a client value; the refusal (`ORDER_FAILURE`) changes no wallet, inventory or
order history (snapshot equality in the tests); a replay of a paid packet still succeeds without
a second charge or grant.
