## Threat note (secure-code-guardian)

This task changes notes only, so it adds no attack surface. The audited path is
the client-controlled `[0,25]` bundle carrying 66/43 buys. A hostile client can
choose child order, a bare/nested/oversized child, more than 128 children, and
any item, quantity or transaction id. The corrected state description is the
safe one: every child is decoded by `application_messages`/`parse_message`
before gameplay; `Gateway::handle_at` stages each child on a cloned `Gameplay`
(and a clone of `NpcInteraction` for 26/10), returns `Err` for a failed
combined child before committing, and assigns the staged state only after the
whole loop; production clones the whole `Gateway` and commits with
`commit_outcome`. Inventory, coins, `next_instance_id`, the shop ledgers and
the NPC menu are inline in those clones, so a refused child cannot leak a menu
consumption or a purchase. The open-shop/stock/range checks, non-zero quantity
bounded by `i32::MAX`, `checked_mul` server price, coin/bag checks, bounded
transaction cache and refusal-without-cache behavior are unchanged and remain
covered by `tests/vendor_sell.rs`. The canonical details are in `F113.md`.
