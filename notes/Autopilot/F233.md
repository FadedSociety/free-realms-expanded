## Security threat note (secure-code-guardian)

Attack surface: a hostile client can drive the chat family/subtype, channel, claimed
identities, message bytes, position/area/guild claims, and join/transfer/disconnect requests
(by logging in and zoning). This change adds no parser, delivery or eligibility path and
changes no production code; it only asserts the server-owned membership invariant after a
successful transfer in the existing socket test. Why it is security-relevant: `joined` gates
`ride_fanout` and the five `commit_outcome` transaction predicates; if a rejoin wrote the
player row and chat member but not `joined`, ride/pet visibility and entry/exit would
silently diverge from chat. The new assertion and canary pin that rejoin. The three refused
transfers (forged 41/103, unknown instance, failed save) still snapshot location + the
three-way tuple and assert equality; no refusal path or write was added. No new
`unwrap`/`?` on client data, no save/coin/item/reward/role change.
