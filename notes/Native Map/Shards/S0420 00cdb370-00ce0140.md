# S0420 findings

The 91 functions cover soccer, two UI data sources, shared list containers, and proxied vehicle-race objects. The main subsystems are `minigame.soccer`, `net.gateway`, `net.minigame.soccer`, `ui.leaderboard`, `ui.quickchat`, and `game.vehicle`; supporting code falls under `engine.containers`, `engine.effect`, `engine.refptr`, `asset.sensory_effect`, and `lib.soeutil.container`.

## Soccer send and object paths

`SoccerPlayer` has five send paths in this range: position (`00cdc4a0`), player state (`00cdc5c0`), free ball (`00cdc710`), controls (`00cdc810`), and ball update (`00cdc9a0`). Each builds a family-76 payload using its packet constructor and routes it through one of the generic wrappers at `00cdbec0`, `00cdbfd0`, `00cdc0e0`, `00cdc1f0`, or `00cdc390`. Those wrappers initialize a writer, serialize the payload, construct a `PacketTunneledClientPacket` via `0089adc0`, and submit it through gateway send helper `00925640`. `00894560` only destroys the temporary writer buffer. The records therefore identify the catalogued outer tunnel packet as the wire item; the family-76 inner packet class is absent from `nmq packet`, and no inner family/subtype literal is present in these sender functions.

The native family-76 reader/dispatcher is outside this shard at `00b80ac0`. The existing wire mapping documents the state sender `00cdc5c0` as sub-14 and controls sender `00cdc810` as sub-16, while leaving several field meanings unresolved ([Soccer Kick Direction Binding](%USERPROFILE%/Documents/Projects/CartoonMMO/project/notes/Research/Soccer%20Kick%20Direction%20Binding.md), [Soccer Kick Pass Wire Mapping](%USERPROFILE%/Documents/Projects/CartoonMMO/project/notes/Research/Soccer%20Kick%20Pass%20Wire%20Mapping.md)). `00cde6f0` writes a 36-byte payload consumed by `00cde880`; `00cde9b0` conditionally constructs and sends `SoccerPacketImpulseBall` (family 76, sub-13) when its send flag is nonzero. The only located dispatcher call passes zero, so the conditional branch is real but an active client-authored impulse invocation remains unlocated. This agrees with the review's bounded wording; it does not prove that no other indirect caller exists ([Soccer Kick Pass Wire Review](%USERPROFILE%/Documents/Projects/CartoonMMO/project/notes/Reviews/Soccer%20Kick%20Pass%20Wire%20Review.md)).

Soccer object code includes `SoccerPlayer` debug display and state methods (`00cdb370`, `00cdcbb0`), and `SoccerBall` construction, attachment/refcount cleanup, effect updates, transforms, and per-frame work (`00cdcbe0`–`00cde480`, with gaps between targets). `00cde1c0` constructs a ball object and initializes named asset paths; `00cde480` is called by the family-76 dispatcher but performs object/resource/effect setup, not packet parsing itself. The helper at `00cddf60` resolves the named bounce and goalie-block effects.

## UI and vehicle groups

`ui.leaderboard` holds the leaderboard data-source and entry-column accessors (`00cdeb20`–`00cded50`) plus constructors/destructors. `ui.quickchat` contains autocomplete columns, row counts, and source access (`00cdf130`, `00cdf240`, `00cdf590`, `00cdf760`); its row lookup and linked-list operations use the neighboring generic container functions (`00cdf1b0`, `00cdf340`–`00cdf570`). `00cdf3e0` clears a list, assigns a string, and calls a virtual notification, but the owner and notification meaning are unknown.

`game.vehicle` covers `ProxiedVehicleRace`, its pickup, and missile objects, including constructors/destructors, state copying, and transform helpers (`00cdf8e0`–`00ce0140`). `00cdf9b0` constructs an embedded `VehicleRacePacketUpdateVehicleRaceClientData` object, but that constructor shows no packet send or receive direction. `00ce0140` composes/applies a transform and resolves an owner racer using a stored GUID. Do not infer the embedded packet's direction from proximity to the vehicle code.

## Server-contract hypothesis and open questions

Hypothesis for a compatible replacement server: it must unwrap the outer client tunnel packet and decode the relevant family-76 payloads. For sub-14/sub-16 identity fields, the replacement should bind the claimed player to the authenticated session; the captured-data review and the existing recovery notes support this as a defensive contract, not as recovered original server behavior. The original server is unavailable, and the community packet catalogue supplies names/opcodes rather than original server rules. No record asserts an original server implementation.

Open questions: the family-76 inner packet rows are missing from the packet catalogue; exact meanings of several soccer fields remain unresolved; no located call activates the impulse sender's nonzero flag; `00cde480`'s exact dispatch subtype is unknown; and the embedded vehicle client-data packet's direction is unestablished. These limitations are recorded in the per-function `open_questions` fields.
