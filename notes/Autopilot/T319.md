## Threat note (secure-code-guardian)

No new client parsing code was added; the row feeds the existing 167/1/1
catalogue and the 26/8 -> 41/108 -> 36/10 -> 26/42 handlers. A hostile client
could send:

- a forged 167/1/2 Play id: the catalogue must contain it, the job must be a
  combat job, the level floor is 0, the busy/occupancy gate and the whole-bundle
  prize preflight run before any state changes; refusals are chat lines and the
  snapshot/save are unchanged. Test 4 sends an unpublished id and asserts the
  refusal text, a typed-snapshot + save-payload equality and that the session
  still answers a refresh;
- a forged 26/8 marker GUID: only a battle spawner within 8 m opens a screen,
  so an arbitrary GUID is inert (test 4);
- a forged/out-of-range 41/108 Go: only the pending screen's encounter and
  instance, with the player still inside 8 m, can start; otherwise the request
  is inert or a chat refusal that reopens the screen (test 4);
- an arbitrary 36/10 target GUID: only the active arena enemy within the
  profile's weapon range and the 600 ms swing can be hit; damage is computed
  from the server profile, never the client payload. Test 4 attacks
  `0xdead_beef` inside an active arena and asserts the typed snapshot and save
  payload are unchanged;
- a replayed 26/42 Close or first-run 41/108: only a Won/Lost active run exits
  and a consumed pending screen cannot be replayed (tests 2, 3, 5);
- a full bag: the four-row whole-bundle preflight refuses before the encounter
  starts (test 4).

The reward is the existing `EncounterReward` applied only on a server-verified
kill; no client quantity, item id, coin amount, win flag or impact is trusted.
The static marker is shared by all sessions (no per-player alias). The content
file is bounded at 128 KiB / 64 battles / 16 enemies per battle / 4 prizes /
quantity 1..=100 with actor, zone and GUID-uniqueness validation; a malformed
or duplicate row is refused at load (test 6). No save field changed.
