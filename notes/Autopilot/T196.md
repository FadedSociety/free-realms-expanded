## What changed

- `src/gameplay/placement_watch.rs` (new module, 309 lines incl. tests)
  - `PlacementWatch { stamp, next_check_ms }` + `Stamp::{Unknown, Absent,
    Modified}`; `poll(path, now_ms)` stats at most once per second, applies a
    changed mtime, reports a deleted file once as "no placed actors", and
    returns `Err` (stamp kept) on a malformed/oversized file.
  - `due(now_ms)` lets the per-session tick skip building the path while the
    one-second window is closed, so an idle tick performs no allocation.
  - `observe(path)` records the file a session just loaded or wrote.
  - `apply_own_placement_write(records, character, out)` applies a successful
    `realm place`/`realm unplace` file as a **delta**: removes placed rows the
    file no longer has, adds rows another admin wrote since this session's last
    poll, then stamps the file. This closes the two-admin case where the acting
    session would otherwise stamp away a row it had not applied.
  - `retry()` drops the stamp when a successful read could not be applied.
  - `Gameplay::tick_live_placements` (the `impl Gameplay` lives in this module,
    keeping the hub thin) gates on `world_dir`, applies the rows to a **cloned**
    `NpcVisibility` with the existing `replace_placements`, and commits only on
    success. It never sets `Outcome::changed`, never saves, and logs a per-session
    error event instead of propagating it out of the tick.
- `src/world.rs`
  - New `pub fn read_placements(&Path) -> io::Result<Vec<Placement>>`: the
    startup loader's existing `read_rows` (regular file, 16 MiB bound,
    `Rows<Placement>` schema) exposed as one public bounded reader.
  - `NpcVisibility::load` now calls it instead of repeating the `Rows` parse;
    startup behaviour is unchanged (a malformed file still fails the load).
  - New `NpcVisibility::placed_guids()`: the type owns the "what counts as a
    placed row" decision, so the own-write delta does not walk private fields
    from a caller.
- `src/gameplay.rs` (hub, **net −3 lines**: 9 added, 12 deleted)
  - `mod placement_watch;`
  - one `placement_watch: PlacementWatch` field (never in `GameplayState`) and
    its `Default` initializer;
  - one `self.tick_live_placements(now_ms, &mut out);` call in `tick` after the
    world/gathering ticks;
  - `observe` after `set_world_dir` loads the table;
  - `realm place`/`realm unplace` now hand their saved rows to the new module's
    delta apply (one line each) instead of a hand-written place/remove block.
- `src/gameplay/content_reload.rs` (+5 lines): `realm reload placements` stamps
  the file it just read, so the watch does not repeat that reload one tick

- `tests/live_placements.rs` (new): 8 end-to-end tests driving the real

## (R) rules

- The once-per-second poll is reconstructed: `realm place` is human-paced and
  the brief pins 1000 ms; there is no content schema for watcher tuning.
- A placement file that disappears means "no placed actors" `(R)`; the existing
  `realm unplace` of the last row writes an empty table instead of deleting the
  file, so this is an external-tool/editor case.
- Non-finite placement positions are skipped by the existing `place()` `(R)`;
  the watch does not add a second validation path.
- The file's mtime is the change signal `(R)`. Two writes inside one filesystem
  clock tick can share an mtime, so a session can miss the second write until
  the next one; human-paced edits make that negligible (see Open gaps).
- The own-write delta is reconstructed `(R)`: a session that just wrote the file
  applies the rows it did not already hold and drops rows the file no longer
  has, then stamps the file. This keeps the acting admin converged without a
  remove/re-add of unchanged rows.

## Security threat note (secure-code-guardian)

- A hostile client cannot write `npc_placements.json`: only the role-checked
  `realm place`/`realm unplace` commands and local tools write it. The watch
  re-reads the same file every session already loads at login, and adds no
  client-supplied field or packet writer.
- A malformed/oversized (>16 MiB) table is refused: `poll` returns `Err` before
  any mutation, `tick_live_placements` keeps the previous view and revision, and
  it logs one `placement_watch_error` event instead of propagating the error out
  of `Gameplay::tick` (which the gateway would turn into a session disconnect).
  The malformed case is tested end to end; the size case is the existing
  `read_rows` bound, shared with the startup loader and inspected here.
- Rows are admin-authored and still go through the existing `place()` checks
  (finite position; existing model/name/transform fields). The 35/2 and 35/3
  bytes are the existing builders; the existing zone, 100 m radius and 64-actor
  cap still decide what a viewer receives.
- No coins, items, rewards, roles, chat or saves are read or granted;
  `Outcome::changed` stays false, so no character save is triggered. A refused
  reload changes no character state (unit test compares `Gameplay::state()`).
- The own-write delta only removes GUIDs the session already holds as placed and
  adds rows parsed by the bounded reader; it never trusts a client quantity.

## Open gaps

- mtime granularity: two writes in one filesystem clock tick can share an
  mtime; a session may miss the second write until the next one. Tests wait one
  clock tick between writes. A content hash per poll would close it at a higher
  per-second cost.
- `Gameplay::tick` is reached by `Gateway::tick_at` only while `is_opening()`/
  kart/derby/soccer is active. The live-world placement route is itself only
  installed by opening content, which keeps `is_opening()` true for every loaded
  session, so the watch is reachable exactly where `realm place` is; a server
  running without opening content has no placement commands.
- The watch is deliberately skipped when `world_dir` is `None`: with no
  `--world`, `placements_path()` falls back to the git-tracked content folder,
  whose edits are content changes that `realm reload placements` already owns;
  polling it would stat a file no gameplay tool edits at runtime.
- Private-instance filtering is the gateway session view (unchanged); the new
  Gameplay tests cover zones and the existing `shared_world_membership` tests
  cover instance membership.
- No native client run in this slot. The packet paths are existing and now
  IDA-confirmed, but the live edit was not observed in the real client; a lead
  native pass remains.
- The existing `replace_placements` re-sends every placed actor when the table
  changes (remove + re-add), unchanged by this slice; the acting admin's own
  write now applies a delta instead.
- Same-GUID field edits by another admin (model/name/position changed while the
  GUID stays) are not re-applied by the own-write delta; they arrive on the next
  mtime change of the watcher. The file is human-paced and the GUID allocator
  makes concurrent same-GUID edits unlikely.
- A malformed table makes the next admin `realm place` allocate a GUID from an
  empty table (existing allocator behaviour, admin-only path).
