## Step 1: what the server reads today

All of it comes from the item's wire row (`Inventory` decodes `serialized_hex`); nothing reads the generator
columns directly: coin price (+0x24, `00cff140`), sell flag and Worth (`sale_flags`), gender usage, members-only
and min profile rank (`Requirement::from_wire`), slot, class, max stack, model, texture, tint alias, composite
effect and wield type (the catalogue columns), and name, description, icon and type (`ItemPresentation`). Every
one is a wire field, so correcting the row corrects the server.

Guesses found, and what the original table now says:

- Consumable cooldown: 1,800,000 ms (69 rows from Sanctuary `CooldownMs`, 23 the (R, OSFR #125) default). The PS3
  recast column says 880 on 317 rows, but its unit is unproven. Left alone; see follow-up 4.
- Heal potions 2173 and 11002: 10 s (R, W146) where the original recast is 0, COMBAT_ONLY 1, PREFERRED_ITEM_BAR_SLOT
  1 and USE_REQUIREMENT_ID set (11243, 10967). The server lets a potion be used out of combat. Follow-up.
- Food and transformation use: USE_REQUIREMENT_ID 133 on 546 items; the server has no requirement table.
- Boomboxes: recast 180 s in `boomboxes.json` (a Sanctuary default); the original table has no recast for them
  (878 carries 2060, like the cakes).
- `slot_min_rank` (Star and Moon runes) comes from the slot table, not the item row. Unchanged.
- EQUIP_REQUIREMENT_ID is set on one item (6883). The wire row's gender, members-only and rank fields already
  carry what the server enforces.

## Era skew: why this does not apply the whole table (R)

The original table is a different build from the 2013 PC client our data follows: it lacks 917 Legacy ids and has
47 Legacy lacks, and it differs from Legacy by thousands of values outside the eight shared columns (tint id and
tintable flag on about 3,700 rows, slot on 700, trade and sale flags on 400). Applying it whole would roll tint,
slot and flag data back to another build. So only the eight shared columns are corrected (the brief), and a row
whose original line blanks the model or icon is held: the boombox rows (878, 56774, 69825, 77329: class 171 and a
model in ours, class 9 and no model in the original) and one placeholder-named row (2215). Lead: say so if you
want the held rows or the other columns applied.

Captured baseline rows (1,649) are not touched: `Inventory::load` lets `inventory.json` win over the catalogue,
the byte oracle pins them, and they are the outlier. Of the 1,482 baseline ids the original table has, 660 rows
differ on the eight columns (cost 538, class 273, category 100, max stack 73, type 25, description 11, name 8),
and Legacy equals the original in nearly all of them (`baseline_gap` in the reference file). That is follow-up 1,
not part of this commit.
