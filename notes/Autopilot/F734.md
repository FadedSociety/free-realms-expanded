## Threat note (secure-code-guardian)

The diff is test-only, but the changed builders are what the coin-store and vendor suites use to exercise
the server's 165/4, 165/5 and 165/12 parsers, so a wrong layout would silently test different bytes than
the client sends. The canonical writer addresses above pin each field, and the shared parser keeps its
56-byte length check, so a hostile client still reaches the same production validation as before: the
merchant must be the open shop, the instance must be owned, the quantity is bounded, and refusals answer
`RESULT_INVALID_ITEM`/`RESULT_FAILURE` without touching inventory or the buy-back ledger. A hostile client
can send a foreign merchant, an unowned instance, an unknown definition, a negative/oversized quantity or
trailing bytes; those requests are refused by the unchanged production code, and the suites assert the
snapshot and coins are unchanged (`an_unbound_pet_item_is_refused_through_the_real_165_4_buy`,
`gateway_buy_back_refusals_answer_the_client_and_change_nothing`). No new input parsing, save code,
role, chat or reward path is added. Fixture content stays under the suite's scratch directory (the OS
temp dir or `lab/build`), never the shipped content files; no player data, names or chat text.
