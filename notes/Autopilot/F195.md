## Threat note (secure-code-guardian)

No production code changed, so the trust boundary is unchanged. The audited
path is the client-controlled `[0,25]` bundle carrying 66/43 buy children. A
hostile client can choose child order, a bare/nested/oversized/over-count
child, and any item, quantity or transaction id. The unchanged code refuses
unsafe input at every layer: every child is decoded before gameplay; each child
is staged on a cloned `Gameplay`; a failed combined child returns before the
commit; item stock and range are checked; quantity is non-zero and at most
`i32::MAX`; price is `checked_mul` from `stores.json`; coins and bag space are
checked; the transaction cache is bounded and refusals are not cached. The
correction removes a false warning that could have induced an unnecessary lock
or disabled shop buys; it does not relax any check. No player names or chat
text were added.
