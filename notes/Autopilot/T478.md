- `--resources DIR` gateway option -> `style_cards::ClientTables::load` (Models.txt and the five CharacterCreate mapping

## Threat note (secure-code-guardian)

A hostile client can send 42/10 or 42/12 with any value, any length, at any time, repeatedly or concurrently with an
activity. The body is exactly 8 bytes or the session ends (existing convention). The value only selects an item the player
owns: an unknown id, an unowned definition, a non-card, a card of another gender or model, PARAM1 0/8/unknown, a busy player,
a missing table and a no-change card all get one chat line and change nothing. Slot, mapping and gender come from the
catalogue row and the strings from the client tables (bounded 512 bytes, no NUL), never from the request. One request spends
at most one card (`consume(item, 1)`), and a duplicate after the last card is a refusal. The look is written only after
`consume` succeeded, inside the gateway's staged transaction: a failed save drops card and look together
(`style_card_save_failure_changes_nothing`). Nothing runs in the tick.

## Checklist

1. Refusal changes nothing: every refusal returns before `consume`; `refused_style_card_changes_nothing` compares the
   serialized `GameplayState` before and after, plus one chat line, no nearby, `changed` false; busy and mining tests too.
2. Rollback covers all state: card and look both live in `Gameplay`, which the gateway stages on a clone and installs only
   after the save; `style_card_save_failure_changes_nothing` proves it. No shared cells; the tables are read-only `Arc`.
3. Deltas, not snapshots: `consume(item, 1)` removes one card from the live inventory; the look is `look.apply(record)` of
   the current look. No old snapshot is written back.
4. Busy rules are mutual: the card refuses under the start gate (`blocks`); a card starts nothing, so no other activity
   needs a new check. Tested with fishing (own gate) and mining (router gate).
5. Every entry path: 42/10 and 42/12 are dispatched in both Gameplay inventory branches (`handle_opening_inner`, `handle`);
   both flows are run by the tests (open world and opening campaign). The gateway reaches them only via `handle_in_world`.
6. Reachable in production, tested through it: `Session::dispatch_message` (bin test), `Gateway::handle_at` and
   `Gameplay::handle_in_world`; `--resources` is parsed and applied in `load_gateway_from`.
7. Survives reconnect: `GameplayState::appearance` is in the character save; relog tests at Gameplay, Gateway and Session level.
8. Exit paths: nothing is held open; a refusal or failed save leaves the player as before.
9. Economy: the request names an item the player owns; one card per request; a no-change card is kept; no free grant, no
   client quantity.
10. Wire format: 35/39 is `style_cards::customization_change` (T477 byte tests, readers cited above); the 38/4 and item
    update come from `Inventory::consume`; the gateway test reads the 35/39 guid and preview byte.
11. Unique ids: none created.
12. Others see changes: `out.nearby` -> `ride_fanout` (range and directed view), 35/39 added to `live_outfit_packet`; late
    joiners through `set_presentation`; test with in-range, out-of-range and late sessions. A viewer in another zone
    instance is excluded by the same `nearby_sessions` rule (`tests/players.rs` pins it); the rig has no second instance.
13. Content end to end: real catalogue cards and client tables; Clean Shaven makes the saved look and AddPc empty.
14. Values in data: slot, mapping and gender come from the catalogue row; no tuning constants.
15. Canaries break production code: listed above.
16. Session plumbing: untouched (no change to session creation, teardown, transactions or save order); the only osfr-gateway
    changes are the option, the `set_style_tables` call and moving the fanout helpers.
17. One player's error never stops the server: nothing runs in the tick; every request path returns `Err` only for a
    malformed length (that player's session) and chat refusals otherwise; no arithmetic on client values.
18. A type's rules live on the type: `Look` and `GameplayState::appearance` document persisted, compared and sent;
    `Look::apply` stays the only record-to-field map.
19. Hot paths: only a request does work; `player_presentation` runs on gameplay change as before.
