# F761: fix the F746 review blockers

Review: `lab/autopilot/reviews/6abfe64-F746.md`. One BLOCKER (STRUCTURE: the
Southvale suite re-declared the shared record/quest helper block) and four
MINOR findings. All five are addressed. No `src/` production file, hub file,
`Cargo.toml`/lock, session, wire or lead-only file changed; the diff is tests
and two notes lines.

The worktree tip is later than `6abfe64`: F745 (`a7e25115`) had already changed
`RawQuest::reward_totals` to take the paid profile, so finding 3 had moved to
the other side of the same conflation: `finish_quest` then got the right
profile share, but the 49/13 star-word assertion expected one profile's XP
instead of the sum over every `job_xp` profile. F761 fixes the split in both
directions.

## What changed

- `tests/support/quest_records.rs` (finding 1): the one shipped-record finder now
  lives here: `shipped_quests()` (read once per test binary), `find_quest(records,
  id)` for a suite that patched its own private catalogue, and `shipped_quest(id)`.
  `RawQuest::reward_stars()` returns every profile's `job_xp` summed, the 49/13
  star word. `ZoneQuest::from_record(record, giver, turnin, profile)` is the one
  `RawQuest` -> `ZoneQuest` card/end-text/payout mapping.
  It is defined in this module rather than `npc_quest_chain.rs` because
  `quest_records` already depends on `npc_quest_chain::read_json`; the reverse
  dependency would not compile in the suites that include `npc_quest_chain` alone
  (this is the review's allowed `ZoneQuest::from_record` call shape).
- `tests/support/npc_quest_chain.rs`:
  - `ZoneQuest` now documents and carries both `xp` (the 49/13 star word, all
    profiles summed) and `profile_xp` (what `finish_quest` credits the named
    profile). `pay_held_turnin` sends the total to `release_end_screen` and the
    share to `finish_quest`; `finish_quest`'s parameter is
    `expected_profile_xp` (finding 3).
  - `zone_player_unlocked(fixture, guid, active, unlocked)`; `zone_player` is now
    `zone_player_unlocked(..., &[ADVENTURER])` (finding 2).
  - `Fixture::save_and_reload` asserts the serialized `GameplayState` round trip
    (`saved(&reloaded) == saved(game)`) instead of the tautological character
    clone check (finding 4).
- `tests/support/mining_quest_chain.rs` (finding 4): `save_and_reload` delegates
  to the canonical `ChainFixture::save_and_reload`; the duplicate envelope code
  and the now-unused `game_store` import are gone.
- `tests/zone_quests_southvale.rs` (findings 1, 2, 3): the local
  `shipped_quests`/`record`/`quest` block is deleted and every quest is built with
  `ZoneQuest::from_record(shipped_quest(id), ...)`; the card, end text, coin word,
  star total and the Miner's share all come from the shared helpers. The
  active-job test now seeds Miner as *learned* while Adventurer is active (and
  asserts that precondition), so the refusal is attributable to the active-job
  gate. New regression
  `the_star_word_sums_every_profile_and_the_miner_is_paid_only_its_share` patches
  the fixture's private quest catalogue (never `data/content`) so Finding
  Southvale pays `{"14": 15, "1": 5}`; it asserts the 49/13 star word is 20, the
  Miner gains 15, the Adventurer gains 5 and the quest completes.
- `tests/zone_quests_wildwood.rs` (finding 1): its `records`/`record`/`quest`
  copies are deleted for `shipped_quest` + `ZoneQuest::from_record`; the two grant
  assertions and the manual `finish_quest` now use `profile_xp`, the star-word
  assertion stays on `xp`.
- The remaining suites that construct `ZoneQuest` add `profile_xp`:
  the single-profile `const` suites use the same pinned value, and
  `zone_quests_round3_briarwood.rs`, `zone_quests_thunder_falls.rs`,
  `zone_quests_seaside_round3.rs`, `zone_quests_stillwater_round3.rs`,
  `zone_quests_speedways.rs` and `zone_quests_sanctuary_round3.rs` derive it from
  their single profile expression (`reward_totals`); the three shared builders that
  carry a `RawQuest` use `reward_stars()` for `xp` so the star word is the total
  even if content gains a profile.
- `notes/Autopilot/F746.md` (finding 5): the two overstated claims are corrected
  (the local `record`/`quest` mapping was a `reuse:` finding; the real test-only
  allocation cost is the save-envelope clone/serialize and the per-call
  `ZoneQuest`).
