# Harvesting Restoration

Rust harvesting restoration (MiniGameData type 8, original `game_farming.gfx` MatchThree "Farming" movie) recovered the original configuration schema, produce catalogue, goal/quota semantics and bundle drop identities, and ships them as a standalone module plus focused tests. Board dimensions, quotas, bundles-per-goal and spatial uncertainty remain explicitly reconstructed. Nothing is registered in `lib.rs`, no gateway/content integration was performed and no native client run happened: the shared game window is lead-controlled. Integration point for the shared type-8 engine is frozen with the mining worker (contract v1) and the engine itself stays owned by `mining_restore`.

Artifacts: module `prototype/osfr-tools/src/harvesting.rs` (SHA-256 `cdb451aefada689fed0558f83bd090ef10940d8aee2234059c6599515c435d9a`), tests `prototype/osfr-tools/tests/harvesting.rs` (SHA-256 `b6fa910a55cf01c17a9398027ad08c10ec915255cc0a9e8b9a63314d8f6104a5`), decompiled original movie and screenshots `../lab/decompiled/minigames/harvesting`, provenance bundle `../lab/reports/harvesting-restoration-20261009T020914Z.json`.

## Reconstructed and explicitly labelled

The original server tables (`MatchThree*Data.txt`) were never shipped with the client: they are absent from the public manifest, from both supplied archives and from the supplied emulator, so board dimensions, shape corners, duration, per-goal quotas, tiles-per-bundle cadence, spawn percentages and the bundles granted per completed goal are reconstructions. The module encodes a 10x10 staircase shape (76 playable cells, rows 4/6/8/10/10/10/10/8/6/4) from the screenshot, 180 seconds, quota 15 tiles per goal with 5 tiles per bundle, wildcard 5%, collectable 12%, no blockers or powerups, and one bundle granted per completed goal. `reconstructed_rules=true` and the `rule_notice` string ship with every spec, and the tests assert both. The movie's `ConfigServer.GAME_ID=60` is a stale local-test default (MiniGameData 60 is Mail Sorting) and is deliberately not used; real ids are 58 plus 109-120/217.

## Module and integration contract

`harvesting.rs` is self-contained (existing `serde`/`serde_json` dependencies only, no `crate::` imports). It owns the produce catalogue, six region profiles, the original schema oracle (`SpawnRow`, `LevelRow`, `ProgressionRow`, `TimerRow`, `GridTemplate` parse/serialize with exact column counts), the original score/quota arithmetic (`chain_score`, `chain_time_bonus_seconds`, `collectable_score`, `evaluate`), and emits the frozen type-8 spec. It does not contain a board engine, network envelope, tick loop or inventory transaction.

Contract v1 with `mining_restore` (frozen names, JSON only, no compile-time link): `content(game_id)` returns `{schema_version, game_id, profile_id, name_id, description_id, icon_id, spec}`, and `write_content(dir, game_id)` writes `harvesting.json`; the shared engine is called as `load(dir, "harvesting.json", game_id, 58_000_001, state)` per instance. `spec` carries `width`, `height`, `shape` (flattened `aMyGrid` codes), `selectable`, `collectable`, `tiles`, `goals{index,value,quota,per_reward,icon_id}`, `outputs{value,definition_id,cluster_quantity}`, `duration_seconds`, `seed`, spawn percentages, `meter_id`, `reconstructed_rules` and `rule_notice`. Goal tiles are `601+slot` per the original `TILE_COLLECTABLE + spawn type`; `profile_id` mirrors `game_id` because no job-profile evidence exists; undefined harvesting variants emit empty goals/outputs rather than invented produce. `validate_content` rejects unknown ids, malformed shape/size, produce/icon/definition mismatches against the recovered tables, missing reconstruction labels, and goals on gap profiles.
