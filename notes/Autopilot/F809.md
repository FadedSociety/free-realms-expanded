## Checklist

1. **Refusal changes nothing.** `follow_location` checks finiteness before mutating; the regression
   test issues a NaN click and asserts the whole `PetPresence` is equal before/after. Water spam
   changes no save (`Session::tick` asserts `changed == false`) and now arms at most one shake.
   No other request can refuse in this change.
2. **Rollback covers all state.** No transaction or side table: the idle state is one `Copy` field
   of `ActivePet`, replaced by every summon; `looped` is inside it. Nothing escapes the service.
3. **Deltas, not snapshots.** Nothing restores an old inventory/coin/position snapshot. The follow
   click moves the pose to the new target; the rest of the pose is advanced from the live owner
   update.
4. **Busy rules are mutual.** No new activity: the idle life still refuses while a feed, groom or
   trick runs (`ActivePet::interacting`) or water is current; the water/care stand-up test covers
   the care path. The `Occupation` table is untouched.
5. **Every entry path gated.** The idle life has one entry (`care_tick` -> `idle_tick`, from
   `Gameplay::pet_tick`/`Gateway::pet_tick`); the late-viewer base packet only replays a state the
   same idle path set. The follow click is the public service API, not a second dispatch path.
6. **Reachable in production, tested through it.** The idle and bubble paths are tested through
   `Gameplay::load`/`handle_in_world`/`pet_tick` and `Gameplay::pet_tick`; the late-viewer packet
   test uses the same `PetService::view` + `PetPresence::spawn_packets` the hub calls. Open: no
   client subtype routes to `follow_location` yet (graph: 0 callers), so its regression test is
   service-level.
7. **Survives reconnect.** Unchanged: the idle state is session-only by design; dismiss and a new
   summon start over (existing test); no new persisted field.
8. **Every exit restores the player.** Standing up happens on owner movement, entering water and a
   care action (all three tested); dismiss/zoning/disconnect drop the actor and its state (existing
   tests). No stuck animation state survives a summon.
9. **Economy safety.** No item, coin, XP or free grant is touched or created; no client-reported
   outcome or quantity; the bubble only reads the server's decayed needs.
10. **Wire format.** 35/27 stays the verified u64 guid, i32 icon, i32 seconds, u8 clear (reader
    `008d7880`; 21 bytes asserted). The late-viewer 35/8 uses the existing writer with the base
    flag 1 (byte-level test). No packet field added.
11. **Unique ids.** No id added; the pet actor guid is the existing session id; the base animation
    targets that same actor.
12. **Others see changes.** The rest base is now replayed to a late viewer through the existing
    `SharedWorld::with_pets` fanout (AddNpc then 35/8); regular ticks already send every idle/rest
    packet to `shared` + `private` (existing per-tick assertion).
13. **Content works end to end.** The Gameplay test asserts a settled dog's idle rows and a hungry
    dog's bubble; the icon pin test asserts the four shipped client ids; the model's idle rows are
    unchanged. Rest/shake are service-level tests (the Gameplay window stops before 90 s).
14. **Values live in data.** All timings, chances, thresholds and the four icon ids are
    `care.idle`; per-model rows are each model's `idle`. Only sanity bounds, the 35/27 subtype and
    `ANIM_ID_STAND` are code.
15. **Canaries break production code.** Six canaries, each a production/data break, each failed
    the intended test (list above); all reverted and re-run green.
16. **Hands off session plumbing.** `bin/osfr-gateway.rs` gets one line inside the existing
    `with_pets` fanout; no session creation/teardown/transaction/save ordering change, and
    `gateway.rs` is untouched.
17. **One player's error never stops the server.** `idle_tick`/`care_tick` return `PetWire`, never
    `?`; all additions are `saturating_add`; the backwards clock returns no bubble and no error
    (tested). A model without rows is disabled without a panic (existing test).
18. **A type's rules live on the type.** `IdleState.looped` is documented and set/cleared by the
    state's own transitions; `PetPose::goto` owns the settle/pose rule; `PetPresence.base_animation`
    is documented as the late-viewer replay field; the four icon ids are one `IdleConfig` field each
    with the shared source.
19. **Hot paths stay cheap.** Per idle tick: one `Copy` of `ActivePet`, a few comparisons and one
    write-back; `PetService::view` adds one `Option<i32>` copy to the per-session presence the
    gateway already rebuilt each tick. A quiet tick allocates nothing new; a due tick allocates its
    packet vector(s) only when due. `spawn_packets` runs only when a delivery adds a player, not per
    tick.
