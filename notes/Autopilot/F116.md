# F116 - Fix T022 review blockers

## Result

Both blockers from `lab/autopilot/reviews/5a451bd-T022.md` are fixed.

- Recipe-book starts (`26/24`) now receive the complete live-activity state.
  A chess table, battle, gathering run or crafting movie therefore refuses a
  competing craft before any service, wallet or offer state changes.
- Chess computer turns are server-authoritative. The table chooses and applies
  its own legal reply; `OnMoveComputerMsg` is inert. This follows the recovered
  client design note in `notes/Build Guides/Gameplay/Chess.md`, which permits a
  server-side computer player and says the movie treats a network move event
  the same as a client-engine reply. No original server code or capture exists.

## Reconstructed rules (R)

- `recipe_book::Player::in_activity` is supplied from `Gameplay::activity_busy`
  and refuses recipe starts with `Refusal::Busy`. This is reconstructed
  admission policy, not a recovered original rule.
- `ChessTable::server_move` chooses a legal move by one-ply material, check,
  promotion and centralisation score. Easy rows may take the deterministic
  second-best move; medium/hard rows take the best. This is a local
  reconstructed policy and is intentionally shallow; it is not the native
  search engine.
- The server no longer sends `MOVE_REQUEST`; it emits the normal chess move
  event immediately after the human move (and at the start when the computer
  is White). A client engine reply cannot select or alter the opponent move.
