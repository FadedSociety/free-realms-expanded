## Classes and subsystems

The range centers on runtime terrain. Addresses 00d4a350, 00d4a6f0, and 00d4ba30 initialize and destroy GameRuntimeTerrain::Tile; 00d4ba50 logs missing tile textures and calls the tile resource setup path at 00d4b390. The stream parser at 00d4a9e0 populates variable tile records and a typed TileFloraData array.

GameRuntimeTerrain::Chunk is constructed at 00d4e0a0 and destroyed at 00d4dc20. Its nearby methods format .gcnk/.gck2 filenames (00d4ead0, 00d4eb30), check runtime terrain assets (00d4e610), inspect chunk headers (00d4e6b0), handle asset results (00d4ec80), and report unavailable assets (00d4c330). The fallback resource path is formatted and installed at 00d4e9a0.

GameRuntimeTerrain::DecompressChunkDataJob is constructed at 00d4d720, prepares buffers at 00d4c2c0, and releases its references and allocations at 00d4d7e0. SoeUtil::Array specializations cover TileEcoData (00d49f80–00d4a280), Tile (00d4d420–00d4df70), and ExportRenderBatch (00d4d570–00d4df90). The range also contains typed SoeUtil::List setup for RuntimeObject pointers (00d4ecd0) and RawLight (00d4f150), plus list-copy and tail-append helpers (00d4ed70–00d4f090).

The texture path has four chunk-reader conversion routines (00d4c360, 00d4c750, 00d4cc20, 00d4d020) and packed-pixel downsamplers (00d4bc20, 00d4be60). These routines convert source rows and build lower-resolution levels. The source format names and channel layouts are not recovered here.

## Chunk format behavior

00d4e6b0 compares the first four bytes against GCNK and GCK2. It accepts GCNK version values 1 through 6 and positive GCK2 versions, creates a typed decompression-job object, and marks failure for unsupported headers. Unknown types log that GCNK or GCK2 was expected. 00d4eb30 conditionally forwards a .gck2 path and always forwards a .gcnk path to a provider callback; the provider's request semantics are not named in this code.

The address-specific note Research/Pieces/080 World collision data.md also identifies 00d4e6b0 and documents the GCNK collision payload recovery. The community-reader assessment in Research/Pieces/079 World terrain readers.md reports preserved GCNK versions 2–6; the native check's acceptance of version 1 therefore describes code bounds, not a version observed in that preserved corpus. These notes do not establish GCK2 payload layout.
