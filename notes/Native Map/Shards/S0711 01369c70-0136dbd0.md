# S0711 — trading-card-game engine core: CTP::Game slots, command gate, error path (01369c70..0136dbd0)

Mapped by a Claude Haiku worker (42 functions; validator `valid_records=42 errors=0`; confirmed 13, likely 8, speculative 21). No catalogue packets (`wire` empty); TCG packets (net.tcg, sub-opcodes 0x26 / 0x28) live elsewhere.

- **CTP::Game virtual slots** (vtable-anchored; RTTI `CWMainController : CWGame : CTP::Game`, so CTP::Game takes the class binding): slot 6 `0136b200`, 9 `0136ba00`, 10 `0136dbd0` (Setup), 39 `0136b7a0`, 41 `0136d1f0` (AdvanceTurn), 65 `0136ca90`, 89 `0136aed0` (ChangeDuration), 134 `0136cb60`, 146 `01369c70` (text-command dispatcher; consumes lines like `receiveList(...)`, `cardPlayed(...)` via tab tokenizers `013c5df0` / `013c5e10`).
- **Command gate.** `0136d640` (DispatchCommandObject) routes to `0136d4f0` / `0136d6a0` (SubmitListEntriesOrReject / IfActive), `0136c550`, or `0136c400` (SubmitGameCommand). Server-ignore flag this+0x362 prints "CW_ERROR: Server ignoring game commands!". In `0136c400`, with this+0x14e set, a command that fails dynamic_cast to `GameCommand_ReadyForStartOfGame` is deleted (that type is the one exception).
- **Error path.** `0136d810` (HandleCaughtGameError) is called from 56 CATCH funclets (catch-side handler, not a destructor): recoverable per-player errors are logged and play continues; a fatal error submits a 0x94-byte object through `0136d6a0` and sets this+0x1d8. (This exposed a lead-tool bug: `nmq` now distinguishes unwind vs catch funclet callers.)
- **Maps.** Command table: MSVC map at this+0x108 (header +0x10c); per key a vector of 8-byte (ptr, ptr) elements. Also maps at this+0x140 (sentinel +0x144) and this+0x200.
- **Tree helpers (`crt.stl`).** `0136c070` TreeEraseIterator ("invalid map/set<T> iterator"); erase/teardown family `0136bfa0`, `0136db00`, `0136c350`; `01368de0` (same string); `01369970` ("map/set<T> too long", insert helper). Repeated shapes: `0136bea0` / `0136cf80` / `0136d8f0` (TreeTidyAndFreeHead); `0136d180` / `0136dac0` (range-erase-and-free); `0136bd40` / `0136be70` differ only in the callee.
- **Ghidra fixes.** `0136ad50`: receiver is param_2 (`mov ecx,esi`), not param_1. Cookie artifacts in `0136c350` etc. (calls to `01365b10`).
- **Lead hints (vtable-column data for callees, not proven here).** `0136d1f0` sends a 0x24-byte object from `0141a120` (GameCommand_ReadyForStartOfGame); `0136d810` uses `01429980` (GameCommand_FatalError); `0136ca90` uses `0142ef60` (GameCommand_IntroduceCard); the 0xa8-byte turn object from `013fd410` is GameTurn.
- **Open.** Flag semantics (from log strings/branches only): this+0x17c (setup done), +0x17d, +0x118 (started), +0x14d (gates trace logging and submission routing), +0x362 (server ignore), +0x388 (accepting), +0x1d8 (fatal/ended), +0x318. Source of the text-command lines consumed by `01369c70` is the main open server-contract question.
