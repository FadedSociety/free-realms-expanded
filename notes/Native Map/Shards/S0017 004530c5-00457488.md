## Containers and vectors

Most of the range is MSVC STL map/set and vector template code (crt.stl). Four tree families are substantially represented: three 0x74-byte node families with Isnil at +0x71, and one 0x18-byte family with Isnil at +0x15. A separate +0x21 Isnil / 0x24-byte node family has initialization and iterator support here, but its matching insert/erase/teardown path is outside this shard. The 0x74-byte nodes store three links, flags at +0x70/+0x71, and a 0x64-byte value; small nodes store flags at +0x14/+0x15.

Insert, erase, range erase, clear, copy, and iterator helpers recur across these instantiations. The confirmed insert bodies throw on their respective size thresholds: 004563f9 at 0x28F5C26 and 004565f6 at 0x1FFFFFFD. The latter is the +0x15 small-node family. Allocator 004539fb makes a zero-linked 0x18-byte node with +0x15 clear; initializer 00454217 turns it into the sentinel head by setting +0x15 and self-linking the three links.

Raw bytes at 00454e3c, 00454e77, 00455121, and 00455182 show recursive freeing of each right subtree followed by a loop down the left links. The decompiler shows only the right recursion. Each path invokes its matching value destructor, frees each node, and stops at its sentinel.

Vector helpers cover 8-byte pairs, 4-byte elements, and 0x24-byte records. 00456031 inserts a run into the 8-byte vector: it checks the maximum element count, grows capacity by 1.5x when possible, and falls back to the required size. The 0x24-byte record constructor 00457238 initializes a string and two container members; 00456749 allocates arrays of those records, while 00456c09 copies a 4-byte-element vector embedded in the record.

004534b7, 00453e15, and 004543b5 are a destruction chain, not a move chain. 004534b7 calls 0045245f to destroy source elements backward and computes a destination-start value; it does not copy elements there. 00453fef adopts the tree head's left/begin node for range erase 0045634f. Stub 004539e5 is used from the full-range path of small-tree range erase 0045654c: after clear, it builds the returned checked iterator; it is not a container copy-constructor helper.

The loop at 00454446 copies one fixed two-word source into successive destinations, decrementing the count and advancing only the destination by 8 bytes. Its entry 00454f0c is used by 00455100 to fill pair storage. The blocked store at 00453739 packs a block index in the upper bits and an 8-byte element offset in the low byte. 004544f8 appends a pair and increments its count. Its higher-level meaning remains unresolved, so that record is speculative.

## Font and GFC code

The font-related functions are engine.gfc.font; 0045728f is the engine.gfc.core destructor body that tears down two tree members and restores GInterface::vftable. No RTTI class name for the 0xe4-byte font object is present.

Its nonzero-size branch converts the double at +0x10/+0x14 with 00d83c90 and calls 006b9ee0; the explicit-dimension branch shifts dimensions by six and calls 006b9f60. Default DPI lookup is in 004549aa: when requested sizes are missing and flag 0x1000000 is set, it calls GetDC/GetDeviceCaps for 0x58/0x5A; otherwise it uses 0x48. It then scans entries and calls virtual slot +0x24.

The wrapper 00454b11 preserves the resolver receiver in ECX, zeros a two-word local, and passes its address as the fifth outgoing stack argument. Raw bytes resolve the disputed FSTP: fstp dword ptr [esp] replaces the immediately preceding pushed ECX slot with the float argument; the earlier pushed local address remains intact. 004549aa reads that pair through param_6. The zero pair's intended role is unknown.

00454cee uses the full descriptor comparator 004513d5 (both strings, float, and integer fields); 00454d5a uses the name comparator 0045149b. 004535f9 draws a glyph through the renderer. 00454bed prepares four callback pointers and two zero words, then passes the table to 006ba990 for immediate processing of nested data at *( *(this+0x1c)+0x54)+0x6c; its return is ignored. The helper invokes callback entries during its loop, so 00454bed does not register or store the table. It then applies an offset through 004524c9 and returns success/failure after releasing two state blocks. The rendering/font role is inferred from the coordinate callback 00454bb7 and surrounding GFC font code; no class RTTI was found.

At 00454bb7, x86 bytes DD 05 load the 8-byte coefficient at 017641b8. The qword bytes decode to double 1/64. Both 32-bit pair components are integer operands, and the scaled results are stored as floats before 004544f8 appends them to the destination passed in ECX. This is one callback supplied to 006ba990; the semantic meaning of the resulting pairs remains unknown.

00453284 also uses a hidden thiscall receiver: bytes preserve destination this in ECX and push the source for 0048185c. Separately, it tests the source's +0x60 pointer, invokes that pointed object's vtable slot +0xC if non-null, then copies the pointer to destination +0x60. The virtual slot's meaning is unproven.

00456d8c preserves the vector receiver in ECX and pushes only its stack argument to 00456887; that stack value is the requested size, not the vector pointer. The wrapper exits with ret 4.
