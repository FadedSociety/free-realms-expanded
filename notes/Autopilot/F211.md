## Threat note (secure-code-guardian)

Attack surface: a hand-edited/replayed character save under `kart_entry.race.weapons`, and the
client's 33/x / 33/7 frames. The new `save_decision_eq` methods are **only** the save-request
decision; they adopt nothing and never validate a save. `KartService::restore` still uses strict
structural equality and `WeaponState::validate_for`, so a save whose weapons differ from default
only by a nonzero clock is still refused (`CorruptSnapshot { field: "weapons" }`, existing test
passes). The clock is not client-settable: no packet path assigns it, only the server racing tick
stamps it, and `validate_for` bounds it to the race window on restore. Excluding `observations` and
`weapon_pose` from a save request is F207's existing rule; both remain persisted, the restored
observation count still bounds a flooded client, and the restored pose still places its next weapon
observation. Suppressing a save for a session-local difference cannot mint a coin, item, id, reward
or eligibility: those fields are compared by the exhaustive destructures, and both the finish payout
and reward claim paths are unchanged (the finish test still asserts the 40-coin grant exactly once).
No new refusal path was added, so no refusal can consume state. The new test content is synthetic;
no player names or chat text were added.
