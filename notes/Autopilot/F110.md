## Security threat note

A hostile client can send an arbitrary `26/13` profile id, repeat `26/10`
trainer choices, or replay requests after an error. The server rejects ids that
are not unlocked, stages selection and learning on a clone, validates every
resulting attachment slot before committing, and never accepts a client item,
reward or impact count. A failed grant drops the clone; the shared NPC menu is
consumed only after a committed change, so repeated refusals cannot unlock
items, move quest progress, or leave a half-applied job. Starter grants reuse
owned definitions and never create a sellable duplicate.
