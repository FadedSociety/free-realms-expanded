# T872 - house visits: a friend enters your lot, shares its instance and sees your edits live (lead build)

Lead build (The owner 2026-10-28: "Finish up housing"). The house directory (T562, T563) waits on this.
Paths are under `prototype/osfr-tools/`.

## What changed

- **One lot, one instance.** `InstanceKind::House { house_guid }` replaces the unused `House { owner_id }`.
  `World::prepare_house_membership` joins the instance already keyed by that house in that zone, or stages a
  new one; a seeded scene keeps its public instance. The gateway calls it when a house scene is staged with
  no other target (`Gateway::visiting_house`), so an owner and their visitors share one instance and see
  each other through the ordinary player code.
- **Another player's lot, served to a visitor.**
  - Before a message is handled, `bin/osfr_gateway/house_visits.rs::admit` finds each 127/19 (enter) and
    127/14 (list houses) in it. Each lot that request names (by lot guid or owner guid) is copied from the
    owner's online session (`Gameplay::own_house_lots`) into the visitor's staged gateway
    (`HousingService::admit_foreign_lot`).
  - The copy is rebuilt with a restore's checks (`Housing::admit_lot`), and every permission on it is
    capped at visiting, so it is read-only.
  - It is never saved: `state()` skips foreign lots. It is dropped on leave, `end_visit` and reconnect, and
    when the visitor enters another lot.
  - `lots_of` now reads every lot the service holds, so a 127/14 for another owner lists the copies.
- **Who may enter.**
  - The service's existing `can_visit` decides: the owner, or a level-1 permission entry on an unlocked
    lot.
  - A friend of the owner (the owner is on the visitor's friends list, `SocialService` profiles; reference
    HouseAccess, facts only) gets a visit pass and an unlocked flag on their copy only.
  - Anyone else is refused until the directory's publish (T562).
- **127/46 on a refused enter.** `ServiceError::enter_failure` maps the refusal to the client's code: 1 when
  the lot is unknown here, which means its owner is not online and no copy was admitted; 3 for a missing
  scene; 2 otherwise. `housing_service::enter_failed` builds the packet (reader `0x00ab9080`: one u32 that
  clears the enter busy flag). Before this a refused enter was a chat line only, and the client stayed
  busy.
- **Live edits.**
  - An owner's lot edit that changes the lot emits a `HouseBroadcast`: the house guid, the new lot snapshot,
    and the public packets (127/40, 127/41 and 127/51 records, plus the fixtures' 35/2 and 35/3).
  - `Outcome::absorb` and the gateway's bundle loop merge two edits of one lot in order
    (`HouseBroadcast::merge`).
  - After the commit, `house_visits::fan_out` replaces each visitor's copy and sends them the packets
    (`Gameplay::visit_update`). A visitor whose lot scene is still loading gets them appended to the packets
    sent after the load, because the client needs 127/28 before any 127/4x.
  - Owner-only replies stay with the owner: the item list, house info, the place answer, denials and
    inventory.
- `tests/housing_session.rs`: three new tests, and one updated (see below). `src/world.rs`: one test.
  `src/gameplay/content_reload.rs`: the absorb test names the new field, plus a merge test.
  `tests/world.rs`: two fixtures renamed to `house_guid`.

## (R) rules and open gaps

- The friend rule and the "published and unlocked" rule are the reference's (HouseAccess), not client
  evidence. Publish is T562.
- Offline owners are a follow-up: no copy can be given, so the enter is refused with code 1.
- Lock toggle 127/11 and sending visitors out, invites (127/15/16/47/48), random neighbour (127/21) and
  the members-only flag are follow-up briefs.
- A visitor's copy is replaced on every owner edit. A lot is at most a few hundred fixtures (the lot cap),
  rebuilt once per edit per visitor.

## Threat note

- The visitor never names an owner session or a lot that the gateway trusts. The lot copy comes from the
  owner's own server-side state.
- The service, not the client, decides entry (`can_visit`), and the friend list is server-side.
- A copy cannot be edited: permissions are capped and `can_enter` needs level 3 or the owner. So a visitor
  can neither place their furniture into an unsaved lot nor change the owner's lot.
- The owner's real lot is never written by a visitor's session. Copies are dropped on every exit and are
  never persisted.
- Packets to visitors are the owner's public records only, never their bag or house info.

## Checklist

1. **A refusal changes nothing.** A refused enter (stranger, code 2; offline owner, code 1) moves nothing
   and saves nothing (`a_stranger_is_refused_with_127_46_and_nothing_is_kept`). A visitor's decorate request
   is refused with 127/53 and changes nothing (both visit tests). `refused_requests_change_nothing` still
   asserts state equality.
2. **Rollback covers all state.** The copy is admitted into the *staged* gateway, so a refused or failed
   dispatch discards it with the clone. The service's `foreign` set lives in the cloned `HousingService`.
3. **Apply deltas.** No snapshot is restored over live state. A visitor's copy is replaced wholesale by
   design (it is a read-only mirror). The owner's lot, bag and pose are never touched by a visit.
4. **Busy rules are mutual.** Entering another player's lot goes through the same `Occupation::Housing`
   check as one's own (`handle_housing`); no new activity was added.
5. **Every entry path is gated.** The only way in is 127/19 through `HousingService::enter`, then
   `can_visit` on the copy. 127/14 copies only list lots.
6. **Reachable in production and tested through it.** The tests drive the real `Gameplay::handle_in_world`
   and `initialize_world`. The gateway hooks are in the real dispatch and commit path. There is no
   two-session gateway test, because the bin's session rig loads no housing content (lab fixtures only);
   see "open gaps".
7. **Survives reconnect.** `abandon_house_for_reconnect` ends the visit, and `end_visit` drops the copy; the
   save holds the world pose and own lots only.
8. **Every exit path restores the player.** Leave sends the 35/3 for each fixture still standing in the
   refreshed copy (tested: `KIT_BLOCKS - 1` after the owner's pickup), then the world zoning.
9. **Economy safety.** No grant, reward, coin or item. A copy cannot be decorated
   (`a_copy_of_a_lot_is_read_only_even_for_an_editor`).
10. **Wire format matches the client reader.** 127/46 is one u32 after the opcodes (reader `0x00ab9080`,
    housing guide). The 127/40, 127/41 and 35/x packets to visitors are the owner's own encoded replies.
11. **Unique ids.** The fixture actor guids derive from the lot and fixture, so they are the same for the
    owner and visitors. Instance ids come from the existing allocator.
12. **Others see changes.** This is the point of the build: visitors get the owner's edits, and owner and
    visitors share one instance.
13. **Content works end to end.** Owner grant, enter and decorate; friend enters, is served the standing
    kit, gets the owner's pickup, and leaves (`a_friend_visits_sees_the_owners_edit_and_leaves_without_a_trace`).
14. **Values live in data.** No new tunables. The permission levels are the existing constants.
15. **Canaries break production code.** Four canaries, listed below.
16. **Hands off session plumbing.** No session creation or teardown change. One pre-handle hook, like
    `group_arena::Held`, and one post-commit fan-out, like boombox.
17. **One player's error never stops the server.** `admit` ignores undecodable messages, and a copy that
    fails to admit is skipped. `fan_out` stops sending to a visitor whose queue refuses and logs it.
18. **A type's rules live on the type.** `Housing::admit_lot` and `forget_lot`, and
    `HousingService::admit_foreign_lot`, `state()` and `end_visit`, own the copy rules.
    `World::prepare_house_membership` owns the instance key.
19. **Hot paths stay cheap.**
    - Every message passes `admit`, most of them movement. It first scans the message bytes for the 4-byte
      127/19 or 127/14 header (application payloads are verbatim slices of the message; no decompression at
      this layer). Only such a message is decoded, and only then are the online sessions scanned.
    - `fan_out` scans the sessions once per lot edit.
    - Membership looks up one instance by kind on a house entry only.
