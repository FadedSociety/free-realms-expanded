## Security threat note (secure-code-guardian)

The change is content/test only; the attack surface is the unchanged NPC/quest
path (26/8, 26/10, 26/6, 49/2, 49/14 plus movement).

- A hostile client can forge a `49/2` accept for the gated 3160004: refused by
  the prerequisite and `pending_offer` gate; the serialized state and save bytes
  are unchanged (tested).
- A forged `49/14` for any quest is refused unless that exact quest is
  `pending_turnin` and complete; a replay after completion pays nothing because
  the reward uses the idempotent `quest:<character>:<quest>` grant key (tested).
- A client cannot claim a search objective: `visit_position` is not
  `client_reported`; only the server-validated pose reaches `on_location`, and
  the zone/radius are content rows.
- No client quantity or item id is read by this chapter. Reward rows are fixed
  content values bounded at load (`coins <= i32::MAX`, known job profile,
  positive unique objective ids, provenance required); the malformed-record test
  asserts each refusal reason at load. F288 corrected the earlier atomicity
  claim: the bind was not atomic (`saved_npc_quests.take()` ran before the
  fallible parse), so it now builds before replacing state, and
  `a_refused_rebind_keeps_the_bound_catalogue_and_saved_progress` proves a live
  catalogue and saved progress survive a refused bind and that a retry restores
  the progress.
- Refusals consume nothing: the open menu, pending offer and held end screen
  survive, and the wrong-NPC talk is now byte-snapshotted (tested).
