## Threat note (secure-code-guardian)
The leave request (127/10) carries no payload, so there is no client field to validate. A hostile client can
only leave its own session's visit: the actor guid is derived from the server-minted fixture guid (bit 55, which
`mint_fixture_guid` keeps clear), never read from a packet, so it cannot name another player's actor. A repeated
leave is refused by `NotInHouse` before any reply is built, and the refusal changes nothing. The 35/3 body has no
client data (submode 1, the derived guid, zeroed tail). The removal list is read from the lot the session
entered, and its size is bounded by `MAX_STATE_FIXTURES`; no filesystem write, item, coin, reward or role path is
touched. The removal timing/order is reconstructed (R); the bytes are the captured pickup shape.
