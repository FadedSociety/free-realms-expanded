# T312: credit a dungeon-completion quest when the fight is won

## Skills applied

- **Ponytail (full):** one field on the existing `EncounterOutcome`, one assignment in the existing win
  transition, one dispatch block in the existing `Gameplay::apply_encounter`, plus one line in the
  existing skill-outcome merge. No new module, packet, content row, saved field or selector. The
  hub-line cost was offset by deleting dead bindings/no-op work in `encounter.rs` (see Structure).
- **secure-code-guardian:** threat note below. A hostile client cannot report a win, an encounter id,
  a quest id or a count; the event is the server's own last-enemy HP transition and the quest engine
  caps the counter at the objective's required count.

## Result

A battle/dungeon win now reports its regional `CompleteDungeon` credit in the **win transition**, in
the same transaction that pays the battle reward, instead of only when the results screen closes.
`EncounterOutcome` gains `win_completed: Option<u32>`, documented next to `completed`; `completed`
still marks the results Close and drives the opening story destination. The Mongo chain's C1/C2
objectives therefore survive a disconnect/crash between the killing blow and Close.

- `src/encounter.rs`: added `win_completed` to `EncounterOutcome`; set it next to `phase = Won` and
  the reward push; `debug_win` now carries it out of its loop (the dev shortcut behaves like a real
  win); deleted two dead `let _ = …` bindings and a no-op `shrink_to_fit`, and folded the guide
  lookup into one let chain (same behaviour) so the hub stays line-neutral.
- `src/encounter/skills.rs`: `merge_skill_outcome` copies `win_completed`, so a job ability, DoT
  tick or power-up that lands the killing blow reports the win too (otherwise only the basic 26/10
  path would credit).
- `src/gameplay.rs`: `apply_encounter` emits `QuestEvent::CompleteDungeon` once from
  `result.win_completed`; the `result.completed` branch keeps `OpeningEvent::DungeonCompleted` and the
  zoning destination but no longer emits the quest event. Packet/reward order is unchanged (win
  reply stream and rewards are appended before the quest event).
- Tests: `tests/brawler_mongo_chain.rs` gains the loss/retry, two-player and replay tests and changes
  the two T252 "Close only" expectations; `tests/encounter_job_skills.rs` pins the DoT-win
  propagation; `tests/quest_content_goals.rs` updates its deliberate exit-only pin.

`debug_win` (`realm win`) does emit `win_completed` (propagated), so the developer route keeps the
same quest credit as a real win.

## Threat note (secure-code-guardian)

A hostile client can send `26/10` attacks, `36/10` abilities, `26/42` results Close, `41/108` Go,
`41/109` leave, `41/114` details and the ordinary `realm retry` chat command. It cannot:
- **Report a win or an encounter id.** `win_completed` is set only inside `strike_damage` when the
  server's HP transition kills the last standing enemy of an active dungeon; the id is the loaded
  content row (positive by `EncounterEngine::load`). There is no client field for either.
- **Credit an inactive or foreign quest.** The event goes to the session's own `QuestEngine`; the
  engine only advances an active, ordered, matching `complete_dungeon` objective, capped at its
  required count.
- **Double-credit or double-pay.** A replayed attack finds `enemy()` `None` once the phase is not
  Fighting; a replayed Close finds no active run; a second event at required is skipped. Tests 1, 3
  and 5 assert the counter, the saved state and the economy.
- **Turn a refusal into a mutation.** The gateway stages the whole `Gameplay` per application and
  commits only on success; `win_completed` is a value in that staged clone, never a shared
  `Rc`/`RefCell`, and it is not persisted. The event is emitted after the reward append in
  `apply_encounter`, so a failure would roll the whole turn back with the reward.
- **Gain rewards from it.** The completion event awards no coin, item or XP; the only payment is the
  unchanged battle reward and the later server-verified quest turn-in.
