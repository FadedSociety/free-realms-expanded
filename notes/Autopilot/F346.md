## Client evidence (IDA, re-checked for the moved harness)

- 26/3 payload reader `00a9ef10`: `sub_A9EF10(this, a2)` calls `sub_A9CB50(a2)`
  (which reads two u16: family 26 and subtype, four bytes total), then stores
  the first payload dword at `*(this + 16)` - the body id the display routine
  `009f5ae0` passes to `Global.Text.<id>`. The shared `gameplay_talk_body`
  reads that dword at packet offset 4 (after the four-byte header); T315
  already re-checked handler `00aa12e0` and display `009f5ae0`.
- 26/8 constructor `008b6bc0`: `sub_8B6BC0(this, a2, a3, char a4)` writes
  `&off_18024A0`, target low/high dwords (`a2`,`a3`) at +16/+20, bool at +24.
- 26/10 constructor `00a36f80`: `sub_A36F80(this, a2, a3, a4)` writes target
  low/high at +16/+20, i32 choice at +24.
- Base constructor `008a2820`: `*(this + 1) = 26` (family) and `a2`/`a3` at
  +8/+12 (subtype), the header `sub_A9CB50` reads back as two u16, so
  `[26, 0, 8, 0]` / `[26, 0, 10, 0]` little-endian is the wire prefix the
  builders produce. No note contradicted IDA.
