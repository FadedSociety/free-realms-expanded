## What the range is

**1. GFC Win32 window-driver layer (0044e1d3 - 004505cf, `engine.gfc.win32`)**

Source fragments of SOE's GFC ("Game Framework Core") Win32 driver, compiled into one
translation-unit cluster:

- Native window class: `RegisterGFCStdWindowClass` (0044f3ab) registers the ANSI and
  wide `GFC_StdWindowClass` class with `WNDPROC` = `Win32WindowProc` (0044eaa3) and
  `cbWndExtra = 4`; `WindowWin32CreateNative` (0044fd43) turns a GFC window object
  into an HWND with `CreateWindowExW`/`CreateWindowExA` against that class, applies
  `ShowWindow`, `WM_SYSCOMMAND` (0xF020/0xF030) and `DragAcceptFiles`.
- The window procedure is an object dispatcher: it stores the object as
  `GWL_USERDATA` on `WM_NCCREATE` and forwards every message to virtual slot +0x128
  of the object, keeping a +0xE8 re-entrancy counter.
- Object classes and their vtables (all without RTTI names, sizes from the class-ops
  allocators): window object 01763dd0/01763dcc (0x110), child window
  01763cd0/01763d40 (0xA8), second child 01763f70/01763fdc (0x158), top window
  01763f00/01763efc (0x150), window manager 01763d48/01763d44 (0x80, base chain
  reaches the `GWindowManagerWin32` vtable 01762c98 via 004474fc/004502c8), small
  helper 01762f68 (0x34), generic 0x14-entry handle table class 01763ba0 (0xC4).
- Class-ops protocol (repeated in ten functions, e.g. 0044f06c, 0044f7bc, 0044f9b8,
  0044fa68, 0045018a, 00450237, 004504e9): action 0 = reset/construct in place,
  1 = copy-construct into given memory from a prototype, 2 = allocate (size constant)
  then construct, 3 = allocate then copy-construct, 4 = run destructor body,
  5 = call the scalar deleting destructor (vtable slot 0 with flag 1). The
  companion factories 0044f6c5/0044f820/0044facc/0044fc64/0045021b are the
  dtor+free thunks.
  The action set varies per class: 0044fa68 and 0044f7bc have no action-0/2 branch
  (their action 2 falls through to `return param_2`), while 0044f06c/0044f9b8/
  0045018a/00450237/004504e9 do implement 0..5.
- Manager-side plumbing: `WindowAttachOwner` (0044f51f) links a window to either an
  owner interface or an ID-bearing record (0044eec4 `AllocateAndRegisterIdEntry`,
  generated id from 0044b296 and registration through 0044dd2e); the record stores
  three supplied values and one generated id, not four caller values, `WindowAttachAndCreateChildren`
  (0044fc80) registers the class, attaches the window and materialises its two child
  objects (0044fbe6 kind 5, 0044f8b9 kind 4), `WindowCreateChildByKind` (004503b4) uses param_3 directly as the kind when param_2 is zero; otherwise it takes the kind from the looked-up record. It creates kind 2/4/5 objects through 0045035d/0044f83c/0044fae8, caches them in +0xE8/+0xF0/+0xEC, and passes the address of the stack slot holding the pointer to FUN_0044ddfb with receiver +0x11C.
- Monitor enumeration: 0044e41b calls the resolved `EnumDisplayMonitors` pointer
  DAT_01bc4480 with the callback `CollectRectWithReducedEdges` (0044e3e6), falling
  back to FUN_0044cb77 with the window rectangle; the surrounding user32 pointer
  globals (DAT_01bc4480/4490/4494/44a8/448c) are resolved by the loader at
  004409bc/004419xx (outside this shard).
- Clipboard: `ClipboardWin32ReadFormats` (0044e4e8) walks `EnumClipboardFormats`,
  maps format ids through the Win32_TEXT/UNICODETEXT/BITMAP/DIB/RIFF/WAVE table
  (00440f73) and exposes the data as GString/bitmap objects - the
  `GClipboardAccess_Win32_TEXT` / `GClipboardAccess_GStringObject` bridge whose class
  names live at 0x17631cc/0x17633ac.

**2. Scaleform / FreeType2 font device (00450697 - 00452b79, `engine.gfc.font`)**

- Registration: `RegisterGFontDeviceFT2` (00450832, dotted registry key `.GFontDeviceFT2`), `RegisterGFontDescFT2`
  (00450a32) and `RegisterGFCFontDeviceInterface` (00452b79) which binds
  `GFC_Draw_FontDevice` to `GFC_Interface` for "Scaleform FreeType2 FontDevice",
  version "1.0.0".
- The device object (vtables 017642f0/017642e8, ctor 00452676, dtor 00452724,
  instance counters at DAT_01bc4574/DAT_01bc4578) plus a font descriptor record
  (copy ctor 0045257b: two wide strings + metric fields) plus the `FontInfo` property-set attempt (00450a65, FUN_00490322; its return reports only the initial validation result) and its reader (00452626, load direction through FUN_00490072 into this+0x24).
- Glyph pipeline: `LoadGlyphMetrics` (00450af3) resolves a char code
  (FUN_006ba1d0), loads the glyph (FUN_006bd770, flags 0x808), reads the face's glyph
  slot (FUN_006c0770) and writes eleven fixed-point fields into the caller's record
  (the row count from glyph+0xC is rounded (x+0x8000)>>16+1, the others >>6);
  `ComputeGlyphBlitRect` (00452762) reads the pixel-format byte from the *source*
  descriptor at param_4+0x12 (the block that also supplies the source base +0xC and
  pitch +8), adjusts the source width for formats 1 (round up to /8), 4 (round to
  even) and 5 (divide by 3) and the row count for format 6 (divide by 3), then clips
  against the destination via virtual slots +0x158/+0x15C and returns 1
  unconditionally (the record is only filled when the clip test passes).
  `DispatchFormatWriterOrBlit` (0045293c) reads source format at param_3+0x12. Format 1 dispatches to the mask writers by destination bpp from slot +0x160 and returns without the blit call. Format 2 expands or copies for destination bpp 32/8 and returns; other format-2 bpp values plus formats 3/4 call slot +0x1BC with flags 0x600000. The guarded local_34 release is unreachable because that pointer stays null. The mask writers (00450bdf-00450f3c) read mask data and write destination pixels.
- Block container: `PointerArrayGrowAndAllocSlab` (00452dad) grows the container's
  block pointer table (the grow test compares the requested block index with the
  capacity at +8) and reserves one 0x800-byte block per call; the accepted sibling
  code indexes 256 8-byte pair records per block (00453739/004544f8), so these blocks
  carry pair records rather than mask data. `OffsetGridPoints` (004524c9) translates
  batched 8-byte point records through a page table at +0x14.
- Scaled point appends (corrected in review round 2 - these are not GFx rect
  setters): 00450fc8 scales one point by the global float _DAT_017641b8 and appends
  it through FUN_004a74ab (which advances a 0x18-byte record cursor and appends the
  pair via FUN_004544f8); 0045100c/00451063 scale two points (second taken from
  param_2 / param_3 respectively) and pass them to FUN_004aaece, which either extends
  the last record (FUN_004a7515, gated by FUN_004844ab against the global threshold
  _DAT_0176ab30) or appends the pair. Same family as the accepted ScalePairAndAppend
  00454bb7.

## Cross-function findings (useful to other shards)

1. **Class-ops dispatch shape.** `__thiscall(class, action, instance, proto)` with
   actions 0/1/2/3/4/5 = reset, copy-ctor, new, new+copy, dtor body, scalar delete.
   The allocation-size constants give class sizes even where RTTI is missing.
2. **GFC heap tag pair 0x56471e89/0x9fe1234a.** Written by 25+ functions elsewhere in
   the binary (00405ca7, 00406346, ..., 00440330, 00440aa5, 004410cf, 00442154,
   00442290). It is a reliable marker for "GFC class instance allocated here".
3. **String family.** FUN_004e884e = wide-string copy-construct from
   `{int len; wchar data[]}`, FUN_004e889c = wide-string from literal (len < 1 means
   measure), FUN_004e8f3d = wide-string append, FUN_004dc61b = wide-string destructor
   (frees unless the pointer is the global empty string). The char-string siblings
   are FUN_004e4e15/FUN_004e4e6d with the empty default &DAT_01bc7e28; the empty
   wide-string default is &DAT_01bc7e20. This confirms and narrows the S0001 note
   that called DAT_01bc7e28 a "default object": it is the empty char string constant.
4. **Offset collision warning:** +0xE4 holds the HCURSOR in the 01763dd0 window
   class (0044e915) but a boolean "active/initialised" flag in the 0x150 top-window
   class (0044f6e1, 0044eec4, 0044efb1, 004503b4). Do not merge those two classes on
   field offsets alone.
5. **Window child slots.** A constructed window owns two child window objects at
   +0x50 (0x158 class) and +0x54 (0xA8 class); a native window additionally creates
   them from 0044fd43. Their exact input roles (mouse/keyboard ports) are not yet
   proven.

## Independent review round 6 corrections

`0044efb1` collects addresses of element+8 fields into the supplied vector for kinds 2/6 and kinds 4/5 with a zero +0x10 field; `0044df6b` is a vector append helper, not a release routine. `004503b4` uses param_3 as the kind when param_2 is zero and performs lookup only for nonzero param_2. `00450832` passes the exact dotted key `.GFontDeviceFT2`; `00450a65` returns its initial validation result even if `00490322` fails. `0044f2a0` remains speculative because its wrapper has no callers. No `DAT_01b839d8` stack-cookie expression occurs in the S0016 pseudocode; raw bytes for 004503b4 confirm ECX=this+0x11C and the actual pushed argument is the address of its local pointer slot.

The 0x24-byte range helpers were rechecked through their x86 call setup and `004b2882`: `00452372` copies one shared value across destination elements, `004523de` copies a forward source range, and `0045245f` copies backwards. The EH-unwind reference on `00452372` does not make its element-copy body a destructor. `00451d1b` also handles end by selecting the rightmost node; `00452004` takes the right child, so its evidence now says successor.

`0045293c` was checked against its branch bytes. Format 1 dispatches to a mask writer without the +0x1BC blit; format 2 copies/expands and returns directly for destination bpp 8/32, while other format-2 bpp values and formats 3/4 take the blit branch. `local_34` remains null, so no temporary release occurs. This branch detail narrows the independent review's broad 'formats 2-4 blit' summary to the actual bpp-specific paths.
