# F144: T109 review blockers

## What changed

1. **BLOCKER, unbounded definition replies.** `CoinShop::item_definitions` no longer collects
   every requested record in an intermediate owned `definitions` vector and then batches it.
   One pass now collects the known ids, the `complete` flag, the total record length and a list
   of borrowed record references; the whole 165/2 request is refused with the normal empty
   incomplete 165/3 answer when that total exceeds `MAX_DEFINITION_REPLY_BYTES` (4 MiB), before
   any record bytes are copied. An accepted request then encodes one bounded 35/37 batch at a
   time from those references. The shared 165/3 builder is now `definition_outcome`.
2. **BLOCKER, cumulative bundle responses.** `Gateway::handle_at` checks the accumulated,
   already-wrapped reply bytes at the start of every event and once after the loop for a
   `[0, 25]` bundle. A bundle whose replies exceed `MAX_BUNDLE_REPLY_BYTES` (8 MiB) returns
   `invalid("bundled application response exceeds the outbound budget")`; the staged gateway
   and gameplay are dropped and the server step ends only that session. At this commit the
   staged `Gameplay` still shared `NpcInteraction` through `Arc<Mutex<_>>`, so the open menu did
   not roll back; F155 (`1e57fbe`) made it an owned `Gameplay` field. F179 counts the replies
   `commit_outcome` adds, carries the budget across the combat split, and adds the
   `a_refused_bundle_leaves_the_npc_menu_closed` regression.
3. **BLOCKER, missing checklist.** `notes/Autopilot/T109.md` now carries the 19-item checklist
   and the skill-use/threat note required by the autopilot brief.

## Reconstructed rules (R)

- One 165/2 answer may carry at most 4 MiB of definition records, and one request may name at
  most 4,096 ids. Both are server memory policy (R), not recovered client limits: the client's
  static item table is a `HashList<ItemDefinitionMetaData,4096,1024>` (vtable `01833bd8`), but
  the 165/2 reader (`00c75580`/`00c75620`) does not cap the requested list.
- One bundled ([0, 25]) request may stage at most 8 MiB of replies, below the sender's 32 MiB
  queue. A request over that bound is refused before commit. The combat-bundle split path
  commits its ordered children one at a time, so it is bounded by the per-request 4 MiB cap and
  the 32 MiB sender queue; F179 adds the cumulative check the split path was missing.
- 165/2 and 165/3 wire layouts are unchanged: `i32 count` then `count x u32` ids
  (`00c75580`, `00c75620`, sender `00c76b10`), answered by `u8 complete`, `i32 count`,
  `count x u32` (`00c74e40`, `008e8230`). IDA was re-read on 2026-10-18.

## Checklist

1. **A refusal changes nothing.** The over-budget 165/2 test and the over-budget bundle test
   both compare `Gateway::snapshot()` before and after; the bundle test also requires the
   refusal error. The 4 MiB refusal is staged only inside the read-only handler, so no clone
   needs restoring. T109's own refusal tests still pass.
2. **Rollback covers all state.** The reply budget itself is a local read of
   `Gateway::handle_at`'s staged clones. At this commit `NpcInteraction` was still
   `Arc<Mutex<_>>` (shared), so a refused bundle could leave the NPC menu open; F155 made it an
   owned `Gameplay` field, and F179's `a_refused_bundle_leaves_the_npc_menu_closed` proves the
   menu rolls back with the refused bundle. T109's `CoinShop` remains inline in `Gameplay`.
3. **Apply deltas, never old snapshots.** Not applicable to this diff: it neither grants nor
   removes items or coins.
4. **Busy rules are mutual.** Not applicable: 165/2 is a read-only search and starts no
   activity, so no `Occupation` row changes.
5. **Every entry path is gated.** The budget is inside `item_definitions`, the one handler for
   165/2; the graph shows both callers (`CoinShop::handle`,
   `NpcInteraction::handle_coin_store`) reach it through `handle`. Both the service and gateway
   tests exercise it.
6. **Reachable in production, tested through it.** The tests send real tunneled application
   packets and bundles through `Gateway::handle_at`; no internal helper is called directly.
7. **Survives reconnect.** Not applicable: definitions are content and no state is created.
   T109's sale history remains session-local (open gap there).
8. **Every exit path restores the player.** Not applicable: no location, activity or lock is
   taken or changed.
9. **Economy safety.** Not applicable beyond T109: no coins, items or rewards are touched;
   the snapshot assertions prove it.
10. **Wire format matches the client reader.** Unchanged. 165/2 fields are cited from IDA
    `00c75580`/`00c75620`; 165/3 from `00c74e40`/`008e8230`. The multi-batch test compares the
    exact catalogue record bytes and the exact 165/3 id list.
11. **Unique ids.** Not applicable: no instance, GUID or lifecycle ids are allocated.
12. **Others see changes.** Not applicable: no public actor, outfit, mount or job change.
13. **Content works end to end.** The multi-batch test asserts every requested row is delivered
    before the answer; the positive control asserts an under-budget request still delivers.
14. **Values live in data.** The new numbers are protocol/memory caps, like the existing
    `MAX_*` packet limits, not gameplay tuning; they are server policy, accepted by the lead on
    2026-10-19 (F179 findings 1-2). T109's `buy_back_window` stays in stores.json.
15. **Canaries break production code.** Both canaries changed production constants (not test
    code) and failed the matching test before being reverted; results are under Gates.
16. **Hands off session plumbing.** The gateway change is one reply-budget check inside
    `handle_at`; session creation, teardown and save ordering are untouched, but the check
    changes when a staged bundle is discarded (the server ends that session), so the policy
    needed lead sign-off, which the lead gave on 2026-10-19. F179's cumulative check sits in
    `commit_outcome` before commit and does not change creation, teardown or save ordering.
17. **One player's error never stops the server.** A single 165/2 refusal returns `Ok`; an
    over-budget bundle returns `Err` from `handle_at`, which the step loop turns into
    `end_session` for that player only. No shared tick work changed.
18. **A type's rules live on the type.** Not applicable to the caps: they are protocol limits,
    not fields whose persisted/compared/sent/reset status this change decides. The fields it
    does read (`CoinShop` inventory and sale deque) are already inline `Gameplay` fields, so
    cloning `Gameplay` decides rollback for them. F179 adds no persisted field.
19. **Hot paths stay cheap.** `handle_at` adds only the bytes appended since the previous event
    (one pass over the new replies, never a rescan of earlier batches); `commit_outcome` checks
    the reply set it already holds once per bundle dispatch. A non-bundle dispatch pays one
    `Option` test, and ticks pass `None`. F179's notes record the same cost.
