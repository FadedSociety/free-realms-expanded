  literal string (`npc_name`) further down the body. The pickup's literal was
  the kind id, which is exactly the reported plate. Native text check

  decided too.
- **`0x00904300`** (`41/125` handler, decompiled this run): builds
  `RespawnWindow:DisplayRespawn(timer, isOverworld, reviveCost)`; the cost
  argument is passed straight through, with no zero/sentinel branch.
  `0x008d6730` consumes the two trailing i32s (timer then cost; the field order
  remains inferred, see piece 058).
- **`lab/decompiled/client-ui/ScriptsBase.lua` line 6430**
  (`RespawnWindow:DisplayRespawn`): sets the wallet with
  `setCoinAmount_lua(Ui.GetPlayerCoinCount())`, the price with
  `setReviveCost_lua(reviveCost)`, and calls `showTwoButtons_lua` only for the
  overworld flag.
- **`revive_window.gfx` `frame_1/DoAction.as`** (piece-037 export
  `lab/reports/piece-037-20261009T035019Z/revive-window/`):
  `showTwoButtons_lua` runs `if(m_coinWallet < m_reviveCost)` -> grey the paid
  button and attach no listener; otherwise enable it and attach the listener.
  The safe button label is always "Revive at safe location: Free".
  `FRIconButton.enable(false)` only sets alpha 50; it never hides the button.
  `Ui.GetPlayerCoinCount` (`loc_C14E30`, disassembled this run) is the player's
  wallet dword, so `m_coinWallet >= 0` always.

**IDA contradicts the old note (IDA wins).** `piece_058.rs` said cost 0
"disables the paid path". The client comparison enables it at cost 0 (0 < 0 is
false) and shows "Revive here: 0 coins". No cost value *hides* the paid button;
only a price above the wallet *greys* it. The fix therefore picks the retail
1,000-coin price (`revive_window.gfx` editor default `setReviveCost_lua(1000)`;
wiki Sunstone Valley: 1,000 coins for the spot revive) instead of a sentinel
that leaks an absurd number into the label. The correction is in the
`RespawnWindow.revive_cost` doc comment.

## Security note (secure-code-guardian)

Threat model for the touched paths:

- **Hostile client input:** nothing new is read from the client. The pickup
  name/model/scale come from server-loaded `power_ups.json` (admin/dev reload
  only); the kill is credited by the server's own damage accounting. The
  `41/125` price is a server constant, and the client cannot choose it. The only
  client-reachable path touched is `41/122` paid/free revive: a hostile client
  can set the bool to 1, but `resume` refuses it before any health, coin,
  position or window state is committed (the state is compared in the test),
  and it cannot name a price, place or wallet. Malformed bodies (wrong length,
  flag > 1) still return `Err` with no mutation.
- **Why it is refused:** the paid path has no payment sink; charging is never
  invented, so a client-reported "paid" click can never mint a revive or spend
  coins. Free revive is the server's safe checkpoint only; the client sends no
  coordinates.
- **No new trust boundary**, no names/chat text, no secret, auth, role or
  session code touched, and no client-supplied quantity or id is used for a
  grant.

## Checklist (19-point review)

1. **Refusal changes nothing.** Applies to paid `41/122` (unchanged).
   `paid_revive_is_refused_and_the_window_comes_back` snapshots
   `e.state().clone()` before the refusal and asserts equality after; the
   gateway route test asserts health 0 and the window resent. Both ran green.
2. **Rollback covers all state.** Not applicable: no transaction, clone or
   shared side table was changed. The new values are computed from immutable
   content at the spawn/offer site.
3. **Apply deltas, never snapshots.** Applicable and unchanged: the paid
   refusal does not touch coins/health/position (state equality test above); the
   free revive still applies the current server checkpoint, not a client value.
4. **Busy rules mutual.** Not applicable: no activity was added.
5. **Every entry path gated.** The price is produced by the single
   `respawn_window()` helper, so every offer path (field damage, tick,
   instance tick, zone-ready) carries the same 1,000; the paid request is gated
   only by `resume`. Tested through the engine knockouts and the real gateway
   route (`gateway_routes_resume_for_a_held_world_knockout`), plus the reload
   test.
6. **Reachable in production, tested through it.** `power_up_drops` kills
   through `EncounterEngine::attack` (the production strike path) and parses the
   actual `35/2` reply; `free_revive` drives `handle`/`Gateway::handle_at` and
   the shared-field damage path. No internal copy of the logic is tested.
7. **Survives reconnect.** The respawn window is intentionally not persisted;
   `a_knockout_saved_to_disk_wakes_up_on_reload` covers the saved-zero-health
   reload. The pickup is session-only by design (`an_unclaimed_drop_lapses`,
   zoning tests). Unchanged and green.
8. **Every exit path restores.** Unchanged: free revive, 15 s fallback, lost
   instance exit, developer heal are covered by the existing green suite.
9. **Economy safety.** The price is display-only; paid revive is still refused
   with zero coin movement (state equality), no item/coin grant is added, and
   the pickup is applied from the server's own position and stored kind. Tests:
   paid refusal + pickup suite.
10. **Wire format matches the client reader.** AddNpc: name id (reader
    0x00921a10) and literal name, byte-checked by `parse_add_npc` in the new
    test; 41/125: bytes 12..16 timer and 16..20 cost, byte-checked in the new
    test, matching handler 0x00904300 and reader 0x008d6730.
11. **Unique ids.** Not applicable: pickup GUIDs still come from
    `PICKUP_GUID_BASE | serial`; no id was added or reused.
12. **Others see changes.** Not applicable: pickups are personal to the killer
    (existing test `every_participant_gets_their_own_pickup_and_nobody_sees_anothers`);
    the window is per-session.
13. **Content works end to end.** The pickup still spawns with its model,
    scale, position and neutral disposition (existing model/position tests) and
    the `41/125` window still appears with the retail price and the free button.
    The new tests assert the emitted outcome, not a flag.
14. **Values live in data.** The revive price stays one `(R)` constant, which
    the brief allows; it is a global rule, not per-zone tuning, and the client
    only labels the button with it. No timeout/window/cap constant was added.
    If the price is ever per-realm, the content-package migration is the trigger
    to move it into data.
15. **Canaries break production code.** Both canaries changed
    `src/encounter.rs` (not the tests) and the new tests failed, then the code
    was restored (results above).
16. **Hands off session plumbing.** Not applicable: no session
    creation/teardown/transaction/save-order change.
17. **One player's error never stops the server.** No new per-player fallible
    work in the tick; the new name is an empty `String` (infallible) and the
    window uses a constant. Existing isolation is untouched.
18. **A type's rules live on the type.** `Actor.name_id` now documents the
    client rule (0 shows the literal, so no-name actors leave both empty); the
    pickup caller points at it via "(pickups below)". `RespawnWindow.revive_cost`
    documents the client's grey-below-cost rule (the piece that the old note got

19. **Hot paths stay cheap.** Per tick: no change. The only difference is at a
    pickup drop (rare): `String::new()` instead of `kind_id.to_owned()`, i.e.
