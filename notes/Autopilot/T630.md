# T630: collection reward items with no definition (bundle item gate)

## What changed

- `make_bundle.py` failed its item gate at tip `1a33a76`: `collection_catalogue.json item_definition_id: 3 of 1555 item
  ids have no definition (e.g. [12410, 38816, 38817])`. All three are **reward** items (kind 1), not entry links:
  collection 311 (3795 "Sunstone Valley Rare Exploration") 38817, 312 (3797 "... Elite Exploration") 38816,
  313 (3802 "Sunstone Valley Explorer") 12410.
- `src/collection_catalogue.rs` `RewardItem`:
  - `item_definition_id` is now `Option<i32>`: the item granted, which must have a definition.
  - new `captured_item_definition_id` (omitted when absent): the captured `+0x24` id, kept only when it is not
    granted. Field docs on the type say which id is granted (rule 18).
- Generator `tests/collection_catalogue.rs` `generate`/`collection` (the file is generated; the drift oracle forbids
  hand edits): a kind-1 row whose captured item Legacy does not define is bound by the row's own display name
  (`+0x10`) to the single Legacy item with that `NameId`, else to no item. The gap list
  `reward_items_missing_from_legacy` still lists the captured ids `[12410, 38816, 38817]`.
- Regenerated `data/content/collection_catalogue.json` (`OSFR_REGENERATE_COLLECTIONS=1`): exactly three rows change.
  - 313: `item_definition_id` 79446, `captured_item_definition_id` 12410 (coins 12 unchanged).
  - 311: `null`, captured 38817 (token 654 unchanged). 312: `null`, captured 38816 (token 655 unchanged).
- New test `every_bound_item_has_a_runtime_definition`: every entry link, reward item and female variant in the
  committed catalogue has a definition in the round70 runtime item catalogue (the same file the bundle ships),
  and pins the three rebound rows. A future capture with an undefined id fails here (full suite), or earlier in
  the pinned `reward_items_missing_from_legacy` assertion, not at bundle time.
- The item gate (`content_check.item_coverage_errors`, `bundle/item_content.py`) is unchanged.

## Evidence

- **No definition source has 12410, 38816 or 38817.** Not in the runtime catalogue
  `lab/reports/round70-native-20261016T061000Z/content/item-catalogue.json` (58,835 ids) nor its `inventory.json`
  (1,649); not in Legacy `ClientItemDefinitions.json` @ `9e082025` (58,795 rows), OSFR
  `ofrserver/Customize/ClientItemDefinitions.json`, or Sanctuary-main `ClientItemDefinitions.json` (58,834). The
  client ships no item table but `CharacterCreate/ItemDefinitions.txt` (none of the three). The only other hits in
  client Resources are unrelated string/image ids (`CodeStringMappings.txt` Cooking1/2, `ImageSetMappings.txt`).
  The capture itself is right: OSFR `PacketSendSelfToClient.json` has the same three reward rows.
- **What the client does with the row.**
  - `0103c460` reads the common part: byte `+0xc`, icon pair (`008caaa0`), then `+0x10`, `+0x20`, `+0x24`, `+0x28`.
  - `0103b4a0` (kind-1 vtable `0187e234`) prints `Item=%d` from `+0x24`: the item id.
  - `00c33430` (`RewardEntryDataSource`, built for `BaseClient.CollectionData.Reward` + `.Entries` by
    `009931e0` -> `00c33b30` -> `00c33a80`) fills column 1 (Name) from vtable `+0x10` = `0103a4a0`, which returns
    `+0x10`, through the text lookup; column 6 (ItemId) from `+0x24`. Lua names the columns
    (`ScriptsBase.lua:3338-3344`, `Name = 1`, `ItemId = 6`).
  - `00b89ca0` (HandleRewardPacket) passes `+0x24` to `00b899f0`, which looks the id up in the client's item
    definitions and logs `ClientRewardManager::PlayItemReceivedNotification - Failed to lookup item definition id`
    when absent. A granted reward item therefore needs a definition the server can send.
- **The rows' display names** (client locale `en_us_data.dat`): 313's `+0x10` 19042 = "Skeletal T-Rex"
  (icon 7799), 311's 33942 = "Sunstone Street Lamp" (icon 8000), 312's 33940 = "Skullz Tent" (icon 74). The
  collection 313 description 3803 promises "the fossilized remains of an ancient T-Rex ride".
- **19042 names exactly one Legacy item**, 79446 (Type 19, Icon 7799, `trex_bones_mount.adr`, Param1 13575), the
  item `mounts.json` already binds to ride 13575 "Skeletal T-Rex" (T452, `earn_only`). No Legacy item has NameId
  33940 or 33942 (the nearest lamps, 18148 "Spooky Street Lamp" and 18152 "Tall Street Lamp", are other items).
