# T526: Marketplace Rides gets its Winged, Non-Winged, Exotic and Mechanical sub-categories

## Summary

`stores.json` `station_cash` gains `ride_categories`: four children of Rides (139), ids **2-5**
(ours, (R)), names 5101131 Winged / 5101134 Non-Winged / 5101132 Exotic / 5101133 Mechanical and
display orders 10/20/30/40. All 89 ride rows get a `ride_category` key and a `category_source`
string. `src/station_cash.rs` turns that into the 66/7 tree nodes (parent 139), one 66/6 group per
child, and the bundle record's category group; an untagged row keeps group 1 (Rides) and an
unknown key fails `StoreCatalogue::load`. The 66/9 affiliate bundle group and every price, wallet,
order, replay and earn-only rule are untouched.

Counts: 89 ride rows (54 shipped + 35 T452) = 81 listed + 8 earn-only. Final types: winged 13,
non-winged 23, exotic 14, mechanical 39. With `ride_categories` absent the packets are
byte-identical to before (the four extra nodes exist only when the config lists them); with the
policy disabled nothing is sent, as before.

Preconditions checked: `lab/autopilot/merged/T380-marketplace-rides-category-lists-its-bun.*` and
`T452-ride-catalogue-osfr-additions.*` exist, and T380's reader-faithful walk test
(`world_entry_store_rows_are_the_shipped_rides_at_their_scaled_prices`) is at tip. The fleet

## Client evidence (IDA, shipped 2014 FreeRealms.exe)

- 66/7 handler `00b48040`: base read `00b2dd60`, then `00b43090`, then the category-tree refresh
  `0099a7b0`; a short read or trailing bytes logs `InGamePurchase.log` and skips the refresh.
- 66/7 record: `00b43090` -> `00b3fd70` (count then one dword key per node, then the `Sorted`
  bool) -> `00b33400` (Id at +4, NameId at +8, Image strings) -> `00b3b080` (three dwords:
  **parent +0x30, count +0x34, display order +0x38**).
- Parent behaviour: `00b43090` copies each node's +0x30 to +0x3C and hashes it (buckets at
  +0xDC0), so the index is **parent -> children**. `009a67c0` (RefreshTree) starts from the root
  parent id `dword_1BE591C`, and `009a5eb0` recursively finds nodes whose parent key equals the
  current node's id and builds the UI tree (`009a31d0`/`009a0d90`, id at +0x20).
- Bundle filter: `0099f150` (and `0099f3b0`) takes the bundle's +204 group key, looks the group up
  in the 66/6 hash at manager+0x35278, and calls `0099d7e0(groupCategory, selected)`. That function
  returns true when the group category equals the selected id, then hashes the selected id's
  **children** and recurses down (child id at node+4). So **selecting Rides (139) lists every
  child's bundles**; selecting a child lists only that child's own bundles.
- 66/9 is a separate namespace: Legacy `StoreBundleGroups.json` ids are 1-11 (Miniclip, Bigpoint,
  ...), while ride bundles carry `CategoryGroupId` 266-269. No 66/9 group has a 266-269 id, so the
  category group of a bundle is not required to appear in 66/9. The single synthetic 66/9 group is
  kept unchanged.
- Empty child: T380's table (`00c402b0` count rebuild) found a zero-count category is deleted in
  the client tree. Sending a zero-count child (and its 66/6 group) is tolerated, so the writer
  sends every configured child; the client drops the empty node.
- Locale names: 5101131 Winged, 5101134 Non-Winged, 5101132 Exotic, 5101133 Mechanical (checked in
  `lab/reports/locale-id-to-text.json`, along with 5101156 "Rides and Pets" and 27547 "Rides"). Legacy
  `StoreBundleCategories.json` (SHA 9f3e8482..., identical in Legacy 9e08202 and Sanctuary 10f129e)
  gives them ids 266 Winged, 269 Non-Winged, 268 Exotic, 267 Mechanical, all `ParentId` 139
  ("Rides and Pets", name 5101156); the Rides portal uses our name 27547. The Lua
  `MarketplaceCategoryIds` table (ScriptsBase.lua) does not contain 2-5, so the child ids cannot
  collide with a client-hardcoded category (0.1, 45, 50, 59, 116, 136, 139, 235-238, 243, 300,
  31415, 31416).

## Threat note (secure-code-guardian)

- No new inbound message or selector. The four categories are server content; a client cannot
  choose its category, price, quantity or bundle id. The wallet/status requests that trigger the
  catalogue are unchanged, and the order/preview path (`place_order`) still revalidates the store,
  bundle, server price, balance, bag and busy table with a clone-and-commit transaction; the
  existing refusal tests assert an unchanged snapshot.
- The only new parser input is `stores.json` at load: `ride_category` is a closed enum, so an
  unknown tag is a deserialization error and `StoreCatalogue::load` fails; a valid tag whose child
  is not configured makes `Catalogue::build` fail with "ride category is not configured". There is
  no fallback to a client-controlled or arbitrary value, and no unwrap on client data.
- Config sanity bounds: exactly four unique keys/ids/orders, all non-zero, ids distinct from the
  Rides/Boombox ids and groups; every wire value is a u32 already validated here.
- No secrets, no new logging of player data, no filesystem writes (content is read-only here).
- The only resource growth is ~192 bytes per catalogue (four 66/7 nodes of 32 bytes and four 66/6
  entries of 16 bytes) when the feature is configured, on the existing per-session catalogue path.

## Checklist

1. **A refusal changes nothing.** The change adds no refusal at request time; the order/preview
   refusals are untouched and `refusals_change_nothing` snapshots inventory + wallet around each.
   The new refusals are content-load failures, so no shop/state exists: `bad_ride_category_content_is_refused_at_load`
   proves each is an `Err` (and the empty-child test is a successful load). The canary break above
   is the deliberate break for that test.
2. **Rollback covers all state.** No transaction is touched; the category data is immutable
   content read at `CoinShop::new`, and a failed load produces no shop. Nothing escapes a clone.
3. **Apply deltas.** This change writes no game state; the order path still debits and grants
   once (existing tests). No snapshots are restored over live state.
4. **Busy rules are mutual.** No new activity or busy gate.
5. **Every entry path is gated.** The category is not an action and cannot be selected by the
   client; it is derived once per shop from validated content in `Catalogue::build`, used by every
   catalogue packet (world-entry/wallet/66-12 paths). No second path exists.
6. **Reachable in production, tested through it.** `new_shop` loads the real content through
   `CoinShop::new` and drives `marketplace_packets`/`catalogue_packets`, the exact packets the
   gateway sends; `wallet_reply_carries_the_marketplace_handshake_and_the_ride_catalogue` now
   asserts the four child names and the bundle's child group through `Gateway` -> gameplay ->
   `CoinShop`.
7. **Survives reconnect.** Nothing new is persisted; the catalogue is rebuilt from
   `stores.json`/`mounts.json` every session. The save/wallet tests are unchanged.
8. **Every exit path restores the player.** No activity, location or cooldown state is involved.
9. **Economy safety.** No grant, price or earn rule changed. Earn-only rides have no bundle and
   are asserted absent from 66/5 and from every child; every listed ride is asserted under exactly
   one child at its scaled row price, so a tag cannot create a free or duplicated grant. The tag
   is server content, not a client input.
10. **Wire format matches the client reader.** 66/7 is walked field for field (key, id, name,
   image strings, parent, count, display order, sorted byte) and 66/6/66/5 are decoded exactly;
   the new parent/order values are the record dwords `00b3b080` already reads, so no extra or
   missing bytes. `catalogue_navigation_packets_match_the_client_readers` pins the six nodes and
   groups; the walk test drains every byte.
11. **Unique ids.** `ride_categories_valid` requires four unique keys, ids and orders, non-zero,
   and distinct from the Rides/Boombox ids and groups. No instance/GUID ids are involved.
12. **Others see changes.** Nothing in this change is visible to other players.
13. **Content works end to end.** The walk test decodes the real packets: 89 tagged rows, 81
    listed rides each under exactly one child at the scaled price, 8 earn-only rides nowhere, the
    parent owning the untagged rows, and an empty child sent with count 0 and its 66/6 group.
14. **Values live in data.** Child ids, name ids, display orders and every row's type are in
    `stores.json`; code only bounds them (four unique non-zero entries, reserved ids).
15. **Canaries break production code.** Two production breaks (serde fallback; parent 0) each made

16. **Hands off session plumbing.** `git diff --numstat` shows 0 lines in `gameplay.rs`,

17. **One player's error never stops the server.** No tick/shared path changes. A bad content file
    is a per-session shop load error (no panic); no client value is unwrapped.
18. **A type's rules live on the type.** `RideCategoryShelf` documents that `category_id` is also

19. **Hot paths stay cheap.** No per-tick work. The catalogue is built once per session and the
