# T015 - Dungeon zone, scene and enemy references

## Result

The 75 dungeon detail files now carry 25 client scene-name values: 24 guide
pages plus the opening cave. Eighteen are backed by non-stub `.gzne` assets;
seven are exact header-only scene stubs and are marked as geometry gaps. The
only numeric zone id remains the opening cave's local 411. No additional
numeric zone ids were invented from scene names.

The enemy mirror moved from 74/367 to 130/367 resolved occurrences. Thirty
client-table-backed enemy definitions were added (`930050..930079`), using
exact client locale ids and `Models.txt`/catalog model rows. Generic and alias
associations remain explicitly reconstructed `(R)`.

`Cray` is resolved in two dungeons but remains unresolved in Misty Mountain,
so the unique resolved/unresolved sets overlap by that name.

## Provenance and (R) rules

Scene source entries cite the exact `Assets_manifest.txt` and `catalog.tsv`
line, pack, offset, extracted size, CRC32 and both file hashes. Each scene-name
entry also carries the explicit `(R)` statement that the guide/content-key to
scene-stem association has not been observed in a native opcode-31 load. Seven
entries call out that their `.gzne` is header-only.

The new enemy definitions use exact client locale name ids from
`lab/reports/locale-id-to-text.json` and model filenames/ids from
`lab/working/OSFR.Client/OSFR Client/Resources/Models.txt`; every model is
present in `lab/extracted/client-assets/catalog.tsv`, with the asset SHA256
recorded in `enemies_unresolved.json`. The generic/alias rules are:

- `Alpha Female Wolf` and `Alpha Male Wolf` share the sole client `Alpha Wolf`
  model because no sex-specific client model was recovered.
- Generic groups such as wolves, bears, trolls, robgoblins, hooligans, yetis,
  ravens and snakes use the canonical generic client model; regional variants
  and role-specific appearances are not claimed.
- `Cruel Fairy Cultist` uses the existing client Fairy Cultist body;
  `Smuggler Boss` uses the existing Shady Smuggler body.
- `Cray` uses the ocean model in Cray Caves and the arctic-swamp model in
  Blackspore; the Misty Mountain occurrence remains unresolved.
- All combat stats, levels, AI, and rewards on the new definitions are `(R)`
  prototype values, with zero per-kill rewards because no original loot table
  was recovered.

No player names, chat text, or native actor identity are added.

## Checker changes

`scripts/content_check.py` now:

- resolves the current checkout when it is a private worktree rather than a
  literal `project/` directory;
- validates dungeon scene names, source presence, enemy-reference status and
  positive definition ids;
- mirrors `enemies`/`bosses` rows against `enemy_refs` and rejects duplicates,
  missing rows and extra rows;
- checks `enemies_unresolved.json` rows, coverage counts and one model binding
  per `enemies.json` definition.

## Open gaps

- 237 enemy occurrences and 169 unresolved unique names remain. Variant- or
  role-specific labels without a unique client model stay null with their
  reasons; no arbitrary model was substituted.
- Scene names are not instance zone ids. The client data does not provide
  server-side numeric instance ids beyond the already-known opening cave 411.
- Seven resolved scene names point at header-only `.gzne` stubs; their
  geometry, collision, spawn transforms and native loading remain unknown.
- No native opcode-31 transition or dungeon `AddNpc` capture supports the new
  scene/enemy associations. The source entries label those associations `(R)`.
- Item, object, quest and NPC reference arrays in `dungeons_unresolved.json`
  were not in this task's resolution set.
