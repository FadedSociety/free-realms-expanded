   `combined` request turns a handler `Err` into a session end (`src/gateway.rs` `handle_at`). The
   `bundle` builder is the shared one, re-exported from `tests/common/gateway_packets.rs` through

   fails to compile until it gets a name; the 26/8 row also loses its per-refusal `format!`
   allocation. Inline test `refusal_reasons_name_every_npc_error` pins every name and asserts no
   two variants collapse. The stale `selection_rejected` sample in

## Threat note (secure-code-guardian)

A hostile client can send a 26/8 with any u64 target and flag, or a 26/10 with any target and i32
choice. Every gate stays before any state change: the 26/8 body must be 13 bytes with the 26/8
header and a 0/1 flag (`decode_npc_interact_26_8`); the 26/10 body must be exactly 16 bytes and its
target must map to a content key (`content_npc_key`, which excludes opening-actors); the shared
busy gate runs next; then `NpcInteraction::select` re-checks zone and the 12 m reach before reading
the open menu, requires that menu to belong to the target, and requires the exact choice id the
server built. The request never names coins, items, rewards or a save path, so a forged or stale
choice cannot pay or grant anything; a refused pick leaves the cloned menu unassigned. The refusal
telemetry carries only ids the client already sent plus a fixed reason name, no text, path or
secret. There is no new network, file or session surface.
