## The flow (what the client sees)

1. Go fish! (26/10): 26/4 dialog close, then the opcode-31 zoning into the hole. Nothing of the
   round is sent into the old scene. The gateway stages zone 562 and the spawn.
2. Ready / Loaded in the hole: the startup zone record uses `current_zone` (the hole); Loaded
   sends the held start packets (39/16 offer; after T393 also its 41/107 ready).
3. Go (39/5): 41/2 (+ 39/17 after T393) and the 35/20 fishing flag, all inside the hole.
4. Any end (39/6, 26/42, 41/109, a zone change): the round's own cancel replies, then the
   opcode-31 zoning back to the kept world pose; the world loads normally.

## (R) rules

- Which holes zone: `client_scene_cached` (561, 562, 564). 560, 563 and 565 stay in place until
  the scene precache lands and the flag is flipped in `fishing_spots.json`.
- Zoning values: type 2, sky `''`, GeometryId 214, envelope flag 1, unknown 1 (Lxzxrus sends 0
  for unknown; the brief and our housing return send 1).
- A hole round has no leash. Its anchor starts at the spawn and follows the player's latest
  supervised position (updated each `supervise` tick; production ticks run because the play
  package ships `opening.json`).
- The same moving anchor places the 138 register replies: `update_data_reply` and every
  `school_reply` are built from the player's position at the last tick before the 138 register,
  not from the spawn. The client registers right after Go, so this is normally the spawn; a player
  who walks before pressing Go gets the schools around where they stand, as an in-place round
  gets them around the guide. Freezing them at the spawn would need a second anchor field; not
  done.
- The return uses the kept pose's zone id (0, the open world) with the world scene's name, sky
  and geometry (housing's `world_zoning`).

## Instance

The hole is reported by `current_zone`, so `bin/osfr-gateway.rs` registers it as a runtime scene
and builds membership from the transferred pose. `World::prepare_membership` gives an unseeded
nonzero scene a **fresh instance per entry**, so **two fishers at the same hole do not see each
other**. The gateway test registers zone 562 and prepares two memberships; their instance ids
differ.

## Threat note (secure-code-guardian)

A hostile client can send Go fish!, the lifecycle (39/5, 39/6, 26/42, 41/109), 138 casts and
movement. Go fish! is admitted only by the NPC service (range, the exact offered option) and the
fishing service (busy, capacity); a refusal changes nothing (tested: state, saved pose and zone
equal). The hole visit exists only while its round exists: every end of the round removes the
visit and zones the player back once, so a client cannot stay in a hole scene without a round,
and a save or a disconnect inside stores the world pose. The cast is still bounded (3..20 m) from
a server-held anchor, which follows only the gateway-validated position, never a client value.
No reward, payout, XP or cap path changed (the catch cap stays disabled). A 127/19 house entry
sent from the hole (or during any other activity that holds the start gate) is refused before
the housing service runs, so a client cannot make a lot keep the hole as its way back and strand
the save in zone 562.

## Checklist

1. **Refusal changes nothing.** `a_refused_go_fish_zones_nothing_and_keeps_no_pose` asserts no
   zoning, `changed` false, `state()` equal, no kept pose and zone not the hole, for an
   out-of-range choice and a busy one. `a_house_cannot_be_entered_from_the_hole` asserts the same
   for 127/19 from the hole (state, kept pose and `current_zone` equal).
2. **Rollback covers all state.** The visit is a plain field on `Gameplay`, cloned with it by the
   NPC router's `commit_if_changed` and by the gateway's per-message copy; no shared state.
3. **Apply deltas.** The return restores only the pose (zone, position, rotation), which is what
   the visit changed; inventory, coins and the rest are never captured or restored.
4. **Busy rules are mutual.** `Occupation::Fishing` covers the whole visit; no hand-written check
   was added. A Go fish! while another activity runs is refused (tested), and 127/19 from the
   hole is refused by the shared start gate. T481 (tip) sets the Fishing ride/pets gates, so
   rides and warps are refused during the round.
5. **Every entry path is gated.** The only production entry is Go fish! (`begin_fishing` ->
   `FishingService::enter`); the low-level `begin` never zones. A reconnect drops the round and
   the visit.
6. **Reachable in production, tested through it.** The tests drive 26/8 -> 26/10 through
   `handle_in_world`, the load through `initialize_world`, ends through `handle_in_world`/`tick`,
   and the gateway test drives the opcode-31 frames, save and reconnect through `Gateway`.
7. **Survives reconnect.** `saves_and_reconnects_...` (abandon + `reset_session`) and the gateway
   test (a new `Gateway` from the in-hole save resumes at the world pose and can fish again) pass.
8. **Every exit restores.** 39/6, 26/42, 41/109 and a server end each zone back once (tests); a
   disconnect after a cancel returns `None` (new assertion); a save inside stores the world pose.
9. **Economy safety.** No payout, XP, cap or item path changed. The cast is still bounded by the
   server-held anchor; no client-reported result is trusted.
10. **Wire format matches the client reader.** The opcode-31 frame is the existing codec for
    reader `0x008e4ae0`; the gateway test decodes the sent frame and checks scene, id and pose,
    and the Gameplay test checks every field of the zoning. The codec's byte-level tests
    (`tests/zone_transition.rs`) pass.
11. **Unique ids.** The hole's zone id is content (unique per spot, checked at load, bounded to
    i32 because it is the wire id: `a_hole_zone_id_must_fit_the_wire_id`); the membership registry
    allocates a fresh instance per visit (tested).
12. **Others see changes.** Nothing new is broadcast; each visit is its own instance.
13. **Content works end to end.** Go fish! -> hole -> offer after load -> Go -> registration ->
    cast accepted -> cancel -> back at the kept pose, asserted across two tests.
14. **Values live in data.** Which holes zone is `client_scene_cached`; spawns, rotation and zone
    ids are content. Type, sky, geometry and the flag bytes are wire constants (R), not tuning.
15. **Canaries break production code.** The canary edited `leave_fishing_hole` in production and
    failed the cancel test; it was reverted and the suite re-ran green.
16. **Hands off session plumbing.** `gateway.rs` keeps its order; two calls are renamed to the
    house-or-hole hooks (net 0 lines). No creation, teardown order, transaction or save ordering
    changed, and `bin/osfr-gateway.rs` is untouched.
17. **One player's error never stops the server.** `supervise_fishing` swallows fishing errors as
    before; the only `?` is `world_zoning`, which fails only without world content and is staged
    by the gateway (a session-local error). `app_fuzz` passes.
18. **A type's rules live on the type.** `Tracked.in_scene` documents what it changes and is set
    where `Tracked` is built (`begin_spec` takes the zoning); `Change.scene` documents the
    caller's duty (zone now, hold the replies); `FishingHole` fields are documented.
19. **Hot paths stay cheap.** See Structure: one `Option` check per tick, a 16-byte anchor copy
    in a hole, no allocation or state clone.
