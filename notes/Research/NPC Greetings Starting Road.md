# NPC Greetings - Starting Road (T246)

Adds 16 recovered `greeting_string_id` values to the starting-road NPC rows in `data/content/npcs/`: five Farnum Farmstead, two Cobblestone Village, three Highroad Junction and six Sanctuary. The 19 W126 bindings are untouched. No Rust production change: `npc_interaction::dialogue_context` already copies `greeting_string_id` into the 26/3 body, and no wire shape changes.

## Method (reproduces [[NPC Greetings]])

1. **Ids versus hashes.** The region build guides cite locale numbers that are usually the raw JenkinsLookup2 hash, not the `Global.Text.<id>` key. Every number below was resolved through `lab/reports/locale-id-map.json` (`hash_to_ids`) and then checked by recomputing `jenkins_lookup2("Global.Text.<id>")` and finding that hash in the read-only stock client locale `lab/working/OSFR.Client/OSFR Client/locale/en_us_data.dat`. The `Greeting id` column is the id the client looks up; the `hash` in the evidence column is the guide/export number; `line` is the physical line in that stock file. All 16 ids are present in the stock file, so no locale overlay is needed.
2. **Speaker proof.** A line counted only when (a) the speaker is named in the line, (b) it sits in the same locale block as a named referral/hand-in, or (c) the matching region build guide row names the NPC and quotes or lists the line. A line merely close to the NPC does not count. The W126 rows below were not changed.
3. **Quest-offer lines.** The 49/1 intro text is the speech bubble shown in the original quest offer (native screenshot, `notes/Research/Quest Offer Reference.md:8`: locale 104097 is the bubble body). For the Sanctuary trainer lines, the quest record binds `giver_npc_id` to the NPC, the quest is named in that NPC row of the region guide, and the intro text is first-person and matches the NPC role. Phase-dependent hand-off lines were rejected when they named the giver in the third person; for example Pappy's hand-off "Go talk with Cleetus" in the Gear Up! block is not assigned to Cleetus.
4. **Fixed default.** Picking one verified speaker line as the fixed Talk greeting, without the original server dialogue/phase table, is reconstructed policy `(R)`; the locale text and ids are recovered client facts and no text is invented.
5. **Quest-offer inference (F271).** For the seven quest-offer rows (Eddie, Bordon, Clover, Doctor Gordon, Naia, Whittington, Karin) the greeting id is the quest's 49/1 `intro_text_string_id`. That id binding is itself reconstructed: each quest record marks its "intro/description/end-text ids from the client locale block around the title (T-1/T+1/T+2)" as `(R)`, filled by `scripts/quest_text_backfill.py` where unambiguous. The speaker link is therefore inferred, not recovered; each NPC row carries a `reconstructed` greeting source that names the quest file, quest id and intro id.

## Client evidence

- 26/3 ShowDialog: handler `00aa12e0` calls payload reader `00a9ef10` and then display routine `ShowDialogFromPacket` `009f5ae0`; `008d2ba0` is the dialog-camera helper (`ReplacePointerAtECAndDispatch ?`, called from `009f5ae0` for the speaker actor), not the packet dispatcher. T246 originally mislabelled it; F271 correction. The dialogue body is the first dword and is a `Global.Text.<id>` key, not the NPC name. `gameplay/npc.rs::dialogue_packet_with` writes `context.body_string_id` into that dword; `patch_npc_actor` only overwrites bytes 12..20 with the runtime actor GUID.
  IDA check (F271, read-only broker, decompiled `00aa12e0`, `00a9ef10`, `009f5ae0`, `008d2ba0`): `00aa12e0` calls `00a9ef10` then `009f5ae0`; `00a9ef10` stores the first payload dword into the message object at `+16` (`*(this + 16) = *v3`), and `009f5ae0` passes `*(_DWORD *)(a2 + 16)` to the Lua lookup `sub_97C1E0` immediately before `:SetDialogText`. That is the first dword after the four-byte family/subtype header, matching `encode_dialogue_26_3`'s `initial_dwords[0]`.
- 26/6 dialogue response reader `009f5890`; 26/9 interaction-list reader `00aa2360`; 26/10 selector constructor `00a36f80`; the client resolves the body through `Global.Text.<id>` (`0097bca0` builds that key; W126 native map evidence).
- The 26/3 byte layout is pinned by `tests/npc_interaction.rs::dialogue_26_3_synthetic_fixture_round_trips_exact_native_field_order`; no new wire shape is introduced.

## Exclusions

- No greeting was added to an `unanchored` or `poi_anchor` row: those rows are not spawned by `NpcVisibility` (`legacy_data` only), so a fixed body would not be reachable on the starting road. All 16 added rows are `legacy_data` with a position, model id and name id.
- Ambiguous candidates were left blank rather than guessed: vendor rows with no recovered speech (Estus, Rocky, Vela, Roosey, Gaston), enemy rows, the duplicate Raina Rush/Speedy row, and the Riley cat line (the Farmstead Riley is the TCG player, not the lazy cat).
- The 16 rows use 16 distinct ids; no generic line was reused across NPCs.

## Open gaps

- The original server greeting/phase tables are not recovered; every row is a fixed default (R), so an NPC always repeats the same line regardless of quest phase.
- `unanchored`/`poi_anchor` starting NPCs (Rucks, Wompugg, Peavey, Amara, Carlos, Poe Tatters, Sam Potts, Roscoe and others) still have no greeting; several do have recovered speech (Rucks, Wompugg, Peavey, Amara), but they are not spawned by the current visibility loader, so this slice left them blank to keep every changed row reachable.
