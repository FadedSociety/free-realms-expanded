# T906: TCG card database census and card-picture check (research, 2026-10-30)

## Why

Owner, 2026-10-30: "I don't want to miss card pictures." Decode the card game's own database, count the cards, and
list which have no picture and where one could come from. No server code changes: the tool and its output are
lab-only (client data) and are kept outside this diff. They were built in the scratch folder and handed to the lead
to place at `lab/tools/tcg_cards.py` and `lab/references/tcg-card-census-20261030/cards.json`.

## Bottom line (numbers; every one is reproduced by the tool)

- `tcg/data/archetypes/index.dat` + `storage.dat` hold **1,391 archetype records**. **708 are collectible cards** (title,
  set, collector number and rarity present): 385 creatures, 160 support, 163 tricks. By set: 257 / 158 / 137 / 78 / 78.
  The other 683 records are 605 loot rows (284 items, 321 companion cards), 17 boosters and starter decks, 8 game objects,
  11 developer or template rows (the three class templates, three "old PROTOTYPE" rows, seven cut cards) and 42 untitled
  pack ids or misc rows. Earlier passes counted 719 "playable" because they included the 11 developer rows.
- `default.cln` lists 2,207 ids: the 1,391 records plus 816 ids that are another record + 300,000 (418 are the variant
  of a real card). The sprite retries `id - 300,000` for ids above 100,300,000, so a variant shows its base picture.
- **Pictures for the 708 cards: 329 in hand, 360 listed by the delivery manifest with no bytes anywhere, 19 with no
  source at all.**
  - In hand: 307 from the 2011 install's asset cache, 38 from the 2014 `assetpack000W_000.pack`, 16 in both.
  - Listed only: `assets/assetpack000_manifest.txt` names `images/card/<id>.jpg` (or `.jpg.z`) with CRC-32 and size.
    Sets 2-5 account for 357 of the 360 (85, 133, 67, 72); set 1 for 3.
  - No source: the 19 print-on-demand cards, ids 100010235-100010249, 100010253, 100010255-100010257 (set 1).
- `cards.rcc` has no face of any real card: its 202 numeric ids are loot items and booster or starter-deck products.
  201 have a record; the 202nd (100011272) is the art id named by record 100011273.
- Loot: 284 items (199 in hand, 56 listed only, 29 none), 321 companion cards (199 / 52 / 70). Boosters 9 (7 / 1 / 1),
  starter decks 8 (8 in hand).

## Client evidence

All addresses are `FreeRealmsTCG.dll` image addresses (base `0x10000000`), read from the preserved listing.

- **Card names are not in `msgStorage`**. That file holds engine message templates. Name, set, type and rarity are
  properties of the archetype record (`GetTcgTextProperty`, T855).
- **Record format**: compact ints (`SerialAppendInteger` family); class 90020 v7 twice, archetype id, `0 1 0`,
  `19 2 23 1`, a property count, then `count` x (property id, `22 4 type 1`, value), then six ints. Value types: 1/2 int,
  3 NUL-terminated string, 6 int list. All 1,391 records parse and match their stored lengths.
- **Parent archetype**: property 569 names it; a property missing on a record is read from the parent. That is how every
  loot item gets kind 7 from the "Item Grant" record 100011271. The earlier "card-type reference" reading holds.
- **Property ids** (collection model `0x102E6E90`): Title 1, Type 0x1C (28), Set # 0x49 (73), # 0x4A (74), Rarity 0x4C
  (76), Cost 0x240 (576), Game Text 0x276 (630), Sphere 0x164AD, Colour 0x164AE, Atk 0x164B4, Def 0x164B5, Traits
  0x164B6, Artist 0x164CD, Qty 0xFC7.
- **Enum ids**: card class 90074 Creature, 90075 Support, 90076 Trick (`zpfilterpanel` cardType, `0x1045F4B0` region);
  sphere 90002 Nature, 90006 Chaos, 90007 Machine, 90008 Order; rarity 90051-90055 Common, Uncommon, Rare, Fixed, Promo
  (`eqfilterpanel` `0x10424FE0`). The rarity code table `0x102017D0` gives C U R F P S E L LP for 90051-90059.
- **Set names**: set 1-5 are the products FreeRealms, Shattered Past, Baron Von Darkcheat, Heroes, Rumbledome (the
  booster and deck records 1900001, 2900001-5, 3900001-5, 4900001, 5900001 carry property 73 = 1..5).
- **Picture path** (`0x1041C080`, T855): kind = property 797; 2 booster, 3/4/7/8/9 loot, else playable. A playable card asks
  for `:/images/card/<id>.jpg` (`:/images/pod/<id>.png` when property 569 as an int is in 0x5F608FB-0x5F60911). Loot and
  boosters ask for `<property 300, else id>.png`. The asset loader (`0x102B44E0`) accepts a path found in the Qt
  resources or in `assetpack000`; ids above 100,300,000 retry with `- 300,000`; otherwise the placeholder.
- **Server fetch**: `frtcg.ini` has no URL, host or asset key (account, window, volume, UI and deck-name preferences).
  `host.svr` is the game-server address. The DLL's own downloader has hard-coded bases (`0x67BA70` live, `0x67B9E0`
  staging; `_compare/asset-delivery.md` section 7); the live host is gone.

## Where the missing pictures could come from

The 360 listed faces (sets 2-5) are in no local source: not the 2014 client, the community client, the 2011 install (its
database is a February 2010 snapshot that predates sets 3-5), the wiki harvest (about 70 loot-card PNGs) or the
`TCG-Files` clone (no art). Only a retail asset-server mirror, a fuller 2012-2014 install or a player's cache could fill
them; the manifest rows give CRC and size to verify any find. The 19 POD cards have neither bytes nor a manifest row.

## (R) rules and open gaps

- (R) Attack, defense and cost are absent on many records (no attack 288, no defense 287, no cost 71 of 708); absent is
  read as 0 or not applicable.
- (R) Rarity names for 90056 S, 90057 E, 90058 L, 90059 LP are only the code letters.
- (R) POD cards: the pod branch tests property 569's value (100008460 on all 19), so they ask for `images/card/<id>.jpg`;
  neither reading has a source.
- (R) A "+300,000 variant" is the id relation the sprite uses; what it is in play (foil, hero, premium) was not read.
- Not decoded: rules scripts (`ruleStorage`, `actionStorage`), the `.cln` instance numbers, traits and artist names.
- Foils (`images/foils/large/<id>.bmp`): 550 of the 708 cards have a manifest row; not counted as pictures.

## Threat note (secure-code-guardian)

No client input, save, coin, item, reward, role or chat path is touched and no production code changed. The tool only
reads local client files, never writes them, and prints counts and ids. It decodes with bounds-checked slicing and
asserts every length; the only expansion is `zlib.decompress` on the client's own archetype records, each checked
against its declared length. Its output holds client data and stays out of Git.
