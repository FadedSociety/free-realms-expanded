## Security Note

A hostile client can replay `41/108`, forge the encounter/instance body, send
an arbitrary activity or battle id to portal Play, call the developer command,
attack arbitrary GUIDs, or replay results Close. The route refuses all of
them:

- Go uses only the server-pending battle; the request body is not trusted.
- A refused Go reopens the same screen with the same instance and leaves the
  pending battle in place, so the client cannot skip the gate by replaying.
- Portal Play uses the published catalogue and its admission rules before the
  owner-module prize gate; the developer command is role-gated.
- `36/10` resolves a live arena enemy in server range; rewards derive from
  server HP reaching zero, never from a client-reported hit.
- `26/42` matches the active instance; duplicate Close and post-win attacks
  add nothing.
- Prize ids are checked against the loaded item catalogue before the
  encounter, inventory or open screen can change; quantities are bounded by
  the field-battle loader.
