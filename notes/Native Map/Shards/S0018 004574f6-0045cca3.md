## Corrections applied through repair attempts 8 and 9

- FUN_004d9207 is the engine size-bucket heap allocator, not an object lookup. Ten identical
  wrappers that pass a byte size and stamp the debug sentinel pair 0x56471e89/0x9fe1234a at

  and AllocHeapCanaryBlockA (0047bc69). The earlier "class signature" reading was wrong.
- 0045cb3a and 0045cca3 are right rotations of the small map/set red-black tree (colour and
  nil bytes at +0x10/+0x11), not list splices: pivot = node->left, node->left = pivot->right
  with parent fix-up, pivot takes the node's place under the parent (or the head root slot),
  then pivot->right = node. They are now `StlTreeRotateRight` / `_2`, reached from the
  accepted std::_Tree::erase bodies 0046fabc/0046fef5.
- The five debug-checked iterator compares (0045c207, 0045c791, 0045c7c9, 0045c9ee,
  0045ca26) are shared vector/tree iterator equality emissions (proxy check through
  FUN_00d83c2d, then node/element pointer compare); they are now container-neutral
  `IteratorEqualsChecked*`. The accepted map/set range-erase code uses five of them.
- 004589ab copies a tree into a fresh header (used at construction by 00458f8b), so it is
  `StlMapCopyTree`, not a copy assignment. 00458a0b is erase(first,last) built from the
  iterator constructor FUN_00451519 and the equality FUN_00451274 - it contains no key
  search - with a whole-range fast path that clears through FUN_00458985.

- 0045afdd owner-counter updates are inside the non-null +0x14 guard; state +0x10 >=2 gates unlinking, while +0x14 is cleared even when null.
