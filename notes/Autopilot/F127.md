## Security note

A hostile client can replay `41/108`, forge another actor GUID, or claim a
reward. Level comes only from server-owned job experience, rewards come only
from the encounter engine's server-owned kill count, and the pending battle id
is server state. A low-level Go returns before consuming that pending state or
entering `begin`; `begin` repeats the same guard for other callers. A forged
marker GUID that is not a field battle creates no pending state and no reward.
The shared entrance GUID is a recovery binding, not client-supplied identity.

## Review checklist correction (F154)

Item 17 (one player's error never stops the server), omitted from the original
run transcript: F127 added only battle-start admission checks and a gateway
regression test. None of that code runs in the shared tick or on another
player's action. The marker, portal and engine admission checks return a chat
refusal or the caller's own `io::Result`; `Gameplay::simulate_battle` runs on
the caller's staged gameplay under an admin developer command. A bad value from
one player therefore fails that player's request, and `contain` in
`src/bin/osfr-gateway.rs` keeps a panic in one session's handler from ending
`Server::step`.
