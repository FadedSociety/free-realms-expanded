## Evidence gaps and reconstructed rules

The brief expected `model_id`/`model_file_name`/`name_string_id` copied from each
NPC row. At this tip **none of the 25 rows has model fields** (0/25; every
non-`legacy_data` NPC row in the package is unmodelled), and 11 have several
`name_string_ids` hashes instead of one id. The brief's stop rule names a
missing model; a stop would have delivered nothing, and the lead's later T385
brief documents the T372 fallback: a real client model from the same family,
tagged `(R)`, is acceptable when no exact model is recovered. I followed that.

- (R) Model fallback. Each model is a real 2014-client `Resources/Models.txt`
  body matching the NPC's wiki race, gender and job. It is not a recovered
  identity. The row's `legacy-data` tag cites the exact `Models.txt` id/file;
  the `reconstructed` tag states the body choice, the reconstructed position
  and that no captured transform exists.
- (R) Name normalization. The NPC rows' `name_string_ids` are `ucdt`/`ugdt`
  hashes, not AddNpc `Global.Text` ids. `lab/reports/locale-id-map.json`
  `hash_to_ids` resolves each row to a locale id whose text equals the row
  name; that locale id is the spawn's `name_string_id`. Examples: Fladnag
  hash 2505010157 -> 5102517; Florina 1160566912 -> 45951; Razzle
  2605501257 -> 413068.
- (R) Position is the row's reconstructed `poi_anchor`/`unanchored` placement,
  not a captured NPC transform. Heading 0.0 because no row has a finite
  heading (the rows carry only a zone quaternion).
- (R) Runtime GUIDs reuse the NPC content key, as Carlos/Geoffrey/Dewey do;
  no new GUID range and no captured server GUID claim.

## Security threat note (secure-code-guardian)

This change is content and tests; no production input parser changed. The new
tests drive client-controlled 26/8 target GUIDs, 26/10 choice ids and the 66/42
window. A hostile client can still send an unknown/foreign NPC, a far or
wrong-zone click, an unoffered menu choice or a forged merchant target. The
server refuses before mutation: `NpcVisibility::content_key` must bind the
runtime GUID, `NpcInteraction::check_range` enforces the zone and 12 m radius,
`select` requires the exact active menu option, and the 66/42 window is built
only from the server's `vendors.json` role/stock map and `stores.json` prices.
The new tests assert the whole `Gateway` snapshot is unchanged after an
out-of-range click, a wrong-zone click and an unoffered choice; the canary
removes a real spawn and makes the drawability test fail. No client string
becomes a path, no reward is taken from a client report, and no refusal is
answered with state or a save.
