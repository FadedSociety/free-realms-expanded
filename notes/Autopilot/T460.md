# T460: world events, part 2 (walking, speech, broadcasts, areas, animation cycles, random endings)

Event timelines in `world_events.json` can now make an actor walk, talk, announce to the zone,
start and stop client areas (stage music), loop dance animations and pick one of several endings.
Everything is content data; the shipped file is still `{"events": []}`.

Ops added (JSON, inside the T458 `{"at_ms": N, "op": {...}}` step):

| Op | Fields | What it does |
|---|---|---|
| `say` | `actor`, `string_id` | 15/4 from the actor to the sessions it has been shown to within 30 m (3-D) |
| `broadcast` | `text`, `locale_id`, `radius_m?` | 15/3 line to the event's instance, or to sessions within `radius_m` on X/Z of the first actor |
| `move` | `actor`, `to [x,y,z]`, `speed_mps` | walk the straight line, one opcode 125 per tick, walk animation, stand animation on arrival |
| `area` | `area_id`, `on` | `ClientAreas::set_area`, packet to every session in the open world |
| `cycle_anim` | `actors`, `ids`, `every_ms`, `jitter_ms`, `until_ms`, `order` (`random`/`sequence`) | `play_anim` on each live actor every `every_ms` plus up to `jitter_ms` |
| `one_of` | `branches [[steps], ...]` | one branch is drawn at the run's start; branch `at_ms` counts from the `one_of` step |

## What changed

- `src/chat.rs`: `string_say(speaker, string_id)`, the 15/4 encoder (43 bytes) with a golden-byte test.
- `src/world_events.rs` (the owner): the ops above. `compile` is now a `Builder` that turns rows
  (and branch rows) into steps. A `Run` owns its resolved timeline (the drawn branches only), its
  `Rng`, its running cycles and the areas it switched on. `WorldEvents::tick` takes the wall clock
  and `&mut ClientAreas`. `piece_052` is included by `#[path]` (as `social_chat` does with
  piece_093) for `movement_packet` and the walk animation id.
- `src/players.rs`: `PlayerRegistry::sessions_in(zone)`, the zone-wide recipient scan.
- `src/power_ups.rs`: `Rng` derives `PartialEq, Eq` (a `Run` holds one and the runner is compared in tests).
- `src/bin/osfr_gateway/world_event_routing.rs`: `tick` passes the unix clock and `world.client_areas`.
- Tests: 8 new in `world_events.rs`, 1 in `chat.rs`, 1 gateway test through the real tick.

## Client evidence (IDA)

- 15/4 reader `0x00b0f680`, header `0x00b0f550` (two u16). Stream: u64 speaker, i32 string id,
  three bytes (each stored `!= 0`), i32 colour, u64, u64, i32 elapsed = 43 bytes with the header.
- Dispatcher `0x00b14350`, case 4: `cmp byte, 0` at `0x00b14db5`. The first bool zero jumps to
  `0x00b14dee`, which calls `0x00b0fad0` (`WorldSay`, then `0x009012b0`). Nonzero calls `0x00b0e190`
  (emote) unless the third bool is set. The brief's routing claim is right (the research pack's
  contrary reading of the local variable names was wrong).
- The second bool (`a6` of `0x009012b0`) is stored into the Lua event table beside the `OnReceiveSay`
  arguments (ScriptsBase.lua:30968, `isChatLogged`): sent set (R). A set third bool also prints the line
  with the speaker's name: left clear (R).
- Movement opcode 125 (reader `0x008e5940`), 35/8 and the rest are T458/piece_052 facts.

## Reconstructed rules (R)

- 15/4 colour and the two u64 stay 0; the names x and y in the brief are not proved by the reader.
- `say` radius is `LOCAL_CHAT_RADIUS` (30 m, 3-D, (R) in `social_chat`). The client resolves the speaker by guid
  (`sub_984960`), so only sessions the actor was already shown to can hear it; `say` shows the actor first.
- `broadcast` is 15/3 (T199's wire); the original probably used the undecoded 77/2 BroadcastPacketZone.
  The zone is the run's instance, the open world. `locale_id` is provenance only and is never sent.
- `move` has no 250 ms clamp (the patrol controller's): a step is `speed * elapsed`, so a stalled server
  catches up. Arrival tolerance is 1 mm of f32 drift. Speed bounds 0.1..=6.25 m/s (the upper bound is piece_052's
  community ceiling, the lower one is mine). A target with no horizontal offset keeps the old heading.
- `cycle_anim`: the first play is at the step, `until_ms` counts from the cycle's own step (the brief did not say), at
  most one play per cycle per tick (a stall skips plays, it never bursts), `sequence` advances once per play for
  all actors, `random` draws per actor. Cycle `every_ms` is at least 100 ms.
- The draw is `Rng::seeded(mix(serial << 32 ^ start_ms))`; tests use `begin(.., Some(seed))`.
- A run's areas are switched off when it is stopped or ends, even if a later step would have done it. Two runs
  that both switch the same area share the toggle: the first to end switches it off for both.
- Sanity bounds, not tuning values: at most 8 branches (no nesting), 32 cycle ids, text of 256 bytes without control
  characters, `radius_m` in 0..=10000, move targets within 1e6 m.

## Threat note (secure-code-guardian)

- Nothing new is reachable by a player. The ops run only from `world_events.json` (admin-started, read at each start).
  No client message selects a text, a string id, a radius or a target.
- A hostile or careless content file: every number is bounded at load (above), floats must be finite, text has no
  control characters and a length limit, branches cannot nest, step count includes branch steps (512), and
  `deny_unknown_fields` still holds. Movement uses finite-checked f32 math and lands on the validated target.
- Chat markup in `broadcast` text goes through `chat::system`'s escaping. A removed actor's ops are skipped.
- One failing recipient never stops the tick: delivery stays in `world_event_routing::tick` (rule 17).

## Checklist

1. **A refusal changes nothing.** The loader refuses a whole file on any bad op (`the_loader_refuses_bad_part_two_ops`
   asserts each bound). A skipped op (removed actor) changes no state: `ops_on_a_removed_actor_are_skipped`. The T458
   refused-command test still passes (nothing about commands changed).
2. **Rollback covers all state.** No new shared state: the runner is in `SharedWorld` as before and `ClientAreas` is
   mutated only by the tick, after the commit.
3. **Apply deltas.** No player state is read or written; area toggles are deltas through `set_area`.
4. **Busy rules.** Not an activity; no player is occupied.
5. **Every entry path is gated.** The only entry is `realm event start`, behind `command_refusal` (admin).
6. **Reachable in production.** The gateway test drives `realm event start/stop` and `world_event_routing::tick`, which
   `Server::step` calls (T458's step test).
7. **Survives reconnect.** Runs are in memory (T458 (R)). A session that loads mid-song gets the area from
   `ClientAreas::world_ready_packets` with the elapsed time (tested); a reconnecting session is shown live actors
   again at their current position (tested for a walker).
8. **Every exit path restores.** Stop, natural end and the per-viewer leave all clear actors; areas are switched off on
   stop and on natural end (tested both).
9. **Economy safety.** Not applicable.
10. **Wire format.** 15/4 golden bytes against the reader layout (`chat::tests`); 125, 35/8 and 89 use the existing
    writers; byte tests in the walking, area and gateway tests.
11. **Unique ids.** Guids unchanged (`EVNT | serial << 8 | index`).
12. **Others see changes.** Every op goes to the sessions that were shown the actor (or the zone for broadcast and area);
    late viewers get the current position, base animation and tags (tested).
13. **Content works end to end.** The gateway test plays spawn, say, broadcast and area, and stop through the real tick.
14. **Values live in data.** Speeds, times, ids, text and radii are in `world_events.json`; the bounds are (R) sanity limits.
15. **Canaries break production code.** All four edited `chat.rs` or `world_events.rs`.
16. **Hands off session plumbing.** Only the world tick call changed.
17. **One player's error never stops the server.** Delivery per session is unchanged and logged; ops use checked math and
    are skipped on bad state; no `unwrap` of content data after the loader.
18. **A type's rules live on the type.** `Shown` documents each field (position, rotation, mover are reset with the rest by
    `mem::take`/respawn); `Run::areas` says who switches them off.
19. **Hot paths stay cheap.** See Structure; the idle tick still allocates nothing (`an_idle_tick_allocates_nothing`).
